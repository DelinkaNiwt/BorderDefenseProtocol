# DevHarness 护盾芯片复现设计

## 目标

在 `BorderDefenseProtocol.DevHarness` 中复现旧 BDP 当前实际 Def（定义）对应的能量盾芯片业务，同时服从新 BDP 的芯片表达、主副槽和 Trion 正式接口。

本次只实现测试业务，不向主模组加入护盾业务代码，也不改变主模组的触发体、表达或 Trion 规则。

## 已确认业务口径

- 护盾芯片属于主副槽芯片，使用 `HandsOnly`（仅主副槽），不沿用旧 XML 中的 `SpecialOnly`（仅特殊槽）标记。
- 每枚芯片占用 50 Trion，激活消耗 20 Trion。
- 激活预热 60 tick（游戏刻），关闭延迟 30 tick。
- 单枚激活时：防护正面 180°，抵挡成功率 70%。
- 主、副槽各激活一枚时：防护范围变为全方位 360°，抵挡成功率 95%。
- 仅拦截远程或爆炸伤害，不拦截近战伤害。
- 成功抵挡前尝试消耗 `伤害值 × 0.7` Trion；Trion 不足时不扣费，伤害正常通过。
- 抵挡成功时完全吸收本次伤害，并播放护盾命中特效、金属火花和音效。
- 护盾激活时绘制旧版同类护盾球表现。

## 方案选择

采用“BDP Hediff（状态）表达宿主 + DevHarness Harmony（运行时补丁）”方案。

芯片通过新 BDP 标准 `ChipDefinitionConfig`（芯片定义配置）声明一条 Hediff 表达。主、副槽各激活一枚相同芯片时，主模组现有 `countToSeverity`（按数量映射严重度）机制会把同一 Hediff 聚合为 Severity（严重度）2。DevHarness 自有 HediffComp（状态组件）读取 Severity，决定使用单枚或双枚护盾参数。

没有采用以下方案：

- Passive（被动）表达：每次受伤都要重新查询表达快照，且健康面板缺少明确状态。
- 直接读取触发体槽位：会绕过已存在的表达聚合与宿主同步链，形成不必要耦合。
- 修改主模组防护架构：当前只有一个测试业务样本，不足以证明需要新的通用基础设施。

## 组件与职责

### 芯片 Def

DevHarness 新增测试护盾芯片，负责声明：

- 主副槽限制；
- 60/30 tick 启停时间；
- 50/20 Trion 成本；
- 指向护盾 Hediff 的表达条目；
- `countToSeverity` 聚合方式。

### 护盾 Hediff Def

护盾 Hediff 继承新 BDP 的 `BdpExpressionHostHediff`（表达宿主状态），保证它仍由主模组正式表达同步链创建、更新和移除。

Hediff Def 通过两个阶段表达名称变化：

- Severity 1：能量盾；
- Severity 2：全方位能量盾。

护盾数值全部写入 DevHarness 自有 HediffCompProperties（状态组件属性），避免把业务数值硬编码进主模组。

### 护盾 HediffComp

护盾组件只承担单个 Hediff 宿主内部的防护判定和表现：

1. 检查 Pawn（角色）已生成、存活、未倒地。
2. 检查伤害是否为远程或爆炸。
3. Severity 1 按 Pawn 朝向与 `DamageInfo.Angle`（伤害角度）检查正面 180°；Severity 2 跳过角度限制。
4. 使用 RimWorld 原版 `Rand.Value`（随机值）执行 70% 或 95% 判定。
5. 通过 `TrionSurfaceAccess.ResolveCommands`（Trion 正式请求入口）全额尝试扣除 `伤害 × 0.7`。
6. 只有扣费成功才把伤害量设为 0，并报告已吸收。
7. 播放命中特效；绘制阶段持续显示护盾球。

组件不保存可重建的业务真值。芯片激活状态、双芯片数量和 Trion 余额仍分别由主模组 Trigger（触发体）、Expression（表达）和 Trion 系统持有。

### Harmony 补丁

DevHarness 使用两个最小补丁接入 RimWorld 原版时序：

- `Pawn.PreApplyDamage`（角色受伤前处理）的 Postfix（后置补丁）：只在伤害尚未被其他系统吸收时查找测试护盾组件。
- `Pawn.DrawAt`（角色绘制）的 Postfix：只为当前存在的测试护盾组件绘制护盾球。

补丁只识别 DevHarness 自有组件类型，因此禁用或删除 DevHarness 后不会留下护盾业务。

## 数据流

```text
主/副槽激活芯片
    -> 新 BDP 表达收集与发布
    -> Hediff 宿主同步
    -> 单枚 Severity 1 / 双枚 Severity 2
    -> RimWorld 伤害前处理
    -> 类型、方向、概率、Trion 判定
    -> 成功时吸收伤害并播放表现
```

## 边界与失败行为

- 伤害已被其他系统吸收：护盾不重复处理，也不扣 Trion。
- 无护盾、Pawn 无效、死亡或倒地：伤害正常通过。
- 近战或不在允许列表内的伤害：正常通过。
- 单枚护盾受到背面攻击：正常通过。
- 概率判定失败：正常通过且不扣 Trion。
- 无 Trion 组件或可用 Trion 不足：正常通过且不发生部分扣费。
- 护盾关闭或触发体移除：由新 BDP Hediff 宿主同步链移除状态，不保留 DevHarness 自有持久状态。

正常路径不保留旧版高频日志。若游戏内实测出现时序或角度问题，再添加带统一前缀、易搜索和易删除的临时诊断日志。

## 验证

先编写失败的 PowerShell（脚本环境）冒烟测试，再补实现：

- 芯片 XML 字段、槽位限制、Trion 成本和启停时间正确；
- Hediff 表达使用 `countToSeverity`；
- Hediff Def 两个 Severity 阶段和护盾参数正确；
- Harmony 补丁只在 DevHarness 内存在，并接入正确原版方法；
- 护盾组件通过 Trion 正式请求口扣费；
- 特效 Def 与贴图路径完整；
- DevHarness Release（发布配置）编译通过。

最后提供游戏内实测清单，覆盖单枚正面/背面、双枚全方向、概率失败、Trion 足够/不足、关闭延迟和对外射击不受影响。
