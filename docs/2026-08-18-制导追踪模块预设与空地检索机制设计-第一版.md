# 制导追踪模块：预设方案 + 空地自动检索机制设计（第一版）

- 日期：2026-08-18
- 范围：只以**原版框架**（RimSearcher 数据库 + DecompilerServer 原版程序集）与 **BDP 主模组**（`BorderDefenseProtocol`）为探查对象。
- 排除：BDP 测试模组（DevHarness）、旧 BDP（Legacy）不参与本次结论。

---

## 一、目标与范围

1. **两套追踪预设**：把制导追踪模块（`BDP_HomingModule_Strong` / `BDP_HomingModule_Weak`）的参数做成两套可复用预设。
   - 预设 A「标准追踪」：50% 路程开始追踪 + 2 次重锁（即现猎犬行为）。
   - 预设 B「弱追踪」：90% 路程才开始追踪 + 0 次重锁（脱了就脱了）。
2. **空地目标 + 自动检索公共机制**：允许玩家选空地为瞄准目标，子弹飞到落点后以自身位置为原点，在半径内检索最近合法目标并开始追踪。
   - 当前阶段：玩家**不可**选 Pawn 视野外目标（受现有直射视线约束）。
   - 未来：等曲线投射（迫击炮式）能力落地后，再放开"玩家选视野外目标"。
   - 关键区分：**子弹自检索**（以子弹检索时刻自身位置做范围+视线判定）与**玩家选目标**（受发射时瞄准约束）是两套独立机制。

---

## 二、可行性结论（总览）

| 需求 | 可行性 | 需代码？ | 依据 |
|---|---|---|---|
| 预设 A（50% + 2 重锁） | ✅ 可行 | 否（纯 XML） | 即现有 `Homing.xml` 的 `defaultConfig` |
| 预设 B（90% + 0 重锁） | ✅ 可行 | 否（纯 XML） | `InitialSegmentTriggerRatio` 语义已验证（`BdpProjectile.cs L1208-1225`）；`MaxRelocks=0` 语义已验证（`HomingModule.cs L844`） |
| 空地目标合法瞄准 | ✅ 可行 | 是（少量） | 原版 `TargetingParameters.CanTarget` 对空地返回 `canTargetLocations`；BDP 已有 RoutePath/毒蛇先例 |
| 落点半径寻最近目标 | ✅ 可行 | 是 | 原版 `GenClosest.ClosestThing_Global(center, searchSet, maxDistance, validator)` 现成可用 |
| 子弹自检索视线判定 | ✅ 可行 | 是 | 原版 `GenSight.LineOfSight(start, end, map)` 现成可用 |
| 模块独立性（互不引用） | ✅ 可行 | 是（公共工具类） | 公共逻辑抽象到 BDP.Core 工具层 |

**结论：两项需求均可行。预设是纯配置改动；空地检索需新增代码，但地基已齐。**

## 三、需求一：两套追踪预设

### 3.1 追踪模块参数全集（`HomingConfig` 全部字段）

当前 `HomingConfig` 共 24 个字段（`HomingConfig.cs`）。预设 = 完整参数包，不只两个差异字段。逐字段含义与两套预设取值见 3.2 对照表。

### 3.2 两套预设对照表

| 字段 | 含义（玩家语言） | 预设 A 标准 | 预设 B 弱追踪 |
|---|---|---|---|
| `InitialSegmentTriggerRatio` | 飞过全程多少比例后才开始追踪 | **0.5** | **0.9** |
| `MaxRelocks` | 追丢后最多重锁几次 | **2** | **0** |
| `HitWindow` | 追到目标多近算"必中"（格） | 0.85 | 0.85 |
| `LossBehindAngle` | 目标落到身后多少度算丢失 | 115 | 115 |
| `LossDistanceGrowthTolerance` | 目标距离增长容忍度（格） | 0.2 | 0.2 |
| `RelockWindow` | 重锁飞行距离（格） | 7.5 | 7.5* |
| `MinClosingDistance` | 最小接近距离（当前未消费，见 3.4） | 0.05 | 0.05 |
| `MaxTurnAngleWhenEvading` | 追踪时最大转角（度） | 18 | 18 |
| `PursuitMinTurnAngle` | 追踪最小转角（度） | 0 | 0 |
| `PursuitTurnResponsiveness` | 追踪转向响应度（0~1） | 0.3 | 0.3 |
| `StaticTargetAngleBypassDistance` | 静态目标角度旁路（当前未消费，见 3.4） | 0.18 | 0.18 |
| `PredictionLeadRatio` | 追踪提前量比例 | 0.35 | 0.35 |
| `RelockLeadRatio` | 重锁提前量比例 | 0.18 | 0.18* |
| `RelockTurnAngle` | 重锁转角（度） | 26 | 26* |
| `RelockMinTurnAngle` | 重锁最小转角（度） | 2 | 2* |
| `RelockTurnResponsiveness` | 重锁转向响应度 | 0.36 | 0.36* |
| `SoftReleaseDistance` | 软释放距离（格） | 2.4 | 2.4 |
| `HardReleaseDistance` | 硬释放距离（格） | 1.6 | 1.6 |
| `ReleaseDistanceDecayPerRelock` | 每次重锁后释放距离衰减量 | 0.3 | 0.3* |
| `CurveArcStrength` | 曲线弧度强度 | 0.45 | 0.45 |
| `InertiaWeight` | 惯性权重 | 0.7 | 0.7 |
| `CaptureWeight` | 捕获权重 | 0.85 | 0.85 |
| `TerminalFlyAwayDistance` | 脱靶飘飞距离（格） | 5.5 | 5.5 |
| `PerEmitVariance` | 每发随机方差 | 0.2 | 0.2 |

> 标注 `*` 的字段：在预设 B（`MaxRelocks=0`）下，重锁路径永不进入，这些字段**名义存在但不生效**（成为死参数）。保留原值是刻意为之——保留默认值可避免未来启用重锁时还要回填，也避免破坏存档序列化。

### 3.3 落地方式（推荐：两个 moduleDef）

已验证现有配置继承链（`RangedAttackModuleResolver.cs L81-91`）：

```
挂载 config（mount.config） > 模块 Def defaultConfig（moduleDef.defaultConfig）
```

运行时通过 `Activator.CreateInstance(runtimeClass)` 创建模块实例，配置从 Def 读入——**两个不同 Def 指向同一个 runtimeClass 完全可行，运行时零感知差异**。

**推荐方案 A：新增第二个 moduleDef（零代码，纯 XML）**

```xml
<!-- 新文件或并入 Homing.xml -->
<BDP.Core.AttackExecution.BdpRangedAttackModuleDef>
  <defName>BDP_HomingModule_Weak</defName>
  <label>制导追踪模块（弱）</label>
  <runtimeClass>BDP.Content.RangedModules.Homing.HomingModule</runtimeClass>
  <defaultConfig Class="BDP.Content.RangedModules.Homing.HomingConfig">
    <InitialSegmentTriggerRatio>0.9</InitialSegmentTriggerRatio>
    <MaxRelocks>0</MaxRelocks>
    <!-- 其余字段沿用默认，可选显式写出 -->
  </defaultConfig>
</BDP.Core.AttackExecution.BdpRangedAttackModuleDef>
```

- 现有 `BDP_HomingModule_Strong` 保持强追踪参数 = 预设 A。
- 芯片想用哪套，就挂哪个 `moduleDef`（`<li><moduleDef>BDP_HomingModule_Weak</moduleDef></li>`）。
- 优点：预设是命名实体、可复用、可被多个芯片引用；完全贴合"预设方案"语义；零代码。

**备选方案 B：一个 moduleDef + 挂载级 `config` 覆盖**

- 挂载点写法：`<li><moduleDef>BDP_HomingModule_Strong</moduleDef><config Class="...HomingsConfig">...</config></li>`。
- 优点：不新增 Def。
- 缺点：每处挂载都要手写整套 24 个字段，不符合"预设复用"；且 XML 无现成先例（现有 Presets.xml 挂载只写 `moduleDef`），需额外验证 Def 序列化器对挂载级 `config` 多态嵌套的解析。

**推荐方案 A。**

### 3.4 死参数与备注

- `MinClosingDistance`、`StaticTargetAngleBypassDistance` 两个字段在当前 `HomingModule`/`HomingPathBuilder` 中**零读取**（仅在配置类自身 Clone/序列化中出现），属于历史遗留。本次预设设计保留默认值，不误删（删字段会影响旧存档反序列化；未来可能启用）。

## 四、需求二：空地目标 + 自动检索公共机制

### 4.1 现有设施盘点（已验证）

| 设施 | 位置 | 用途 |
|---|---|---|
| `TargetingParameters.CanTarget` 空地分支 | 原版 `RimWorld.TargetingParameters.CanTarget` | 空地（Thing==null）仅当 `canTargetLocations=true` 放行 |
| RoutePath 空地先例 | `RoutePathModule.cs L652-656` `EnableGroundTargeting` | 已有模块在 Targeting 阶段强制 `canTargetLocations=true` 的现成做法（但属 RoutePath 私有，不可直接复用） |
| 毒蛇预设空地配置 | `Presets.xml L128-138` | `canTargetLocations=true` + `DirectTargetLineOfSight=NotRequired` 已实战验证 |
| `GenClosest.ClosestThing_Global(center, searchSet, maxDistance, validator)` | 原版 `Verse.GenClosest` | **半径内找最近目标**，不依赖 Pawn 视角，正是落点寻敌工具 |
| `GenSight.LineOfSight(start, end, map)` | 原版 `Verse.GenSight` | **子弹自检索视线判定** |
| `Thing.HostileTo(thing)` | 原版 `Verse.Thing` | 敌对判定（合法目标过滤器） |
| Homing 空地格追踪 | `HomingPathBuilder.TryResolveTargetPosition L35` | 现有 LockedTarget 是 `LocalTargetInfo`，空地格照追（数据结构零障碍） |
| 目标入口双通道 | `ProjectileInitStageContext` 的 `RequestedTarget` / `FinalTarget` | Homing 现用 `FinalTarget` 优先、回退 `RequestedTarget`（`HomingModule.cs L499-507`） |

### 4.2 机制设计

**两个独立机制，务必分开建模：**

1. **玩家选目标（发射侧约束）**
   - 空地瞄准合法性由 `TargetingParameters.canTargetLocations` + 现有 `DirectTargetLineOfSight` 决定。
   - 当前阶段：`DirectTargetLineOfSight=Required`（猎犬现状），玩家**不能**选视线外目标。
   - 未来曲线投射能力落地后，再允许选视线外空地。

2. **子弹自检索（飞行侧逻辑）**
   - 触发点：子弹飞到落点（空地目标）后，进入"落点捕获"分支。
   - 原点：**子弹检索时刻的自身位置**（不是玩家、不是落点格，虽然二者此时通常重合）。
   - 范围：`AcquireRadius`（新增配置，落点寻敌半径）。
   - 视线：从子弹位置到候选目标的 `GenSight.LineOfSight` 判定（可选开关）。
   - 检索结果：`GenClosest.ClosestThing_Global` 返回半径内最近合法目标 → 更新 `LockedTarget` 为该实体 → `ContinueTracking` 转入常规追踪；找不到 → 落地/脱靶。

**新增状态/配置（`HomingState` + `HomingConfig`）：**

- `HomingConfig` 新增：
  - `AllowGroundTarget`（bool，默认 false）：是否允许空地瞄准。
  - `AcquireRadius`（float）：落点寻敌半径（格）。
  - `AcquireRequireLineOfSight`（bool，默认 true）：自检索是否要求视线。
- `HomingState` 新增：落点捕获标记（如 `AcquirePending`，或复用现有 Phase 加一个 `Acquiring` 阶段）。
- `HomingModule` 改动点：Arrival 阶段加"空地目标落点捕获"分支；ProjectileInit 阶段加"空地目标不立即锁定实体，标记待捕获"逻辑。

### 4.3 模块独立性：公共工具类

**约束**：远程攻击模块相互之间不可认识、不可依赖。RoutePath 的 `EnableGroundTargeting` 是私有实现，Homing 不能引用它，也不能复制一份私有版。

**要求**：把可复用的通用逻辑抽象到 BDP.Core 公共工具层（建议放 `BDP.Core.AttackExecution` 下的共享命名空间，如 `BdpRangedTargetAcquisitionUtility`），Homing / RoutePath / 未来模块各自调用同一工具类，互相零引用。

公共工具建议封装两件事：
1. `EnsureGroundTargetingAllowed(TargetingParameters)` —— 强制 `canTargetLocations=true`（现 RoutePath 私有逻辑上移）。
2. `FindNearestAcquirableTarget(Vector3 origin, Map map, float radius, bool requireLos, Predicate<Thing> validator)` —— 包装 `GenClosest.ClosestThing_Global` + `GenSight.LineOfSight` + 合法目标过滤器。

**工具类详细设计见附录 A。**

### 4.4 新增配置字段汇总

| 字段 | 类型 | 编码默认 | Def 默认 | 说明 |
|---|---|---|---|---|
| `AllowGroundTarget` | bool | false | false | 是否允许玩家选空地瞄准 |
| `AcquireRadius` | float | 0（表示未启用） | **5** | 落点寻敌半径；>0 才启用自检索 |
| `AcquireRequireLineOfSight` | bool | true | true | 自检索是否要求视线 |

> - `AcquireRadius` 采用"编码默认 0 + Def 默认 5"：编码层 0 表示"未显式配置、默认关闭检索"，Def 层把默认值写成 5，二者通过"0 = 回退 Def"的解析逻辑区分（与 `RangedModuleConfigNode` 现有"挂载 config 优先、回退 defaultConfig"的模式一致）。
> - 上述三字段为"空地检索"通用机制的配置，独立于 3.2 的两套追踪预设。未来若做曲线投射，可再追加"允许视野外"类开关，本次不实现。

### 4.4 新增配置字段汇总

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `AllowGroundTarget` | bool | false | 是否允许玩家选空地瞄准 |
| `AcquireRadius` | float | 待定（建议 3~5） | 落点寻敌半径 |
| `AcquireRequireLineOfSight` | bool | true | 自检索是否要求视线 |

> 上述三字段为"空地检索"通用机制的配置，独立于 3.2 的两套追踪预设。未来若做曲线投射，可再追加"允许视野外"类开关，本次不实现。

### 4.5 视野约束现状与未来

- **现状**：玩家选空地受 `DirectTargetLineOfSight` 约束（猎犬 `Required`）。空地自检索属于飞行侧逻辑，不改变发射侧约束。
- **未来（本次不做）**：曲线投射（迫击炮式）允许玩家选 Pawn 视线外目标，届时在发射侧放开视野限制，并可能让弹道走"越顶"（flyOverhead）路径。

## 五、预期表现（玩家视角）

### 预设 A（标准追踪，现猎犬）

不变：子弹半程后开始绕弧追人，追丢可急转弯重锁两次，命中率高，是"强追踪导弹"。

### 预设 B（弱追踪）

- 弹出膛后 90% 路程与普通子弹完全一致（直飞，可被掩体挡）。
- 最后 10%（约 3 格）才微微拐弯。
- 追丢**立即**沿当前方向飘 5.5 格消失，零补救、不误伤路人。
- 静止目标通常仍能中；横移快的目标基本追不上。
- 手感 = "末端带轻微修正的直射"，命中率明显低于标准追踪，符合"弱性能追踪"定位。

### 空地自动检索（叠加在任意预设上）

- 瞄准环可点地面（掩体前、敌人必经处、建筑旁空地）。
- 子弹直飞落点，到点后以自身位置为圆心扫一圈，咬住**最近**敌人开始追踪。
- 落点附近无敌人 → 弹落空/飘走，无伤害。
- 战术价值：打"提前量"——朝敌人即将跑到的地面开火，弹到那附近自动咬住跑进范围的目标。
- 与预设 B 叠加 = "要预判走位的弱追踪武器"，命中率低但有技巧感。

## 六、决策结论（已确认）

1. **预设落地方式**：✅ **方案 A**（两个 moduleDef：`BDP_HomingModule_Strong` 强追踪 + `BDP_HomingModule_Weak` 弱追踪，共享 runtimeClass）。
2. **`AcquireRadius` 默认值**：✅ 编码默认 `0`（= 未启用检索），Def 默认 `5`。
3. **公共工具类**：✅ 见附录 A 详细设计。
4. **弱追踪预设转向能力**：✅ 保持不动（18° 转角、0.3 响应度不变），先跑通，游戏实测后再调。
5. **空地检索失败后的行为**：✅ 落地（地面空放，无伤害）。

## 附录 A：公共工具类详细设计

### A.1 定位与命名

- **类名**：`BdpRangedTargetAcquisitionUtility`
- **命名空间**：`BDP.Core.AttackExecution`（与远程攻击协议层同层，供 Homing/RoutePath/未来模块共用，不依赖任何具体模块）
- **文件位置**：`Source/BDP/Core/AttackExecution/BdpRangedTargetAcquisitionUtility.cs`
- **性质**：`internal static`（模块协议内部公共工具，不暴露为 mod API）

### A.2 职责边界

只做"目标检索"这一件事的几何与合法性判定，**不碰**：
- 不碰阶段调度、不碰投射物生命周期、不碰命中/伤害结论。
- 不认任何具体模块（不引用 Homing/RoutePath/AreaExplosion）。
- 只依赖原版 `Verse`/`RimWorld` 与 BDP 协议层已有的中性类型。

### A.3 方法一：强制空地瞄准

```csharp
internal static void EnsureGroundTargetingAllowed(TargetingParameters parameters)
{
    if (parameters == null) return;
    parameters.canTargetLocations = true;
}
```

- **来源**：上移 RoutePath 现有 `EnableGroundTargeting` 的私有逻辑（RoutePathModule.cs L652-656）。
- **用途**：在 Targeting 阶段，让"原本不可瞄地"的 verb 临时允许点地面。
- **调用方**：Homing 模块在 `ITargetingStageModule.Contribute`（或 BDP 的 Targeting 协议回调）里，当配置 `AllowGroundTarget=true` 时调用。
- **为何上移**：RoutePath 已证明这是通用需求（毒蛇靠它瞄地），Homing 也要用，按"模块互不依赖"约束抽象成公共工具。

### A.4 方法二：落点半径寻最近合法目标

```csharp
internal static LocalTargetInfo FindNearestAcquirableTarget(
    Vector3 origin,            // 子弹检索时刻自身位置（平面坐标）
    Map map,                   // 当前地图
    Faction hostileToFaction,  // 敌对基准派系（来自弹体 Launcher.Faction）
    float radius,              // 检索半径（>0）
    bool requireLineOfSight,   // 是否要求从 origin 到目标的视线
    Predicate<Thing> extraValidator)  // 附加合法性过滤（可 null）
```

**实现要点（全部基于已验证的原版 API）：**

1. **候选集合**：`map.attackTargetsCache.TargetsHostileToFaction(hostileToFaction)`（public，返回 `HashSet<IAttackTarget>`）。
2. **规避 HashSet 强转陷阱**：`GenClosest.ClosestThing_Global` 的 `searchSet` 参数是 `IEnumerable`，其内部对 `IList<Thing>/IList<Pawn>/IList<Building>/IList<IAttackTarget>` 走快速分支，其余类型走 `foreach (Thing item in searchSet)` 强转。`HashSet<IAttackTarget>` 不属于上述四类，会走强转兜底分支——**IAttackTarget 的实现者均为 Thing，强转安全**；但为了可读性与避免隐式风险，工具类内将 HashSet 先物化为 `List<IAttackTarget>` 再传入（命中 `IList<IAttackTarget>` 快速分支，行为明确）。
3. **距离过滤**：`radius` 直接作为 `ClosestThing_Global` 的 `maxDistance`（该函数内部按水平距离平方比较，已含半径语义）。
4. **视线过滤**：`requireLineOfSight=true` 时，在 `validator` 里追加 `GenSight.LineOfSight(origin.ToIntVec3(), thing.Position, map)`。
5. **合法性**：`validator` = 目标未摧毁 + 存活（若为 Pawn 则 `!Downed`）+ `extraValidator`（可空）。
6. **返回**：命中最近者则 `new LocalTargetInfo(thing)`；否则 `LocalTargetInfo.Invalid`（供调用方走"落地空放"分支）。

**关键语义**：检索原点用**子弹自身位置** `origin`，而不是玩家、不是落点格——这落实了"子弹自检索以自身位置做范围和视线判定"的要求。`hostileToFaction` 从 `ArrivalStageContext.Launcher.Faction` 取得（弹体 Launcher 在 Arrival 上下文已提供），工具类自身不关心这个派系从哪来。

### A.5 调用关系

```
HomingModule（Targeting 阶段）  ──►  BdpRangedTargetAcquisitionUtility.EnsureGroundTargetingAllowed
HomingModule（Arrival 阶段落点捕获）──►  BdpRangedTargetAcquisitionUtility.FindNearestAcquirableTarget
RoutePathModule（未来可选重构）    ──►  （同一工具类，替换其私有 EnableGroundTargeting）
```

三个模块之间仍然零直接引用，只各自依赖公共工具 + 原版 API。

### A.6 与"玩家选目标"的区分

| 维度 | 玩家选目标 | 子弹自检索 |
|---|---|---|
| 触发时机 | 瞄准阶段 | 飞行到落点后 |
| 原点 | 玩家 Pawn | 子弹自身位置 |
| 范围约束 | verb 射程 + 视线（`DirectTargetLineOfSight`） | `AcquireRadius` + 可选视线 |
| 合法性 | `TargetingParameters.CanTarget` | `HostileTo` + 存活 + 自定义 |
| 视野外 | 当前禁止 | 不受玩家视野限制（由弹体自身判定） |

> 当前两者在"视野外"上的差异是有意为之：玩家仍受直射视线约束（不能点视野外），但子弹飞到落点后，若落点附近视野内有敌人，子弹可按自身位置判定并咬住——这不违反"玩家不能选视野外"的限制，因为玩家瞄准的是落点（视野内），咬人是飞行侧行为。
