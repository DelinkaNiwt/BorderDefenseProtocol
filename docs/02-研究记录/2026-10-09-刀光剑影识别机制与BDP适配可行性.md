# 刀光剑影识别机制与 BDP 适配可行性

日期：2026-10-09。范围：前置研究，不实施兼容补丁，不改变攻击或绘制逻辑。

## 结论

可以适配。只让 BDP 的实际近战攻击选择正确刀光，复杂度低至中；再让刀光尺寸跟随表达出来的武器，复杂度中等。让每种动态芯片进入刀光剑影设置页并分别保存设置，复杂度中至高；同步扩展真实攻击距离，复杂度高，应另立范围。

核心错位不是“攻击完全没被捕获”，而是刀光剑影优先把装备物品定义当作武器身份。BDP 的装备来源是触发体，实际招式则来自动态表达，二者不能等同。

建议先做实际攻击刀光类型的最小兼容，再评估尺寸读取；设置页和真实射程留作独立后续事项。

## 一、怎样识别加载的近战武器

它有不同用途的入口，不能把设置页筛选条件当作所有播放条件。

### 设置页武器目录

`DGJY_MeleeWeaponCatalog.EnsureInitialized / IsMeleeWeapon`（武器目录初始化与筛选）扫描 `DefDatabase<ThingDef>.AllDefsListForReading`（全部已加载物品定义列表），首次需要时初始化，并提供重新构建入口。

进入目录须同时满足：

1. 定义存在，物品类别为 `Item`（物品）。
2. `tools`（近战工具列表）存在且非空。
3. `Verbs`（攻击配置列表）中没有任何非近战配置。

没有额外要求原版 `IsWeapon`（是否武器）标志，也没有要求必须是主装备。若一把枪有近战工具但同时存在远程攻击配置，仍被整个排除。反之，仅满足这些条件的其它物品也可能入列。列表按定义、显示名和所属模组组织，不扫描每个角色当前表达出来的攻击。

### 扩展距离数据库

`DGJY_WeaponReachDatabase.LooksLikeMeleeWeapon / Initialize / TryGetData`（距离数据库筛选、初始化、查询）另有一道条件：`equipmentType == Primary`（装备类型为主装备）。它预先按物品定义计算并缓存距离数据，也可补算后来查询的符合条件定义。

### 实际播放入口

`DGJY_Verb_MeleeAttack_TryCastShot_Patch`（原版近战发动补丁）监听原版 `Verb_MeleeAttack.TryCastShot`（实际近战尝试），不要求先出现在设置页目录。

攻击前，角色须已生成在地图上、具有姿态追踪器且没有全身忙碌；`DGJY_ContextBuilder.Build`（构建播放上下文）保存角色、目标、当前工具、伤害类型、装备来源和游戏刻。攻击后，原方法确实运行且上下文有效才进入播放服务。这里没有要求实际命中，因此正常未命中或闪避也可播放挥击效果。

## 二、怎样决定刀光类型

`DGJY_MeleeVfxClassifier.ClassifyDetailed`（详细分类）按下列顺序判断，先识别成功就返回：

```text
装备来源的整份物品定义
    ↓ 未识别
身体拳击工具对应的主装备视觉回退
    ↓ 未识别
本次攻击的 Tool（近战工具）
    ↓ 未识别
本次 DamageDef（伤害定义）名称
    ↓ 未识别
Unknown（未知）
```

整份装备的判断由 `ClassifyEquippedWeapon / ScoreWeaponTools / PickScoreCategory`（装备分类、工具评分、类别选择）完成，结果按物品定义缓存：

- 每个工具以 `power`（威力）作为基本权重，非正数时用 1。
- 手柄、握把、剑首等英文工具标签的权重乘 0.2；`Poke`（轻戳）能力权重乘 0.25。
- 按工具能力名称给类别累计评分；从 `ManeuverDef`（近战招式定义）取得对应伤害类型后，再以 0.6 的权重补充评分。
- 名称、标签、武器类别的关键词类别，若得分达到最高类别的 75%，可以胜出；否则取最高分。等分时依次优先斩击、刺击、钝击、拳击、爪击、撕咬。
- 工具没有提供有效评分时，可回退到装备文字关键词。

当前工具的回退判断较简单：先识别拳击；再依工具能力顺序取第一个识别成功的类别；最后查工具标签。它不是重新对当前工具做整套装备加权。

| 刀光类别 | 关键词示例与含义 |
|---|---|
| Slash（斩击） | Cut（切割）、Slash（斩）、Blade（刀刃）、Sword（剑）、Knife（刀）、Axe（斧）等 |
| Stab（刺击） | Stab（刺）、Pierce（穿刺）、Spear（矛）、Spike（尖刺）、Poke（轻戳）等 |
| Blunt（钝击） | Blunt（钝击）、Bash（砸）、Hammer（锤）、Mace（钉锤）、Club（棍棒）等 |
| Punch（拳击） | Fist（拳头）、Punch（拳击）、“拳” |
| Claw（爪击） | Scratch（抓）、Claw（爪）、Talon（利爪） |
| Bite（撕咬） | Bite（咬）、Jaw（颌）、Teeth（牙）、Fang（尖牙）等 |
| Unknown（未知） | 上述均无法识别 |

关键词按固定先后匹配，组合名称可能同时命中多个词，不能理解为精确的武器语义分析。

分类完成后，`DGJY_MeleeVfxService.TryPlay`（播放服务）选择该类别的 `DGJY_MeleeVfxProfileDef`（效果配置），经过阵营、自然攻击、排除、概率和去重等开关，再交给原有生成器。玩家手动武器视觉覆盖用于替换效果纹理，不能据此认为它会重写攻击类别或战斗距离。

## 三、怎样决定“距离”和刀光尺寸

这里有两种独立数值：真实可攻击距离与视觉效果尺寸。刀光形状类别也不等于距离类别。

### 距离归类

优先级为：玩家手动距离类别 > 显式武器定义规则 > 自动关键词推断。

| 距离类别 | 基础距离 | 自动推断形状 |
|---|---:|---|
| Short（短） | 1.42 | 匕首、短刀 |
| Normal（普通） | 2.0 | 剑、刀、斧、锤、钉锤、棍棒；无法识别也落此档 |
| Long（长） | 3.0 | 杖、长棍 |
| Polearm（长柄） | 3.0 | 矛、戟、长柄镰等 |

自动推断读取定义名、显示名、武器标签、武器类别名与显示名，以及全部工具标签和能力名与显示名。形状关键词有顺序，例如“杖”先于钉锤类别匹配。尺寸与重量会影响某些判断说明或可信度，当前未知形状的最终距离档仍为普通；并不存在“大且重就一律变长”的规则。

运行时查询确认的显式规则：

- 匕首、刀、短刀：短档 1.42。
- 短剑、长剑、单分子剑、等离子剑及规则列出的变种：普通档 2。
- 棍棒、钉锤、战锤、宙斯锤等：普通档 2。
- 矛、伊夸、长矛：长柄档 3。
- 灵能杖、杖、长棍：长档 3。
- 名为“观察到的镰式长柄”规则，实际是精确指定 `KT_SealScythe`，并非给所有镰刀无条件套用。

`FillMetrics / FinalRangeFor`（填充指标、最终距离）计算：

```text
贴图尺寸 = drawSize（绘制尺寸）两个分量绝对值的较大值；无效回退 1
默认：最终距离 = max(1.42, 基础距离)
开启按贴图缩放距离：最终距离 = max(1.42, 基础距离 × sqrt(贴图尺寸 / 1))
```

默认 `extendedMeleeReachEnabled=false`（扩展真实近战距离关闭），`scaleReachByWeaponGraphicSize=false`（按贴图尺寸缩放距离关闭）。因此表中 2、3 是它计算的扩展距离档，并不意味着默认安装就能隔两三格攻击。

### 刀光尺寸

`DGJY_WeaponVisualDatabase.GetEffectScaleFactor`（效果尺寸系数）默认开启动态尺寸。斩击、刺击、钝击、爪击可以读取视觉装备来源定义的绘制尺寸，使用线性尺寸倍率；不是上面真实距离的平方根倍率。

仅在扩展真实距离开关同时启用时，额外乘距离类别视觉倍率：短档 0.7，普通档 1，长档和长柄档 1.5。该倍率取距离类别，并不直接取最终距离数值。最后乘全局倍率，其设置值限制为 0.5 至 1.5。

所以一把剑可以同时是“斩击刀光、普通距离档、因大贴图而较大刀光”；这三项来自不同步骤。

## 四、BDP 为什么只被识别成触发体

已确认的代码链：

1. `CompTriggerBody`（触发体组件）继承原版 `CompEquippable`（装备组件）。`BdpVerb_FormalHostMelee.InitializeFormalHost`（近战正式宿主初始化）将攻击绑定到它的攻击追踪器。
2. 原版 `Verb.EquipmentSource`（攻击的装备来源）返回该装备组件的父物品，所以这里得到触发体，而不是生成攻击的芯片。
3. `BdpVerb_MeleeAttackDamage.TryCastShot`（BDP 近战实际尝试）通过自身检查后调用原版方法。连击内部还会临时解除自己的间隔忙碌姿态，所以刀光剑影现有的原版入口仍有机会捕获各次合法挥击。
4. 正式宿主的运行时 `tool` 和 `verbProps`（工具、攻击属性）来自实际表达；刀光剑影上下文确实读取这些字段，但分类先看触发体定义。
5. 当前标准触发体定义含 `Blunt`（钝击）工具；弧月、蝎子表达则含 `Cut`（切割）工具。由现有分类顺序推导，触发体钝击类别成功后，会先返回，实际切割工具不会继续参与。此具体显示结果尚需游戏内日志确认。

静态目录还有第二层限制：`Chips.xml` 中成品统一使用 `BDP_Chip_Custom`（通用芯片物品定义），没有顶层近战工具，绘制尺寸 0.85 代表芯片物品图。不同武器的工具位于制造配置的表达条目内，弧月和蝎子当前实际武器视觉则使用绘制尺寸 1.2 的弧月视觉预设。

因此，给通用芯片补静态工具、简单替换装备来源、或添加一条按芯片定义名的规则，都不能完整解决：各芯片与各形态仍共用定义及缓存，图标尺寸也不等于实际武器尺寸。

## 五、适配范围、复杂度与风险

| 范围 | 可行性与复杂度 | 主要工作及边界 |
|---|---|---|
| 当前攻击正确选刀光类别 | 高，低至中 | 在 BDP.Compatibility（兼容程序集）建立可选适配器，仅识别 BDP 实际近战；让当前工具、当前伤害优先，复用外部效果配置和播放流程 |
| 刀光尺寸跟随表达武器 | 高，中 | 需要对应正式结果的实际视觉尺寸；当前公开结果快照未直接提供视觉预设字段，须继续核实公开读面，必要时另提最小中性读取口 |
| 设置页分列弧月、蝎子、形态或组合，并各自保存覆盖 | 可行，中至高 | 外部目录、覆盖设置和缓存均按物品定义组织；需要动态身份到配置项的桥接、稳定保存键和界面支持，不能靠一条定义补丁完成 |
| 扩展真实攻击距离 | 可行但需专项验证，高 | 外部修改攻击距离、攻击线和原版追敌动作；BDP 自有任务先要求接触目标，必须统一追敌、射程、遮挡与逐击合法性，单改距离数值无效 |

### 建议的最小路线

第一步只做实际近战类别适配。可在 `DGJY_ContextBuilder.Build`（上下文构建）后记录该上下文对应的 BDP 攻击身份，再对 `ClassifyDetailed`（分类结果）做限定处理；这样保留原有播放入口与阵营、概率等行为。具体补丁数量和字段访问方式在实施设计时定稿。

不改真实 `Verb.EquipmentSource`（装备归属），不修改全局触发体或通用芯片定义，也不把 BDP 攻击伪装成自然攻击。真实装备归属还服务原版属性、伤害记录及 BDP 资源归属；将播放上下文来源清空，则又会影响自然攻击筛选和主装备回退。

`BdpVerb_MeleeAttackDamage.ResultId`（表达结果标识）与 `ExpressionSurfaceAccess.TryGetPublishedResult`（按标识读取公开结果）可用于确认实际来源、模式、主副侧及组合关系；`TriggerSurfaceAccess.ResolveLoadoutReader`（装载读取口）可取得芯片实例。不能只猜当前主手芯片，也不能把当前物品定义名当成每种武器的唯一身份。

第二步如需尺寸适配，读取实际表达视觉，而非 0.85 的芯片图标；尊重刀光剑影动态尺寸和全局倍率开关。若要补公开视觉读面，应只暴露已成立的中性结果，不让 Core（核心程序集）认识外部刀光类别。

兼容层复用现有 `CompatibilityHost`（兼容宿主）的可选发现、独立补丁标识与禁用机制；通过运行时反射定位外部类型和成员，不新增外部程序集硬依赖。外部模组缺失或必要成员变更时，只停用适配器。

### 必须留意的兼容点

- **缓存身份：**外部类别、尺寸和距离按物品定义缓存。同一触发体下切换芯片、形态或组合，不应复用触发体定义缓存代替当前结果。公开结果读取会构造快照，也应按攻击需要读取，避免逐帧全量重建。
- **连击时序：**应跟随原有实际挥击入口，正常未命中仍能播放；目标预检查失败则不产生额外效果。不要再订阅攻击完成事件重复播放。当前蝎子三击间隔 5 游戏刻，现有按同刻去重本身不会合并这三击。
- **同刻双击：**外部去重键为角色、目标格、效果配置及游戏刻，没有攻击或芯片身份。未来同刻同目标同类别的双攻击可能被合并；是否改去重要先明确视觉需求。
- **特殊攻击边界：**通过原版近战入口的攻击可复用该路线；能力、投射物或特殊范围伤害须逐类确认，不能因玩家称为“刀”就保证都会触发刀光。
- **真实距离：**外部 `GetWeaponDef`（取得武器定义）仍读触发体来源；`TryGetExtendedRangeData`（取得扩展距离）没有排除 BDP。启用其扩距选项时，可能已有按触发体定义介入距离的行为；BDP 任务又强制 `PathEndMode.Touch`（接触寻路）。两边不能假定天然同步。
- **外部更新：**当前有公开可调用方法，但未发现通用的动态武器身份接入协议；反射与 Harmony（运行时补丁）仍依赖具体成员形状，需要安装和升级时检查。

## 六、后续验证建议

主线：先设计并实施“实际近战刀光类型”适配，在 Development（开发程序集）加可移除日志，记录结果标识、真实装备来源、当前工具、最终类别与播放次数；游戏内验证弧月、蝎子三连击、钝击工具、芯片切换、未命中、目标离开和卸载外部模组。

随后再检查实际视觉尺寸的公开读取边界，验证动态尺寸开关和倍率。按芯片独立设置、特殊能力刀光及扩展真实距离属于支线；它们需要各自确定范围后再实施。

本轮交付只有研究记录与工作日志，没有安装兼容补丁，也没有声称游戏内兼容已经验证。
