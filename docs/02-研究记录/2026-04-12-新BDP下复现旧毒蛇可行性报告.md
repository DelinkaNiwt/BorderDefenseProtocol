# 新 BDP 下复现旧“毒蛇”可行性报告

## 结论先说

### 结论 1：核心机制复现，**可行**

能复现的核心包括：

- 5 发齐射。
- 每发低伤害普通命中。
- 先看第一段是否合法。
- 子弹按锚点逐段折线飞行。
- 中间锚点只转向，不结算。
- 中途被拦截就地结束。
- 整套逻辑作为**外部可插拔模块**挂在新 BDP 骨架上。

### 结论 2：旧毒蛇的 1:1 输入表象，**目前不完全可行**

卡点不在飞行后半段，而在**目标交互输入层**。

现在主模组公开给模块读到的 `TargetingInputFrame`（目标输入帧）只有：

- 当前悬停目标
- 当前选中目标
- 是否请求确认
- 是否请求取消

它没有：

- `Shift`（键盘修饰键）
- 鼠标按键种类
- “这次点击是加锚点还是收尾确认”的显式事实
- 已采集锚点列表的通用输入字段

所以：

- **旧毒蛇那种“Shift + 左键 连续加锚点，普通左键收尾”的原样操作，不够条件直接做。**
- 但**下半身飞行和发射骨架已经够了**，只差上半身输入事实暴露不足。

## 一张图看懂：哪里能做，哪里卡住

```text
旧毒蛇需求
   |
   +-- 多步手动设锚点输入 --------- 目前卡住（主模组中性输入事实不够）
   |
   +-- 预览路径 / 最终落点 --------- 可做
   |
   +-- 第一段 LOS 合法性 ---------- 可做
   |
   +-- 5 发齐射 ------------------- 可做
   |
   +-- 折线逐段飞行 --------------- 可做
   |
   +-- 中途拦截即终止 ------------- 可做
   |
   +-- 普通命中非爆炸 ------------- 可做
```

## 1. 为什么说“核心机制可行”

因为新 BDP 的下半段基础设施已经齐了：

- `Fire`（发射展开）阶段能把发射数改成 5。
- `ProjectileInit`（投射物初始化）阶段能给每一发设置发射目标、当前目标、速度倍率等。
- `BdpVerb_Shoot`（远程宿主动作）会实际吃 `LaunchTarget`（真正发射朝向），所以第一段朝向是能控的。
- `Flight`（飞行）+ `Arrival`（到达）阶段能逐段改下一段目的地。
- `Impact`（落地效果）阶段可以保留原版普通子弹命中，不强行加爆炸。
- 模块私有上下文可以冻结进 `RangedModuleContextSnapshot`（模块上下文快照），再跟着 `ProjectileInitPlan`（投射物初始化计划）一路传到飞行后半段。

换句话说：

- **“飞出去以后怎么走”这件事，新 BDP 已经完全够做毒蛇。**

## 2. 真正卡住的地方是什么

不是发射，不是飞行，也不是命中。

真正卡住的是：

- 玩家第一次左键，模块怎么知道这是“加锚点”还是“最后确认”？
- 玩家有没有按 `Shift`？
- 模块怎么在不自起一套独立 `Targeter`（目标选择器）的前提下，复用主模组的中性交互骨架完成旧毒蛇那套手势？

基于当前代码，答案是：

- **不知道。**

所以严格按你给的硬条件：

- 不改主模组。
- 不另起独立复杂系统。
- 尽量复现旧毒蛇的输入和外在表现。

那么结论就必须是：

- **严格 1:1 版，现在不成立。**

这不是想象出来的，而是当前输入接口确实没把这些事实暴露出来。

## 3. 如果接受“核心机制优先，输入表象暂不 1:1”，那该怎么落

### 应放在哪里

建议全部放在**测试模组 `BorderDefenseProtocol.DevHarness`（开发测试模组）**，而不是主模组里。

大致落点：

- 模块 Def（定义）：
  - `模组工程/BorderDefenseProtocol.DevHarness/1.6/Defs/Pawn/Expressions/Test/`
- 模块 C#（代码）：
  - `模组工程/BorderDefenseProtocol.DevHarness/Source/BDP.DevHarness/RangedModules/`
- 参考样例：
  - `模组工程/BorderDefenseProtocol.DevHarness/1.6/Defs/Pawn/Expressions/Test/RangedAttackModuleDefs_Test.xml`
  - `模组工程/BorderDefenseProtocol.DevHarness/Source/BDP.DevHarness/RangedModules/Samples/RangedTeachingSkeletonModule.cs`

### 应该长成什么

不是去做一个“毒蛇专用小系统”，而是：

- 先准备一个测试芯片表达条目。
- 这条条目声明一个远程 `Verb`（动作）基线。
- 然后把“毒蛇业务”作为 `RangedModules`（远程模块）挂上去。

也就是：

```text
测试芯片表达条目
   + 远程 Verb 基线
   + 毒蛇远程模块
   = 新 BDP 里的“毒蛇”
```

## 4. 这个“毒蛇模块”大致该分几段做

### A. 表达条目基线

表达条目本身负责给出旧毒蛇最基础的壳：

- 远程攻击。
- 射程约 40。
- 暖机约 1.0 秒。
- 基础投射物 Def（定义）使用 `BdpProjectile`（统一投射物宿主）兼容弹。
- 伤害约 5，护甲穿透约 0.15。
- 音效、图标、文案尽量贴近旧毒蛇。

### B. `Fire`（发射展开）阶段

这里负责旧毒蛇最醒目的外形：

- 把发射数改成 5。
- 视需要给每发补一点起点散布 / 偏移。
- 保持“普通命中弹”语义，不做爆炸弹。

### C. `ProjectileInit`（投射物初始化）阶段

这里负责把“第一段该朝哪飞”写进计划：

- 如果有手动路径，就把第一段目标写进 `LaunchTarget`。
- 把当前的路径状态冻结进模块私有上下文快照。
- 后半段飞行只读快照，不回头读玩家交互临时状态。

### D. `Flight`（飞行）+ `Arrival`（到达）阶段

这里才是真正的“毒蛇飞行脑子”：

- 记录当前还剩几个锚点。
- 每到一个锚点，就把下一段目的地写回去。
- 中间锚点只负责继续飞，不负责结算。
- 如果已经进入最终段，就把当前目标切到最终目标。
- 如果中途撞墙 / 护盾 / 拦截导致正常 `Impact`（落地），那就结束，不再续飞。

### E. `Impact`（落地效果）阶段

旧毒蛇本质是普通命中弹，所以这里最重要的不是“加东西”，而是**别多做**：

- 保留原版基线直接伤害。
- 不做范围爆炸。
- 不做锚点爆炸。
- 不做额外复杂特效逻辑。

## 5. 如果以后主模组补齐输入事实，严格版该怎么接上

一旦主模组以后补出中性输入事实，比如：

- 修饰键状态
- 鼠标点击种类
- 本轮输入动作种类
- 更正式的多步锚点输入快照

那严格版旧毒蛇就能直接接上，而且**不用推倒重来**。

因为下半段本来就已经能用。

届时只需要把上半段补上：

- `Targeting`（目标选择）阶段：识别 `Shift + 左键` 为“添加锚点”。
- `Preview`（预览）阶段：画发射点 -> 锚点们 -> 最终目标的折线。
- `Confirm`（确认）阶段：把锚点列表冻结进模块私有上下文。

后面的 `Fire / ProjectileInit / Flight / Arrival / Impact` 都可以原封不动继续复用。

这说明新 BDP 的方向其实是对的：

- **骨架没问题。**
- **差的是输入上游的中性事实还不够。**

## 6. 最稳妥的结论

如果你问的是：

### “能不能在不改主模组的前提下，做一个完全等同旧毒蛇操作手感的版本？”

- **现在不能。**
- 原因是上游输入协议不够，模块拿不到区分“加锚点”和“收尾确认”的必要事实。

### “能不能在新 BDP 骨架上做出旧毒蛇的核心战斗效果，而且还是外部可插拔模块？”

- **能。**
- 重点位置在 `Fire`、`ProjectileInit`、`Flight`、`Arrival`、`Impact`。
- 真正需要补的不是飞行骨架，而是更中性的目标交互输入事实。

## 7. 不应该怎么做

为了守住新 BDP 的定位，下面这些做法都不对：

- 在主模组硬写“毒蛇专用逻辑”。
- 直接复制旧 BDP 的独立 `Verb`（动作）/ `Projectile`（投射物）系统过来。
- 绕开 `AttackExecution`（攻击执行）和 `BdpVerb_Shoot`（远程宿主动作）自己发子弹。
- 把业务入口塞进投射物 Def（定义）里，而不是表达条目里。
- 为了做出旧表象，反过来破坏新 BDP 的中性骨架。
