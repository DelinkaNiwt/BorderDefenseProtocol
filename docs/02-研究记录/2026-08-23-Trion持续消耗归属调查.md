# Trion 持续消耗归属调查

日期：2026-08-23  
范围：BDP 主模组当前工作区源码、Def 配置和已有架构测试  
主题：芯片表达与战斗体维护的 Trion 持续消耗边界

## 一、结论先行

当前中央 Trion 账本中，芯片表达和战斗体维护是两条不同的注册路线：

| 类型 | 直接注册者 | 注册依据 | 注销依据 | 是否由 Hediff 实例直接决定 |
| --- | --- | --- | --- | --- |
| 芯片状态表达 | `ExpressionSustainDrainService`（表达持续费用服务） | 最终有效表达结果 | 表达结果失效、芯片停用或投影清空 | 否 |
| 战斗体维护 | `CombatBodySessionTrionBinding`（战斗会话 Trion 绑定器） | `CombatBodyPhase.Active`（战斗体 Active 阶段） | 战斗体退出 Active、崩解收尾或运行时清理 | 否 |

两者都可能在 Pawn 身上表现为 Hediff，但当前架构中 Hediff 都是表现或宿主投影，不是持续 Trion 账单的直接 owner（所有者）。

## 二、中央账本共同机制

Trion 组件保存一个持续消耗登记表。外部系统通过 `ITrionCommands.RegisterDrain`（注册持续消耗）和 `UnregisterDrain`（注销持续消耗）维护登记表；`CompTrion.CompTick`（组件游戏时钟）再把所有登记项聚合，按每秒速率折算后扣除当前 Trion。

核心文件：

- `Source/BDP/Core/Trion/ITrionCommands.cs`
- `Source/BDP/Core/Trion/CompTrion.cs:299-308, 471-500, 641-661`
- `Source/BDP/Core/Trion/TrionDrainKey.cs`

不同业务通过不同的 `TrionDrainKey`（持续消耗身份键）分开登记：

- 芯片表达：`Expression/...`
- 战斗体维护：`CombatBody/Maintenance`

## 三、芯片表达的持续消耗

### 3.1 直接参与注册的是谁

严格说，既不是芯片实例，也不是 Hediff 实例，而是表达层的 `ExpressionSustainDrainService`。

表达发布时，`ExpressionService.SyncProjectedHosts` 先同步 Ability、Hediff 等宿主，再调用表达持续费用服务进行账本对账：

```text
ExpressionService.SyncProjectedHosts
    → DefaultExpressionHostSynchronizer.Sync
    → ExpressionSustainDrainService.Reconcile
    → Trion RegisterDrain / UnregisterDrain
```

对应位置：

- `Source/BDP/Core/Expressions/Access/Surfaces/ExpressionFormalSurfaces.cs:298-307`
- `Source/BDP/Core/Expressions/Runtime/ExpressionSustainDrainService.cs:19-60`

### 3.2 持续费率来自哪个字段

芯片本体级 `ChipTrionConfig` 不再拥有持续消耗字段，只保留：

- `CapacityCost`（容量占用）
- `ActivationCost`（一次性激活费用）

对应文件：`Source/BDP/Core/Chips/Config/ChipTrionConfig.cs:9-19`

持续费用位于表达条目的 `Trion` 参数块：

```text
ChipDefinitionConfig
└─ Expression
   └─ Entries
      └─ ChipExpressionEntryConfig
         └─ Trion
            └─ SustainCostBySourceCount
               └─ ExpressionSustainCostBySourceCountConfig
```

字段定义：

- `ExpressionSourceConfigBase.Trion`
- `ExpressionSourceTrionConfig.SustainCostBySourceCount`
- `ExpressionSustainCostBySourceCountConfig.SourceCount`
- `ExpressionSustainCostBySourceCountConfig.TotalPerSecond`

对应文件：

- `Source/BDP/Core/Expressions/Config/ExpressionSourceConfigBase.cs:47-49`
- `Source/BDP/Core/Expressions/Config/ExpressionSourceTrionConfig.cs:12-25`
- `Source/BDP/Core/Expressions/Config/ExpressionSustainCostBySourceCountConfig.cs:12-17`

XML 结构示例：

```xml
<Expression>
  <Entries>
    <li>
      <Kind>Hediff</Kind>
      <HediffDefName>BDP_TestHediff_ExpressionOnly</HediffDefName>
      <Trion>
        <SustainCostBySourceCount>
          <li>
            <SourceCount>1</SourceCount>
            <TotalPerSecond>2</TotalPerSecond>
          </li>
          <li>
            <SourceCount>2</SourceCount>
            <TotalPerSecond>5</TotalPerSecond>
          </li>
        </SustainCostBySourceCount>
      </Trion>
    </li>
  </Entries>
</Expression>
```

`UseCost`（每次使用费用）和 `MinimumRequired`（使用前最低要求）也在同一个表达 `Trion` 参数块中，但它们不是持续消耗字段。

### 3.3 芯片表达何时注册和注销

表达层先从当前激活槽位收集来源，再经过形态、组合、条件和可用性求值，形成 `FormalExpressionResult`（最终正式表达结果）。只有满足以下条件的结果才进入持续费用登记：

- `IsAvailable` 为真；
- 使用条件满足；
- 存在 `SustainCostBySourceCount` 费用表；
- 费用表解析出正数每秒费用。

相同最终 Hediff 效果按当前 `HediffDefName`（状态定义名）聚合，多个来源只登记一条账单，再按有效来源数选择 `TotalPerSecond`。

因此当前测试样例是：

- 一个有效来源：2 Trion/秒；
- 两个有效来源：合计 5 Trion/秒；
- 全部表达失效：注销该表达账单。

### 3.4 Hediff 自己消失时的边界

当前表达对账读取的是 `ExpressionSnapshot`（表达快照），不是 Pawn 当前实际持有的 Hediff 列表。

如果出现以下情况：

```text
芯片仍激活
表达结果仍有效
Hediff 因自身合法生命周期被移除
```

那么：

- 已登记的持续 Trion 暂时保留；
- 不会因为 Hediff 实例消失而自动注销；
- 下一次表达投影刷新时，系统还可能按有效表达重新补回 Hediff；
- 只有表达结果本身失效或被移除时，才会在对账中注销费用。

这说明芯片表达的真实语义是：

> “最终表达有效就收费”，而不是“实际 Hediff 实例存在才收费”。

## 四、战斗体维护的持续消耗

### 4.1 直接参与注册的是谁

战斗体维护消耗由 `CombatBodySessionTrionBinding` 直接维护，不由 `BDP_CombatBodyActive` Hediff 注册。

进入战斗体 Active 阶段后，激活事务调用：

```text
CombatBodyActivationTransaction.TryActivate
    → CombatBodySessionTrionBinding.BindActiveRuntime
    → RegisterDrain(CombatBody/Maintenance, rate)
```

对应位置：

- `Source/BDP/Core/CombatBodySession/CombatBodyActivationTransaction.cs:94-118`
- `Source/BDP/Core/CombatBodySession/CombatBodySessionTrionBinding.cs:63-110`

战斗体退出时：

```text
CombatBodyExitTransaction.Execute
    → CombatBodySessionTrionBinding.ClearActiveRuntime
    → UnregisterDrain(CombatBody/Maintenance)
```

对应位置：

- `Source/BDP/Core/CombatBodySession/CombatBodyExitTransaction.cs:78-86`
- `Source/BDP/Core/CombatBodySession/CombatBodySessionTrionBinding.cs:116-123`

### 4.2 维护费率来自哪个字段

战斗体维护费率由 `CompCombatBodyHost.MaintenanceDrainPerSecond` 提供：

```csharp
get { return CombatBodyHostConfigResolver.Resolve().maintenanceDrainPerSecond; }
```

当前设定为 1 Trion/秒。

对应位置：

- `Source/BDP/Core/CombatBody/Bridge/CompCombatBodyHost.cs:116-121`
- `Source/BDP/Core/CombatBodySession/CombatBodySessionTrionBinding.cs:103-110`

### 4.3 “战斗体激活” Hediff 的真实职责

`BDP_CombatBodyActive` Hediff 的实现类明确说明，它只承担运行态表象和外部兼容标记，不反向充当战斗体业务真值中心：

- `Source/BDP/Core/Hediffs/Hediff_BdpCombatBodyActive.cs:6-9`
- `Source/BDP/Core/CombatBody/Bridge/PawnCombatBodyBridge.cs:475-520`

战斗体主链的真值在 `CombatBodyState` / `CombatBodyService` / `CombatBodySessionService` 中；Hediff 只是进入或退出战斗体时附加到 Pawn 身上的表现层状态。

因此，如果战斗体仍处于 `Active`，但 `BDP_CombatBodyActive` Hediff 因其它原因单独消失：

- `CombatBody/Maintenance` 账单仍然保留；
- 不会因为 Hediff 消失而自动注销；
- 只有战斗体会话退出 Active，才会注销维护消耗。

## 五、两条路线的最终对比

```text
芯片表达：
激活槽位
  → 最终有效表达结果
  → ExpressionSustainDrainService 注册
  → Hediff 作为表达宿主被添加

战斗体维护：
战斗体进入 Active
  → CombatBodySessionTrionBinding 注册
  → BDP_CombatBodyActive Hediff 作为表现/兼容状态被添加
```

两者的关键共同点：

> 持续 Trion 账单绑定的是各自业务运行时的有效状态，不是绑定到 Hediff 实例本身。

两者的关键区别：

- 芯片表达按最终有效表达结果和 `SustainCostBySourceCount` 计费；
- 战斗体按会话 `CombatBodyPhase.Active` 和固定维护费率计费；
- 芯片表达由表达层对账；
- 战斗体由战斗会话绑定器维护。

## 六、本次调查结论

1. 芯片本体没有持续 Trion 字段；持续费用字段位于表达条目的 `Trion.SustainCostBySourceCount`。
2. 芯片状态表达的持续费用由表达结果登记，不由实际 Hediff 实例登记。
3. 战斗体维护持续费用由战斗会话 Active 阶段登记，不由 `BDP_CombatBodyActive` Hediff 登记。
4. 两种 Hediff 都不是当前持续账单的生命周期 owner（生命周期所有者）。
5. 当前若 Hediff 被外部合法移除，但对应业务真值仍有效，持续消耗不会自动停止；这是当前架构边界，也是需要后续明确是否修正的行为点。
