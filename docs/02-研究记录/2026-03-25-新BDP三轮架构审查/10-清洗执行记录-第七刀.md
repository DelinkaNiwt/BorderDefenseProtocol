# 清洗执行记录-第七刀

日期：2026-03-25

## 本刀目标

把 `CombatBody` 从“宿主 Comp 直接站在全部对外接口位上”推进到“宿主 Comp + 正式表面对象”。

这一步的目标是把三核心的对外边界统一起来：

- `Trigger`：owner + 正式表面对象
- `Trion`：owner + 正式表面对象
- `CombatBody`：补齐到同一结构

## 实际改动

### 1. `CompCombatBodyHost` 退出公开接口位

处理结果：

- `CompCombatBodyHost` 不再声明实现：
  - `ICombatBodyReader`
  - `ICombatBodyCommands`
  - `ICombatBodyEvents`

保留：

- `ThingComp`

裁定：

- `CompCombatBodyHost` 继续作为 Pawn 上的战斗体主链宿主位
- 但不再直接充当对外正式读写事件面

### 2. 新增 `CombatBodyFormalSurfaces`

位置：

- `Source/BDP/Core/CombatBody/CombatBodyFormalSurfaces.cs`

新增表面：

- `CombatBodyReaderSurface`
- `CombatBodyCommandSurface`
- `CombatBodyEventSurface`

作用：

- 由表面对象承接正式接口
- 由宿主继续保有主链对象和真值接线

### 3. `CompCombatBodyHost` 内部持有并分发正式表面

新增内部出口：

- `ReaderSurface`
- `CommandSurface`
- `EventSurface`

结果：

- CombatBody 宿主现在明确分出：
  - 主链宿主位
  - 正式读取面
  - 正式请求面
  - 正式事件面

### 4. 新增 `CombatBodySurfaceAccess`

位置：

- `Source/BDP/Core/CombatBody/CombatBodySurfaceAccess.cs`

作用：

- 外部系统统一从这里拿 CombatBody 的正式读写口
- 不再要求外部自己去摸 `CompCombatBodyHost`

## 结构结果

本刀前：

- CombatBody 已有读写事件接口
- 但接口仍直接挂在 `CompCombatBodyHost` 上

本刀后：

- CombatBody 和 Trigger、Trion 一样，正式对外入口改由 surface 承接
- `CompCombatBodyHost` 退回“主链宿主位”职责

## 当前裁定

这刀之后，三核心的外部边界结构已经基本统一：

- `Trigger`：owner + 正式表面对象 + surface access
- `Trion`：owner + 正式表面对象 + surface access
- `CombatBody`：host comp + 正式表面对象 + surface access

下一步重点不再是“有没有中间层”，而是：

1. 检查是否仍残留 owner public 面过宽的问题
2. 检查各系统命名、目录归属、兼容接口有没有空壳
3. 对 Enter / Exit pipeline、SurfaceAccess、兼容接口做一次综合复审
