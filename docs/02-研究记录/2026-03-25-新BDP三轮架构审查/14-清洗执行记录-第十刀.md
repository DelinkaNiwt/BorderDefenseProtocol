# 清洗执行记录-第十刀

日期：2026-03-25

## 本刀目标

处理第二版清洗清单里的两项高价值问题：

1. `Trigger` 投影宿主口不再挂在正式读取面上
2. 装备按钮构建服务从 `Core/Projections` 迁回 `Core/Trigger`

## 实际改动

### 1. 投影宿主口从读取面剥离

处理结果：

- `TriggerLoadoutReaderSurface` 不再实现 `ITriggerProjectionHost`
- 新增：
  - `TriggerProjectionHostSurface`

新增内部出口：

- `CompTriggerBody.ProjectionHostSurface`

同时调整：

- `TriggerSurfaceAccess.ResolveProjectionHost`
  - 直接返回独立投影宿主表面

裁定：

- 正式读取面只负责正式读取
- 投影宿主口只服务投影链
- 两者不再混挂在同一个 surface 上

### 2. `TriggerProjectionService` 接线改直白

处理结果：

- 构造函数改为显式接收：
  - `ITriggerLoadoutReader`
  - `ITriggerProjectionHost`
  - `Pawn`

不再做：

- `triggerLoadoutReader as ITriggerProjectionHost`

裁定：

- 投影链依赖什么，现在在构造入口上就是明牌
- 不再靠读取口顺手转型挂投影能力

### 3. 装备按钮构建服务迁回 `Trigger`

处理结果：

- 删除：
  - `Core/Projections/TriggerEquippedGizmoService.cs`

- 新增：
  - `Core/Trigger/TriggerEquippedGizmoService.cs`

裁定：

- 这个服务的职责是：
  - 组装 Trigger 装备按钮
  - 拼接外部 gizmo 扩展
  - 调用手动按钮投影

- 它属于 Trigger 对外面，不属于投影目录

### 4. 调用链同步更新

已调整：

- `CompTriggerBody`
- `Patch_Pawn_TryGetAttackVerb`
- `Patch_Pawn_MeleeVerbs_TryMeleeAttack`

结果：

- 投影链和按钮链都改成显式拿投影宿主口

## 结构结果

本刀前：

- 读取 surface 顺手兼任投影宿主
- 装备按钮服务挂在 `Projections` 目录里

本刀后：

- 读取面、投影宿主面、按钮构建服务三者归属更清楚
- `Trigger` 的外部面和投影链接线更直白

## 当前裁定

这刀之后，`Trigger` 的边界划分更干净：

- 读取：`ITriggerLoadoutReader`
- 请求：`ITriggerLoadoutCommands`
- 事件：`ITriggerEvents`
- 诊断：`ITriggerIntegrityDiagnostics`
- 投影宿主：内部独立 `ITriggerProjectionHost`
- 装备按钮：归回 `Core/Trigger`
