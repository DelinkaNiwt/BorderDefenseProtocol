# 清洗执行记录-第十九刀

日期：2026-03-25

## 本刀目标

清理 `Trigger/Switching/Flow` 里的“流程实现 + 上下文壳”混搭问题。

## 本刀判断

`Switching/Flow` 里原本有两类东西：

### 1. 真流程 / 真规则

- `TriggerActivationRequestService`
- `TriggerActivationCoordinator`
- `TriggerActivationRules`
- `TriggerBindingEngine`
- `TriggerDisableSync`
- `TriggerSwitchEngine`

这些都是真正在跑主链的过程件。

### 2. 流程上下文壳

- `TriggerActivationRequestContext`
- `TriggerBindingEngineContext`
- `TriggerDisableSyncContext`
- `TriggerSwitchEngineContext`

这些不是流程本体，只是 owner 提供给流程件的一组回调和访问面。

另外还有：

- `TriggerDisableSyncCache`

它也不是流程，而是禁用同步的瞬时缓存，更像模型侧运行时缓存。

## 裁定

### 1. `*Context` 不留在 `Flow`

原因：

- 它们本身不推进流程
- 只是流程件的依赖壳
- 继续塞在流程文件尾部，会让人误以为它们和流程本体是同一级别角色

执行：

- 新增 `Trigger/Switching/Contexts`
- 把 4 个 `*Context` 全部迁进去

### 2. `TriggerDisableSyncCache` 归 `Model`

原因：

- 它是状态缓存
- 不是流程

执行：

- 迁到 `Trigger/Switching/Model`

### 3. `Flow` 保持聚焦

结果：

- `Flow` 现在只放：
  - 规则
  - 协调器
  - 推进器
  - 请求服务

这比之前更像“主链过程目录”，而不是“流程 + 附件大礼包”。

## 本刀后的目录理解

### `Trigger/Switching/Model`

- 切换状态模型
- 禁用原因
- 同步缓存

### `Trigger/Switching/Contexts`

- owner 提供给流程件的访问壳

### `Trigger/Switching/Flow`

- 真正执行启停、切换、绑定、禁用同步的过程件

## 本刀的价值

这一步没有改玩法，但把 `Switching` 这一组的层级更压实了：

- 模型归模型
- 上下文归上下文
- 流程归流程

后面再讲 Trigger 切换链时，目录本身就能帮助讲清楚这条主链。
