# 清洗执行记录-第十四刀

日期：2026-03-25

## 本刀目标

复审三核心内部厚度，专门看 `FormalSurfaces` 与 owner / host 之间有没有“只是在替内部主链对象说话”的空转发。

## 复审结论

### 1. `Trigger`

当前判断：

- owner 内部方法很多
- 但它们不只是给 formal surface 用
- 还直接服务：
  - 装卸链
  - 切换链
  - 禁用同步链
  - 绑定链
  - 投影链

裁定：

- 不做机械压缩
- 现在这部分厚度是真主链厚度，不是假层厚度

### 2. `Trion`

当前判断：

- formal surface 主要在转 `CompTrion` 的资源真值和资源请求
- `CompTrion` 本身就是资源真值宿主
- 没有单独的状态 owner 可以直接接过去

裁定：

- 不强行再拆
- 这部分属于宿主本体直接对外提供资源事实，符合体量

### 3. `CombatBody`

当前判断：

- `CompCombatBodyHost` 是 Pawn 宿主位
- 真正的阶段事实在 `CombatBodyState`
- 真正的主链请求在 `CombatBodyCoordinator`

但之前 `CompCombatBodyHost` 上保留了整排成员：

- `Phase`
- `AllocatedTrion`
- `ActivationTick`
- `CollapseReason`
- `CanActivate`
- `CanManualDeactivate`
- `IsInvulnerable`
- `GetCooldownRemaining`
- `GetCollapseRemaining`
- `TryActivate`
- `RequestDeactivate`
- `TriggerCollapse`

这些成员本质上都只是在替：

- `CombatBodyState`
- `CombatBodyCoordinator`

开口说话。

裁定：

- 这是真正可以压掉的机械转发厚度

## 本刀实际执行

### 1. `CombatBody` formal surface 改为直接依赖内部主链口

新增宿主内部入口：

- `PhaseStateSurface`
- `CoordinatorSurface`

作用：

- 前者统一提供已经准备好的 `ICombatBodyPhaseState`
- 后者统一提供已经准备好的 `ICombatBodyCoordinator`

### 2. 删除 `CompCombatBodyHost` 上那一排纯代言成员

删除后的结果：

- reader surface 直接从 `PhaseStateSurface` 取阶段真值
- command surface 直接从 `CoordinatorSurface` 发起正式请求
- host comp 不再承担“转手再说一遍”的中间话筒角色

## 本刀后的结构理解

`CombatBody` 现在更清楚了：

- `CompCombatBodyHost`
  - Pawn 宿主位
  - 负责准备内部主链对象
  - 负责暴露正式表面

- `CombatBodyState`
  - 阶段真值

- `CombatBodyCoordinator`
  - 主链请求协调

- `CombatBodyFormalSurfaces`
  - 正式外口

这样比“宿主再代言一层状态和协调器”更贴模组真实结构。
