# 三核心对外开放与内部保留总表-第一版

日期：2026-03-25

## 一、这份表是干什么的

这份表只回答三件事：

1. 三核心现在正式对外开放了什么
2. 外部系统能向它们提交什么请求
3. 哪些东西是它们内部自己保留的，不该被外部直接依赖

这份表不是代码清单。

它是后续讲解、接线、扩展时统一口径用的。

---

## 二、先给总结论

现在新 BDP 的正式对外口径非常简单：

- `Trigger` 对外开放“槽位与芯片系统”
- `Trion` 对外开放“资源系统”
- `CombatBody` 对外开放“阶段系统”

外部统一只该从这三个入口拿能力：

- `TriggerSurfaceAccess`
- `TrionSurfaceAccess`
- `CombatBodySurfaceAccess`

除此之外：

- `Expressions`
- `Projections`
- `BodyConstraints`
- 各种 `Coordinator / Pipeline / Context / Cache`

都不该被讲成正式外部协议。

---

## 四、Trigger

## 1. Trigger 对外开放什么

正式入口：

- `TriggerSurfaceAccess`

正式开放的能力：

- `ITriggerLoadoutReader`
- `ITriggerLoadoutCommands`
- `ITriggerEvents`
- `ITriggerIntegrityDiagnostics`

正式开放的扩展口：

- `ITriggerExternalGizmoProvider`
- `TriggerExternalGizmoRegistry`
- `TriggerExternalGizmoContext`

### 给普通玩家/初级开发者的白话解释

`Trigger` 对外开放的是：

- 这把武器现在有哪些槽位
- 哪些槽位装了芯片
- 哪一侧现在正在工作
- 能不能切换、停用、装卸
- 如果要排查问题，能不能看“槽位和正式容器是否一致”
- 如果外部模组想加按钮，走正式按钮扩展口

## 2. Trigger 接收什么请求

### 读取

`ITriggerLoadoutReader` 能读：

- 全部槽位
- 指定侧别槽位
- 当前已正式激活的槽位
- 当前切换中的目标槽位
- 当前切换状态快照

### 请求

`ITriggerLoadoutCommands` 能收：

- 装芯片
- 卸芯片
- 请求激活某槽位
- 请求停用某侧当前激活槽位

### 事件

`ITriggerEvents` 会广播：

- 槽位装载变化
- 槽位正式激活完成
- 槽位正式停用
- 槽位禁用状态变化

### 诊断

`ITriggerIntegrityDiagnostics` 能查：

- 正式容器里现在有哪些芯片
- 某个槽位和正式容器是否一致

## 3. Trigger 内部自己保留什么

内部保留，不对外讲成正式协议的东西：

- `CompTriggerBody`
- `TriggerActivationCoordinator`
- `TriggerResolvedExpressionCache`
- `ITriggerProjectionHost`
- `TriggerProjectionHostSurface`
- `TriggerProjectionService`
- `Switching/Model`
- `Switching/Contexts`
- `Switching/Flow`
- `Loadout` 内部服务

### 白话解释

这些东西属于：

- Trigger 自己怎么保存真值
- 自己怎么切换
- 自己怎么缓存表达结果
- 自己怎么把当前结果投到按钮、近战、远程入口

外部不该直接绕过正式外口去摸这些内部件。

## 4. Trigger 现在的边界结论

`Trigger` 是三核心里现在最完整的一块。

它已经做到：

- 正式外口清楚
- 内部切换链清楚
- 投影宿主和正式读取面分开
- 外部按钮扩展有正式入口

当前只需要守纪律，不需要再大拆。

## 五、Trion

## 1. Trion 对外开放什么

正式入口：

- `TrionSurfaceAccess`

正式开放的能力：

- `ITrionReader`
- `ITrionCommands`
- `ITrionEvents`

### 白话解释

`Trion` 对外开放的是：

- 这个 Pawn 现在有多少 Trion
- 最大多少
- 已经锁出去多少
- 自由还能用多少
- 有没有持续消耗
- 现在能不能扣、怎么扣、怎么释放

## 2. Trion 接收什么请求

### 读取

`ITrionReader` 能读：

- 当前总量
- 最大容量
- 已占用量
- 预占用量
- 可自由使用量
- 每天总持续消耗
- 是否冻结自然恢复

### 请求

`ITrionCommands` 能收：

- 检查够不够付
- 全额扣除
- 尽力扣到见底
- 设置预占用
- 正式锁定占用
- 释放占用
- 注册持续消耗
- 注销持续消耗
- 读取当前持续消耗快照
- 冻结/解冻自然恢复

### 事件

`ITrionEvents` 会广播：

- 可用量见底
- 总量见底

## 3. Trion 内部自己保留什么

内部保留：

- `CompTrion`
- `TrionReaderSurface`
- `TrionCommandSurface`
- `TrionEventSurface`
- 持续消耗注册表
- 自然恢复与周期结算

### 白话解释

这些东西属于 Trion 自己管自己的资源真值，不需要外部直接伸手进去改。

外部只需要：

- 读资源
- 发资源请求
- 听资源边界事件

## 4. Trion 现在的边界结论

`Trion` 现在非常干净：

- 没有多余空层
- 没有假扩展架子
- 它就是一个正式资源系统

这块不该再为了整齐继续拆目录。

## 六、CombatBody

## 1. CombatBody 对外开放什么

正式入口：

- `CombatBodySurfaceAccess`

正式开放的能力：

- `ICombatBodyReader`
- `ICombatBodyCommands`
- `ICombatBodyEvents`

### 白话解释

`CombatBody` 对外开放的是：

- 现在处于什么阶段
- 能不能进入
- 能不能手动退出
- 有没有崩解
- 锁了多少 Trion
- 阶段变化时通知外部

## 2. CombatBody 接收什么请求

### 读取

`ICombatBodyReader` 能读：

- 当前阶段
- 当前锁定的 Trion 量
- 进入 Active 的时刻
- 当前崩解原因
- 能不能激活
- 能不能手动退出
- 是否处于无敌表现阶段
- 冷却剩余
- 崩解表现剩余

### 请求

`ICombatBodyCommands` 能收：

- 尝试激活
- 请求退出
- 触发崩解

### 事件

`ICombatBodyEvents` 会广播：

- 阶段变化

## 3. CombatBody 内部自己保留什么

内部保留：

- `CompCombatBodyHost`
- `CombatBodyState`
- `CombatBodyCoordinator`
- `CombatBodyEnterPipeline`
- `CombatBodyExitPipeline`
- `PawnCombatBodyBridge`

### 白话解释

这些东西属于：

- CombatBody 自己怎么切阶段
- 自己怎么进出主链事务
- 自己怎么和 Pawn 宿主接线

外部不该直接跳过正式请求口去改这些内部件。

## 4. CombatBody 现在的边界结论

`CombatBody` 现在比前面干净很多，宿主厚度也已经压到了合理范围。

它现在仍比 `Trigger` 更像“主链框架骨头”，原因不是空层太多，而是：

- 它本来就承担阶段事务
- 进入/退出本来就要串资源、宿主变化、阶段提交

所以这块接下来不该再为了“看起来更薄”硬砍。

---

## 七、三核心之间怎么互相接触

```text
Trion
  提供资源读 / 请求 / 边界事件

CombatBody
  激活/退出时会向 Trion 提交资源请求

Trigger
  自己管理槽位、芯片、切换
  并把当前成立的表达结果送去内部投影链

内部中间链
  Expressions -> Projections -> Verbs / Projectiles / Semantics
```

### 关键点

- `Trion / CombatBody / Trigger` 是正式外口层
- `Expressions / Projections / BodyConstraints` 是内部中间层
- `Semantics` 是跨链描述协议
- `Verbs / Projectiles` 是贴 RimWorld 原版入口的宿主层

## 八、讲解时最容易讲错的点

### 1. 不要把内部链讲成正式外口

不要把下面这些和三核心外口并列讲：

- `Expressions`
- `Projections`
- `BodyConstraints`
- `Coordinator`
- `Pipeline`
- `Context`
- `Cache`

### 2. 不要把 Trigger 说成“攻击总控”

`Trigger` 负责的是：

- 槽位
- 芯片
- 切换
- 按钮
- 攻击入口的当前表达来源

它不是整个攻击系统总控。

### 3. 不要把 CombatBody 说成“变身表现层”

`CombatBody` 现在对外开放的是阶段系统，不只是外观表现。

### 4. 不要把 Trion 说成“数值仓库”

`Trion` 现在已经是正式资源系统，有：

- 读取
- 请求
- 边界事件
- 占用与持续消耗逻辑

---

## 九、最终统一口径

一句话版本：

- `Trigger` 是武器侧的槽位与芯片系统
- `Trion` 是 Pawn 侧的资源系统
- `CombatBody` 是 Pawn 侧的阶段系统

再补一句：

- 外部只从 `SurfaceAccess` 进
- 内部怎么跑，是主模组自己保留的实现细节
