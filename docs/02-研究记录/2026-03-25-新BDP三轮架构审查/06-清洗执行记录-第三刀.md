# 清洗执行记录-第三刀

日期：2026-03-25

## 本刀目标

把 `TriggerCommandFacade` 迁移到真正该在的位置，一次做完这条按钮链的职责纠偏：

- 不把它删回 `CompTriggerBody`
- 不再保留 `Facade` 这种误导性旧命名
- 明确它是“装备状态额外按钮投影服务”

## 实际改动

### 1. `TriggerCommandFacade` 改名并改归属

处理结果：

- 文件从 `Core/Trigger/TriggerCommandFacade.cs` 移到 `Core/Projections/TriggerEquippedGizmoService.cs`
- 类型名从 `TriggerCommandFacade` 改为 `TriggerEquippedGizmoService`
- 命名空间从 `BDP.Core.Trigger` 改为 `BDP.Core.Projections`

原因：

- 它不是通用“命令门面”。
- 它做的真实事情是：
  - 收集外部扩展按钮
  - 在草稿状态下补接手动按钮投影
  - 向装备状态额外按钮入口输出最终按钮列表

这本质上是投影服务，不是 owner，也不是请求入口本身。

### 2. `CompTriggerBody` 保持接线，不回收脏活

`CompTriggerBody.CompGetEquippedGizmosExtra()` 现在仍然只负责：

- 先交出 base 的额外按钮
- 再调用 `TriggerEquippedGizmoService.BuildEquippedGizmos(...)`

没有把按钮拼接、草稿判断、外部扩展整合重新塞回 owner。

这正是本轮清洗的关键。

## 涉及文件

- `Source/BDP/Core/Projections/TriggerEquippedGizmoService.cs`
- `Source/BDP/Core/Trigger/CompTriggerBody.cs`

## 结构结果

本刀之后，Trigger 按钮链更清楚了：

- `CompTriggerBody`
  - 只负责正式装备额外按钮入口接线
- `TriggerExternalGizmoRegistry`
  - 继续作为 Trigger 对外扩展按钮注册口
- `TriggerEquippedGizmoService`
  - 负责装备状态下额外按钮拼接
- `TriggerProjectionService`
  - 负责表达结果到手动按钮/自动攻击入口的投影

也就是说，现在按钮链已经从“旧式 facade 命名”切到“真实服务职责”。
