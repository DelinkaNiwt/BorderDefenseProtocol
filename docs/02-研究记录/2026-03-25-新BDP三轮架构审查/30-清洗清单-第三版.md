# 新BDP清洗清单-第三版

日期：2026-03-25

## 本版目的

前两版解决了：

- 哪些空层必须砍
- 哪些正式外口必须立住
- 哪些内部链不该伪装成公开协议

第三版不再铺新问题。

第三版只做总收尾：

- 哪些已经定型，不再碰
- 哪些还有真实价值，应继续清洗
- 哪些明确不该拆、不该膨胀、不该再反复磨

---

## 一、已定型，不再碰

### 1. 三核心正式外口

已定型：

- `TriggerSurfaceAccess`
- `ITriggerLoadoutReader`
- `ITriggerLoadoutCommands`
- `ITriggerEvents`
- `ITriggerIntegrityDiagnostics`
- `ITriggerExternalGizmoProvider`
- `TrionSurfaceAccess`
- `ITrionReader`
- `ITrionCommands`
- `ITrionEvents`
- `CombatBodySurfaceAccess`
- `ICombatBodyReader`
- `ICombatBodyCommands`
- `ICombatBodyEvents`

裁定：

- 这就是新 BDP 现在该对外讲的正式面
- 后续讲解、接线、扩展都以这组口径为准

### 2. 三核心目录分组

已定型：

- `Trigger`
  - `Access / State / Switching / Loadout / External / Projection`
- `CombatBody`
  - `Access / State / Flow / Bridge`
- `Trion`
  - 保持平铺

裁定：

- 这套分组已经贴职责
- 不再为了外观统一继续拆 `Trion`

### 3. 启动接线归属

已定型：

- `Bootstrap/PawnCompBootstrap`
- `Bootstrap/Injectors/PawnTrionCompInjector`
- `Bootstrap/Injectors/PawnCombatBodyCompInjector`

裁定：

- 启动接线归 `Bootstrap`
- 不再把接线器挂回三核心目录

### 4. 中间链公开面收口

已定型：

- `Expressions` 运行时接口与实现为 `internal`
- `Projections` 运行时接口与实现为 `internal`
- `BodyConstraints` 为 `internal`
- `Semantics` 保留 `public`
- `Projectiles` 保留 `public`
- `Verbs` 只保留 RimWorld/Def 入口确实要看到的 `public`

裁定：

- 这条边界现在清楚了
- 后续不要再把内部中间件重新放成公开协议

### 5. `Runtime` 杂物层处理结果

已定型：

- `Core/Runtime` 已不存在

裁定：

- 这件事已经结束
- 后续禁止以 `Runtime / Services / Managers` 这类宽泛名字重建杂物区

## 二、还应继续清洗

### 1. `FormalSurfaces` 厚度

现状：

- 三核心 `FormalSurfaces` 现在合理，但偏机械转发

后续裁定：

- 可以继续压缩厚度
- 但前提必须是：
  - 不破坏 owner 退出公开面
  - 不把正式外口重新和内部实现缠回去

结论：

- 这是“能动但不急”的项

### 2. `CompCombatBodyHost` 宿主厚度

现状：

- 它已经不再替 state/coordinator 做大批空转发
- 但仍是正式宿主位

后续裁定：

- 可以继续看有没有还能收紧的成员
- 但不能为了“更薄”把宿主位职责削没

结论：

- 这是“复扫项”，不是“立刻下刀项”

### 3. `TriggerExternalGizmoRegistry` 扩展边界

现状：

- 它是真扩展口，不是假层

风险：

- 按钮扩展很容易重新长成旁路入口

后续裁定：

- 外部扩展只能拿正式上下文
- 不能摸回 owner
- 不能反向塞主流程

结论：

- 这是“靠纪律冻结”的项，不是靠目录整理解决的项

### 4. 成员级中文注释补齐

现状：

- 三核心新增和关键文件已经补了很多
- 但全项目并没有完全齐平

后续裁定：

- 后面若继续碰到某文件，就顺手补齐成员级中文注释
- 不专门为了补注释再开一次大范围扫图

结论：

- 这是“随改随补”项

## 三、明确不该再动

### 1. 不该再硬拆小系统目录

对象：

- `Trion`
- `Expressions`
- `Projections`
- `Verbs`
- `Projectiles`
- `Semantics`

裁定：

- 当前规模都在可直读范围
- 为整齐硬拆只会把模组写得像框架

### 2. 不该再回头制造总入口空层

禁止方向：

- 新的 `Facade`
- 新的 `Runtime`
- 新的 `Manager`
- 新的“统一服务中心”

裁定：

- 没有真实职责厚度就不准长

### 3. 不该再把内部链讲成外部协议

对象：

- `Expressions`
- `Projections`
- `BodyConstraints`
- `CombatBody` 内部协调链
- `Trigger` 内部切换链

裁定：

- 这些都属于内部实现
- 讲解时不能和三核心正式外口并列

### 4. 不该再回到旧 BDP 式膨胀

重点警戒：

- `Projectiles`
- `Semantics`
- `CombatBody` 流程层

裁定：

- 没有真实玩法需求，不准预铺大系统骨架

---

## 四、现在的全局裁定

到这一版为止，新 BDP 的上层结构已经进入稳定区：

- 三核心对外口径清楚
- 启动接线归属清楚
- 中间链公开面清楚
- 大系统分组和小系统平铺的边界清楚

现在后续工作应转向：

- 接真实玩法
- 在真实玩法接入时顺手做小幅清洗
- 而不是再做一轮“为了架构而架构”的大扫除

## 六、第三版最终结论

现在的新 BDP 已经不缺“再拆一层”。

现在的新 BDP 需要的是：

- 守住这套边界
- 后续接功能时不回到旧 BDP 的膨胀路子
- 只在真实玩法要求下做小刀、准刀、贴职责的调整
