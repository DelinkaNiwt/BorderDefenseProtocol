# 清洗执行记录-第一刀

日期：2026-03-25

## 本刀目标

按三审结论，先清掉“纯转发薄壳”，不误伤三大核心系统的正式对外边界。

本刀只处理：

- `TriggerProjectionFacade`
- `CombatBodyHostAccess`

暂不处理：

- `TriggerCommandFacade`

原因：

- `TriggerCommandFacade` 现在仍然承担“外部扩展按钮拼接 + 草稿状态下手动按钮接入”的正式出口职责。
- 它已经偏薄，但还不是纯空壳，直接删掉会把 UI 出口拼接细节重新塞回 `CompTriggerBody`。

## 实际改动

### 1. 删除 `TriggerProjectionFacade`

裁定：

- 删除

原因：

- 它只是在外面 new `BdpProjectionRuntime` 再转发一次。
- 没有独立协议，没有独立状态，没有独立业务判断。

替代方式：

- 自动远程入口直接调用 `BdpProjectionRuntime.GetPrimaryRangedVerb()`
- 自动近战入口直接调用 `BdpProjectionRuntime.GetPrimaryMeleeVerb()`
- 手动按钮构建直接调用 `BdpProjectionRuntime.BuildManualCommands()`

### 2. 删除 `CombatBodyHostAccess`

裁定：

- 删除

原因：

- 全工程无引用。
- 它本质只是 `pawn?.GetComp<CompCombatBodyHost>()` 的包装，没有留下来的价值。

## 涉及文件

- `Source/BDP/Patches/Patch_Pawn_TryGetAttackVerb.cs`
- `Source/BDP/Patches/Patch_Pawn_MeleeVerbs_TryMeleeAttack.cs`
- `Source/BDP/Core/Trigger/TriggerCommandFacade.cs`
- 删除 `Source/BDP/Core/Trigger/TriggerProjectionFacade.cs`
- 删除 `Source/BDP/Core/CombatBody/CombatBodyHostAccess.cs`

## 结构结果

本刀之后：

- `Trigger` 的自动近战入口更直接
- `Trigger` 的自动远程入口更直接
- `Trigger` 的手动按钮投影入口更直接
- `CompTriggerBody` 没有因此重新膨胀
- `TriggerCommandFacade` 仍作为装备按钮正式拼接出口保留

也就是说，这一刀删掉的是“假中间层”，不是“真边界”。
