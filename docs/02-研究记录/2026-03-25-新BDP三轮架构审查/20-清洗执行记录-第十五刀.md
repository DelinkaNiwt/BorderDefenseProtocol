# 清洗执行记录-第十五刀

日期：2026-03-25

## 本刀目标

复审三核心内部命名，处理“名字会把职责讲歪”的地方。

这一步不改玩法，只改讲解口径和代码可读性。

## 本刀发现的两个误导点

### 1. `TriggerActivationCoordinator`

现状：

- 只在 Trigger 内部切换链里使用
- 不属于正式对外开放面
- 但类型和接口都是 `public`

问题：

- 名字里有 `Coordinator`
- 可见性又是 `public`
- 很容易让人误以为它是给外部系统依赖的正式协调口

裁定：

- 保留名字
- 但把接口和实现都收口成 `internal`

这样它就回到真实定位：

- Trigger 内部过程件
- 不是外部协议

### 2. `PawnCombatBodyHost`

现状：

- 它只负责把 CombatBody 主链接到 Pawn 宿主事实
- 真正的正式宿主位其实是 `CompCombatBodyHost`

问题：

- 内外两边都叫 `Host`
- 讲解时很容易出现：
  - 哪个才是正式宿主？
  - 哪个只是内部桥？

裁定：

- `PawnCombatBodyHost` 改名为 `PawnCombatBodyBridge`

这样职责一眼就更清楚：

- `CompCombatBodyHost`
  - 正式宿主位
- `PawnCombatBodyBridge`
  - 内部 Pawn 桥接件

## 本刀实际执行

### Trigger

收口：

- `ITriggerActivationCoordinator` -> `internal`
- `TriggerActivationCoordinator` -> `internal`

### CombatBody

改名：

- `PawnCombatBodyHost.cs` -> `PawnCombatBodyBridge.cs`
- `PawnCombatBodyHost` -> `PawnCombatBodyBridge`

并同步更新宿主引用。

## 本刀后的命名口径

### `Access`

- 对外获取正式开放面的入口

### `Surface`

- 正式读写事件表面

### `Host`

- 正式宿主位
- 或内部确实承担宿主职责的对象

### `Bridge`

- 内部桥接件
- 只负责把主链接到 RimWorld 宿主事实

### `Coordinator`

- 内部主链协调件
- 不默认等于对外正式接口

## 本刀后的全局判断

这一步的价值在于：

- 讲解时不再把内部桥和正式宿主混成一团
- 不再把内部协调件误讲成公开协议
- 三核心名字开始更贴“模组真实接线关系”，不像抽象工程词堆叠
