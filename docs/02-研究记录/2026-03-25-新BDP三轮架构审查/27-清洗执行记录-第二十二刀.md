# 清洗执行记录-第二十二刀

日期：2026-03-25

## 本刀目标

从全局口径收两件事：

- 把 Pawn 宿主注入器归回 `Bootstrap`
- 把 `Trion` 正式外口的成员级中文注释补齐

## 本刀裁定

### 1. 注入器不该挂在三核心目录里

判断：

- `PawnTrionCompInjector`
- `PawnCombatBodyCompInjector`

这两个文件做的都是同一类事：

- 在 Def 全部加载后
- 把正式宿主 Comp 接回 Pawn Def

它们解决的是“何时接线”，不是“三核心内部怎么玩”。

裁定：

- 物理位置迁到 `Core/Bootstrap/Injectors`
- 命名空间归到 `BDP.Core.Bootstrap`
- 三核心保留自己的宿主、状态、流程和正式外口，不再混放启动接线器

### 2. `TrionFormalSurfaces` 该补到可讲解状态

判断：

- `Trion` 已经是正式开放面之一
- 讲解时不仅要知道“有 reader / command / event”
- 还要能一眼看出每个成员到底只是转发什么

裁定：

- 为 `TrionReaderSurface`
- `TrionCommandSurface`
- `TrionEventSurface`

补齐成员级中文注释

## 本刀实际执行

- 新建 `Core/Bootstrap/Injectors`
- `PawnTrionCompInjector.cs` 迁入该目录
- `PawnCombatBodyCompInjector.cs` 迁入该目录
- 两个注入器命名空间改为 `BDP.Core.Bootstrap`
- `PawnCompBootstrap` 去掉对旧核心目录注入器命名空间的依赖
- `TrionFormalSurfaces.cs` 补齐成员级中文注释

## 本刀结果

这刀之后，“启动接线”和“三核心玩法主链”分得更直白了：

- 三核心负责自己的真值、流程、正式外口
- `Bootstrap` 负责游戏启动时把这些正式宿主接上 Pawn

这样后面讲架构时，不容易再把“玩法系统”和“启动接线”混成一层。
