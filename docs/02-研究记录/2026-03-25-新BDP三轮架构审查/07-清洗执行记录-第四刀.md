# 清洗执行记录-第四刀

日期：2026-03-25

## 本刀目标

补上三核心开始走正式对外接口获取面的第一步：

- 不再让外部系统自己 `GetComp<CompTriggerBody>()`
- 不再让外部系统自己 `GetComp<CompTrion>()`
- 先把“怎么拿到正式读写口”这条边界立起来

这一步不是再包一层没用壳，而是把跨系统访问入口收拢到统一地点。

## 实际改动

### 1. 新增 `TriggerSurfaceAccess`

位置：

- `Source/BDP/Core/Trigger/TriggerSurfaceAccess.cs`

作用：

- 统一提供 Trigger 的对外获取入口
- 当前包含：
  - `ResolveLoadoutReader`
  - `ResolveLoadoutCommands`
  - `ResolveEvents`
  - `ResolveIntegrityDiagnostics`

裁定：

- 外部系统以后应优先从这里拿 Trigger 的正式接口
- 不再在业务代码里手写“主武器 -> TryGetComp<CompTriggerBody>”

### 2. 新增 `TrionSurfaceAccess`

位置：

- `Source/BDP/Core/Trion/TrionSurfaceAccess.cs`

作用：

- 统一提供 Trion 的对外获取入口
- 当前包含：
  - `ResolveReader`
  - `ResolveCommands`
  - `ResolveEvents`

裁定：

- 外部系统以后应优先从这里拿 Trion 的正式接口
- 不再在业务代码里手写 `pawn.GetComp<CompTrion>()`

### 3. 跨系统调用切到正式获取面

本次已替换：

- `CombatBodyEnterPipeline`
- `CombatBodyExitPipeline`
- `Patch_Pawn_TryGetAttackVerb`
- `Patch_Pawn_MeleeVerbs_TryMeleeAttack`

结果：

- 战斗体进入/退出流程不再直接摸 `CompTrion` / `CompTriggerBody`
- 自动近战/远程补丁也不再直接摸 `CompTriggerBody`

## 结构结果

本刀后，跨系统访问关系从：

- 业务代码 -> 直接摸具体 `Comp`

变成：

- 业务代码 -> `XxxSurfaceAccess` -> 正式接口面

这意味着：

- owner 还在
- 但 owner 不再是外部随手乱抓的默认入口
- 三核心“中间层对外面”开始形成统一样板

## 当前裁定

这一刀解决的是“拿接口的方式”。

它还没有解决的，是：

1. `CompTriggerBody` / `CompTrion` / `CompCombatBodyHost` 仍然亲自实现全部接口
2. 三核心还没有把读、写、事件面拆成独立可替换对象

所以这刀是正式收口的第一步，不是最终态。

## 下一步

下一刀应继续判断：

1. 三核心是否需要把 `Reader/Commands/Events` 从 owner 上继续拆成独立表面对象
2. 哪个核心先拆最有收益
3. 哪些现有调用已经足够停在 `SurfaceAccess`，不必继续膨胀
