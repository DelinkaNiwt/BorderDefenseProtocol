# 清洗执行记录-第二十一刀

日期：2026-03-25

## 本刀目标

回到全局，收 `CombatBody` 和 `Trion` 剩余的公开面尾巴。

## 本刀核对结论

### 必须保持 `public` 的类型

以下类型不能乱收口，因为 XML 或外部接线直接依赖：

- `CompTrion`
- `CompCombatBodyHost`
- `CompProperties_Trion`
- `CompProperties_CombatBodyHost`
- 正式外口接口
- `SurfaceAccess`

### 可以收口的类型

#### 1. `CombatBodyState`

判断：

- 它是真正的内部阶段真值
- 只被 `CompCombatBodyHost` 和 `CombatBodyCoordinator` 这些内部主链件使用
- 不属于正式对外开放面
- XML 也不直接依赖它

裁定：

- `public` -> `internal`

#### 2. `PawnTrionCompInjector`

判断：

- 它只是启动接线器
- 只被 `Bootstrap` 调用
- 不属于正式玩法接口

裁定：

- `public` -> `internal`

#### 3. `PawnCombatBodyCompInjector`

判断：

- 同样只是启动接线器
- 只被 `Bootstrap` 调用
- 不属于正式玩法接口

裁定：

- `public` -> `internal`

## 本刀实际执行

- `CombatBodyState` 收口为 `internal sealed`
- `PawnTrionCompInjector` 收口为 `internal static`
- `PawnCombatBodyCompInjector` 收口为 `internal static`

## 本刀后的全局口径

到这里为止，三核心的公开面更统一了：

- `public`
  - XML 宿主类型
  - 正式外口接口
  - 正式 `SurfaceAccess`
  - 真正要给外部系统依赖的扩展点

- `internal`
  - 内部真值对象
  - 内部流程协调件
  - 内部桥接件
  - 启动接线器
  - 各类上下文与缓存壳

这样“外部能依赖什么，内部自己怎么跑”就更不容易讲混。
