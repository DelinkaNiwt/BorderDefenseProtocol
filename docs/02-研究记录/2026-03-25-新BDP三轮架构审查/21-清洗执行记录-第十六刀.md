# 清洗执行记录-第十六刀

日期：2026-03-25

## 本刀目标

处理三核心目录“太平铺”的问题。

这一步不追求形式整齐，而是追求：

- 玩家或初级开发者看目录时，能一眼看出
  - 哪些是外口
  - 哪些是真值
  - 哪些是过程
  - 哪些是桥接
- 不再把三十多个文件全摊在一层里

## 本刀总裁定

### 1. `Trigger` 必须分组

原因：

- 文件已经太多
- 一层里同时混着：
  - 正式外口
  - 槽位真值
  - 切换过程
  - 装卸过程
  - 外部按钮扩展
  - 投影链

如果继续平铺：

- 找文件靠记忆
- 讲解职责容易串
- 新会话也更容易把内部件当公开口

### 2. `CombatBody` 适合中等分组

原因：

- 文件数量不算夸张
- 但已经明确存在：
  - 外口
  - 状态
  - 主链事务
  - 宿主桥

这类结构继续平铺，会让“正式宿主 / 内部桥 / 主链流程”混在一层。

### 3. `Trion` 不分组

原因：

- 体量小
- 结构简单
- 强拆只会做出样子货

### 4. `Expressions / Projections` 不分组

原因：

- 这两层现在规模克制
- 文件数还没到必须拆
- 硬拆会回到“像框架”的坏方向

## 本刀实际执行

### `Trigger`

新增子目录：

- `Access`
- `State`
- `Switching`
- `Loadout`
- `External`
- `Projection`

归属口径：

- `Access`
  - 正式对外接口
  - formal surfaces
  - surface access
- `State`
  - owner
  - 槽位真值
  - 状态快照
- `Switching`
  - 激活
  - 切换
  - 绑定
  - 禁用同步
- `Loadout`
  - 芯片装卸
  - 装配约束
- `External`
  - 外部按钮扩展
  - 装备按钮拼装
- `Projection`
  - 内部投影宿主
  - 表达缓存
  - Trigger 专属投影服务

### `CombatBody`

新增子目录：

- `Access`
- `State`
- `Flow`
- `Bridge`

归属口径：

- `Access`
  - 正式对外接口
  - formal surfaces
  - surface access
- `State`
  - 阶段真值
  - 阶段枚举
  - 阶段变化参数
- `Flow`
  - coordinator
  - enter / exit pipeline
- `Bridge`
  - 正式宿主 comp
  - Pawn 桥接件
  - comp 注入器

## 为什么不用别的目录名

### 不用 `Runtime`

因为：

- 太宽
- 太容易重新变杂物区

### 不用 `Services`

因为：

- 这里要表达的是玩法职责
- 不是表达“都是服务类”

### 不给 `Trion` 也硬拆一套

因为：

- 那会变成“为了统一而统一”
- 不贴体量

## 本刀后的结构判断

这一步之后，目录更像一个大型 RimWorld 模组：

- 大块系统有层次
- 小块系统不硬摆层
- 目录名表达玩法职责，不表达工程腔
