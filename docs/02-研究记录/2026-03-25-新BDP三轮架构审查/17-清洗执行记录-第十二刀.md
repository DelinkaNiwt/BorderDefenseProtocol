# 清洗执行记录-第十二刀

日期：2026-03-25

## 本刀目标

把目录级裁定落到代码上，处理两件事：

- 清掉空壳 `Core/Runtime`
- 把“表达解析”和“投影落地”彻底分开

## 为什么这一刀要先做

从玩家玩法链看：

1. Trigger 先收集当前成立的芯片表达
2. Expressions 负责判断哪些表达成立、哪个是主近战、哪个是主远程
3. Projections 负责把这些结果变成按钮、近战入口、远程入口

所以：

- `Expressions` 只该回答“现在成立了什么”
- `Projections` 才该回答“把它投到哪里去”

如果把投影注册器留在 `Expressions`，目录边界就会继续发虚。

## 本刀实际执行

### 1. 投影注册口迁到 `Core/Projections`

迁移文件：

- `IExpressionProjectionRegistry.cs`
- `VerbExpressionProjectionRegistry.cs`

处理结果：

- 这两个文件从 `Core/Expressions` 迁到 `Core/Projections`
- 命名保留不动，避免这刀把“归属纠偏”和“概念重命名”混在一起
- 名空间同步改为 `BDP.Core.Projections`

裁定理由：

- 这两个类型干的是“把表达来源投到 RimWorld 宿主”
- 它们不负责收集表达，也不负责解析表达
- 它们属于投影落地层，不属于表达解析层

### 2. `Projections` 内部引用同步收口

处理结果：

- `AutoMeleeProjection`
- `AutoRangedProjection`
- `ManualCommandProjection`

这几个投影器现在直接使用同目录下的投影注册口。

### 3. `Core/Runtime` 空壳目录列入删除执行

目录复查结论：

- 当前 `Core/Runtime` 没有承载真实代码
- 它已经不是“待整理目录”，而是“空壳目录”

执行裁定：

- 直接删除

## 本刀后的全局判断

这一刀之后，目录职责更贴模组真实主链：

- `Trigger`：武器 Trigger 真值、装载、按钮编排、对外表面
- `Expressions`：收集表达、解析表达、得出当前成立结果
- `Projections`：把解析结果投到按钮、近战、远程等宿主出口
- `Verbs`：最小自定义攻击入口
- `Projectiles`：最小自定义弹体

这更像一个 RimWorld 模组在做真实玩法接线，不像一个先摆概念层再等玩法来填的框架。

本刀不改行为，只改归属。
