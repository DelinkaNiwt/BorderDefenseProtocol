  - `DefaultExpressionVerbHostSynchronizer`
- 已把宿主总同步器扩成三通道：
  - `Ability`
  - `Hediff`
  - `Verb`
- 已明确 `Verb` 宿主创建点只在宿主同步器内：
  - resolver 不再 `new Verb`
  - resolver 不再维护本地缓存
  - resolver 只读已同步宿主
- 已把 targeting 适配层收紧为：
  - 有真实宿主时复用真实 `Verb.targetParams`
  - 没有真实宿主时直接返回不可用参数
  - 不再借通用攻击参数继续撑起 UI

### 关键裁定

这轮最终落地的结构是：

```text
Trigger
    -> 只负责装载真值 / 激活真值 / 来源事实
    -> 不持有 Verb 宿主

Expressions/Projection
    -> 负责把正式 Verb 结果同步为原版运行时宿主

DefaultExpressionVerbHostResolver
    -> 只读已同步宿主
    -> 不再动态创建

AttackExecution
    -> 继续作为唯一正式执行边界
```

### 为什么这轮不保留旧路径

- 旧问题的根因不是“少一个补字段”，而是：
  - resolver 本身长期承担了动态创建宿主职责
- 只要这条路径还在，系统就会继续依赖：
  - `FormalResult -> resolver -> new Verb`
- 因此这轮直接删除旧动态创建路径，不保留 fallback，不保留兼容桥。
