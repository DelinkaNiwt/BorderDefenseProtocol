# 2026-03-23 逐步阅读推进（九）

## 这轮新确认

- 旧 GUI 不是需求目标，但它暴露了很多内部真约束
- 最重要的约束包括：
  - 左右手独立切换状态机
  - 槽位至少五态，不是简单开关
  - “最佳显示槽位”这种显示默认投影规则
  - 内部状态会重新投影回 RimWorld 原版展示通道
- `Window_TriggerBodySlots` 和 `Gizmo_TriggerBodyStatus` 只是状态投影窗口，不是业务 owner
- `CompTriggerBody.Display` 说明旧 BDP 很重视把内部状态回投到：
  - Label
  - InspectString
  - Tooltip
  - SpecialDisplayStats
- 当前旧实现里，UI 读取状态还会顺带触发切换状态机懒求值推进
- 这不是理想结构，但背后反映的是 RimWorld 装备 `CompTick` 不跑这个宿主事实

## 这轮重要观察

- “显示默认投影”和“主攻击默认投影”不是同一回事
- 特殊槽和左右手槽不是同一种交互对象
- 玩家是否能管理芯片，是单独的领域开关，不应和芯片存在状态混在一起
