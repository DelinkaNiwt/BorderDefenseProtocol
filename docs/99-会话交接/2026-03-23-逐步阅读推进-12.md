# 2026-03-23 逐步阅读推进（十二）
## 这轮新确认
- `Verb_BDPSingle` 不是独立远程系统，而是共享远程桥上的“单侧编排器”
- 单侧远程里：
  - `Sequential` 继续依赖引擎 burst 节奏
  - `Simultaneous` 才是单次逻辑内循环瞬发多颗
- FireMode、Trion 消耗这些控制，仍停留在单侧编排层，不散进投射物或命中层
- `Verb_BDPProxy` 不是真攻击者，而是给原版自动攻击 AI 看的桥接外壳
- `SyncFrom(...)` 的本质是把真实芯片 Verb 的关键表面复制给 Proxy：
  - range
  - warmup
  - cooldown
  - projectile
  - sound
  - muzzleFlashScale
- ProxyVerb 明确：
  - 不生成自己的 Gizmo
  - 不执行自己的 TryCastShot
  - 只在 `Available()` / `TryStartCastOn()` 时委托给当前主攻击 Verb
- 这说明旧 BDP 的自动攻击结构是：
  - 原版 AI 先看到 Proxy
  - Proxy 再转给真实芯片 Verb
  - 真实芯片 Verb 最终回到共享远程主链
- `GetPrimaryChipVerb()` 在这里再次被证实不是 UI 装饰，而是真正影响自动攻击识别的规则核心

## 这轮最重要的认识
- 自动攻击桥接入口和真实攻击执行宿主，在旧版里是明确分层的
- Proxy 的职责应理解为“表面兼容桥”，而不是执行层
- 单侧和双侧的差别主要在编排复杂度，不在远程主链本身
- 主攻击投影至少同时服务：
  - 自动攻击 AI
  - 外部兼容表面
  - 玩家默认攻击理解
