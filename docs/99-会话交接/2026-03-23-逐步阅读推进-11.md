# 2026-03-23 逐步阅读推进（十一）
## 这轮新确认
- 旧 BDP 的标准远程并不是整套重写原版命中系统，而是：
  - 外层自定义“发射编排”
  - 内层尽量复用原版远程主链
- `Verb_BDPRangedBase.TryCastShotCore()` 的本质是：
  - 复制原版 `Verb_LaunchProjectile.TryCastShot()` 主链
  - 但替换关键输入：
    - `equipmentSource` 尽量投影成芯片
    - `drawPos` 尽量矫正到枪口
    - 引导路径 / 当前 projectileDef / 当前目标由外层先准备好
- `ForcedMissRadius`、`ShotReport`、cover miss、wild miss、`Projectile.Launch(...)` 这些原版核心环节都还在
- `Verb_BDPDual` 的复杂性主要在调度：
  - 当前是哪一侧
  - 当前是一发还是一批
  - 当前是否带路径
  - 当前要不要恢复 `Thing` 目标
  - 当前要临时切哪一个 projectileDef
- 齐射的真实实现是：
  - 一次攻击表达内循环调用 `TryCastShotCore(...)`
  - 每发只改 `shotOriginOffset`
- `shotOriginOffset` 只改发射起点 / 视觉散布，不改 LOS / cover 判定主体
- 双手引导里路径不是默认作用于全部子弹，而是按“当前发射侧是否支持路径”分别处理
- `WithTargetRestore()` 表明旧业务里存在明确要求：
  - 引导侧按锚点 / Cell 处理
  - 非引导侧仍尽量对真实 `Thing` 目标开火

## 这轮最重要的认识
- 要把“标准远程主链”和“BDP 发射编排层”分开理解
- 双手远程的真正复杂点不在命中学，而在调度和上下文切换
- “从枪口发射”不是视觉锦上添花，而是宿主一致性修正
- 旧版已经有一个值得保留的方向：
  - 用共享桥接层负责标准远程链
  - 让单侧 / 双侧 / 齐射 / 引导这些复杂变化停留在编排层
