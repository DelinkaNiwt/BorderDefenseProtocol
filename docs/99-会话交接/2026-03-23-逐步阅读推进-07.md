# 2026-03-23 逐步阅读推进（七）

## 这轮新确认

- 用户对“组合技”的修正已被旧 BDP 代码事实确认
- 真正的上位概念不是 `ComboVerbDef`，而是 `ComboEffectDef`
- `ComboEffectDef` 表达的是：
  - 左右芯片满足组合条件后
  - 额外生成一个第三表达
- 这个第三表达当前已明确有两种落地：
  - `ComboVerbDef` -> `Verb`
  - `ComboAbilityDef` -> `Ability`
- `ComboEffectType` 还预留了 `Hediff`
- `UpdateComboEffects()` 是统一组合表达激活入口
- `activeComboEffects` 持有的是 `ComboEffectDef`，不是攻击定义列表
- 组合技攻击按钮只服务 `ComboVerbDef` 这一路投影
- 能力型组合技直接走原版 Ability 通道，不经过攻击按钮链

## 这轮重要观察

- 旧 BDP v15 已经在概念上把“组合技不是攻击本体”这件事上提了
- 但实现仍处于过渡态：
  - 新的 `ComboEffectDef + UpdateComboEffects()` 已建立
  - 旧的 `CreateComboVerbs()` 直扫 `ComboVerbDef` 逻辑仍保留在 `VerbSystem`
- 所以后续不能照抄旧实现形状，只能吸收其正确抽象方向

## 这轮最重要的提醒

- 二次重构时，组合技必须放在“表达生成层”，不能放在“攻击系统子分支”
- 攻击型组合技只是第三表达投影到 `Verb` 的一种情况
- 宿主投影应后置决定，而不是先把组合技默认绑死为攻击
