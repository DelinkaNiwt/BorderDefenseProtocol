# 2026-03-23 逐步阅读推进（十五）
## 这轮新确认
- 普通非 Verb 芯片表达已经明确接回 RimWorld 原版宿主：
  - `AbilityChipEffect` 直接 `GainAbility/RemoveAbility`
  - `HediffChipEffect` 直接操作 `pawn.health.hediffSet`
- 这说明旧 BDP 不是把所有表达都硬塞进攻击 Verb，而是按宿主类型投影回原版
- 组合第三表达已经有统一方向：
  - `CompTriggerBody.UpdateComboEffects()` 统一匹配
  - `ComboEffectDef` 统一抽象
  - `ComboAbilityDef` 直接证明“第三表达可以不是攻击”
- `CompAbilityEffect_TrionCost` 进一步证明：
  - Ability 只是表现入口
  - 消耗真值仍回到芯片 / Trion 统一层
- 三大真值边界再确认：
  - `CompTrion`：资源真值 owner
  - `CombatBodyState`：战斗体外层相位 owner
  - `CompTriggerBody`：装载与激活表达 owner，但明显越界过重
- `IsCombatBodyActive` 更像触发体侧的镜像可用标志，不应与 `CombatBodyState` 并列当双真值
- `CompTriggerBody.CombatBodySupport` 这组代码证明了触发体为什么会显得像“第二核心”：
  - 它不仅管装载
  - 还直接参与 Allocate / Release / 战斗体支援事务

## 这轮最重要的认识
- “表达系统”比“攻击系统”更上位
- 组合第三表达必须继续按统一抽象层看待，而不能默认归入攻击
- 资源真值必须继续集中在 `CompTrion`
- `CombatBodyState` 应保持薄而清楚，只管外层相位
- `CompTriggerBody` 是二次重构里最需要收缩边界的对象
