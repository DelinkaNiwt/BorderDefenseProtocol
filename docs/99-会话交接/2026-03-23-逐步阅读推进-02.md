# 2026-03-23 逐步阅读推进（二）

## 这轮新确认

- `CompTrion` 仍是资源真值 owner
- `CombatBodyState` 是战斗体外层相位 owner
- `CombatBodyRuntime` 只是访问门面，不是真 owner
- `CombatBodyOrchestrator` 是跨域流程协调者
- `CompTriggerBody` 既是装载 owner，又越界持有战斗体相关状态与资源写入口
- 触发体卸下时，旧版不是“只发事件”，而是先自己释放正式占用，再通知核心做后续解除
- 战斗体支援查询事实上绑定 `pawn.equipment.Primary`
- 崩解监听关键点是 `CompTrion.OnAvailableDepleted`，不是 `OnTrionDepleted`
