# 芯片信息译名来源扩展指南

芯片信息值必须明确区分“原始标识”“本地化文本键”和“Def 引用”。展示端不猜测字符串的含义：Def 引用按类型和 DefName 查找原版 Def，再读取 `LabelCap`；Keyed（文本键）才调用 `Translate()`；原始标识保持原样。

## 引用原版或已有 Def

在信息生产代码中保留 Def 的真实类型和 DefName：

```csharp
ChipInformationValue.FromDefReference(typeof(DamageDef), damageDef.defName)
```

当前已内置解析器的类型包括伤害、物品、能力、健康状态，以及 BDP 的分类、标签、排斥组和职业 Def。缺少 Def 或尚未登记的类型会回退显示原始 DefName，不会丢失身份信息。

## 引用扩展模组自己的 Def

扩展模组为自己的 `Def` 子类登记一次解析器，然后用同一个类型创建信息值：

```csharp
ChipInformationDefLabelResolverRegistry.Register<MyShieldDef>();
ChipInformationValue value = ChipInformationValue.FromDefReference(
    typeof(MyShieldDef),
    shieldDef.defName);
```

登记只保存类型到 `DefDatabase<TDef>` 的查找规则，不会在登记时提前读取 Def；展示时按当前游戏语言读取原版 `LabelCap`。因此，译名由扩展模组的 Def `label` 与其本地化替换共同管理，无需再为同一 Def 另建一套信息面板翻译键。

如果值本来就是 Keyed 文本键，使用 `ChipInformationValue.FromTranslationKey("MyMod_ShieldMode_Facing")`。若它只是内部枚举或身份键，则使用 `FromEnum("Facing")`，不会自动翻译。

该注册入口是 C# 扩展接口；单靠 XML 无法可靠确定任意字符串引用的是哪个 `Def` 子类型。Def 类型需显式登记，之后信息值中的类型与键即可自然路由到对应原版数据库。
