# 芯片信息模型一次性统一实施计划

**目标：** 让一般信息与功能信息最终都只以 `ChipInformationNode`（芯片信息节点）树表示；删除重复的结果对象、反向转换层和依赖旧对象的界面路径，并用节点树重做读取与展示。

**方案：** 保留一般信息规则和功能语义解析两条取值逻辑，因为它们收集、裁定的内容不同；两路逻辑直接产出统一节点与属性。最终信息树只保存客观结构、类型化值和来源链，不保存未知、无效、冲突、未启用等解释状态。错误和冲突进入独立诊断通道；界面专用的排版结果可以保留，但不能再持有旧信息结果对象。

**范围：** 当前主模组 `BorderDefenseProtocol`，直接在当前项目分支完成，不创建工作树或新分支。

## 实施结果（2026-09-29）

- 一般信息和功能解析现在都写入 `ChipInformationNode` / `ChipInformationProperty`；芯片模型只保留根节点和独立诊断。
- 删除了旧块、字段、上下文和 `ResolvedChipFeature` 结果类；功能界面已改成直接读统一节点，反向拼回旧对象的适配器已删除。
- 按客观数据边界修正统一树：节点和属性不再带状态；空值不生成属性；功能值类型错误和同层冲突只写入解析诊断。
- 界面只格式化实际存在的值，不显示未知、无效、冲突、未启用等属性状态标签；移除对应的无用语言键。
- Core 与 Content 项目构建通过，零警告、零错误；相关旧架构冒烟脚本已改为检查统一节点契约，但未运行测试脚本或游戏内验证。

## 统一结果约定

- `ChipInformationNode` 是唯一信息节点：一般信息块、功能、功能组、上下文和关系均为节点。
- `ChipInformationProperty` 是唯一属性：保存稳定键、类型化客观值、单位和来源链；不能保存空值或解释状态。
- 节点只表示对象身份、语义种类、显示名称、顺序及层级，不判断功能是否可用。
- 没有实际值的属性不进入最终树；类型错误和来源冲突写入独立诊断，不制造“未知/无效/冲突”占位值。
- 来源是否实际参与保留在来源链的 `Applied` 客观记录中；形态/姿态以独立上下文节点及其事实表达，不附加“未启用”状态。
- `ChipInformationModel` 若继续保留，只作为根节点与解析诊断的薄封装，不重复保存节点内容。
- 保留定义、声明、来源读取器、规则、裁定逻辑和校验器；它们是输入与处理职责，不是第二份最终结果。
- 详情界面和制造预览直接读取节点。专用功能绘制器可保留，但接口改为接收节点/统一属性；视图结果只能保存节点或界面文字，不能保存旧解析对象。

## 实施任务

### 任务一：补齐唯一节点格式（已完成）

- 节点和属性只承载客观结构、类型化值、单位和来源，不承载通用状态。
- 有值的属性必须提供实际类型化值；无值属性不造占位项。
- 功能属性类型错误与同层来源冲突写入独立诊断，并从结果树排除。

### 任务二：一般信息规则直接生成统一结果（已完成）

- 将规则贡献与合并结果接到节点/属性格式。
- 删除最终结果中的 `ChipInformationBlock`、`ChipInformationField`、`ChipInformationContext` 副本；输入事实、字段/块结构声明和规则诊断按实际用途保留，输入事实不再携带通用值状态。
- 让身份、上下文层级和一般信息客观值落入根节点树。

### 任务三：功能语义解析直接生成统一结果（已完成）

- 保留 `ChipFeatureDef`（功能定义）、`ChipFeatureDeclaration`（功能声明）、来源读取器、属性合并、上下文投影和校验逻辑。
- 将解析结果、分组、子组、嵌套功能和属性改为统一节点/属性；属性只保留实际值，无法裁定的结果改由诊断说明。
- 将组合技正式结果投影、制造构型来源值和根/上下文功能都接到同一结果树。
- 删除作为第二份最终结果的 `ResolvedChipFeature`（已解析功能对象）及其属性/组/子组对象。

### 任务四：界面移除旧输入后按节点重做（已完成）

- 删除节点重新拼回旧功能对象的适配层。
- 重做详情界面、制造预览和专用功能绘制器的输入契约，使其只读统一节点/属性。
- 保留界面排版所需的专用视图结果；它们不能复制另一份功能事实。
- 界面只显示树中实际存在的客观值，不把解析状态伪装成属性值或节点状态。

### 任务五：清理与收尾（代码和构建已完成）

- 清除不再使用的并列集合、查询方法、旧结果类型和过渡注释。
- 更新本计划中的完成状态、相关开发说明及项目工作日志。
- 只提交本任务涉及的源代码、文档和日志，不纳入已有用户修改、构建缓存或临时文件。

## 实施前确认的问题

- `ChipInformationModel` 已有 `Root`，但仍保存 `Blocks`、`Features`、`Contexts` 等旧集合。
- 一般信息合并器仍输出块/字段对象，功能解析器仍输出独立功能对象，随后再经投影器转换为节点。
- 详情界面与制造预览读取节点后，功能绘制器仍接收重建出的旧功能对象。
- 节点格式当前没有状态字段；投影会忽略空值，反向适配还会把属性状态设为有效。
- 因此不能只删旧类型；必须先把状态与读取路径迁入统一格式，再清除旧结果和重做界面。
