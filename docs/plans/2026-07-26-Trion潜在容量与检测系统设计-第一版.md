# Trion 潜在容量与检测系统设计（第一版）

## 1. 目标

为所有人形 Pawn（角色）建立一次生成、永久保存的 Trion 潜在容量，并以正式的 Trion 腺体基因控制实际使用资格。

- 没有 Trion 腺体基因时，角色不显示 Trion 状态，不恢复 Trion，也不能使用依赖 Trion 的功能。
- 未植入基因的角色可以接受检测；检测只公开预设档位，不公开精确值。
- 植入基因后，潜在容量直接成为实际容量，精确数值与现有 Trion 状态条正常显示。
- 固定检测仪和一次性便携检测器都需要另一名智识等级不低于 10 的操作员。

## 2. 核心概念

```text
潜在容量
├─ 与生俱来的永久个体真值
├─ 生成范围为 100～5000
└─ 按 100 为基本单位

Trion 腺体基因
├─ 不提供固定容量
├─ 解锁潜在容量
├─ 解锁 Trion 的储存、恢复、显示与使用
└─ 提供固定 500/天的恢复速率

检测记录
├─ 只表示玩家是否已经获知潜质档位
├─ 不生成或修改潜在容量
└─ 不等于 Trion 使用资格
```

## 3. 真值归属

不增加新的 Comp（组件）。所有新增真值直接保存到现有 `CompTrion`：

```text
int potentialCapacity
bool potentialInitialized
bool potentialAssessed
```

现有的 `cur`、`max`、`allocated`、`reserved` 和 `frozen` 继续表示实际资源运行状态。

潜在容量和检测记录属于 Trion 宿主自身，不使用全局字典、隐藏 Hediff（健康状态）或第二个 Pawn 组件保存平行真值。

## 4. 潜在容量生成

潜在容量只生成一次，随后写入存档。所有结果均按 100 量化。

### 4.1 概率分层

| 全体概率 | 数值范围 | 定位 |
|---:|---:|---|
| 99% | 100～2900 | 普通主体 |
| 0.99% | 3000～3900 | 天才 |
| 0.0099% | 4000～4900 | 破格者 |
| 0.0001% | 5000 | 封顶大奖 |

普通主体使用以 1000 为中心、离散程度约为 350 的钟形抽样。量化后若超出 100～2900，则重新抽取，不把越界结果强制夹到边界，避免最低值或最高值堆积。

3000～3900 与 4000～4900 两个稀有区间内部继续向区间下部倾斜，数值越高越少。5000 是独立的百万分之一封顶分支。

所有概率、范围、中心、离散程度和量化单位均由 Def（定义）配置承载，代码只执行通用抽样规则。

### 4.2 生命周期

- 新 Pawn 创建时生成并保存潜在容量。
- 旧存档 Pawn 缺少潜在容量字段时，在首次安全初始化时生成并保存。
- 读档、检测、添加基因和移除基因均不得重新抽取。
- 本次不保留旧测试基因统一提供的 700 容量，不建设向后兼容层。

## 5. 基因资格

现有 `BDP_Gene_TrionGland` 转为主模组正式基因：

- 保留 `Gene_TrionGland` 实现类和现有 Def 名称。
- 删除所有“测试用”和“验证链路”说明。
- 删除固定 `+700` 容量。
- 有效基因把 Pawn 的潜在容量投影到 `BDP_TrionCapacity` 属性。
- 有效基因提供 `BDP_TrionRecoveryRate = 500/天`。
- 暂定 `biostatCpx（复杂度） = 2`、`biostatMet（代谢） = -1`。
- 设置 `selectionWeight = 0` 与 `canGenerateInGeneSet = false`，禁止进入原版随机基因包和随机异种人生成池。

游戏生成时已经拥有有效基因的 Pawn 以满 Trion 开始。游戏运行中后来获得或重新激活基因的 Pawn 从 0 开始自然恢复。

基因被移除或失效时：

- 实际最大容量与当前量归零；
- 潜在容量和检测记录保留；
- 若正在维持战斗体或其他 Trion 运行状态，必须触发现有 Trion 见底退出流程。

未来获取渠道暂定为“一次性腺体植入物 + 原版医疗手术”，但相关物品、研究、配方和手术不属于本次范围。

## 6. 可见性

### 6.1 没有有效基因

- 实际最大容量为 0。
- 当前量与恢复不运行。
- 不显示 Trion 状态条和精确容量。
- 不能使用依赖 Trion 的功能。
- 未检测时不显示任何潜质信息。
- 已检测时只在角色信息页显示档位名称。

### 6.2 拥有有效基因

- 潜在容量成为实际最大容量。
- 现有 Trion 状态条和精确数值正常显示。
- 模糊检测档位不再显示，避免重复信息。
- 后台检测记录继续保留；以后失去基因时重新显示原档位。

角色信息页优先使用 RimWorld 原版 `SpecialDisplayStats（特殊信息条目）`入口，不为此修改通用信息窗口。

## 7. 检测档位

| 潜在容量 | 档位 | 简述 |
|---:|---|---|
| 100～400 | 微弱 | Trion 潜质十分有限。 |
| 500～700 | 偏低 | Trion 潜质低于常见水平。 |
| 800～1200 | 普通 | Trion 潜质处于常见水平。 |
| 1300～1700 | 良好 | Trion 潜质高于常见水平。 |
| 1800～2400 | 优秀 | Trion 潜质明显优于常人。 |
| 2500～2900 | 卓越 | Trion 潜质极为出众。 |
| 3000～3900 | 天才 | 检测到极其罕见的 Trion 潜质。 |
| 4000～5000 | 破格 | 检测结果已远超常规评价范围。 |

档位使用独立 Def 条目声明最低容量、最高容量、名称、描述和显示顺序。5000 不单列档位，避免模糊检测间接公开精确容量。

## 8. 检测设备与工作

### 8.1 固定式 Trion 检测仪

- 主模组正式建筑。
- 可重复使用。
- 需要正常供电。
- 需要一名操作员和一名不同的受检者。

### 8.2 一次性便携检测器

- 主模组正式物品。
- 不需要固定建筑和供电。
- 仍需要一名操作员和一名不同的受检者。
- 只在检测成功提交时消耗一个；工作中断不消耗。

### 8.3 操作员资格

- 操作员必须与受检者不同。
- `Intellectual（智识）`等级必须不低于 10。
- 智识只作为硬门槛，不影响结果准确度。
- 满足资格后，检测结果必定准确。

### 8.4 受检者资格

- 必须是 `Humanlike（人形智能）` Pawn。
- 必须没有有效的 Trion 腺体基因。
- 必须尚未完成检测。
- 必须拥有有效潜在容量真值。

已有基因者直接读取精确容量，不提供检测。已检测者直接查看既有记录，不允许重复检测。

### 8.5 提交流程

固定仪器与便携道具共用同一个检测资格服务和结果提交服务。

检测开始与完成时都重新验证操作员、受检者和设备。成功时按固定顺序提交：

1. 写入 `potentialAssessed = true`。
2. 解析潜在容量对应的检测档位。
3. 弹出一次检测结果消息。
4. 使角色信息页开始显示同一档位。
5. 若使用便携检测器，消耗一个道具。

操作员资格丢失、任一 Pawn 倒地或死亡、目标不可达、受检者中途获得基因、固定仪器断电损坏或便携道具丢失时，工作安全取消，不记录结果，也不消耗便携道具。

## 9. 模块边界

本功能作为主模组正式 Trion 机制实现，但内部继续分层：

```text
Trion/Core
├─ 潜在容量真值
├─ 实际资源真值
└─ 存读档

Trion/Eligibility
└─ Trion 腺体有效资格

Trion/Assessment
├─ 概率配置
├─ 档位映射
├─ 检测资格与提交
├─ 固定检测仪
└─ 便携检测器
```

检测模块只能读取潜在容量并提交检测记录，不能直接改写潜在容量、当前量、占用量或恢复状态。

## 10. 验证要求

- 潜在容量始终为 100 的整数倍，且位于 100～5000。
- 大多数样本集中在 1000 附近。
- 约 1% 样本达到 3000 以上。
- 5000 分支约为百万分之一。
- 存读档不重新抽取。
- 无基因时不显示、不恢复、不可使用。
- 有基因后公开精确容量，并按 500/天恢复。
- 生成时已有基因以满值开始，运行中获得基因从 0 开始。
- 智识 9 的操作员不能检测，智识 10 可以。
- 两种设备解析出相同档位。
- 便携设备只在成功提交时消耗。
- 检测即时消息与信息页记录一致。
- 基因失效时正确结束依赖 Trion 的运行状态。

对只能在游戏内完整复现的双人工作时序，使用可插拔诊断日志记录开始资格、完成资格、取消原因和最终提交结果；验证完成后删除临时日志。

## 11. 2026-07-26 实施状态

本设计已在主模组落地：

- `CompTrion` 直接保存永久潜在容量、初始化标记和检测记录，没有新增 Pawn Comp（角色组件）。
- 正式腺体基因已从 DevHarness（伴生测试模组）移入主模组；它不进入原版随机基因池，动态解锁潜在容量，并提供固定 500/天恢复。
- 八个检测档位、角色信息页模糊投影、统一资格与原子提交服务均已实现。
- 固定供电检测仪、一次性便携检测器和双人 Job（工作）均已实现。
- 创建时已有腺体、运行中获得、移除和被其它基因覆盖失活均走统一资源迁移入口。

自动验证已完成：新增烟测、XML（配置文件）语法解析、主模组与 DevHarness 发布编译均通过。直接调用正式 C#（C#语言）生成器抽取 1,000,000 次，结果为：最小 100、最大 5000、非 100 倍数 0 个、800～1200 占 52.111%、3000 以上占 1.0014%、4000 以上占 0.0096%、5000 出现 2 次。

双人移动、断电中断、便携物品消耗、信息页实际显示和战斗体现场退出仍属于必须进游戏确认的人工验收项；本次没有把未执行的游戏内测试写成已通过。
