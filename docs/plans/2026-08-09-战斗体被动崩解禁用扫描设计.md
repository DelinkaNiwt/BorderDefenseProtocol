# 战斗体被动崩解禁用扫描设计

## 目标

战斗体退出扫描只服务玩家主动解除。被动崩解及其紧急脱离扩展直接瞬时恢复原身，不捕获人物快照、不生成扫描 Mote；既有崩解烟雾和紧急脱离表现保持不变。

## 现况与根因

- 主动解除恢复宿主时，战斗体阶段仍为 `Active`。
- 被动崩解恢复宿主时，战斗体阶段仍为 `Collapsing`。
- 紧急脱离由崩解扩展执行，使用同一 `Collapsing` 退出链。
- Core 当前对所有宿主退出广播同一种 `Exit` 表现通知；Content 扫描提供器没有读取阶段，因此所有退出都会生成扫描。

## 采用方案

只在 `CombatBodyTransformScanPresentationProvider` 中增加表现资格判断：

```text
Enter                         → 播放扫描
Exit + Active                 → 播放扫描
Exit + Collapsing             → 不播放扫描
```

`Begin` 在清理旧暂存后立即检查资格，崩解时不捕获退场快照。`End` 再检查一次；如果阶段不允许，则释放可能存在的暂存快照并返回，不创建 Mote。

该判断通过 Core 已有的只读 `CombatBodySurfaceAccess.ResolveReader(pawn).Phase` 获取阶段，不新增退出枚举，不修改宿主接口、恢复时序、烟雾、紧急脱离、服装或 Trion 逻辑。

## 验证范围

- 扫描提供器明确拒绝 `Exit + Collapsing`。
- 主动解除 `Exit + Active` 不受影响。
- 进入战斗体扫描不受影响。
- 被拒绝时不捕获新快照，并释放已有暂存快照。
- Core 表现注册表继续保持中性，不认识崩解业务或具体 Mote。
