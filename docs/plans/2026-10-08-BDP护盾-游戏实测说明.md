# BDP 护盾游戏实测说明

状态：首轮测试版本已实现并通过编译、离线行为测试及独立审查，待游戏实测。来源条件刷新只续接身份与攻击定义未变的攻击，失效动作正常结束。

## 首轮参数与接口

普通单盾/常驻自动盾 120 耐久，普通双盾 240 共用一组，光魂两种盾姿态 240 共用一组；破盾恢复均为 600 游戏刻（10 秒），每点成功吸收伤害损耗一点耐久。

Content（正式内容）调用面位于 `BDP.Content.Shield.EnergyShieldApi`：

```csharp
// 本次同步伤害穿过本类 BDP 护盾；原版护盾不受影响。
using (EnergyShieldApi.BeginBypass(targetPawn))
{
    targetPawn.TakeDamage(damageInfo);
}

// 指定护盾组破盾，已经破盾则不延长恢复时间。
EnergyShieldApi.TryBreak(targetPawn, EnergyShieldApi.LightSoulGroupKey);

// 破坏当前本类防护宿主所属的盾组；与穿盾独立。
EnergyShieldApi.BreakActiveShields(targetPawn);

// 读取不可写的耐久比例、恢复完成刻和防护宿主状态。
var snapshots = EnergyShieldApi.GetSnapshots(targetPawn);
```

组键：`energy_shield`（普通）、`energy_shield_auto`（常驻自动）、`light_soul`（光魂）。范围必须用 `using`（自动释放语句）成对释放，不在异步或延期命中之前提前开启；延期攻击在实际受伤调用处开启。穿盾不会自动扣盾耐久或破盾，需要两种效果时调用方明确组合。

## 原版开发菜单测试入口

新程序集需重启游戏后加载。启用开发模式，选中测试人物，在调试动作菜单的 BDP 分类进入“护盾耐久与破盾测试”。

- “输出选中人物护盾状态”：查看真实耐久比例、恢复完成刻及能量。
- “正面弹伤 5/25”：施加真实普通伤害，格挡仍服从原配置概率；未挡住会真实受伤。
- “穿过本类护盾的弹伤 5”：应不消耗本类盾的耐久与格挡能量，但其它防护/护甲仍使用原版流程。
- “破坏当前本类护盾”：无需靠随机格挡耗尽耐久，直接进入正式破盾流程。
- “切换护盾状态观测”：每秒检查选中人物，仅盾组状态变化时输出日志；关闭即停止采样，不保存开关。

调试内容只在 Development（开发程序集）内。日志用 `[BDP护盾诊断]` 标记，便于搜索。破盾/关闭期间显示的上限是最近防护宿主配置参考值，剩余比例与恢复完成刻才是持久真值。

## 建议实测顺序

1. 单盾成功挡住几次伤害，检查能量与耐久同时下降。开启第二枚后剩余比例不变、上限翻倍；反复关闭/开启不能补满。
2. 光魂灵活/举盾切换，确认比例不变。举盾能近战，不能远程；已有合法近战不应被警戒覆盖。
3. 用强制破盾确认盾面、防护和盾击暂时消失、推进不可用；举盾的减速、禁远程与警戒保留。
4. 关闭芯片等待十秒再开启，应满耐久。破盾中途保存并读档，完成游戏刻应不重置。
5. 用普通伤害累积到最后一击，确认人物不承受该次成功格挡的溢出伤害，再进入破盾。
6. 穿盾伤害不扣本类盾耐久；另穿戴原版护盾时，本接口不应绕过它。重复强制破盾不延长计时。
7. 普通盾在另一把武器预热、连射或近战连击期间破盾或恢复，该武器的未变化攻击应继续，剩余次数和近战进度不回退；光魂盾击真正失效才结束。续接后下达停止/移动命令，旧攻击应正常清理，再次攻击不能卡住。观察攻击焦点与枪口位置是否保持正确。

此说明不把离线状态测试和 XML（定义结构）解析当作游戏实测。完整目标选择、连击/预热、存档恢复与视觉表现需实际进游戏确认。
