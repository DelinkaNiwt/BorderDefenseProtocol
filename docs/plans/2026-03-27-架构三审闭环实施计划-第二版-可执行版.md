# 架构三审闭环实施计划（第二版，可执行版）

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 以“运行时闭环真实成立、结构复查可过、游戏实测可过”为唯一目标，完成 BDP 本轮架构三审整改，避免再次出现“计划执行完但复查仍认定没做到位”的结果。

**Architecture:** 本计划先补运行时最小合法前提，再拆 owner 越权，再拆读取即现算，最后收投影层和边缘兼容层。执行原则是：所有重算都必须有显式入口，所有读取都必须是纯读取，所有动态运行时对象都必须满足原版最小前提，所有阶段都必须同时过结构门、运行时门、游戏门。

**Tech Stack:** RimWorld 1.6、C# 7.3、Harmony、ThingComp、CompEquippable、VerbTracker、Pawn_MeleeVerbs、现有 BDP Surface/Reader/Command 分层、`dotnet msbuild`、以游戏实测为最终验收。

这不是评审提纲，这是执行用计划。

1. 先完成一个 Task 的全部 Step

- 先让 UI 读出来正常，底层运行时以后再整理

## 1. 当前问题的最终定义

本轮要解决的，不是抽象意义上的“架构不优雅”，而是四个硬问题：

1. 动态 Verb 仍是半成品运行时对象。
2. `CompTriggerBody` 仍在直接编排表达重算和宿主刷新。
3. 表达层仍是“读取即现算”。
4. VerbHosting 仍然有机会继续长回“第二套 runtime 系统”。

只要这四个问题中任意一个还在，本轮就不能叫完成。
