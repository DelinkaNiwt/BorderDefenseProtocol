# 许可声明链与动态目标直视放宽 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将表达侧的许可字段统一命名为 `DeclaredPermissionKeys`，并让显式声明许可的普通 BDP 远程攻击与 Ability 在操作员控制台运作时动态放宽直达目标视线要求。

**Architecture:** 保留 Core 的地图许可提供/读取链为中性布尔能力信号。新增一个只描述“直达视线放宽判定”这一 Core 接入点的可选解析器契约与注册表；Content 的操作员控制台接收器同时实现现有事实通知接口和该解析器接口。攻击运行时通过 `FormalExpressionResult.DeclaredPermissionKeys` 创建许可上下文，实时查询地图许可，不改写静态 `ResolvedVerbSpec`。

**Tech Stack:** RimWorld 1.6、C# 7.3、.NET Framework 工程、Verse `Verb`/`Ability`、现有 BDP Expression/AttackExecution/Targeting 管线、PowerShell smoke tests、`dotnet msbuild`。

### Task 3: 增加中性直达视线许可解析契约与注册表

- Modify: `Source/BDP.Content/OperatorConsole/DirectTargetLineOfSightPermissionReceiver.cs`

**Step 1: Write the minimal Core contract**

- `IDirectTargetLineOfSightPermissionResolver` 只接收 `MapPermissionContext`，返回当前表达是否可放宽直达目标视线。
- `DirectTargetLineOfSightPermissionResolverRegistry` 只提供注册、移除、清理和查询；不出现 `OperatorConsole`、具体芯片名或许可键字符串。
- 查询按注册顺序调用解析器；单个解析器异常通过现有诊断隔离并按未授权处理。
- 该注册表与现有 `ChipFunctionPermissionReceiverRegistry` 分离：前者负责同步通知，后者负责效果判定，避免两种职责继续混杂。

**Step 2: Connect the Content receiver**

- 让 `DirectTargetLineOfSightPermissionReceiver` 同时实现两个 Core 接口。

- 将同一实例注册到现有通知注册表和新的解析器注册表；清理路径同步移除/清空。

**Step 1: Add a result-to-context query helper**

- 通过解析器注册表即时查询，不缓存控制台状态，不修改 `ResolvedVerbSpec.RequiresDirectTargetLineOfSight`。
- 缺少结果、Pawn、地图、读取器或解析器时按未放宽处理。

**Step 2: Adjust formal host target legality**

- `BdpVerb_FormalHostShoot.CanHitTargetFrom` 的单侧路径在静态要求直视但动态许可有效时，临时以 `requireLineOfSight=false` 调用原版命中判定，仍保留原版射程与目标类型检查。

- `BdpVerb_Shoot.TryStartCastOn` 的既有 fallback 继续负责原版暖机阶段的非虚拟 `TryFindShootLineFromTo` 拒绝；只在 `CanHitTargetFrom` 已按动态许可通过且实际射击线缺失时构造虚拟暖机线。

**Step 3: Adjust manual targeting boundary**

- `AttackExecutionTargetingSource.CanEnterNeutralTargetingBoundary` 在静态 `RequiresDirectTargetLineOfSight=true` 且动态许可有效时，仅保留射程边界，不再用原版 `CanHitTarget` 拦截视线外候选点。
- 确认阶段仍使用原版 `ValidateTarget` 的意识形态、派系和目标类型校验；不把许可变成全局目标放行。

**Step 4: Add execution-side dual regression assertions**

- `CanExecuteDualRangedSide` 与相关目标执行确认必须读取同一动态许可判定，确保预览、确认和实际执行使用同一条规则。
