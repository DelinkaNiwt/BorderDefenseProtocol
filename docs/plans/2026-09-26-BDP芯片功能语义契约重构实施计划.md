# BDP 芯片功能语义契约重构实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不改变 BDP 现有玩法执行表现的前提下，以显式、可扩展的功能语义契约统一开发者声明、表达结果读取、芯片制造台预览、触发器装配台预览和第三方扩展。

**Architecture:** 保留现有表达、Verb、Ability、Hediff、被动、护盾、组合技和武装构型执行链作为唯一玩法真值；新增只读的语义信息层。功能身份由 XML 显式声明，实际属性由类型化来源 Worker 从声明定义、有效定义或运行时快照读取。Core.dll 只提供中性契约、解析和诊断；Content.dll 提供 BDP 正式功能、属性、标准来源 Worker 和展示；Development.dll 提供原始技术诊断与第三方扩展示例。制造台和装配台仅构造不同请求，共用同一解析模型。

**Tech Stack:** RimWorld 1.6 Def/XML、C# 7.3、.NET Framework 4.8、Harmony（仅沿用现有必要补丁）、PowerShell 冒烟测试、`dotnet msbuild`。

## 0. 使用范围与执行纪律

### 0.1 设计依据

本计划执行以下已确认设计：

- [BDP 芯片功能语义契约重构设计](./2026-09-26-BDP芯片功能语义契约重构设计.md)
- 该设计取代旧信息模型设计中“按 Verb、Hediff、Ability、Passive 等技术类型自动识别玩家功能”的部分。
- 旧模型中仍有价值的类型化值、状态、来源、上下文、诊断和通用信息块保留并收敛，不为重构而全部重写。

### 0.2 不可变边界

实施中不得自行改变以下决策：

1. 功能身份必须显式声明，不能从技术结构猜测。
2. 语义信息系统只读，不参与玩法执行，不授予任何功能。
3. 执行事实单向流向信息模型，信息模型不能回写执行链。
4. 一个实现主动声明自己属于哪个功能；功能 Def 不维护所有实现列表。
5. XML 优先；只有全新取值算法才要求 C# Worker。
6. 不提供任意字段路径，不保留 `CanProvide()` 顺序探测注册表。
7. 制造台与装配台共用解析器、结果模型和展示契约。
8. 相同 `ChipFeatureDef` 的不同实例默认不合并，实例身份由稳定 `Id` 决定。
9. 专用展示器不能吞掉自己不认识的属性，未消费属性必须交给通用展示器。
10. 最终不能保留新旧两套正式信息主链，也不能用旧技术扫描作回退。
11. 存档兼容不作为目标；现有正式玩法行为必须保持不变。
12. Core.dll 保持中性，Content.dll 承载业务，Development.dll 不得被其它程序集依赖。

### 0.3 允许在实施中校准的细节

以下项目可依据真实 Def 和有效结果校准，但不得突破上述边界：

- 首批属性 Def 的精确数量、命名、排序与单位；
- 某个复杂效果建模为属性还是子功能；
- 专用展示器的具体版式；
- 极少数属性是否需要增加必需性约束；
- 首批标准来源 Worker 的拆分粒度；
- BDP 个别芯片在“机动”“组合支持”等语义之间是否同时声明多个功能。

若校准会改变玩家所理解的功能身份，而不只是实现细节，必须先暂停并向需求决定者确认。

## 1. 目标数据结构冻结

以下结构是实施目标，不要求一次完成，但最终公共方向不得漂移。

### 1.1 作者声明层

```text
ChipDefinitionConfig
└─ Features: List<ChipFeatureDeclaration>
   ├─ Id                         功能实例稳定标识
   ├─ Feature: ChipFeatureDef    玩家语义身份
   ├─ LabelKey                   可选实例名称
   ├─ Sources                    实际属性来源
   └─ Children                   结构化子功能
```

`ComboDef` 同样增加自己的 `Features`。组合功能描述最终组合结果，不把两枚来源芯片的信息块简单拼接成组合结果。

### 1.2 语义目录层

```text
ChipFeatureDef
├─ label / description           使用原生 DefInjected 翻译
├─ DisplayOrder
└─ Properties: List<ChipFeaturePropertySlot>
   ├─ Property: ChipFeaturePropertyDef
   └─ Order

ChipFeaturePropertyDef
├─ label / description
├─ ValueKind
└─ UnitKey（可选）
```

`ChipFeatureDef.Properties` 是可被 RimWorld 原生 XML Patch 追加的接收槽位列表。槽位表示“允许接收和显示”，不是“每个实现必须提供”。缺失的可选值默认不显示。

### 1.3 来源层

```text
ChipFeatureSourceConfig（抽象）
├─ Id
└─ WorkerClass

IChipFeatureSourceWorker
└─ Resolve(source, context)
   └─ IReadOnlyList<ChipFeatureValueContribution>
```

标准来源配置由 Content.dll 提供；第三方可通过 XML 的 `Class` 和 `WorkerClass` 指向自有配置与 Worker，无需启动时调用全局 `Register()`。

Worker 只允许定位来源、读取或计算有效值、返回类型化贡献。Worker 不得决定功能身份、构造 UI、修改游戏对象、授予行为或反射倾倒任意字段。

### 1.4 解析结果层

```text
ChipInformationModel
├─ Identity
├─ GeneralBlocks
├─ Features: IReadOnlyList<ResolvedChipFeature>
├─ Contexts: IReadOnlyList<ChipInformationContext>
└─ Diagnostics

ResolvedChipFeature
├─ InstanceId
├─ Feature
├─ LabelKey
├─ Properties: IReadOnlyList<ResolvedChipFeatureProperty>
└─ Children: IReadOnlyList<ResolvedChipFeature>
```

功能比较键为“功能实例完整路径 + 属性 Def”。例如：

```text
meteora_attack/impact_explosion + BDP_Property_DamageAmount
```

### 1.5 请求层

统一请求至少表达：

```text
Identity
DeclaredConfig
EffectiveConfig
RuntimeSnapshot（可选）
CurrentModeKey（可选）
CurrentStanceKey（可选）
ComboResults（可选）
Descriptions / 业务来源说明（可选）
```

制造台提供候选配置而无运行对象；装配台提供成品有效配置，并可附加当前形态、姿态与运行时值。

### 1.6 值裁定

同一属性的层级顺序固定为：

```text
运行时值 > 有效定义值 > 作者声明值
```

- 同层同值：合并来源链。
- 同层不同值：`Conflict`，不得按来源顺序猜测。
- 类型不符：`Invalid`。
- 来源不存在：保留功能身份，该属性缺失或 `Unknown`，并记录诊断。
- 需要业务公式：由明确 Worker 计算最终贡献，通用合并器不猜公式。

## 2. 首批正式语义与迁移清单

### 2.1 首批功能语义

第一阶段只建立 BDP 已有真实内容需要的功能：

| DefName | 中文语义 | 主要现有内容 |
| --- | --- | --- |
| `BDP_Feature_RangedAttack` | 远程攻击 | 小行星、美特拉、毒蛇、猎犬、卵之冠、Fujin 远程攻击等 |
| `BDP_Feature_MeleeAttack` | 近战攻击 | 弧月、Fujin、蝎子、光魂盾击与重刃 |
| `BDP_Feature_Shield` | 护盾 | 能量护盾、自动能量护盾、光魂大盾 |
| `BDP_Feature_Movement` | 机动 | 蚱蜢、浮空、推进器、紧急脱离 |
| `BDP_Feature_Stealth` | 隐蔽 | 变色龙 |
| `BDP_Feature_AttackModifier` | 攻击增强 | 铅弹、铅弹·改 |
| `BDP_Feature_ComboSupport` | 组合支持 | 旋空、推进器等明确作为组合来源的效果 |

`Ability`、`Hediff`、`Passive`、`Verb` 不建立为玩家功能 Def；它们只属于实现来源类型。

### 2.2 首批通用属性族

属性 Def 必须表达精确语义，不能只有含糊的 `Distance`。首批目录至少按以下族群建立，具体 DefName 在任务 6 中由真实内容清单冻结：

- 使用与触发：使用方式、触发条件、目标类型、视线要求、概率、使用次数、最大次数、充能、单次消耗、持续消耗、使用要求。
- 空间：有效施放距离、最小施放距离、效果半径、最大目标数、移动距离、作用角度、路径和环境限制。
- 时间：准备时间、冷却时间、持续时间、周期间隔、恢复延迟、结束条件。
- 通用结果：伤害、伤害类型、护甲穿透、治疗、状态、状态强度、属性变化、身体能力变化、叠加上限、解除条件、生成对象与数量。
- 远程重点：射程、精度、连发、投射物行为、追踪、引导、爆炸、附加状态。
- 近战重点：攻击方式、伤害、类型、穿透、冷却、权重、连击次数、连击间隔。
- 护盾重点：防护角度、格挡概率、可抵挡类型、容量或资源、抵挡消耗、恢复、破盾、绕过、反射、转化。

### 2.3 复杂功能

复杂结果继续使用 `ChipFeatureDeclaration.Children`，第一版不建立第二套“效果模型”。首批候选子功能语义：直接伤害、范围伤害、附加伤害、状态施加、属性修改、身体能力修改、资源变化、对象生成。

作者数据通常不超过两层。解析器必须有明确深度上限；超限时停止展开、保留已解析父级并输出诊断，不能递归崩溃。

## 6. 最终完成定义

只有同时满足以下条件，才能声明本重构完成：

1. 所有 BDP 正式芯片与组合技都有显式功能声明。
2. 同一玩家语义可由 Verb、Ability、Hediff、Passive 或第三方自定义实现提供。
3. 制造台和装配台消费同一个解析服务和结果模型。
4. 功能展示不依赖技术块类型、父子位置、实现类猜测或反射字段倾倒。
5. 第三方能纯 XML 新增语义、属性、标准来源声明和 XML Patch 属性扩充。
6. 第三方全新实现只需一个小型 Worker，并通过 XML 挂接。
7. 专用展示器未知的属性仍会由通用展示器显示。
8. 复杂效果、形态、姿态和组合保持结构化、可比较、可诊断。
9. 信息解析失败不会改变或阻止任何玩法行为。
10. 旧技术类型规则、反射 provider、表达信息块和 UI 硬编码已经删除。
11. Core 中性、Content 正式业务、Development 诊断样例的依赖边界通过验证。
12. 代表性芯片、组合、制造、装配和扩展样例通过自动与游戏内回归。

若只完成了新模型但仍保留旧正式信息主链，或者只完成制造台而装配台仍有独立理解逻辑，均不算完成。
