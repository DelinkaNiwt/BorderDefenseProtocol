# BDP 事项 09C：装配设施内容化设计

## 目标

把“触发器装配台＋芯片仓”这一整套玩家业务从 `BDP.Core.dll` 移到 `BDP.Content.dll`，保持现有装卸、搬运、窗口和存读档行为不变。

## 边界

- Core 保留 Trigger 槽位、装载命令、芯片定义校验和通用只读规则。
- Core 新增公开的芯片定义只读快照，只暴露装配界面需要的中性字段，不泄漏内部契约对象。
- Content 持有装配台建筑、芯片仓容器、设施连接、装配事务、Job、WorkGiver、窗口和面板。
- 建筑、Job、WorkGiver Def 移到 `1.6/Content`，类名与玩家行为暂不重命名。
- 不增加新的装配功能，不改变固定装载触发体的禁止配置规则，不改芯片参数。

## 为什么不能直接搬

当前装配窗口直接使用 Core 内部的 `ChipSurfaceAccess` 和 `ChipDefinitionReadResult`。直接搬迁会破坏编译边界，或迫使 Content 依赖 Core 内部实现。因此先增加一个中性的公开快照读取面，再让 Content 使用它。

## 验收

- Core 不再包含 `Core/Assembly` 业务源码和装配 Def。
- Content 能独立编译并读取正式芯片快照。
- 装配台、芯片仓、Job、WorkGiver、窗口和 XML 类名引用全部解析到 Content。
- Core 仍不引用 Content，Core 依赖门禁通过。
