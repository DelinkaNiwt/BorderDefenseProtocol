# BDP 事项 09H：Core 中性化巡检报告

> 时间：2026-08-01（Asia/Shanghai）
> 状态：已完成（只读审计，无运行代码修改）

## 一、巡检范围

- `Source/BDP/Core/**` 全部 C#（C#语言）源码。
- 主模组 `1.6/Defs/**` 中由 Core 读取的 Def（定义）。
- Core 工程引用、Core 与 Content（内容程序集）/候选模组之间的名称和依赖边界。
- Core 中的玩家提示文字、诊断文字和可能残留的具体业务语义。

本次不检查、不中转、不修改候选模组中的具体芯片业务。

## 二、已经确认干净的部分

1. `BDP.Core.csproj` 没有引用 `BDP.Content.dll`、`BDP.DevHarness.dll` 或其它本模组程序集，只引用原版与 Unity（Unity引擎）程序集。
2. Core 源码和 Core Def 没有发现具体芯片名称、具体触发体名称、护盾/毒蛇/追踪等具体业务 Def。
3. Core 没有发现对 `BDP.Content` 或 `BDP.DevHarness` 类型的直接源码依赖；现有 Core 单向依赖门禁继续有效。
4. 已迁出的装配台、Trion 天赋检测、紧急脱离和伤口视觉业务没有重新出现在 Core 生产目录中。

## 三、发现但暂不处理的内容

### 1. Core 中存在较多硬编码玩家文字

例如 Trion 状态、战斗体按钮、条件检查、表达诊断和通用错误提示。这些不等于具体芯片业务，但未来可以单独做“玩家文字与本地化整理”。当前直接搬动会牵涉大量界面和测试，不建议混入本次巡检。

### 2. 默认手动入口包含“双持远程/双持近战”显示名

`DefaultManualEntryGizmoResolver` 会根据通用 `DualWeapon`（双武器复合表达）类型显示这些名称。它是表达入口的具体显示规则，不是某一枚芯片；但它与事项12“双持远程应用”有关，暂时保留，等事项12确认时再决定是否改成配置化显示名。

### 3. 少量注释提到毒蛇、路线引导、爆炸或 DevHarness

这些目前只出现在注释、诊断事件名或通用语义说明中，没有形成程序集依赖或具体业务调用。它们可以在最终全局旧语义清理时统一改写，不值得现在为了改注释而触碰运行代码。

### 4. 静态搜索不能证明某个类一定“无调用”

Harmony（补丁框架）、Def 反射和原版接线都可能通过字符串或运行时类型使用代码。因此本次不凭“搜不到调用”删除 Core 文件；真正退役必须另加边界测试并逐项确认。

## 四、结论与后续建议

Core 当前没有发现需要立即清除的具体芯片业务或反向程序集依赖，整体边界已经达到“可继续向前设计”的状态。

后续非芯片候选按优先级建议为：

1. 玩家提示文字与本地化整理（影响面较大，建议先设计再实施）。
2. Core 注释和诊断事件名中的旧业务例子清理（低风险、低优先级）。
3. 双武器复合入口的显示名配置化（等事项12，不提前处理）。
4. 最终候选模组退役前的全局引用与文件清单复核（接近事项20时处理）。
