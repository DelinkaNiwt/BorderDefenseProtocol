# BDP 触发体动态自动攻击信息实施计划

## 实施顺序

### 第 1 步：固化设计和基线

- 提交本设计文档；
- 确认基线提交 `d7cb738d`（已完成）。

### 第 2 步：测试先行

- 新增 `TriggerBodyDynamicWeaponInfoSmokeTests.ps1`（触发体动态武器信息静态边界测试）；
- 先运行并确认测试因实现不存在而失败；
- 测试约束：必须复用已发布投影、必须保留失败回退、必须只在动态成功时过滤原版武器分类、不得修改攻击入口或 ThingDef 工具。

### 第 3 步：Core 内部适配

- 在 `VanillaWeaponStatSurfaceFactory` 增加 `FormalExpressionResult`（正式表达结果）内部重载；
- 新增 `TriggerBodyWeaponInfoPublisher`（触发体武器信息发布器）；
- 从 `PublishedCombatProjection` 读取默认主近战/远程结果；
- 复用原版临时统计表面和统计读取器，不复制原版伤害、精度、冷却公式。

### 第 4 步：信息卡边界接线

- 在 Content 新增 `ThingWithComps.SpecialDisplayStats` Harmony 补丁；
- 仅对带 `CompTriggerBody` 的物品做包装；
- 动态读取成功才替换原版武器分类；
- 其它条目保持原顺序和原内容；
- 动态读取异常或无有效表达时返回原始枚举结果。

### 第 5 步：验证和提交

- 运行新增测试及全部现有 `Source/BDP.Tests` PowerShell（PowerShell）烟测；
- 编译 `BDP.csproj` 和 `BDP.Content.csproj`；
- 检查改动只涉及信息读取路径；
- 写入工作日志；
- 提交最终实现，便于回退。

## 明确不做

- 不删除或改写触发体 XML 中现有近战 Tool；
- 不改 `AttackExecutionSurfaceAccess`、自动攻击补丁和表达投影选择；
- 不改变存档格式；
- 不调整芯片制造台、触发器装配台或成品芯片信息卡的既有布局。

## 风险与回退

如果原版 `SpecialDisplayStats` 的调用时机、临时 ThingDef 统计读取或运行时表达快照在某个异常状态下不可用，补丁必须返回原始枚举结果。任何异常只记录一次诊断，不阻塞信息面板打开。
