# Trion 立方体阶段贴图细化设计

## 目标

细化 BDP 模组射手体系的 Trion 立方体构型视觉：

- 待机时保持现有主层和发光叠层不变。
- 预热时切换为“切割主侧东不发光”和“切割主侧东带发光”两张新贴图。
- 射击和冷却时隐藏整个 Trion 立方体视觉。

## 已确认事实

- Trion 视觉由 `BDP_Visual_TrionCube` 和 `BDP_Visual_TrionCube_Dual` 两个正式预设承载。
- 现有视觉是“不发光主层 + 带发光叠层”两层结构。
- `Core` 已有 `Idle`、`Warmup`、`Firing`、`Cooldown` 阶段解析和主层阶段覆盖能力。
- 现有阶段覆盖尚未支持按阶段替换叠层，因此直接只替换主层会在预热时残留旧发光叠层。
- 工作区存在用户已有未提交改动，本任务不得覆盖、回退或纳入提交。

## 方案比较与决策

### 方案 A：扩展通用阶段叠层能力（采用）

在 `Core` 的阶段视觉覆盖配置中增加可选叠层集合。阶段配置了叠层集合时使用该集合，未配置时沿用预设原有叠层；没有阶段覆盖的旧预设继续保持旧行为。

`Content` 只声明 Trion 的具体阶段策略。这样能精确实现两张预热贴图成对切换，同时不改变待机贴图、姿态、尺寸、枪口和攻击逻辑。

### 方案 B：预热只使用合并的带发光图

不扩展阶段叠层能力，直接将新带发光图作为预热主层。该方案会与现有旧发光叠层冲突，或者迫使正式配置全局移除旧叠层，无法同时保证待机和预热效果，放弃。

### 方案 C：增加 Trion 专用 C# 绘制钩子

绕过现有阶段设施，在 `Content` 中按 Trion 业务自行切换和绘制。该方案会重复已有时序解析，增加业务耦合和生命周期风险，放弃。

## 结构与数据流

1. `ExpressionVisualStageOverrideConfig` 增加可选阶段叠层集合。该字段只描述通用视觉数据，不包含 Trion 名称或具体资源路径。
2. `ExpressionVisualPresetDef` 提供统一阶段叠层解析：
   - 当前阶段有叠层集合时使用阶段集合；
   - 当前阶段没有阶段集合时沿用默认 `OverlayLayers`；
   - 未声明 `StageVisuals` 时完全保持旧行为。
3. `VisualPoseResolver` 使用已经解析出的动作阶段同时解析主层和叠层。
4. 现有绘制前的阶段可见性判断继续统一控制整个视觉，因此 `Firing` 和 `Cooldown` 会同时隐藏主层与叠层。
5. 单武器和双武器 Trion 预设使用相同的阶段策略。

## Content 与资源

正式资源命名为：

- `1.6/Textures/Things/Trigger/Chip/Trion/trion_cube_warmup_base.png`
- `1.6/Textures/Things/Trigger/Chip/Trion/trion_cube_warmup_glow.png`

两张参考图只复制到正式模组资源目录，不修改参考资源，也不覆盖现有：

- `trion_cube_base.png`
- `trion_cube_glow.png`

两个 Trion 视觉预设的阶段配置一致：

- `Idle`：不声明覆盖，使用现有贴图；
- `Warmup`：新不发光主层 + 新带发光叠层；
- `Firing`：`Visible=false`；
- `Cooldown`：`Visible=false`。

预热主层继续使用 `Graphic_Single` 和 `Cutout`，预热叠层继续使用 `Graphic_Single`、`MoteGlow` 和现有 Trion 青绿色，不新增尺寸、姿态或偏移。

## 验证

- 检查 `Visual.xml` 的 XML 结构和阶段配置。
- 检查两张新 PNG 存在于正式 `1.6/Textures` 路径，旧 PNG 未被覆盖。
- 更新并运行 `TrionCubeVisualSmokeTests.ps1`，覆盖单武器、双武器、预热切图和射击/冷却隐藏。
- 更新或补充 Core 边界烟测，确保阶段叠层设施保持中性，不包含 Trion 业务路径。
- 编译 `BDP.Core.dll` 和 `BDP.Content.dll`。
- 运行相关 PowerShell 烟测及项目已有构建边界检查。
- 最终在游戏内观察待机 → 预热 → 射击 → 冷却的连续切换；静态检查不能替代实际渲染时序验证。

## 改动边界

预计改动范围：


- `Source/BDP/Core/Expressions/Config` 的通用阶段叠层解析设施；
- `1.6/Content/Defs/ExpressionDef/Visual.xml` 的两个 Trion 视觉预设；
- `1.6/Textures/Things/Trigger/Chip/Trion` 的两张正式 PNG；
- Trion 视觉相关烟测；
- 本次设计文档和项目工作日志。

不修改 Core 以外的攻击逻辑、Trion 资源逻辑、姿态参数、尺寸参数或其它构型。
