# 第一阶段对象到接口映射表（第一版）

## 目的

这份文档只做一件事：

- 把第一阶段会碰到的核心对象，映射到对应接口和职责边界

它的作用是避免后面真正开写时又出现这些问题：

- owner 混了
- 同一职责分散到多处
- 接口写了，但不知道该由谁承接
- 某个对象又开始无限膨胀

## 一、映射阅读方法

每个对象都按四件事写：

1. 它是什么
2. 第一阶段它负责什么
3. 它应承接哪些接口
4. 它不该越界去做什么

## 二、核心对象映射

### 1. `CompTrion`

它是什么：

- 小人的 Trion 资源宿主

第一阶段负责：

- 当前值、最大值、可用值
- 正式占用
- 预占用
- 一次性消耗
- 持续消耗聚合
- 释放
- 可用值耗尽通知

建议承接接口：

- `ITrionState`
- `ITrionEvents`

不该越界：

- 不负责战斗体激活流程
- 不负责芯片装载与激活
- 不负责表达合成
- 不负责入口投影

### 2. `CombatBodyState`

它是什么：

- 战斗体外层相位状态对象

第一阶段负责：

- `Inactive / Active / Cooldown`
- 激活后当前所占 Trion 的记录
- 主动解除时机
- 基本冷却语义

建议承接接口：

- `ICombatBodyPhaseState`

不该越界：

- 不自己记 Trion 账
- 不自己管槽位装载
- 不自己合成表达
- 不自己生成按钮

### 3. `CombatBodyCoordinator`

它是什么：

- 战斗体激活、解除、异常结束的薄协调者

第一阶段负责：

- 激活前检查
- 激活事务串联
- 主动解除事务串联
- 基本异常收尾入口

建议承接接口：

- `ICombatBodyCoordinator`

不该越界：

- 不持有资源真值
- 不持有装载真值
- 不持有表达真值

### 4. `CombatBodyHost`

它是什么：

- 战斗体系统碰 RimWorld 宿主事实的桥接对象

第一阶段负责：

- 提供当前 Pawn
- 进入战斗体表现
- 从战斗体表现恢复

建议承接接口：

- `ICombatBodyHost`

不该越界：

- 不负责表达规则
- 不负责资源规则

### 5. `CompTriggerBody`

它是什么：

- 触发体装载与局部激活宿主

第一阶段负责：

- Main / Sub 槽位
- 装入与卸下
- 激活与关闭
- 当前激活槽位读出
- 切换状态推进

建议承接接口：

- `ITriggerLoadoutState`

不该越界：

- 不负责资源真值
- 不负责战斗体相位真值
- 不负责全局表达解析
- 不负责自动入口桥接真值

### 6. `TriggerSlotState`

它是什么：

- 单个槽位的轻量状态对象

第一阶段负责：

- 记录侧别
- 记录编号
- 记录装载芯片
- 记录是否激活
- 记录是否禁用

建议承接接口：

- `ITriggerSlotState`

不该越界：

- 不负责复杂业务结算
- 不负责主动触发外部事务

### 7. `TriggerActivationCoordinator`

它是什么：

- 单次槽位激活与关闭的局部事务协调者

第一阶段负责：

- 激活一个槽位
- 关闭一个槽位
- 串联必要的局部状态变更

建议承接接口：

- `ITriggerActivationCoordinator`

不该越界：

- 不直接做全局表达解析
- 不直接做战斗体激活

### 8. `ExpressionCollector`

它是什么：

- 从当前激活状态收集表达来源的对象

第一阶段负责：

- 读取当前激活槽位
- 产出表达来源列表

建议承接接口：

- `IExpressionCollector`

不该越界：

- 不决定最终主攻击
- 不决定自动入口桥接

### 9. `ExpressionSource`

它是什么：

- 单个表达来源的统一描述

第一阶段负责：

- 描述来源来自哪侧
- 描述来源来自哪个芯片
- 描述最终投向哪类宿主

建议承接接口：

- `IExpressionSource`

不该越界：

- 不自己执行攻击
- 不自己做外部投影

### 10. `ExpressionResolver`

它是什么：

- 把当前来源集合解析成最终表达结果的规则对象

第一阶段负责：

- 区分单侧近战与远程
- 给出默认主近战投影
- 给出默认主远程投影
- 产出当前已解析表达结果

建议承接接口：

- `IExpressionResolver`

不该越界：

- 不自己生成 Gizmo
- 不自己接原版 AI
- 不自己持有装载真值

### 11. `ResolvedExpressions`

它是什么：

- 当前表达解析后的结果快照

第一阶段负责：

- 汇总当前可用表达
- 暴露默认主近战投影
- 暴露默认主远程投影

建议承接接口：

- `IResolvedExpressions`

不该越界：

- 不自己再去查 owner
- 不自己做业务计算

### 12. `ExpressionProjectionRegistry`

它是什么：

- 把表达来源投向具体 RimWorld 宿主的注册表

第一阶段负责：

- `Verb` 宿主投影
- 给后续 Ability / Hediff 预留入口

建议承接接口：

- `IExpressionProjectionRegistry`

不该越界：

- 不自己决定当前该用哪个表达

### 13. `ManualCommandProjection`

它是什么：

- 玩家手动入口投影器

第一阶段负责：

- 把解析结果投成 Gizmo / Command

建议承接接口：

- `IManualCommandProjection`

不该越界：

- 不自己重新解析表达
- 不自己决定资源规则

### 14. `AutoRangedProjection`

它是什么：

- 自动远程桥接投影器

第一阶段负责：

- 给原版自动远程查询口返回默认远程表达

建议承接接口：

- `IAutoRangedProjection`

不该越界：

- 不兼任自动近战桥
- 不兼任手动入口

### 15. `AutoMeleeProjection`

它是什么：

- 自动近战桥接投影器

第一阶段负责：

- 给原版自动近战查询口返回默认近战表达

建议承接接口：

- `IAutoMeleeProjection`

不该越界：

- 不兼任自动远程桥
- 不兼任手动入口

### 16. `VisualProjection`

它是什么：

- 对外默认表面与基础展示投影器

第一阶段负责：

- 提供默认表面投影概念
- 给后续文本、图形、信息卡展示留口

建议承接接口：

- `IVisualProjection`

不该越界：

- 不持有真值
- 不自己重新做表达解析

### 17. `CleanupCoordinator`

它是什么：

- 解除与异常结束时的收尾协调者

第一阶段负责：

- 撤销表达
- 释放资源
- 恢复宿主
- 清理入口投影

建议承接接口：

- 第一阶段可以先内聚在协调层里
- 后续再独立成 `ICollapseCleanupCoordinator`

不该越界：

- 不重新定义资源语义
- 不重新定义战斗体相位语义

## 三、第一阶段最关键的映射结论

### 1. 三类真值 owner 不能混

- `CompTrion` 只做资源真值
- `CombatBodyState` 只做战斗体相位真值
- `CompTriggerBody` 只做装载与局部激活真值

### 2. 协调者只串流程，不吞真值

- `CombatBodyCoordinator`
- `TriggerActivationCoordinator`
- `CleanupCoordinator`

它们都应该尽量薄。

### 3. 表达系统只做“读来源 -> 出结果 -> 投宿主”

表达系统要强，但不能膨胀成第二个全能核心。

### 4. 入口投影必须继续分层

- 手动入口
- 自动远程入口
- 自动近战入口
- 默认表面投影

这几条口第一阶段就要分开。

## 四、当前结论

如果这张映射表后面还能成立，
说明第一阶段骨架大致是稳的。

如果后面一写代码就不断出现：

- 某个对象需要同时知道所有事
- 某个协调者开始持有真值
- 某个投影器开始重做业务结算

那就说明又开始偏离当前骨架了。
