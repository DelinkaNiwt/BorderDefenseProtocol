# 敌对 Trion 公共资源接口实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在公共资源基本逻辑接入敌方隐藏容量、免功能成本、免芯片占用规则，仅保留受伤泄露损耗。

**Architecture:** 沿用同一真实资源容器与伤口账本。Core（核心程序集）提供中性规则接口及应用点，Content（内容程序集）提供原版敌对判定和具体规则；普通攻击、能力、跳跃、护盾沿原入口工作，不逐项增加敌对补丁。

**Tech Stack:** C# 7.3（C# 语言）、.NET Framework 4.8（运行框架）、RimWorld 原版程序集与现有 Def（定义）。

Status: Implemented

工作目录为当前 BDP 工程；不创建分支、工作树、独立聊天或子代理。不包含追兵队伍、皇室任务、研究树与数值平衡。用户要求先提交基线再继续，已建立实施前基线 `ea79fe92`。下列公共资源功能已实现，游戏内实测待完成。

## 1. 中性规则与敌方提供器

新增路径，均相对主模组：

- `Source/BDP/Core/Trion/ITrionResourceRuleProvider.cs`（资源规则提供接口）：按资源宿主读取一份规则。
- `Source/BDP/Core/Trion/TrionResourceRules.cs`（资源规则值）：仅包含功能成本、芯片占用、容量可见性三个决策。
- `Source/BDP/Core/Trion/TrionResourceRuleRegistry.cs`（规则注册入口）：沿现有恢复门控单一提供器模式；未注册时全部按普通规则处理，不增加策略优先级或组合框架。
- `Source/BDP.Content/Trion/Resource/HostileTrionResourceRuleProvider.cs`（敌方资源规则提供器）：非人物宿主普通处理，人物使用原版敌对查询确定是否采用三项关闭的敌方规则。
- 修改 `Source/BDP.Content/ContentBootstrap.cs`（内容初始化）：注册提供器。

原版依据：`RimWorld.GenHostility.HostileTo(Thing, Faction)`（物体对派系是否敌对，实际方法令牌 `0600D39F`）已经处理人物所属关系、精神状态等原版情况，末尾再查询派系关系。直接采用原版当前判定，不另外设计俘虏／招募切换条件，不用“不是玩家阵营”代替敌对。

规则只影响当前操作，不改原始芯片参数、真实容量或恢复配置。所有新增成员写中文注释，默认普通规则不能依赖 Content（内容程序集）。

## 2. 一次成本与资源门槛

修改 `Source/BDP/Core/Trion/CompTrion.cs`（资源真值组件），在 `CanAfford`（够用检查）、`TryConsume`（尝试支付）和 `ConsumeUntilDepleted`（尽力消耗）的公共基本逻辑读取规则。

功能免耗时对应资源门槛放行、支付成功且当前量不变；普通规则保持原费用。资源宿主缺失、腺体不合法、战斗体未启动等原有运行条件不因免耗被替代。

无需分别改普通攻击、能力、芯片启动、蚱蜢或护盾的效果实现；其原有公共调用自然生效。不要把 `ITrionReader`（资源读取接口）的余量改成极大值来骗过检查。

验证：同样的成本对普通宿主正常拒绝／扣除，对敌方低余量宿主支付成功但不扣除；护盾同样免耗。实际零余量不等于允许重新启动战斗体。

## 3. 持续账本分类与实际结算

- 新增 `Source/BDP/Core/Trion/TrionDrainKind.cs`（持续损耗类别），仅分功能维持与伤口泄露。
- 修改 `ITrionCommands.cs`（资源请求）、`TrionService.cs`（资源服务）、`CompTrion.cs`（账本）：持续登记带类别，默认功能维持；来源键继续只承担身份。
- 修改 `Source/BDP/Core/CombatBody/Wounds/CombatBodyWoundTrionBinding.cs`（伤口资源绑定）：登记时明确为伤口泄露。

每条登记保留声明速率；总速率和实际结算按规则只计入有效类别。`GetDrainSnapshot`（登记快照）继续为表达维持对账提供声明速率，不能返回过滤后的零费表造成重复登记。注销必须连同类别资料清理；读档按现有来源重建，不另设敌方账本。

验证：普通宿主扣所有已登记费用；敌方只扣伤口泄露；伤口移除／到期停止泄露；敌方剩余 Trion 被泄露耗尽时仍发原有见底事件。检查表达费用多次对账与读档后没有重复来源。

## 4. 有效占用与启动生命资源

- 修改 `Source/BDP/Core/Trigger/State/CompTriggerBody.cs`（触发体状态）：在已有预占用汇总出口计算宿主有效占用，触发器资源绑定沿用该出口。
- 修改 `Source/BDP/Core/CombatBodySession/CombatBodyActivationTransaction.cs`（战斗体启动事务）：搭载芯片汇总后应用占用规则，支付检查、实际账本及 `TryEnterActive`（进入激活态）使用相同金额。
- 修改 `Source/BDP/Core/CombatBodySession/CombatBodySessionPolicy.cs`（会话判断）与 `CombatBodySessionService.cs`（会话服务）：公共启动准入与正式启动都采用一致的实际资源存活检查，避免显示可启动而正式请求失败，或空血敌方因零占用重新启动。
- 核对 `Source/BDP/Core/CombatBodySession/CombatBodyExitTransaction.cs`（退出事务）：只释放相位记录的实际占用，无虚构金额；不改崩解后恢复原身流程。

敌方启动后预占用、实际占用、相位记录为零；未受伤且不发生其他崩解原因时，不因使用或维持耗尽 Trion。规则适用改变时复用资源与战斗会话已有生命周期核对账本和记录，不能静默留下旧占用；这一项是实现一致性检查，不引入身份玩法。如执行中确需新增公共生命周期接口，先说明实际缺口，不自行扩展。

验证：普通人物按原芯片金额占用；敌方搭载昂贵芯片也为零；启动失败回滚、主动解除与崩解不多释放；敌方零余量不可启动，伤口见底正常崩解。

- 修改 `Source/BDP/Core/Genes/StatPart_TrionCapacityPotential.cs`（容量潜力来源说明）与 `TrionGeneGizmoBridge.cs`（资源状态条）：按同一规则阻止隐藏容量从说明或状态条显示。

普通人物保留现有显示限制；内部读取真值正常。不新增玩家文案，不扩大隐藏到释放力、普通伤势或既有泄露提示。不对原版所有属性追加 Harmony（运行时补丁）。

验证：敌方正常界面无容量、余量和容量潜力说明；真实资源读取、伤口表现与普通人物显示正常。容量计算结果不因界面隐藏而改变。
