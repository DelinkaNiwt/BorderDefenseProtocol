# 变色龙能力释放与冷却设计

## 目标

变色龙芯片激活后提供一个一次性能力按钮：能力成功释放后进入 40 秒冷却，并添加持续 20 秒的隐身 Hediff。隐身 Hediff 到期或被其它流程移除后，表达宿主和持续 Trion 消耗必须立即重新对账。

能力释放继续使用 0.5 秒前摇和三段释放音效；芯片激活阶段不播放这组音效。变色龙的具体数值和冷却键只写在 Content 的 Ability/Hediff Def 中，Core 不识别变色龙业务。

## 设计边界

### Core 通用架构

1. `CompProperties_AbilityReleaseCooldown` 声明一个配置驱动的 `cooldownKey`。
2. `GameComponent_AbilityReleaseCooldownLedger` 按“Pawn + cooldownKey”保存冷却结束 tick，并通过原版存档接口保存。
3. `CompAbilityEffect_AbilityReleaseCooldown` 复用原版 Ability 已实际启动的冷却时长，负责阻止来源级冷却期间再次释放。
4. `DefaultExpressionAbilityHostSynchronizer` 在 Ability 被重新挂载时恢复来源级冷却剩余时间。
5. `CompProperties_AbilityEffect_ApplyExpressionHediff` 和对应效果组件只按配置添加表达宿主 Hediff，不负责业务状态关闭和冷却。
6. `BdpExpressionHostHediff.PostRemoved` 在原版从 `HediffSet` 移除完成后触发统一宿主对账；表达服务使用重入保护，避免移除回调递归同步。

### 变色龙业务配置

1. Ability 使用 `cooldownTicksRange=2400`，即 40 秒原版冷却。
2. Ability 使用 `cooldownKey=BDP_AbilityCooldown_Chameleon`，同一 Pawn 的变色龙能力共享这一冷却。
3. Ability 使用通用一次性 Hediff 应用组件，目标为 `BDP_Hediff_Chameleon`。
4. Hediff 使用原版 `HediffCompProperties_Disappears`，持续 1200 ticks，即 20 秒。
5. 隐身组件、攻击成功后关闭芯片、隐秘组互斥和持续消耗配置均保持原有业务规则。

## 时序

```text
点击能力按钮
    ↓
0.5 秒释放前摇
    ↓
原版 Ability 成功释放并启动 40 秒冷却
    ↓
记录 Pawn + cooldownKey 的来源级冷却结束时间
    ↓
添加隐身 Hediff，持续 20 秒
    ↓
Hediff 到期/被移除
    ↓
统一重新同步表达宿主并注销实际不存在的持续消耗
```

若芯片因攻击自动关闭，Ability 宿主会被移除，但来源级冷却账本不受影响。之后重新激活同一张或另一张变色龙芯片，Ability 会恢复剩余冷却，不能通过换芯片绕过规则。

## 风险控制

- 不再使用“`cooldownTicksRange=0` 后手动 `StartCooldown`”组合，避免原版 `Ability` 的 `CanCooldown` 判定阻止冷却状态收尾。
- 不把冷却状态放进 Hediff；Hediff 到期后冷却仍需继续存在。
- 不把冷却状态只放进 Ability；Ability 被芯片停用移除后仍需保留冷却。
- 不在 Core 写入 `BDP_Ability_Chameleon`、`BDP_Hediff_Chameleon` 或 20/40 秒业务常量。

## 验证

- 冒烟测试确认 Core 设施按配置键工作，变色龙只声明业务参数。
- Core、Content、Development 全部 Release Rebuild，并执行 Core 程序集隔离检查。
- 进游戏实测：释放前摇音效、隐身持续 20 秒、Hediff 到期后持续消耗注销、Ability 40 秒冷却、芯片重新激活后恢复剩余冷却、另一张变色龙不能绕过共享冷却。
