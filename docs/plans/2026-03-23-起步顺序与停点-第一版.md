# 起步顺序与停点（第一版）

## 目的

这份文档只规定两件事：

- 二次重构正式开写前，按什么顺序推进
- 每推进到哪里必须停下来核对，不允许一路失控写下去

## 一、总路线

当前起步路线固定为：

1. 定边界
2. 定 owner
3. 定第一阶段范围
4. 定对象到接口映射
5. 定旧功能纳入时机
6. 定开写顺序
7. 再进入真正实现

前五步已经基本落文档。

现在这份文档负责把第六步也固定下来。

## 二、正式开写前的顺序

### 第 1 步：先做资源闭环

范围：

- `CompTrion`
- `ITrionState`
- `ITrionEvents`

完成标准：

- 资源基本读写语义成立
- 正式占用和预占用成立
- 可用值耗尽事件成立

停点检查：

- 资源 owner 有没有被别的系统偷走
- 持续消耗语义是不是已经够第一阶段使用

### 第 2 步：再做战斗体基础相位

范围：

- `CombatBodyState`
- `ICombatBodyPhaseState`
- `ICombatBodyCoordinator`
- `ICombatBodyHost`

完成标准：

- 手动激活成立
- 手动解除成立
- `Inactive / Active / Cooldown` 跑通

停点检查：

- 战斗体相位有没有开始混进装载和表达细节
- 激活流程是不是已经直接贴着 RimWorld 宿主走

### 第 3 步：做触发体装载与局部激活

范围：

- `CompTriggerBody`
- `TriggerSlotState`
- `ITriggerLoadoutState`
- `ITriggerSlotState`
- `ITriggerActivationCoordinator`

完成标准：

- Main / Sub 槽位可用
- 芯片能装入、卸下、激活、关闭
- 当前激活状态可稳定读取

停点检查：

- 触发体有没有再次膨胀成全能核心
- Main / Sub 命名有没有保持稳定

### 第 4 步：做表达来源收集与解析

范围：

- `IExpressionSource`
- `IExpressionCollector`
- `IExpressionResolver`
- `IResolvedExpressions`

完成标准：

- 能收集当前激活芯片的来源
- 能区分单侧近战与远程
- 能给出默认主近战 / 主远程结果

停点检查：

- 表达系统是不是还在“读来源 -> 出结果”
- 有没有开始自己持有资源、相位、装载真值

### 第 5 步：做 `Verb` 宿主投影

范围：

- `IExpressionProjectionRegistry`
- 真实 `Verb` 宿主桥接

完成标准：

- 当前表达能稳定投到 `Verb`
- 不错误回塞到原版 `VerbTracker.AllVerbs`

停点检查：

- 有没有再次走向“全表达回原版池”
- 主近战 / 主远程投影是否仍分开

### 第 6 步：做三条入口和默认表面投影

范围：

- `IManualCommandProjection`
- `IAutoRangedProjection`
- `IAutoMeleeProjection`
- `IVisualProjection`

完成标准：

- 玩家手动入口成立
- 自动远程桥成立
- 自动近战桥成立
- 默认表面投影成立

停点检查：

- 手动入口和自动入口有没有被合流
- 自动近战和自动远程有没有被混成一条

### 第 7 步：做主动解除收尾

范围：

- 清表达
- 释放资源
- 恢复宿主
- 清入口

完成标准：

- 主动解除后不留脏状态

停点检查：

- 资源是否全部释放
- 入口是否全部撤销
- 宿主状态是否恢复

## 三、哪些情况必须暂停，不继续深入

出现下面任一情况，就该停下来回看文档和旧代码：

### 1. 某个对象开始同时知道太多系统事实

说明：

- owner 又开始混了

### 2. 某个协调者开始持有长期真值

说明：

- 协调层开始变核心层

### 3. 某个投影器开始重做业务规则

说明：

- 入口层开始回吞表达层

### 4. 某项功能需要解释不清才能继续写

说明：

- 需求理解还不够
- 该回旧 BDP 查代码事实

### 5. 某项实现明显只是在追求“更统一”

说明：

- 很可能又在偏离 RimWorld 原版通道现实

## 四、哪些地方该深入，哪些地方先不要钻

### 该深入的

- 资源语义是否和旧 BDP 一致
- 战斗体相位是否和旧 BDP 一致
- 自动近战 / 自动远程桥接是否回到 RimWorld 正确入口
- 主动解除收尾是否完整

### 先不要钻的

- 大量 UI 细节
- 表现优化
- 复杂组合技完整效果
- 高级资源恢复规则
- 大量测试内容

## 五、当前结论

后面真正开写时，
应当按“资源 -> 战斗体 -> 装载 -> 表达 -> 投影 -> 收尾”的顺序推进。

每走完一步就停一下，
确认边界没混、目标没漂，再进入下一步。
