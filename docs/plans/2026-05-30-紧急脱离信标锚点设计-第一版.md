# 紧急脱离信标锚点设计 - 第一版

## 目标

在新 BDP 主模组中新增一个“紧急脱离信标”建筑。战斗体被动崩解并具备“紧急脱离”被动表达时，传送落点优先使用该信标附近的安全格。

该功能属于主模组基础设施：建筑只提供“可用锚点服务”，不持有紧急脱离流程真值，不决定是否触发紧急脱离，也不消费芯片。

## 已确认事实

### 新 BDP 现状

- 紧急脱离是否可用由 `CombatBodyEmergencyEscapeResolver` 读取已发布的 Passive（被动）表达结果。
- 紧急脱离执行由 `CombatBodyEmergencyEscapeService` 负责传送、特效、芯片消费、解除征召。
- 传送落点集中在 `CombatBodyEmergencyEscapeRouter.FindEscapeDestination(Pawn pawn, Map map)`。
- 当前路由只在小人附近 12 格内寻找可站立、未战争迷雾格，失败则原地。

### 原版参考

- 原版基因装配台使用 `CompPowerTrader`（供电组件）和 `CompFlickable`（开关组件）表达“通电且启动”。
- 原版轨道贸易信标贴图路径为 `Things/Building/Misc/DropBeacon`，图形类为 `Graphic_Single`。

### 旧 BDP 参考

旧 BDP 的 `EmergencyEscapeRouter` 使用四级落点回退：

```text
通电紧急脱离信标附近
    ↓
最近殖民者建筑附近
    ↓
地图中心附近随机安全格
    ↓
原地
```

旧信标 `BDP_EmergencyBeacon` 的关键约束：

- 地图内只能建造一座。
- 需要通电。
- 使用 `CompPowerTrader` 和 `CompFlickable`。
- 建筑本体是普通 `Building`，不拥有退出流程。

这些旧策略保留为新 BDP 的行为参考，但新实现要服从当前主模组的分层：路由只选落点，退出事务仍由现有紧急脱离执行链负责。

## 非目标

- 不改“紧急脱离”被动表达解析规则。
- 不改芯片消费逻辑。
- 不把建筑做成战斗体流程 owner（所有者）。
- 不加入 DevHarness（伴生测试模组）业务原型。
- 不引入复杂 FacilityService（设施服务）大框架；本轮只做当前需求需要的最小设施能力。

## 建筑设计

新增建筑 Def：

```text
defName: BDP_EmergencyEscapeBeacon
label: 紧急脱离信标
thingClass: BDP.Core.CombatBody.Building_EmergencyEscapeBeacon
texPath: Things/Building/Misc/DropBeacon
size: (1,1)
designationCategory: Misc
```

组件：

```text
CompProperties_Forbiddable
CompProperties_Power + CompPowerTrader
CompProperties_Flickable
BDP.Core.Trion.CompProperties_Trion
```

Trion（触力）预留：

- 建筑挂 `CompTrion`，`baseMax=0`，`recoveryPerDay=0`。
- 本轮不消耗、不恢复、不参与路由判断。
- 建筑类暴露只读/命令口的属性，未来可接入建筑耗能、充能或网络服务。

地图数量限制：

- 沿用旧 BDP：每张地图只允许一座紧急脱离信标。
- 使用一个通用 `PlaceWorker_OnlyOnePerMap`，只检查同 Def 的殖民者建筑。

## C# 设计

### `Building_EmergencyEscapeBeacon`

职责：

- 读取自身供电状态。
- 暴露 `IsActiveAnchor`，表示该建筑能作为紧急脱离锚点。
- 暴露未来 Trion（触力）接口，不参与当前业务。

判定规则：

```text
Spawned（已生成）
&& !Destroyed（未销毁）
&& Faction == Faction.OfPlayer（玩家殖民者建筑）
&& power == null || power.PowerOn（无供电组件时视为可用；有则必须通电）
```

### `PlaceWorker_OnlyOnePerMap`

职责：

- 在放置阶段限制同一地图上同 Def 殖民者建筑只存在一座。
- 这是通用建筑放置辅助，不携带紧急脱离业务。

### `TrionSurfaceAccess`

当前 `TrionSurfaceAccess` 只支持 `Pawn`。为建筑预留接口时，新增 `ThingWithComps` 重载：

```csharp
public static ITrionReader ResolveReader(ThingWithComps thing)
public static ITrionCommands ResolveCommands(ThingWithComps thing)
public static ITrionEvents ResolveEvents(ThingWithComps thing)
```

保留现有 `Pawn` 重载，避免影响既有调用。

## 路由设计

新路由顺序：

```text
1. 启动的紧急脱离信标附近 1 格
2. 最近殖民者建筑附近 10 格
3. 小人当前位置附近 12 格
4. 地图中心附近随机安全格
5. 原地
```

说明：

- 第 1、2、4 层继承旧 BDP 的意图。
- 第 3 层保留新 BDP 当前“原地附近安全格”行为，减少无信标时的突兀远距离传送。
- 信标落点不使用建筑格本身，而是在附近找可站立、未战争迷雾格。
- 路由失败时返回小人原位置，保持当前执行链可继续收尾。

## 数据流

```text
CombatBody 崩解入口
    ↓
缓存紧急脱离解析结果
    ↓
崩解延时结束
    ↓
CombatBodyEmergencyEscapeService
    ↓
CombatBodyEmergencyEscapeRouter
    ↓
信标 / 殖民者建筑 / 近身 / 地图安全格
    ↓
设置 pawn.Position 并刷新图形
```

建筑只参与 `Router` 的落点查询，不进入上游判定和下游收尾。

## 验证策略

### Smoke tests（烟测）

新增 `CombatBodyEmergencyEscapeBeaconRouteSmokeTests.ps1`，锁定：

- 建筑 XML 存在。
- 建筑使用轨道贸易信标贴图。
- 建筑包含供电、开关、Trion（触力）预留组件。
- 建筑使用 `Building_EmergencyEscapeBeacon`。
- 路由顺序包含信标、殖民者建筑、小人附近、地图中心、原地。
- 路由不读取芯片定义，不重新解析紧急脱离。

### 构建

- 主模组 Release（发布版）构建通过。

### 游戏内实测

必要实测：

1. 无信标时，紧急脱离仍可回退到安全位置。
2. 有信标但未通电时，不使用信标。
3. 有信标且通电时，优先传送到信标附近。
4. 尝试在同地图放第二座信标，被放置提示拦截。

## 风险与处理

- 多信标风险：放置阶段限制一座；若调试生成出多座，路由可接受第一座有效信标，不额外做复杂仲裁。
- 无可站立格风险：信标附近找不到格时继续回退，不中断紧急脱离。
- Trion（触力）预留风险：只挂空资源组件，不参与当前逻辑，避免未来接口污染当前行为。
- 建筑流程膨胀风险：建筑类只回答“我是否可作为锚点”，不拥有退出流程。

## 最终裁决

按旧 BDP 的路由策略收回“安全地带”的体验，但按新 BDP 的工程边界收紧实现：

```text
旧行为意图：信标优先，失败后找殖民者安全区，再随机安全区。
新实现边界：建筑只提供锚点服务，紧急脱离流程仍由 CombatBody 现有链路拥有。
```
