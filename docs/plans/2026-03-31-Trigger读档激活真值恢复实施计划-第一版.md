# Trigger读档激活真值恢复 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 把 Trigger 在读档阶段的激活真值与投影恢复链补完整，消灭“slot/container 已恢复但 expression/host 仍为空”导致的 `bugged verb after loading`。

**Architecture:** 现状不是 `chipContainer` 再次成为业务真值，而是读档恢复链在 `PostLoadInit` 内刚恢复完 slot/container 后，又经由通用读路径触发 `PrepareReadState()`，把 slot 激活/禁用状态重新按未稳定的宿主运行时做了一次重算。整改后，`PostLoadInit` 必须拥有显式恢复阶段：恢复阶段内只允许消费已恢复的 slot 正式真值，不允许读路径再次触发禁用同步或切换结算；恢复阶段结束后才回到常规运行时读路径。

**Tech Stack:** RimWorld 1.6 C#, Verse `Scribe` 序列化, Harmony mod runtime, PowerShell smoke tests

---

## Scope

- 只处理 Trigger 读档后的激活真值恢复与投影恢复。
- 不回退单一真值方向，不重新把 `chipContainer` 拉回业务层。
- 不在攻击层追加症状兜底。

## Non-Goals

- 不做旧存档兼容迁移层设计。
- 不扩展新的战斗规则或 UI 行为。
- 不重写整套 Trigger 切换系统。

## Success Criteria

- `PostLoadInit` 内部完成 slot/container 恢复后，首次表达快照必须能直接消费恢复好的正式真值。
- 恢复阶段内，不允许 `PrepareReadState()` 再次改写 slot 激活/禁用状态。
- 读档后首次宿主重建能够产出主远程宿主，自动远程入口不再报告 missing host。
- 手工场景下，战斗中存档再读档不再出现 `Verse.Stance_Warmup had a bugged verb after loading`。

## Architecture Decisions

### Decision 1: 读档恢复阶段必须是显式生命周期阶段

- `CompTriggerBody` 必须显式标识“当前正处于 PostLoad 恢复阶段”
- 该阶段只允许恢复正式真值与投影，不允许触发常规运行时重算

### Decision 2: 通用读路径不得在恢复阶段改写真值

- `PrepareReadState()` 在恢复阶段必须短路
- `SyncDisabledStateFromOwnerPawn()` 与 `ResolveDueSwitchTransitions()` 仍然保留为常规运行时逻辑
- 但它们不能插入 `PostLoadInit` 的恢复链中途

### Decision 3: 首次投影重建必须直接依赖已恢复的 slot 正式真值

- expression snapshot 的首次重建必须建立在恢复后的 active/loadout truth 上
- verb host 只跟随 snapshot
- auto ranged 只跟随 host
