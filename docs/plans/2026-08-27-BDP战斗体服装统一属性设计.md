# BDP 战斗体服装统一属性设计

## 背景

战斗体前台服装有 `MirrorOriginal` 与 `Preset` 两条生成分支。两条分支最终都属于战斗体激活期间的临时前台服装，因此必须共同满足以下运行时契约：

- 不可主动脱下；
- 无品质；
- 无耐久损耗、不会因耐久销毁，并且界面不显示耐久；
- 退出战斗体后按现有镜像/预设生命周期恢复或销毁。

当前代码只在公共穿戴循环中使用 `locked: true`，品质处理只存在于镜像生成函数，预设服装和耐久没有统一处理。

## 根因

RimWorld 原版把耐久开关放在共享 `ThingDef.useHitPoints`，不是服装实例属性。预设通过 `ThingMaker.MakeThing(apparelDef)` 直接生成原版服装，因此自然继承原版品质组件和耐久行为。镜像当前反射移除品质组件只影响当前内存实例；原版 `ThingWithComps.ExposeData` 在读档加载变量时会按 Def 重新初始化组件，所以读档后仍可能恢复品质组件。

## 方案

### Core：只维护中性身份与生命周期

在现有前台服装公共生命周期中增加中性登记能力：

1. 两分支生成完成后，服装成功穿戴时登记为当前战斗体前台服装。
2. 退出时移除登记。
3. 读档后的 `PostLoadInit` 根据现有持久化的 `ActiveApparelThingIds` 和当前穿戴列表重建登记。

该登记只表达“此实例由战斗体前台层拥有”，不包含无品质、无耐久等业务规则。

### Content：统一实现战斗体服装规则

在公共穿戴边界调用一个统一规范化入口，对登记范围内的战斗体服装执行：

1. 移除 `CompQuality`，复用当前已有的组件清理逻辑。
2. 将实例耐久归一到满值，防止旧版本或读档残留导致原版锁定自动解除。
3. 对已登记实例屏蔽 `Thing.TakeDamage`，阻止耐久损耗、耐久归零销毁和死亡时的服装耐久损伤。
4. 对已登记实例隐藏 `ThingWithComps.GetTooltip` 和 `GetCustomLabelNoCount` 中的耐久显示。

不修改共享 `ThingDef`，不向 `CombatBodyFrontPresetDef` 增加属性，也不为每个预设复制一套规则。

## 生命周期与存档

- 激活：生成 → 统一规范化 → `Wear(..., locked: true)` → 成功穿戴后登记并写入已有 `ActiveApparelThingIds`。
- 运行：登记身份作为 Harmony（和谐补丁）的唯一判据，普通服装不匹配。
- 读档：在宿主 `PostLoadInit` 重建登记，并再次规范化当前激活服装；这样可以覆盖原版重新初始化 `CompQuality` 和保存的旧耐久值。
- 退出：先注销身份，再按现有模式移除；镜像销毁，预设放回 `CombatApparelContainer`。

## 不采用的方案

- 不把 `useHitPoints=false` 写进具体预设：这只覆盖某个 Def，无法保证镜像和未来预设。
- 不修改原版或共享服装 Def：会影响普通服装。
- 不为每个实例动态克隆并注册 ThingDef：会引入 Def 身份、存档解析和全局注册生命周期问题，不是本问题的最小改动。

## 验收标准

1. `MirrorOriginal` 与 `Preset` 均无品质、无耐久显示。
2. 两者均不会发生耐久下降、耐久销毁或因耐久导致的自动解锁。
3. 两者均保持不可主动脱下。
4. 存档/读档后上述行为不变。
5. 退出战斗体后镜像销毁、预设回收，原身服装恢复逻辑不变。
6. 普通服装不受影响。
