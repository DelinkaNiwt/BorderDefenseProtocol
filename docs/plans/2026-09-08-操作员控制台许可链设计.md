# 操作员控制台许可链设计

## 目标

新增“操作员控制台”建筑。它必须由玩家指派的小人持续操作，并接入电力；同时必须收到“Trion中继核心”的上游许可。控制台进入运作状态后，只发布一个稳定的下游地图许可，供本地图玩家派系的芯片业务读取。芯片业务收到许可后做什么，由各自业务逻辑决定，Core 不写入具体武器效果。

## 已确认事实

- BDP 主模组分为 Core、Content、Development 三层；Core 不依赖 Content，正式建筑和芯片业务放在 Content，调试设施放在 Development 或正式内容的开发按钮入口。
- BDP 已有 `TrionFacilityMapComponent`，能按建筑生命周期登记 Trion 中继核心，并实时判断玩家派系设施是否有效。
- 远程表达已经把 `RequireLineOfSight` 与 `RequiresDirectTargetLineOfSight` 分成两层；后续免直视范例必须在业务接收器中处理，不能直接全局改写所有远程攻击。
- BDP 已有手动操作建筑的工作驱动模式和语言包键；Trion 中继核心资源组件已有可持久化的强制运行调试按钮模式。
- 当前工作区有用户未提交的 `1.6/Content/Defs/ChipFunctionDef/Presets.xml` 修改，本需求不得覆盖或回退该修改。

## 核心概念

### 运作状态与许可分层

控制台的内部运作状态和对外许可严格分开：

```text
控制台运作状态
  = 强制运作调试覆盖
    或（电力正常
        且玩家指派的小人正在操作
        且 Trion 中继核心上游许可有效）

BDP.OperatorConsole.Active
  = 控制台运作状态

芯片业务
  = 只查询 BDP.OperatorConsole.Active
```

下游许可提供器不能再次读取电力、操作员或 Trion 中继核心；这些条件只存在于控制台自身的运作状态判定中。这样未来更换运作条件时，不需要修改所有芯片消费者。

### 中性许可接口

Core 提供以下中性运行时契约：

- 地图许可读取接口：按 `Map（地图）`、`Faction（派系）` 和许可键查询当前许可是否存在。
- 地图许可提供接口：由具体建筑或其它业务对象报告自己当前提供的许可键和有效状态。
- 芯片功能许可接收接口：通用芯片表达运行时向具体业务传递只读许可上下文。上下文至少包含当前 Pawn、Map、Faction、结果标识和许可读取入口。

表达侧使用 `DeclaredPermissionKeys` 表示“该表达主动声明愿意接入哪些许可判定”。Core 另提供直达目标视线许可解析器接入点，但不登记或解释任何具体许可键。

Core 只负责收集和传递事实，不把任何许可键映射为“免直视、加伤害或其它效果”。具体业务通过接收接口自行解释许可。

### 许可归属

- 许可作用域为当前地图。
- 许可对象为玩家派系。
- 任意一个有效的同类提供者即可提供许可，不叠加效果。
- 建筑离图、派系不再是玩家派系、运作状态失效或地图重建后，许可查询必须立即反映真实状态。

## Content 实现边界

### 建筑尺寸与视觉资源（已确认）

- 逻辑占地固定为 `3×2`，四方向可旋转。
- 交互格位于建筑相对南侧一格，`interactionCellOffset=(0,0,-1)`。
- 暂时复用原版通信台多朝向贴图 `Things/Building/Misc/CommsConsole`，图形类为 `Graphic_Multi`。
- 视觉绘制尺寸沿用原版 `drawSize=(5,4)`；这只影响贴图显示边界，不改变 3×2 的阻挡、寻路和交互占地。
- 本次不新增自定义建筑 PNG；若游戏内观感过大，后续只调整 `drawSize`，不改变许可链契约。
- 基础功耗暂定为 `200 W`，通过 ThingDef 配置，不在 C# 中硬编码。

### Trion 中继核心

沿用现有 `TrionFacilityMapComponent` 的资源结算和生命周期登记。Content 通过中性许可提供接口把“存在有效玩家派系 Trion 中继核心”发布为上游许可，例如 `BDP.TrionRelayCore.Active`。不把 Trion 资源细节下沉到 Core。

### 操作员控制台

- 新增独立的 `Building_OperatorConsole` 和运行状态组件，放在 `Source/BDP.Content`。
- ThingDef 放在 `1.6/Content/Defs/ThingDef/Buildings`，使用原版 `CompPowerTrader` 电力组件，并配置交互格。
- 控制台运行状态组件只保存必要的持久化调试覆盖；操作员引用和心跳属于运行时瞬态，读档后必须重新建立。
- 手动操作工作使用独立 `JobDef`、`JobDriver` 和 `WorkGiverDef`。第一版仅允许玩家右键指派，不参与自动工作扫描；为以后增加可选自动工作保留 `directOrderable` 与工作资格边界。
- 工作驱动通过预留控制台和交互格，持续心跳更新操作状态；工作结束、被打断、无法触碰、操作员失去 Manipulation（操作）能力或控制台离图时清除状态。
- 控制台下游许可提供器只读取 `IsOperational`，不得重新组合其前置条件。

### 上帝模式调试

- 控制台提供与原版电力设施一致的强制运行切换。
- 调试按钮只在上帝模式/开发 Gizmo 条件满足时出现，所有玩家可见文本进入简体中文语言包。
- 强制运行状态持久化到存档；开启时 `IsOperational` 直接为真，绕过电力、操作员和 Trion 中继核心许可；关闭后立即恢复真实条件计算。
- 检视文本明确区分“真实运作中”“调试强制运作”和“未运作”，避免把调试覆盖误认为操作员仍在工作。
- 其它调试按钮保持可插拔；本次至少保留强制运作按钮和状态诊断入口，不把调试逻辑写入 Core。

## 芯片业务范例边界

首个范例不做全局远程武装改写。新增一个 Content 业务接收器，只有显式声明接收 `BDP.OperatorConsole.Active` 的远程表达结果才参与处理；它在普通远程 Verb 与 Ability 的当前目标准入/执行阶段读取许可，并自行决定是否把“必要直达视线”降为不要求。

- 未声明接收许可的远程表达保持现有行为。
- 原本 `DirectTargetLineOfSight=NotRequired` 的表达不因许可发生变化。
- 双侧远程、手动瞄准、持续发射和普通 `VerbProps.requireLineOfSight` 的模块内部路径检查继续分别遵守各自契约。
- 许可读取必须发生在实际攻击运行时，而不是在 Def 加载或静态表达缓存阶段冻结，以便控制台状态变化能即时生效。

## 数据流与时序

```text
Trion 中继核心资源结算
  -> 上游许可提供器
  -> 地图许可查询

玩家右键指派小人
  -> 预留控制台/交互格
  -> JobDriver 心跳
  -> 控制台运作状态
  -> 下游许可提供器
  -> 芯片业务接收器读取许可
```

许可查询不保存一份独立的“下游真值”；地图组件只维护可重建的提供者索引，提供者状态从建筑组件实时读取。读档后先重建索引，再按当前 tick（游戏刻）和建筑状态计算。

## 异常与生命周期

- 地图、派系、建筑组件、操作员或许可读取器缺失时按未运作/未授权处理，不抛出异常阻断游戏。
- 工作驱动结束必须通过统一清理路径释放操作状态；地图组件同时清理失效提供者引用。
- 强制运行覆盖只属于控制台自己的调试状态，不修改电力组件状态、不伪造 Pawn 工作、不修改 Trion 中继核心资源。
- 多个控制台各自独立运作；同一地图许可只报告存在，不叠加许可强度。

## 验证方案

1. 先写 Core 许可契约、控制台状态判定和芯片接收边界的失败测试，确认测试因功能缺失而失败。
2. 编写通过测试所需的最小接口、地图提供者索引和控制台组件；再运行全部相关 PowerShell（脚本）烟雾测试。
3. 检查 ThingDef、JobDef、WorkGiverDef 和语言包 XML 结构，确认无重复 DefName、缺失语言键或错误程序集类型。
4. 构建 `BDP.Core`、`BDP.Content` 和 `BDP.Development`，确认依赖边界检查通过。
5. 在 Development/游戏内验证：断电、撤销操作员、Trion 核心失效、建筑离图和读档均会撤销许可；上帝模式强制运作可绕过三项真实条件，关闭后恢复真实状态。
6. 使用至少一个显式接收许可的远程表达和一个未接收许可的远程表达验证免直视范例没有全局污染。

## 不在本次范围内

- 不实现自动派工，只保留未来可选自动工作的接入点。
- 不修改 Trion 中继核心的资源消耗、献祭或升级系统。
- 不让下游芯片直接知道电力、操作员或 Trion 核心条件。
- 不对所有远程芯片统一取消直视。
- 不修改现有用户未提交的芯片 Def 数值。
