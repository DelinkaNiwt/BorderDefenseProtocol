# BDP 开发辅助程序集 Implementation Plan（实施计划）

> **For Claude（给执行代理）:** REQUIRED SUB-SKILL（必需子技能）: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal（目标）:** 在主模组工程内增加一个仅供开发环境加载的 `BDP.Development.dll`，集中承载详细诊断输出、开发可视化、临时原型和游戏内测试入口，同时保证 Core、Content 和正式发布产物对它零依赖。

**Architecture（架构）:** `BDP.Development` 单向引用 `BDP.Core` 与 `BDP.Content`，输出到独立的 `1.6/Development/Assemblies` 加载目录。Core 保留中性诊断发射口，Development 注册实际日志接收器并接管纯开发可视化；正式发布由用户手动移除开发产物，再运行只检查不删除的发布门禁。

**Tech Stack（技术栈）:** C# 7.3、.NET Framework 4.8、RimWorld 1.6、Verse、Harmony（和谐补丁库）、旧式 MSBuild（微软构建系统）工程、PowerShell 5.1 冒烟与反射测试。

**Step 3: 实现最小中性出口**

Core 接口：

```csharp
public interface IBdpDiagnosticSink
{
    void Write(string message);
}
```

注册表只维护一个当前接收器：

```csharp
public static void Register(IBdpDiagnosticSink sink);
public static void Unregister(IBdpDiagnosticSink sink);
internal static void Write(string message);
```

要求：空接收器安全静默；重复注册以最后一次为准；只有传入同一实例才能注销；`Write` 捕获接收器异常。`BdpDiagnostics` 继续拥有开发模式判断、Once（一次性）、Throttled（节流）和攻击执行通道，但 `SafeLog` 改为调用注册表。

Development 实现：

```csharp
public sealed class VerseLogDiagnosticSink : IBdpDiagnosticSink
{
    public void Write(string message)
    {
        Log.Message(message);
    }
}
```

`DevelopmentBootstrap` 始终安全注册日志接收器；是否输出仍由 Core 当前 `Prefs.DevMode` 判断。临时 Harmony 补丁只在安全读取到开发者模式开启时执行 `PatchAll()`。
