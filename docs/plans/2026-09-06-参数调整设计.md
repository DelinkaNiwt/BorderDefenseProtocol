# BDP 参数调整设计

## 目标

按本次平衡需求，调整毒蛇、朱鹮、左轮手枪、旋空弧月、冲锋枪和风刃的正式运行参数；保持现有攻击链、模块边界、视觉和存档结构不变。

## 已确认事实

- 当前正式参数位于 `1.6/Content/Defs` 下的投射物、武装构型和 Ability 定义中。
- 毒蛇使用 `BDP_Projectile_Variable`；朱鹮使用 `BDP_Projectile_SniperStandard`。
- 左轮手枪的射程、冷却和伤害倍率由 `BDP_ArmamentForm_Revolver` 覆盖。
- 旋空弧月同时有 Ability 的目标射程和波体组件的最大有效范围；两处都必须收口到 25，避免瞄准范围与实际波体范围不一致。
- 冲锋枪当前 XML 默认说明和简体中文 Keyed（键值语言包）说明仍写“六发”，需要同步为“四发”。
- 风刃的伤害、护甲穿透和飞行速度直接由 `BDP_Projectile_Fujin` 的投射物字段承载。

## 方案比较

### 方案 A：直接调整正式 Def（采用）

修改现有 XML 参数，并更新必要的玩家说明、冒烟测试断言和注释。该方案沿用 RimWorld 原版字段和现有 BDP 解析链，改动最小、可直接由游戏重新加载。

### 方案 B：新增统一平衡配置层

把所有数值抽到新的配置类或总表，再由运行时覆盖。这样集中管理，但会新增一套与现有 Def 并行的真值来源，不符合本次简单参数调整的最小介入原则。

### 方案 C：在运行时代码中按 Def 名称强制修正

通过初始化或攻击执行阶段改写数值。该方案会绕过正式 Def，并增加加载时序、存档和兼容性风险，不采用。

## 参数变更

| 对象 | 字段 | 原值 | 新值 |
|---|---|---:|---:|
| 毒蛇 `BDP_Projectile_Variable` | `projectile.speed` | 200 | 120 |
| 朱鹮 `BDP_Projectile_SniperStandard` | `projectile.speed` | 250 | 150 |
| 左轮手枪 `BDP_ArmamentForm_Revolver` | `overrides.range` | 15 | 20 |
| 左轮手枪 `BDP_ArmamentForm_Revolver` | `overrides.defaultCooldownTime` | 1.6 秒 | 1.5 秒 |
| 左轮手枪 `BDP_ArmamentForm_Revolver` | `projectileOverrides.damageMultiplier` | 5 | 4 |
| 旋空弧月 `BDP_Ability_SenkuKogetsu` | `verbProperties.range` | 40 | 25 |
| 旋空弧月波体组件 | `maxRange` | 40 | 25 |
| 冲锋枪 `BDP_ArmamentForm_SubmachineGun` | `overrides.burstShotCount` | 6 | 4 |
| 风刃 `BDP_Projectile_Fujin` | `projectile.damageAmountBase` | 50 | 20 |
| 风刃 `BDP_Projectile_Fujin` | `projectile.armorPenetrationBase` | 0.50 | 0.35 |
| 风刃 `BDP_Projectile_Fujin` | `projectile.speed` | 120 | 140 |

不修改左轮手枪的预热、连发模式和停止力，不修改旋空弧月最小范围、伤害和速度，不修改风刃齐射数与追踪模块。

## 最小改动范围

- 修改 `1.6/Content/Defs/ThingDef/Projectiles/Projectiles.xml`。
- 修改 `1.6/Content/Defs/ThingDef/Projectiles/Fujin.xml`。
- 修改 `1.6/Content/Defs/ChipArmamentFormDef/Presets.xml`。
- 修改 `1.6/Content/Defs/AbilityDef/SenkuKogetsu.xml`。
- 修改 `Languages/ChineseSimplified (简体中文)/Keyed/ChipManufacturing.xml` 中冲锋枪说明。
- 更新现有风刃/冲锋枪检查脚本；若现有脚本没有覆盖本次参数，则新增一个只读参数冒烟测试。
- 同步过时的 XML 注释和工作日志；不修改 `Core.dll`、`Development.dll`、旧版/归档模组或视觉资源。

## 验证

1. 解析所有涉及 XML，确认结构合法、Def 唯一且每项新值准确。
2. 运行参数冒烟测试、风刃检查、冲锋枪检查及相关正式边界检查。
3. 运行正式发布目录和程序集边界检查；参数变更不应引入程序集改动。
4. 复核 Git 差异和工作日志；游戏内需要最终观察射程、冷却、飞行速度和实际伤害表现。
