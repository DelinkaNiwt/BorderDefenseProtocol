# 投射物整发高角视觉进度设计

## 目标

让高角飞行只表达一发投射物从发射开始到整发结束的一次“起飞—落下”视觉过程，不感知追踪、路线或其它模块把物理飞行切成多少段。

## 已确认的问题

当前高角视觉偏移使用当前 `ProjectileFlightPathSnapshot`（当前物理路径快照）和当前段进度。追踪投射物每次续飞都会绑定新的路径，当前段进度重新从零开始，于是每个短段都会重新播放一次高角抛物线。目标附近的短 `terminal_approach`（末端接近）段配合固定弧高后，形成截图中的尖锐“落地弹跳”视觉。

## 设计决策

### 物理路径与高角视觉解耦

投射物继续使用当前物理路径处理移动、追踪、碰撞和到达。该路径可以被任意模块切分或替换。

高角视觉不再以当前物理路径段作为弧线进度来源，而使用整发投射物的全局飞行进度：

```text
物理路径：发射点 → 物理段1 → 物理段2 → 实际结束点
高角视觉：整发进度 0 → 1，只升起一次、只落下一次
```

高角视觉的水平基准仍使用投射物当前真实位置，从而在目标移动时不把视觉落点冻结在旧目标位置；只有升降偏移使用整发进度。

### Core 与 Content 的职责

- Core（核心层）只提供并维护整发飞行进度的中性生命周期输入，并在绘制、朝向和视觉采样时消费该进度。
- Content（内容层）的高角模块只提交起点偏移、终点偏移和弧高参数，不读取物理路径段，也不判断续飞类型。
- Homing（追踪）和 Route（路线）模块只继续负责物理路径，不增加高角适配分支。

### 实现倾向

优先复用现有投射物生命周期和冻结的发射计划，删除高角视觉对当前段进度的依赖。只有在现有生命周期无法表达整发进度时，才增加一个通用的整发飞行时钟；不增加追踪或高角专用状态。

## 不在本次范围内

- 不修改追踪转向、时间预测、追踪强度和目标躲避概率。
- 不修改命中、碰撞、掩体和真实三维高度语义。
- 不强制把水平视觉路线固定成发射点到初始目标点的直线；移动目标仍由物理位置决定视觉水平基准。
- 不对 Core 做无关的大规模拆分或重命名。

## 验收标准

1. 高角直射静止目标只出现一次完整弧线。
2. 高角追踪静止目标在多次续飞后不出现重复上升、尖角或落地弹跳。
3. 高角追踪移动目标最终视觉位置仍跟随实际投射物位置，并在整发结束时完成下降。
4. 普通低角投射物的追踪、命中和可躲避性不改变。
5. 位置、朝向和拖尾在物理路径切换处使用同一全局高角进度，不产生不同步。
6. 存档读档后高角进度能够继续，不重新播放或跳变。
