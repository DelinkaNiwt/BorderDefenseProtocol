# 战斗体编辑台与个人服装模板设计

## 目标

新增“战斗体编辑台”建筑，让每个 Pawn（小人）在游戏中动态创建、选择、重命名和删除自己的战斗体服装模板，并在生成战斗体时使用选中的模板作为外观。

本功能是现有战斗体前台衣物“镜像 / 预设”两条分支中预设分支的个人化版本：模板由玩家在游戏中上传，而不是由开发者预先写入 XML（可扩展标记语言）。

## 已确认行为

- 所有人形 Pawn 的默认模式统一为 `MirrorOriginal`（镜像原身）。
- 只有 Pawn 选择了有效个人模板时，才使用 `Preset`（预设）模式。
- 删除当前模板、模板失效或个人数据缺失时，自动切回镜像。
- 每个 Pawn 独立拥有多套模板；模板不按地图隔离，跨地图、离开地图和读档后仍属于原 Pawn。
- 新模板自动命名，并允许玩家重命名。
- 允许上传空模板；空模板表示预设模式下不挂载前台服装。
- 上传模板时保存当前穿着服装的外观字段：服装定义、实际 `Stuff`（材料）、颜色和 `StyleDef`（风格）。不保存品质、耐久等不影响外观的属性。
- 上传成功后，原实体服装从 Pawn 身上移除并转入其库存；实体不销毁，避免异常、读档或删除模板时丢失物品。
- 上传成功后自动选中新模板，但不强制把模式切换为预设；“保存模板”和“启用模板”是两个明确操作。
- 预览显示穿上模板后的完整 Pawn 立绘；预览使用临时服装副本，结束后恢复 Pawn 原状态，不消耗模板或真实服装。
- 当前战斗体激活期间不能打开编辑台，避免把战斗体前台衣物误当作原身服装上传。

## 最小方案

### 1. 数据宿主

- 在 `BDP.Content.dll` 增加一个存档级 `GameComponent`（全局存档组件）个人外观模板账本。
- 不再给 Pawn 注入新的 `ThingComp`（组件）。当前 BDP 已有 Trion、CombatBody、Trion 天赋检测和紧急脱离四类 Pawn 组件，不为本功能继续叠加组件。
- 账本按 Pawn 的持久引用 / `ThingID`（唯一 ID）绑定，不保存地图归属。
- Pawn 永久销毁后清理对应档案；Pawn 换地图或暂时成为世界小人时保留档案。

### 2. 模板数据

每个 Pawn 档案保存：

- 当前个人模式；
- 当前选中的模板 ID；
- 模板列表；
- 下一个自动编号。

每个模板保存：

- 稳定模板 ID；
- 玩家可见名称；
- 服装外观记录列表。

每条服装外观记录保存：

- `ThingDef`（服装定义）；
- `Stuff` 对应的 `ThingDef`（实际材料）；
- 是否存在有效染色及颜色值；
- `StyleDef`（风格定义）。

通过 `Scribe_Defs`（Def 存档）保存定义引用，通过 `Scribe_Values`（值存档）保存模式、ID、颜色等值，通过深度存档保存模板和服装记录集合。

### 3. Core / Content 边界

- `BDP.Core.dll` 只增加中性的“按 Pawn 解析战斗体前台外观”扩展口与运行时服装外观条目。
- `PawnCombatBodyBridge` 在进入战斗体时先查询该扩展口；没有个人有效预设时，继续执行镜像逻辑。
- `BDP.Content.dll` 提供个人账本解析器，负责把个人模板转换为 Core 可消费的运行时条目。
- Core 保留通用固定 `CombatBodyFrontPresetDef`（前台固定预设 Def）能力，但 BDP 默认配置改为镜像；现有临时固定服装 XML 后续删除，不再作为 BDP 正式内容。
- 动态预设每次生成都按当前模板重建前台服装并清理旧动态缓存，不能沿用当前固定预设的“容器非空则复用”路径，否则切换模板后可能仍显示旧服装。

## 玩家交互与数据流

1. 玩家选中战斗体编辑台，指定 Pawn 右键选择使用入口。
2. Pawn 走到交互格后打开编辑面板；建筑入口检查建筑存在、通电、可到达、Pawn 可操作且不在战斗体激活阶段。
3. 面板读取该 Pawn 的个人档案，默认显示镜像模式和现有模板列表。
4. 点击新建模板时，先读取 `WornApparel`（当前穿着服装）中的全部外观字段。
5. 所有字段读取成功后，将原服装从服装栏转入 Pawn 库存；任一转移失败则取消本次上传并保持原穿着状态。
6. 创建自动名称模板，自动选中该模板，保存账本。
7. 玩家可重命名、选择或删除模板，也可切换镜像 / 预设模式。
8. 预览选中模板时生成临时服装副本，复制材料、颜色和风格，短暂穿到操作者身上捕获现有 Pawn 肖像，然后移除临时副本并恢复原状态。
9. 下次生成战斗体时，Core 按个人模式解析：镜像走现有原身镜像分支；预设走个人模板动态服装分支。

## 面板布局

沿用现有 BDP 装配台的三栏窗口风格，不提供字段级拖拽编辑：

```text
┌────────────── 战斗体编辑台 · 操作者名称 ──────────────┐
│ 当前模式： [ 镜像 ] [ 预设 ]        当前模板：模板 2 │
├──────────────┬──────────────────────┬───────────────┤
│ 个人模板      │      外观预览        │ 模板详情       │
│ ○ 模板 1     │   小人完整立绘       │ 模板名称       │
│ ● 模板 2     │   镜像或选中模板      │ 服装数量       │
│ ○ 空模板     │                      │ 服装清单       │
│ [+ 新建模板] │                      │ 材料 / 颜色 /  │
│ [重命名]     │                      │ 风格           │
│ [删除]       │                      │ [重命名] [删除]│
├──────────────┴──────────────────────┴───────────────┤
│ [上传当前服装为新模板]                         [关闭] │
└─────────────────────────────────────────────────────┘
```

- 顶部“镜像 / 预设”立即保存当前 Pawn 的分支选择。
- 左栏显示模板名称与服装数量；中栏显示完整 Pawn 立绘；右栏显示服装名称、材料、颜色和风格。
- 上传前弹出确认，说明服装会从身上移入库存；新建成功后自动选中新模板，但不自动切换到预设。
- 删除前弹出确认；重命名使用原版文本输入窗口；所有操作即时保存。
- 空模板是合法模板；没有模板时预设按钮灰显；模板失效时显示警告并自动切回镜像。

## 失效与异常处理

- 个人档案不存在时直接使用镜像，不创建额外运行时状态。
- 选中的模板 ID 不存在时，清除选中 ID 并把个人模式改为镜像。
- 模板中的服装定义或材料定义缺失时，跳过对应条目并写入可搜索的诊断日志。
- 模板没有任何有效条目时视为失效并回到镜像；正常创建的空模板需能明确区分为合法空模板。
- 预览捕获失败时销毁临时纹理和临时服装，并恢复 Pawn 原状态，不改变账本。
- 关闭窗口时释放预览纹理，不能留下 Unity（游戏引擎）资源。
- 删除模板只删除模板数据，不处理已经转入库存的原实体服装。
- 旧存档中已激活的战斗体按存档前台状态完成当前解除；下一次生成遵循新默认镜像，不做危险的实体服装迁移。

## 文案与 Def

- 新建筑、面板按钮、模式名称、失效提示、上传失败提示和预览提示全部写入简体中文语言包。
- 新增建筑 Def、使用 JobDef（工作任务定义）和必要的交互文案放入 `1.6/Content`。
- 默认 `CombatBodyHostConfigDef` 改为镜像，并移除对临时固定预设的引用。
- `1.6/Content/Defs/CombatBody/TemporaryFrontPreset.xml` 后续删除；Core 通用固定预设类型不因本功能强行删除。

## 验证

### 静态与构建

- 编译 `BDP.Core` 与 `BDP.Content`，确认 Core 不反向引用 Content。
- XML 结构检查、Def 加载检查和语言键检查。
- 验证建筑 ThingDef、JobDef、运行时类型和窗口入口一致。
- 更新或新增 Content 边界、GameComponent 存档和动态前台服装的 smoke test（冒烟测试）。

### 游戏内场景

- 使用带材料、染色和风格的服装上传，确认身上消失、库存保留、模板字段完整。
- 生成战斗体并退出，确认个人模板外观正确且原身快照恢复流程不受影响。
- 创建模板 A、B，切换后分别生成，确认不会串用旧前台缓存。
- 删除当前模板，确认立即切回镜像；创建空模板，确认预设模式下无前台服装。
- 小人跨地图、离开地图、读档后继续使用同一模板。
- 缺少服装 Def / 材料 Def、预览失败和库存转移失败时，确认安全回退且无物品丢失。

## 非目标

- 不增加服装字段级编辑器；模板只记录上传时的外观快照。
- 不改变战斗体 Trion、伤口、触发体和武装逻辑。
- 不把个人模板放入 Core，不让 Core 依赖 Content。
- 不为本功能保留开发者预设服装；现有临时固定模板只作为退役清理对象。
