# BDP 简体中文本地化设计

## 目标

把 BorderDefenseProtocol 主模组中已经确定、玩家可见的文字集中提取为 RimWorld 语言键和 DefInjected 文本，首轮只建立简体中文，不建立英文翻译。

## 组织原则

语言文件不按 Core/Content、DLL 或源码类拆分，而按 RimWorld 的语言资源分类组织。程序内部只依赖稳定键名，不依赖具体翻译文件名。

语言资源放在主模组根目录的 `Languages/ChineseSimplified (简体中文)/` 下：

```text
Languages/
└─ ChineseSimplified (简体中文)/
   ├─ LanguageInfo.xml
   ├─ Keyed/
   │  ├─ Commands.xml
   │  ├─ Messages.xml
   │  ├─ StatsReport.xml
   │  ├─ Windows.xml
   │  ├─ Jobs.xml
   │  └─ Gameplay.xml
   └─ DefInjected/
      ├─ ThingDef/
      ├─ GeneDef/
      ├─ HediffDef/
      ├─ StatDef/
      └─ JobDef/
```

`Keyed` 文件按玩家理解的功能分类；`DefInjected` 目录按实际 Def 类型分类，文件名再按游戏内容归类。后续新增语言时复用同样的键名和目录结构。

## 键名规则

- 所有 BDP 自有键使用 `BDP_` 前缀。
- 键名使用稳定的英文标识，不随中文措辞调整而改变。
- 键名按玩家功能命名，例如 `BDP_Command_CombatBody_Activate`、`BDP_Message_Trion_LockedMinimum`。
- 当前简体中文值直接写入对应键；不创建英文值，也不把英文假文本混入中文文件。

## 首轮提取范围

纳入：

1. 玩家可见的按钮、Gizmo、窗口标题、窗口说明、状态文字和消息。
2. 玩家可见的 Hediff、Gene、Stat、Thing、Job 等 Def 文本字段，包括 `label`、`description`、`reportString` 等。
3. 已确定属于主模组正式功能的通用文字。

暂不纳入：

1. 开发者日志、内部断言、配置校验错误和仅用于排查问题的诊断字符串。
2. 测试模组中的具体芯片、候选业务和临时原型文本。
3. 尚未确认命名或业务含义的具体芯片文本。

所有被排除的文字仍会在盘点报告中登记，避免误认为遗漏；只有玩家可见文字会在本轮替换为键调用。

## 运行与兼容约束

- 不改变 Core/Content 的 DLL 依赖方向。
- 不改变现有业务逻辑，仅替换文字来源。
- Def 原始文本保留为默认回退值；语言包用 `DefInjected` 覆盖当前语言，不直接删除必需字段。
- 替换过程中保留格式化参数、数字单位和换行结构。
- 如果中文语言包缺少某个已调用的键，验证阶段必须报告；不能默默留下显示键名的情况。

## 验证方式

1. XML 结构检查：所有语言 XML 可解析，键名无重复。
2. 代码键检查：代码中所有新增 `Translate()` 键都能在中文 Keyed 文件找到。
3. Def 键检查：每个 DefInjected 条目对应现有 Def 和字段。
4. 编译检查：Core 与 Content 仍能成功构建，且不产生反向引用。
5. 游戏内检查：中文语言下检查战斗体按钮、Trion 状态、人才检测、触发器装载等已纳入范围的界面。
