# 皇室入口原版首发安排实现计划

Status: Implemented, game verification pending

**Goal:** 按用户批准的暂定方案，第八天专门派发皇室求援，不设三人或极端生态限制，保留缺少皇室时的随机再次接触。

**Architecture:** 使用原版 `IncidentWorker_GiveQuest`（派发任务事件）和 `StorytellerComp_SingleOnceFixed`（单次定时派发部件）。以 XML（可扩展标记语言）追加仅属于 BDP 的部件，不修改原版开场事件，不新增代码补丁或定时扫描。身份保持原版临时小派系借住，正式加入和契约边界不变。

**Tech Stack:** RimWorld 1.6（边缘世界1.6）、原版任务及叙事者部件、现有内容定义和中文语言包。

## 最小改动与执行

1. 新增 `1.6/Content/Defs/IncidentDef/RoyalArrivalOpening.xml`，事件 `BDP_GiveQuest_RoyalArrivalOpening` 直接指向现有 `BDP_RoyalArrival`，事件随机权重为零，只由专门首发部件调用；中文标签在 `Languages/ChineseSimplified (简体中文)/DefInjected/IncidentDef/RoyalArrivalOpening.xml`。
2. 新增 `1.6/Content/Patches/RoyalArrivalOpening.xml`，给具有部件列表的叙事者追加原版单次定时部件，目标为世界，第八天触发；最低人数为零、不跳过极端生态、不检查原版爵位。选择路径排除已有同一 BDP 派发部件，不替换任何原版部件。
3. 修改 `1.6/Content/Defs/QuestScriptDef/RoyalArrival.xml`，保留随机权重和增加人口属性，普通随机候选最早从第八天开放，避免专门首发之前提前随机出现。两个八天配置均注明暂定且调整时同步；同类任务和正式皇室准入沿用现有节点。
4. 验证定义与语言格式、实际原版追加操作保持既有皇权部件，并排除重复追加；运行现有任务及借住资格回归。纯配置改动不新增模仿配置的永久测试，不重编未变动的程序集。
5. 更新入口记录及工作日志，精确暂存并在当前分支提交。实际第八天派发与完整任务流程留给游戏实测，不将离线配置验证当作游戏验收。

## 原版时序与边界

- 原版定时部件按游戏总时间检查第八天的派发时点，不轮询补偿错过的首发；人口限制为零时不会等待人数达标。
- 已超过第八天的旧存档不补一次立即派发；仍可通过普通随机渠道或既有开发任务入口接触。
- 首发时若已有正式皇室、已有同类待接受／进行中任务，或不满足正式任务准入，原版事件会拒绝；不绕过和平难度及敌对人类派系等现有条件。
- 随机再次接触仍受原版人口增员与任务权重规则影响，没有保证固定重试间隔。保留此渠道不表示定义新的补发平衡。
- 第八天及其他平衡配置是当前暂定版本，用户明确以后还会改；不作为长期玩法标准。

## 执行结果

最小配置已接通：新增 BDP 首发事件、原版定时部件追加配置和中文事件名称；现有任务的随机最早日同步为第八天。临时小派系身份及所有任务业务代码保持现有实现。

离线实际调用原版 `PatchOperationAdd`（定义追加操作）验证了叙事者部件追加、既有皇权开场部件保持原样、非叙事者定义不受影响、重复追加排除；原版定时配置字段和运行类对应正确，首发事件指向现有任务，随机再次接触渠道保留。四份改动 XML（可扩展标记语言）格式检查、现有任务防重复和借住契约资格回归通过。一次性验证程序已删除，不增加临时脚本或永久模拟配置测试。

本轮只有配置、语言和文档改动，无程序集代码变更，无需重编；真实启动定义加载、第八天派发及完整任务流程仍待游戏实测。验收时使用第八天之前的存档，确认仍无正式皇室／同类任务，再观察定时通知；超过时点的存档只验证随机或开发入口，不误认为首发失效。
