# BDP 事项09A：Trion 天赋检测内容化设计

## 一、用户已确认的边界

本项把“Trion 天赋检测”从 Core 中拆到 Content，但不搬走 Trion 本身的底层能力。

保留在 `BDP.Core.dll`：

- Trion 当前值、最大容量、预占用、锁定、持续扣费和自然恢复。
- 角色永久 `TrionCapacityPotential（Trion容量潜质）` 原始值。
- 角色永久 `TrionIntensity（Trion释放力）` 原始底数及原版 Stat（属性）修正。
- 统一 Trion 读取/命令面。

进入 `BDP.Content.dll`：

- Trion 天赋检测仪建筑和便携检测器。
- 检测资格、选择受检者、检测 Job、等待 Job、WorkGiver（工作给予者）和检测交互。
- “是否已经完成检测”的存档状态。
- 容量潜质档位名称、检测结果对象和角色面板中的检测结果显示。

## 二、为什么要这样拆

“容量潜质”和“释放力”是角色本身的数值事实，芯片门槛和其它系统可以直接读取；“检测仪”只是玩家获得这些事实的一个业务途径。

如果继续把检测状态放进 `CompTrion`，Core 就必须知道：

- 什么叫“完成天赋检测”；
- 检测结果什么时候对玩家公开；
- 哪些建筑和 Job 可以写入这个状态。

这会让 Core 依赖某个具体玩法。拆开后，Core 只保存数值，Content 决定检测和展示规则，仍保持 `Content → Core` 单向依赖。

## 三、目标结构

```text
BDP.Core.dll
├─ Core/Trion/CompTrion.cs                 Trion资源宿主
├─ Core/Trion/Capacity/                    容量潜质原始值生成
├─ Core/Trion/Intensity/                   释放力原始值生成与统一读取
└─ Core/Genes/Requirements                  原版属性和门槛

BDP.Content.dll
└─ Content/Trion/Talent/
   ├─ CompTrionTalentAssessment.cs         检测完成状态与角色面板显示
   ├─ TrionTalentAssessmentService.cs      检测提交服务
   ├─ TrionTalentAssessmentEligibility.cs  检测资格
   ├─ Building_TrionDetector.cs             检测仪建筑
   ├─ Thing_TrionPortableDetector.cs       便携检测器
   ├─ Jobs/                                 检测 Job
   ├─ WorkGivers/                           检测 WorkGiver
   └─ Capacity/                             容量潜质档位显示定义
```

## 四、状态拆分

新增 Content 侧 `CompTrionTalentAssessment`，由 Content 启动接线器注入所有人形 Pawn Def：

- `IsCompleted`：是否已经完成检测。
- `TryMarkCompleted()`：只允许第一次成功提交。
- `PostExposeData()`：保存 Content 侧检测完成状态。
- `SpecialDisplayStats()`：检测完成后显示容量潜质档位和释放力。

Core 的 `CompTrion` 删除：

- `trionTalentAssessmentCompleted` 字段及其存档键。
- `ITrionReader.TrionTalentAssessmentCompleted`。
- `ITrionCommands.TryMarkTrionTalentAssessmentCompleted()`。
- 依赖检测完成状态的 `SpecialDisplayStats()` 分支。

植入有效 Trion 腺体后，Content 组件仍然存在且 `IsCompleted` 不变，因此检测结果继续显示；释放力的显示值改为读取 Core 的统一有效属性。

本次不兼容旧存档中的检测完成字段；旧字段会被忽略，按新组件状态处理。

## 五、目录与命名调整

### Core 源码

- `Core/Trion/Talent/Capacity/TrionCapacityPotentialDistributionDef.cs` → `Core/Trion/Capacity/`
- `Core/Trion/Talent/Capacity/TrionCapacityPotentialGenerator.cs` → `Core/Trion/Capacity/`
- `Core/Trion/Talent/Intensity/TrionIntensityDistributionDef.cs` → `Core/Trion/Intensity/`
- `Core/Trion/Talent/Intensity/TrionIntensityGenerator.cs` → `Core/Trion/Intensity/`
- `Core/Trion/Talent/Intensity/TrionIntensityUtility.cs` → `Core/Trion/Intensity/`

### Content 源码

- 检测仪、便携检测器、检测状态、服务、资格、结果、浮动菜单、Jobs 和 WorkGivers 全部进入 `Source/BDP.Content/Trion/Talent/`。
- `TrionCapacityPotentialBandDef` 与 Resolver 进入 Content 的 `Trion/Talent/Capacity/`，因为它们是检测结果的玩家可读档位，不是容量原始值。

### Def

- Core 原始分布：`1.6/Defs/Trion/TrionCapacityPotentialDistributionDefs.xml`、`TrionIntensityDistributionDefs.xml`。
- Content 检测档位：`1.6/Content/Defs/Trion/Talent/TrionCapacityPotentialBandDefs.xml`。
- Content 检测业务：检测建筑、便携检测器、检测 Job 和 WorkGiver Def 全部进入 `1.6/Content/Defs/` 对应目录。

## 六、明确不做

- 不改容量潜质和释放力的概率、数值范围或显示文字。
- 不改检测时长、检测仪外观、工作流程和资格条件。
- 不迁移装配台、紧急脱离、战斗日志或伤口视觉；它们仍是事项09后续分组。
- 不迁入 DevHarness 中尚未确认的具体芯片。
