# BDP 触发体动态自动攻击信息设计

## 目标

触发体的信息面板继续使用 RimWorld（边缘世界）原版信息面板和原版武器统计条目，但在显示层读取当前已发布表达结果中会作为自动攻击入口的近战或远程攻击。

这项改动只处理“信息面板看到什么”，不改变以下任何运行事实：

- 自动攻击选择；
- 远程或近战执行；
- 表达投影、芯片激活和停用；
- Trigger 的 ThingDef（物品定义）工具列表；
- 存档字段和保存结构。

## 当前问题

触发体 ThingDef 自身带有一个用于原版宿主和回退的近战 Tool（工具），因此原版信息面板会把这个占位 Tool 读成触发体的近战武器。它不是当前表达真正发布的自动攻击。

`CompTriggerBody`（触发体组件）当前只追加触发器类别，没有在信息卡边界替换原版武器条目。

## 设计结论

### 1. 真值来源

显示读取 `CompTriggerBody.PublishedCombatProjection`（已发布战斗投影）中的 `PrimaryMelee` 或 `PrimaryRanged`（默认主近战/远程结果）。这是当前表达系统已经发布、且自动攻击执行路径会使用的结果，不重新解析芯片配置，也不重新裁定攻击。

没有有效的默认主武器结果时，保持原版信息面板原样显示，确保回退安全。

### 2. 原版统计桥接

新增 Core（核心程序集）内部的触发体武器信息发布器：

1. 从已发布 `FormalExpressionResult`（正式表达结果）读取武器模式和最终 Verb（攻击动作）规格；
2. 复用既有 `VanillaWeaponStatSurfaceFactory`（原版武器统计表面工厂）建立未注册临时 `ThingDef`；
3. 复用既有 `VanillaWeaponStatSurfaceReader`（原版武器统计表面读取器）调用 RimWorld 原版统计逻辑；
4. 把得到的 `StatDrawEntry`（原版统计条目）交给信息卡边界。

这样显示字段仍由原版统计 API（接口）决定，而不是在触发体里手写一套平行字段。

### 3. 替换边界

在 Content（内容程序集）对 `ThingWithComps.SpecialDisplayStats`（带组件物品的特殊统计入口）做最小 Harmony（运行时补丁）包装：

- 只识别带 `CompTriggerBody` 的物品；
- 只有动态武器统计成功生成时，才过滤该物品原有 `Weapon_Melee` / `Weapon_Ranged`（原版近战/远程武器分类）条目；
- 其它基础、来源、触发器类别和组件条目全部保留；
- 追加当前自动攻击对应的原版武器条目；
- 动态读取失败时完整回退到原始结果。

触发体自己的 ThingDef 工具列表不被修改，所以这不是战斗逻辑补丁。

### 4. 当前无目标场景

信息面板没有攻击目标，不能执行目标距离选择。因此显示使用已经发布的默认主结果：

- 远程：使用 `PrimaryRanged`；
- 近战：使用 `PrimaryMelee`。

这与自动攻击入口的默认选择一致，不伪造一个目标，也不改变真正攻击时的距离选择。

### 5. 暂不扩展的内容

- 不改原版面板布局；
- 不新增“BDP 成品”“实际攻击”等自定义分类标题；
- 不把芯片规格、持续消耗、来源链混入触发体武器块；
- 不在本次引入新的多 Tool（多工具）展示格式；当前先让原版武器统计入口读取真实表达结果。

## 数据流

```text
当前已发布表达投影
        │
        ├─ PrimaryMelee / PrimaryRanged
        │
        ▼
触发体动态武器信息发布器
        │ 复用原版统计表面工厂与读取器
        ▼
原版 StatDrawEntry 条目
        │
        ▼
信息面板边界：成功则替换武器分类，失败则原样回退
```

## 验收标准

- 激活远程表达时，触发体信息卡的武器段显示当前远程结果的伤害、射程、连射、精度和远程冷却等原版可提供字段；
- 激活近战表达时，触发体信息卡的武器段显示当前近战结果，而不是 ThingDef 占位 Tool 的固定数值；
- 没有有效武器表达时，触发体原版武器段保持不变；
- 读档、激活、停用、攻击执行与当前版本行为一致；
- 现有制造芯片和触发器装配台信息设施不被改写。
