# BDP 追踪弹命中与可躲避性修复设计

## 结论

本次问题不是单一参数过小，而是追踪弹在到达段末时把三种情况混成了一个分支：

1. 子弹已经进入命中窗口并且仍在接近目标。
2. 子弹已经越过目标，目标正在从子弹后方拉开。
3. 目标仍然有效，但当前段需要继续追踪。

当前实现先用“目标在子弹后方”判定丢失，再处理命中窗口。因此，目标静止或轻微移动时，子弹即使已经在命中窗口内，也可能先进入 `lost_flyaway`（丢失后飞离）并被改绑到远离目标的地图格子。另一个问题是，目标仍有效且距离已经很近时，`HardReleaseDistance`（硬释放距离）会直接把飞行方向冻结为当前前进方向，造成近距离擦过。

## 目标

- 让“命中窗口内且仍在接近”优先进入原版命中结算。
- 让目标仍有效的近距离段继续进行一次终端追踪，不再无条件沿旧前进方向释放。
- 用目标位移 / 观测间隔得到目标速度，再按下一段预计飞行时间进行有限预测，减少移动目标身后的擦过。
- 保留追踪强度造成的可躲避性：目标已经越过子弹、距离持续增大，或丢失后重新锁定失败时，仍按原有重锁 / 飞离流程处理。

## 方案边界

- 只修改 `BDP.Content` 的 `Homing`（追踪弹）业务逻辑。
- 不修改 `BDP.Core` 的原版投射物推进与命中入口，不新增全局碰撞判定。
- 不修改 XML 参数默认值；强弱差异继续由现有转向、丢失、重锁和预测参数控制。
- 诊断日志继续保留，用于区分 `enter_hit_check_closing`（接近中的命中窗口）、`terminal_approach`（终端追踪段）和原有丢失 / 释放分支。

## 时序

```text
到达段末
  ├─ 命中窗口内 + 距离未增大 ──> 原版命中结算
  ├─ 目标仍有效 + 进入硬距离 ──> 终端追踪段
  ├─ 已丢失 / 正在远离 ────────> 重锁或飞离（保留可躲避）
  └─ 其他 ────────────────────> 带时间预测的普通追踪段
```

## 存档与兼容

追踪状态增加最近一次目标观测 tick（游戏刻）用于计算观测间隔。旧存档没有该字段时按至少 1 tick（游戏刻）处理，不改变旧状态的读取路径；该字段只服务于追踪预测，不改变 Core 层存档契约。
