# 远程模块职责与武装平衡设计

Status: Designed
日期：2026-10-18。目标：RimWorld 1.6、1.7。
源码基线：`00a46b060`。版本产物清单：同目录`2026-10-18-远程武装版本基线.json`。
本轮只提交基线、设计和实施计划；游戏功能尚未实施，两个版本均未构建或实测。

## 1. 最终范围

用户已经明确：部位选择使用独立模块；部位崩解和铅块负重是不同效果逻辑包，同挂一个远程减益模块；优先利用原版伤害信息、承伤结果和健康状态机制自然衔接。卵之冠的“非致命”就是现有`AvoidVital`（避开要害），原样沿用其分类、权重和无候选回退，不新增严格非致命算法。

本任务包括六项武装修改及为正确实现它们所需的职责收敛。风刃80%精度未兑现、普通偏射判定的姿态处理等只作为已有调查结论，不并入修复。不得顺手调整其他平衡、目标准入或全局原版算法。

| 对象 | 最终要求 |
|---|---|
| 卵之冠 | 速度20；独立避开要害模块；每次同部位叠加1/2，第二次满层；继续取消真实伤害、保留现有护盾绕过及反馈规则 |
| 猎犬 | 伤害8；0或1个手动锚点；不自动路由；路线排列在追踪之前，实际先经锚点再进入弱追踪 |
| 黄蜂 | 强追踪参数保留；其他攻击参数、路线限制及伤害跟随猎犬 |
| 美特拉 | 伤害6，护穿0，爆炸半径1.9，速度80 |
| 战斧 | 伤害、护穿、半径跟随美特拉；其他攻击参数跟随毒蛇，当前速度120、停止力1；保留爆炸伤害类型和毒蛇路线 |
| 朱鹮 | 伤害40，挂现有优先要害模块；其他参数保持 |

数值为基础投射物值，构型倍率继续按既有机制叠加。猎犬单锚点限制不扩散到毒蛇、战斧；禁自动路由不等于禁追踪的地面搜敌。

## 2. 现况与根因

原版普通子弹先碰撞取得目标，再进入承伤；伤害工作器确定部位，之后计算护甲和伤口。指定部位由`DamageInfo.HitPart`承载，承伤结果由`DamageWorker.DamageResult`提供。两个维护版本已核对，相关实现一致。

BDP独立部位模块虽然在`Impact`（效果计划）接口中生成贡献，但执行时尚未施加伤害，结果已进入原版伤害信息，因此不为阶段命名而重划协议。

已确认的实现问题：

1. 减益模块自行选部位，效果计划阶段提前固化部位，越过职责边界。
2. 命中后效果事件没有携带既有原版部位结果。
3. 崩解、负重的业务规则散布在通用模块配置和通用执行器中，没有独立效果包边界。
4. 路线和追踪都能覆盖下一段，首段比例也会覆盖；仅调整定义顺序不产生正确交接。
5. 黄蜂模块独立、战斧投射物数值独立，不能只看来源跟随字段就认定完整跟随。

分类为共享实现／配置问题，不是已确认的1.7独有差异。

## 3. 远程减益模块和效果包

### 3.1 单一宿主

保留一个`RangedDebuffModule`（远程减益模块）运行类，统一模块定义`BDP_RangedDebuffModule`。挂载配置引用`EffectDef`（效果包定义）。模块负责触发、目标作用域以及既有伤害处置、拦截与投射物表现参数，不解释具体效果种类。

```text
卵之冠 → 远程减益模块〔崩解效果包〕
铅弹   → 远程减益模块〔负重效果包〕
```

当前铅弹的降速、拖尾、无伤害、绕盾等攻击修饰保持原行为，仍作为挂载配置，不挪到负重状态业务中。效果包负责“目标中了以后发生什么”。

### 3.2 最小效果包入口

在Content内部新增小型效果定义，确定由具体Def子类直接提供无状态应用方法：

```csharp
// 只在Content解释效果包，Core继续只处理既有ExtraEffectPlan。
public class RangedDebuffEffectDef : Def
{
    public HediffDef hediffDef;
    public virtual bool RequiresHitPart => false;
    public virtual bool Apply(ExtraEffectExecutionContext context) => false;
}
```

不再额外创建工作器、工厂或专用注册表。两个效果包有各自的应用入口，宿主只调用入口；不在宿主写效果名称判断。Def是共享配置，不能保存某个目标的层数、部位或恢复计时，这些运行状态仍归原版健康状态及组件。

实施校正：1.6、1.7的真实`GenDefDatabase.AllDefTypesWithDatabases`实现相同，只为首个非抽象Def基类建库。因此共同入口必须为普通Def类，具体效果使用子类覆写；配置校验拒绝直接实例化入口基类。否则共同类型的效果引用在游戏加载时无法解析。这是原版定义机制约束，不增加新的业务层。

确定使用两个具体定义类型：`BodyPartDisintegrationEffectDef`（崩解）和`LeadWeightEffectDef`（负重）。共同参数只保留健康状态引用等真实共性；专属参数归具体类型。包定义通过原版Def引用与读取，不另建效果数据库。

效果执行使用现有`ExtraEffectPlanExecutorRegistry`注册一个Content适配器，效果种类键为`rangedDebuff`；计划携带效果包DefName，适配器解析后调用对应包。Core不读取Content的Def类型。

### 3.3 两个业务包

- 崩解包：查找同一目标同一部位标记，叠加，达到上限后使用原版缺失部位机制移除。按用户后续修订设置`hitsToDisintegrate=2`，每次增加`1f/2`，第二次移除。标记仍使用既有HediffDef，避免无意义更换健康状态身份。开发精确移除包复用该逻辑、参数为1次。
- 负重包：每次直接命中增加0.1、爆炸每目标增加0.01，上限1；移动惩罚继续用原版按严重度属性曲线，延迟与逐步恢复仍由健康状态组件驱动。叠加量只保留一个权威来源，清理现有未消费的重复`severityPerHit`字段；恢复组件只维护恢复计时和状态。

移除减益配置中的`HitPartSelectionMode`、精确部位字段，以及迁入包的叠加／阈值规则。通用执行器不再识别负重恢复组件或处理崩解移除动作。旧阈值动作注册表仅有本路径使用，完成引用核查后删除，不留兼容外壳。未使用的直击／范围空预设随调用迁移清理，不作为另一套宿主保留。

## 4. 部位事实通过原版承载

独立选择模块保留现有要害／避开要害实现，补充承接开发精确选择配置；`AvoidVital`行为不得更改。主伤害继续通过原版伤害信息验证部位、计算护甲和伤口。

在既有直接目标事件及效果执行上下文补充可空命中部位字段。部位效果声明`ImpactPart`（本次命中部位）作用域，执行时消费该事实，而不是提前选部位。

部位解析顺序固定：

1. 有正常承伤结果时，沿用现有主伤害部位解析语义；本轮不改变风刃额外伤害继承规则。
2. 主伤害被模块取消且效果确需部位时，优先验证并使用已指定部位。
3. 没有指定部位时，调用实际原版伤害工作器的`ChooseHitPart`；用缓存的调用入口保留其虚方法行为，不复制算法，不将所有工作器都当成基础子弹。
4. 指定部位已失效则停止对应部位效果，不重新随机到别处；无有效部位不得回退全身。
5. 原版护盾已阻断时不施加效果。明确绕过护盾的挂载继续遵守既有规则。

无伤害路径不得调用一次零伤害／微量伤害伪造结果。普通未挂部位效果的攻击不提前选部位，不增加随机数消耗。范围事件的部位保持为空，不能把一个目标的部位传播给整个爆炸范围。

`LastHitPart`表示最后受影响部位，不承诺是伤害传播的初始部位。本轮维持现有读取语义，不全局重写原版传播。若以后需要严格初始部位，作为独立需求研究。

## 5. 路线与追踪：控制权顺序

### 5.1 行为表

| 情况 | 行为 |
|---|---|
| 猎犬／黄蜂，0锚点 | 不自动生成路线，继续既有直射／高角和弱／强追踪 |
| 猎犬／黄蜂，1锚点 | 先完整到达锚点，再按最后一段启动既有追踪比例；弱90%、强50%，地面搜敌比例仍为1 |
| 第2锚点 | 原有目标交互拒绝，使用语言键反馈 |
| 毒蛇／战斧 | 现有完整路线、8锚点和自动路由保持 |

路线挂载新增仅必要配置：`ReleaseControlAfterLastAnchor=true`（最后锚点后释放控制）、`AllowUnroutedFinalTarget=true`（零锚点沿用其他模块目标方式）；默认false，避免改变毒蛇／战斧。

### 5.2 最小中性贡献规则

在既有初始化和到达贡献中增加`ExclusiveFlightControl`（当前段独占飞行控制）布尔值，不新增控制管理器或业务模块互相查询。

- 初始化合并时，前序路线存在手动锚点则声明独占；锁定当前段的目标、路径、触发比例以及与路径不可分的弹种／轨迹覆盖。后续仍可提交护盾、减益、外观等无关贡献，不能将首段改为90%或50%提前结束。
- 到达服务把已汇总的独占状态提供给后序模块。路线尚未完成时，追踪不推进自己的观察、丢失或重锁状态。
- 最后锚点到达后，路线记录已释放状态并永久停止接管该发；后序追踪从锚点建立当前目标观察基准，并先创建其90%／50%首追踪段，而不是跳过参数直接强追踪。
- 追踪只读取中性控制状态，不识别路线模块名称；路线也不识别猎犬、黄蜂或追踪模块名称。
- 新状态并入现有私有上下文的克隆和存档，按发次隔离，不增加另一套快照主干。

存在明确手动路径时，高角模块不能把它切换为越顶路线；零锚点才沿用既有高角选择。手动路径各段仍须满足合法视线，不能靠越顶掩盖非法锚点。既有范围、屋顶及操作台许可均保留，不无条件放开间接攻击。

## 6. 参数跟随的最小落点

- 黄蜂继续共用追踪弹，现有第一来源射程、节奏、精度、消耗跟随保留；使用共享的一锚点手动路线配置，模块顺序统一为路线→高角→追踪，仅追踪选择不同预设。可用原版抽象Def父配置共享路线挂载默认值，避免复制两套限制。
- 战斧射击参数继续使用第一来源毒蛇的现有解析。投射物声明以毒蛇为原版XML父定义继承弹速、停止力等，使用其长拖尾；伤害类型、伤害、护穿、半径由Content一个具体的组合定义解析方法读取美特拉并赋给战斧。调用放在既有启动定义处理入口、成品验证之前，只处理这项正式组合业务，不建立通用字段反射／任意Def跟随框架。
- 美特拉仍是爆炸四字段的权威来源，战斧不再重复写三份独立平衡数字；源定义缺失时报明确加载错误，不借用另一版本或保留过时数值冒充跟随。
- 若初始化顺序或原版Def校验要求部分字段先声明，则用最小初值满足加载，再由该具体解析器统一确定结果；诊断和信息面板必须读取解析后的真实Def，不读历史常量。

## 7. 迁移、清理和边界

正式类、效果包及配置在Content；Core仅承载部位事实与中性贡献合并；Development仅放验收动作和诊断。不得形成Core依赖Content，正式层依赖Development。

迁移正式卵之冠、铅弹两种被动挂载及开发精确移除定义、相关信息面板和测试。新玩家文案、模块／效果包标签和诊断提示进入简体中文语言文件；技术参数袋键不翻译。

旧模块配置字段及旧效果入口删除，不做历史配置兼容。健康状态DefName保留。改动导致旧在途投射物快照结构变化时，不实现复杂迁移；新发射和新结构保存／载入必须验证，禁止把旧槽位状态误认成新模块类型。

## 8. 验收与回滚

验收分为：定义结构／权威数值检查、真实程序集上的中性合并与克隆行为测试、两个版本游戏内最小情景验证。不要用大量正则断言替代游戏行为验证。

关键情景：效果包独立；换部位策略只改部位；第二次同部位崩解；无真实伤口；铅弹负重与恢复不变；0／1／2锚点；弱强追踪比例不变；手动路径与高角；原版拦截与明确绕盾；同轮多发及新结构读档；战斧来源修改后真实Def与信息面板同步。

源码按阶段提交，失败撤回该阶段尝试。两个版本的程序集归档位于基线清单记录的本地zip；源码基线不等于“当前产物已与源码重新同步”。仅做针对本任务文件的恢复，不执行覆盖其他聊天工作的全工作区重置。

本轮设计取舍：选择原版数据薄适配＋小型效果包＋必要的段控制贡献；不采用新建全局命中框架、所有攻击统一预选部位或全局原版补丁方案。
