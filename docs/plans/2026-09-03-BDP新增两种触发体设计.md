# BDP 新增两种触发体设计

## 一、目标

在不修改现有触发体运行时、芯片装载逻辑和攻击逻辑的前提下，新增两种正式触发体：

- `边境特制触发体`：主槽 7 个、副槽 7 个、特殊槽 2 个，玩家可配置。
- `近界测试触发体`：主槽 0 个、副槽 0 个、特殊槽 6 个，玩家不可配置；首次生成时在特殊槽 1 预装自动护盾芯片，在特殊槽 2 预装紧急脱离芯片。

## 二、现状与约束

- 现有标准触发体定义位于 `1.6/Content/Defs/ThingDef/Equipment/Trigger.xml`。
- 槽位数量和玩家控制权限由 `BDP.Core.Trigger.CompProperties_TriggerBody` 提供。
- 现有 `BDP_ChipFunction_EnergyShield_Auto` 和 `BDP_ChipFunction_EmergencyEscape` 是 `ChipFunctionDef`（芯片功能预设），不是可以直接交给 `ThingMaker` 的实体芯片 `ThingDef`。
- 所有动态成品芯片都使用 `BDP_Chip_Custom`，并在 `CompManufacturedChip` 中保存 `ChipCombinationRecord`（芯片组合记录）。两项功能均声明为 `Special` 区域、`Single` 占用，适合预装到特殊槽。
- `PlayerNonConfigurable` 已由装配台、装配窗口和正式装卸事务共同执行，不能只依赖隐藏界面。
- `TriggerLoadoutPanelExtension` 只负责主/副槽控制面板的显示许可，不是底层权限校验。近界测试触发体没有主/副槽且不可配置，因此不添加该扩展。

## 三、实现设计

### 1. 定义文件

在现有 `Trigger.xml` 中新增两个独立的 `ThingDef`，保留 `BDP_TriggerBody_BorderStandard` 原文和字段不变。为支持动态芯片预装，在 Core 增加中性的固定装载成品工厂入口；Content 通过该入口复用成品芯片生成逻辑，不让 Core 引用 `ChipFunctionDef`。

拟定 DefName：

- `BDP_TriggerBody_BorderSpecial`
- `BDP_TriggerBody_NeighborTest`

两者均继续继承原版 `BaseWeapon`，沿用标准触发体的贴图、技术等级、基础属性、近战工具和 `CompProperties_Styleable`。

### 2. 触发体配置

`BDP_TriggerBody_BorderSpecial`：

- 类别：`BDP_TriggerCategory_Border`
- `loadoutControlMode`：`PlayerConfigurable`
- `mainSlotCount`：`7`
- `subSlotCount`：`7`
- `specialSlotCount`：`2`
- 保留 `TriggerLoadoutPanelExtension`
- 不设置 `fixedLoadout`

`BDP_TriggerBody_NeighborTest`：

- 类别：`BDP_TriggerCategory_Neighbor`
- `loadoutControlMode`：`PlayerNonConfigurable`
- `mainSlotCount`：`0`
- `subSlotCount`：`0`
- `specialSlotCount`：`6`
- `fixedLoadout`：两条记录都使用实体芯片 DefName `BDP_Chip_Custom`；特殊槽 1 的 `initializationKey` 为 `BDP_ChipFunction_EnergyShield_Auto`，特殊槽 2 的 `initializationKey` 为 `BDP_ChipFunction_EmergencyEscape`
- 不设置 `TriggerLoadoutPanelExtension`

固定芯片沿用现有首次生成机制，只在新物品首次生成时创建并装入；读档不会重复创建。Content 成品工厂会根据功能预设建立单功能 `ChipCombinationRecord`，复用 `CompManufacturedChip` 的成品初始化逻辑，且不创建工单、不消耗材料、不占用工作时间。特殊槽 3 至 6 保持为空。

### 3. 文案

在 `Languages/ChineseSimplified (简体中文)/DefInjected/ThingDef/BDP_Things.xml` 增加两个触发体的 `.label` 和 `.description` 语言键。定义文件保留与现有 Def 一致的中文默认文本，语言包负责正式简体中文显示。

## 四、验证设计

1. 先运行配置冒烟测试，确认新 Def 和工厂契约在实现前按预期失败。
2. 解析 `Trigger.xml` 和 `BDP_Things.xml`，确认 XML 合法。
3. 检查两个 DefName 唯一，字段分别为 7/7/2 和 0/0/6。
4. 检查近界测试触发体的类别、不可配置权限、实体芯片 DefName 和两个功能初始化键。
5. 构建现有 BDP 工程，确认 Core/Content 的工厂接线没有编译问题。
6. 需要实际进游戏确认：两个物品能被加载；边境特制触发体显示 7+7 个主/副槽；近界测试触发体生成后有两个有效预装特殊芯片，装配入口拒绝玩家修改。
