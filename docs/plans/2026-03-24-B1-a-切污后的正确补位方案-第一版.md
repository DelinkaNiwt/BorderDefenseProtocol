# B1-a 切污后的正确补位方案

**目标：** 在已经切除主模组测试污染的前提下，重新定义 `B1-a` 后续如何获得游戏内可测、可视、可反馈、易诊断能力，并保证这些能力不再反向污染正式 owner 与主模组。

**架构：** 主模组只保留 Trigger 正式职责、关键诊断日志、正式读取口与正式扩展口；游戏内可视化测试面只能作为外置层挂入，且必须通过正式接口读取，不得直接依赖主模组内部私实现。

**技术栈：** RimWorld 1.6、C# 7.3、主模组 `ThingComp / Gizmo` 正式扩展口、外置测试模组。

---

## 一、补位目标

本次补位不是把刚删除的测试窗口换个名字加回来。

本次补位要解决的是：

- `B1-a` 仍然需要短阶段可测机会
- 但这种可测机会不能再以污染主模组为代价

因此后续补位的真实目标是：

- 把“观察与验证能力”外置
- 把“真值与正式业务”留在主模组

## 二、主模组允许补的位

主模组后续如需继续补位，
只允许进入以下内容：

### 1. 正式最小读取口

这类读取口必须满足：

- 面向正式语义，不面向某个测试窗口
- 返回正式结果，不返回内部可变容器本体
- 删除测试层后仍然有存在意义

例如方向上允许的是：

- 某侧当前正式激活槽位
- 全部正式槽位的只读枚举
- 某侧局部切换上下文的正式读取结果

不允许的是：

- “专供某临时窗口显示”的拼装口
- “顺手暴露内部列表看看”的查询口

### 2. 正式扩展口

主模组可继续依赖并扩展：

- `TriggerExternalGizmoRegistry`
- `ITriggerExternalGizmoProvider`

这类扩展口的职责是：

- 允许外部模组按正式上下文挂入按钮或观察面
- 不让外部模组直接改主模组按钮链私实现

### 3. 关键诊断日志

主模组可继续保留和补充：

- 装载
- 卸载
- 一致性修复
- 正式拒绝原因

但必须坚持：

- 非高频
- 非循环
- 服务正式问题定位

## 三、外置测试层允许补的位

外置测试层后续如需进入实现，
只允许承载以下内容：

### 1. 游戏内观察窗口

允许：

- 槽位状态汇总显示
- 容器快照显示
- 一致性结果可视化显示

不允许：

- 在测试窗口中持有或缓存真值
- 通过测试窗口替代正式业务提交

### 2. 测试专用交互

允许：

- 打开测试窗口
- 刷新显示
- 切换显示层级

如需“触发正式行为”，
也只能调用主模组已有正式接口，
不能要求主模组额外提供只为测试存在的私口。

## 四、B1-a 后续实现进入条件

只有当以下条件同时满足时，
才允许继续实现 `B1-a` 的外置可视化测试层：

1. 主模组侧没有残留测试专用窗口、按钮、查询口
2. 外置测试层只通过正式读取口和正式扩展口接入
3. 删除整个测试层目录后，主模组编译与运行都不受影响
4. 测试层不持有真值，不承载业务裁定

## 五、当前对后续实现的直接要求

从本方案开始，
后续若要恢复 `B1-a` 的游戏内可视化验证能力，
顺序必须是：

1. 先确认主模组缺哪些“正式最小读取口”
2. 再确认现有正式扩展口是否足够挂入外置测试按钮
3. 最后才允许在测试模组中实现窗口或观察面

不再允许：

1. 先在主模组写个临时窗口
2. 先在 owner 里塞几个调试查询口
3. 后面再讨论是否迁出

## 六、一句话总括

`B1-a` 在切除污染后，正确的补位方向不是“把测试窗口迁个地方继续塞”，而是把主模组收回到“正式真值 owner + 正式读取口 + 正式扩展口 + 关键诊断日志”，再把游戏内可视化验证层放到可直接删除的外置测试模组中，通过正式接口自然接入。
