# 战斗体系统生命周期与手动切换锁解耦实施计划

**目标：** 修复原版复用人物换装后，系统激活被 BDP 手动切换锁拒绝的问题。

**已确认设计：** 用户已同意修复通用生命周期，机制与近界派系解耦。阶段、腺体、资源准入仍由既有事务检查；12 刻手动锁只约束玩家形态切换，崩解冷却保持原义。直接在当前分支工作。

## 实施步骤

1. 增加真实阶段状态的行为回归检查：锁内系统重新激活、锁内手动切换拒绝、到期恢复、活跃/崩解/冷却禁止重复激活。先对旧代码执行，确认系统激活用例失败。
2. 修改 Core 的 ICombatBodyReader、CombatBodyState、CombatBodyCoordinator：区分 CanActivate（系统阶段准入）和 CanManualActivate（叠加手动锁）。既有阶段进入事务继续使用系统准入。
3. 修改 ICombatBodyCommands、CombatBodySessionService、CombatBodyTriggerGizmoProvider：TryActivate 用于系统激活，不启动手动锁；新增 TryActivateManually 供玩家按钮使用，成功后启动锁。系统激活仍检查腺体、资源和退出重入。
4. 修改 CompTriggerBody.Notify_Unequipped：走装备卸下的系统退出入口，不受手动锁阻挡、不新增锁；与已有腺体失效入口复用强制退出事务。保留装备卸下前已切入崩解时的既有保护。退出事件准确区分 EquipmentDetached 与 ForcedEligibilityLoss。
5. 更新直接涉及入口语义的既有检查；构建 Core、Content、Development 和 Compatibility，验证依赖边界及二进制一致性。备份并部署受影响的 Core 产物，记录日志并提交。

## 验证边界

- 不增加派系特判、逐刻补激活或延时重试。
- 行为检查使用真实阶段状态源码，只隔离游戏时钟及序列化依赖；不能替代游戏内换装、健康状态、快照和资源清理实测。
- 游戏内主线：原版复用已有激活战斗体的人物，重新换装后应立即完成系统激活，出门有激活健康状态。
- 相关回归：玩家激活/解除仍有 12 刻锁；锁内卸下触发体正确退出；倒地崩解不被普通装备退出覆盖。

## 执行结果

- 步骤 1—5 已完成：4 项真实状态行为检查及 10 份相关检查脚本通过，四个程序集编译无警告无错误，依赖边界检查通过。
- 只读审查无阻断发现；仅部署 Core 程序集及调试符号，备份和哈希见本次工作日志。
- 游戏内复用换装、健康状态和资源/快照清理仍待实测，未把编译通过表述为游戏实测通过。
