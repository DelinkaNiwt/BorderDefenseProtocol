# 组合技定义并入现有系统实施计划-第一版

**目标：**

在不引入结果导向特判、不新增组合技专用攻击链的前提下，把 `ComboDef`、`ComboResult` 和现有表达/攻击系统正式接通，让组合技以“无实体第三芯片定义”的中性方式并入当前主模组系统。

**实施原则：**

- 只做架构缺口补齐，不做任何具体业务实现。
- 不把当前只先消费 `Verb`，误写成“结构上只能有 Verb”。
- 不新开组合技专用执行器、组合技专用宿主链、组合技专用攻击分支。
- 组合技在表达层特殊，在攻击层普通。
- 一切接线都以“最小、稳定、可落地”为准，不为未来假想需求预埋复杂系统。

**技术范围：**

- C#
- RimWorld 模组主工程
- 现有芯片定义读取链
- 现有表达快照构建链
- 现有攻击执行链
- PowerShell 边界烟雾测试

## 任务 5：在表达系统复合阶段真正构建 ComboResults

**文件：**

- 修改：`Source/BDP/Core/Expressions/Pipeline/ExpressionSnapshotBuilder.cs`
- 修改：`Source/BDP/Core/Expressions/Model/CompositeExpressionReference.cs`
- 修改：`Source/BDP/Core/Expressions/Model/CompositeExpressionSet.cs`
- 测试：`Source/BDP.Tests/ComboDefinitionBoundarySmokeTests.ps1`

**步骤 1：先写失败断言**

至少锁死以下事实：

- `ComboResults` 不能继续是硬编码空表。
- 命中组合技时，正式结果必须带 `CompositeKind = Combo`。
- 组合技结果必须写入 `ComboDefName`。
- 组合来源关系仍由现有复合引用结构承接，不另造一套并行系统。

**步骤 2：最小实现策略**

在 `ResolveComposite(...)` 中：

1. 读取当前主、副两侧可参与复合的芯片输入。
2. 若缺一侧，则直接返回空 `ComboResults`。
3. 若两侧都存在，则按 `chipA/chipB` 不分顺序匹配 `ComboDef`。
4. 当前规则是一对芯片最多命中一个组合技，因此命中后直接生成一组结果即可。

结果构造要求：

- 仍使用 `FormalExpressionResult`
- `OriginKind = Composite`
- `CompositeKind = Combo`
- `ComboDefName = 命中的 ComboDef`
- 表达条目翻译尽量复用现有单条目翻译流程

必须坚持：

- 输入为空是正常路径，不是异常。
- 当前先只真实消费 `Verb`，但结构上不能写死为“只允许 Verb”。

**步骤 3：本任务完成标准**

- `ComboResult` 已真实进入 `ExpressionSnapshot.Results`。
- 组合技第一次成为表达系统正式输出，而不是留在预留空位里。

**步骤 2：最小实现范围**

统一规则：

1. 有显式值，先取显式值

注意：

- 对象引用型字段当前不做 `Average / Sum / Max / Min`
- 本任务只补正式求值骨架，不做任何结果导向业务逻辑

## 最终验收规则

本轮完成后，必须同时成立以下 5 条：

1. 组合技已成为主模组正式定义对象，而不是旧式专用残留逻辑。
2. 表达系统能在两侧芯片存在时，按中性匹配规则生成 `ComboResult`。
3. `ComboResult` 能像普通单条结果一样继续进入现有攻击系统。
4. 默认主攻击选择逻辑保持不变。
5. 代码中没有引入任何具体业务结果导向的硬编码。

只要这 5 条同时成立，这轮组合技架构缺口就算正式补齐。后续再继续推进协议模块配置，也不会反过来破坏当前主链边界。
