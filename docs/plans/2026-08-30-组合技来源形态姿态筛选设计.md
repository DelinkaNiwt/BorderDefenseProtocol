# 组合技来源形态姿态筛选设计

## 1. 目标

让 `ComboDef`（组合技定义）在现有“芯片来源键”匹配之外，可选地继续匹配来源芯片当前的形态和姿态：

```text
芯片来源键 → 可选形态键 → 可选姿态键
```

本次正式需求是：`BDP_Combo_LightSoulPropulsion`（光魂推进）只允许光魂的 `shield`（大盾）形态；大盾形态下不限制姿态，因此灵活姿态和举盾姿态都允许；`heavy_blade`（重刃）形态不允许。

## 2. 已确认的当前架构事实

- `ComboDef` 当前用 `firstSourceKey` 和 `secondSourceKey` 声明两侧芯片来源。
- `ComboRuntimeIndex` 当前按两侧芯片来源键建立无序索引，再执行成品身份准入和正反向来源分配。
- `ITriggerLoadoutReader` 已经提供芯片当前正式形态键和姿态键读取口。
- 形态/姿态切换已经触发战斗投影重新发布，组合结果可以随当前状态重算。
- 形态/姿态属于 `TriggerSlotState`（触发槽位状态）的运行时真值，不写入成品芯片制造记录。

## 3. 设计方案

### 3.1 新增独立来源状态筛选块

不把形态和姿态混入现有 `FirstSourceAdmission` / `SecondSourceAdmission`（来源成品身份准入），新增中性的 `ComboSourceScopeConfig`（组合来源状态范围配置）：

```csharp
public sealed class ComboSourceScopeConfig
{
    public string ModeKey;
    public string StanceKey;
}
```

`ComboDef` 和内部配置/契约各自增加第一来源、第二来源的可选状态范围字段。原有 `firstSourceKey`、`secondSourceKey` 保持不变，降低现有 Def 和读取链改动范围。

### 3.2 匹配语义

- `ModeKey` 为空：任意形态符合。
- `ModeKey` 有值、`StanceKey` 为空：指定形态下的任意姿态符合。
- `ModeKey` 和 `StanceKey` 都有值：必须同时精确符合。
- 只填写 `StanceKey`：定义校验失败。姿态必须从属于明确形态。
- 不填写 `StanceKey` 不表示“只允许无姿态”，而表示姿态通配。
- 单形态芯片的当前形态键为空；未填写形态筛选时正常匹配，填写形态筛选时不命中。

匹配顺序保持为：

```text
芯片来源键
  → 成品身份准入
  → 来源变体一致性
  → 当前形态/姿态范围
  → 组合定义成立
```

正向和反向来源分配都必须分别应用对应的状态范围。

### 3.3 运行时状态传递

组合索引仍按无序芯片来源对索引，不把形态或姿态加入索引键。`CompositeExpressionResolver`（复合表达解析器）在已有候选槽位上读取当前状态，并把形态/姿态作为匹配上下文传入组合读取面；`ComboRuntimeIndex` 只负责比较状态，不直接访问槽位内部字段。

这样可以复用现有 `ITriggerLoadoutReader` 读取口，不新增第二套形态状态，也不把运行时状态错误地存到芯片实体。

### 3.4 光魂推进配置

光魂推进保留现有芯片来源：

```text
BDP_ChipFunction_LightSoul + BDP_ChipFunction_Thruster
```

第一来源增加：

```xml
<FirstSourceScope>
  <ModeKey>shield</ModeKey>
</FirstSourceScope>
```

不填写 `StanceKey`，因此覆盖：

```text
光魂大盾·灵活姿态 + 推进器
光魂大盾·举盾姿态 + 推进器
```

光魂重刃不匹配。现有光魂推进能力、推进器来源和攻击执行逻辑不改。

### 3.5 候选歧义

保留当前“多份 `ComboDef` 同时命中则拒绝”的保护，不在本次偷偷引入按具体程度自动择优的规则。

因此同一芯片来源对不能同时存在一个无条件组合和一个形态限定组合；否则会触发组合歧义。若未来确实需要“通用组合作为回退、精确组合优先”，另行增加明确的匹配优先级设计。

## 4. 影响范围

### Core

- 来源状态配置、配置镜像、正式契约和契约解析器。
- 组合定义校验：检查姿态必须依附形态。
- 组合运行时索引和来源匹配上下文。
- 复合表达解析器的组合匹配调用参数。

### Content

- 光魂推进 ComboDef 增加大盾形态条件。
- 不改变光魂芯片表达目录、形态/姿态切换、推进能力运行代码。

### 存档与性能

- 不新增存档字段；沿用已有槽位形态/姿态真值。
- 不改变无序芯片对索引，额外判断只发生在同一来源对的候选定义列表内，性能影响很小。

## 5. 验证范围

- 来源状态配置和正式契约存在且正确传递。
- 形态为空时通配所有形态。
- 指定形态、姿态为空时通配该形态的所有姿态。
- 指定形态和姿态时精确匹配。
- 只写姿态的定义被拒绝。
- 光魂推进在重刃形态不成立，在大盾灵活/举盾姿态成立。
- 形态切换后组合结果重新发布，能力状态同步变化。
- 现有无形态限制的组合技行为不改变。
- Core、Content、Development（开发程序集）边界和 Release 构建通过。
