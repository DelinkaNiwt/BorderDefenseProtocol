# 敌方战斗体资源实测入口实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在开发者菜单生成首次落地图即处于战斗体状态的敌对人物，并方便核验隐藏资源。

**Architecture:** 全部新增内容位于 Development（开发程序集及其语言包）。生成原版成年敌对人物，赋予腺体、装备标准触发体和真实芯片；提前调用资源组件已有的幂等首次初始化，再走正式战斗体请求，成功后才落地图。使用原版进攻队伍，不实现正式任务追兵队伍，不添加补丁、不修改核心和内容业务。

**Tech Stack:** C# 7.3（C#语言）、RimWorld 1.6 原版程序集、现有 BDP 公共请求与读取接口。

Status: Implemented

2026-10-06 后续修正：用户再次明确正式追兵直接装备已有近界原型。无护盾测试入口现改为生成该原型并复用其固定预载，不另装芯片；护盾公共资源样本仍用标准触发体，两项菜单已明确装备类型。此修正不代表正式追兵队伍或任务已经实现。下文原“两个入口均用标准触发体”为历史实现。

用户已确认：公共资源测试不限于原型；人物首次出现在地图上就必须已经是完整战斗体，而非出现后现场变身。原身快照必须通过正式变身保留。

## 1. 生成入口

新增 `Source/BDP.Development/CombatBody/HostileResource/HostileTrionDebugActions.cs`。

- 原版开发菜单返回自带本地化名称的 `DebugActionNode`（调试菜单节点），避免属性文字硬编码；实际程序集已确认允许节点提供自己的名称。
- 两种标准触发体测试配装：主槽弧月、副槽小行星；同样武装加特殊槽常驻型自动护盾。通过既有芯片成品工厂和装载请求生成完整芯片，不复制芯片配置，不新增测试物品定义。
- 点击可站立空地生成单个测试敌人；选用当前世界中已有的敌对人类派系，不修改外交。用原版人物生成请求强制成年人、可暴力、新人物、腺体，避免重用世界人物或改变既有人物。
- 资源组件已有首次初始化仅使用宿主属性与游戏时钟、无地图依赖。在开发入口提前调用其 `PostSpawnSetup(false)`（生成初始化），将首次初始化标记设好；之后正式落地图会走已初始化分支，不重置当前值、冻结和占用。
- 装备、真实资源、正式战斗体激活均在落地图前完成；失败时清理本次新人物和未交接物品，不保留半成品。成功后使用原版单人进攻队伍，关闭超时／溃逃、绑架和偷窃，仅服务资源实测。

## 2. 观测与控制

新增 `Source/BDP.Development/CombatBody/HostileResource/MapComponent_HostileTrionDiagnostics.cs`。

- 菜单提供输出选中人物资源状态、切换持续观测、设满／低余量／零、正式受伤入口。低余量是调试样本，不作为平衡参数。
- 仅开发模式且启用观测时记录选中人物，每秒核对一次，只在快照改变时输出；暂停时可手动输出。观测默认关闭，读档后可重新开启，不增加保存状态。
- 日志包含实际余量／容量、预占用／正式占用／相位占用、有效持续损耗、声明账本、当前规则与战斗体阶段；仅日志读取真值，不恢复敌方玩家面板。
- 测试伤口选完整外部非核心部位，经原版 `TakeDamage`（受伤入口）产生真实损伤；不直接登记伪造泄露。不保证护盾每次都放行伤害，实际拦截结果也属于观测对象。
- 所有新增界面与日志文案进入 `1.6/Development/Languages/ChineseSimplified (简体中文)/Keyed/HostileTrion.xml`，C# 每个成员中文注释。

## 3. 验证与交付

- 编译开发程序集；解析语言包、核对所有新语言键；检查差异与正式程序集未修改。
- 复跑已有真实公共资源行为测试，确认工具接入未带入资源业务修改；不把离线测试宣称为地图生成实测。
- 用户实测：生成即为战斗体；无伤攻击／护盾不扣费；受伤泄露与见底崩解；玩家界面隐藏；持续泄露存读档后保持一致；普通殖民者原费用正常。
- 更新本文状态、工作日志、公共资源实施记录；直接在当前分支精确提交本任务文件，不创建分支、工作树或子代理。

## 游戏内操作预期

重启游戏后开启开发者模式，在调试动作菜单搜索“BDP：敌方 Trion 资源测试”。选择生成配装并点击空地，右键退出生成工具；选中生成的人物，再开同一菜单启用持续资源日志或手动输出。建议先用无护盾版观察泄露，再用护盾版验证拦截免耗。

- 开发程序集编译通过；语言包 30 个键可解析、无重复，直接引用与四个动态相位名称齐全。原有真实资源行为测试再次通过。
- 新工具的地图生成、日志显示、实际战斗与存档仍待游戏内验证；离线检查不代表新生成路径已经实测通过。

## 第一轮实测步骤

1. 重启游戏、进入测试地图、开启开发者模式；调试动作菜单搜索“BDP：敌方 Trion 资源测试”。使用无护盾版本，点击空地，右键退出生成工具。
2. 暂停并选中该敌人，查看外观、健康页与人物信息页：出现时应已是战斗体，容量条目和余量面板应隐藏。手动输出资源日志，确认阶段激活、三项敌方规则关闭、预占用／正式占用／相位占用均为零，恢复冻结开启。
3. 开启持续资源日志，观察正常攻击；按后续已确认的敌方规则，芯片启停无等待，生成完成后已激活。未受伤时余量应保持不变，有效持续扣减为零；声明账本仍允许有维持来源。
4. 设余量为 1%，再次攻击仍不因功能费用耗尽；使用 5 点切割造伤入口。真正命中产生泄露后，有效持续损耗应大于零，余量下降，见底进入崩解并恢复原身。此处只检验资源／变身，暂不据此检验尚未实现的追兵队伍“原身继续死战”。
5. 用有护盾版本检查成功拦截时不扣 Trion；其格挡有原配置概率，未拦截且造成伤口时允许泄露，所以不能将所有受击都期待为零损耗。
6. 用另一无护盾样本在满余量下造伤，持续泄露期间存读档；读档后重新开启观测，检查阶段、零占用、泄露及其到期注销。日志实际速率应与伤口相符，不能翻倍。
7. 关闭持续资源日志。普通殖民者可用同一输出入口作对照，仍应按原费用和芯片金额支付、占用。

## 第一轮反馈：敌方操作按钮与行动逻辑（2026-10-06）

- 用户确认实际敌人会显示攻击按钮，并观察到冲锋近战。原版先枚举装备组件额外按钮，再筛选原版装备攻击按钮；因此触发体组件需自行检查原版玩家控制资格。已在共同装备按钮入口检查 `IsColonistPlayerControlled`（玩家可控殖民者），覆盖表达攻击、变身及各扩展操作，不影响敌方自动攻击或装备运行。
- 当前工具采用普通原版进攻队伍；不绑架、不偷窃、不因超时或队伍损失撤退。目标、移动与射击位置选择交给原版；没有另做 BDP 配装战术，也未接通正式追兵的崩解后死战队伍。
- 本次现有游戏日志中，水晶（Human181142）出现时已经激活战斗体，弧月与小行星随后都完成启动。此后只有同一 `atk_1`（攻击会话）的持续弧月近战，未见该人物的远程发射。
- 源码确认：原版自动近战任务有到期重新判断设置，BDP 自动近战接管却创建无到期设置的持续任务，并使用 `TryTakeOrderedJob`（玩家下令入口），原版会把任务标成玩家强制。这解释了进入近战后持续追砍、缺少正常重新选择的路径。最初为何选中近战未被现有日志直接记录；芯片启动期间的原版近战回退是合理推断。
- 本轮仅修按钮权限并编译核心成功；尚未在游戏中复核新按钮行为。自动近战任务的原版决策节奏恢复留作下一项明确修复，不擅自加入战术策略或修改研究、剧情等内容。
