# 远程投射物拖尾颜色覆盖设计

## 1. 设计结论

铅弹的拖尾颜色需求使用独立的可选视觉覆盖通道。它与受击闪烁颜色使用相同的“模块声明、Core（核心）传递、视觉内容消费”分层原则，但不共用运行时存储或应用入口。

本设计遵守以下边界：

1. `RangedDebuffModule`（远程减益模块）只提交“本发投射物需要拖尾颜色覆盖”的需求，不认识 `BeamTrail`（光束拖尾）业务类型。
2. Core 只承载中性的投射物视觉外观覆盖，并把它冻结到 `ProjectileInitPlan`（投射物初始化计划）。
3. `ProjectileVisualAttachmentHost`（投射物视觉附加宿主）把覆盖传给所有视觉提供器；具体视觉内容自行决定是否消费。
4. `BeamTrail` 只覆盖 `TrailColor`（拖尾颜色），保留原有贴图、宽度、寿命、透明度和高度参数。
5. 没有拖尾提供器时，不创建新拖尾；存在拖尾时，每个本发投射物产生的拖尾线段使用冻结后的覆盖颜色。
6. 多个模块同时提交拖尾颜色时，按 `ProjectileInit` 模块装配顺序采用最后一个显式覆盖，未提交覆盖的模块不清空已有值。

## 2. 原版与当前 BDP 基线

原版 `Verse.Projectile.DrawAt()` 只绘制投射物本体，没有通用的独立子弹拖尾颜色接口。BDP 当前的正式拖尾由 `BeamTrailExtension` 创建 `BeamTrailAttachment`，再由 `BeamTrailSegment.Draw()` 将 `TrailColor` 写入材质属性块 `_Color`。

因此本需求不修改原版 `Projectile` 绘制，也不替换整个拖尾预设，而是在现有拖尾外观快照生成前增加颜色覆盖输入。

## 3. 责任划分

### 3.1 Content（内容程序集）

- `RangedDebuffConfig` 增加 `HasProjectileTrailColor` 和 `ProjectileTrailColor`。
- 铅弹 XML 声明灰黑色值 `(0.12, 0.12, 0.12, 1)`。
- `RangedDebuffModule` 在 `ProjectileInit` 阶段按每个 emit 提交颜色需求。
- `BeamTrailExtension` 接收通用外观覆盖，并把颜色传给 `BeamTrailAppearanceSnapshot`。

### 3.2 Core（核心程序集）

- 增加中性的 `ProjectileVisualAppearanceOverrides`（投射物视觉外观覆盖）。
- 在 `ProjectileInitPlanContribution`、`ProjectileInitPlan` 和 `ProjectileInitStageService` 之间传递并冻结覆盖值。
- `BdpProjectile` 初始化视觉附加宿主时把冻结覆盖交给 `ProjectileVisualAttachmentHost`。
- 扩展视觉提供器接口，使提供器可选择消费覆盖；Core 不写入任何 `BeamTrail` 名称。

## 4. 时序

```text
RangedDebuffModule.ProjectileInit
    ↓ 提交颜色覆盖
ProjectileInitStageService
    ↓ 合并并写入 ProjectileInitPlan
BdpProjectile
    ↓ 初始化视觉附加宿主
ProjectileVisualAttachmentHost
    ↓ 传给视觉提供器
BeamTrailExtension
    ↓ 生成带覆盖色的外观快照
BeamTrailSegment
    ↓ 按线段保存并绘制
灰黑色拖尾
```

颜色必须在发射阶段冻结。若等到命中阶段才处理，已经生成的历史拖尾线段不会被可靠地改色。

## 5. 不做的事情

- 不把拖尾颜色并入 `HitFeedbackColor`（受击反馈颜色）。
- 不使用或扩展 `beamTrailPreset`（拖尾预设名称）来间接替换整套预设。
- 不让 Core 依赖 `BDP.Content.dll`，不在 Core 中写铅弹或 `BeamTrail` 分支。
- 不为没有拖尾的投射物强行生成拖尾。

## 6. 验证标准

1. 铅弹配置存在独立拖尾颜色字段，并设置为灰黑色。
2. 普通 BDP 拖尾的其他外观参数保持原值。
3. 受击颜色路径继续独立工作。
4. 没有拖尾提供器的投射物不会新增视觉对象。
5. Core、Content、Development（开发程序集）构建通过，Core 隔离边界不被破坏。
