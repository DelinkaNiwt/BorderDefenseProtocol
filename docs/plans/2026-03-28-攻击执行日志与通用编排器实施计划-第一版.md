# 攻击执行日志与通用编排器 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不破坏现有表达边界与武器发射边界的前提下，补齐正式攻击生效日志，并引入位于 `Core/AttackExecution/` 下的通用执行编排器，使齐射、顺序攻击、双侧同步与后续扩展都能通过统一计划执行链承接。

**Architecture:** 保留 `Expression -> AttackExecution` 的现有主链，把现有 `DefaultAttackPlanner` 明确收敛为“计划生成器”，再新增“计划执行器”负责按组推进。正式执行模型采用 `Plan -> Group -> Cast -> Emit`：`Cast` 表示一次真实施放动作，`Emit` 表示该次施放动作内部产生的单个效果实例。`Verb` 继续只负责一次 cast，`Projectile / Damage` 继续只负责效果落地。日志拆成“计划执行日志”和“效果生效日志”两层，并通过统一攻击实例标识串联，不让低层对象反向理解高层计划。

**Tech Stack:** C#, RimWorld Verb/JobDriver/Projectile 体系, BDP Expression/AttackExecution/Semantics 分层

**Files:**
- Modify: `Source/BDP/Core/AttackExecution/AttackExecutionPlan.cs`

- Create: `Source/BDP/Core/AttackExecution/AttackGroupTimingMode.cs`

**Step 1: 收敛正式计划模型**

要求：

- `AttackExecutionPlan` 代表一次攻击请求的完整静态蓝图
- `AttackExecutionGroup` 代表一个执行窗口内的并列动作集合
- `AttackExecutionCast` 代表一个最小施放动作
- `AttackExecutionEmit` 代表该次施放动作内部的单个效果实例
- 三者都直接放在 `Core/AttackExecution/` 下，不额外开 `Model/` 子目录

**Step 2: 给 Group 明确职责**

`AttackExecutionGroup` 至少承载：

- `GroupIndex`
- `TimingMode`
- `Casts`
- `DelayAfterGroupTicks`

要求：

- Group 只描述“这一组怎么执行”
- 不持有 Pawn、Verb、Job 等运行时对象

**Step 3: 让 Cast / Emit 各守边界**

`AttackExecutionCast` 继续承载：

- `ResultId`
- `WeaponMode`
- `Target`
- `SlotKey`
- `CastOrdinal`

按需要补充：

- `AttackInstanceId`
- `CastLocalIndex`
- `IntervalTicksAfter`

要求：

- 不把效果实例级字段塞回 Cast
- 不把 Verb、Projectile、DamageInfo 缓存在 Cast / Emit 里

### Task 3: 正式引入通用计划执行器

**Files:**
- Create: `Source/BDP/Core/AttackExecution/IAttackPlanExecutor.cs`
- Create: `Source/BDP/Core/AttackExecution/DefaultAttackPlanExecutor.cs`

**Step 1: 新增统一计划执行入口**

要求：

- `IAttackPlanExecutor` 接收 `AttackExecutionResolvedRequest`
- 它读取 `request.Plan`
- 它按 group 推进，不再直接按“需要多少 cast”粗略折算

**Step 2: 引入最小执行游标**

`AttackExecutionCursor` 至少承载：

- 当前 group 索引
- 当前 cast 索引
- 当前 `AttackInstanceId`

要求：

- 游标只负责推进状态
- 不承载表达快照与正式结果本体

**Step 3: 执行器按 group 统一调度**

要求：

- 对 `ImmediateTogether` 之类的同组模式，一次性派发整个 group
- 对顺序模式，只推进当前 group
- 对持续推进模式，把 cursor 交给后续运行时承接

**Step 1: 提炼统一 EffectEmitter**

要求：

- 输出是一次“最小施放动作”的真实派发

要求：

- `AttackPlanExecutor` 只负责“这一组该执行哪些 cast”
- `AttackEffectEmitter` 只负责“把单个或一组 cast 派发给真实武器层”
- `Verb` 只负责“完成一次实际发射/挥击”

**Step 3: 保留原执行器作为模式适配层**

要求：

- `DefaultRangedAttackExecutor` / `DefaultMeleeAttackExecutor` 不再自己决定节奏
- 它们转为把运行时上下文整理好，再交给 `AttackPlanExecutor` 与 `AttackEffectEmitter`

**Step 1: 引入正式攻击实例标识**

要求：

- 每次进入 `AttackExecution` 的请求都生成一个 `AttackInstanceId`
- 同一攻击计划下的所有 group / cast / emit 共用这一标识

**Step 2: 统一传播**

要求：

- `Request`
- `ResolvedRequest`
- `Plan`
- `Group`
- `Cast`
- `Emit`

都能读取到同一实例标识，避免各层自行生成零散 key

**Step 3: 不把标识做成业务语义**

要求：

- `AttackInstanceId` 只服务追踪和日志
- 不参与伤害计算
- 不参与表达真值判断
