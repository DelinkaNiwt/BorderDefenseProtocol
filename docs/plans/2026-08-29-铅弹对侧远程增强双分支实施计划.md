# 铅弹对侧远程增强双分支 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在保留现有铅块负重远程模块的前提下，将铅弹拆分为全侧有效的“铅弹·改”和只对另一侧有效的“铅弹”。

**Architecture:** 在 Core 的开放式远程模块增强配置中增加中性 `AllSides/OppositeSide` 作用范围。表达增强解析器按增强来源结果和目标射击结果的 `TriggerSide`（触发侧别）统一判定，不识别任何铅弹 DefName。现有铅块负重模块、攻击执行链和双侧投射物编排继续复用。

**Tech Stack:** C#、RimWorld Def/XML、简体中文 Keyed 语言包、PowerShell 烟测脚本、MSBuild Release 构建。

## Task 2: 实现 Core 通用作用范围

**Files:**
- Modify: `Source/BDP/Core/Expressions/Config/RangedModuleAugmentationConfig.cs`
- Modify: `Source/BDP/Core/Expressions/Pipeline/ExpressionAugmentationResolver.cs`

**Step 1: 增加中性作用范围模型**

在 `RangedModuleAugmentationConfig` 增加：

```csharp
public RangedModuleAugmentationScope Scope =
    RangedModuleAugmentationScope.AllSides;
```

新增枚举：

```csharp
public enum RangedModuleAugmentationScope
{
    AllSides,
    OppositeSide
}
```

在 `Clone()` 中复制 `Scope`。

**Step 2: 把作用范围判断收口到解析器**

将现有只按目标能力判断的逻辑扩展为：

- 先判断 `AppliesToCapability == RangedWeapon`；
- `AllSides` 直接匹配；
- `OppositeSide` 仅在来源和目标分别为 Main/Sub 且侧别不同的时候匹配；
- 来源或目标缺少来源侧别、属于 Special 或其它未知侧别时不匹配；
- 作用范围判断只读取通用结果来源信息，不读取芯片名称。

模块追加使用该统一判断。动态远程入口名称前缀也使用同一判断。

对于 `DualWeapon`（双侧武器）和其它高层复合结果，沿用现有 `CompositeExpressionReference` 的来源结果 Id，按实际来源侧别判断前缀；实际投射物模块继续由双侧编排分别从主侧和副侧结果消费。
