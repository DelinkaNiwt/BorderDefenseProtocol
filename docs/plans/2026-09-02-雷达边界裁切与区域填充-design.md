# 雷达边界裁切与区域填充设计

## 目标

在触发器装配台的雷达图中保留真实的超限数据表现，但把几何图形裁切在最外层雷达多边形以内；同时为闭合的数据范围增加符合当前深色青绿色 UI 的半透明底色。

## 已确认事实

- 当前雷达数据使用 `当前值 / 最大值` 计算顶点，因此超限值会落到外层多边形之外。
- 现有 `ChartGeometryRenderer` 已有矩形视口裁切、三角扇填充和三角形带折线能力。
- 矩形裁切不能表达雷达五边形边界；仅把数值改成 `Mathf.Clamp01` 会丢失超限位置，不能满足需求。

## 方案

为几何绘制器增加凸多边形裁切入口，继续使用 Sutherland-Hodgman（多边形逐边裁切）算法：先按图表矩形裁切，再按最外层雷达多边形逐边裁切。雷达图把最外层环作为裁切边界，当前值填充、声明值填充、轮廓、增减线和超限标记均使用该边界；原始数值和超限状态不改变。

底色分为两层：完整声明值轮廓使用低透明度的暗青色，最终值轮廓使用略亮但克制的青绿色。最终值始终填充其闭合区域；声明值只有在所有轴都有声明值时填充，部分声明值继续只绘制已有相邻边，避免凭空构造缺失数据。

## 范围与限制

- 修改范围仅限 `BDP.Content` 的图表几何绘制器、雷达图调用和对应契约测试。
- 不修改雷达数据、文字标签、空位排版、数值排版或其它面板线条。
- 不引入 stencil（模板缓冲）、RenderTexture（渲染纹理）或新的资源文件。

## 验证

- 先增加“必须存在凸多边形裁切并由雷达调用”的失败契约。
- 运行图表、装配台详情/窗口和程序集边界测试。
- 使用 `dotnet msbuild` 构建 `BDP.Content` Release，并检查 `git diff --check`。
- 最终需要重启游戏，用超限数据截图确认雷达外框外没有数据几何泄漏，闭合区域有半透明底色。
