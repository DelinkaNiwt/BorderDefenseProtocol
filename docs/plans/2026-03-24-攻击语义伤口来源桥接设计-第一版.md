# 攻击语义伤口来源桥接设计（第一版）

## 这次具体要解决什么

当前只解决一件事：

- BDP 攻击造成伤害后，伤口 Hediff 括号里显示攻击行为名，而不是装备名

目标例子：

- 普通芯片“小行星”造成枪伤后显示 `枪伤(小行星)`
- 组合技“战斧”造成爆炸伤后显示 `炸伤(战斧)`
- 组合技“旋空弧月”造成割裂伤后显示 `割裂(旋空弧月)`

这次不顺手做别的 UI 改写，不顺手改战斗日志，不顺手重做整个伤害系统。

## 这次真正的实现目标

不是“把伤口文字改一下”。

而是补一条可靠的小链路：

1. 先在攻击入口确定“这次攻击行为叫什么”
2. 再让这个名字跟着攻击链往下走
3. 最后在伤口写入时把这个名字读出来

如果这条链成立，后面别的结果层也能复用。

## 第一版准备怎么做

### 1. 先明确第一版只打三段主链

第一版只管这三段：

- 近战直伤链
- 远程投射物直伤链
- 投射物爆炸链

对应 RimWorld 实际链路：

- `Verb -> DamageInfo -> TakeDamage -> Hediff`
- `Verb -> Projectile -> DamageInfo -> TakeDamage -> Hediff`
- `Verb -> Projectile -> Explosion -> DamageInfo -> TakeDamage -> Hediff`

其它链先不碰：

- Ability 特殊链
- Thing 飞行物特殊链
- Hediff 主动伤害链
- Beam 等非当前主线攻击

## 2. 语义放在哪

第一版不做大总线。

第一版分三个具体落点：

- 表达来源上有一份 `SemanticContext`
- BDP 自定义 `Verb` 子类身上有一份当前攻击语义
- BDP 自定义 `Projectile` 子类身上有一份当前攻击语义

也就是说，第一版优先让“原版子类自己带着语义跑”。

## 3. 第一版准备新增哪些类

### 已有并继续使用

- `SemanticContext`
- `ISemanticContext`
- `IExpressionSource.SemanticContext`

### 第一版准备新增

- `IBdpSemanticCarrier`
  - 很小，只表示“这个对象现在能拿到一份攻击语义”
- `BdpVerbBase : Verb`
  - BDP 自定义 Verb 基类
  - 身上直接带当前攻击语义
- `BdpVerb_Shoot : Verb_Shoot`
  - BDP 远程射击基类
  - 以后 BDP 远程表达默认优先落到这里
- `BdpVerb_MeleeAttackDamage : Verb_MeleeAttackDamage`
  - BDP 近战基类
  - 近战直伤链优先从这里接语义
- `BdpProjectileBase : Bullet` 或 `BdpProjectileBase : Projectile_Explosive`
  - 视当前测试链实际使用的投射物类型拆开
  - 身上直接带当前攻击语义
- `BdpDamageSemanticBridge`
  - 很小
  - 负责从 `Verb / Projectile / Explosion` 这些宿主上取语义
  - 不负责业务规则

### 当前先不新增

- 自定义 `Explosion` 子类

原因：

- 原版爆炸生成入口比较封闭
- 先把 `Verb` 和 `Projectile` 打稳
- 再判断爆炸这层到底是能自然承载，还是只能在生成边界做最小接线

## 4. 第一版准备怎么接入现有代码

### 表达来源阶段

改：

- `TriggerExpressionCollector`

做法：

- 普通芯片第一默认显示名改为芯片名
- 不再优先用 `verb.label`
- 这里产出的 `SemanticContext` 只负责说明“这次攻击表达是谁”

### Verb 生成阶段

改：

- `VerbExpressionProjectionRegistry`

做法：

- 不再只按 XML 里的 `verbClass` 裸创建原版 Verb
- 如果是 BDP 当前支持的攻击类型，优先创建 BDP 自定义 Verb 子类
- 创建后把 `SemanticContext` 塞给这个 Verb 子类

第一版的实际目标很简单：

- 当前主远程入口生成的是 BDP 自定义远程 Verb
- 当前主近战入口生成的是 BDP 自定义近战 Verb

### Projectile 阶段

做法：

- 如果当前远程表达使用的是 BDP 自定义投射物类，就让 Verb 在发射时把语义交给 Projectile
- 如果当前投射物还是纯原版类，先不强行全改，先记为“还没进入第一版完全覆盖”

所以第一版对远程的要求不是“所有投射物都能带语义”，而是：

- 当前 BDP 测试链和后续重构主链必须改用 BDP 自定义投射物宿主

### Explosion 阶段

做法：

- 先确认当前爆炸链是通过什么投射物触发
- 如果语义能在爆炸生成前自然传进去，就直接用
- 如果原版这里没有自然口，再把“爆炸生成边界最小接线”作为单独问题处理

这里先不承诺“完全零 patch”。
这里只承诺：

- 不把爆炸问题扩散成多点补丁
- 只允许在一个明确边界接

### Hediff 写入阶段

目标：

- 最后写 `Hediff_Injury.sourceLabel` 时，优先用当前攻击语义的 `DisplayLabel`

这里目前的判断是：

- 大概率还是需要一个最小 patch
- 但 patch 只允许写在最终封闭写入口
- patch 只做“取语义、写来源名、无语义回退原版”

## 5. 第一版明确不做什么

- 不为所有原版 `Verb` 都加语义能力
- 不试图零成本覆盖所有原版投射物
- 不试图一次性统一所有爆炸来源
- 不为了避免 patch 而重包整条原版伤害系统
- 不把组合技、Ability、Thing 飞行物全部一起做掉

## 6. 第一版成功标准

达到以下就算第一版成功：

- 普通芯片近战伤口显示芯片名
- 普通芯片远程伤口显示芯片名
- 当前主链里的爆炸型表达能显示攻击行为名
- 原版武器和非 BDP 伤害完全不受影响
- 代码里能清楚看出：
  - 语义从哪来
  - 语义挂在哪些宿主上
  - 语义在哪个最终入口写进伤口

## 7. 一句话版

这次第一版不做大系统，只做一条实链：

- `ExpressionSource`
- `BDP 自定义 Verb`
- `BDP 自定义 Projectile`
- `最终伤口来源名写入`

先把这条链跑通，再继续扩到组合技和其它攻击入口。

## 8. 当前落地结果

截至 2026-03-24，第一版已落到这几个实际宿主和边界上：

- 近战直伤链
  - `BdpVerb_MeleeAttackDamage`
  - 在真正 `TakeDamage` 前压入攻击语义
- 远程直伤链
  - `BdpVerb_Shoot`
  - `BdpBullet`
  - 由 Verb 把语义交给投射物，再在投射物真正 `TakeDamage` 前压入攻击语义
- 爆炸链
  - `BdpExplosiveProjectile`
  - 在 `GenExplosion.DoExplosion(...)` 调用边界压入攻击语义
  - `Explosion.StartExplosion(...)` 只做一次最小接线，把语义挂到 `Explosion` 实例
  - `DamageWorker.ExplosionDamageThing(...)` 只在真正 `TakeDamage` 前把语义压回当前作用域
- 最终伤口来源写入
  - `DamageWorker_AddInjury.FinalizeAndAddInjury(...)`
  - 只在当前存在 BDP 攻击语义时覆盖 `Hediff_Injury.sourceLabel`

当前这版的意思不是“所有攻击入口都完成了”，而是：

- 普通芯片近战
- 普通芯片远程直伤
- 远程爆炸表达

这三条主链已经都有正式代码接点，可进入游戏验证。
