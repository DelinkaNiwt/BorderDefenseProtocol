# BDP 战斗体倒地崩解与触发体保护实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让 BDP 触发体在战斗体激活和短暂崩解阶段不因指定原版倒地路径掉落，并在激活态倒地后立即进入崩解。

**Architecture:** 只在 `BDP.Content.dll` 增加业务 Harmony 补丁。补丁为原版倒地清装备、操控能力丧失和倒地出生补偿建立临时上下文；实际装备拦截只保护当前主装备上的 `CompTriggerBody`。倒地后通过 Core 已有的 `ICombatBodyCommands.TriggerCollapse` 请求崩解，不改原版倒地判定。

**Tech Stack:** C# 7.3、Harmony、RimWorld 1.6、PowerShell 源码烟雾测试、MSBuild。

### Task 2: Implement the narrow protection context

**Files:**
- Create: `Source/BDP.Content/CombatBody/Protection/Patch_Pawn_HealthTracker_CombatBodyTriggerProtection.cs`

**Step 1: Implement the temporary context**

Add a small reference-counted per-Pawn context so nested `CheckForStateChange` and `MakeDowned` calls do not clear one another’s protection state.

**Step 2: Patch the three target callers**

- `Pawn_HealthTracker.MakeDowned`: protect the trigger during original downed cleanup; after the original method finishes, request collapse only when the pre-call phase was `Active` and the Pawn is now downed.
- `Pawn_HealthTracker.CheckForStateChange`: protect the trigger only around the manipulation-loss branch.
- `Pawn_EquipmentTracker.Notify_PawnSpawned`: protect the trigger only for a spawned Pawn that is already downed and not in bed.

**Step 3: Guard the actual equipment move**

Patch `Pawn_EquipmentTracker.TryDropEquipment`. When the temporary context is active, the phase is `Active` or `Collapsing`, and the requested equipment is the Pawn’s current primary with `CompTriggerBody`, return a successful no-op and leave the Thing in the equipment tracker. All other equipment and paths call the original method.
