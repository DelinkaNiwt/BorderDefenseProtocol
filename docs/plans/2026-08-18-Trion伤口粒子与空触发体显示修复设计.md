# Trion 伤口粒子与空触发体显示修复设计

## 问题性质

- 伤口粒子属于 Content（内容层）业务表现错误：全局提供器共享一份运行时，导致不同 Pawn（角色）的发射、清理和读档状态串线。
- Trion Gizmo（界面按钮面板）属于 Core（核心层）中性资源显示错误：错误地用锁定量判断是否显示持续消耗。

## 最小修复

1. 伤口表现接口的存档、清理和过期通知补齐 Pawn 参数；已有新增、移除、重建和 Tick（每帧更新）入口保持原有 Pawn 参数。
2. Content 提供器按 `pawn.thingIDNumber` 保存独立 `CombatBodyWoundSprayRuntime`（战斗体伤口喷射运行时），所有生命周期只操作对应角色。
3. `Gizmo_TrionStatus.BuildRateText`（Trion 状态面板速率文本构造）以 `reader.TotalDrainPerSecond > 0f` 判断是否显示消耗；冻结图标仍直接读取 `reader.Frozen`。

## 不做事项

- 不修改原版伤害链、伤口事实、Trion 结算或战斗体激活时序。
- 不给 Core 引入 Content 类型，也不让 Trion 反向读取 CombatBody（战斗体）业务状态。
- 不处理与本次两个根因无关的现有工作区改动。

## 验证

- 源码契约测试确认表现运行时按 Pawn 隔离，且所有清理和过期入口携带 Pawn。
- 源码契约测试确认速率文案不再使用 `Allocated`（锁定量），而使用正式持续消耗值。
- 运行相关伤口粒子、Trion Gizmo 测试并编译 Core 与 Content 的 Release（发布）配置。
