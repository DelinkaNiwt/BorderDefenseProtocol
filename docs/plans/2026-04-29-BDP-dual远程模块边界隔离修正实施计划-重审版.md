# dual（双持复合）远程模块双侧独立会话隔离实施计划

> **For Claude（供 Claude 执行）:** REQUIRED SUB-SKILL（必需子技能）: 使用 `superpowers:executing-plans（逐任务执行）` 按任务逐步实施本计划。

**Goal（目标）:** 在 `dual（双持复合）` 远程攻击下，让两侧模块在 `Aim（瞄准）` / `Prepare（准备）` / `Fire（开火）` / `ProjectileInit（投射物初始化）` 前半段各自运行在自己的 `ModuleSession（模块会话）` 里，不再互相污染；同时保持现有 `dual` 外层入口壳、宿主 `verb（攻击动词）` 发射桥、`burst（连发）` 宿主消费方式不变。

**Architecture（架构）:** 保留 `dual` 外层 `result（正式结果）` 作为入口门面与宿主发射桥承接点，不改表达层、不改执行器、不改 `verb` 宿主。仅在 [RangedAttackProtocolService.cs](C:/NiwtDatas/Projects/RimworldModStudio/模组工程/BorderDefenseProtocol/Source/BDP/Core/AttackExecution/RangedProtocol/RangedAttackProtocolService.cs) 内部，把 `dual` 的 `runtime step（运行时动作步）` 先按 `sourceResultId（来源结果标识）` 拆成单侧 `lane（来源泳道）`，每条 `lane` 复用现有单侧协议链独立运行，再按外层 `StepEmits（动作步发射集合）` 顺序合并回一份外层 `VerbEmissionPlan（宿主发射计划）`。

**Tech Stack（技术栈）:** C# 7.3 / RimWorld 1.6.4633 / BDP `AttackExecution（攻击执行）` + `RangedProtocol（远程协议）` / PowerShell 烟测 / `dotnet msbuild`

- `dual` 下的普通模块作者，不需要额外写 `sourceResultId（来源结果标识）` 手动过滤，也能自然得到双侧隔离。

**Step 3: Write minimal implementation（写最小实现）**

在 `RangedAttackProtocolService.cs` 内新增 4 个合并辅助方法：

```csharp
private static IReadOnlyList<ProjectileInitPlan> MergeProjectilePlansByOuterEmitOrder(...)
private static PrepareRecord BuildMergedPrepareRecord(...)
private static FireRecord BuildMergedFireRecord(...)
private static RangedVerbEmissionPlan BuildMergedVerbEmissionPlan(...)
private static RangedProjectionSeed BuildMergedProjectionSeed(...)
```

合并规则必须写死如下：

1. **`ProjectilePlans（投射物计划）` 顺序**
   - 主排序基线：`outerEntry.StepEmits（外层动作步发射集合）`
   - 逐个读取 `outerEntry.StepEmits[i].SourceResultId`
   - 从对应来源 `lane` 的 `ProjectilePlans` 队列里取下一个计划
   - 若某来源还有剩余计划但外层顺序已遍历完，再按来源 `lane` 原顺序把剩余计划追加到末尾

2. **`PrepareRecord（准备记录）` 聚合**
   - `ResourceCost（资源成本）`：求和
   - `MinimumRequired（最低门槛）`：取最大值
   - `SkipResourceConsumption（跳过资源消耗）`：按 `OR（或）`
   - `WarmupTicks（预热 Tick）`：取最大值
   - `ChargeTicks（充能 Tick）`：取最大值
   - `RequiresLock（需要锁定）`：按 `OR（或）`
   - `LockSatisfied（锁定已满足）`：按 `AND（且）`
   - `Tags（标签）`：追加合并

3. **`FireRecord（开火记录）` 聚合**
   - `FireCount（开火次数）`：使用合并后的计划数量
   - `Emits（发射记录）`：按合并后的外层顺序重建
   - `Tags（标签）`：把成功 `lane` 的标签全部追加

4. **`VerbEmissionPlan（宿主发射计划）` 聚合**
   - 只保留 **1 份** 外层计划，不能改成多宿主
   - `StepHostResultId（动作步宿主结果标识）`：沿用 `outerEntry.RuntimeStep.HostResultId`
   - `StepSourceResultIds（动作步来源结果集合）`：按合并后实际落地的来源去重收集
   - `ExpectedEmitCount（预期发射数）`：使用合并后的计划数量
   - `BattleLogPresentation（战斗日志表象）`：
     - 仅 1 条成功 `lane` 时：沿用该 `lane` 的单侧表象
     - 多条成功 `lane` 时：沿用 `outerEntry` 的 `dual` 表象

5. **`ProjectionSeed（投影种子）` 聚合**
   - 仅 1 条成功 `lane` 时：沿用该 `lane` 的 `seed（种子）`
   - 多条成功 `lane` 时：
     - `AttackInstanceId（攻击实例标识）`：沿用外层
     - `MainTarget（主目标）`：优先取第一个合并计划的目标；没有就回退外层目标
     - `AttackRole（攻击角色）`：沿用 `outerEntry.AttackRole`
     - `SourceResultId（来源结果标识）`：写 `null`
     - `FireCount（开火次数）`：使用合并后的计划数量
     - 各类 `Tags（标签）`：把成功 `lane` 的标签全部追加

最终组装出的外层结果应保持：
