# 战斗体伤口策略设计 - 第一版

日期：2026-05-14

状态：设计稿，待确认后进入实施计划。

## 1. 任务本质

这次需求不是重写 RimWorld 的伤口系统，也不是给 `Trion`（资源）系统增加扫描逻辑。

本质是：当 Pawn 处于 `CombatBody Active`（战斗体激活态）时，原版伤口 `Hediff`（健康状态）仍然作为伤口事实存在，但 BDP 需要按战斗体语义重新解释这些伤口的有效结果。

一句话：

```text
原版负责“这是什么伤”，BDP 负责“战斗体状态下这伤怎么算”。
```

## 2. 当前基线

### 2.1 BDP 当前已经有的能力

`CombatBody`（战斗体）当前已经有完整会话链路：

- 进入战斗体时：快照原身，清理当前非排除 `Hediff`，挂上 `BDP_CombatBodyActive`。
- 退出战斗体时：清理战斗期残留 `Hediff`，恢复进入前快照。
- 读档后：恢复战斗体运行期绑定，例如 `Trion` 维护消耗。

`BDP_CombatBodyActive` 当前已经通过原版 `HediffStage`（健康状态阶段）字段控制全局健康效果：

- `preventsDeath=true`：阻止常规健康判死。
- `painFactor=0`：总痛觉归零。
- `totalBleedFactor=0`：总流血率归零。
- `blocksMentalBreaks=true`：阻止精神崩溃。
- `hungerRateFactor=0`：暂停饥饿消耗。
- `restFallFactor=0`：暂停休息流失。
- `disablesNeeds=Comfort`：禁用舒适度需求。
- `statOffsets`：扩展舒适温度范围，提高毒性抗性。
- `makeImmuneTo`：免疫部分原版疾病。

`Trion` 当前已经有聚合持续消耗账本：

- 业务系统注册 drain（持续消耗）。
- `CompTrion` 统一合并 drain 并结算。
- 读档后 drain 注册表会清空，由各业务 owner（拥有者）重建。

### 2.2 当前缺口

`BDP_CombatBodyActive.totalBleedFactor=0` 只能压住 `BleedRateTotal`（总流血率）。

它不能压住单个伤口自己的：

- `BleedRate`（单伤口流血率）。
- `Bleeding`（是否显示为正在流血）。
- 健康页单伤口滴血图标。
- 信息卡里单伤口出血率。
- 其它直接看单伤口 `Bleeding/BleedRate` 的原版逻辑。

所以需要补一层战斗体伤口策略。

## 3. 设计目标

第一版目标只做必要闭环：

1. 保留原版伤口 `Hediff` 作为事实基线。
2. 战斗体激活期间，让单个伤口的有效流血表现与总流血归零保持一致。
3. 为未来 Trion 伤口流失保留正确机制，但默认值为不流失。
4. 伤口感染等全局健康保护优先放在 `BDP_CombatBodyActive`，不在伤口层重复实现。
5. 退出战斗体、读档、伤口移除时不会留下错误 drain 或残留状态。

## 4. 非目标

第一版不做以下事情：

- 不替换原版 `Hediff_Injury`（伤口）或 `Hediff_MissingPart`（缺失部位）。
- 不新建一套 BDP 伤口系统。
- 不重写治疗、医疗 AI（人工智能）、缺肢、自然愈合、伤口合并。
- 不把 `Trion` 写成定期扫描伤口的业务系统。
- 不在伤口策略层重复做痛觉、死亡保护、精神崩溃、饥饿、休息、温度、毒性、通用疾病免疫。

这些已经属于原版或 `BDP_CombatBodyActive` 的职责。

## 5. 总体结构

新增一层主模组内置业务：

```text
CombatBody Active（战斗体激活）
        |
        v
原版伤口 Hediff
        |
        v
CombatBodyWoundPolicy（战斗体伤口策略）
        |
        +-- 有效单伤口流血 = 0
        +-- 可选 Trion drain 注册/更新/注销
        +-- 读档/退出时重建或清理
```

建议的代码分层：

```text
BDP.Core.CombatBody.Wounds
  CombatBodyWoundPolicy
  CombatBodyWoundRuntime
  CombatBodyWoundTrionBinding
  CombatBodyWoundDrainSettings
  CombatBodyWoundRawMetrics
```

含义：

- `CombatBodyWoundPolicy`：判断当前是否应用战斗体伤口规则。
- `CombatBodyWoundRuntime`：处理伤口变化、进入、退出、读档重建。
- `CombatBodyWoundTrionBinding`：只负责把伤口 drain 写入/移出 `CompTrion`。
- `CombatBodyWoundDrainSettings`：读取默认配置。
- `CombatBodyWoundRawMetrics`：读取原版伤口的原始指标，例如未被 BDP 压制前的原始流血潜势。

## 6. 写死与可配置边界

### 6.1 可以写死的规则

以下属于架构边界，应该写死：

- 只在 `CombatBodyPhase.Active`（战斗体激活阶段）生效。
- 原版伤口 `Hediff` 仍是真值，不替换、不复制、不自造。
- 退出战斗体必须清理所有 BDP 伤口 drain。
- 读档后如果仍处于 Active，必须重建运行时 drain。
- drain 身份必须绑定到具体伤口实例，不能只按伤口 Def 聚合。
- Trion 默认不流失。
- 伤口策略不直接改原版伤口严重度、治疗状态、感染计时、自然愈合。

这些规则是为了保证系统边界稳定，不能交给 XML（可扩展标记语言）随意改。

### 6.2 不该写死的规则

以下不该写死：

- Trion 流失是否启用。
- Trion 流失倍率。
- Trion 流失是否按全部伤口、只按会流血伤口、或未来按特定伤口 Def 调整。
- 是否把 `WoundInfection`（伤口感染）加入战斗体激活态免疫列表。
- 未来是否显示特殊伤口视觉。

这些属于玩法参数，应该留给 XML 默认值或外部模组 patch（补丁）调整。

### 6.3 第一版默认配置

建议新增一个默认配置 Def：

```xml
<BDP.Core.CombatBody.Wounds.CombatBodyWoundPolicyDef>
  <defName>BDP_DefaultCombatBodyWoundPolicy</defName>
  <suppressIndividualBleeding>true</suppressIndividualBleeding>
  <trionDrainEnabled>false</trionDrainEnabled>
  <trionDrainPerRawBleedRate>0</trionDrainPerRawBleedRate>
  <includeMissingPartBleedPotential>true</includeMissingPartBleedPotential>
</BDP.Core.CombatBody.Wounds.CombatBodyWoundPolicyDef>
```

说明：

- `suppressIndividualBleeding=true` 是第一版核心行为，让单伤口显示和总流血逻辑一致。
- `trionDrainEnabled=false` 表示默认不产生 Trion 流失。
- `trionDrainPerRawBleedRate=0` 进一步保证默认值为 0。
- `includeMissingPartBleedPotential=true` 只是计算口径默认值；因为 drain 默认关闭，不会产生实际消耗。

如果以后要开启 Trion 流失，只需要 patch 默认 Def 或新增配置来源，不需要改 `CompTrion`。

## 7. 流血规则设计

### 7.1 总流血

继续使用现有 `BDP_CombatBodyActive.totalBleedFactor=0`。

它负责：

- `BleedRateTotal`（总流血率）为 0。
- 原版失血 `BloodLoss` 不增长。
- 血迹/血滴不生成。
- 因流血死亡的时间计算归零。

这部分已经正确，不重复做。

### 7.2 单伤口流血

新增最小 Harmony（运行时补丁）接线：

- `Hediff_Injury.BleedRate`
- `Hediff_MissingPart.BleedRate`

当满足以下条件时，把返回结果改成 0：

- Pawn 处于 `CombatBodyPhase.Active`。
- 默认策略 `suppressIndividualBleeding=true`。
- 当前调用不是 BDP 自己读取原始指标的 bypass（绕过）上下文。

效果：

- 单伤口 `Bleeding` 变为 false。
- 健康页单伤口滴血图标消失。
- 信息卡单伤口出血率不再显示。
- `Gene_Clotting` 等直接看 `hediff.Bleeding` 的原版逻辑不会再误判战斗体伤口正在流血。

## 8. Trion 流失设计

### 8.1 默认值

第一版默认不流失：

```text
trionDrainEnabled = false
trionDrainPerRawBleedRate = 0
```

也就是说，即使伤口策略层存在，也不会默认改变当前战斗体资源平衡。

### 8.2 为什么仍要设计流失机制

因为后续如果要开启 Trion 泄漏，不能临时写成扫描器。

正确关系是：

```text
伤口变化 -> 伤口策略更新 drain -> Trion 聚合账本结算
```

而不是：

```text
Trion 每隔一段时间扫描所有伤口
```

前者业务关系正确，后者会让资源系统理解伤口业务，边界反了。

### 8.3 drain 身份

每个伤口实例一条 drain。

建议 key（键）：

```text
Domain  = CombatBody
Channel = Wound
Index   = -1
Tag     = Hediff_具体loadID
```

理由：

- 同一个 Pawn 可以同时有多个同 Def 伤口。
- 伤口合并后保留旧实例，应更新旧实例 drain。
- 伤口移除时只注销自己的 drain，不影响其它伤口。
- 读档后 `loadID` 可恢复，适合作为稳定身份。

### 8.4 drain 计算口径

如果以后启用默认流失，建议第一种默认计算口径是：

```text
drainPerDay = rawBleedRate * trionDrainPerRawBleedRate
```

其中 `rawBleedRate` 不是被 BDP 压成 0 后的有效流血率，而是“原版伤口在没有 BDP 单伤口压制时会返回的原始流血潜势”。

这个口径天然继承原版判断：

- 伤口严重度。
- 伤口 Def 的 `injuryProps.bleedRate`。
- 部位 `bleedRate`。
- 种族 `bleedRateFactor`。
- 是否能流血。
- 是否已治疗。
- 是否永久伤。
- 是否自然止血。
- 是否新鲜缺失部位。
- 是否机械/非有机部位。

这样 BDP 不需要重新定义“什么伤更严重”，只把原版已经算好的伤口危险度转换成 Trion 流失。

### 8.5 rawBleedRate 读取方式

因为 BDP 会把单伤口有效 `BleedRate` 压成 0，所以不能直接在普通上下文读 `hediff.BleedRate` 来算 drain。

需要一个内部 bypass（绕过）机制：

```text
CombatBodyWoundRawMetrics
  临时进入 bypass
  读取 hediff.BleedRate
  退出 bypass
```

BDP 的 `BleedRate` 补丁看到 bypass 时不压制结果。

这样：

- 玩家看到的有效流血是 0。
- drain 计算仍能读到原版原始流血潜势。
- 其它模组对原版 `BleedRate` 的正常改动仍可参与计算。

### 8.6 更新时机

主机制是事件驱动：

- 伤口加入：注册或更新 drain。
- 伤口移除：注销 drain。
- 伤口合并：更新保留下来的旧伤口 drain。
- `Notify_HediffChanged`：更新相关伤口 drain。
- 进入 Active：全量重建当前伤口 drain。
- 退出 Active：清空所有 BDP 伤口 drain。
- 读档后仍 Active：全量重建。

同时保留低频校准：

- 只在 `trionDrainEnabled=true` 时启用。
- 只用于补原版静默变化，例如治疗持续时间自然到期这类不一定触发 `Notify_HediffChanged` 的状态。
- 不作为主流程，不每 tick 扫描。

建议校准间隔默认 600 tick。

## 9. 伤口感染设计

伤口感染不放进 `CombatBodyWoundPolicy`。

原版伤口感染来自伤口上的 `HediffComp_Infecter`，最终会尝试添加 `WoundInfection`。

如果业务目标是“战斗体伤口不会感染”，最小正确做法是把 `WoundInfection` 加入 `BDP_CombatBodyActive.makeImmuneTo`。

理由：

- 走原版 `ImmunityHandler.DiseaseContractChanceFactor`。
- 不需要单独拦截 `HediffComp_Infecter`。
- 不影响原身旧感染：旧感染在进入战斗体时被快照，退出时按快照恢复。
- 外部模组可以通过 XML patch 调整免疫列表。

默认建议：

```text
BDP_CombatBodyActive.makeImmuneTo 增加 WoundInfection
```

但这属于激活态全局保护，不属于伤口策略层。

## 10. 生命周期

### 10.1 进入 Active

```text
TryActivate
  -> 原有战斗体变换
  -> 挂 BDP_CombatBodyActive
  -> CombatBodyWoundRuntime.RebuildActiveWounds
  -> 如果 drain 开启，注册当前伤口 drain
```

默认 drain 关闭时，重建结果为空，不产生消耗。

### 10.2 Active 期间新增伤口

```text
原版伤害 -> AddDirect -> 原版伤口加入
  -> BDP 伤口事件接线
  -> 如果 Active，更新单伤口策略状态
  -> 如果 drain 开启，注册该伤口 drain
```

单伤口流血压制不需要保存状态，查询 `BleedRate` 时动态判断。

### 10.3 伤口变化

```text
治疗 / 愈合 / 合并 / 自然止血 / 新鲜缺肢变化
  -> 原版触发 Notify_HediffChanged 或合并回调
  -> BDP 更新对应 drain
```

如果某些原版变化不发通知，低频校准兜底。

### 10.4 退出 Active

```text
战斗体退出
  -> CombatBodyWoundRuntime.Clear
  -> 注销所有 CombatBody/Wound drain
  -> 原有战斗体恢复流程继续
```

必须保证即使恢复流程清理了伤口，也不会留下 drain。

### 10.5 读档恢复

```text
CompCombatBodyHost.PostExposeData(PostLoadInit)
  -> 如果 Phase == Active
  -> CombatBodyWoundRuntime.RebuildActiveWounds
```

符合 `CompTrion` 当前设计：drain 注册表是运行期账本，读档后由业务 owner 重建。

## 11. 错误与安全策略

如果没有 `CompTrion`：

- 不注册 drain。
- 不报错刷屏。
- 单伤口流血压制仍可生效。

如果伤口没有有效 `loadID`：

- 不注册 drain。
- 可记录一次性诊断。

如果配置 Def 缺失：

- 使用内置默认值：
  - 单伤口流血压制开启。
  - Trion 流失关闭。
  - Trion 流失倍率 0。

如果 Active 状态异常：

- 以 `CombatBodyPhase.Active` 为真值。
- `BDP_CombatBodyActive` 只作为原版健康效果承载，不作为业务真值。

## 12. 测试与验证

建议第一版验证点：

1. Active 期间总流血率为 0。
2. Active 期间单伤口不显示滴血图标。
3. Active 期间单伤口信息卡不显示出血率。
4. 非 Active 状态原版伤口流血完全不变。
5. 默认配置下，新增伤口不产生 Trion drain。
6. 启用测试配置后，伤口新增注册 drain，移除注销 drain。
7. 伤口合并后 drain 更新，不留下新伤口残余 key。
8. Active 退出后所有 `CombatBody/Wound` drain 清空。
9. Active 读档后 drain 可重建。
10. `WoundInfection` 加入激活态免疫后，战斗体伤口不会生成伤口感染。

游戏内难复现点优先加可拆卸诊断日志，不依赖过度脚本测试。

## 13. 最终结论

第一版推荐落点：

```text
BDP_CombatBodyActive
  继续管全局健康保护
  补 WoundInfection 免疫

CombatBodyWoundPolicy
  只管 Active 期间原版伤口的有效解释
  默认压制单伤口流血
  默认不启用 Trion 流失

CombatBodyWoundTrionBinding
  只在配置启用时，把每个伤口注册成独立 drain
  drain 计算基于原版 rawBleedRate
```

这能保持 BDP 的主模组定位：

- 不重造 RimWorld 健康系统。
- 不把业务塞进 Trion 基础设施。
- 不让伤口策略重复激活态全局保护。
- 保留默认简单行为。
- 为后续 Trion 泄漏和伤口扩展留下清晰入口。
