# 皇室追兵队伍最小实现计划

Status: Implemented, game verification pending

**目标：** 接通已批准的“战斗体崩解后原身继续进攻”，只补本任务追兵队伍，不扩展一般敌方战术。

**接法：** 内容程序集继承原版进攻队伍，关闭超时／溃逃、绑架和偷窃。原版在倒地方法内部先移除队伍成员，BDP 后置处理才请求崩解；因此只在实际战斗体激活／崩解阶段暂缓倒地移除。保存这些待恢复人物，原版队伍更新时只检查此小列表：原身能行动则继续原版进攻，仍倒地则补发原版失能通知。死亡、被俘等不延迟。不增加全地图扫描、全局补丁、事件总线或持续日志。

**原版依据：** 当前游戏程序集模块标识 `61e4173561894da49d210260257b5097`；`LordJob.ShouldRemovePawn`（成员移除判断）`0600688E`、`Lord.Notify_PawnLost`（失去成员）`06006837`、`LordJob.Notify_PawnUndowned`（恢复行动）`06006887`、`Lord.LordTick`（队伍更新）`06006831`。队伍更新即使成员倒地仍调用业务更新；普通恢复行动不会重新加入已经失去的队伍。

## 执行步骤

1. 新增 `Source/BDP.Tests/RoyalPursuerLordTests.cs` 和 `.ps1`，针对实际内容程序集验证：普通人物和原身正常移除；激活／崩解倒地暂缓；死亡、被俘不暂缓；重复通知不积累重复记录；恢复行动后清除等待记录；原版进攻队伍不受改变；本队伍关闭三种离场开关。先运行并确认缺少新业务类型导致失败。
2. 新增 `Source/BDP.Content/Royal/Quest/LordJob_RoyalPursuers.cs`，采用原版公开覆盖口，保存人物引用，不触及核心程序集。
3. 修改 `Source/BDP.Development/CombatBody/HostileResource/HostileTrionDebugActions.cs`，复用现有地图外激活生成逻辑，增加“本任务追兵”实测按钮；其余公共资源测试仍用普通队伍。按钮语言键加入开发语言包 `HostileTrion.xml`。
4. 构建开发工程及依赖；运行新行为验证和既有战斗体倒地保护回归；核对语言文件；只提交本轮文件和实际更新的内容程序集，记录工作日志。

## 游戏实测与边界

开发菜单“BDP：敌方 Trion 资源测试”中生成本任务追兵；验证原型远程／近战、耗尽崩解后原身继续进攻、战斗体受伤倒地崩解后恢复进攻、原身真正倒地／死亡／被俘移除；在崩解期间存读档核对队伍身份。离线验证不代替地图战斗、保存和整波胜利信号实测。

正式任务随后接通，届时使用单组队伍并把原版队伍结束信号连到正式加入。驱动核心物品、人数／强度／时机不在本轮代定；不增加备用武器、再次变身或必须杀死倒地追兵的规则。

## 本轮结果

已实现队伍与专用生成按钮，三个程序集构建通过，新队伍离线边界验证、战斗体倒地保护回归及语言文件解析通过。离线夹具使用实际程序集，明确将人物设为原版可行动状态；不启动地图或任务系统。“原身恢复后仍倒地”的原版移除链、整波结束信号及崩解期间存读档保留为游戏实测项。不保留尝试用离线补丁启动地图通知链的夹具改动。
