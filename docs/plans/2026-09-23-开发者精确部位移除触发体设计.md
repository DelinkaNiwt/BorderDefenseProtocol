# 开发者精确部位移除触发体设计

## 1. 目标

新增一个仅供开发者生成的测试触发体。该触发体固定预装一枚远程武装类芯片，允许开发者在攻击前通过现有芯片形态按钮选择原版人类身体树中的具体部位，例如左手、右手、左肺或右肺。投射物直接命中 Pawn（角色）后，立即通过原版 `MissingBodyPart`（部件缺失）机制移除预选部位。

本功能用于开发验证，不进入制造、交易、随机装备、任务奖励或普通掉落流程。

## 2. 已确认行为

1. 先选择部位，再选择攻击目标；部位选择与具体目标解耦。
2. 选择精确到同类部位的出现序号，可以区分左手和右手等同定义记录。
3. 投射物只对直接命中的 Pawn 生效。
4. 指定部位不存在、已经缺失、不可摧毁或生命值已经为零时，本次无效果。
5. 没有命中 Pawn 时，本次无效果。
6. 失败时不回退到同类其他部位，也不造成普通伤害。
7. 触发体由开发菜单直接生成，生成时已经固定预装测试芯片。
8. 普通游戏流程不得自然产生该触发体或芯片。

## 3. 现有设施

### 3.1 远程命中与部位移除

现有 `RangedDebuffModule`（远程减益模块）已经能够：

- 在投射物 `Impact`（命中生效）阶段处理直接命中；
- 只对 Pawn 解析身体部位；
- 把 `BodyPartRecord`（身体部位记录）写入额外效果计划；
- 抑制投射物的真实伤害；
- 对指定部位添加 Hediff（健康状态）；
- 在严重度达到上限后调用 `RemoveBodyPartThresholdAction`（移除身体部位阈值动作）；
- 通过 `HediffDefOf.MissingBodyPart`（原版部件缺失定义）移除部位。

因此不新增专用投射物命中链，不直接修改身体树，也不增加全局伤害补丁。

### 3.2 芯片形态按钮

现有芯片形态系统已经提供：

- 左键循环形态；
- 右键展开完整形态菜单；
- 当前形态随触发体槽位状态存读档；
- 形态切换后重建正式表达；
- 开火时冻结当前表达和远程模块配置。

本功能把每个精确部位预设声明为一种芯片形态，不新增第二套选择状态。

### 3.3 固定装载与开发生成

现有固定装载工厂能够根据 `initializationKey`（初始化键）创建真实动态芯片并原子装入触发体。现有开发菜单也已有“在选中殖民者附近生成测试触发体”的成熟模式。

本功能继续复用这两项设施，不提供独立芯片生成入口。

## 4. 架构边界

### 4.1 Core.dll（核心程序集）

不修改。

核心程序集现有的远程模块运行时、攻击上下文、投射物计划、固定装载、芯片形态和外部按钮扩展已经满足需求。精确部位选择属于 Content（正式内容）的部位策略，不应下沉为新的核心业务概念。

### 4.2 Content.dll（正式内容程序集）

只扩展现有通用部位解析能力：

- 在 `HitPartSelectionMode`（命中部位选择模式）增加精确定义序号模式；
- 在 `RangedDebuffConfig`（远程减益配置）增加可选的身体部位定义与出现序号；
- 在 `RangedDebuffModule` 中按该配置调用精确解析；
- 保持现有随机、偏好要害和回避要害模式不变；
- 将新增通用字段投影到芯片信息系统。

默认值必须关闭新行为，避免影响现有卵之冠和其他远程减益配置。

### 4.3 Development.dll（开发程序集）

只承载开发菜单生成入口。入口读取专用测试触发体定义，在当前选中且受玩家控制的殖民者附近生成一个完整触发体。

### 4.4 1.6/Development（开发定义目录）

承载：

- 专用测试触发体 `ThingDef`（物品定义）；
- 隐藏的测试芯片功能定义；
- 零基础伤害的测试投射物；
- 开发功能所需的简体中文语言键。

## 5. 精确部位身份

每个预设使用以下中性身份：

```text
BodyPartDef（身体部位定义） + OccurrenceIndex（完整身体树中的同定义出现序号）
```

例如，在当前原版人类身体树中：

```text
Hand + 0  -> 左手
Hand + 1  -> 右手
Lung + 0  -> 左肺
Lung + 1  -> 右肺
```

解析必须遵守以下顺序：

1. 遍历目标完整身体树的全部记录。
2. 收集 `part.def` 等于配置部位定义的全部记录。
3. 在未过滤缺失状态前，按身体树顺序取得指定序号。
4. 对选中的唯一记录检查是否可摧毁、是否缺失以及当前生命值是否大于零。
5. 任一检查失败则返回无结果。

不能先过滤缺失部位再计算序号，否则左手缺失后右手会错误地成为第零个手。

该身份以原版人类身体结构为作者基线。其他种族如果具有相同部位定义和足够的出现数量，可以按其自身身体树顺序解析；否则无效果，不做猜测或回退。

## 6. 芯片形态与定义组织

测试芯片以原版人类身体树为基准，手工枚举可移除的实际部位。每个形态使用稳定、非本地化的形态键，并通过语言键显示中文名称。

为避免新增状态系统或修改 Core，芯片表达目录只声明一条公共远程射击条目，并为每个精确部位声明一条被动增强条目。每个形态同时启用公共射击条目和对应的部位增强条目；现有 `RangedModuleAugmentations`（远程模块增强）设施会把该部位的远程减益模块挂到公共射击结果上。

各部位增强所引用的开发模块定义，以一个抽象父定义保存公共减益参数，具体子定义只覆盖 `BodyPartDef`（身体部位定义）和 `OccurrenceIndex`（出现序号）。这样既不复制整套射击配置，也不为压缩测试 XML 引入运行时生成器或新的通用抽象。

默认形态选择一个明确、非歧义的部位。左键按定义顺序循环，右键列出全部部位。

## 7. 命中数据流

```text
开发者选择部位形态
  -> 正常远程攻击 Pawn
  -> 开火时冻结当前表达和精确部位配置
  -> BDP 投射物直接命中
  -> RangedDebuffModule 解析 BodyPartDef + OccurrenceIndex
  -> 创建携带 HitPart 的部位 Hediff 效果计划
  -> 一次写入最大严重度
  -> RemoveBodyPartThresholdAction 立即执行
  -> 原版 MissingBodyPart 生效
```

测试配置把单次严重度设置为 Hediff 最大严重度，因此命中一次立即移除部位，不改变通用叠层执行器。

已经发射的投射物继续使用发射时冻结的配置。飞行途中切换形态只影响之后发射的投射物。

## 8. 失败关闭与非 Pawn 处理

测试投射物的基础伤害为零，主动目标参数只允许 Pawn。

以下情况不提交部位效果计划：

- 无效命中；
- 命中对象不是 Pawn；
- 目标没有健康系统或身体树；
- 配置的身体部位定义为空；
- 出现序号小于零或超出范围；
- 选中的记录已经缺失；
- 选中的记录不可被伤害摧毁；
- 选中部位当前生命值不大于零。

失败后不改选其他部位。由于投射物基础伤害为零，误撞建筑、物品或不匹配 Pawn 时也不会造成普通伤害。

## 9. 开发生成与普通流程隔离

专用测试触发体：

- 使用现有触发体组件；
- 只有一个固定装载所需槽位；
- 通过 `initializationKey` 预装隐藏测试芯片；
- 不提供普通配方；
- `tradeability`（可交易性）设为不可交易；
- 不声明随机武器生成标签；
- 不加入商店、掉落、任务奖励或其他生成表；
- 隐藏芯片功能设置为不可在制造界面显示。

开发菜单入口：

- 只在游戏进行中出现；
- 要求当前选择一个已生成、受玩家控制的殖民者；
- 在该殖民者附近生成完整触发体；
- 失败时销毁未成功放置的临时物品并显示语言包消息。

通用开发者物品生成工具仍可看见测试定义，这是允许的开发途径，不属于普通游戏流程。

## 10. 验证

### 10.1 静态与自动验证

1. 精确解析在完整身体树上计算出现序号。
2. 第零个部位缺失后，第一个部位不会顶替它。
3. 空定义、负序号、越界序号和非 Pawn 均返回失败。
4. 现有随机、偏好要害、回避要害和卵之冠配置保持原行为。
5. 新配置的克隆保留部位定义和出现序号。
6. 测试投射物基础伤害为零。
7. 测试芯片不进入制造列表。
8. 测试触发体无配方、不可交易且没有随机生成标签。
9. Core 不出现本功能的业务类型或字段。

### 10.2 游戏内验证

1. 开发菜单能在选中殖民者附近生成预装芯片的触发体。
2. 激活芯片后出现部位形态按钮，左键循环和右键菜单均正常。
3. 左手和右手分别命中正确记录。
4. 左手缺失后再次选择左手无效果，右手保持不变。
5. 选择不存在或越界部位命中其他种族时无效果。
6. 投射物误撞非 Pawn 时不造成伤害。
7. 飞行途中切换形态不改变旧投射物的结果。
8. 保存并读取后当前部位形态保持不变。
9. 制造、交易、奖励和普通生成流程中不出现测试触发体或测试芯片。

## 11. 非目标

- 不实现针对任意目标动态生成部位菜单。
- 不提供独立测试芯片生成入口。
- 不为非 Pawn 构造虚假的部件系统。
- 不保证不同身体结构中的序号具有相同左右语义。
- 不新增全局 Harmony（运行时补丁）或侵入式伤害补丁。
- 不修改旧版模组或退役测试模组。
