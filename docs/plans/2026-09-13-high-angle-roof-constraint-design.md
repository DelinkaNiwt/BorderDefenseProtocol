# 高角射击屋顶约束设计

## 目标

为高角射击模块增加屋顶约束：发射者处于屋顶下时不能进行高角射击；目标处于厚屋顶或山顶屋顶下时不能进行高角射击；目标处于普通薄屋顶下时由模块配置决定，默认禁止。

## 已确认事实

1. 当前 `HighAngleShootingModule` 只参与 `ProjectileInit`（投射物初始化）阶段，在最终目标没有直视线时替换为 `flyOverhead`（越顶飞行）投射物并提交视觉轨迹参数。
2. BDP 的 `Confirm`（确认）阶段已有模块拒绝机制，可以在手动下单前返回本地化拒绝原因。
3. BDP 的 `ProjectileInit` 阶段已有停止请求机制；阶段停止会使本次协议不生成投射物计划，上层不会回退发射普通子弹。
4. 原版迫击炮目标筛选只拒绝厚屋顶目标；普通薄屋顶目标允许。原版自动炮台在发射者格存在任意屋顶时不启动越顶投射物。

## 方案

### 规则判断

只在当前攻击确实需要高角路径时执行屋顶约束，即最终目标与发射者之间没有原版直视线。普通直视线攻击不受高角模块规则影响。

判断顺序：

1. 发射者所在格存在任意屋顶：拒绝。
2. 目标所在格是厚屋顶或山顶屋顶：拒绝。
3. 目标所在格是普通薄屋顶：只有 `AllowTargetUnderThinRoof` 为 `true` 时允许。
4. 目标所在格无屋顶：允许。

山顶屋顶使用原版 `RoofDef.isThickRoof`（厚屋顶标记）识别，不按建筑名称或贴图判断。

### 归属与数据流

屋顶规则属于 `BDP.Content` 的高角业务模块，不进入 `BDP.Core`：

```text
高角模块配置
    ↓
HighAngleShootingModule
    ├─ Confirm：手动确认时拒绝并反馈语言包文案
    └─ ProjectileInit：自动攻击/正式计划生成时硬拒绝
```

同一套私有判断方法由两个阶段复用，避免手动和自动路径出现规则漂移。

### 手动攻击

高角模块额外实现 `IConfirmStageModule`。确认记录使用最终语义目标；不满足屋顶条件时设置 `IsAllowed=false` 和对应语言键，目标交互保持打开，玩家可以重新选择目标。

本次不实现 `ITargetingStageModule` 的悬停即时红色反馈，避免扩大目标交互行为，也保留当前高角模块“不接管目标选择”的边界。

### 自动攻击与正式计划

高角模块在现有 `IProjectileInitStageModule` 中先判断屋顶条件，再提交高角投射物覆盖。条件不满足时提交 `Stop`（停止请求），使 `ProjectileInitStageService` 返回空计划；不得只跳过投射物覆盖，否则可能错误地发射普通子弹。

对于双来源攻击，继续沿用现有单侧泳道隔离：被屋顶规则拒绝的高角来源泳道停止，其他合法来源泳道不被连带修改。

## 配置

在 `HighAngleShootingConfig` 增加：

```csharp
public bool AllowTargetUnderThinRoof = false;
```

同步完成配置克隆和存档读写；高角模块 Def 显式写入：

```xml
<AllowTargetUnderThinRoof>false</AllowTargetUnderThinRoof>
```

默认值为 `false`，即普通薄屋顶目标默认禁止高角射击。需要放行的具体模块或组合技可以在自己的配置中改为 `true`。

## 文案

拒绝原因写入简体中文语言包，不在 C# 中硬编码：

- 发射者位于屋顶下。
- 目标位于厚屋顶/山顶屋顶下。
- 当前配置不允许攻击薄屋顶下目标。

## 非目标

- 不修改 `BdpProjectile` 的飞行、追踪、命中或视觉逻辑。
- 不修改 `flyOverhead` 的原版碰撞语义。
- 不在 `BDP.Core` 增加高角、屋顶或迫击炮专用判断。
- 不新增实际发射瞬间的 Core 通用扩展；只有在验证发现暖机期间屋顶变化能绕过约束时，才单独评估该问题。

## 验收标准

1. 无屋顶发射者对无屋顶目标：高角射击正常生成。
2. 发射者在普通屋顶下：高角射击被拒绝。
3. 发射者在山顶屋顶下：高角射击被拒绝。
4. 目标在山顶屋顶下：高角射击被拒绝。
5. 目标在普通薄屋顶下且配置为 `false`：被拒绝。
6. 目标在普通薄屋顶下且配置为 `true`：允许。
7. 有直视线的普通攻击不受上述高角规则影响。
8. 自动攻击与手动攻击都不能通过高角模块发射普通子弹作为回退。
9. 双来源攻击继续按来源泳道分别裁定。
10. 新增拒绝文案可从语言包读取，Core 与 Content 的程序集依赖边界不改变。
