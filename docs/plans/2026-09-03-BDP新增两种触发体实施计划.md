# BDP 新增两种触发体 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 新增“边境特制触发体”和“近界测试触发体”，并让后者在首次生成时通过现有动态芯片成品逻辑预装自动护盾与紧急脱离芯片。

**Architecture:** 触发体槽位仍由 Core 的 `CompProperties_TriggerBody` 管理。Core 只增加中性的固定装载成品工厂契约和初始化键，不认识 Content 的芯片功能预设；Content 注册工厂，把功能预设解析为单功能 `ChipCombinationRecord`，再创建 `BDP_Chip_Custom` 成品。现有标准触发体和运行时槽位语义保持不变。

**Tech Stack:** C# 7.3、.NET Framework 4.8、RimWorld 1.6 Def/XML、PowerShell 冒烟测试、MSBuild/.NET build。

### Task 2: 增加 Core 固定装载成品工厂边界

**Files:**
- Create: `Source/BDP/Core/Trigger/Loadout/ITriggerFixedLoadoutFactory.cs`
- Create: `Source/BDP/Core/Trigger/Loadout/TriggerFixedLoadoutFactoryRegistry.cs`
- Modify: `Source/BDP/Core/Trigger/Defs/TriggerFixedLoadoutEntry.cs`
- Modify: `Source/BDP/Core/Trigger/State/CompTriggerBody.FixedLoadout.cs`
- Modify: `Source/BDP/Core/Trigger/Loadout/TriggerFixedLoadoutValidator.cs`

**Step 1: Add the neutral factory contract**

`ITriggerFixedLoadoutFactory` 只接受 `ThingDef chipDef` 与 `string initializationKey`，返回已初始化的 `Thing`；Core 不引用 `ChipFunctionDef`、`ChipCombinationRecord` 或任何 Content 命名空间。

`TriggerFixedLoadoutFactoryRegistry` 按注册顺序尝试工厂，忽略空工厂和重复具体类型，隔离单个工厂异常；没有初始化键时继续使用现有 `ThingMaker.MakeThing(entry.chipDef)` 路径。

在 `TriggerFixedLoadoutEntry` 增加可选 `initializationKey` 字段，并逐成员补充中文注释。

**Step 2: Connect fixed-loadout creation**

`CompTriggerBody.FixedLoadout` 在 `initializationKey` 非空时调用注册表创建完整成品；创建失败时沿用现有失败报告和批次回滚。无初始化键的旧固定装载行为不变。

**Step 3: Keep static validation compatible**

`TriggerFixedLoadoutValidator` 在初始化键为空时继续校验静态芯片契约；初始化键非空时只校验实体 `chipDef`、槽位和占用规则，把动态芯片有效性留给 Content 工厂运行时解析。

**Step 4: Build Core**

### Task 3: 提取并复用 Content 动态芯片成品生成逻辑

**Files:**
- Create: `Source/BDP.Content/Assembly/ChipManufacturing/Production/ChipProductCreationService.cs`
- Create: `Source/BDP.Content/Assembly/ChipManufacturing/Production/ManufacturedChipTriggerFixedLoadoutFactory.cs`
- Modify: `Source/BDP.Content/Assembly/ChipManufacturing/Debug/ChipFabricatorDebugCompletionService.cs`
- Modify: `Source/BDP.Content/ContentBootstrap.cs`

**Step 1: Add a shared product creation service**

从调试制造完成服务中抽出“根据有效 `ChipCombinationRecord` 创建 `BDP_Chip_Custom` 并写入 `CompManufacturedChip`”的共用步骤。服务不创建账单、不扣材料、不占用工作时间；失败时销毁未交付的实体芯片并返回失败原因。

**Step 2: Reuse the service in debug production**

调试制造流程保留自己的账单处理和放置逻辑，但改为调用共用成品创建服务，避免正式预装和调试制造各自维护一套成品初始化代码。

**Step 3: Add the fixed-loadout adapter**

Content 工厂只处理 `chipDef == BDP_Chip_Custom` 的初始化键。它按功能预设 DefName 查找 `ChipFunctionDef`，从功能配置的类别和原生职业建立单功能 `ChipCombinationRecord`，交给 `ChipCombinationResolver` 验证，然后调用共用成品创建服务。

使用：

```text
BDP_ChipFunction_EnergyShield_Auto
BDP_ChipFunction_EmergencyEscape
```

不设置武装构型。两个功能预设本身均为特殊槽单槽芯片。

**Step 4: Register the factory**

在 `ContentBootstrap` 启动期注册工厂，保持 `BDP.Core.dll` 不依赖 `BDP.Content.dll`。

**Step 5: Run Content build**

Run:

```powershell
dotnet build .\Source\BDP.Content\BDP.Content.csproj --configuration Release --no-restore
```

Expected: PASS，生成 `1.6/Assemblies/BDP.Content.dll`。
