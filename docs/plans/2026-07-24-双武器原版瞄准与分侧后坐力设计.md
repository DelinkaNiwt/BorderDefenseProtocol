# 双武器原版瞄准与分侧后坐力设计

日期：2026-07-24  
状态：已确认  
适用范围：`BorderDefenseProtocol`（边境防御协议主模组）双武器视觉基础设施

## 一、背景与问题

BDP（边境防御协议）的双武器视觉不能直接调用原版 `DrawEquipmentAiming`（瞄准装备绘制）两次，因为原版入口只知道一件实际装备，而 BDP 需要按两个表达结果分别绘制两张武器贴图。

因此，BDP 必须保留“分别绘制两个常驻视觉条目”的最小适配层，但这个适配层不应重新发明瞄准镜像和后坐力规则。

当前存在两个具体问题：

1. 南北、东西姿态配置中保留了 `AimMirror`（瞄准镜像）作者开关，但运行时实际按原版瞄准角度分区决定网格镜像，并未读取这两个开关。它们是无效、容易误导的配置面。
2. 单武器贴图替换路径已经调用原版 `EquipmentUtility.Recoil`（装备后坐力计算），双武器常驻条目路径却没有后坐力；若简单读取复合宿主的开火时间，又无法判断实际由主手还是副手发射。

## 二、目标

本次设计只解决以下事项：

1. 删除作者可配置的 `AimMirror`（瞄准镜像）开关。
2. 双武器继续固定执行原版瞄准角度、装备角度偏移和网格镜像规则。
3. 双武器每一侧分别使用原版后坐力计算。
4. 谁真正发射，谁更新自己的原版 `Verb.LastShotTick`（攻击动作最近开火时间），从而只让对应武器发生后坐力。
5. 不新增后坐力参数、曲线、计时容器或存档字段。

## 三、非目标

本次不做以下扩展：

1. 不允许芯片自定义瞄准镜像。
2. 不允许芯片自定义后坐力方向、幅度或恢复曲线。
3. 不从投射物反向识别开火来源。
4. 不把双武器拆成两套完整、独立执行的攻击 `Verb`（攻击动作）。
5. 不让视觉后坐力改变枪口锚点、投射物出生点、弹道或命中结果。
6. 不顺带重构无关的单武器绘制路径。

## 四、原版机制基线

### 4.1 原版瞄准姿态

原版 `PawnRenderUtility.DrawEquipmentAiming`（单位装备瞄准绘制）按 `aimAngle`（瞄准角度）固定处理：

- 基础角度为 `aimAngle - 90`。
- `20 < aimAngle < 160` 时使用普通网格，并加上装备角度偏移。
- `200 < aimAngle < 340` 时使用镜像网格，角度减去 `180`，并减去装备角度偏移。
- 其他角度使用普通网格，并加上装备角度偏移。

这不是可选效果，而是原版为保证武器贴图朝向正确而使用的固定绘制规则。

### 4.2 原版后坐力

原版射击成功时，由正在执行射击的 `Verb`（攻击动作）记录 `lastShotTick`（最近开火时刻）。绘制装备时，原版把以下数据交给 `EquipmentUtility.Recoil`（装备后坐力计算）：

- 装备定义中的 `recoilPower`（后坐力强度）；
- 装备定义中的 `recoilRelaxation`（后坐恢复速度）；
- 射击 `Verb`（攻击动作）的 `LastShotTick`（最近开火时刻）；
- 当前瞄准角度。

该方法只返回本帧的绘制位置偏移和角度偏移，不参与投射物生成或命中计算。

## 五、总体方案

采用“每个来源复用自己的正式 `Verb` 状态，再调用原版后坐力函数”的方案。

```text
某一发射计划通过全部开火前校验
        |
        v
读取 plan.ResultId（计划来源结果标识）
        |
        +--> 当前执行宿主.lastShotTick = 当前游戏刻
        |
        +--> 找到该来源的正式 RangedVerb（远程攻击动作）
                 |
                 v
             sourceVerb.lastShotTick = 同一游戏刻

后续每帧绘制两个视觉条目
        |
        +--> 主手条目.ResultId --> 主手 sourceVerb --> 原版 Recoil（后坐力）
        |
        +--> 副手条目.ResultId --> 副手 sourceVerb --> 原版 Recoil（后坐力）
```

复合宿主仍负责统一攻击编排；来源正式 `Verb` 只保存原版本来就有的“最近开火时刻”。它不重新执行攻击，也不接管投射物。

## 六、详细设计

### 6.1 删除可配置瞄准镜像

删除：

- `ExpressionVisualSouthNorthPoseConfig.AimMirror`（南北姿态瞄准镜像开关）；
- `ExpressionVisualEastWestPoseConfig.AimMirror`（东西姿态瞄准镜像开关）；
- 诊断快照中只用于显示上述配置值的 `SouthNorthAimMirror`（南北配置镜像）；
- 诊断快照中只用于显示上述配置值的 `EastWestAimMirror`（东西配置镜像）；
- DevHarness（开发测试模组）诊断窗口中对应的两行配置显示。

保留：

- `ResolvedVisualPose.AimMirror`（已解析姿态实际发生瞄准镜像）；
- 常驻视觉诊断中的实际 `AimMirror`（瞄准镜像）结果；
- `VisualPoseResolver`（视觉姿态解析器）内部按原版角度分区得出的镜像状态。

删除的是“作者能否关闭原版镜像”的假配置，不是删除原版镜像本身。

### 6.2 在真实射击动作上记录来源侧

改动落点是 `BdpVerb_Shoot.TryEmitPlan`（BDP 射击动作发射计划）：

1. 保持现有目标、地图、射线等前置校验。
2. 先确认最终 `projectileDef`（投射物定义）存在。
3. 与原版相同，在真正进入发射动作时记录当前游戏刻。
4. 当前执行宿主继续更新自身 `lastShotTick`。
5. 使用 `plan.ResultId`（计划来源结果标识）通过现有 `VerbHostSurfaceAccess.TryGetByResultId`（按结果标识读取攻击宿主）找到来源绑定。
6. 若来源的 `RangedVerb`（远程攻击动作）是 `BdpVerb_Shoot`，调用一个仅供 BDP 内部使用的成员方法，把同一游戏刻写入它继承自原版的 `lastShotTick`。

来源绑定不存在或类型不匹配时，安全跳过来源同步，不抛异常、不制造常态日志；当前宿主的原版时间仍正常更新。

单侧发射时，来源 `Verb` 可能就是当前宿主本身，重复写入同一个时间值没有副作用。

### 6.3 双武器逐条目调用原版后坐力

在双武器 `DrawResidentEntries`（绘制常驻条目）路径中，每个 `VisualResidentEntry`（视觉常驻条目）独立处理：

1. 根据 `entry.ResultId`（条目结果标识）找到该来源的正式 `RangedVerb`。
2. 调用原版公开方法：

   `EquipmentUtility.Recoil(equipment.def, sourceVerb, out drawOffset, out angleOffset, sample.AimAngle)`

3. 将返回的位置偏移和角度偏移加到该条目的主贴图姿态。
4. 对该条目的全部附加层姿态应用同一组偏移，保证整件武器一起摆动。
5. 不修改 `ResolvedMuzzleAnchor`（已解析枪口锚点）。

如果找不到来源 `Verb`，后坐力偏移视为零，仍正常绘制武器。

### 6.4 为什么枪口与投射物不跟随后坐力

原版后坐力是装备绘制阶段的临时视觉偏移。投射物已经按攻击逻辑确定发射位置，原版不会因为武器贴图在某一帧后移而重新移动投射物。

因此，BDP 也只修改：

- 主武器贴图绘制位置与角度；
- 同一武器附加层绘制位置与角度。

不修改：

- 枪口锚点；
- 发射计划；
- 投射物出生点；
- 弹道数据。

## 七、状态、存档与生命周期

不新增状态容器。

来源正式 `Verb` 已由 `TriggerBodyVerbHostManager`（触发器攻击宿主管理器）持有并参与原版 `Verb` 序列化；`lastShotTick` 也是原版 `Verb` 已有字段。因此本方案：

- 不增加 BDP 存档字段；
- 不需要自定义读档迁移；
- 来源绑定切换时继续依赖现有 `Reset`（重置）清除旧身份状态；
- 不会把旧芯片最后一次开火时间泄漏给新绑定的芯片。

## 八、预期行为矩阵

| 场景 | 主手视觉 | 副手视觉 |
|---|---|---|
| 只有主手成功发射 | 原版后坐力 | 不动 |
| 只有副手成功发射 | 不动 | 原版后坐力 |
| 两侧同一游戏刻成功发射 | 原版后坐力 | 原版后坐力 |
| 两侧交替发射 | 按各自开火时刻摆动 | 按各自开火时刻摆动 |
| 某侧计划被校验拒绝 | 不记录该侧开火 | 不记录该侧开火 |
| 某侧一刻内多发 | 维持原版单一最近开火时刻语义 | 维持原版单一最近开火时刻语义 |

两侧若在同一游戏刻同时发射，原版确定性计算可能让两把武器得到相同方向的摆动。本设计保留这个原版表现，不人为增加随机差异。

## 九、验证范围

### 9.1 自动验证

1. 新增一个最小烟雾测试，确认两个作者配置类不再暴露 `AimMirror` 字段。
2. 确认运行时仍保留原版角度分区和实际 `AimMirror` 诊断。
3. 确认 `TryEmitPlan` 在成功发射边界同步 `plan.ResultId` 对应来源 `Verb` 的最近开火时刻。
4. 确认双武器绘制逐条目调用原版 `EquipmentUtility.Recoil`。
5. 确认后坐力只施加到主贴图和附加层，不写入枪口锚点。
6. 运行相关既有视觉、正式宿主、双武器协议烟雾测试和主项目编译。

### 9.2 游戏内验证

使用 DevHarness（开发测试模组）做以下实际观察：

1. 主手单独开火；
2. 副手单独开火；
3. 主副手交替开火；
4. 主副手同刻齐射；
5. 一侧因射线或目标条件失败、另一侧成功；
6. 连发武器连续射击；
7. 四个朝向及跨镜像角度瞄准；
8. 存档、读档后再次射击。

若只能在游戏内复现来源错配，再增加可插拔、易删除的临时诊断日志；默认不向正式路径加入常态日志。

## 十、设计结论

BDP 只补上原版单装备入口无法表达“双视觉条目、双来源 `Verb`”的适配缺口：

- 瞄准镜像：固定遵循原版，不提供特别修改。
- 后坐力算法：直接调用原版，不复制算法。
- 后坐力归属：在真实射击动作发生时，按计划已有的来源标识更新对应原版 `Verb` 状态。
- 绘制结果：谁开枪谁抖；两边都开枪就两边都抖。

这是满足双武器需求所需的最小介入。
