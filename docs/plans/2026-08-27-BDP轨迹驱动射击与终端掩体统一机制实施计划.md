# BDP 轨迹驱动射击与终端掩体统一机制 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将 BDP 远程弹道的掩体、硬阻挡、首发命中分支、路线续飞和视觉路径统一到同一份轨迹事实中，优先修复毒蛇但不写入毒蛇专属基础逻辑。

**Architecture:** 发射前生成轨迹快照；掩体始终依据最后一段路径起点调用原版 `CoverUtility`；整条路径继续执行物理障碍检查；发射时冻结 `ProjectileLaunchDisposition`。正常命中沿名义路线，偏射使用冻结偏移后的安全路线，掩体拦截和强制未命中保留原版终止语义。普通直射没有锚点时，最后一段起点自然等于发射位置。

**Tech Stack:** C# 7.3、.NET Framework 4.8、RimWorld 1.6 `Assembly-CSharp`、Harmony、Windows PowerShell 静态烟测、现有 BDP Core/Content/Development 工程。

---

## 执行约束

- 直接在当前 `main` 工作树执行，不创建新分支或 worktree；这是 BDP 项目规则对通用流程的明确覆盖。
- `Core.dll` 只增加中性轨迹与发射解析设施；毒蛇名称和具体配置只存在于 Content/XML。
- 不全局 Harmony 修改原版 `CoverUtility`，不复制完整 `ShotReport` 公式，不在每个锚点重复掷掩体概率。
- 每一步先写或扩展静态烟测，再做最小实现；每个稳定阶段单独提交。
- 任何需要新增玩家可见文案的情况先放入语言包；本计划默认不新增文案。
- `wild_miss` 的蛇形偏移如果无法通过现有安全检查，必须回退到原版偏射直线，不能为了视觉强行穿过障碍物。
