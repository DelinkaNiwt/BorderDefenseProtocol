# 追踪弹拦截残差设计

## 目标

修正追踪弹把“弹体当前方向偏差”误判为“目标已经逃逸”的问题。

期望行为是：追踪模块只根据追踪控制器面对的运动学误差调整飞行状态，不识别“静止目标场景”或“移动 Pawn 场景”，也不在命中结果层强行改判。初始射击方向即使因原版射击误差、故意脱靶或其它模块而偏离，只要目标的预期位置没有失效，追踪弹仍应自然收束到目标；目标自身的运动使预期位置持续失效时，有限追踪强度才允许产生擦边或脱靶。

## 根因

当前 `HomingModule.IsTargetLost` 直接使用弹体到目标的当前夹角，以及相邻采样的距离增长，作为目标丢失依据。这样把两个不同来源的误差混在了一起：

```text
弹体初始方向错误  -> 当前夹角很大
目标运动导致预测失效 -> 当前目标位置偏离预期拦截点
```

前者是追踪控制器本来应该纠正的导航误差，后者才是追踪能力可能无法继续收束的运动学误差。仅凭当前夹角无法区分两者，因此静止目标也可能过早进入重锁或飞离流程。

## 方案

追踪状态记录上一段追踪路径实际使用的“预期目标位置” `ExpectedTargetPosition`。它不是目标移动标志，也不针对 Pawn 做特殊处理，而是追踪控制器自身的通用控制量。

每次到达处理时：

1. 解析目标当前位置。
2. 用当前位置与上一段追踪路径预期位置计算目标预测残差 `targetPredictionResidual`。
3. 只有残差达到已有容差后，当前夹角/距离增长条件才有资格触发目标丢失；残差不足时，当前方向偏差仍属于可纠正的弹体导航误差。
4. 生成下一段路径时，把本段路径使用的预测目标点写回状态；终端收束段使用当前目标位置，重锁段使用重锁预测点，飞离段清除该预期点。

状态关系如下：

```text
上一段路径的预期点 ──┐
                     ├─> 目标预测残差 ──> 是否允许进入丢失/重锁/飞离
目标当前解析位置 ────┘

弹体当前方向 ──> 下一段曲线切线与转向限制（保留原有逻辑）
```

## 为什么能得到需要的结果

- 静止目标：实际位置持续接近上一段预期点，残差不会因为弹体初始射偏而变大；追踪继续使用有限转向能力收束，最终交给原版命中流程判断。
- 移动目标：实际位置会逐步偏离上一段预测点。若偏离超过追踪控制器能处理的范围，已有追踪强度、预测提前量、转向限制和重锁次数自然决定擦边或脱靶。
- 非 Pawn 目标：不需要添加特殊例外；是否能追上只由目标位置变化和追踪运动学结果决定。
- 命中判定：不修改 `HitStage`、命中窗口或原版碰撞规则，不把静止目标直接改成必中。

## 边界与兼容性

- 不新增“目标是否移动”“是否 Pawn”等业务分支，避免把结果要求倒灌成场景判断。
- 初次没有历史预期点的旧存档弹体，首个采样按无残差处理；生成下一段路径后建立正常状态。
- 仍保留目标失效、不可解析、真正无法继续追踪等现有退出条件。
- 现有路径曲线的段间切线连续逻辑不改，避免把本次命中语义修正扩大成视觉轨迹重构。
- 使用现有 `LossDistanceGrowthTolerance` 作为最小有意义残差容差的基础，不新增 Def 配置；如果实测证明需要单独调参，再另行提出配置需求。

## 验证重点

必须同时验证：初始射偏的静止目标继续收束、运动目标仍可在有限追踪强度下擦边、原版命中/墙体/高角模块不受影响，并且代码中没有新增 Pawn/静止目标结果分支。
