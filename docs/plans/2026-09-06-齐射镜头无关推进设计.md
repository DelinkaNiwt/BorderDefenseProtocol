# BDP 齐射镜头无关推进设计

## 1. 当前事实

- 当前 BDP 的齐射在 `BdpVerb_Shoot.TryCastShot()` 的同一个 `SimultaneousStep（同窗发射）` 窗口内循环消费多个 `ProjectileInitPlan（投射物初始化计划）`，各发射调用使用同一个游戏 `Tick（游戏刻）`。
- BDP 的 `BdpProjectile` 仍继承原版 `Projectile（投射物）`，当前没有覆盖 `UpdateRateTicks（更新间隔）`。
- RimWorld 1.6 原版 `Projectile.UpdateRateTicks` 会在投射物位于镜头内时返回 1，在镜头外时返回 15；`Thing.DoTick()` 按这个值批量调用 `TickInterval（间隔推进）`，并使用投射物自身哈希相位安排批次。
- BDP 的 `BdpProjectile.TickInterval()` 包装原版投射物推进，同时发布拖尾飞行样本。因此镜头可见性会影响位置推进、碰撞检查、命中时刻和拖尾样本，而不只是影响绘制。

## 2. 目标与边界

目标是让 BDP 正式计划投射物的飞行推进不再依赖当前镜头，使同一齐射批次保持真实的同刻发射和一致的逐 tick 推进。

本次不修改齐射编排、目标判定、路径规划、命中伤害、拖尾绘制裁剪或原版投射物碰撞算法；不使用 `drawOffscreen（屏幕外绘制）` 伪修复，也不新增独立的批次模拟器。

## 3. 方案

在 `BdpProjectile` 中覆盖 `UpdateRateTicks`：

- 已绑定 `launchPlan（发射计划）` 的 BDP 投射物返回 1；
- 未绑定 BDP 计划的异常/原版兼容生成路径继续返回 `base.UpdateRateTicks`。

这样只改变 BDP 正式攻击投射物的更新频率，不改变它们的速度、路径和命中规则。由于 BDP 的 `Tick()` 本来就会每个游戏 tick 执行，新增成本主要是原版每 tick 的位置、穿越段碰撞与到达检查。

## 4. 预期时序

```text
TryCastShot()
  └─ 同一发射窗口内生成全部计划
       └─ 每个 BdpProjectile 绑定 launchPlan
            └─ UpdateRateTicks = 1（与镜头无关）
                 ├─ 每 tick 执行 BdpProjectile.Tick()
                 └─ 每 tick 执行 BdpProjectile.TickInterval(1)
                      ├─ 原版位置/碰撞推进
                      └─ BDP 拖尾真实飞行样本
```

## 5. 验证

- 新增静态回归烟测，锁定 `BdpProjectile` 对已绑定计划返回逐 tick 更新，并保留未绑定计划的原版回退。
- 先在当前实现上运行烟测并确认失败，再加入最小代码改动后确认通过。
- 运行 BDP Core/Content Release 构建、投射物与远程攻击相关烟测、Core 隔离检查和 Development 边界检查。
- 进游戏验证齐射在镜头覆盖全程、镜头移出飞行路线、相机移动缩放、路径弹、追踪弹和阻挡碰撞下的发射/推进/命中时序；并观察大量投射物时的性能。
