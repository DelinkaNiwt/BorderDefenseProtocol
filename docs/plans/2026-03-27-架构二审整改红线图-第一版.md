# 架构二审整改红线图（第一版）

## 目的

这份文档只做一件事：

- 给本轮架构整改提供不可越线的红线定义

它不是实现计划，
也不是业务需求补充。

它只负责回答：

- 谁可以拥有真值
- 谁只能生产结果
- 谁只能做桥接
- 哪些退化路径本轮绝对禁止

## 一、对象分层红线

### 1. 真值 owner

本轮唯一允许持有核心业务真值的对象只有三类：

- `CompTrion`
- `CombatBodyState`
- `CompTriggerBody`

红线：

- 不得新增第四 owner
- 不得把派生结果缓存重新升级成事实来源
- 不得让 patch、UI、Verb 宿主、compat 层反向持有这些真值

### 2. 正式结果层

正式结果层当前指：

- `Expressions` 产出的正式表达结果
- 攻击执行过程中正式请求、计划、上下文对象

红线：

- 结果层只能由 owner 输入推出
- 结果层可以被重算，但不能长成拥有独立生命周期的事实层
- 结果层不得持有 host runtime、UI runtime、compat runtime

### 3. 投影与桥接层

投影与桥接层包括：

- `VerbHosting`
- 各类 gizmo / UI provider
- Harmony patch 入口桥
- 原版宿主适配

红线：

- 只能消费正式结果
- 只能把正式结果映射到外部表面
- 不得为了“方便”回写核心真值
- 不得为了“兼容”在内部补造事实

## 二、模块级红线

### 1. `Expressions`

允许：

- 收集正式输入
- 生成正式表达结果
- 提供正式结果读取
- 提供显式重算入口

禁止：

- 持有 host 生命周期
- 主动维护 host sync 总线
- 兼任 UI/compat/attack 总协调器
- 用 `Surface` 包揽外围系统便利调用

### 2. `Trigger`

允许：

- 槽位真值
- 装载真值
- 局部激活与禁用真值
- 合法的 Trigger 自身切换过程

禁止：

- 兼任跨核心协调器
- 在 Tick 中顺手刷新表达、host、UI
- 承接越来越多外围接线细节
- 再次长回旧版巨型 `CompTriggerBody`

### 3. `VerbHosting`

允许：

- 将正式表达结果投影到原版宿主
- 保存最少量可由正式结果唯一推出的派生数据

禁止：

- 拥有独立业务真值
- 拥有独立时钟
- 拥有独立自愈 refresh 体系
- 让系统依赖“先 sync host 才正确”

### 4. `AttackExecution`

允许：

- 接收正式攻击意图
- 生成正式执行请求与计划
- 执行近战/远程正式主链
- 下传统一语义上下文

禁止：

- 把 patch 内分支当成核心逻辑
- 让 targeting 长成兼容垃圾桶
- 在 patch 层临时拼接 damage/伤口/爆炸来源真义

### 5. Patch 与 Compat

允许：

- 入口桥接
- 原版调用转正式入口
- 必要的最薄兼容层

禁止：

- 回写核心状态
- 决定业务规则
- 兜底修复 core 逻辑
- 为 patch 再写 patch

### 6. UI / Gizmo / 外部扩展口

允许：

- 读取正式结果快照
- 发出明确命令

禁止：

- 读取即触发同步
- 读取即触发重建
- 读取即触发重算
- 把空 registry、空 provider 提前塞进主路径

## 三、抽象层红线

允许：

- 真实多实现接口
- 明确边界隔离接口
- 真实测试替身接口

禁止：

- `单实现接口 + 默认实现 + SurfaceAccess` 三件套泛滥
- 为了看起来分层而制造静态门面
- 主链必须跨多层空壳才能追到真值逻辑

## 四、性能与诊断红线

允许：

- 显式、可解释的重算
- 显式请求下的诊断生成

禁止：

- 一次业务动作触发多轮“顺手重算”
- UI 打开诱发热路径重建
- 调试诊断默认压进热路径

## 五、本轮整改完成标准

只有满足以下条件，才算本轮整改完成：

- 三核心 owner 稳定，外围无法越权持有真值
- `Expressions`、`Trigger`、`VerbHosting`、`AttackExecution` 各自职责可以一句话说清
- Patch、UI、compat、投影层都只能消费结果或桥接
- 游戏内关键主链可实测通过
- 临时 smoke 已删除

达不到这些条件，
即使代码表面更整齐，
也不能算本轮整改完成。
