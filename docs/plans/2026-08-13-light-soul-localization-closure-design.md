# 光魂本地化闭环设计

## 问题与根因

光魂定义保留英文回退文本，并曾依赖 `ChipActionPresetDef` 的 `DefInjected`（定义注入语言包）覆盖嵌套字段。实测中该覆盖没有作用于动作名称、说明和 `Tool`（攻击工具）名称。后续局部增加的 `labelKey` 与 `DisplayLabelKey` 只修复了制造名称和重刃表达名称，导致同一攻击工具英文继续进入攻击按钮与伤口来源。

原版伤口界面会使用 `SourceToolLabel` 模板拼接表达来源名与 `Tool.label`。BDP 的伤害语义桥接又按原版字段传递 `dinfo.Tool.label`，因此正确修复点是运行时 `Tool` 建立之前，而不是健康界面。

## 方案

1. `ChipActionPresetDef` 增加可选 `descriptionKey`，提供统一的 `ResolvedDescription`。制造信息窗对动作预设读取解析后的说明，其他 `Def` 保持原版说明行为。
2. `ChipExpressionEntryConfig` 增加按 `tools` 顺序对应的 `ToolLabelKeys`。表达契约解释器在复制作者声明的 `Tool` 时解析语言键，保留英文源文本作为无对应键时的回退。
3. 光魂四个表达条目全部声明 `DisplayLabelKey`，重刃两把攻击工具声明两个稳定语言键。
4. 不改写旧伤口。旧伤口中的来源名称已经序列化，批量迁移会扩大修改范围；修复以新攻击产生的按钮、日志和伤口来源为验收对象。

## 边界

- Core.dll（核心程序集）只增加中性的可选语言键设施，不写入光魂业务名称。
- Content.dll（内容程序集）承载动作预设说明解析与光魂具体语言键。
- 不修补原版健康界面，也不对日志、按钮分别添加显示补丁。
- 不处理截图中的原版 `Dev tool...`（开发工具）文字。

## 验证

- 静态回归测试确认说明键、四个表达键、两个工具键及复制链完整存在。
- Core 与 Content 解决方案重新编译。
- 运行 BDP 测试脚本；游戏内以新造成伤口确认显示为“光魂重刃钝击”或“光魂重刃切割”。
