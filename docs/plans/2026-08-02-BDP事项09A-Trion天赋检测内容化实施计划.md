# BDP 事项09A：Trion 天赋检测内容化实施计划

## 一、实施目标

在不改变游戏规则和检测流程的前提下，将 Trion 天赋检测从 `BDP.Core.dll` 物理迁入 `BDP.Content.dll`，并把“检测完成”从 Core 的 Trion 资源宿主拆成 Content 侧 Pawn 组件。

## 二、实施顺序

1. 新增事项09A边界测试，先锁定 Core 不再拥有检测专属状态、检测类和业务 Def，Content 拥有检测状态宿主与检测类。
2. 运行新测试确认当前代码按预期失败。
3. 在 Content 新增 `CompTrionTalentAssessment` 和人形 Pawn 注入器；将角色面板显示从 Core 移到该组件。
4. 从 Core 删除检测完成字段、接口成员、服务转发和 Core 侧角色面板分支。
5. 将原始容量/释放力生成器和统一释放力工具移到 Core 中性目录；将容量潜质档位解析移到 Content。
6. 迁移检测仪、便携检测器、资格、服务、结果、浮动菜单、Job 和 WorkGiver 到 Content，统一命名空间并更新 Def 类型字符串。
7. 将检测相关 Def 移到 `1.6/Content/Defs`；原始分布 Def 留在 `1.6/Defs/Trion`。
8. 更新事项相关 PowerShell 冒烟测试路径和命名空间断言；不改与本项无关的测试。
9. 构建 Core、Content、DevHarness；运行 Core 单向依赖门禁、XML 解析、Trion 专项和全量回归。
10. 更新总计划、事项09盘点、工作日志并独立提交。

## 三、允许修改范围

- `Source/BDP/Core/Trion`、`Source/BDP/Core/Genes`、`Source/BDP/Core/Requirements` 中与本次状态拆分直接相关的引用。
- `Source/BDP.Content/Trion/Talent` 新增迁移内容。
- `1.6/Defs/Trion` 与 `1.6/Content/Defs/Trion`、`Buildings/Trion`、`Things/Trion`、`Jobs/Trion`、`WorkGivers/Trion`。
- 事项09A直接验证的 `Source/BDP.Tests` 脚本。
- 事项09计划和工作日志。

## 四、明确不修改范围

- 不处理 `Core/Assembly`、`CombatBody/Escape`、战斗日志和伤口视觉。
- 不改 Trion 数值、分布、检测耗时、资格条件或玩家文本语义。
- 不改候选测试模组的具体芯片。
- 不改 About、LoadFolders 或游戏加载控制。
- 不覆盖用户现有未提交源码、Def 或构建产物改动。

## 五、验收条件

- Core 源码和 Core Def 不再出现检测仪、检测 Job、检测 WorkGiver、检测完成接口或检测完成存档字段。
- Content 源码拥有检测状态组件、检测仪、便携检测器、检测 Job、WorkGiver 和结果档位。
- 人形 Pawn 仍自动拥有 Trion 宿主和 Content 检测状态宿主。
- 检测完成后角色面板仍显示容量潜质与释放力；植入腺体后两项仍保留。
- 检测业务仍能通过正式 Trion 读取面读取容量潜质和释放力，并在 Content 组件中提交完成状态。
- Core 构建 0 警告 0 错误，Core 不引用 Content；Content 构建和全量回归无新增失败。
