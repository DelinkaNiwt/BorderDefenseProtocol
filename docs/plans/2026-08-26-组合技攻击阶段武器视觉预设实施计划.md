# 组合技攻击阶段武器视觉预设 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 把组合技接入现有武器动作阶段视觉链，并让 Trion 立方体构型在组合技攻击阶段复用 `BDP_Visual_TrionCube`。

**Architecture:** 保留现有 `WeaponVisualStageResolver`、`StageVisuals` 和主侧/副侧/双持绘制路径。新增只针对组合技攻击阶段的视觉预设字段，沿现有表达契约和武装构型覆盖链传播；视觉投影为每个组合结果生成一个阶段绑定，绘制时仅在当前宿主是该组合结果且阶段非 `Idle` 时消费绑定，待命继续使用现有双武器视觉。

**Tech Stack:** C#、RimWorld Def/XML、PowerShell 冒烟测试、Release `dotnet msbuild`。

### Task 3: 建立组合技攻击视觉绑定

**Files:**
- Create: `Source/BDP/Core/Expressions/Model/ComboAttackVisualBinding.cs`
- Modify: `Source/BDP/Core/Expressions/Model/VisualExpressionProjection.cs`
- Modify: `Source/BDP/Core/Expressions/Projection/DefaultVisualProjectionBuilder.cs`
- Modify: `Source/BDP/Core/Expressions/Pipeline/ComboFormalExpressionResultFactory.cs`

**Step 1: Implement binding model**

绑定携带 `ComboResultId`、`VisualPresetDefName` 和 `OwnerSourceResultId`，不保存视觉状态，不改变 `RelationKind`。

**Step 2: Build bindings from formal references**

从 `ExpressionSnapshot.Results` 找到有组合技攻击视觉字段的 `CompositeExpressionKind.Combo` 结果，再从 `CompositeReferences` 找到主侧来源结果作为绘制归属。缺失结果、引用或来源时跳过绑定。

**Step 3: Run focused test**

确认绑定字段存在，且组合技攻击字段没有被加入 `HasDeclaredComboVisualRelation` 的待命关系判断。

### Task 4: 接入阶段绘制选择

**Files:**
- Modify: `Source/BDP/Patches/Patch_PawnRenderUtility_DrawEquipmentAiming_BdpVisual.cs`

**Step 1: Resolve active combo binding**

用现有 `WeaponVisualStageSnapshot.HostResultId` 匹配 `ComboResultId`；仅 `Warmup`、`Firing`、`Cooldown` 消费绑定。

**Step 2: Draw one combo-stage visual owner**

命中绑定时只让 `OwnerSourceResultId` 对应条目进入绘制；以组合结果身份构造临时绘制条目并读取指定视觉预设。非归属来源跳过，避免同一个组合阶段预设重复绘制。

**Step 3: Preserve fallback behavior**

预设无法解析、阶段为空闲、宿主不是组合结果或会话校验失败时继续使用原有绘制路径。

**Step 4: Run focused test**

确认绘制入口同时保留原有阶段解析、单武器路径、待命预设选择和组合阶段绑定选择。
