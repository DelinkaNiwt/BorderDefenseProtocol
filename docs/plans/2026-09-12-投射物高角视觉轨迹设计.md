# 投射物高角视觉轨迹设计

日期：2026-09-12

## 结论

在 BDP.Core 中增加一个可选的投射物高角视觉扩展与纯计算工具。只有投射物 Def（定义）显式挂载该扩展时，BDP 投射物才在绘制时叠加高角高度；没有扩展的投射物继续使用现有低角绘制路径。

第一版只改变绘制位置、投射物朝向与视觉样本的空间位置，不改变 `ExactPosition（精确位置）`、飞行时长、碰撞扫描、命中判定或续段逻辑。这样可以先复刻 Eccentric Tech 的连续高角表现，同时把真实高角移动留到后续明确接入。

## 配置契约

建议类名：`BDP.Core.Projectiles.Visual.ProjectileVisualArcExtension`。

它挂在投射物 `ThingDef` 的 `modExtensions` 中：

```xml
<modExtensions>
  <li Class="BDP.Core.Projectiles.Visual.ProjectileVisualArcExtension">
    <arcHeight>12</arcHeight>
    <startHeight>0</startHeight>
    <endHeight>0</endHeight>
    <positionCurve>EaseInCubic</positionCurve>
    <heightCurve>Linear</heightCurve>
    <arcCurve>Sine</arcCurve>
  </li>
</modExtensions>
```

字段含义：

- `arcHeight`：抛物线额外最高高度。
- `startHeight`：飞行开始时的基础绘制高度。
- `endHeight`：飞行结束时的基础绘制高度。
- `positionCurve`：当前 BDP 路径进度的水平缓动曲线。
- `heightCurve`：基础高度从起点到终点的曲线。
- `arcCurve`：额外抛物高度曲线。

第一版内置 `Linear`、`Sine`、`EaseInQuad`、`EaseOutQuad`、`EaseInOutQuad`、`EaseInCubic`、`EaseOutCubic`。曲线名不识别时回退为 `Linear`，避免错误配置破坏投射物主线。

`Sine` 的定义为 `sin(progress * PI)`，因此起点和终点高度为零，中点达到最高点。复刻 Eccentric Tech M36 连续段时使用 `arcHeight=12`、`positionCurve=EaseInCubic`、`arcCurve=Sine`；由于不包含冷发射阶段，`startHeight` 应保持 0。

## 运行时边界

计算工具使用现有 `ProjectileFlightPathSnapshot`（投射物路径快照）作为水平路径输入，不修改 `ProjectileFlightPathUtility` 的现有取样语义。

给定进度 `p` 后：

```text
水平进度 = positionCurve(p)
基础高度 = Lerp(startHeight, endHeight, heightCurve(p))
抛物高度 = arcHeight * arcCurve(p)
绘制高度 = 基础高度 + 抛物高度
```

绘制坐标使用 RimWorld 的地图平面约定：水平路径保持 `y=0`，原版 `def.Altitude`（投射物绘制层高度）仍放在 `y`，高角视觉高度叠加到 `z`。

`BdpProjectile.DrawAt` 只在当前投射物存在有效高角扩展且配置产生非零效果时走高角绘制分支；否则直接调用原版绘制。高角分支复用原版图形类、材质、旋转自转与组件后绘制，只替换投射物网格位置，并补充对应的地面阴影。

现有视觉附加件收到的飞行样本，在启用高角配置时也消费同一份视觉高度取样，使 BDP 现有拖尾能够跟随高角轨迹；未启用时样本数据保持原样。

## 非目标

- 不引入 Eccentric Tech 的冷发射、巡航、末端等多阶段状态机。
- 不修改 BDP 现有低角路径、飞行时间、碰撞或命中判定。
- 不把高角视觉高度写入存档运行态；读档后根据 Def 配置与当前路径重新取样。
- 不在 Core 中实现具体武器或导弹内容。
- 第一版不让高角配置自动改变投射物的物理移动；后续如需真实高角移动，必须由明确的飞行模式接入同一工具。
