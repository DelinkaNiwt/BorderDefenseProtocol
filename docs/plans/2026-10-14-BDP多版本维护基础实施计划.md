# BDP 多版本维护基础实施计划

> 用户于 2026-10-14 确认执行：建立 1.7 目录、共享源码、分版本构建和加载，并写入技能及工作规则。补充要求：目标版本不明确时必须询问，禁止猜测；相同资源在 Common 公共目录共用，不能复制两份。用户确认 1.6 游戏安装位于 C:/NiwtGames/RimWorld-1.6。

**目标：** 在同一项目、同一分支中维护 1.6 与 1.7，避免版本适配覆盖其他版本。

**设计：** 源码保持共享；将相同的定义、贴图、音效和开发资源迁入 Common（公共目录），版本目录只存独立程序集和实际差异。版本参数必须显式提供；游戏及 Harmony 引用、编译中间文件和输出均分版本。1.6 保留旧式 .NET Framework 4.8 构建，1.7 条件导入本机 .NET 10 SDK（开发工具包）。不修改业务逻辑，不部署到正在运行的游戏。

## 1. 配置版本隔离

- 新建 `Source/Build/Bdp.Version.props` 与 `Bdp.Version.targets`，集中版本参数、引用选择、构建隔离和必要的错误检查。
- 在四个现有 `.csproj` 工程中导入配置：`BDP`、`BDP.Content`、`BDP.Compatibility`、`BDP.Development`；保留程序集名称和依赖方向。
- 使用 `RimWorldVersion=1.6` 或 `1.7`；缺失、非法或缺少对应引用时停止，不能回退到另一游戏版本。
- 本机引用路径放入不入库的 `Bdp.Local.props`；提供可维护的说明与示例。核实用户提供的 1.6 独立目录，不能从当前 Steam 安装借用另一版本。
- Core（核心程序集）隔离检查同时检查公共和目标版本的 Def（定义）目录；正式发布检查明确接收目标版本并检查公共开发资源。

## 2. 建立版本资源和加载入口

- 逐文件核实资源内容后，将共同 Defs、Content、Development 资源、Sounds、Textures 迁入 Common；删除经过哈希核实的同内容副本，不迁移版本程序集。共享源码和根语言文件不复制。
- 在 `LoadFolders.xml` 中分别声明两版本的公共及本版本加载顺序，所有列出的目录必须实际存在。
- 补充 1.7 程序集目录的忽略规则；空程序集目录仅留可追踪的标记，不能伪装成可运行发布版。
- 版本专属文案进入版本语言目录；共同文案继续共享。

## 3. 固化维护原则

- 修改工作区 `AGENTS.md`、全局 `C:/Users/Niwt/.codex/AGENTS.md` 和 `C:/Users/Niwt/.agents/skills/rimworld-development/SKILL.md`。
- 新任务版本不明确时必须先提醒并询问；声明维护多个版本不能替代对本次目标版本的确认。持续任务已有明确确认时可沿用。
- 异常按证据区分实现错误、版本差异、待确认；仅 1.7 报错不自动等于版本差异。实现错误修正所有受影响维护版本，版本适配仅作用对应版本。
- “重构默认不做向后兼容”不免除正在维护的游戏版本支持义务。
- 外部规则原文先备份，保留回退入口；技能只写通用方法，BDP 具体目录和版本约束写工作规则。

## 4. 验证与交付

- 比对公共资源的相对路径和文件哈希，确认原资源内容未改动且不再重复，两版本程序集分别编译。
- 分别检查两版本的加载列表、工程引用和输出/中间目录；验证缺失版本及错误引用会失败。
- 分别构建两个版本的四个工程，将发现的 API（接口）差异记录进兼容性排查，不在本任务顺手修复；没有游戏内实测时不声称业务兼容。
- 校验技能格式，检查三处规则含义一致。
- 写工作日志，提交本次项目改动；后续继续收集报错并统一修复。
