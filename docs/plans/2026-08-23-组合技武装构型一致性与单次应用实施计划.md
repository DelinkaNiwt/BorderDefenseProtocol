# 组合技武装构型一致性与单次应用 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让组合技只在第一、第二来源项对应芯片的实际来源变体一致时准入，并让组合级来源构型只对组合结果显式字段应用一次，不重复影响从第一、第二来源结果继承的字段。

**Architecture:** Core 继续只消费中性的 `SourceVariantKey`，不直接依赖 `ChipArmamentFormDef`。`ComboRuntimeIndex` 在匹配阶段执行第一、第二来源项的来源变体一致性检查；组合表达管线携带一致的来源变体键，并通过 Core 的中性变体修正扩展点让 Content 在解释组合结果条目前修正组合结果显式字段。来源动作仍先形成第一、第二来源结果，继承字段不再经过组合级修正。

**Tech Stack:** C#、RimWorld Def/XML、PowerShell 冒烟测试、MSBuild/dotnet build。

---

## 已确认规则

```text
第一、第二来源项均无构型             → 允许，组合结果无来源变体
第一、第二来源项使用同一构型         → 允许，组合结果使用共同来源变体
第一、第二来源项使用不同构型         → 拒绝
第一、第二来源项一方有构型、另一方无构型 → 拒绝
```

`SourceVariantKey` 的空白值统一按无来源变体处理；非空值按不区分大小写的稳定键比较。比较基于 ComboDef 声明的第一、第二来源项身份，不依赖当前 Main/Sub 槽位顺序。

**Step 1: 增加默认开启的契约字段**

```csharp
public bool RequireSameSourceVariant = true;
```

并在 `ToConfig()`、正式契约和契约解析器中逐层复制。XML 未声明时仍保持 `true`，因此第一、第二来源项均无构型或使用同一构型的组合正常；构型不同或一方缺失构型的组合按新规则拒绝。

**Step 2: 增加中性配对求值器**

在 `ComboSourceAdmissionEvaluator` 增加内部方法：

```csharp
internal static bool AreSourceVariantsCompatible(
    ComboSourceAdmissionSnapshot left,
    ComboSourceAdmissionSnapshot right)
```

实现要求：

1. `null` 快照按空快照处理。
2. `null`、空字符串和全空白统一归一化为无来源变体。
3. 非空键使用 `StringComparison.OrdinalIgnoreCase` 比较。
4. 不访问 `ChipArmamentFormDef`，只比较 `SourceVariantKey`。

**Step 3: 在正向/反向分配前执行配对检查**

修改 `ComboRuntimeIndex.MatchesAssignment`，增加 `requireSameSourceVariant` 参数，并在身份键和单侧准入通过后执行：

```csharp
!requireSameSourceVariant
    || ComboSourceAdmissionEvaluator.AreSourceVariantsCompatible(
    firstSourceSnapshot,
    secondSourceSnapshot)
```

正向和反向来源项身份分配都使用第一、第二来源项的实际芯片快照，因此 Main/Sub 交换不会改变构型一致性结果。

未通过时保持现有候选遍历逻辑，最终失败摘要使用稳定诊断键 `SourceVariantMismatch`；本轮不增加玩家界面硬编码文本。

## Task 4: 增加 Core 中性的组合条目变体修正扩展点

**Files:**
- Create: `模组工程/BorderDefenseProtocol/Source/BDP/Core/Expressions/External/IComboExpressionVariantModifierProvider.cs`

- Modify: `模组工程/BorderDefenseProtocol/Source/BDP/Core/Expressions/Pipeline/ComboFormalExpressionResultFactory.cs`

**Step 1: 定义中性提供器接口**

接口只表达“给定来源变体键，修正组合条目副本”，不暴露武装构型类型：

```csharp
public interface IComboExpressionVariantModifierProvider
{
    void Apply(
        IList<ComboExpressionEntryConfig> comboEntries,
        string sourceVariantKey);
}
```

注册表只保存一个正式提供器，重复注册覆盖旧实例；未注册时保持原组合行为。

**Step 2: 实现组合条目深复制**

`ComboExpressionEntryCloneService` 复制：

- `VerbPropsOverlay` 的所有字段；
- `Execution`、`Presentation`；
- `Tool`、`tools`、`Maneuver`；
- `RangedModules`、`ExposedData`、标签和条件列表；
- `VerbPropsResolve`、`ExecutionResolve`、`TrionResolve` 等解析声明。

不得修改 `ComboDefinitionReadResult` 缓存中的原始条目。

**Step 3: 在组合解释入口应用副本修正**

在 `CompositeExpressionResolver.BuildComboResults` 中：

1. 从实际来源材料读取 `mainMaterial.SourceVariantKey` 和 `subMaterial.SourceVariantKey`。
2. 仅在两者归一化后一致时生成 `commonSourceVariantKey`。
3. 克隆 ComboDef 条目列表。
4. 调用 `ComboExpressionVariantModifierRegistry` 修正克隆列表。
5. 将同一份修正后列表同时传给 `ChipExpressionContractInterpreter` 和后续 `ComboDefinitionContractResolver`。

这样 `VerbPropsOverlay` 的组合结果显式字段在解析前已完成构型修正，而第一、第二来源结果完全不被再次修改。

**Step 4: 携带组合结果的来源变体元数据**

在 `ComboFormalExpressionResolution` 增加 `SourceVariantKey`、`SourceVariantLabel` 输入；工厂写入 `FormalExpressionResult`。组合结果不从槽位推断变体，也不把不同来源变体拼接成新键。

## Task 5: 在 Content 实现武装构型对组合结果显式字段的单次修正

**Files:**
- Create: `模组工程/BorderDefenseProtocol/Source/BDP.Content/Assembly/ChipManufacturing/Resolution/ChipArmamentFormComboExpressionModifier.cs`

**Step 1: 实现 Content 提供器**

`ChipArmamentFormComboExpressionModifier` 实现 Core 的中性接口：

1. 用 `sourceVariantKey` 调用现有来源变体到构型的 Content 映射入口。
2. 构型缺失或覆盖块为空时直接返回。
3. 只处理 `PrimaryVerb`、`SecondaryVerb` 且为近战/远程的条目。
4. 只修改组合结果条目自身已显式声明的字段，不给组合结果凭空创建来源字段。

**Step 2: 复用现有构型覆盖语义**

在 `ChipArmamentFormExpressionService` 增加面向 `ComboExpressionEntryConfig` 的内部辅助方法：

- 组合结果的 `VerbPropsOverlay` 字段存在时，绝对值覆盖替换该字段；
- 组合结果的显式数值字段存在时，倍率修正作用于该显式值；
- 组合结果没有声明的继承字段保持未声明，交给第一、第二来源结果的解析回退；
- 组合结果已有 `Execution`、`Presentation`、`Tool`、`Maneuver`、`RangedModules` 时，按现有绝对覆盖和 `Append/Replace` 语义修正；
- 不读取、不修改 `MainSourceResult`、`SubSourceResult`。

不得复制一份新的武装构型字段语义；公共字段计算应尽量抽到现有服务的共享辅助方法。

**Step 3: 启动期注册**

在 `ContentBootstrap` 注册 `ChipArmamentFormComboExpressionModifier`。注册位置与现有内容提供器一致，Core 在未加载 Content 时仍能保持无提供器的原始行为。

**Step 4: 写构型传播测试**

冒烟测试至少覆盖：

```text
第一、第二来源项使用同一构型，组合结果 range = 30，构型 rangeMultiplier = 1.2 → 组合结果 range = 36
第一、第二来源项使用同一构型，组合结果 range = 30，构型绝对 range = 50       → 组合结果 range = 50
第一、第二来源项使用同一构型，组合结果未声明 range                           → 仍由来源结果解析，不追加构型
第一、第二来源项使用同一构型，组合结果显式 RangedModules                    → 按构型 Append/Replace 处理一次
第一、第二来源项使用同一构型，组合结果继承 FollowChipMain                    → 使用当前 Main 来源结果，不重复套构型
```

测试同时断言组合结果的原始 ComboDef 条目没有被永久改写，第二次构建结果不会继续累乘。
