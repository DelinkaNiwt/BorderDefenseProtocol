# BDP 芯片槽位区域字段规范化设计

日期：2026-07-30
状态：用户已确认，等待实施计划

## 一、要解决的问题

当前 `Loadout.SidePolicy（装载配置.侧别策略）`实际只回答一件事：

> 这枚芯片属于主副槽区，还是特殊槽区？

旧名称存在三个问题：

1. `Side（侧别）`容易被理解为主侧或副侧，但当前配置从不允许芯片分别声明主侧、或者副侧。
2. `Policy（策略）`显得过重；这里不是一套策略，只是一个必填的区域分类。
3. `HandsOnly（只进手区）`沿用了“手”的旧业务说法，没有直接对应玩家看到的主槽、副槽和特殊槽。

## 二、正式设计

### 2.1 配置结构

字段正式改为：

```xml
<Loadout>
  <SlotRegion>MainSub</SlotRegion>
</Loadout>
```

`SlotRegion（槽位区域）`是单选必填字段，只允许：

- `MainSub（主副槽区）`
- `Special（特殊槽区）`

主副槽区与特殊槽区永久互斥，同一枚芯片不能同时属于两区。

### 2.2 未填写状态

C#（C#语言）枚举在 XML（定义文件）没有填写时仍会自动得到第一个值。为可靠识别漏填，底层枚举保留：

- `Unspecified（未指定）`

它只用于校验，不是合法作者配置。合法芯片出现以下任一情况时，定义校验必须报错：

- 没有填写 `SlotRegion`
- 填写 `Unspecified`
- 填写无法识别的值

不得再把漏填静默解释为主副槽区。

### 2.3 代码命名

- 配置与契约字段：`SlotRegion`
- 枚举类型：`ChipSlotRegion（芯片槽位区域）`
- 枚举值：`Unspecified / MainSub / Special（未指定/主副槽区/特殊槽区）`
- 运行快照字段：跟随改为 `LoadoutSlotRegion（装载槽位区域）`

运行消费者只按区域判断主槽、副槽或特殊槽是否合法，不增加新的槽位系统。

## 三、迁移边界

本次不兼容迁移：

- 删除 `SidePolicy（侧别策略）`
- 删除 `ChipLoadoutSidePolicy（芯片装载侧别策略）`
- 删除 `HandsOnly / SpecialOnly（只进手区/只进特殊槽区）`
- 候选内容中所有合法芯片改为显式填写新字段和新值
- 故意缺少区域的非法定义样本继续缺失，用于验证校验错误

本次不修改：

- `IsDualWieldBinding（是否双持绑定）`，留给下一小项的 `SlotOccupancy（槽位占用方式）`
- `ExclusionTags（排斥标签）`
- `WarmupTicks / WinddownTicks（切入/切出时长）`
- 芯片表达、Trion（能量）、形态、攻击和具体业务参数
- 事项 07A、07B 以及触发器、触发体分类

## 四、运行与错误处理

定义读取顺序保持现况：

```text
XML 定义
  → 芯片配置
  → 芯片契约
  → 定义校验
  → 装载、启用与界面消费者
```

校验通过后，运行系统只会收到 `MainSub`或`Special`。缺失和非法值属于作者配置错误，不做运行时猜测或兼容回退。

## 五、验证要求

实施时至少验证：

1. 合法芯片必须显式填写 `SlotRegion`。
2. 漏填、`Unspecified`和未知值都会产生定义错误。
3. `MainSub`允许进入主槽和副槽，拒绝特殊槽。
4. `Special`只允许进入特殊槽，拒绝主槽和副槽。
5. 候选库现有合法芯片只发生字段和值的等义迁移，游戏行为不变。
6. 旧字段、旧枚举和旧值在正式源码、版本 XML 与字段清单中没有残留。
7. 三个程序集能够构建，`BDP.Core.dll（核心动态链接库）`继续不依赖其他本模组程序集。

## 六、方案取舍

曾比较以下命名：

- `SlotRegion（槽位区域）`：最短、最贴近 RimWorld（边缘世界）定义习惯，采用。
- `AllowedSlotRegion（允许的槽位区域）`：含义明确，但单选结构下 `Allowed（允许）`重复。
- `SlotArea（槽位区）`：可以表达含义，但与项目既有“区域”用语不如 `Region（区域）`统一。
