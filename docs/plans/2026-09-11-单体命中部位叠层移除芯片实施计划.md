# 单体命中部位叠层移除芯片实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在 BDP 中实现一种只对非爆炸投射物直接命中的 Pawn（人形单位）生效的部位标记机制：不造成伤害，按身体部位独立叠加 Hediff（健康状态），达到最大层数后通过原版机制移除该部位。

**Architecture:** 复用现有 `RangedDebuffModule`（远程减益模块）、`ExtraEffectPlan`（额外效果计划）和护盾绕过策略，扩展四项通用能力：可选命中部位上下文、Hediff 作用域、最大严重度阈值动作和可替换的部位选择策略。Core（核心基础设施）只增加中性的 `BodyPartRecord`（身体部位记录）传递字段；Content（正式内容程序集）负责部位解析、按作用域叠加 Hediff，以及通过阈值动作注册表执行具体后果。本需求的 `RemoveBodyPart`（移除身体部位）只是一个阈值动作，不在 `RangedDebuffModule` 中增加断肢专用分支。模块在有效 Pawn 的直接命中上才取消伤害，因此命中建筑或其他非 Pawn 目标不会被错误吞伤害。当前项目规则要求直接在现有工作区执行，不创建 worktree（工作树）。

**Tech Stack:** C# 7.3、.NET Framework 4.8、RimWorld 1.6 `Assembly-CSharp`、Harmony、XML Def、PowerShell 烟测、MSBuild。

---

## 当前工作边界

- 只处理 `DirectHitThing`（直接命中目标）。
- 只处理非爆炸投射物；带 `explosionRadius`（爆炸半径）的投射物直接跳过。
- 目标只允许 Pawn。
- 允许头部、核心等要害部位被移除，后续死亡和能力变化交给原版。
- 不新增投射物类，不新增全局伤害补丁，不处理爆炸逐目标链。
- 远程模块 Def 和 Hediff Def 纳入本次机制实现。
- 芯片的职业、槽位、费用、射程和最终弹道平衡尚未由需求指定；实施时先提供可挂载的正式模块和 Hediff，正式芯片功能预设只在宿主配置明确后加入，不猜测无关平衡数值。

### Task 5: 实现按作用域叠加 Hediff 和可注册阈值动作

**Files:**
- Modify: `Source/BDP.Content/RangedModules/Debuff/HediffExtraEffectExecutor.cs`
- Create: `Source/BDP.Content/RangedModules/Debuff/HediffThresholdActionRegistry.cs`

- Modify: `Source/BDP.Content/ContentBootstrap.cs`
- Test: `Source/BDP.Tests/BodyPartDisintegrationSmokeTests.ps1`

**Step 1: Preserve existing whole-Pawn behavior**

保留当前普通减益的全身逻辑；只有效果计划携带 `HitPart` 且 `PartTargetMode = ImpactPart` 时，进入部位作用域分支。

**Step 2: Add part-specific lookup and stacking**

部位分支按以下条件查找：

```text
hediff.def == configuredDef
hediff.Part == effectPlan.HitPart
```

没有对应状态时，用带 `BodyPartRecord` 的 `HediffMaker.MakeHediff` 创建并通过 `Pawn_HealthTracker.AddHediff` 添加；存在时只增加该部位状态的严重度。

当前每次有效命中增加 `0.2`，严重度上限为 `1`，五次有效命中达到阈值。部位模式不调用恢复组件的命中刷新逻辑，也不自动设置持续时间。

**Step 3: Dispatch the threshold action**

达到 HediffDef 最大严重度且 `MaximumSeverityAction` 不为 `None` 时：

1. 再次确认目标仍有该部位且部位尚未缺失；
2. 通过 `HediffThresholdActionRegistry` 按动作标识解析并执行动作；
3. 不在 `RangedDebuffModule` 或通用 Hediff 叠加代码中硬编码具体后果；
4. 无法解析的动作应记录可搜索的诊断信息并安全返回，不回退成其他动作。

**Step 4: Implement the reusable `RemoveBodyPart` action**

`RemoveBodyPartThresholdAction` 接收目标 Pawn、达到阈值的部位 Hediff、命中部位和效果计划：

1. 调用 `targetPawn.health.RemoveHediff(partHediff)`；
2. 调用 `targetPawn.health.AddHediff(HediffDefOf.MissingBodyPart, hitPart)`；
3. 不直接修改身体树，不手动处理死亡、服装或能力；
4. 允许头部、核心等要害部位沿用原版死亡处理。

在 `ContentBootstrap` 注册 `RemoveBodyPart` 动作。后续其他阈值后果只新增动作实现，不修改远程模块和通用 Hediff 叠加流程。

允许头部、核心等要害部位走同一条路径。重复命中已缺失部位时不得再次添加缺失状态。

## 芯片正式挂载的后续边界

本计划已覆盖可复用的正式远程模块和 Hediff 机制，但没有猜测芯片的职业、槽位、制造费用、攻击按钮、弹道和伤害平衡。若需要本次同时新增可制造芯片，需要在现有 `ChipFunctionDef`（芯片功能定义）中补充一个明确的宿主配置，再单独增加：

- 是否独立 Ability（能力）或作为远程增强；
