# BDP 事项08A固定芯片初始装载 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 把触发体玩家控制模式改成对称命名，并在Core加入可空、只于首次生成应用、失败整批回滚的固定芯片初始装载能力。

**Architecture:** `loadoutControlMode`只控制玩家装卸权限；`fixedLoadout`独立描述新触发体的出厂装载。固定条目先由Def配置校验，运行时在RimWorld原版`PostPostMake`中创建真实芯片并直接复用现有`TriggerLoadoutService`，不经过受玩家权限限制的命令口；存读档、特殊槽启用和芯片业务规则保持原链。

**Tech Stack:** RimWorld 1.6、C# 7.3、Verse Def/XML、PowerShell冒烟测试、MSBuild/dotnet build、Git。

**执行约束:** 不使用worktree（工作树）或新分支；不创建近界、黑、边境特制等业务触发体；不修改候选芯片业务；不覆盖或提交用户当前未提交的目标判定、旋空配置、专项测试和触发体贴图改动。

### Task 5：实现首次生成的原子装载事务

**Files:**

**Step 1: 只接入原版首次制造时机**

在生命周期片段增加：

```csharp
public override void PostPostMake()
{
    base.PostPostMake();
    TryInstallInitialFixedLoadout();
}
```

该入口不在读档流程触发，因此不需要额外持久化标记。

**Step 2: 实现内部装载流程**

`TryInstallInitialFixedLoadout()`执行：

```text
空表 -> 立即成功返回
补齐内部状态、容器和空槽
逐条创建真实芯片
调用 TriggerLoadoutService.TryLoadChip(BuildLoadoutContext(), side, slotNumber - 1, chip)
全部成功 -> 重建容器一致性并结束
任一失败/异常 -> 回滚本批创建物和本批占用的全部根槽/镜像槽
```

回滚只按“本批创建的芯片对象集合”清除槽位引用，不触碰任何其它来源的芯片；清除绑定与激活残值后重建容器，再从持有者移除并用`DestroyMode.Vanish`销毁本批对象。最终保证新触发体要么拥有完整预装，要么保持空装载。

**Step 3: 记录一次明确诊断**

捕获失败条目的`chipDef`、`side`、`slotNumber`和异常摘要，使用稳定检索键，例如：

