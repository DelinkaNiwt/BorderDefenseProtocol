# 单体命中部位叠层移除芯片设计

## 1. 目标

为 BDP 增加一种远程芯片效果：非爆炸投射物直接命中 Pawn（人形单位）后不造成伤害，而是对本次命中的身体部位添加指定 Hediff（健康状态）并叠加层数；某个身体部位上的该 Hediff 达到最大层数后，移除该部位。

本功能只处理单体直接命中，不处理爆炸、范围伤害、范围目标事件或其他攻击生产者产生的目标集合。

## 2. 已确认范围

1. 目标只允许 Pawn。
2. 只处理非爆炸投射物的直接命中。
3. 命中建筑、范围目标或其他非 Pawn Thing（对象）时，本功能不生效，也不应因为本功能而取消原本的伤害。
4. 投射物不造成真实伤害。
5. 投射物绕过 BDP 已注册的伤害护盾。
6. 每个身体部位独立保存 Hediff 层数。
7. 达到阈值后使用原版 MissingBodyPart（缺失身体部位）机制移除部位。
8. 允许头部、核心等要害部位被移除；死亡和身体能力变化沿用原版后续处理。
9. 当前版本不提供范围攻击兼容逻辑。

## 3. 当前工程事实

### 3.1 已有远程命中链

`BdpProjectile` 已在 `Impact`（命中生效阶段）执行以下流程：

```text
命中记录
  → 生成 ImpactPlan（命中计划）
  → 按 DamageDisposition（伤害处置）决定是否执行真实伤害
  → 派发 ExtraEffectPlan（额外效果计划）
```

`RangedDebuffModule` 已能提交 `hediff` 效果，并用 `SuppressAllProjectileImpact` 取消投射物伤害。当前 `BypassRegisteredDamageShields` 为真时，BDP 会把该命中归类为模块主动拦截，而不是护盾拦截，随后仍允许命中效果执行。

相关文件：

- `Source/BDP/Core/Projectiles/BdpProjectile.cs`
- `Source/BDP.Content/RangedModules/Debuff/RangedDebuffModule.cs`
- `Source/BDP.Content/RangedModules/Debuff/HediffExtraEffectExecutor.cs`
- `Source/BDP/Core/Projectiles/Interaction/ProjectileInteractionPolicy.cs`

### 3.2 原版命中部位限制

正常伤害会进入原版 `DamageWorker_AddInjury.ChooseHitPart`（伤害工作器的部位选择），并在 `DamageResult.LastHitPart` 中留下结果。

本功能取消真实伤害后，不会进入这条原版伤害工作器路径，因此没有可直接读取的 `LastHitPart`。不能通过 0 伤害 `TakeDamage`（承伤调用）伪造命中部位，否则会引入护盾、伤害补丁和其他副作用。

本功能需要在 BDP 命中阶段主动选择一个部位，并按原版 `GetRandomNotMissingPart`（随机选择未缺失部位）的覆盖率和伤害类型命中倍率进行选择，同时过滤不可摧毁、已缺失和生命值归零的部位。

## 4. 设计原则

### 4.1 复用现有远程减益设施

不新增专用投射物类，不复制飞行、命中、护盾绕过和伤害处置逻辑。新芯片继续使用已有的 `RangedDebuffModule`、远程模块挂载和额外效果派发链。

本次扩展只增加可复用的通用能力，不增加“部位裂解专用模块”或“本芯片专用命中链”。远程模块负责组合和传递以下能力：目标范围、命中部位、Hediff 作用域、叠层策略和达到阈值后的动作。

配置字段使用机制语义，不使用本需求的业务名称。例如使用 `PartTargetMode`（部位作用域模式）和 `MaximumSeverityAction`（达到最大严重度后的动作），不使用 `RemovePartAtMaximumSeverity`（满层移除部位）这样的专用布尔开关。

### 4.2 Core 保持中性

Core（核心基础设施）只增加“额外效果携带一个命中部位”的中性数据能力，不知道“部位裂解”“叠层”或 `MissingBodyPart` 的业务含义。

Content（正式内容程序集）负责：

- 选择有效身体部位；
- 按部位查找和叠加 Hediff；
- 判断是否达到阈值；
- 调用原版缺失部位机制。

### 4.3 原版机制优先

部位移除必须通过 `Pawn_HealthTracker.AddHediff` 添加 `HediffDefOf.MissingBodyPart`，不能直接修改身体部位列表或手动伪造缺失状态。这样可以保留原版服装、身体能力、死亡判定和其他健康系统通知。

### 4.4 共性与本次业务的边界

应沉淀为通用设施的能力：

- 投射物命中计划可以携带可选的命中部位；
- Hediff 效果可以选择作用于 Pawn 全身或指定部位；
- Hediff 可以按现有 `StackMode` 叠加，并以 HediffDef 的最大严重度作为阈值；
- 达到阈值后通过可注册动作执行后续效果；
- 部位选择通过可替换的命中部位策略完成。

只属于本次芯片配置的内容：

- 使用原版风格随机部位策略；
- 允许要害部位进入候选；
- 阈值动作选择 `RemoveBodyPart`（移除身体部位）；
- 本芯片的 Hediff、层数和玩家可见文案。

这样可以扩展现有设施，但不会让 `RangedDebuffModule` 直接知道“断肢芯片”这个业务。

## 5. 运行时设计

### 5.1 Impact 阶段

远程部位标记模块在 `Impact` 阶段执行：

1. 检查 `context.IsValidHit`。
2. 检查 `context.HitThing is Pawn`。
3. 检查投射物没有 `explosionRadius`（爆炸半径）。
4. 解析一个当前仍存在且可摧毁的身体部位。
5. 创建 `ExtraEffectPlan`，写入 `EffectKind = "hediff"`、目标范围 `DirectHitThing`、命中部位和通用阈值动作参数。
6. 仅对有效 Pawn 命中提交 `SuppressAllProjectileImpact`。
7. 提交 `BypassRegisteredDamageShields = true` 的投射物交互策略。

无效目标不得提交取消伤害的处置，避免命中建筑时因为本功能导致原本的建筑伤害消失。

### 5.2 命中部位传递

在 Core 的 `ExtraEffectPlan`（额外效果计划）增加可选 `BodyPartRecord HitPart` 字段，并在复制计划时保留该字段。

该字段只表示“Content 已经解析出的部位事实”。Core 不判断它是否要害，也不决定是否应移除。

### 5.3 Hediff 作用域与叠加

`HediffExtraEffectExecutor` 支持两种作用域：

- 没有 `HitPart` 或 `PartTargetMode = None`：维持现有全身 Hediff 行为；
- `PartTargetMode = ImpactPart`：按以下键查找状态：

```text
目标 Pawn + HediffDef + BodyPartRecord
```

不能在部位作用域中继续使用当前全身共用的 `GetFirstHediffOfDef`，否则左臂和右臂会共用一个层数。部位作用域解析失败时必须失败关闭，不能退回到全身 Hediff。

目标部位没有对应 Hediff 时，使用带部位的 `HediffMaker.MakeHediff` 或 `Pawn_HealthTracker.AddHediff` 创建；存在时只增加该 Hediff 的严重度。当前部位裂解方案使用归一化严重度：`maxSeverity = 1`，每次有效命中增加 `0.2`，等价于五层；玩家标签按 20%、40%、60%、80% 显示进度。

### 5.4 达到阈值后的可注册动作

当部位 Hediff 的严重度达到 HediffDef 最大严重度，并且计划声明了 `MaximumSeverityAction` 时：

1. 再次检查该部位没有在同一命中流程中提前缺失。
2. 通过 Content（正式内容程序集）中的阈值动作注册表解析动作，不在 `RangedDebuffModule` 中硬编码动作分支。
3. 本次 `RemoveBodyPart` 动作移除该部位上的标记 Hediff。
4. 本次 `RemoveBodyPart` 动作调用原版 `pawn.health.AddHediff(HediffDefOf.MissingBodyPart, hitPart)`。
5. 不自行处理头部、核心部位、服装或身体能力后果。

达到阈值后的动作应在本次命中立即完成，不延迟到下一个 Tick（游戏刻）。动作执行后必须停止继续使用可能已经死亡或状态改变的 Pawn。

## 6. Def 与配置设计

继续复用 `RangedDebuffConfig`，增加通用目标作用域和阈值动作配置，而不是新建第二套投射物效果协议。

本芯片的固定配置建议为：

```text
TargetFilter: PawnsOnly
TargetScope: DirectHitThing
DamageSuppression: SuppressAllProjectileImpact
BypassRegisteredDamageShields: true
EffectKind: hediff
PartTargetMode: ImpactPart
HitPartSelectionMode: VanillaRandom
StackMode: Add
MaximumSeverityAction: RemoveBodyPart
DurationTicks: 0
```

`BypassProjectileInterceptors`（绕过投射物拦截器）与伤害护盾是两个独立语义。本芯片当前同时声明绕过原版投射物拦截器和已注册伤害护盾，以满足“投射物无视护盾后仍需命中并叠加部位状态”的需求。

新增通用配置的默认值必须保持兼容：`PartTargetMode = None`、`HitPartSelectionMode = None`、`MaximumSeverityAction = None`。只有显式组合出部位作用域和阈值动作时，才进入本需求的行为。

阈值动作标识通过现有额外效果参数协议传递，由 Content（正式内容程序集）的注册表解析。Core 不引用动作名称的业务实现。芯片信息系统需要同步投影这些通用字段，否则玩家只能看到普通 Hediff 参数，无法得知效果是按部位叠加还是达到阈值后执行动作。

HediffDef 使用专用 DefName，设置：

- `maxSeverity` 当前固定为归一化满值 `1`；每次命中增加 `0.2`，对应五层命中进度；
- `initialSeverity` 为 0；
- 通过专用 Hediff 显示类调用通用严重度百分比标签工具，使部位裂解与铅弹使用同一显示格式；
- 不添加恢复组件；
- 不添加自动消失组件；
- 不自行提供伤害或致死属性，部位移除是唯一终点效果。

## 7. 不支持和边界行为

### 7.1 范围攻击

本功能不向 `VanillaExplosionAffectedThings`、`VanillaExplosionAffectedPawns` 或 `AttackTargetEvents` 提供部位标记行为。模块明确拒绝带爆炸半径的投射物，避免一个爆炸对多个目标产生不明确的部位选择。

### 7.2 已缺失部位

已缺失部位不进入候选，也不创建新的标记 Hediff。

### 7.3 不可摧毁部位

`destroyableByDamage = false` 的部位不进入候选。若目标没有任何有效候选，本次只视为没有可应用效果，不应取消原本伤害；具体是否保留“无伤害命中”语义需由模块入口统一处理。

### 7.4 要害部位

不排除头部、核心、心脏等要害部位。移除后由原版健康状态检查决定 Pawn 是否死亡或失去能力。

## 8. 验证方案

### 8.1 静态与烟测

至少验证：

1. 新模式会携带 `HitPart`。
2. 普通 Hediff 仍保持全身模式，不受部位模式影响。
3. 部位模式按部位独立查找状态。
4. 有效 Pawn 命中取消伤害并允许效果执行。
5. 非 Pawn 命中不被本模块错误取消伤害。
6. 爆炸投射物不会进入该模块。
7. 达到阈值时调用原版缺失部位 Def，且不会重复添加。
8. Core 不引用部位裂解业务类型或 Content 类型。

### 8.2 游戏内验证

使用 Development（开发诊断程序集）提供可插拔测试入口，验证：

1. 同一部位命中 N-1 次时只出现 N-1 层标记，不造成真实伤害。
2. 第 N 次命中后该部位变为缺失。
3. 左右同名部位或不同部位的层数互不影响。
4. 命中头部、核心等要害部位时沿用原版死亡处理。
5. 目标拥有 BDP 能量护盾或原版伤害护盾时，效果仍能执行。
6. 命中建筑或其他非 Pawn 目标时，原本的建筑伤害不被本功能错误抑制。
7. 同一 Tick（游戏刻）连续命中多个部位时，已经缺失的部位不会再次叠层。

## 9. 预期修改范围

预计涉及：

- Core：`ExtraEffectPlan` 的中性命中部位传递字段；
- Content：远程减益配置、命中部位解析、Hediff 按作用域叠加、阈值动作注册和部位移除动作；
- 信息系统：远程模块通用字段的芯片信息投影和简体中文标签；
- Def：远程模块、专用 Hediff、芯片功能挂载；
- 语言包：芯片名称、说明、Hediff 名称和说明；
- Development：必要的可插拔诊断或最小验证入口。

不涉及：

- 新投射物基类；
- 全局 `TakeDamage` 伤害补丁；
- 范围攻击协议；
- Core 对 Content 的反向依赖；
- 单独的部位裂解投射物模块或独立命中链；
- 旧版模组或退役测试模组。
