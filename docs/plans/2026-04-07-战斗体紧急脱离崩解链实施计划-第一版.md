# 战斗体紧急脱离崩解链实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在新 BDP 的被动崩解链中接回旧 BDP 的紧急脱离表象：有紧急脱离被动表达时，崩解收尾可传送到安全点、播放特效、消费一次性来源芯片，并继续走被动崩解本体收尾。

**Architecture:** 紧急脱离仍是“被动崩解的可选附加阶段”，不是第三种退出模式。判定只读表达投影，芯片消费只走 Trigger 正式命令，传送只放在 CombatBody 退出事务里，避免 CombatBody、Trigger、Expression、Trion、GUI 相互硬访问。

**Tech Stack:** C# 7.3、RimWorld 1.6 Verse/RimWorld API、XML Def、PowerShell smoke tests、`dotnet msbuild`。

## 0. 旧版事实基线

- 旧版入口：`BorderDefenseProtocol.Legacy/Source/BDP/Combat/CombatBodyOrchestrator.cs:87`
- 旧版判断：`isEmergency && HasEmergencyEscapeChip(...)`，并要求特殊槽里 `BDP_Chip_EmergencyEscape` 处于激活：`BorderDefenseProtocol.Legacy/Source/BDP/Combat/CombatBodyOrchestrator.cs:94`、`:555`
- 旧版传送：入口特效、改 `pawn.Position`、`Notify_Teleported(...)`、出口特效：`BorderDefenseProtocol.Legacy/Source/BDP/Combat/CombatBodyOrchestrator.cs:103`、`:107`、`:108`、`:129`
- 旧版落点：信标附近、殖民者建筑附近、随机安全位置、原地：`BorderDefenseProtocol.Legacy/Source/BDP/Combat/Escape/EmergencyEscapeRouter.cs:21`
- 旧版一次性消费：传送成功后销毁芯片、清槽、取消征召、发消息：`BorderDefenseProtocol.Legacy/Source/BDP/Combat/CombatBodyOrchestrator.cs:134`、`:146`
- 旧版崩解本体：紧急脱离后仍会 `ForceDeplete()`、挂枯竭 hediff、进入 cooldown：`BorderDefenseProtocol.Legacy/Source/BDP/Combat/CombatBodyOrchestrator.cs:188`、`:190`、`:200`

## 1. 新版架构原则

- 不新增“紧急脱离退出模式”；`CombatBodySessionExitMode` 仍只有 `Release` 与 `Collapse`。
- `CombatBodyEmergencyEscapeResolver` 只读 `ExpressionSurfaceAccess.ResolveReader(pawn).GetCombatProjection(pawn)`。
- `CombatBodyExitTransaction` 是唯一接入崩解收尾的位置。
- `Trigger` 负责芯片槽真值与芯片销毁命令，CombatBody 不直接改槽位字段。
- `Trion` 只负责资源清零、释放、冻结状态；紧急脱离不写进 `ChipTrionConfig`。
- `TrionGUI` 只读 resolver 的结果做提示，不参与传送或销毁。
- 所有新增成员写中文注释；文件保持 UTF-8。

## 2. 边界保护

- 禁止在 `CombatBodyEmergencyEscapeResolver` 里出现 `ChipSurfaceAccess`、`ChipTrionContract`、`SupportsEmergencyEscape`、`TriggerSurfaceAccess.ResolveLoadoutReader`。
- 禁止通过解析 `ResultId` 字符串反推芯片实例。
- 禁止从 CombatBody 直接访问 `CompTriggerBody` 内部槽字段。
- 禁止主动解除链执行紧急脱离。
- 禁止紧急脱离控制崩解 debuff；debuff 仍由被动崩解本体处理。
- 禁止把信标变成紧急脱离的唯一前提；旧版表象是“信标优先，不存在则回退”。

```csharp
/// <summary>
/// 销毁指定槽位中匹配的已装载芯片。
/// </summary>
internal bool TryDestroyLoadedChip(TriggerSide side, int slotIndex, string expectedThingId)
{
    bool success = TriggerLoadoutService.TryDestroyLoadedChip(BuildLoadoutContext(), side, slotIndex, expectedThingId);
    if (success)
    {
        RuntimeCoordinator?.MarkDirty(ProjectionDirtyReason.LoadoutChanged);
        RuntimeCoordinator?.RebuildAndPublish();
    }

    return success;
}
```

在 `TriggerLoadoutService` 中最小实现：

- 找槽。
- 拒绝空槽。
- 拒绝 `expectedThingId` 不匹配。
- 若槽位还 active，先清 active 状态或复用已有 deactivation 事务。
- `slot.LoadedChip.Destroy(DestroyMode.Vanish)`。
- `slot.SetLoadedChip(null)`。
- 双持镜像槽位如果指向同一芯片，也同步清。

**Boundary note:**

- 这是 Trigger owner 的职责，不是 CombatBody 的职责。
- 如果当前 Trigger 只有请求式 `RequestDeactivate`，本命令可以作为“强制一次性消费”专用通道，但必须只对明确匹配的 `expectedThingId` 生效。

```csharp
        IntVec3 beacon = TryFindBeaconPosition(map);
```

**Design:**

- `Service` 才负责执行：路由、特效、移动、消费芯片、取消征召、消息。
- 只在 `Collapse` 调用，不给主动解除使用。

**Resolution sketch:**

```csharp

/// 来源追踪。
/// </summary>

```

**Service sketch:**

```csharp
internal sealed class CombatBodyEmergencyEscapeService
{
    /// <summary>
    /// 在可用时执行紧急脱离。
    /// </summary>
    internal bool ExecuteEmergencyEscapeIfAvailable(Pawn pawn, CombatBodyEmergencyEscapeResolution resolution)
    {
        if (pawn == null || !pawn.Spawned || resolution == null || !resolution.IsAvailable)
        {
            return false;
        }

        Map map = pawn.Map;
        IntVec3 origin = pawn.Position;
        IntVec3 destination = CombatBodyEmergencyEscapeRouter.FindEscapeDestination(pawn, map);
        if (!destination.IsValid || destination == origin)
        {
            return false;
        }

        CombatBodyEmergencyEscapeEffects.PlayEntryEffects(origin, map);
        pawn.Position = destination;
        pawn.Notify_Teleported(endCurrentJob: true, resetTweenedPos: true);
        pawn.Drawer?.renderer?.SetAllGraphicsDirty();
        pawn.Drawer?.renderer?.EnsureGraphicsInitialized();
        CombatBodyEmergencyEscapeEffects.PlayExitEffects(destination, map);

        TryConsumeSourceChip(pawn, resolution.SourceReference);
        if (pawn.drafter != null)
        {
            pawn.drafter.Drafted = false;
        }

        Messages.Message($"{pawn.Name} 紧急脱离至安全位置", new TargetInfo(destination, map), MessageTypeDefOf.PositiveEvent);
        return true;
    }
}
```

**Boundary note:**

- `TryConsumeSourceChip` 只调用 `TriggerSurfaceAccess.ResolveLoadoutCommands(pawn)?.TryDestroyLoadedChip(...)`。
- 如果来源追踪缺失，可以传送但不消费芯片；同时用 `BdpDiagnostics.Once(...)` 记录，避免静默错账。

## Task 7: 接入被动崩解退出事务

**Files:**
- Modify: `Source/BDP/Core/CombatBodySession/CombatBodyExitTransaction.cs`
- Modify: `Source/BDP/Core/CombatBodySession/CombatBodySessionService.cs`

**Design:**

推荐时序：

1. `DeactivateAllSlots(...)`
2. 清战斗会话运行时绑定
3. 释放 allocated
4. 解冻 Trion
5. `EnterCooldown(...)`，内部恢复战斗体快照
6. 如果 `Collapse`：
   - `TrySetCurrent(0f)`
   - 执行紧急脱离附加阶段
   - `ApplyCollapseAftereffect(ownerPawn)`
7. 发布状态变化

**Reason:**

- 传送发生在战斗体恢复后，避免快照恢复链覆盖位置或图形状态。
- 崩解 debuff 在传送后挂，避免旧位置下应用后又被恢复链清理。
- `cur = 0` 是被动崩解本体，不依赖紧急脱离是否成功。

**Implementation sketch:**

```csharp
if (exitMode == CombatBodySessionExitMode.Collapse)
{
    CombatBodyEmergencyEscapeResolution resolution = emergencyEscapeResolver.Resolve(ownerPawn);
    trionCommands?.TrySetCurrent(0f);
    emergencyEscapeService.ExecuteEmergencyEscapeIfAvailable(ownerPawn, resolution);
    ApplyCollapseAftereffect(ownerPawn);
}
```

- 无紧急脱离 Passive 时，被动崩解链只执行崩解本体。
- 主动解除不触发紧急脱离。
- 来源芯片只在紧急脱离实际传送成功后消费。
- `cur = 0` 与崩解后遗症不依赖紧急脱离成功。
- 所有新增成员有中文注释。
- 相关 smoke 与主工程编译通过。

- 每完成一个 Task，可以作为一个提交点留给用户确认。
- 如果用户明确要求提交，再按任务粒度提交。
