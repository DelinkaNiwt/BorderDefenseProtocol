# BDP Homing Tracking Hit and Dodging Fix Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 修复 BDP 追踪弹在目标移动或静止时从目标身旁擦过的问题，同时保留低追踪强度目标可以躲过子弹的机制。

**Architecture:** 在 `BDP.Content` 的 Homing（追踪弹）模块内修复到达段末的决策优先级：接近中的命中窗口优先于丢失判定；目标仍有效的硬距离分支改为一次终端追踪段；目标预测从“每段位移直接乘比例”改为“位移 / 观测间隔 × 下一段飞行时间 × 追踪预测比例”。`BDP.Core` 不改。

**Tech Stack:** C#（C#语言）、RimWorld 原版投射物时序、PowerShell（PowerShell脚本）源码烟雾测试、MSBuild（微软构建工具）。

---

### Task 1: 添加失败测试，锁定修复契约

**Files:**
- Add: `Source/BDP.Tests/HomingPursuitDecisionSmokeTests.ps1`

**Steps:**
1. 检查 `HomingModule`（追踪模块）存在接近中的命中窗口判定。
2. 检查普通目标的硬距离分支使用终端追踪路径，而不是直接调用 `BuildReleasePath`（释放路径）。
3. 检查 `HomingState`（追踪状态）保存最近目标观测 tick。
4. 检查 `HomingPathBuilder`（追踪路径构建器）接受观测间隔与下一段预计 tick。
5. 运行测试，确认当前源码先以 RED（失败）结束。

### Task 2: 增加追踪预测所需的最小状态

**Files:**
- Modify: `Source/BDP.Content/RangedModules/Homing/HomingState.cs`
- Modify: `Source/BDP.Content/RangedModules/Homing/HomingModule.cs`

**Steps:**
1. 增加最近目标观测 tick，并接入 Clone（复制）与 ExposeData（存档读写）。
2. 初始化目标位置时同步记录观测 tick。
3. 到达段末用观测 tick 差计算目标位移对应的 tick 间隔。
4. 对旧存档 / 无游戏 tick 场景回退到 1 tick。

### Task 3: 修复命中窗口与近距离决策

**Files:**
- Modify: `Source/BDP.Content/RangedModules/Homing/HomingModule.cs`
- Modify: `Source/BDP.Content/RangedModules/Homing/HomingPathBuilder.cs`

**Steps:**
1. 增加“命中窗口内且距离未持续增大”的判定。
2. 将该判定放在 `targetLost`（目标丢失）分支之前。
3. 目标仍有效且进入硬距离时构建终端追踪段，清理旧释放状态并继续追踪。
4. 目标确实越过或远离时继续走原有重锁 / 飞离流程。

### Task 4: 改为时间感知的有限预测

**Files:**
- Modify: `Source/BDP.Content/RangedModules/Homing/HomingPathBuilder.cs`
- Modify: `Source/BDP.Content/RangedModules/Homing/HomingModule.cs`

**Steps:**
1. 根据目标位移和观测 tick 差得到位移速度。
2. 根据目标距离和投射物速度估算下一段飞行 tick，并限制在稳定范围内。
3. 目标预测点使用有限的下一段时间，不把跨多段的位移过度外推。
4. 重锁段使用更低的现有预测比例，保留强弱差异。

### Task 5: 验证与交付

**Steps:**
1. 运行 `HomingPursuitDecisionSmokeTests.ps1`，确认 GREEN（通过）。
2. 运行现有 `BDP.Tests` 全部 PowerShell 烟雾测试。
3. 编译 BDP Content 工程，确认无新增编译错误。
4. 检查 diff（差异）只包含本任务源码、测试、文档和工作日志；不覆盖用户已有脏文件。
5. 记录工作日志并提交最终修改，交付游戏内复测重点：静止目标、移动目标、高追踪强度、低追踪强度。
