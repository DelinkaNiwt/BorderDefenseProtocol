# 战斗体切换单事务与短时锁设计

## 目标

同一 Pawn 当前处于状态 A 时，无论玩家在短时间内点击多少次战斗体按钮，只允许一次正式 A→B 状态切换，并且最多生成一段对应的扫描动画。重复点击必须在正式命令入口被拒绝；即使其他调用方绕过按钮重复发送表现通知，Content 也不能叠加扫描 Mote。

## 已确认现况

- 生成战斗体是同步事务；完成后立即进入 `Active`。
- 主动解除使用 0 tick 冷却；退出事务会在同一 tick 直接回到 `Inactive`。
- `isExitInProgress` 只防止一次退出事务内部的嵌套调用，事务返回后立即清除，不能限制下一次点击。
- Gizmo 根据当前阶段立即重建，所以玩家可以在同一游戏 tick 内连续执行 `Inactive→Active→Inactive→Active`。
- Content 每收到一组有效 `Begin/End` 通知都会创建新 Mote；当前只管理换装前暂存，没有管理已经生成的同 Pawn 动画。

## 采用方案

### 1. Core 保存正式短时变换锁

在 `CombatBodyState` 中增加一个“手动变换锁结束 tick”，沿用绝对游戏 tick 表示并参与存档：

- `CanActivate` 只有在 `Inactive` 且锁已结束时才返回 true；
- `CanManualDeactivate` 只有在 `Active` 且锁已结束时才返回 true；
- 一次激活事务成功后启动短时锁；
- 一次主动解除事务成功后重新启动短时锁；
- 重复点击在事务入口被拒绝，不触发宿主换装、Trion 结算或表现通知。

锁只控制手动 A↔B 切换，不新增 `Generating/Releasing` 阶段，也不延迟真实换装。这样不扩大现有状态机，不改变伤害、Trigger、Trion 或崩解时序。

### 2. XML 配置默认 12 tick

在 `CombatBodyHostConfigDef` 增加 `manualTransformLockTicks`，默认值与正式 XML 均设为 12 tick，约 0.2 秒。当前扫描动画为 10 tick，锁比动画多两 tick，覆盖生成、销毁和界面重建边缘。

该值是 Core 的手动事务节流配置，不要求 Content 依赖或读取它；Content 继续保持独立的 10 tick 动画时长。

### 3. Gizmo 明确显示锁定

Gizmo 仍按真实阶段显示“生成战斗体”或“解除战斗体”，但在对应 `CanActivate/CanManualDeactivate` 为 false 时禁用，并使用语言包提示“战斗体正在完成变换”。

按钮禁用只是玩家反馈；真正的安全边界仍在命令入口和状态判断，其他代码直接调用正式命令也不能绕过。

### 4. Content 保持同 Pawn 动画单实例

`CombatBodyTransformScanPresentationProvider` 增加按 Pawn 编号保存的动画占用截止 tick：

- `Begin` 发现同 Pawn 仍在 10 tick 动画窗口内时，不捕获新快照；
- 对应 `End` 因没有本轮暂存而直接返回，不生成第二个 Mote；
- 只有 Mote 成功生成后才登记动画占用窗口；
- 窗口到期后下一次合法变换正常捕获和生成。

这里选择“忽略重复动画”，不销毁并替换正在播放的动画。因为第一个 A→B 动画对应已经接受的正式事务；后续重复通知不是新的合法事务，不应抢占第一段表现。

## 时序

```text
状态 A，锁已结束
  ↓ 第一次点击
正式入口接受 A→B
  ├─ 宿主只换装一次
  ├─ Content 只生成一个扫描 Mote
  └─ Core 启动 12 tick 锁

锁定期间重复点击
  ├─ Gizmo 变灰
  ├─ 正式入口拒绝
  ├─ 不再次换装
  └─ 不再次生成动画

12 tick 后
  └─ 允许从当前真实状态 B 发起下一次 B→A
```

## 异常与边界

- 锁使用绝对 tick 并存档，暂停游戏时不会自行结束，读档后也不会丢失当前短时边界。
- 配置小于 0 时按 0 处理；0 表示明确关闭短时锁，但 Content 的同动画窗口防叠加仍保留。
- Mote 创建失败不登记动画窗口，下一次合法切换可以正常尝试表现。
- 多个 Pawn 独立计时，互不阻塞。
- 崩解仍由现有 `Collapsing/Cooldown` 阶段控制，不额外套用手动切换锁。

## 验证范围

- `CombatBodyState` 的锁定 tick、存档字段及激活/手动解除准入。
- 激活成功和主动解除成功后都启动 XML 配置的锁。
- Gizmo 在锁定期间禁用，并使用语言包文案。
- 重复正式命令不再次进入宿主变换和表现生命周期。
- Content 在同 Pawn 动画窗口内不捕获、不生成第二个 Mote。
- 既有战斗体状态、退出、扫描、前台预设和 Core 隔离测试继续通过。
