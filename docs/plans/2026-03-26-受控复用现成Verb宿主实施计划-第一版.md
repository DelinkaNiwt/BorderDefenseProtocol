# 受控复用现成 Verb 宿主 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不破坏 `FormalExpressionResult / AttackExecution` 正式边界的前提下，为 BDP 攻击执行链补入“受控复用现成芯片 Verb 宿主”的基础设施，消除近战 `new Verb` 半初始化带来的原版运行时异常，并保留未来自定义 `BDP_Verb` 的承载能力。

**Architecture:** 这次改动不回退到旧 BDP 的 `Verb` 中心结构。正式攻击真值继续留在表达系统和 `AttackExecution`；Trigger/宿主层只新增“现成芯片 Verb 宿主池”，供执行阶段复用完整宿主实例。外部系统不得直接围绕宿主池做决策，统一仍经 `IExpressionVerbHostResolver` 读取。

**Tech Stack:** RimWorld 1.6 C# Mod, Harmony, Verse/RimWorld 原版 `Verb / VerbTracker / CompEquippable` 运行时模型。

## 目标状态

```text
FormalExpressionResult / AttackExecution
    -> 决定这次正式攻击事实
    -> 决定何时、为何、用哪条攻击

Trigger 宿主层
    -> 维护“芯片现成 Verb 宿主池”
    -> 宿主池不进入 AllVerbs
    -> 宿主池不对外直接暴露为正式边界

IExpressionVerbHostResolver
    -> 按 Pawn + FormalResult 解析宿主 Verb
    -> 优先复用现成宿主
    -> 只在过渡阶段保留受控 fallback

BDP 自定义 Verb
    -> 继续作为真正执行宿主
    -> 继续承载语义上下文和未来自定义行为
```

## 非目标

- 不把芯片 Verb 塞进 `VerbTracker.AllVerbs`。
- 不把 `Verb` 重新升级成系统正式真值。
- 不回退到旧 BDP “外部系统直接拿缓存 Verb 就开打”的结构。
- 不同时重做攻击编排、Targeting 适配层、Trigger 装载架构。
- 不引入单元测试体系。

## 关键裁定

### 裁定 1：为什么不能直接走 `AllVerbs`

- 旧 BDP 已明确验证：芯片近战 Verb 若进入 `AllVerbs`，会被原版近战选择池和 `GetVerbsCommands` 误拾取。
- 因此“复用现成 Verb”不等于“去 `AllVerbs` 里捞”。
- 当前方案的现成宿主池必须独立于 `AllVerbs`。

### 裁定 2：为什么 `BDP_Verb` 仍然保留

- `BDP_Verb` 不是这次问题的根因；问题是“宿主解析方式”不完整。
- 未来的语义上下文、自定义命中逻辑、自定义连射/爆炸/多段行为，仍然需要承载在 `BDP_Verb` 上。
- 这次只改变“如何拿到完整宿主实例”，不取消 `BDP_Verb` 的存在价值。

### 裁定 3：为什么允许 Trigger 里有宿主池但不算回退旧 BDP

- 宿主池只是执行层基础设施，不是系统正式边界。
- 攻击真值仍由 `FormalExpressionResult / AttackExecution` 决定。
- 外部读取必须经正式表面和 `IExpressionVerbHostResolver`，不能直接摸 Trigger 内部字段。
