# 光魂推进与推进器组合技设计

## 1. 目标

将光魂当前内置的“光魂推进”抽离为独立组合技：

```text
光魂 + 推进器 → 光魂推进
```

新增配件类芯片“推进器”，技术标识为 `BDP_ChipFunction_Thruster`。光魂的盾形态和重刃形态都可以在同侧 Main/Sub（主/副）来源满足时获得组合技能力。

“光魂推进”不再是跳跃，而是贴地直线冲刺：

- 玩家选取位置决定本次实际推进距离；
- AbilityDef（能力定义）的射程只作为最大距离上限；
- 冲刺路径遇到不可通行建筑时在建筑前停止，不能穿墙；
- 路径上的敌方 Pawn（单位）受到一次钝伤，并沿冲刺方向被推挤；
- 推挤形成大致的连续链条，不追求严格物理模拟；
- 敌人撞到墙或大体型敌人时短暂晕眩；
- 体型超过推进器停止力判定的敌人不能被推动，只受一次钝伤，并作为临时阻挡物；
- 建筑会截断范围预览，大体型敌人不会改变范围预览。

## 2. 当前事实与架构裁定

当前光魂能力使用 `CastJump`、`Verb_CastAbilityCombatBodyShortJump` 和跳跃成本提交基类；该能力由光魂两个形态直接引用。

蚱蜢已经具备可复用的贴地线性位移、爆发速度曲线、`PawnFlyer.MakeFlyer` 生成、选中状态恢复和范围指示基础。但蚱蜢的完整 Verb（能力动作入口）还包含 Shift 多段路径输入，效果组件还包含多段链式跳跃和分段 Trion（特里恩）扣费。

因此本设计明确禁止以下关系：

```text
光魂推进 → 继承蚱蜢业务类
```

改为建立中性地面冲刺设施：

```text
                 ┌─ 蚱蜢专属路径/链式逻辑
地面冲刺设施 ────┤
                 └─ 光魂推进专属碰撞/推挤逻辑
```

这些设施放在 Content（内容程序集）内部，不放入 Core（核心程序集）；它们是多个正式业务能力共用的游戏玩法设施，不是通用基础设施。

## 3. 中性设施与命名

### 3.1 地面冲刺飞行承载体

从现有 `PawnFlyer_Grasshopper` 中抽出中性部分，建立 `PawnFlyer_GroundDash`：

- 贴地线性位置计算；
- 现有无过冲进度曲线读取；
- 阴影和 Pawn 绘制；
- 飞行结束后的通用回调；
- 不包含蚱蜢踏板、气浪和蚱蜢名称。

蚱蜢如需保留现有踏板与气浪表现，使用蚱蜢专属子类或专属视觉扩展；光魂推进使用自己的冲刺飞行器子类，不能继承蚱蜢类。

### 3.2 地面冲刺生成工具

将 `GrasshopperUtility.DoJump()` 中的通用生成逻辑抽出为 `GroundDashUtility.DoDash()`：

- 保存地图、起点和选中状态；
- 调用原版 `PawnFlyer.MakeFlyer`；
- 生成自定义地面冲刺飞行器；
- 恢复 Pawn 选中状态。

蚱蜢和光魂推进都调用该工具。蚱蜢的多段路径排队、锚点消费和分段费用仍由蚱蜢专属逻辑负责。

### 3.3 目标校验和范围指示

抽出中性 `Verb_CastAbilityGroundDash`，承载两种能力共有的：

- 最大射程；
- 地面目标校验；
- 直线视线与地图边界校验；
- 射程圈；
- 目标格高亮；
- 建筑阻挡后的有效终点计算。

蚱蜢在此基础上追加 Shift 多段路径输入；光魂推进直接使用中性目标入口，不获得蚱蜢的多段路径功能。

## 4. 芯片与组合技定义

### 4.1 推进器芯片

新增 `BDP_ChipFunction_Thruster`：

- 玩家名称：推进器；
- 分类：`BDP_ChipCategory_Accessory`（配件类）；
- 槽区：`MainSub`；
- 占用：`Single`；
- 不生成独立主动能力；
- 以最小 `Passive`（被动）表达条目作为组合来源；
- 使用独立的 `PassiveIdentityKey`，不复用旋空身份。

推进器不放入 `Special`（特殊槽），因为当前组合技规则不允许特殊槽参与组合。

### 4.2 光魂内置表达调整

从光魂表达目录和盾/重刃两个形态的 `ActiveEntryIds` 中移除 `light_soul_propulsion`。光魂仍保留原有盾、重刃、姿态和视觉表达。

### 4.3 光魂推进组合技

新增组合技定义 `BDP_Combo_LightSoulPropulsion`：

- 第一来源：`BDP_ChipFunction_LightSoul`；
- 第二来源：`BDP_ChipFunction_Thruster`；
- 只在合法同侧 Main/Sub 来源激活时成立；
- 组合结果继续使用现有 `BDP_Ability_LightSoulPropulsion` 作为唯一 Ability 宿主；
- 该 Ability 不再代表光魂内置能力，只代表组合结果；
- Trion 使用费用和最低要求默认跟随光魂侧，保留当前光魂推进的费用语义；
- 组合 Ability 使用组合条件检查和 Trion 成本组件。

## 5. 光魂推进运行时行为

### 5.1 有效终点

施法时生成一个路径快照：

```text
玩家鼠标位置
  → 最大距离裁剪
  → 从起点向目标逐格检查
  → 首个不可通行建筑前停止
  → 得到有效冲刺终点
```

路径不绕路，只沿起点到目标的直线推进。不可通行墙体、岩石、关闭的不可通行门和不可通行建筑都视为路径阻挡。

玩家选取位置在最大距离以内时，实际终点就是选取位置；超过最大距离时，终点被限制在最大距离；目标在建筑后时，终点限制在建筑前最后一个合理格。

### 5.2 路径碰撞

光魂专用飞行器在每帧使用上一帧到当前帧之间的逐格线段检查，避免高速移动跨格漏检。

每次能力施放维护一组已处理 Pawn：

- 每个敌人最多受到一次钝伤；
- 每个敌人最多参与一次推挤判定；
- 不因飞行器连续多帧经过同一格而重复处理。

### 5.3 体型与停止力

推进器使用独立的 `pushStoppingPower` 配置，判定形式对齐原版投射物：

```text
target.BodySize <= pushStoppingPower + 0.001
    可推动

target.BodySize > pushStoppingPower + 0.001
    不可推动，仍受钝伤，并成为临时阻挡物
```

大体型目标本身只受一次钝伤，不因为充当阻挡物而自动晕眩。

### 5.4 推挤链

推挤只沿冲刺方向处理，不调用可能绕路的寻路逻辑：

1. 发现可推动的敌人后，尝试向冲刺方向移动；
2. 前方有其他可推动敌人时，继续递进处理；
3. 前方是墙、不可通行建筑或大体型目标时，整条已被推动的敌人链停止；
4. 被推动链中实际撞上阻挡物的敌人，以及被压缩在其后的已推动敌人，进入短暂晕眩；
5. 无法找到合理落点时停在最近可用位置，不穿墙、不重叠、不强行覆盖其他单位。

推挤链只要求结果大致符合直觉，不模拟质量、冲量和复杂碰撞反弹。

### 5.5 撞击晕眩

使用 Pawn 现有的 `StaggerHandler.StaggerFor()`（踉跄处理器）施加短暂晕眩，确保受到 Pawn 自身 `StaggerDurationFactor`（踉跄时长倍率）修正。

初始晕眩时长沿用原版投射物默认的 95 ticks（刻），后续只通过 XML（配置）参数调整，不新增第二套状态系统。

## 6. 视觉与逻辑一致性

范围预览只根据地图几何阻挡计算，不读取 Pawn 体型：

- 建筑会让范围圈和冲刺路径在建筑前截断；
- 大体型敌人不会截断范围圈，也不会改变最大射程；
- 实际施放时，大体型敌人作为动态阻挡物停止推挤链；
- 目标高亮使用有效终点，不高亮墙后或不可达位置；
- 冲刺飞行器的终点、路径碰撞和预览使用同一套有效路径规则。

光魂推进不使用 `Longjump_Jump`/`Longjump_Land`（跳跃音效），也不显示蚱蜢踏板和蚱蜢气浪。视觉上使用贴地冲刺表现，必要时只增加中性的冲刺拖尾或撞击特效。

## 7. 文案与语言包

所有新增或改写的玩家可见文字进入简体中文语言包：

- 推进器名称和说明；
- 光魂推进组合技名称和说明；
- 光魂芯片说明中移除“所有形态均可使用光魂推进”的旧描述，改为组合条件说明；
- 能力描述改为贴地冲刺、推挤和钝伤效果。

代码和正式 Def 不新增硬编码玩家文案。

## 8. 验证范围

### 静态和构建验证

- 光魂不再直接引用推进表达条目；
- 光魂推进不继承任何 `Grasshopper` 业务类；
- 蚱蜢和光魂推进共同引用中性地面冲刺设施；
- 组合来源、语言键和 Def 引用完整；
- `CastJump` 和跳跃音效不再出现在光魂推进定义中；
- Core 与 Content 依赖方向不改变；
- Core、Content、Development（开发程序集）构建和边界检查通过。

### 行为验证

- 玩家选取近距离时只推进到选取位置；
- 超过最大距离时被最大距离限制；
- 建筑前截断实际路径和范围预览；
- 大体型敌人不截断范围预览，但在实战中阻断推挤链；
- 小体型敌人依次被推挤；
- 同一敌人只受一次钝伤；
- 撞墙或撞大体型敌人时，被推动链产生短暂晕眩；
- 大体型敌人只受伤害，不被推动；
- 不穿墙、不重叠、不绕路；
- 光魂盾形态和重刃形态均能正确获得组合能力；
- 缺少推进器时不出现光魂推进按钮；
- 组合技来源失效时能力按钮和绑定结果正确清理。

## 9. 实施边界

本次不修改无关的光魂盾牌、重刃、姿态、视觉和攻击逻辑；不修改 Core 的通用 Ability 成本设施；不引入旧存档或旧 DefName 兼容层；保留工作区已有的贴图、DLL 和 PDB 未提交改动。
