# BDP 触发体芯片控制面板正式化设计

## 1. 目标

把候选测试模组中当前实际生效的 Trion（触粒子）右侧芯片控制面板正式迁入 `BDP.Content.dll`（内容程序集），去除测试语义，并建立明确的玩家面板许可边界。

本事项只负责战斗中的芯片启用、关闭和切换，不提供芯片装入、卸下或编辑功能。

## 2. 玩家界面

正式界面继续附着在 Trion 状态卡右侧：

```text
┌──── Trion 能量 ────┬──── 芯片控制区 ────┐
│ 当前能量与恢复状态  │ 主 [槽][槽][槽]……  │
│                     │ 副 [槽][槽][槽]……  │
└─────────────────────┴────────────────────┘
```

保留现有视觉结构：

- 主、副两行槽位。
- 芯片图标、空槽、激活、禁用和镜像状态颜色。
- 切入与退出进度条。
- 特殊侧继续使用 Trion 顶部徽标，不进入主、副槽位网格。

不增加按钮、分页、右键菜单、装配窗口或复杂动画。

## 3. 玩家操作边界

面板只支持：

- 点击待命芯片：启用或切换。
- 点击当前芯片：关闭。
- 点击镜像槽：不给命令，提示玩家操作主控槽位。
- 点击禁用槽：不给非法命令，显示简短原因。

面板不支持：

- 从背包装入芯片。
- 从触发体卸下芯片。
- 销毁芯片。
- 修改芯片配置。

旧式独立芯片窗口具有装入和卸下能力，但它不是本事项的正式玩家界面，不迁入主模组。

## 4. 显示许可

不得再把“触发体存在槽位”当成显示面板的充分条件。

新增 `TriggerLoadoutPanelExtension`（触发体装载面板扩展），由每个具体触发体 Def（定义）主动挂载。挂载表示该触发体允许普通玩家看到并操作芯片控制面板；未挂载表示不开放。

规则如下：

- 当前候选“测试触发体”挂载该扩展，保持现有面板可用。
- 未来“边境标准触发体”和“边境特制触发体”可以分别挂载。
- 近界触发器和黑触发器默认不挂载，即使内部存在芯片槽也不显示面板。
- 不根据 DefName（定义名称）、显示名称、槽位数量或触发器类别名称猜测。
- 完整类别字段、固定芯片字段和触发体正式改名继续留到事项08A。

许可扩展属于 Content 的具体玩家界面业务，不进入 Core（核心程序集）。

## 5. 程序集与文件归属

### 5.1 Core

`BDP.Core.dll` 不新增触发器类别、面板许可字段或具体业务判断。

继续提供已有中性设施：

- Trion 右侧面板扩展容器。
- Trigger（触发器）装载读取口。
- Trigger 交互语义读取口。
- Trigger 装载命令口。

### 5.2 Content

正式源码进入：

```text
Source/BDP.Content/Trigger/UI/
```

正式类型：

- `BDP.Content.Trigger.UI.TriggerLoadoutPanelExtension`
- `BDP.Content.Trigger.UI.TriggerLoadoutPanelProvider`

`ContentBootstrap`（内容启动入口）负责注册面板提供器。启动入口只做接线，不写槽位判断或具体芯片逻辑。

### 5.3 候选测试模组

- 删除已经迁出的 `TrionTriggerLoadoutPanelProvider` 源码。
- `DevHarnessBootstrap` 删除面板注册，只保留其余尚未处理的候选接线。
- 当前候选触发体 Def 挂载正式许可扩展。
- 不迁移、不删除旧式独立窗口、诊断窗口和摘要控件；它们分别留待事项06、08处理。

程序集依赖保持：

```text
BDP.Content.dll → BDP.Core.dll
BDP.Core.dll    → 不依赖任何本模组其它程序集
```

## 6. 数据流

```text
Trion 状态卡请求右侧面板
        ↓
Content 面板检查当前主装备 Def 是否挂载许可扩展
        ↓
无许可：返回宽度 0，不显示
有许可：通过 Core 正式 surface（接口面）读取槽位与交互语义
        ↓
绘制主、副槽位
        ↓
玩家点击
        ↓
根据 Core 正式交互语义调用 RequestActivate / RequestDeactivate
```

Content 只直接读取自己拥有的许可扩展；Trigger 运行状态和写入动作仍全部通过 Core 正式接口完成，不直接访问 `CompTriggerBody` 或内部槽位集合。

## 7. 玩家文字

迁移时清理开发者语义：

- `Main/Sub` 改为“主侧/副侧”。
- 玩家看到的槽位从1开始编号；底层索引仍从0开始，不改变存档与运行真值。
- “正式交互：Activate”改为“点击启用”。
- 当前芯片显示“点击关闭”。
- 切换目标显示“点击切换至此芯片”。
- 镜像槽显示“此槽位与主侧槽位X绑定，请操作主槽位”。
- 删除“正式请求面”“控制=Main[0]”“旁观槽位”等开发表达。
- 命令入口意外不可用时只提示“当前无法操作此芯片”。

正式界面不得出现 Test（测试）、DevHarness（开发测试框架）、Diagnostics（诊断）等语义。

## 8. 异常处理

- 没有许可扩展：不显示。
- 有许可扩展但当前无法取得 Trigger 正式读取口：不显示，不刷日志。
- 主、副两侧都没有槽位：不显示空壳面板。
- 能读取但暂时没有命令口：保留状态显示；玩家点击时提示“当前无法操作此芯片”。
- 交互语义不可用：不给命令，只显示经过玩家化的不可用原因。
- 空槽：显示为空，不响应装入操作。

## 9. 不做范围

- 不重做 Trion 状态卡布局。
- 不修改芯片槽、切换时序、攻击表达或存读档。
- 不修改任何具体芯片。
- 不新增完整触发器分类。
- 不改名当前候选测试触发体。
- 不处理事项06的诊断按钮、开启战斗体和解除战斗体按钮。
- 不迁移旧式独立芯片窗口、装载诊断窗口或摘要控件。
- 不修改旧版模组。

## 10. 验证

静态检查：

- 正式许可扩展和面板提供器只存在于 `BDP.Content`。
- `ContentBootstrap` 注册正式面板提供器。
- 候选启动入口不再注册面板。
- 候选触发体挂载许可扩展。
- 面板先检查许可扩展，再读取主、副槽位。
- Content 不出现 `BDP.DevHarness`、测试或诊断命名。
- 面板不直接访问 `CompTriggerBody` 或内部槽位集合。
- 玩家文字和1起始编号符合设计。

构建检查：

- Core、Content、候选三个程序集构建成功。
- Core 零本模组程序集依赖门禁通过。
- XML（配置文件）全部可解析。
- 事项05专项检查通过。
- 全量回归与既有失败基线比较，不得新增失败。

游戏内检查：

1. 有 Trion、手持挂载许可扩展的触发体：显示右侧面板。
2. 有 Trion、手持未挂载许可扩展但有槽位的触发体：不显示右侧面板。
3. 点击待命芯片：启用或切换。
4. 点击当前芯片：关闭。
5. 禁用、镜像和切换进度表现保持正确。
6. 玩家文字不出现开发者术语，槽位编号从1开始。
