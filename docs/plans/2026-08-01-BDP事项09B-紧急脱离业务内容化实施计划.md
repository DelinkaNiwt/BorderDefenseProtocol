# BDP 事项 09B：紧急脱离业务内容化实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将紧急脱离具体业务从 `BDP.Core.dll` 移到 `BDP.Content.dll`，由 Core 提供中性的战斗体崩解扩展入口，并保持现有游戏行为不变。

**Architecture:** Core 新增 `ICombatBodyCollapseExtensionProvider` 与注册表，负责在崩解开始、退出执行和退出清理三个时点通知外部扩展。Content 自己保存紧急脱离缓存结果，负责解析、信标、路由、传送、芯片消费和徽标；Core 不再出现 `EmergencyEscape` 业务类型或缓存字段。

**Tech Stack:** C#、RimWorld/Verse、Harmony、XML Def、PowerShell 冒烟测试、`dotnet build`。

---

## 实施约束

- 不使用 worktree，直接在当前工程执行。
- 不做旧存档兼容读取；旧 Core 类型和字段直接删除。

- Core 只能被 Content 依赖，Core 不得引用 Content。
- 每完成一个逻辑组先运行对应测试，再进入下一组。
- 每个 C# 新增或修改成员补充中文注释；XML 每个移动或修改的条目保留/补充中文注释。

### Task 2: 建立 Core 中性的崩解扩展入口

**Files:**
- Create: `模组工程/BorderDefenseProtocol/Source/BDP/Core/CombatBody/External/ICombatBodyCollapseExtensionProvider.cs`
- Create: `模组工程/BorderDefenseProtocol/Source/BDP/Core/CombatBody/External/CombatBodyCollapseExtensionRegistry.cs`
- Modify: `模组工程/BorderDefenseProtocol/Source/BDP/Core/CombatBodySession/CombatBodySessionService.cs`
- Modify: `模组工程/BorderDefenseProtocol/Source/BDP/Core/CombatBodySession/CombatBodyExitTransaction.cs`
- Modify: `模组工程/BorderDefenseProtocol/Source/BDP/Core/CombatBodySession/CombatBodyActivationTransaction.cs`

**Step 1: 实现最小接口**

`ICombatBodyCollapseExtensionProvider` 只提供：

```csharp
void Prepare(Pawn pawn);
void Execute(Pawn pawn);
void Clear(Pawn pawn);
```

`CombatBodyCollapseExtensionRegistry` 保存注册提供器，提供 `Register`、`Prepare`、`Execute`、`Clear` 四个静态入口；同一具体提供器类型只注册一次；单个提供器异常记录诊断并不阻断战斗体通用退出。

**Step 2: 接入战斗体时序**

- `CombatBodySessionService.TriggerCollapse` 在进入 `Collapsing` 前调用注册表 `Prepare(OwnerPawn)`。
- `CombatBodyExitTransaction` 在原地烟雾之后、通用 Trion 释放之前调用 `Execute(ownerPawn)`。
- 主动解除和激活事务调用 `Clear(pawn)`；被动崩解退出完成后也调用 `Clear(pawn)`。
- 删除退出事务对紧急脱离 Resolver/Service 的构造依赖。

**Step 3: 运行边界测试**

边界测试应从“Core 直接业务耦合失败”推进到只剩 Content 文件和旧缓存字段未迁移的失败。

### Task 4: 增加 Content 侧可持久化状态和退出扩展提供器

**Files:**
- Create: `模组工程/BorderDefenseProtocol/Source/BDP.Content/CombatBody/Escape/CompCombatBodyEmergencyEscapeState.cs`
- Create: `模组工程/BorderDefenseProtocol/Source/BDP.Content/CombatBody/Escape/PawnCombatBodyEmergencyEscapeStateInjector.cs`
- Create: `模组工程/BorderDefenseProtocol/Source/BDP.Content/CombatBody/Escape/CombatBodyEmergencyEscapeExtensionProvider.cs`
- Modify: `模组工程/BorderDefenseProtocol/Source/BDP.Content/ContentBootstrap.cs`

**Step 1: 建立 Content 状态组件**

状态组件保存当前崩解入口缓存的 `CombatBodyEmergencyEscapeResolution`，通过 `PostExposeData` 持久化；提供 `SetPreparedResolution`、`GetPreparedResolution`、`Clear` 三个成员。组件只挂到人形 Pawn，不改变战斗体本身的 Core 宿主状态。

**Step 2: 实现退出扩展提供器**

- `Prepare`：调用 Content Resolver 并把结果写入状态组件。
- `Execute`：读取缓存结果，调用 Content Service；无结果、无地图或无有效目的地时直接返回，不阻断 Core 收尾。
- `Clear`：清除缓存状态。

**Step 3: 注册 Content 提供器**

`ContentBootstrap` 调用 `CombatBodyCollapseExtensionRegistry.Register(new CombatBodyEmergencyEscapeExtensionProvider())`。注册顺序在 Harmony 扫描后、其它 Content provider 注册附近完成。
