# 通用额外伤害模块与命中部位继承实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 为 BDP 增加可复用的远程通用额外伤害模块，并让额外伤害通过 Core（核心基础设施）的中性协议继承当前 Impact（命中结算）已经解析的命中部位。

**Architecture:** `VitalHitModule`（要害命中模块）继续只提交 `ImpactPlan.HitPartOverride`（命中部位覆盖）；通用 `RangedExtraDamageModule`（远程额外伤害模块）只创建 `DamagePlan`（伤害计划）并声明 `InheritImpactHitPart`（继承本次 Impact 命中部位）。Core 在汇总和执行阶段连接两者，业务模块之间不互相引用。风刃通过 Def 配置使用“实际命中部件最大生命值 × 10%”的额外 `Cut`（切割）伤害。

**Tech Stack:** RimWorld 1.6、C# 7.3、.NET Framework 4.8、Verse/RimWorld 伤害 API、PowerShell smoke tests（烟测）、`dotnet msbuild`。

---

## 当前约束

- 直接在当前工作区实施，不创建 worktree（工作树）。
- 不修改 `VitalHitModule` 的业务逻辑。
- Core 不引用 Content；通用额外伤害模块放在 `BDP.Content`。
- 不使用 Harmony（运行时补丁）拦截全局 `TakeDamage`（目标承伤）。
- 额外伤害仍通过现有 `BdpProjectile` 的原版伤害入口执行。
- 风刃当前每轮发射 10 枚投射物；倍率按每枚有效命中分别结算。
- 所有玩家可见模块名称和说明放入简体中文语言包，不在 C# 中硬编码。

**Files:**

**Step 1: 增加中性枚举**

在 Core 中定义 `HitPartResolutionMode`：

```csharp
public enum HitPartResolutionMode
{
    Independent,
    InheritImpactHitPart
}
```

枚举只表达执行策略，不出现“要害”或任何 Content 业务名称。

**Step 2: 扩展 `DamagePlan`**

给 `DamagePlan` 增加：

```csharp
public HitPartResolutionMode HitPartResolutionMode { get; set; }
```

默认值保持 `Independent`，避免改变现有基线伤害和历史额外伤害的隐含行为。通用额外伤害模块显式设置为 `InheritImpactHitPart`。

**Step 3: 让额外伤害执行路径解析部位**

在 `BdpProjectile.ExecuteImpact` 的额外伤害循环中：

1. 保留 `DamageDisposition`（伤害处置）、护盾拦截和伤害结果逻辑；
2. 为每条额外 `DamagePlan` 解析 `BodyPartRecord`；
3. `InheritImpactHitPart` 时使用 `impactPlan.HitPartOverride`；
4. `Independent` 时传入 `null`；
5. 把解析出的部位传入现有 `ApplyDirectDamage` 重载。

建议新增私有方法，避免把条件判断堆入伤害循环：

```csharp
private static BodyPartRecord ResolveExtraDamageHitPart(
    ImpactPlan impactPlan,
    DamagePlan damagePlan)
{
    if (damagePlan == null
        || damagePlan.HitPartResolutionMode != HitPartResolutionMode.InheritImpactHitPart)
    {
        return null;
    }

    return impactPlan != null ? impactPlan.HitPartOverride : null;
}
```

### Task 4: 实现通用额外伤害模块和配置快照

**Files:**
- Create: `Source/BDP.Content/RangedModules/ExtraDamage/RangedExtraDamageModule.cs`
- Create: `Source/BDP.Content/RangedModules/ExtraDamage/RangedExtraDamageConfig.cs`
- Test: `Source/BDP.Tests/RangedExtraDamageModuleSmokeTests.ps1`

**Step 1: 定义配置枚举和字段**

在 `RangedExtraDamageConfig` 中增加最小通用字段：

- `AmountMode`：`Fixed`、`BodyPartMaxHealthSumPercent` 或 `HitPartMaxHealthPercent`；
- `Amount`：固定伤害量；
- `Ratio`：百分比倍率；
- `DamageDef`：可选伤害类型，空时回退当前投射物伤害类型；
- `ArmorPenetration`：可选护甲穿透，空值语义为继承投射物护甲穿透；
- `HitPartResolutionMode`：命中部位策略，默认 `Independent`，由具体挂载配置显式改为继承；
- `OnlyPawns`：身体部件公式的目标限制，默认 `true`。

配置必须实现 `Clone()` 和强类型副本方法，保证运行时沿用现有模块配置快照边界。

**Step 2: 实现模块初始化**

`RangedExtraDamageModule.Initialize` 只读取 `RangedExtraDamageConfig` 并保存强类型副本。配置类型不匹配时使用安全的空配置，不抛出跨模块异常。

**Step 3: 实现命中贡献**

`IImpactStageModule.Contribute` 按以下顺序执行：

1. 配置或贡献对象为空时返回；
2. `context.IsValidHit` 为假时返回；
3. `context.HitThing` 为空时返回；
4. 身体部件百分比模式要求 `context.HitThing is Pawn target`；
5. 计算伤害量；
6. 伤害量小于等于 0 时不追加计划；
7. 创建 `DamagePlan`；
8. 写入伤害类型、护甲穿透、发射者、来源宿主、意图目标和语义上下文；
9. 写入配置的 `HitPartResolutionMode`；
10. 添加到 `contribution.ExtraDamagesToAppend`。

身体部件百分比模式使用：

```csharp
float bodyPartMaxHealthSum = 0f;
foreach (BodyPartRecord part in target.health.hediffSet.GetNotMissingParts())
{
    bodyPartMaxHealthSum += part.def.GetMaxHealth(target);
}

float damageAmount = bodyPartMaxHealthSum * config.Ratio;
```

不要读取当前伤口剩余血量；不要把已缺失部件计入总和。
