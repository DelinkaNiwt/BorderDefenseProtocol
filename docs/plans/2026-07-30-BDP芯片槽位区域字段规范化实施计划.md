# BDP 芯片槽位区域字段规范化 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 把芯片装载侧的 `SidePolicy / HandsOnly / SpecialOnly（侧别策略/只进手区/只进特殊槽区）`不兼容迁移为必填的 `SlotRegion / MainSub / Special（槽位区域/主副槽区/特殊槽区）`，并让漏填成为明确的定义错误。

**Architecture:** Core（核心程序集）只保留一个中性的 `ChipSlotRegion（芯片槽位区域）`枚举，配置、契约、运行快照和消费者使用同一语义。`Unspecified（未指定）`只承担缺失检测，定义校验拒绝它；候选内容只做等义字段迁移，不改装载行为和业务参数。

**Tech Stack:** RimWorld 1.6 XML（边缘世界1.6定义文件）、C#（C#语言）、PowerShell（自动检查脚本）、.NET Release（发布）构建、Git（版本控制）

---

## 执行约束

- 按项目要求直接在当前 `main（主线）`工作，不创建分支或 worktree（工作树）。
- 不做旧字段兼容；旧名称必须物理删除。
- 本计划只处理槽位区域字段，不处理 `SlotOccupancy（槽位占用方式）`、互斥组、启停延迟、事项07A或事项07B。
- 候选库正常芯片只做等义迁移；故意非法的 `BDP_TestChipInvalidDefinition`继续缺失区域字段。
- 不调整任何芯片、攻击、Trion（能量）、护盾、追踪、毒蛇、弧月或旋空弧月参数。
- 每一阶段只提交本计划明确列出的文件；保留工作区原有无关改动。

## 正式结构

配置示例：

```xml
<Loadout>
  <SlotRegion>MainSub</SlotRegion>
</Loadout>
```

枚举：

```csharp
public enum ChipSlotRegion
{
    Unspecified = 0,
    MainSub = 1,
    Special = 2
}
```

校验规则：

```text
Unspecified 或未填写
  → 定义错误

MainSub
  → 允许 Main（主槽）与 Sub（副槽）
  → 拒绝 Special（特殊槽）

Special
  → 只允许 Special（特殊槽）
```

{
    /// <summary>
    /// 芯片所属的槽位区域。
    /// 它只区分主副槽区和特殊槽区，不描述具体槽位数量或占用方式。

    {

        /// 该值只用于缺失检测，不是合法的正式配置。

        /// 主槽与副槽共同组成的主副槽区。
        /// </summary>

}

**Step 5：迁移槽位判定**

```csharp
private static bool IsSlotRegionAllowed(
    ChipSlotRegion slotRegion,
    TriggerSide side)
{
    switch (slotRegion)
    {
        case ChipSlotRegion.MainSub:
            return side == TriggerSide.Main || side == TriggerSide.Sub;
        case ChipSlotRegion.Special:
            return side == TriggerSide.Special;
        default:
            return false;
    }
}
```

所有调用改读 `constraint.SlotRegion`。`Unspecified`和未知值都返回 `false`，这只是最后一道安全边界，不替代定义校验。
