# 铅弹对侧远程增强双分支设计

## 1. 需求结论

当前正式铅弹芯片拆分为两个玩家可见分支：

| 芯片 | 作用范围 | 芯片画像分类 | 表达类型 |
| --- | --- | --- | --- |
| 铅弹·改 | 主、副两侧全部远程射击 | 被动类 | Passive |
| 铅弹 | 只对另一侧远程射击 | 能力类 | Passive |

新“铅弹”的“能力类”只修改芯片画像中的 `Profile/Category`，不把表达条目的 `Kind` 修改为 `Ability`。它仍通过现有被动表达和远程模块增强机制提供效果，不新增 `AbilityDef`。

不考虑旧存档兼容。两个分支的 DefName、表达条目标识、PassiveKey 和语言键全部使用明确的新标识。

## 2. 当前实现事实

当前铅弹位于 `1.6/Content/Defs/ChipFunctionDef/Presets.xml`，其表达条目为 `Kind=Passive`，并通过 `RangedModuleAugmentations` 向远程武装结果追加 `BDP_RangedDebuff_LeadWeight`。

`ExpressionAugmentationResolver` 会收集当前激活的被动表达，并在复合结果生成前向远程结果追加模块。主侧和副侧结果已经保留 `SourceReference.Side`，双侧远程执行也已经分别消费主侧和副侧结果的模块列表。

因此，本需求不需要复制铅块负重模块，不需要新增铅弹专用攻击补丁，也不需要重写双侧攻击执行链。

## 3. 设计方案

### 3.1 通用作用范围

在 Core 的 `RangedModuleAugmentationConfig` 中增加中性作用范围字段和枚举：

- `AllSides`：增强对所有符合目标能力的侧别生效。
- `OppositeSide`：增强只对与来源结果不同的 Main/Sub 侧别生效。

默认值使用 `AllSides`，避免未填写字段的既有增强声明产生意外行为；正式铅弹 XML 显式填写作用范围，保证 Def 自身可读。

作用范围只由通用解析器判断，不读取芯片 DefName，不写铅弹专用分支：

```text
AllSides：      直接追加模块
OppositeSide：  Main 来源 → Sub 结果
                Sub 来源 → Main 结果
                Special 不参与对侧匹配
```

模块追加和动态远程入口名称前缀使用同一作用范围判断。高层双侧结果的实际投射物仍按主侧和副侧来源结果分别执行；对侧增强只进入应受影响的那一侧。

组合技既有模块继承边界不在本需求内扩展，本次只调整已经存在的开放式增强作用范围。

### 3.2 两个正式芯片

#### 铅弹·改

由当前全侧铅弹改名而来：

- `DefName`：`BDP_ChipFunction_LeadShotModified`
- 表达 `Id`：`lead_shot_modified_passive`
- `PassiveKey`：`BDP_LeadShotModified`
- `Profile/Category`：`BDP_ChipCategory_Passive`
- `Kind`：`Passive`
- 增强作用范围：`AllSides`

制造参数、槽位、Trion、激活条件、远程模块、投射物属性和命中反馈保持当前设计。

#### 铅弹

新增对侧远程增强芯片：

- `DefName`：`BDP_ChipFunction_LeadShotOppositeSide`
- 表达 `Id`：`lead_shot_opposite_side_passive`
- `PassiveKey`：`BDP_LeadShotOppositeSide`
- `Profile/Category`：`BDP_ChipCategory_Ability`
- `Kind`：`Passive`
- 增强作用范围：`OppositeSide`

除分类、技术标识、玩家可见文本和作用范围外，复用“铅弹·改”的现有配置。

新“铅弹”由于属于能力类芯片，会沿用普通能力芯片的侧级激活和互斥路径；它不享受被动类别的同侧默认互斥豁免。它的预期使用方式是激活在一侧，增强另一侧的射击芯片。

### 3.3 语言包

所有玩家可见名称、说明和动态表达名称都放入简体中文语言包。两个分支使用互不混淆的语言键，文本中明确说明全侧或对侧作用范围。

## 4. 预期行为

```text
主侧：铅弹
副侧：小行星
结果：副侧小行星获得铅弹效果，主侧不获得
```

```text
主侧：铅弹·改
副侧：小行星
结果：主侧和副侧远程射击都获得铅弹效果
```

当形成双侧远程射击时，模块按实际发射侧独立生效，不把对侧增强重新扩散到来源本侧。

## 5. 修改范围

预计修改：

- Core 远程增强配置模型及其克隆逻辑；
- Core 远程增强解析器；
- 正式芯片功能 XML；
- 简体中文语言包；
- 远程增强和铅弹 Def 边界烟测。

明确不修改：

- `RangedDebuffModule` 和铅块负重 Hediff；
- 投射物命中、护盾绕过和攻击执行主链；
- 芯片激活架构；
- 其它芯片的分类和增强声明；
- 组合技模块继承语义。

## 6. 验证方案

### 静态与构建验证

1. 检查作用范围枚举、默认值、克隆链和解析器无业务芯片名称硬编码。
2. 解析正式 XML，确认两个 Def 唯一、技术标识不重复且旧标识不残留。
3. 确认“铅弹·改”为被动类，“铅弹”为能力类，但两者表达均为 `Passive`。
4. 确认两者都继续使用 `BDP_RangedDebuff_LeadWeight`。
5. 执行相关 PowerShell 烟测。
6. 构建 Core/Content Release，并执行 `git diff --check`。

### 游戏内验证

1. 主侧铅弹、副侧射击：只有副侧生效。
2. 副侧铅弹、主侧射击：只有主侧生效。
3. 铅弹·改在主、副两侧均生效。
4. 双侧远程射击时不发生串侧。
5. 新铅弹按能力类芯片的激活、关闭和同侧互斥规则运行。
