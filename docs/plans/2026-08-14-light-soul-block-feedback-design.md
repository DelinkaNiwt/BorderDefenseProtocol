# 光魂抵挡反馈与芯片按钮独立控制设计

## 目标

修正光魂大盾抵挡特效的方向与位置，为成功抵挡增加短促受击回弹，并保证同时启用的两枚光魂芯片各自拥有独立的形态、姿态按钮。

## 根因

### 抵挡特效

灵活姿态与举盾姿态共用 `HediffComp_EnergyShield`。该组件先算出带小数的盾面命中点，随后却把它转换为 `IntVec3` 交给原版 `Deflect_Metal_Bullet`，因此小于一格的方向偏移被抹掉。它还把特效目标 B 传成 `TargetInfo.Invalid`；原版特效会按 A 到 B 的方向追加 `offsetTowardsTarget`，于是这段偏移稳定朝向无效坐标一侧，表现为 Pawn 南偏西。

原版子弹和 BDP 子弹都会把飞行角写入 `DamageInfo.Angle`，远程方向数据本身有效。原版近战则用 `-1` 构造伤害角，`DamageInfo` 会把它随机化；所以举盾姿态允许抵挡近战时，120° 判定和特效方向都不能直接相信该角度。

### 按钮聚合

`Command_ChipMode` 与 `Command_ChipStance` 沿用原版 `Command.groupable = true`。两枚同类芯片生成的按钮具有相同标签、图标和默认组键，原版便将其合并，并把一次输入传播给组内所有按钮。

## 设计

### 攻击方向与原版特效

护盾在判定前解析一次“攻击行进角”：

- 远程与爆炸沿用 `DamageInfo.Angle`，保持弹道和爆心给出的原版真值。
- 近战在攻击者与受击者同地图且位置有效时，以攻击者中心指向受击者中心计算；无法解析时才回退 `DamageInfo.Angle`。

这一个角度同时用于防护弧判定、盾面命中点和回弹方向，避免三套方向各算各的。

`Deflect_Metal_Bullet` 继续复用原版定义。源目标 A 使用受击 Pawn，目标 B 使用攻击者；没有有效攻击者时，按攻击来源方向构造邻近目标格。通过 `Effecter.offset` 抵消原版固定的 `offsetTowardsTarget` 并补足小数盾面半径，使火花最终中心落在精确命中点。闪光与音效保持现有链路。

### 盾面受击回弹

Core 提供中性的“表达视觉瞬时位移”运行时能力，不认识光魂或护盾业务。Content 在抵挡成功后，以当前表达 Hediff 为来源发布一次位移冲量：先沿攻击行进方向向 Pawn 内侧短促后退，再小幅反向回弹并归零。

位移记录按正式表达结果 ID 保存；绘制时只叠加到对应常驻视觉条目的主贴图与附加层，不改变 Pawn、宿主装备、枪口锚点或其它芯片。形态切换导致投影版本变化时，旧冲量随运行时视觉状态一起清空。

光魂在两个护盾 Hediff 的 XML 中分别声明持续时间、位移距离。初始值为 8 tick、0.08 格，后续可直接调参。若同一个表达 Hediff 由两枚相同芯片共同发布，两张有效盾面都响应这次抵挡，符合当前聚合 Hediff 的实际防护语义。

### 独立按钮

形态与姿态按钮在构造时显式设为不可聚合。按钮闭包仍只捕获自身芯片实例，右键菜单也继续向同一实例提交请求；不修改 Core 的通用 Gizmo 规则。

## 验证

- 纯计算测试覆盖四个来袭方向、近战攻击者方向回退和回弹关键帧。
- 结构测试确认原版特效取得有效 A/B、精确偏移，两个姿态均配置回弹参数。
- Gizmo 测试确认形态和姿态命令均关闭聚合。
- 构建 Core、Content，并运行相关冒烟测试。
- 游戏内分别验证灵活姿态远程、举盾姿态远程、举盾姿态近战，以及两枚光魂独立切换。
