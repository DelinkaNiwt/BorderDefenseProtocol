# 玩家控制边界与敌方芯片即时启停

最新状态：用户复审后已将即时启停与资源简化范围确认为**非玩家派系人物，包含无派系**；原版控制资格只用于手动入口。修正已实施，见[最新修正记录](2026-10-06-非玩家派系规则与自动近战修正.md)。下文保留此前敌方限定的实施过程。

## 目标与边界

- 用户要求敌对单位芯片启停免延迟；按钮权限按原版玩家可控资格处理，不以敌对或玩家派系代替。
- 原版 `Pawn.IsPlayerControlled`（玩家可控）与攻击按钮的 `CanOrderPlayerPawn`（允许下令）等价，覆盖可控殖民者、机械体和异变体。原版任务队伍可通过 `AllowsDrafting`（允许征召）禁用战斗命令；不可控人物仍可以有状态信息与开发工具。
- 手动界面控制与自动业务运行分别判断。敌方免延迟按当前敌对关系提供，不扩大到访客、盟友、囚犯或暂时失控的玩家人物。不修改原版全局逻辑，不新增派系状态缓存，不处理已记录的自动近战任务替换问题。

## 最小方案

1. 核心新增单一可插拔启停延迟规则口；触发体的延迟解析器取得当前持有者，普通规则继续返回芯片原配置。内容程序集注册当前敌方免延迟提供器。正式切换流程已有零时长立即提交分支，沿用原生命周期、互斥与身体资格校验，不直接写激活标记。
2. 共同装备按钮入口改用原版玩家可控判断，并沿用任务队伍禁止征召时的禁用原因；覆盖攻击、变身、模式、姿态和浮空等扩展按钮。多选远程武器识别采用同一原版资格。
3. 补齐独立的芯片槽位点击和光魂注视警戒操作。资源状态面板保留既有可见规则，只禁止不可控人物的调试资源写按钮。黑触发器献祭已有更窄的可控殖民者业务门槛，原版能力按钮已有原版筛选，不改其业务资格。
4. 编译核心与内容，确认程序集依赖边界，检查差异；更新工作日志并精确提交。游戏实测覆盖敌人、盟友、精神失常玩家人物、正常可控人物与任务禁止征召人物；敌方生成时芯片已激活，手动调试启停后不产生等待阶段。

## 方案取舍

共同解析口可覆盖普通、独立和同步启停，内容规则可移除，核心保持中性。逐芯片复制零延迟配置会留下重复成品；在各切换分支加敌对判断会遗漏入口。因此采用共同解析口。界面直接复用原版资格，不另建身份系统。

## 实施与验证

- 已接通中性延迟规则口及敌方内容提供器。共同启停解析器按需读取当前持有者，普通、独立、同步流程均继续使用原回调；不改变身体条件、装载和互斥资格，也不改变芯片资产的配置。
- 共同装备按钮、多选远程识别改用原版玩家可控资格；装备操作及注视警戒命令沿用任务队伍禁止征召的禁用原因。槽位操作面板在不可控或任务禁止征召时不提供，独立资源条仍沿用原可见规则；资源调试写按钮也不向不可控人物提供。
- 原版能力追踪器负责普通能力按钮的控制资格筛选，黑触发器献祭已有更窄的可控殖民者业务条件；均不增加重复筛选补丁。未修改自动攻击与自动近战任务的派单逻辑。
- 核心、内容编译成功，核心程序集依赖边界检查通过。临时离线夹具直接调用编译后的真实启停解析器，验证默认时长、免启停延迟、任意显式时长、持有者变化、规则变化及移除规则；夹具运行后已删除。原有真实资源行为回归通过。
- 尚未由代理进入游戏验证界面和正式切换时序；需重启游戏后生成新敌人，确认两颗芯片即时激活，再比较不可控人物与正常可控人物的操作界面。既有存档中已经开始的等待阶段未被本轮强制改写。
