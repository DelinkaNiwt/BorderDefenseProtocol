# BDP远程模块全链路真实接通设计方案（第一版）

## 1. 目标

本方案用于一次性解决当前 BDP 远程模块化系统里的“半接通”问题。

这里所说的“半接通”，指的是：

- 作者能看到接口。
- 作者能写入字段。
- 协议能生成记录或计划。
- 但宿主没有真实执行。

本次设计的最终要求只有一条：

**任何对作者开放的能力，都必须从作者输入一路真实落到游戏行为；做不到的能力，不再对作者开放。**

---

## 2. 本次设计的总原则

### 2.1 原版基线原则

- `BdpProjectile` 继续继承原版 `Bullet`。
- 手动瞄准、目标选择、发射、命中、伤害、爆炸，仍尽量复用原版链路。
- 只有原版确实没有可直接承载的地方，才做最小补位。

### 2.2 中性协议原则

- 主骨架只认阶段、记录、计划、裁决、冻结。
- 主骨架不认知任何具体业务模块。
- 主骨架不为爆炸、穿透、追踪、范围指示之类具体业务写专门分支。

### 2.3 真实接通原则

每一项能力必须满足二选一：

- 真正接通到宿主行为。
- 从作者开放面移除。

不允许继续保留第三种状态：

- 字段存在，但只是记录、标签或伪能力。

### 2.4 封闭裁定原则

某个能力是否继续开放给作者，不以“当前有没有做完实现”作为判断标准。

正确标准是：

- 如果它表达的是**作者可理解、协议中性、可由基线宿主最小补位消费**的能力，就应继续开放，并补实现。
- 如果它只是**内部同步字段、派生字段、重复字段、或没有独立行为语义的实现细节**，才应封闭。
- 如果它虽然听起来很强，但实际上没有统一裁决方式、没有统一执行语义，继续开放只会制造假能力，也应封闭。

也就是说：

**缺实现，是施工问题，不是封闭理由。**

### 2.4.1 开放与封闭的具体判断示例

为避免后续再次把“暂未接通”误判成“应该封闭”，本次直接给出具体判断样例：

- `Aim.AccuracyFactorMultiplier` 应开放：
  - 它表达的是作者可直接理解的业务意图：让本次射击更准或更不准。
  - 它可以自然映射到原版命中/失准裁决。
  - 因此应补宿主接线，不应封闭。
- `Flight.ContinueFlight` 应开放：
  - 它表达的是作者可直接理解的业务意图：这一发在一次到达后是否继续下一段飞行。
  - 它不绑定爆炸、穿透、追踪等具体业务，是协议中性的续行意图。
  - 因此应开放，并由内部桥负责收口执行。
- `Arrival.ContinueFlight` 不单独开放：
  - 它不是新的作者业务意图，而是 `Flight.ContinueFlight` 被宿主消费前的内部收口真值。
  - 它的职责是把“作者想继续飞”翻译成“此刻 projectile 是否进入下一段飞行”。
  - 因此它应保留为内部桥，不应成为第二套作者入口。
- `Arrival.NextDestination` 不单独开放：
  - 它是内部续行桥计算后的下一段目的地结果。
  - 作者若要影响它，应通过 `Flight.RedirectDestination` 等上游正式能力表达，而不是直接改内部桥结果。

结论：

- 只要某项能力是**独立、可理解、可裁决的作者意图**，就应开放。
- 只要某项能力只是**内部桥接后的收口结果**，就应内部化。
- 作者并不是“不能影响内部值”，而是应通过上游正式阶段**间接塑形**内部值，而不是直接改内部桥。

### 2.5 简化优先原则

当前系统里凡是已经出现“字段很多、链条很长、真实落点很少”的部分，统一按下面规则处理：

- 能贴着原版落地的，保留并接通。
- 不能贴着原版稳定落地的，删掉开放面，不强行做未来感预留。

## 3. 本次设计的总体裁定

本次设计不走“把所有半成品字段都硬接成大而全系统”的路线。

而是正式裁定为：

### 3.1 保留并真实接通

- `ManualEntry`（手动入口）
- `Targeting`（目标选择）
- `Preview`（预览）
- `Confirm`（确认）
- `Aim`（瞄准）中的少量基线可落地能力
- `Fire`（发射）中的基线可落地能力
- `Flight`（飞行）中的少量宿主可消费能力
- `Impact`（命中结果）中的中性计划执行能力

### 3.2 从作者开放面移除

下列能力不再继续作为作者可直接依赖的公开能力：

- `Aim.ValidationPassed`
- `Aim.AimPointWorld`
- `Aim.AimOffsetWorld`
- `Aim.PathCells`
- `Aim.PathVariance`
- `Aim.GuideCell`
- `Fire.EnableAutoRouteFire`
- `Flight.OverrideLockedTarget`
- `Flight.OverridePhase`
- `Impact.ExtraEffects`

### 3.3 从内部骨架清理或下沉

下列内部半成品能力不再继续保留成“看似完整”的协议骨架：

- `Arrival.NewCurrentTarget`
- `Arrival.NewLockedTarget`
- `Arrival.ForceGroundImpact`
- `Hit.ContinueAfterHit`
- `Hit.PassthroughRemaining`
- `Hit.SpawnSecondaryProjectiles`
- `Hit.SecondaryProjectileCount`
- `ProjectileInit.PathSeedCells`
- `ProjectileInit.GuideSeedCell`
- `ProjectileInit.RetargetingEnabled`

它们的处理方式不是“先留着以后再说”，而是：

- 要么缩成内部最小记录。
- 要么彻底删去相关对外承诺。

## 4. 最终阶段开放面

本次设计完成后，作者仍然只面对 8 个正式阶段，但每个阶段只保留真实可用字段。

### 4.1 `ManualEntry`（手动入口）

保留能力：

- 改按钮名称
- 改按钮说明
- 改按钮图标
- 隐藏按钮

理由：

- 这部分已经完整接到按钮生成链。
- 原版与 BDP 都有明确承载点。

---

### 4.2 `Targeting`（目标选择）

保留能力：

- 改是否可进入原版目标选择
- 改是否允许多选
- 改是否隐藏 Pawn tooltip
- 改目标参数

理由：

- 这部分已经完整接到 `AttackExecutionTargetingSource`。
- 改动是原版 `Targeter` 可直接消费的表面。

---

### 4.3 `Preview`（预览）

正式裁定：

`Preview` 阶段继续保持为**原版预览维度开关层**，不扩展为作者自绘画布。

保留能力：

- `UseVanillaRangeRing`：是否保留原版射程圈
- `UseVanillaTargetHighlight`：是否保留原版目标高亮
- `UseVanillaFieldRadius`：是否保留原版范围反馈
- `UseVanillaMouseAttachment`：是否保留原版鼠标附着图标

不新增能力：

- 不提供“模块自行绘制预览图形”的入口
- 不提供“模块接管整个 Targeter GUI”的入口

理由：

- 这样最贴近原版。
- 这样最稳定。
- 这样最不容易把预览层变成独立 UI 系统。

---

### 4.4 `Confirm`（确认）

保留能力：

- 修改最终确认目标
- 阻止本次攻击下单
- 修改确认原因
- 修改派单意图
- 写入拒绝原因

新增要求：

- `RejectReason` 必须有统一反馈出口。
- 当模块阻止确认时，玩家必须能收到一条明确提示。

理由：

- 这属于玩家交互链路的最后校验点。
- 不能只在记录里写原因而没有实际反馈。

---

### 4.5 `Aim`（瞄准）

本次设计后，`Aim` 只保留下面这些真实可落地能力：

- `AbortRequested` / `AbortReason`：中止当前执行
- `OverrideFinalTarget`：覆盖最终目标
- `AccuracyFactorMultiplier`：修改原版命中/失准裁决倍率
- `ForcedMissRadiusCandidate`：覆盖或扩大强制失准半径
- `Tags`：阶段标签

移除出作者开放面的能力：

- `ValidationPassed`
- `AimPointWorld`
- `AimOffsetWorld`
- `PathCells`
- `PathVariance`
- `GuideCell`

理由：

- `AccuracyFactorMultiplier` 可以自然映射到原版命中/失准裁决，是作者可理解、且可由基线宿主最小补位消费的能力，因此应保留并补实现。
- 其余字段当前没有稳定贴着原版的真实落点。
- 如果强行保留，只会继续制造“看似开放、实则无效”的伪能力。

最终定义：

`Aim` 是一个**目标与强制失准裁定层**，不是一个自定义弹道编辑器。
它保留少量原版可理解的命中裁决调制能力，但不承担内部弹道翻译职责。

---

### 4.6 `Fire`（发射）

本次设计后，`Fire` 保留下面这些真实能力：

- `OverrideProjectileDef`：覆盖投射物 Def
- `OverrideFireCount`：覆盖发射数量
- `AddedOriginOffsetWorld`：追加发射原点偏移
- `AddedSpreadOffsetWorld`：追加每发散布偏移
- `SpeedFactorMultiplier`：每发初始速度倍率
- `DamageFactorMultiplier`：每发初始伤害倍率
- `Tags`：阶段标签

移除出作者开放面的能力：

- `EnableAutoRouteFire`

理由：

- 发射数量、每发偏移、投射物覆盖，都是当前宿主可以直接消费的。
- `EnableAutoRouteFire` 目前没有稳定宿主意义，不应继续挂在作者面上。

---

### 4.7 `Flight`（飞行）

本次设计后，`Flight` 只保留下列真实飞行能力：

- `RedirectDestination`：重定向本发真实目的地
- `OverrideCurrentTarget`：覆盖当前追踪目标
- `ContinueFlight`：命中/到达后继续进入下一段飞行，而不是结束本次弹体
- `SpeedFactorMultiplier`：飞行过程速度倍率
- `DamageFactorMultiplier`：飞行过程伤害倍率
- `Tags`：阶段标签

移除出作者开放面的能力：

- `OverrideLockedTarget`
- `OverridePhase`

理由：

- `RedirectDestination` 和 `CurrentTarget` 可以由宿主最小接线真实消费。
- `ContinueFlight` 是作者可理解、协议中性的飞行续行意图，不应因为当前未接完就被封闭；正确做法是补上宿主续行桥。
- 速度倍率可以通过 `BdpProjectile` 的最小补位真实生效。
- `OverrideLockedTarget` 当前没有独立、稳定、可观察的基线宿主语义；如果不同时开放一整套锁定策略，它就是孤立字段，因此应封闭。
- `OverridePhase` 属于协议内部实现状态，不是作者业务意图，应封闭。

最终定义：

`Flight` 是一个**有限飞行修正层**，不是一个完整导弹 AI 系统。
它负责表达作者可理解的飞行意图，不负责暴露内部收口桥。

---

### 4.8 `Impact`（命中结果）

本次设计后，`Impact` 保留：

- `SuppressBaselineImpact`
- `DirectDamage`
- `AreaEffect`
- `ExtraDamages`
- `Tags`

移除：

- `ExtraEffects`

理由：

- 直接伤害和范围效果已经能稳定落回原版 `TakeDamage` 与 `GenExplosion.DoExplosion`。
- `ExtraEffects` 当前没有统一执行器，也没有原版稳定承载面，继续保留只会制造假开放。

最终定义：

`Impact` 是一个**中性命中计划层**，负责告诉宿主“命中后执行什么”，而不是让模块直接接管宿主。

---

## 5. 内部骨架最终收口

先明确一条：

- `Prepare / ProjectileInit / Arrival / Hit` 保持内部，不是因为“作者不需要”，
- 而是因为它们的职责是**把作者阶段已经表达好的业务意图翻译给下游宿主**。

也就是说：

- 作者阶段负责回答“我想改什么”
- 内部桥负责回答“系统怎么把这个改动送到宿主”

因此：

- 合理业务意图应上提到作者阶段
- 纯翻译桥不直接开放

### 5.1 `Prepare`

保留为内部阶段。

作用：

- 给基线执行前做内部准备与中止。

不对作者开放。

理由：

- 作者真正的业务意图应写在 `Confirm / Aim / Fire`。
- `Prepare` 只负责在协议内部做执行前翻译与整理。

### 5.2 `ProjectileInit`

保留为内部阶段，但缩减为真实初始化计划翻译层。

保留字段：

- `ProjectileDef`
- `OriginOffsetWorld`
- `OriginSpreadRadius`
- `AbsoluteOriginWorld`
- `LaunchTarget`
- `AimTarget`
- `CurrentTarget`
- `InitialSpeedFactor`
- `InitialDamageFactor`
- `ModuleSession`
- `SemanticContext`

清理字段：

- `PathSeedCells`
- `GuideSeedCell`
- `RetargetingEnabled`
- 其他没有真实消费面的导引类字段

理由：

- 它的职责是把 `Fire` 结果翻成投射物初始化计划。
- 其中可理解的作者意图已经分别由 `Fire / Aim / Flight` 承接。

### 5.3 `Arrival`

保留为内部最小到达与续行桥接层。

最终只回答：

- 当前 projectile 已到达哪个格
- 当前命中前的现场目标是谁
- 是否继续飞
- 下一段应朝向哪里

不再承担：

- 改锁定
- 改目标
- 强制地面命中决策

补充说明：

- `ContinueFlight` 虽然对作者开放在 `Flight` 阶段，
- 但宿主真正进入“继续飞还是进入命中”的收口判断，仍要通过内部 `Arrival` 桥做最小翻译。
- 因此 `Arrival` 自身不作为作者阶段开放。

### 5.4 `Hit`

保留为内部最小命中快照层。

最终只回答：

- 命中了谁
- 命中格是什么
- 是否是地面命中

不再承担：

- 穿透续飞
- 次级投射物调度
- 剩余穿透量

理由：

- `Hit` 的职责是把命中现场压成最小事实。
- 作者若要表达命中后的业务效果，应写在 `Impact`，而不是直接改内部命中快照。

## 6. 宿主层的最终职责

### 6.1 `BdpVerb_Shoot`

最终职责：

- 消费正式 `ProjectileInitPlan`
- 生成原版 projectile
- 使用正式计划中的发射原点、散布、投射物 Def
- 使用正式计划中的强制失准结果

新增要求：

- 不再只依赖旧 `ResolvedVerbSpec.ForcedMissRadius`
- 必须优先消费远程协议 `Aim` 已裁定后的强制失准真值

### 6.2 `BdpProjectile`

最终职责：

- 继续继承 `Bullet`
- 每 tick 消费有限的 `FlightRecord`
- 真正执行：
  - 目的地重定向
  - 当前目标覆盖
  - 速度倍率
  - 伤害倍率累积
- 命中时执行：
  - `Arrival`
  - `Hit`
  - `Impact`
  - 原版伤害/爆炸落地

不再承担：

- 多段续飞状态机
- 穿透链主调度
- 次级投射物派生系统

## 8. 测试与文档标准

### 8.1 测试标准

本次设计完成后，每一项保留的作者能力都必须有 smoke 证明：

- 写入生效
- 会话冻结正确
- 宿主真实消费
- 游戏行为发生变化

### 8.2 文档标准

所有作者说明文档只允许描述以下两类内容：

- 已真实接通的能力
- 明确禁止作者使用的能力

不允许再写：

- “现在虽然没接完，但以后会支持”
- “这个字段先留着备用”

## 9. 本次设计完成后的系统形态

完成后，BDP 远程模块系统会变成一个更干净的结构：

- 玩家作者看到的阶段仍然是 8 个。
- 每个阶段只保留真实有效能力。
- 内部骨架缩回最小必需集。
- `BdpVerb_Shoot` 与 `BdpProjectile` 只做中性宿主消费。
- 没有模块时，整体继续尽量表现为原版远程攻击。

这才是符合当前项目体量、RimWorld 原版基线，以及 BDP 模块化目标的正式收口形态。
