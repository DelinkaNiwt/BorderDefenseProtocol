## 手动类型失效的时序

真实第三方程序集与原版程序集确认的调用关系：

```text
BDP 配置：蝎子手动穿刺
  → 兼容层 SpawnPrefix 将纹理参数设为 Stab
  → 第三方 SpawnEffecterLayer
      → WeaponVfxTextureOverride.Apply：临时替换共享 FleckDef 的图像
      → EffecterDef.Spawn：创建粒子，粒子保留 FleckDef 引用
      → finally / GraphicRestoreToken.Restore：立即还原共享 FleckDef 图像
  → 后续 FleckStatic.Draw
      → def.GetGraphicData：此时才读取图像
      → 读到已还原的挥砍图像
```

关键方法：第三方 `DGJY_MeleeVfxSpawner.SpawnEffecterLayer`、`DGJY_WeaponVfxTextureOverride.Apply`、`GraphicRestoreToken.Restore`；原版 `FleckStatic.Setup`、`FleckStatic.Draw`、`FleckDef.GetGraphicData`。

原版粒子没有在创建时冻结图像。因而临时改定义后立即还原不能实现持久的逐次粒子贴图覆盖。这是第三方手动覆盖实现与原版绘制时序的冲突，BDP 当前适配复用了这一失效入口。此前行为夹具只确认分类、配置读取、生成参数和补丁安装，没有覆盖真实粒子后续绘制，未能发现这处问题。

## 挥砍与钝击相似的资源原因

对当前安装目录 `1.6/Textures/FlashingBlades` 进行 SHA256（文件指纹）核对，三组文件逐一相同：

| 文件对 | SHA256 |
|---|---|
| Slash_A / Blunt_A | AB1F16259BF85DB1A42E81124B29871074B10C0B3629133B0DE7E0068AE26831 |
| Slash_B / Blunt_B | A9AD9AC3849D4430CD0E7BCE548DCC52C9BFD50BD531D64735AE082736976AEA |
| Slash_C / Blunt_C | BEBE479AF392D2B7EF7CD91F42A48627D8E4D55EC9C8965CBA438F90CEF8EF0A |

穿刺三张图像均与上述不同。第三方钝击效果与挥砍在速度、透明度等参数上有所不同，钝击主效果还包含目标处的闪光；不能把“拖尾图像相同”扩大成“全部效果参数相同”。
