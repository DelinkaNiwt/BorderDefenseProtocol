# BDP 芯片制造台重做 Implementation Plan（实施计划）

> **For Claude（给执行代理）:** REQUIRED SUB-SKILL（必需子技能）: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal（目标）:** 把现有芯片制造业务替换为一套以 RimWorld 原版工作台、账单和半成品流程为骨架，支持动态动作/枪壳组合、三栏制造面板、任务队列与安全失效迁移的正式系统。

**Architecture（架构）:** Core.dll（核心程序集）只保留中性的“芯片实例定义提供器”和“来源引用提供器”，Content.dll（内容程序集）独占职业、动作预设、枪壳、组合记录、解析合成、动态材料/工作量、工作台、账单、半成品、界面与迁移业务。制造流程复用 `Building_WorkTable`（原版工作台）、`Bill_ProductionWithUft`（带半成品的生产账单）、`UnfinishedThing`（原版半成品）、`WorkGiver_DoBill`（原版执行账单工作）和 `Toils_Recipe`（原版配方工作步骤），只对动态零需求材料槽、跨制作者续作和组合记录匹配做类型限定补丁。

**Tech Stack（技术栈）:** C# 7.3、.NET Framework 4.8、RimWorld 1.6、Verse/RimWorld 原版 API（应用程序接口）、Harmony（和谐补丁库）、XML Def（定义）、PowerShell 5.1 冒烟/反射测试。

**Step 3: 实现单一解析入口**

解析器公开唯一主入口：

```csharp
public ChipCombinationResolution Resolve(ChipCombinationRecord record)
```

解析顺序必须固定：

1. 解析主分类、职业、有序动作和可空枪壳 Def。
2. 任一 DefName 查不到，返回 `MissingSource`，保留记录和 `LastResolvedLabel`。
3. 全部来源存在后，检查分类、职业、动作数量、多形态和枪壳兼容。
4. 双动作检查槽位结构、条件合并器和扩展合并器；任何无规则项返回 `Invalid`。
5. 合成芯片配置，再按动作顺序生成形态 1/2；形态内 `UseCost`（使用消耗）和 `MinimumRequired`（最低需求）独立保留。
6. 最后施加枪壳覆盖；枪壳只施加一次。
7. 单动作标签为动作标签；双动作为 `A / B`；内置多形态使用预设自身标签；不提供手动改名。
