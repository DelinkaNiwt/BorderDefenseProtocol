# 芯片表达契约重构实施计划（第一版） Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将主模组的芯片正式输入从“按四类来源列表组织”一次性重构为“统一条目契约 + 形态操作”，并同步回收表达系统 `Contract -> Pipeline -> Projection` 全链，保证主模组内部边界更清楚、外部内容作者的写法更稳定直观。

**Architecture:** 本次不做长期双轨兼容。先定稿文档和目录分层，再在代码中新增 `Contract` 层、改写 `Config` 结构、删除旧四列表主读法、让 `Pipeline` 只消费契约对象，最后回收 `Projection` 和示例 Def。整个任务必须一次性把“芯片契约”这个最上游输入切干净，避免继续污染 Trigger、Pipeline、Projection 的边界。

**Tech Stack:** C# 7.3, .NET Framework 4.8, RimWorld `DefModExtension` / `ThingComp` / `Verb` / `Ability` / `Hediff`, XML Def, `dotnet msbuild`

---

## 总执行原则

- 不保留旧四列表作为未来主结构
- 不让 `Pipeline` 再直接解释原始芯片配置
- 不让 Trigger 负责芯片条目解释
- 不把从属关系做成重系统；只保留轻量契约语义
- 每个阶段都必须能编译
- 每个阶段都必须同步回写文档和日志，避免代码与标准脱节

## 完成标准

本计划完成时，应同时满足：

- 芯片正式配置结构已经改为统一 `Entries`
- 形态配置已经改为 `Operations`
- 主模组存在 `Core/Expressions/Contract`
- `Pipeline` 已改为只消费契约对象，不再直接读旧四列表
- 旧四列表主读法已被删掉，不再作为主设计继续使用
- DevHarness 示例芯片 Def 已迁移到新结构
- BDP 主模组与 DevHarness 均可编译
- 文档、计划、交接日志已经回写为新结构事实
