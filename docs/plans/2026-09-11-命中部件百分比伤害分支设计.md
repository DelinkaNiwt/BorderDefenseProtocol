# 命中部件百分比伤害分支设计

## 目标

在现有通用 `RangedExtraDamageModule`（远程额外伤害模块）中新增一种伤害量计算模式：

```text
命中部件最大生命值 × 配置比例
```

保留已有的固定伤害和“所有未缺失部件最大生命值总和百分比”模式。风刃可以选择新模式，但不新增风刃专用运行时模块。

## 已确认事实

1. 额外伤害模块在 `Impact`（命中效果）阶段生成 `DamagePlan`（伤害计划）。
2. 普通命中的具体身体部件由原版 `TakeDamage`（承受伤害）过程确定；进入 `Impact` 阶段时不一定已经知道。
3. `DamageWorker.DamageResult.LastHitPart`（原版伤害结果的最后命中部件）可以提供实际结果。
4. `VitalHitModule`（命中要害模块）只提交命中部件覆盖值，不应被额外伤害模块直接引用。

## 推荐方案

### 1. Core（核心基础设施）增加中性延迟伤害量解析口

`DamagePlan` 增加可选的 `IDamageAmountResolver`（伤害量解析器）。Core 只负责在正式执行伤害前，把以下中性事实传给解析器：

- 目标 `Thing`（承伤对象）；
- 最终解析出的 `BodyPartRecord`（身体部件）。

Core 不知道“百分比伤害”的业务含义，也不引用 Content（正式内容）模块。

### 2. Core 在主伤害完成后确定共享部件

执行额外伤害前，按以下顺序获取共享部件：

1. 优先读取主伤害 `DamageResult.LastHitPart`（原版最终命中部件）；
2. 若原版结果没有部件，再回退到 `ImpactPlan.HitPartOverride`（模块显式提交的部件）；
3. 若仍为空，额外伤害的部件百分比解析器返回零，避免自行重新随机部件。

所有设置为 `InheritImpactHitPart`（继承命中部件）的额外伤害计划，都复用这个结果。

### 3. Content 只实现业务计算

`RangedExtraDamageModule` 增加 `HitPartMaxHealthPercent`（命中部件最大生命值百分比）模式，并提交一个 Content 侧解析器：

```text
amount = hitPart.def.GetMaxHealth(target) × max(0, ratio)
```

最终伤害仍通过原版 `TakeDamage` 入口执行，因此原版护甲、伤害类型和承伤链保持不变。

## 交互与边界

- `VitalHitModule` 和额外伤害模块仍互不认识。
- 两个模块搭载时，VitalHit 提交的部件会成为主伤害实际部件，额外伤害读取同一部件。
- 普通随机命中时，额外伤害读取原版伤害结果中的实际部件。
- 若主伤害被护盾拦截、没有进入原版伤害工作器，或没有解析出部件，新模式不追加伤害。
- “最大生命值百分比”不等于无视护甲的真实生命值扣除；额外伤害仍遵守配置的伤害类型与护甲穿透。

## 配置

通用模块新增 `HitPartMaxHealthPercent`（命中部件最大生命值百分比）能力，当前风刃挂载选择该模式：

```xml
<AmountMode>HitPartMaxHealthPercent</AmountMode>
<Ratio>0.10</Ratio>
<DamageDef>Cut</DamageDef>
<HitPartResolutionMode>InheritImpactHitPart</HitPartResolutionMode>
```

通用模块 Def 只保留中性定义：

```text
BDP_RangedExtraDamageModule
```

风刃在自己的 `RangedModules` 挂载项中提供业务配置；其他内容也可以使用同一模块并按需选择固定伤害、全身部件总和百分比或命中部件百分比模式。

## 验证

- 先增加失败烟测，证明新模式、延迟解析口和实际命中部件回传尚不存在。
- 实现后运行 Core、Content、Compatibility、Development 四个工程编译。
- 运行命中部件继承、通用额外伤害和风刃配置烟测。
- 解析相关 XML，扫描旧名称和 Core 到 Content 的反向依赖。
- 游戏内仍需用测试存档确认部件被基础伤害摧毁时的原版后续处理。
