# BDP 事项08A触发器类别与边境标准触发体转正设计

## 一、目标

把当前候选库中的 `BDP_TestTriggerBody（测试触发体）` 正式转为主模组的 `BDP_TriggerBody_BorderStandard（边境标准触发体）`，同时建立可被第三方模组扩展的触发器类别基础。

## 二、已确认设计

### 1. 两级关系

```text
TriggerCategoryDef（触发器类别定义）
└─ ThingDef（具体触发体款式）
```

类别只表达所属分类；具体触发体独立配置槽位、固定芯片和玩家控制权限。

### 2. Core公开类别

- Core新增公开 `TriggerCategoryDef`。
- `CompProperties_TriggerBody`新增必填 `triggerCategory` 字段。
- 类别漏填或引用未知Def都属于定义错误，不猜测默认类别。
- 第三方模组可依赖 `BDP.Core.dll`，用自己的DefName新增类别并让自己的触发体引用。

正式类别：

- `BDP_TriggerCategory_Border`：边境触发器
- `BDP_TriggerCategory_Neighbor`：近界触发器
- `BDP_TriggerCategory_Black`：黑触发器

### 3. 玩家显示

触发体的物品信息中显示：

```text
触发器类别：边境触发器
```

显示读取类别Def的玩家名称，不把类别名称硬编码到程序中。

### 4. 边境标准触发体

- 新DefName：`BDP_TriggerBody_BorderStandard`
- 玩家名称：边境标准触发体
- 主模组路径：`1.6/Content/Defs/Things/Equipment/Trigger/ThingDefs_TriggerBodies.xml`
- 类别：`BDP_TriggerCategory_Border`
- 主槽4个、副槽4个、特殊槽2个保持不变。
- 保留 `TriggerLoadoutPanelExtension`，继续显示右侧芯片控制面板。
- 不添加固定芯片。
- 不改变原版武器属性、工具配置、战斗体行为和槽位语义。
- 删除候选库旧的 `BDP_TestTriggerBody`，不做存档兼容。

用户提供的512×512透明PNG作为正式物品贴图，直接复制到：

```text

```


### 6. 玩家芯片配置边界

类别不直接决定玩家是否可以配置芯片；这项能力属于具体触发体自己的Core配置。

```text
CompProperties_TriggerBody
├─ triggerCategory       -> 触发器所属类别
└─ loadoutControlMode    -> 玩家可配置 / 玩家不可配置
```

- `PlayerConfigurable`：允许玩家通过正式装配入口装入、卸下和调整芯片。边境标准触发体显式使用此模式。
- `PlayerNonConfigurable`：玩家不显示可配置面板，也不能从装配台或正式装卸命令修改芯片。
- 控制模式只决定玩家之后能否修改，不限制触发体是否通过定义文件获得初始芯片；两种模式都允许填写初始固定装载表。
- `TriggerLoadoutPanelExtension`仍只负责Content面板是否显示，不能作为底层权限判断。
- 装配台入口、装配窗口、装配事务和Core正式装卸命令都必须执行同一边界检查，避免只隐藏界面留下可操作后门。
- 固定芯片的具体写法与首次生成规则见《2026-08-01-BDP事项08A固定芯片初始装载设计》；本阶段仍不创建近界、黑或边境特制触发体。

## 三、本次不处理

- 不创建边境特制触发体、近界触发体或黑触发体实例。
- 不调整芯片业务定义、槽位数量、启停时序或攻击实现。
- 不迁移候选模组的其它芯片和上层应用。
