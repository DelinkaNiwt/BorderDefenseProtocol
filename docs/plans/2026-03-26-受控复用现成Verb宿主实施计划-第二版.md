# 受控复用现成 Verb 宿主 Implementation Plan（第二版）

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不让 `Trigger` 持有或创建 `Verb` 宿主、且完全移除 fallback/兼容路径的前提下，把 BDP 的正式攻击执行链改为只消费“表达宿主同步层”已同步出的完整现成 `Verb` 宿主实例，消除近战 `new Verb` 半初始化问题。

**Architecture:** 本版明确把“现成 `Verb` 宿主同步”下沉到 `Expressions/Projection` 层，作为与 `Ability / Hediff` 同级的原版宿主投影通道；`Trigger` 继续只承担装载真值、局部激活真值和来源事实读取，不持有运行时 `Verb` 宿主对象。`IExpressionVerbHostResolver` 改为只读已同步宿主，不再动态创建 `Verb`，也不保留 fallback 或兼容旧路径。

**Tech Stack:** RimWorld 1.6 C# Mod, Harmony, Verse/RimWorld 原版 `Verb / VerbTracker / CompEquippable` 运行时模型。

## 本版硬边界

### 边界 1：`Trigger` 不持有 `Verb` 宿主实例

- `CompTriggerBody` 只维护：
  - 槽位
  - 芯片容器
  - 激活态
  - 切换上下文
  - 来源事实读取面
- `CompTriggerBody` 不新增：
  - 宿主池字段
  - `Verb` 句柄缓存
  - `Verb` 创建逻辑
  - `Verb` 运行时生命周期管理

### 边界 2：`Expression` 层负责把正式结果投影成现成 `Verb` 宿主

- `ExpressionHostSynchronizer` 扩展为：
  - `Ability` 宿主同步
  - `Hediff` 宿主同步
  - `Verb` 宿主同步
- `Verb` 宿主仍只是“原版运行时宿主投影”，不是正式攻击真值。

### 边界 3：`Resolver` 只读，不创建

- `IExpressionVerbHostResolver` 只负责：
  - 按 `Pawn + FormalExpressionResult` 解析已存在宿主
- 它不再负责：
  - `Activator.CreateInstance`
  - fallback
  - 兼容旧缓存
  - 半初始化补丁

### 边界 4：彻底不保留 fallback / 兼容路径

- 不保留“现成宿主未命中则动态创建”的兜底路径。
- 不保留“先新逻辑，失败再回旧逻辑”的兼容桥。
- 一旦 `Verb` 宿主同步链未建立，正式执行直接失败，并在日志里诚实暴露。

## 目标状态

```text
Trigger
    -> 维护装载真值 / 激活真值 / 来源事实
    -> 不持有 Verb 宿主
    -> 不负责 Verb 运行时创建

Expression Source / Formal Result
    -> 只承载最小宿主来源定位信息
    -> 不承载运行时 Verb 对象

Expression Host Synchronizer
    -> 把当前正式结果同步为 Ability / Hediff / Verb 宿主
    -> Verb 宿主在这里创建、绑定、回收

IExpressionVerbHostResolver
    -> 只读取已同步好的 Verb 宿主
    -> 不做 new Verb
    -> 不做 fallback

AttackExecution
    -> 决定何时、为何、执行哪条正式结果
    -> 通过 resolver 取真实 Verb 宿主
    -> 执行器本身不拥有宿主缓存
```

## 非目标

- 不把芯片 `Verb` 塞进 `VerbTracker.AllVerbs`。
- 不把 `Verb` 重新升级成系统正式真值。
- 不在 `Trigger` 内新增任何运行时 `Verb` 宿主池。
- 不保留 fallback、过渡兜底、兼容旧解析路径。
- 不同时重做攻击编排、Targeting 适配层、Trigger 完整装载规则、多表达正式模型。
- 不引入单元测试体系。

## 关键裁定

### 裁定 1：为什么本版不允许 `Trigger` 持有宿主

- `Trigger` 当前已被裁定为“装载与局部激活真值 owner”。
- 如果把 `Verb` 宿主实例缓存、创建、回收再塞进 `Trigger`，就会把它重新推向运行时总控层。
- 本版只允许 `Trigger` 提供“来源事实”，不允许它提供“运行时宿主对象”。

### 裁定 2：为什么本版必须取消 fallback

- fallback 会天然形成第二条真实执行路径。
- 只要 fallback 还在，代码最终一定会继续依赖“动态 new 一个临时 `Verb` 也能跑”的旧结构。
- 本版目标不是“兼容旧问题”，而是“把旧问题对应的路径直接删掉”。

### 裁定 3：为什么 `Verb` 宿主同步要放在 `Expressions/Projection`

- 当前 `Ability / Hediff` 宿主同步已经在这里。
- `Verb` 也是“把正式结果翻译为原版宿主”的同类问题。
- 把三类宿主同步放在同一层，边界最诚实，也最符合现有 BDP 的“结果 -> 原版宿主投影”方向。

### 裁定 4：为什么 `BDP_Verb` 仍然保留

- `BDP_Verb` 继续承担：
  - 语义上下文
  - 自定义命中逻辑
  - 自定义连射/爆炸/多段行为
- 本版只改“宿主实例从哪里来”，不改“真实执行宿主长什么样”。
