# BDP 核心零模组程序集依赖检查实施计划

> **For future AI agents（给后续 AI 执行者）：** REQUIRED SUB-SKILL（必须使用的工作方式）：使用 `executing-plans（执行计划）` 逐任务实施，并使用 `test-driven-development（测试驱动开发）` 保证每段实现前先看到对应测试失败。不得创建 worktree（工作树），因为项目根规则明确禁止。

**Goal（目标）：** 建立自动构建门禁，保证 `BDP.Core.dll` 不依赖任何其他由 BDP 模组自身提供的 DLL（动态链接库）。

**Architecture（架构）：** PowerShell（命令行脚本）检查器自动读取 `Source` 下所有 `.csproj`（C# 工程）形成第一方程序集名单，再检查核心工程引用、编译 DLL 的 `AssemblyRef`（程序集引用表）以及核心源码/XML（配置文件）中的其他第一方专属名称。核心工程完成编译后调用同一检查器，违规时以非零退出码中止构建。

**Tech Stack（技术环境）：** PowerShell 5.1、旧式 MSBuild C# 工程、.NET Framework 4.8、RimWorld 1.6（边缘世界1.6）、Git（版本控制）。

---

## Task 1：实现可独立运行的三层检查器

**Files（文件）：**

- Create（新建）：`Source/Build/Verify-BdpCoreIsolation.ps1`
- Create（新建）：`Source/BDP.Tests/CoreModAssemblyIsolationVerifierSmokeTests.ps1`

### Step 1：先写失败测试

测试脚本先断言检查器文件存在，然后准备四组输入：

1. 当前真实 Core：应通过。
2. 临时工程中的核心 `ProjectReference` 指向另一本模组工程：应失败并包含“工程引用”。
3. 用 `BDP.Content.dll` 作为受检 DLL、用无工程引用的临时工程目录声明 `BDP.Core` 为另一本模组程序集：应失败并包含“DLL 引用表”和 `BDP.Core`。
4. 临时其他工程声明 `BDP.DevHarness` 命名空间，临时核心源码明确写出该名称：应失败并包含“明确名称”和文件路径。

临时测试目录必须创建在系统临时目录下的独立 GUID（全局唯一标识符）子目录，并在 `finally`（最终处理）中只删除该已解析目录。

### Step 2：运行测试并确认正确失败

Run（运行）：

```powershell
& '.\Source\BDP.Tests\CoreModAssemblyIsolationVerifierSmokeTests.ps1'
```

Expected（预期）：FAIL（失败），原因是 `Source/Build/Verify-BdpCoreIsolation.ps1` 尚不存在。

### Step 3：编写最小检查器

检查器参数：

```powershell
param(
    [string]$CoreProjectPath,
    [string]$CoreAssemblyPath,
    [string]$ModSourceRoot,
    [string]$CoreSourceRoot,
    [string]$CoreDefsRoot
)
```

实现以下成员并逐成员写中文注释：

- `Get-ProjectMetadata`：读取工程的 `AssemblyName`、`RootNamespace`、工程路径与 `ProjectReference`。
- `Get-DeclaredNamespaces`：从其他工程的非 `obj/bin` C# 源码中读取 `namespace` 声明。
- `Get-AssemblyReferenceNames`：以 `ReadAllBytes` 加 `ReflectionOnlyLoad(byte[])` 读取 DLL 引用，避免锁定发布文件。
- `Find-SpecificNameMentions`：扫描核心 C# 与核心 Def XML 中的其他第一方专属名称。

违规统一收集后一次输出；发现任一违规时 `throw`（抛出错误），无违规则输出：

```text
PASS: BDP.Core.dll 未依赖任何其他本模组程序集。
```


Expected：PASS，四种行为全部符合预期；外部的 RimWorld、Unity、Harmony 和 .NET 引用不被误报。

## Task 2：把检查器接到核心构建末尾

**Files：**

- Modify（修改）：`Source/BDP/BDP.csproj`
- Create（新建）：`Source/BDP.Tests/CoreModAssemblyIsolationBuildHookSmokeTests.ps1`

### Step 1：先写失败测试

读取核心工程 XML，断言：

- 存在 `AfterTargets="Build"` 的检查目标。
- 设计器构建 `DesignTimeBuild` 被排除。
- `Exec`（执行命令）调用 `Verify-BdpCoreIsolation.ps1`。
- 命令传入核心工程、目标 DLL、模组源码根、核心源码根和核心 Def 根五个路径。

### Step 2：运行测试并确认正确失败

Run：

```powershell
& '.\Source\BDP.Tests\CoreModAssemblyIsolationBuildHookSmokeTests.ps1'
```

Expected：FAIL，原因是核心工程尚无构建后门禁。

### Step 3：添加最小 MSBuild 目标

在 `Microsoft.CSharp.targets` 导入后新增一个目标：

```xml
<Target
  Name="VerifyBdpCoreModAssemblyIsolation"
  AfterTargets="Build"
  Condition="'$(DesignTimeBuild)' != 'true'">
  <Exec Command="powershell.exe ... Verify-BdpCoreIsolation.ps1 ... " />
</Target>
```

只做构建接线，不更改编译项、引用或游戏运行代码。

### Step 4：运行专项测试

Run：

```powershell
& '.\Source\BDP.Tests\CoreModAssemblyIsolationBuildHookSmokeTests.ps1'
& '.\Source\BDP.Tests\CoreModAssemblyIsolationVerifierSmokeTests.ps1'
```

Expected：两项 PASS。

### Step 5：运行真实构建

Run：

```powershell
dotnet build '.\Source\BDP.Content\BDP.Content.csproj' -c Release -t:Rebuild
```

Expected：

- `BDP.Core.dll` 和 `BDP.Content.dll` 均成功生成。
- 构建输出中出现核心零模组依赖 PASS。
- 0 警告、0 错误。

### Step 6：提交

