# BDP 护盾属性归属与规则组移除设计

## 状态

已实施。BDP.Content Debug/Release 构建均成功，内容 Def 与语言 XML 可解析；未运行静态契约脚本。

## 背景

当前 `BDP_Feature_Shield` 将抵挡角度、抵挡概率、可抵挡类型、伤害吸收比例和抵挡消耗放在 `BDP_FeatureGroup_ShieldRule`（护盾规则信息组）中。组的语义把护盾属性解释成“针对某类来袭攻击的一条规则”，但现有来源读取的是护盾组件本身的属性，并不以某种特定攻击作为属性所有者。这使信息模型多出一个没有对应业务实体的节点，也让扇形图必须绕到子组读取抵挡角度。

表达上下文中的光魂移动姿态和举盾姿态已经各自声明独立的护盾功能实例，并分别关联自己的来源条目。保留这些功能实例即可维持姿态筛选，无需护盾规则组来区分数据。

## 目标

- 让每个护盾功能节点直接拥有护盾的抵挡属性。
- 从 BDP 信息声明、解析结果、面板和正式定义中移除 `BDP_FeatureGroup_ShieldRule`。
- 保持当前来源读取、聚合护盾数值计算、姿态筛选和扇形图表现。
- 不改变 Core（核心）通用信息模型，不影响近战攻击方式组、机动方式组或通用子组机制。

## 设计

### 属性归属

把下列属性槽位加入 `BDP_Feature_Shield.Properties`：

- `BDP_Property_BlockAttackTypes`（可抵挡攻击类型）
- `BDP_Property_BlockArc`（抵挡角度）
- `BDP_Property_BlockChance`（抵挡概率）
- `BDP_Property_DamageAbsorptionRatio`（伤害吸收比例）
- `BDP_Property_BlockCost`（抵挡消耗）

从 `BDP_Feature_Shield.Groups` 中移除规则组槽位，并删除 `BDP_FeatureGroup_ShieldRule` 定义及其专属本地化名称。现有容量、恢复、持续时间、作用半径等护盾功能直属属性保持不变。

### 来源与信息模型

把护盾来源从每个组实例的 `Groups[].Sources` 移到对应功能实例的 `Sources`。将 `ShieldRuleFeatureSourceConfig` 和 `ShieldRuleFeatureSourceWorker` 改名为 `ShieldFeatureSourceConfig` 和 `ShieldFeatureSourceWorker`，保留它们读取指定表达条目、提取原版护盾组件数据和处理聚合护盾值的逻辑。

解析后，`ChipInformationNode` 中的护盾功能节点直接含有上述 `Properties`；不再为护盾创建 `KindKey=feature_group` 的规则子节点。光魂两个姿态继续使用各自独立的护盾功能节点和 `EntryId`（表达条目键）。

### 面板绘制

护盾扇形图改由护盾功能节点的 `BDP_Property_BlockArc` 触发，使用现有通用图表画布和滚动裁切。移除渲染器中面向护盾规则组的判断及组属性过滤。角度值和属性名已显示在扇形图内，因此仍隐藏同一角度属性的重复文本行；其它护盾属性照常显示。

### 文档与契约

更新芯片功能语义开发者指南、来源配置说明、护盾属性定义注释和现有契约检查，使当前推荐结构明确为护盾功能直属属性和直属来源。已完成的历史实施计划保留为历史记录，不将旧决策继续描述为当前规范。

## 方案取舍

1. **完整移除规则组并移动到护盾功能，采用。**信息模型和当前文档与业务语义一致；不引入新通用机制。
2. **只把来源移动到护盾功能，保留规则组来源类名。**实现改动较少，但类名仍表示已删除的规则概念，后续作者容易继续按规则组设计。
3. **只在面板隐藏规则组。**不能消除错误的信息模型节点，不符合需求。

## 影响范围

- `BDP_Feature_Shield` 属性声明、Shield Rule Group Def（护盾规则组定义）及对应语言键。
- 护盾来源配置类和 Worker（来源读取器）的名称，以及护盾功能预设中的来源位置。
- 芯片信息面板对抵挡角度的触发和重复行过滤。
- 现有内容契约与作者指南。

不修改 Core 的 `ChipFeatureDeclaration`、`ChipInformationNode` 或通用解析/分组 API。通用结构仍允许其它功能使用真实存在的多实例信息组。

## 验证

- 编译 BDP.Content（内容程序集），确认重命名后的配置类型、来源读取和渲染器接口一致。
- 搜索正式源码、内容 Def（定义）、语言包和当前作者指南，确认不再有护盾规则组或旧来源类型的活动引用。
- 检查各现有护盾功能实例均保留原 `EntryId` 和来源配置；确认抵挡角度直接进入护盾功能属性并仍触发扇形图。
- 不在本设计阶段承诺游戏内视觉实测；需要在实现完成后单独进行。
