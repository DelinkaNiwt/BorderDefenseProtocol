# 风刃施放诊断日志 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement the plan task-by-task.

**Goal:** 为风刃 Ability 的目标确认后施放链路增加可定位失败阶段、且不会按游戏 Tick 无限刷屏的开发诊断日志。

**Architecture:** 在 `BDP.Development` 增加只观察风刃的原版 Ability 点击、工作创建和工作启动边界，在 `BdpVerb_AbilityShoot` 保留施放入口和远程协议构建边界；不改变激活、目标选择、投射物和伤害逻辑。失败日志使用现有 `BdpDiagnostics.AttackExecutionThrottled`，按 Pawn、Ability 和阶段组成限流键；成功日志只在一次完整发射后记录一次。

**Tech Stack:** C#、BDP.Core、RimWorld Ability/Verb、现有 BDP 诊断汇聚器、PowerShell 静态烟测。

---

### Task 1: 建立风刃施放诊断契约

**Files:**
- Create: `Source/BDP.Tests/FujinCastDiagnosticsSmokeTests.ps1`
- Modify: `Source/BDP/Core/Abilities/BdpVerb_AbilityShoot.cs`

**Step 1: Write the failing test**

静态测试读取风刃宿主源码，要求存在施放入口日志、分阶段失败日志、成功发射日志，并要求使用 `AttackExecutionThrottled`；同时禁止在 `TryCastShot` 或投射物循环中直接使用无界的 `AttackExecution` 日志。

**Step 2: Run test to verify it fails**

Run:

```powershell
powershell -ExecutionPolicy Bypass -File Source/BDP.Tests/FujinCastDiagnosticsSmokeTests.ps1
```

Expected: FAIL，因为当前风刃宿主没有这些诊断入口。

**Step 3: Write minimal implementation**

在 `BdpVerb_AbilityShoot` 中：

- 增加诊断命名空间引用和一个由 Pawn/Ability/阶段组成的限流键辅助方法。
- `TryStartCastOn` 进入时记录目标信息；绑定结果或 Verb 表面准备失败时记录明确阶段并返回。
- `TryBuildRangedProtocol` 把目前的复合条件拆成独立检查，每个失败点只记录自己的阶段。
- 记录攻击入口、运行时动作步、远程协议和投射物计划为空等失败。
- `TryCastShot` 在 Trion 成本提交失败、发射数量为零时记录；成功完成后记录一次计划数和实际发射数。
- 日志全部经过 `AttackExecutionThrottled`，不在 `LaunchPlans` 的逐枚循环内输出。

**Step 4: Run test to verify it passes**

Run the same PowerShell test and expect `FujinCastDiagnosticsSmokeTests PASS`.

**Step 5: Commit**

```powershell
git add Source/BDP.Tests/FujinCastDiagnosticsSmokeTests.ps1 Source/BDP/Core/Abilities/BdpVerb_AbilityShoot.cs
git commit -m "diag: 增加风刃施放链路诊断日志"
```
