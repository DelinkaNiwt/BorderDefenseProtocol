# 战斗体旧档安全解除 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 防止旧存档或半途中断的战斗体事务在解除时误收、误毁角色当前服装，并在缺少有效原身快照时保留角色当前实际状态。

**Architecture:** 在 `PawnCombatBodyBridge` 中建立单一的有效回滚凭据判断，并由读档协调与正式解除入口共同使用。完整事务沿用原恢复流程，但前台服装只按已保存编号回收；无效事务走最小安全解除，只移除 BDP 激活标记并清理事务记录，不触碰无法证明归属的角色实物与健康状态。

**Tech Stack:** C# 7.3、RimWorld 1.6 `IExposable` 存档链、`ThingOwner` 容器、PowerShell 冒烟测试、dotnet Release 构建。

### Task 2: 最小实现安全回滚

**Files:**
- Modify: `Source/BDP/Core/CombatBody/Bridge/PawnCombatBodyBridge.cs`
- Modify: `Source/BDP/Core/CombatBody/Bridge/CompCombatBodyHost.cs`
- Modify: `Source/BDP/Core/CombatBody/Bridge/CombatBodyFrontState.cs`
- Modify: `Source/BDP/Core/CombatBody/Snapshot/CombatBodySnapshotState.cs`

**Step 1: Add one rollback predicate**

在宿主桥中增加只读成员：

```csharp
private bool HasValidRollbackSnapshot()
{
    return hostState != null
        && hostState.TransformationApplied
        && hostState.HasSnapshot
        && hostState.SnapshotState?.IsCaptured == true;
}
```

**Step 2: Split valid and safe exit paths**

完整分支维持既有火焰、战斗期伤势、前台服装、快照与最终残留清理次序。无效分支只移除战斗体激活标记，把残留容器实物转入独立旧档回收容器并尝试归还当前背包，再清除事务布尔值和前台激活记录；不得调用依赖原身基线的清理。回收容器不参与正常会话重置，转移失败的物品继续随存档保留。

**Step 3: Restrict front ownership**

从 `ActiveApparelThingIds` 建立 `HashSet<int>`，只筛选当前穿着且编号在集合中的服装。销毁镜像副本或回收预设服装后清除激活记录。

**Step 4: Reconcile after load**

增加 `ReconcileAfterLoad`：当 `TransformationApplied` 为真但有效快照缺失时，只将事务收敛为安全解除状态并输出一次警告，不碰 Pawn 实物。`CompCombatBodyHost.PostExposeData` 在 `EnsureInternalState` 后、运行时恢复前调用。

`CombatBodyFrontState.Bind` 与 `CombatBodySnapshotState.Bind` 同时补齐旧档可能缺失的列表和字典，保证安全解除后再次激活不会因空集合引用失败。
