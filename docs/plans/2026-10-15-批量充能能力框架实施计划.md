# 批量充能能力框架实施计划

**Goal:** 实现可复用的批量目标能力：原版次数逐次恢复、关闭来源后继续恢复、切换不刷新、按目标数量支付触力能，并提供直线划选和配置驱动建筑生成扩展点。

**Architecture:** 角色的原版 Ability（能力）对象持有唯一次数与恢复计时，表达同步只决定是否可用，不复制次数账本。Core（核心）提供批量请求、原版划选适配、来源门槛和数量结算；Content（正式内容）提供不绑定特定墙体的建筑生成效果。全部能力与组件需显式配置才启用，既有芯片保持原有路径。

**Tech Stack:** RimWorld 1.6／1.7 真实程序集、共享 C# 7.3 源码、原版角色能力／作业／划选工具、现有触力能命令入口。

## 范围与已确认规则

- 用户明确本轮先做框架，不创建具体芯片、正式墙体、制造配方或平衡数值。
- 一格目标是一个使用单位，批量请求只激活一次；使用次数和触力能均按目标数量结算。
- 原版逐次恢复负责时间推进；剩余次数可继续使用，关闭芯片继续充能，同角色同能力共用一池。
- 新能力的来源失效时隐藏按钮并禁止队列／目标／实际施放，保留对象及原版存档状态。只配置了保留组件的能力改变回收行为。
- 拖拽只预览；确认后目标列表保存在原版 Job（作业）中。第一版不开放同能力多批排队。
- 批量目标需去重、在同一地图、全部合法、预算充足；超额或失效不自动截断、不扣费。
- 不修改上一轮发现的风刃、蚱蜢等既有问题，不把护盾连续耐久抽象成新次数系统。

## 现有复用依据

- 护盾 `Hediff_EnergyShieldState`（人物持久护盾状态）已证明“来源开关与人物恢复状态分开”；借用生命周期原则，不复用业务耐久算法。
- `DefaultExpressionAbilityHostSynchronizer`（表达能力同步器）、`BdpVerb_CastAbility`（正式能力动作）、`BdpAbilityTrionCostCommitter`（成本提交器）继续作为入口。
- 原版 Ability 保存次数／冷却；原版 Designator（划选工具）和 DesignationDragger（拖拽器）提供交互；原版 Job 保存目标队列。
- 原信息定义已有充能上限与恢复时间键；扩展已有读取器，不另建信息系统。

## 实施步骤

### 1. 数量成本验证与共同支付

- 新增 `Source/BDP.Tests/BatchAbilityBudgetTests.ps1`，显式指定版本，先验证新预算入口缺失，再运行实际程序集验证多单位总价、最低门槛、不合法数量及数值。
- 新增 `Source/BDP/Core/Abilities/BatchAbilityBudget.cs`，只计算数量与费用，不知道墙体业务。
- 修改 `CompAbilityEffect_BdpTrionCost.cs` 和 `BdpAbilityTrionCostCommitter.cs`，为共同检查／提交增加数量入口；原参数入口仍按一次调用，防止既有技能被重复扣费。

### 2. 来源停用保留与准入

- 新增 `CompProperties_AbilityEffect_BdpExpressionLifecycle.cs` 与对应效果组件。
- 同步器在已持有且显式声明保留的能力来源失效时跳过移除，继续由原版更新和保存。
- 组件统一隐藏、可施放、目标确认、人工智能及实际施放前的来源检查；不能只隐藏按钮。

### 3. 批量请求、能力及施放动作

- 新增 `BdpBatchAbility.cs`，从当前原版作业读取已冻结目标队列，拒绝无批量请求的直接激活，并在原版激活前额外扣除 N−1 次；原版仍扣一次和启动逐次恢复，合计恰好 N 次。
- 新增 `BdpVerb_CastBatchAbility.cs`，最终复查整批目标和资源后按 N 单位提交成本，再进入原版能力激活。不循环调用 N 次完整激活。
- 批量使用原版能力作业，目标队列随作业存档；禁止同能力多批预占和排队。

### 4. 直线划选

- 新增批量能力按钮及专属原版划选工具，绑定角色／能力／地图，复用原版直线样式。
- 预览与确认读取同一候选列表；计数、费用、范围和合法性统一检查。切图、失去来源或角色失效时取消。
- 新增必要的通用绘制样式类别定义，只引用原版直线，不新增形状算法。

### 5. 配置驱动建筑效果与信息

- Content 新增通用建筑生成组件，建筑定义通过配置提供；无特定墙体名称和数值。只接受一格建筑；用户实测后要求与原版建墙一致，因此落点直接使用原版建造判定，移除最初的空格／可站立附加限制，生成沿用原版框架完工清理模式。
- 生成效果逐个处理已确认格子；生成代码抛出异常时清理本批新增对象并继续抛出，不伪报成功。本轮沿用原版能力异常语义，不提供次数／触力能／计时自动回滚；正常预算、来源与位置拒绝均发生在支付之前，不收费。
- 信息读取器区分“逐次恢复”与“释放冷却”，提供充能上限／恢复时间；新增通用提示文案放公共语言包。

### 6. 分版本验证和收尾

- 使用 `dotnet msbuild Source/BDP.Development/BDP.Development.csproj -p:RimWorldVersion=1.6 -p:Configuration=Release` 构建 1.6。
- 使用 `dotnet msbuild Source/BDP.Development/BDP.Development.csproj -restore -p:RimWorldVersion=1.7 -p:Configuration=Release` 构建 1.7。
- 构建前只备份将受影响的既有程序集／调试符号；不更改既定构建输出路径，不部署游戏目录。
- 两版本分别运行数量预算验证；核对 XML（定义文件）、语言键和 Core 依赖边界。
- 补充框架接入说明与游戏内验收项目：逐次恢复、关闭继续恢复、切换不刷新、取消不扣、整批一致、前摇中来源失效、读档、切地图。
- 没有正式芯片接入前，明确“构建／数量验证完成”和“游戏内验收待接入”的边界。按任务文件提交，保留其它工作区内容。

## 验收重点

次数真相只有原版能力一份；新功能停用不移除该对象；新组件缺省不影响现有能力；一次 N 目标消耗 N 次与 N 倍单价；原生恢复计时不因再次使用重置；取消及支付前校验拒绝不产生副作用；无具体芯片和墙体配置被加入正式内容。支付前冻结本轮目标与地图，支付恰好耗尽触力能并同步结束作业时仍完成本次已支付效果，再承受崩解；这份同步上下文不存档，不代替原版作业目标队列。

## 执行结果

- 上述框架源码、直线样式、语言包、信息读取和接入说明已完成；没有新增具体芯片或墙体定义。
- 1.6、1.7 分别完成核心／正式内容／开发辅助构建，核心依赖边界检查及实际程序集数量预算测试均通过。
- 公共定义与语言文件解析、语言键检查通过；预算测试先确认缺失入口失败，再验证实际新增入口通过。
- 存档检查补齐原版深存档要求的传入角色构造；新增实际程序集构造入口测试，两个版本均先在缺失构造的产物上失败，再在修复产物上通过。
- 只读代码审查发现支付见底同步结束作业会丢目标，已改为支付前冻结本轮目标、地图和代表格，并复查修复在两版本原版时序下闭合。
- 生成异常不提供资源／次数／计时自动回滚，接入说明已明确；不调用调试资源写入口伪造正式退款。
- 尚无具体芯片接入，游戏内验收未执行；未部署。下一步为可移除开发配置的双版本实测，不是添加正式墙体业务。
