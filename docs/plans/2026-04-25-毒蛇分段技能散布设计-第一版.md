# 2026-04-25 毒蛇分段技能散布设计（第一版）

## 目标

- 让毒蛇模块的每一段都具备类似首段的随机散布感，而不是只有首段随机、后续沿固定中心线续飞。
- 让续段散布强弱重新与射手 `Shooting` 技能挂钩：技能低更散，技能高更收。
- 保留当前已修复好的“不会从第二段开始重新汇聚成一条线”的特性。

## 现状结论

- 首段之所以“像首段”，是因为它走 `BdpVerb_Shoot` 的宿主命中链，包含发射点散布、强制失准、野失误、掩体等逻辑。
- 续段之所以“不像首段”，是因为它不是重新开火，而是 `Arrival -> ContinueFlight` 直接续飞；当前毒蛇续段只吃 `NextFlightPathSnapshot`，不会重新进入首段命中链。
- 因此，如果目标是“每段都像首段一样有随机散布感”，就不能只依赖当前固定路径快照；必须在每段生成时都重新采样该段散布。

## 设计选择

### 方案 A：每段完整重跑首段命中链

- 优点：最接近“完全像首段”。
- 缺点：侵入面大，容易把掩体、强制失准等首段语义错误地套到锚点段上；还会显著放大宿主协议耦合。

### 方案 B：每段重新采样“技能驱动散布”（采用）

- 做法：
  - 首段继续交给宿主命中链。
  - 第二段起，仍由毒蛇模块接管，但每段都重新采样该段随机偏移。
  - 散布半径以 `AnchorSpreadRadius` 为基底，再乘以“按射击技能插值出的倍率”。
  - 去掉当前“越往后越大”的分段倍率，让每段都按完整半径散开，更接近“每段都像首段”。
- 优点：
  - 只改毒蛇模块自身，最小侵入。
  - 能稳定恢复“每段都有独立随机散布感”。
  - 能让低技能小人明显更散、更不准。

### 方案 C：仅扩大固定续段散布半径

- 优点：改动最小。
- 缺点：只是把后续段整体放大，不会体现射击技能差异，也不够像首段。

## 配置设计

- 保留现有 XML 字段：
  - `AnchorSpreadRadius`
- 新增 XML 字段：
  - `LowSkillSpreadMultiplier`
  - `HighSkillSpreadMultiplier`

含义：

- `AnchorSpreadRadius`：毒蛇每段随机散布的基础半径。
- `LowSkillSpreadMultiplier`：射击技能低时的放大倍率。
- `HighSkillSpreadMultiplier`：射击技能高时的收束倍率。

技能换算：

- 以 `Shooting` 0~20 线性插值。
- `0` 级取 `LowSkillSpreadMultiplier`。
- `20` 级取 `HighSkillSpreadMultiplier`。
- 中间等级线性过渡。

## 代码落点

- `PathLatchConfig.cs`
  - 增加技能散布倍率配置并支持 `CloneTyped()`。
- `PathLatchModule.cs`
  - 在 `ProjectileInit` 冻结“本次发射的有效续段散布半径”。
- `PathLatchState.cs`
  - 路径上下文继续持久化有效散布半径，保证读档续飞不变。
- `PathLatchSegmentResolver.cs`
  - 续段散布改为“每段完整半径随机采样”，不再按段号递增。
- `RangedAttackModuleDefs_Test.xml`
  - 为测试毒蛇模块补上新增 XML 字段。

## 测试策略

- 先改 `PathLatchWaypointSpreadSmokeTests.ps1`，让它先要求：
  - 新配置字段存在并克隆。
  - 续段散布不再使用“按段号递增比例”。
  - 解析器存在技能散布倍率换算/使用痕迹。
- 跑烟测确认先红，再实现代码，再跑回归。

## 成功标准

- 首段继续保持当前恢复后的随机散布。
- 第二段及以后每段都重新随机散开，不再像固定中心线。
- 射击技能低的小人，续段更散；高技能小人，续段更收。
- 现有 PathLatch 回归烟测与 DevHarness 编译保持通过。
