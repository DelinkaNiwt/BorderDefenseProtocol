# 表达系统公开读取面收口设计

**Goal（目标）:** 把当前内部的表达正式真源整理成一个可对外消费的公开读面，同时保留 Verb / Ability / Hediff / Passive 四通道的一致读取与各自的 live 宿主解析口。

**Architecture（架构）:** 主模组只提供中性的正式读取层，不暴露 `IExpressionReader`、`FormalExpressionResult` 这类内部真值对象。公开面以一份不可变投影快照为中心，按 `ResultId`、通道键和复合引用索引读取正式结果；宿主解析则按通道分开，Verb 走 live `Verb`，Ability 走 `AbilityDef` 绑定，Hediff 走宿主 `Hediff`，Passive 只读正式结果本身。

**Tech Stack（技术栈）:** RimWorld 1.6 Mod、C#、现有 BDP 主模组、DevHarness 业务侧引用

---

## 设计

### 1. 公共正式快照

新增一份公开、只读的表达投影快照，用来承接当前已发布投影的正式结果、四通道分组、结果索引与复合引用索引。

### 2. 公共结果条目

每条公开结果只保留稳定身份、通道、发布键、基础描述、来源引用、Trion 参数和被动暴露数据，不直接暴露内部结果对象。

### 3. 四通道宿主解析

新增公开解析口：

- `Verb` 按 `ResultId` 解析 live 壳。
- `Ability` 按 `AbilityDefName` 解析当前宿主。
- `Hediff` 按 `HediffDefName` 解析当前宿主。
- `Passive` 不解析 live 宿主，只读正式结果。

### 4. 非目标

- 不公开内部表达服务本体。
- 不把 `FormalExpressionResult` 直接改成对外 DTO。
- 不把 Verb 的 live 解析方式错误推广成 Ability/Hediff/Passive 的统一模型。
