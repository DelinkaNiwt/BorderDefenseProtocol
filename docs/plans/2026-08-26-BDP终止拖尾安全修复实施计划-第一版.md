# BDP 终止拖尾安全修复 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让 BDP 投射物拖尾显示到实际终止位置，并在客观阻挡终止时裁到墙体近侧视觉安全边界。

**Architecture:** 保留现有物理命中位置，不把物理终点改成视觉边界。Core 负责提供中性的视觉终点与安全标记；Content 的拖尾系统只固化已有真实活动头段，不读取目标中心，也不重建目标导向线段。

**Tech Stack:** C#（C#语言）、RimWorld 1.6、PowerShell（微软命令行脚本）、MSBuild（微软构建工具）

- Reference: `Source/BDP/Core/Projectiles/Visual/ProjectileVisualAttachmentContracts.cs`

**Step 1: 写静态边界断言**

断言以下契约不存在：

- 物理阻挡终点与视觉终点共用同一字段；
- 视觉终止路径使用目标中心；
- 阻挡视觉终点缺少阻挡格外安全回退。

断言以下契约存在：

- 阻挡记录有独立视觉安全终点和有效标记；
- 投射物宿主有独立视觉阻挡终点状态；
- 终止上下文携带视觉终点安全标记。

### Task 3: 实现安全视觉终点

**Files:**
- Modify: `Source/BDP/Core/Projectiles/RangedFlightProtocol/Model/SegmentCollisionRecord.cs`
- Modify: `Source/BDP/Core/Projectiles/RangedFlightProtocol/Collision/SegmentCollisionService.cs`
- Modify: `Source/BDP/Core/Projectiles/BdpProjectile.cs`
- Modify: `Source/BDP/Core/Projectiles/Visual/ProjectileVisualAttachmentContracts.cs`

**Step 1: 增加阻挡视觉终点记录**

- 保留现有 `FirstObjectiveBlockerExactPosition` 作为物理/诊断位置。
- 增加阻挡格外的视觉安全位置与有效标记。

**Step 2: 从首次阻挡进度向前回退求视觉点**

- 使用真实路径快照求取首次阻挡进度。
- 沿路径反向回退安全余量。
- 只有候选点仍在阻挡格外时才接受。
- 失败时标记视觉终点不可安全固化。

**Step 3: 宿主分离物理和视觉状态**

- 物理 `ExactPosition` 继续使用现有阻挡锚点。
- 视觉终点优先使用阻挡安全点，否则使用实际终止位置。
- 终止上下文携带安全标记。

### Task 4: 实现最后活动头段固化

- Modify: `Source/BDP.Content/Projectiles/BeamTrail/BeamTrailAttachment.cs`

**Step 1: 增加 `FinalizeLiveSegment`**

- 找到指定投射物的活动头段。
- 用终止上下文的视觉终点更新其终点。
- 从活动头段字典移除并加入历史段列表。

- 安全终点有效时固化已有活动头段。
- 安全终点无效时清除活动头段。
- 不访问目标中心或目标语义。
