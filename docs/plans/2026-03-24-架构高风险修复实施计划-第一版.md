# 架构高风险修复实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不引入新 owner、不破坏当前正式行为边界的前提下，先完成当前主模组严重 / 高风险架构问题的结构修复，为后续继续推进路线 B / C 建立可持续基础。

**Architecture:** 本计划优先处理三类问题：`CompTriggerBody` 膨胀、`CombatBody` 双轨职责与未接主链、表达 / 投影假解耦。修复方式一律采用“保留 owner，外移局部规则与接线”的模式，不通过新增总控层逃避问题。

**Tech Stack:** RimWorld 1.6、C# 7.3、Harmony、ThingComp、CompEquippable、正式只读/请求接口、外置 DevHarness。

---

## 实施前硬约束

1. 不新增新的真值 owner
2. 不把测试层逻辑回灌进主模组
3. patch 只做接线，不承载复杂业务
4. 每一子阶段结束后：
   - 重新编译主模组
   - 重新编译 DevHarness
   - 做一次全局架构复审
   - 写会话日志

---

## 阶段 P1：`CompTriggerBody` 瘦身第一轮

**目标：**

- 保留 `CompTriggerBody` 的 Trigger owner 身份
- 先把最容易继续膨胀的规则与切换推进剥离出去

**涉及文件：**

- 修改：
  - `Source/BDP/Core/Trigger/CompTriggerBody.cs`
- 新建：
  - `Source/BDP/Core/Trigger/TriggerActivationRules.cs`
  - `Source/BDP/Core/Trigger/TriggerSwitchEngine.cs`
  - `Source/BDP/Core/Trigger/TriggerDisableSync.cs`

**具体任务：**

1. 把“激活前规则判断”从 `CompTriggerBody` 抽到 `TriggerActivationRules`
2. 把“双手绑定目标归一、互斥冲突判断”并入该规则模块
3. 把“切换上下文构造、阶段到期结算”抽到 `TriggerSwitchEngine`
4. 把“宿主身体禁用同步”抽到 `TriggerDisableSync`
5. `CompTriggerBody` 只保留：
   - 真值字段
   - 对外正式接口实现
   - 调用上述局部模块

**完成标准：**

- `CompTriggerBody` 文件显著缩小
- 新增模块不持有真值
- 最近修复的“递归重入”问题不因重构再次引入

---

## 阶段 P2：`CombatBody` 单主链化接通

**目标：**

- 把 `CombatBodyCoordinator` 正式确立为唯一主协调者
- 让 `CombatBodyCleanupCoordinator` 成为被主协调者调用的事务模块

**涉及文件：**

- 修改：
  - `Source/BDP/Core/CombatBody/CombatBodyCoordinator.cs`
  - `Source/BDP/Core/Cleanup/CombatBodyCleanupCoordinator.cs`
  - `Source/BDP/Core/CombatBody/PawnCombatBodyHost.cs`
- 可能删除或内部化：
  - `Source/BDP/Core/Cleanup/ICollapseCleanupCoordinator.cs`

**具体任务：**

1. 决定 `CleanupCoordinator` 是否保留接口
2. 若保留，则将其作为 `CombatBodyCoordinator` 依赖显式接入
3. 把退出 / 崩解流程统一成：
   - 相位裁定
   - 收尾事务
   - 冷却进入
4. 让 `PawnCombatBodyHost` 至少进入最小正式主链，而不是纯空桥位

**完成标准：**

- 主模组中不再存在“两个都像主协调者”的收尾职责
- `CombatBody` 代码从定义集合变成已接通闭环

---

## 阶段 P3：表达 / 投影链瘦身

**目标：**

- 去掉第一阶段当前没有真实替换价值的抽象层
- 收窄对 `CompTriggerBody` 具体类的依赖

**涉及文件：**

- 修改：
  - `Source/BDP/Core/Trigger/TriggerProjectionFacade.cs`
  - `Source/BDP/Core/Runtime/BdpProjectionRuntime.cs`
  - `Source/BDP/Patches/Patch_Pawn_TryGetAttackVerb.cs`
  - `Source/BDP/Patches/Patch_Pawn_MeleeVerbs_TryMeleeAttack.cs`
- 评估删除或内部化：
  - `Source/BDP/Core/Projections/*.cs`
  - `Source/BDP/Core/Projections/I*.cs`

**具体任务：**

1. 把 facade 入参收窄到最小正式接口
2. 评估 `AutoRanged / AutoMelee / Manual / Surface` 四层是否继续保留公开类型
3. 对于当前只有单实现且仅被 runtime 内部直接 new 的层，优先内部化或压平
4. 保留真正有价值的边界：
   - 收集
   - 解析
   - 投影宿主创建

**完成标准：**

- facade 不再把 `CompTriggerBody` 写死为正式边界
- 投影链层次数量下降，主链更易读

---

## 阶段 P4：正式外部命令扩展口规范化

**目标：**

- 保留 `外部按钮 / 外部扩展命令` 作为正式需求
- 但避免它继续让 Trigger owner 承担更多 UI 接线责任

**涉及文件：**

- 修改：
  - `Source/BDP/Core/Trigger/CompTriggerBody.cs`
  - `Source/BDP/Core/Trigger/TriggerExternalGizmoRegistry.cs`
  - `Source/BDP/Core/Trigger/TriggerExternalGizmoContext.cs`
- 新建：
  - `Source/BDP/Core/Trigger/TriggerCommandFacade.cs`

**具体任务：**

1. 把 `CompGetEquippedGizmosExtra()` 中的拼接逻辑进一步外移
2. 明确：
   - 正式外部命令扩展
   - 正式手动表达命令
   - 读取/请求/诊断能力上下文
3. 保证该扩展口的命名、上下文结构和注释都面向未来普通扩展模组作者，而不是围着 DevHarness 解释

**完成标准：**

- 主模组仍提供正式外部命令扩展能力
- 但 Trigger owner 不再继续吸收 UI 接线细节

---

## 阶段 P5：空骨架与死抽象清仓

**目标：**

- 移除当前没有真实价值的认知负担

**涉及文件：**

- 重点审查：
  - `Source/BDP/Core/Projections/IVisualProjection.cs`
  - `Source/BDP/Core/Semantics/ISemanticDamageSource.cs`
  - 其它只有接口、没有实现或没有接线的类型

**具体任务：**

1. 列出“只有接口、没有实现”
2. 列出“只有实现、没有接线”
3. 对每个对象做三选一裁定：
   - 接回主链
   - 内部化
   - 删除

**完成标准：**

- 主模组中的空桥位和死抽象显著减少
- 代码阅读者不再需要先穿过大量未生效骨架才能看见正式主链

---

## 阶段 P6：回归验证与文档更新

**目标：**

- 确认架构修复没有破坏当前可测主链

**验证项：**

1. 主模组编译通过
2. DevHarness 编译通过
3. 普通芯片装载 / 激活 / 关闭仍可工作
4. 双手绑定芯片装载 / 激活 / 挤占 / 关闭仍可工作
5. 暂停下部位缺失禁用仍立即成立
6. 自动近战 / 自动远程 patch 仍能通过正式投影入口读到结果

**文档更新：**

- 更新总路线图中的当前节点说明
- 更新会话日志
- 补写本轮架构复审结论

---

## 推荐执行顺序

1. `P1`
2. `P2`
3. `P3`
4. `P4`
5. `P5`
6. `P6`

原因：

- 先止住 Trigger owner 膨胀
- 再把 `CombatBody` 主链接通
- 然后瘦身表达 / 投影与 UI 扩展骨架
- 最后清理剩余死抽象

---

## 预期结果

当本计划完成后，预期主模组会从当前的：

- `CompTriggerBody` 重 owner + 重流程 + 重接线混合体
- `CombatBody` 多骨架未接通
- 表达 / 投影多层但具体依赖仍很强

转为：

- owner 明确、局部模块化、外部扩展边界正式化
- `CombatBody` 闭环进入主链
- 表达 / 投影主链更短、更清晰、更可验证
