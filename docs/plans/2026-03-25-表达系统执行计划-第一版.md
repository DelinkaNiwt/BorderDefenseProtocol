# 表达系统执行计划（第一版） Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在主模组内部正式重建表达系统，从“来源材料 -> 单侧结果 -> 双侧高层结果 -> 完整结果总表 -> 多条投影层”完整落地，并保持 Trigger / CombatBody / Trion 边界诚实。

**Architecture:** 实现顺序严格按内部运算链先于投影层推进，先建立芯片表达声明配置层、结果对象与计算接口，再回接默认投影三线、手动入口、视觉、说明。Special 武器类唯一化与双手锁定视觉伪装分别落在独立裁定器与视觉投影器中，不允许重新长成大而全运行时。

**Tech Stack:** C# 7.3, .NET Framework 4.8, RimWorld `ThingComp`/`Verb`/`Gizmo`/`Hediff`/`Ability`, `dotnet msbuild`

## 映射器实施裁定

当前已正式确认：

- “结果到宿主实例”的映射器应落在 `Projection` 层
- 不落在 `Trigger`
- 不落在 patch
- 不落在 `FormalExpressionResult`

当前推荐拆法为：

1. `IExpressionVerbHostResolver`
2. `DefaultExpressionVerbHostResolver`
3. `ExpressionVerbBridge`
4. `IManualEntryGizmoResolver`
5. `DefaultManualEntryGizmoResolver`
6. `ExpressionManualGizmoBridge`

实施顺序：

1. 先补 `IExpressionVerbHostResolver` 及默认实现骨架，只解析，不发明行为
2. 再让 `ExpressionVerbBridge` 改为真正调用 resolver
3. 再补 `IManualEntryGizmoResolver` 及默认实现骨架
4. 最后再补“哪些入口项映射成什么 Gizmo”的正式规则

当前约束：

- resolver 只回答“能不能找到真实宿主实例”
- bridge 只负责接线
- 没有正式宿主实例时必须诚实返回空

- 当前已继续补齐的投影结果形状还包括：
- `VisualExpressionProjection` 已具备常驻显示 / 执行跟随 / 枪口跟随三个正式读取位
- `ExpressionInfoProjection` 已具备结构化说明条目，以及默认主远程 / 默认主近战 / 当前执行表达结果标识
