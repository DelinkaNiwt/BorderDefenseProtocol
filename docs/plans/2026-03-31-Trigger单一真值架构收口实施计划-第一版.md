# Trigger单一真值架构收口 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将 Trigger 的芯片装载与激活状态收口为 `TriggerSlotState` 单一正式真值，令 `chipContainer` 退化为从属物理持有容器，从架构上消灭“容器有芯片而槽位无芯片”这类分叉状态。

**Architecture:** 当前 `CompTriggerBody` 同时持有 `chipContainer` 与 `TriggerSlotState.loadedChip` 两套“芯片存在性真值”，读档时它们分开恢复，导致状态分叉。整改后，所有业务语义只允许从 slot 读取；`chipContainer` 只能由 slot 单向重建；读档、完整性修复、表达投影、宿主重建必须统一遵守 `slot truth -> container rebuild -> expression -> verb host` 的链路。

**Tech Stack:** RimWorld 1.6 C#, Verse `Scribe` 序列化, Harmony mod runtime, PowerShell smoke tests

---

## Scope

- 只处理 Trigger 架构收口，不顺手改攻击协议、Verb 宿主行为、UI 逻辑。
- 不做新旧兼容层，不保留双真值过渡逻辑。
- 不引入新的“LoadoutState”大对象；仍以 `TriggerSlotState` 作为正式真值载体。

## Non-Goals

- 不在本轮修改组合技、双持、远程协议的业务规则。
- 不在本轮扩展新的存档格式版本迁移系统。
- 不在本轮增加新的用户可见功能。

## Success Criteria

- 读档后若 `chipContainer` 中有芯片，则对应 slot 真值也必须完整恢复，表达层能产出正确 snapshot。
- `chipContainer` 不再作为业务语义来源；业务层只认 slot。
- 完整性修复只能单向执行：`slot -> container`。
- 自动远程、表达、VerbHost 三层都能在读档后自然恢复，不依赖补丁式修洞。
- 删除或收缩掉当前所有“从 container 反推 slot”的恢复逻辑。

## Architecture Decisions

### Decision 1: `TriggerSlotState` 是唯一正式真值

- `LoadedChip`
- `IsActive`
- binding 元数据
- disable 状态

这些都只允许由 slot 持有并对外表达。

### Decision 2: `chipContainer` 是从属存储设施

- 它的职责只有：
  - 让芯片作为 `Thing` 被 Trigger 正式持有
  - 配合 RimWorld 存档系统保存物理对象
- 它不再回答：
  - 哪个 slot 装了什么芯片
  - 哪个 slot 当前激活
  - 哪些芯片参与表达或宿主投影

### Decision 3: 读档恢复链必须单向

固定顺序：

1. 读回 slot 真值
2. 校验并收束 slot 真值
3. 从 slot 重建 `chipContainer`
4. 刷新表达快照
5. 重建 VerbHost

### Decision 4: 一致性修复只允许“正式真值 -> 从属存储”

- 允许：slot 有 chip，但 container 缺失时，按 slot 重建 container
- 不允许：container 有 chip，但 slot 无引用时，反向猜它属于哪个 slot

如果出现后一种情况，应当把它定义为“正式真值缺失”，优先暴露问题，而不是偷偷补洞。

## Implementation Notes

- 不要在任何地方再增加“如果 slot 丢了就从 container 猜”的补丁逻辑。
- 如果读档后发现 container 中存在孤儿 chip，应当把它当作从属状态污染处理，而不是把它抬升成业务真值。
- 若 `TriggerSlotState.loadedChip` 的 `Scribe_References` 本身不可靠，本轮允许修改 slot 的存档策略，但前提仍然是：正式真值仍在 slot，不引入第二真值对象。
- auto ranged 当前报错只是症状，不要从攻击层兜底这个问题。

## Risks

- 若现有某些切换逻辑隐式依赖 container 作为事实来源，本轮收口后可能暴露新的调用点，需要一并清理。
- 若 slot 的存档字段设计本身不足以稳定恢复芯片引用，可能需要补一个更稳定的 slot 挂载恢复策略，但不能让它重新变成双真值。
- 临时调查日志较多，实施时要注意在 Task 6 收掉。

## Definition Of Done

- `TriggerSlotState` 成为唯一正式业务真值
- `chipContainer` 只承担从属持有职责
- restore 顺序固定为 `slot truth -> container rebuild -> expression -> host`
- 无 `container -> slot` 推断
- 读档后自动远程 warmup 可自然恢复，无 `bugged verb after loading`
- 调查日志删除，替换为少量永久 invariant 诊断
