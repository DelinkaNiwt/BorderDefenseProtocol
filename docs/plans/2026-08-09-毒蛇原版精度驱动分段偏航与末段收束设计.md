# 毒蛇原版精度驱动分段偏航与末段收束设计

## 1. 文档范围

- 文档类型：业务功能设计。
- 适用对象：新 BDP 主模组的毒蛇预设与 `RoutePathModule（路线引导模块）`。
- 目标版本：RimWorld 1.6（边缘世界 1.6）。
- 本次只调整带中间锚点的毒蛇分段弹道；零锚点直射、猎犬追踪、其它远程模块和旧版模组不在范围内。
- 本设计不把毒蛇业务写入 `Core.dll（核心程序集）`；Core 只补一份可供任意投射物消费的中性精度事实快照。

## 2. 玩家体验目标

毒蛇应表现为“乱而有序”：

```text
名义路线：射手 → A → B → 最终目标
实际路线：射手 → A' → B' → 最终目标附近 C
```

- `A'`、`B'` 是受本发原版精度影响的中间偏航点。
- 技能低、武器精度差、天气恶劣或受到其它原版精度惩罚时，中途偏航更明显。
- 技能高、武器精度好、环境有利时，中途路线更稳定。
- 中间偏航不得因为随机结果主动打断锚点链；无法安全采用偏移时缩小偏移，最终回退名义锚点。
- 最后一段明显向最终目标收束，但仍保留一份独立的小散布，不能变成必中。
- 一发子弹只做一次原版命中裁定；锚点数量不得把命中率逐段相乘。

## 3. 已确认行为

### 3.1 一次开火、一次精度事实

每发 projectile（投射物）只在正式开火时生成一次原版 `ShotReport（射击报告）`。毒蛇续段继承这份报告的输出，不在每个锚点重新运行原版开火链。

原因：原版报告的正式输入是“射手当前位置 → 语义最终目标”，没有“飞行中的投射物当前位置 → 中间锚点”的合法入口。逐段重跑会错误读取射手位置、目标体型、姿态和掩体，并让命中率随锚点数量叠乘。

### 3.2 首段保持现有原版接入

首段继续由 `BdpVerb_Shoot（BDP 射击动词）`完成：

- `navigationTarget（导航目标）`是第一个锚点。
- `semanticTarget（语义目标）`是玩家确认的最终目标。
- `ShotReport（射击报告）`按语义最终目标计算射手、武器、距离、天气、烟雾、光照、体型、姿态和掩体等原版事实。
- 原版命中类别与 `ProjectileHitFlags（投射物命中类别）`继续由现有宿主决定，不搬入路线模块。

本次不为路线模块预写 `InitialFlightPathSnapshot（首段飞行路径快照）`，避免抢走当前首段的原版发射真值。

### 3.3 续段不重新判定命中

从第二段开始，路线模块只改变下一段的几何目的地，不创建新的射击报告，不改写：

- 原版命中类别；
- 预定目标资格；
- 非目标 Pawn（小人）命中资格；
- 掩体结论；
- 伤害、爆炸或命中模块结论。

中间锚点永远只是导航点，不是新的攻击目标。

### 3.4 最终段收束但不必中

最后一段使用与中间段不同的独立随机样本和更小的基础半径。它只让几何落点接近冻结的最终目标，不覆盖开火时已经得到的命中资格。

因此“视觉上收束”与“最终命中”保持分离：原版已经裁定为失手的子弹，即使回到目标附近，也不能被路线模块改造成命中。

## 4. 原版精度事实

当前 `BdpVerb_Shoot.TryLaunchSinglePlan（发射单份计划）`已经在临时注入每发来源芯片的四档精度后调用：

```csharp
ShotReport.HitReportFor(caster, this, semanticTarget)
```

设计只冻结原版对外公开、且后续确实需要的合成事实：

- `StandardAimChance（标准目标瞄准概率）`：使用 `ShotReport.AimOnTargetChance_StandardTarget（标准目标瞄准概率） × AccuracyFactor（额外精度倍率）`，限制在 0～1。
- `IgnoringPostureAimChance（忽略姿态后的瞄准概率）`：保留诊断与未来通用消费，不作为中间偏航主因子。
- `PassCoverChance（通过掩体概率）`：保留原版事实，但路线偏航算法不拿它计算中间锚点。
- `ForcedMissRadius（强制失准半径）`：保留原版事实；毒蛇当前默认值为 0，本次不新增强制失准专用业务。
- `IsAvailable（事实可用）`：区分正常报告和旧存档、缺失报告等回退情况。

`StandardAimChance（标准目标瞄准概率）`已经综合射手精度、武器距离档精度、天气、致盲烟雾及原版其它标准修正。中间路线不再单独读取 `Shooting（射击）`技能，避免双重计算。

目标体型、姿态与掩体继续只影响最终命中语义，不重复折算进中间偏航半径。

## 5. Core 中性设施

### 5.1 新数据类型

在 Core 的远程协议模型内新增：

```text
ProjectileAccuracySnapshot（投射物精度快照）
```

它是 `IExposable（可存档对象）`，只保存上一节列出的中性事实，不出现下列业务词：

- Viper（毒蛇）；
- Route（路线）；
- Anchor（锚点）；
- Convergence（收束）。

### 5.2 真值写入点

`BdpVerb_Shoot（BDP 射击动词）`仍是唯一写入点：

1. 临时应用当前 `ProjectileInitPlan（投射物初始化计划）`携带的来源芯片精度。
2. 调用原版 `ShotReport.HitReportFor（生成射击报告）`。
3. 恢复 `verbProps（动词属性）`。
4. 从报告公开值构造 `ProjectileAccuracySnapshot（投射物精度快照）`。
5. 在 `Projectile.Launch（投射物发射）`前写回当前计划。

不允许 Content（内容层）自行重复拼装天气、技能、武器精度或烟雾公式。

### 5.3 后半段只读暴露

`ProjectileInitPlan（投射物初始化计划）`深度保存该快照，`ArrivalStageContext（到达阶段上下文）`只读暴露它。投射物存档继续通过现有 `BdpProjectile.ExposeData（BDP 投射物存档）`保存整个计划。

旧存档缺少快照时：

- `IsAvailable（事实可用） = false`；
- 路线模块使用中性精度 0.5 作为视觉回退；
- 不建立旧字段迁移层；
- 不改变原有命中类别和碰撞结论。

### 5.4 依赖方向

```text
BDP.Content.dll（内容程序集） → BDP.Core.dll（核心程序集）
BDP.Core.dll（核心程序集）    → 不依赖本模组其它程序集
```

Core 只提供精度事实，不知道使用者要画混乱路线还是做其它弹道表现。

## 6. Content 路线配置

`RoutePathConfig（路线引导配置）`调整为：

```csharp
public float IntermediateSpreadRadius = 1.25f;
public float FinalSpreadRadius = 0.30f;
public float HighAccuracySpreadScale = 0.25f;
public int SpreadSafetyShrinkSteps = 4;
public float ArrivalTolerance = 0.35f;
```

字段语义：

- `IntermediateSpreadRadius（中间段散布半径）`：精度最差时的中间偏航基础上限。
- `FinalSpreadRadius（最终段散布半径）`：精度最差时的最终残余散布基础上限。
- `HighAccuracySpreadScale（高精度散布比例）`：精度为 1 时仍保留的最低风格散布比例，默认 0.25。
- `SpreadSafetyShrinkSteps（安全收缩次数）`：候选点不安全时最多折半收缩 4 次。
- `ArrivalTolerance（到达容差）`：判断首段原版偏航是否仍可视为到达当前名义锚点，默认 0.35 格。

删除旧字段：

```text
AnchorSpreadRadius（锚点散布半径）
LowSkillSpreadMultiplier（低技能散布倍率）
HighSkillSpreadMultiplier（高技能散布倍率）
```

本项目默认不做向后兼容；旧字段不保留别名。删除原因是原版精度快照已经包含射手能力，再乘一次技能倍率会重复惩罚。

`ArrivalTolerance（到达容差）`当前没有实际消费者。本事项会给它唯一且必要的职责：首段原版偏航导致实际落点无法连接下一段时，判断是否需要先回接当前名义锚点。它不参与普通续段的飞行完成判定。

## 7. 续段偏航算法

### 7.1 有效精度与半径

```text
quality = clamp01(StandardAimChance)
spreadScale = lerp(1.0, HighAccuracySpreadScale, quality)

中间段半径 = IntermediateSpreadRadius × spreadScale
最终段半径 = FinalSpreadRadius × spreadScale
```

默认范围：

- 中间段：0.3125～1.25 格。
- 最终段：0.075～0.30 格。

这些是首版标定值，正式实施后必须通过游戏内低技能/高技能、晴天/恶劣天气对照实测；只有实测证明风格过弱或过强时才调整 XML（可扩展标记语言）数值，不在算法中增加补丁式常量。

### 7.2 稳定随机

沿用现有稳定种子结构：

```text
AttackInstanceId（攻击实例）
+ ResultId（结果标识）
+ EmitSequence（轮内发射序号）
+ SegmentIndex（段序号）
+ SampleKind（中间/最终样本类型）
```

每段在圆盘内均匀采样，使用 `Rand.PushState / Rand.PopState（随机状态入栈/出栈）`，不污染全局随机状态。

同一存档、同一发子弹、同一段必须得到相同偏移；不同发和不同段必须独立。

### 7.3 安全约束

对名义目的地加偏移后，候选点必须满足：

1. 候选格在地图内。
2. 候选格可被看过，不落入完整遮挡格。
3. 当前投射物实际位置到候选格具有 `LOS（直线视野）`。
4. 非最终段时，候选格到下一个名义路径点仍具有 `LOS（直线视野）`。

失败时把偏移向量减半并重试，最多 `SpreadSafetyShrinkSteps（安全收缩次数）`次。仍失败则返回零偏移，使用下一段名义目标。

首段由原版发射链接管，可能自然落在首锚点附近的其它位置。若从该实际位置连下一段的零偏移名义目标也不安全，则按以下规则处理：

1. 实际位置距离当前名义锚点大于 `ArrivalTolerance（到达容差）`：不推进 `CurrentLegIndex（当前段序号）`，先生成一条回接当前名义锚点的续段。
2. 回接段只负责恢复规划路线，不重新判命中，也不追加随机散布。
3. 到达当前名义锚点后，再正常推进下一段。
4. 实际位置已经在容差内，但下一段因地图变化不安全：不得循环回接；仍提交下一段名义路径，让统一投射物宿主按真实客观阻挡裁短并命中阻挡物。

这样只修复“本发原版精度偏航造成的断链”，不会把确认后新出现的真实墙误判成需要绕过的随机误差。

该回退只防止随机偏航主动破坏已经确认的合法路线。若地图在确认后出现真实新增阻挡，例如新墙、护盾或其它客观障碍，统一投射物宿主仍按现有碰撞扫描终结投射物；路线模块不得赋予穿墙能力。

### 7.4 段类型

- 首段：保持现有原版发射结果，不使用本算法。
- 中间续段：使用 `IntermediateSpreadRadius（中间段散布半径）`。
- 最终续段：使用 `FinalSpreadRadius（最终段散布半径）`，并以冻结最终落点为基准。
- 零锚点直射：没有续段，行为完全不变。

## 8. 运行时序

```text
玩家确认路线
  → 冻结名义锚点与最终目标
  → ProjectileInit（投射物初始化）为每发选择手动/自动左路/自动右路
  → BdpVerb_Shoot 按现有原版链发射首段
  → 生成并写入本发 ProjectileAccuracySnapshot
  → 首段自然到点
  → Arrival（到达阶段）读取本发精度快照
  → 若实际落点无法连下一段且未到当前名义锚点：先回接当前名义锚点
  → 推进 CurrentLegIndex（当前段序号）
  → 中间段：生成较大受约束偏航
  → 最终段：生成独立小散布并收束
  → 无下一段时回落现有命中/Impact（冲击）链
```

手动路径与自动路径只在锚点来源上不同，偏航和收束算法完全共用。

自动左右分流继续按轮内发射序号奇偶选择；精度快照、随机种子和当前段状态均按每发独立保存，不共享可变状态。

## 9. 命中与碰撞边界

- 路线模块只提供 `NextFlightPathSnapshot（下一段飞行路径快照）`、下一目标和继续飞行结论。
- 不改写 `ProjectileHitFlags（投射物命中类别）`。
- 不把偏航点写成语义最终目标。
- 不在中间段执行 Hit（命中）或 Impact（冲击）模块。
- 不吞掉统一宿主发现的客观阻挡。
- 不因最终收束恢复已经失去的预定目标命中资格。
- 最终目标移动时继续使用现有冻结落点；本事项不把毒蛇改成追踪弹。

## 10. 错误处理与诊断

以下属于正常结果，不写常规日志：

- 精度快照缺失并使用 0.5 回退。
- 候选偏航不安全并逐步缩小。
- 所有偏航候选失败并回退名义锚点。
- 最终段保留残余散布而未命中。

只有游戏内出现以下异常时，才增加可插拔临时诊断：

- 同一发同一段读档前后偏移不同。
- 偏航候选通过校验后仍从静态墙中穿过。
- 自动左右路线读取到错误发射序号。
- 原版命中类别在续段后改变。

临时日志前缀统一为 `[BDP.Content.RoutePath.OrderedSpread]`，不得预埋逐 Tick（游戏刻）常驻日志。

## 11. 风险与控制

### 11.1 命中结论和几何目标耦合

风险最高。现有发射链同时决定物理落点和命中类别。实施时只允许新增只读精度快照，不得让路线模块重新裁定或修复原版命中类别。

### 11.2 精度重复计算

删除旧技能插值，续段只消费 `StandardAimChance（标准目标瞄准概率）`。专项检查必须禁止 `RoutePathModule（路线引导模块）`继续读取 `SkillDefOf.Shooting（射击技能定义）`。

### 11.3 随机偏航破坏路线

通过 LOS（直线视野）双向检查、折半收缩、零偏移回退和首段失准后的名义锚点回接控制。已经到达名义锚点后出现的新阻挡不得触发回接循环，也不得通过忽略碰撞解决。

### 11.4 存读档与多发串线

精度快照跟随每发计划深存档；随机种子必须包含轮内发射序号。读档缺失采用中性回退，不反查运行时会话。

### 11.5 平衡偏差

算法保持不动，优先只调整 XML 数值。首轮实测至少覆盖射击技能 0、10、20，晴天与恶劣天气，单锚点与多锚点，手动与自动左右路线。

## 12. 不做范围

- 不逐段重跑原版 `ShotReport（射击报告）`。
- 不把中间锚点变成攻击目标。
- 不做 A*（A 星）寻路或飞行中重算自动路线。
- 不修改毒蛇伤害、射速、射程、Trion（三离子）消耗和自动左右分流规则。
- 不修改猎犬追踪、爆炸、拖尾和其它远程模块。
- 不把 `ArrivalTolerance（到达容差）`扩展成所有飞行段的通用到点判定；它只服务首段失准后的安全回接。
- 不更新旧版模组。
- 不以 DevHarness（开发测试模组）替代主模组正式业务实现。

## 13. 验证设计

### 13.1 静态专项检查

- 精度快照属于 Core 中性命名并实现深存档。
- `ProjectileInitPlan（投射物初始化计划）`保存精度快照。
- `BdpVerb_Shoot（BDP 射击动词）`只在正式原版报告生成后写入一次。
- `ArrivalStageContext（到达阶段上下文）`只读暴露快照。
- Content 不复制原版天气、技能、武器距离档或烟雾公式。
- 路线模块不再读取 `SkillDefOf.Shooting（射击技能定义）`。
- 中间和最终半径独立，最终半径小于中间半径。
- 偏航包含稳定种子、安全收缩和名义锚点回退。
- 首段原版偏航无法安全连接下一段时先回接当前名义锚点；已经到达名义锚点时不得回接循环。
- 首段与零锚点直射不预写飞行快照。
- Core 零本模组程序集依赖检查继续通过。

### 13.2 构建与回归

- `BDP.Core.csproj（核心工程）`Release（发布）构建通过。
- `BDP.Content.csproj（内容工程）`Release（发布）构建通过。
- 远程计划存档、续段、客观阻挡、目标语义、轮内发射序号、路线模块和统一投射物专项检查全部通过。
- 全量 PowerShell（微软命令行脚本）专项检查无新增失败。

### 13.3 游戏内实测

1. 零锚点直射与当前版本一致。
2. 单锚点时首段保持当前原版发射，最终段明显收束并保留小散布。
3. 多锚点时中间段偏航明显，但每段都能接回后续路线。
4. 低技能比高技能更凌乱。
5. 恶劣天气比晴天更凌乱。
6. 不同毒蛇武器精度预设产生可观察差异。
7. 首段原版野射落点无法直接连接下一段时，会先回接首锚点再继续，不会断链。
8. 锚点贴近墙角时，随机偏航不会主动进入墙格。
9. 已经到达名义锚点后新增真实阻挡仍会拦截子弹，不发生无限回接。
10. 四发自动路径在左右两路间继续按 0/1/2/3 交替。
11. 保存并读档后，同一发同一段保持相同偏航。
12. 最终段会出现贴近目标但未命中的可见失手，不会变成必中。
