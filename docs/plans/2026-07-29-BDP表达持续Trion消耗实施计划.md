# BDP 表达持续 Trion 消耗 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 删除芯片激活固定持续费用，建立由最终有效表达统一登记的来源数量价目表，并让候选状态芯片在一个有效来源时消耗 2 Trion/秒、两个有效来源时合计消耗 5 Trion/秒。

**Architecture:** 芯片本体只保留容量、一次性激活费用和功率要求；每条表达在 `Trion.SustainCostBySourceCount` 中声明统一价目表。表达投影完成后，由一个通用对账服务按正式宿主身份聚合有效结果、选择合计费用，并只改写中央 Trion 账本中发生变化的 `Expression` 领域条目；不恢复 Hediff 专属扣费组件。

**Tech Stack:** C# 7.3、RimWorld 1.6 `DefModExtension` XML 反序列化、现有表达投影与 Trion 账本、PowerShell 冒烟测试、MSBuild、Core 单向依赖门禁。

**Status（状态）：** 2026-07-29 已实施完成。三个程序集 Release（发布）构建均为 0 警告、0 错误，Core 单向依赖门禁通过；47 个 XML 全部可解析；233 项主模组冒烟测试为 221 项通过、12 项既有基线失败、新增失败 0；候选护盾专项测试通过。游戏内实际扣速与颜色/手感观察仍由用户实测。

### Task 5：建立最终有效表达统一对账

**Files:**

- Create: `Source/BDP/Core/Expressions/Runtime/ExpressionSustainDrainService.cs`

**Step 1：定义稳定聚合键**

`ExpressionSustainDrainKeyFactory`生成：

```csharp
new TrionDrainKey("Expression", result.ResultKind.ToString(), -1, stableEffectIdentity)
```

稳定效果身份按现有正式宿主语义解析：

- Hediff：`HediffDefName`。
- Ability：`AbilityDefName`。
- Passive：`PassiveKey`。
- 普通 Verb：来源 `ChipDefName + ":" + result.Id`，避免不同芯片碰巧复用条目 ID 后错误聚合。
- Combo：`ComboDefName + ":" + result.Id`。
- 其它缺少正式身份的结果：不登记并输出一次性诊断，禁止使用显示文字当键。

同一 Hediff Def 或 Ability Def 的多个有效结果应得到相同键，因此只形成一条最终效果账单。

**Step 2：构建目标账单**

`ExpressionSustainDrainService`只读取：

```csharp
result != null
&& result.IsAvailable
&& result.Trion?.SustainCostBySourceCount?.Count > 0
```

先按稳定效果键分组，再：

1. 统计有效来源数量。
2. 确认同组价目表一致。
3. 调用 `ExpressionSustainCostPolicy.ResolveTotalPerSecond`。
4. 费用大于 0 时生成一条目标账单。

同组出现不同价目表时，记录一次明确诊断并采用按结果 ID 稳定排序后的第一张表，避免运行结果随集合顺序漂移；该情况视为业务定义错误，不自动合并两张不同价目表。

**Step 3：与中央账本差量对账**

通过 `ITrionReader.GetDrainSnapshot()`读取现有账单，只处理 `Domain == "Expression"`的条目：

- 旧键不在目标中：`UnregisterDrain`。
- 新键不存在：`RegisterDrain`。
- 同键数值变化：覆盖注册。
- 同键数值相同：不操作。

不保存额外可序列化账本；读档后 `CompTrion`先清空注册表，正式表达重新发布时自然重建。

**Step 4：接入唯一发布点**

`ExpressionService`构造时建立 `ExpressionSustainDrainService`，并在：

```csharp
hostSynchronizer?.Sync(pawn, snapshot);
sustainDrainService.Reconcile(pawn, snapshot);
```

处统一对账。

空投影同样调用 `Reconcile`，从而在解除战斗体、关闭全部芯片或卸下 Trigger 时清除旧表达账单。

**Step 5：更新玩家可读账单来源**

`Gizmo_TrionStatus`新增 `Expression`领域说明：

```text
状态表达维持消耗
技能表达维持消耗
被动表达维持消耗
攻击表达维持消耗
```

删除不再可能出现的“主/副/特殊触发槽芯片持续消耗”和旧 `Hediff`领域专属文案；保留未知来源回退。
