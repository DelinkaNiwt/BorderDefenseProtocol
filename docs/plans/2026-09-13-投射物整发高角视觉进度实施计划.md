# 投射物整发高角视觉进度 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让高角视觉只按一发投射物的整发进度完成一次起飞与落下，不因追踪或其它模块替换物理路径而重复播放弧线。

**Architecture:** 保留 `currentFlightPathSnapshot`（当前物理路径快照）作为移动、朝向、碰撞和到达的唯一物理真值；把高角视觉的升降进度改为投射物级、单调的全局进度。视觉水平基准继续使用投射物当前真实位置，避免移动目标时视觉落点冻结；高角模块不读取路径段或续飞类型。优先复用现有投射物生命周期，只有无法表达整发进度时才增加一个通用进度值。

**Tech Stack:** C# 7.3、.NET Framework 4.8、Unity/RimWorld、PowerShell 冒烟测试、`dotnet msbuild`。

### Task 2: 把视觉轨迹求值改为“双进度”

**Files:**

- Modify: `C:\NiwtDatas\Projects\RimworldModStudio\模组工程\BorderDefenseProtocol\Source\BDP\Core\Projectiles\BdpProjectile.cs`

**Step 1: Write the minimal implementation**

- 将视觉轨迹求值接口明确分为 `pathProgress`（当前物理段进度）和 `trajectoryProgress`（整发视觉进度）。
- 视觉基础位置使用 `pathProgress`，确保当前投射物位置和追踪转向不变。
- 高角偏移使用 `trajectoryProgress`，确保 `0 → ArcHeight → 0` 只执行一次。
- 视觉切线与拖尾采样使用同一组双进度，避免位置、朝向和拖尾分开重置。
- 在投射物发射时初始化整发进度；路径续飞时只更新物理段，不清零整发进度。
- 优先使用现有的整发生命周期信息计算进度；如当前 `ticksToImpact` 在续飞时无法表达整发进度，则增加最小的通用投射物级进度存储，并加入存读档。
- 不在 Core 增加 `Homing`、`HighAngle` 或 `terminal_approach` 分支。
