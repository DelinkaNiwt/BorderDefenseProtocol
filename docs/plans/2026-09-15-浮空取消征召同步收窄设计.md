# 浮空取消征召同步收窄设计

## 目标

让玩家 Pawn 取消征召时，在原版清理工作前立即解除实际浮空状态，同时保留该 Pawn 的浮空偏好；征召时不在原版 `Drafted` setter 的前置阶段提前添加浮空 Hediff。

## 已确认的架构

- `GameComponent_FloatingFlight` 保存 Pawn 个体的持久偏好。
- `BDP_Hediff_FloatingFlight` 是实际浮空状态的唯一真值，并负责浮空自身许可。
- `FloatingFlightStateController.Reconcile` 负责常规状态收口。
- Harmony 只作为取消征召的生命周期边界补丁，不替换原版 setter，也不阻止原版继续执行。

## 本次最小改动

1. 保留 `Pawn_DraftController.set_Drafted` 的 Harmony `Prefix`。
2. Prefix 只处理 `value == false` 的取消征召路径。
3. 取消征召路径继续使用强制收地逻辑：必要时先寻找合法地面，再移除浮空 Hediff。
4. `value == true` 的征召路径不在 setter 前添加 Hediff；由原版完成征召后，再由现有 Reconcile 流程按偏好和环境决定是否添加。
5. 不修改 `PreferredMode`，不新增状态真值，不改 Core。

## 验收标准

- 取消征召前置补丁只调用取消征召同步入口。
- 取消征召后偏好记录仍保持原值。
- 征召时不会在 `Drafted` setter 的前置阶段提前添加浮空 Hediff。
- 现有浮空状态、寻路、许可和存档测试保持通过。
- Content Release 构建通过。
