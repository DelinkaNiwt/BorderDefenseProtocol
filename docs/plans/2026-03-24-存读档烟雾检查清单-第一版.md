# 存读档烟雾检查清单

## 目标

- 确认当前主模组已实现的触发体、芯片、表达入口在存档后读回时仍保持同一事实状态。
- 重点不是看一两个按钮是否偶然还在，而是看“槽位装载状态”和“激活后的攻击入口”有没有一起恢复。

## 测试步骤

1. 进入游戏，生成测试触发体并让殖民者装备。
2. 点击开发测试按钮：
   - `测 装主远程`
   - `测 装副近战`
   - `测 开主`
   - `测 开副`
3. 确认此时已经能看到对应的远程/近战测试按钮，或能触发对应自动攻击入口。
4. 立即存档。
5. 退回主菜单后重新读入该存档。
6. 读档后重新检查：
   - 主槽 0 仍装有远程芯片。
   - 副槽 0 仍装有近战芯片。
   - 主侧、副侧原本的激活状态仍成立。
   - 远程/近战测试入口仍能出现并正常工作。
7. 再做一次攻击，确认读档后的攻击表现与读档前一致。

## 预期结果

- 读档后不需要重新装芯片。
- 读档后不需要重新激活槽位。
- 远程/近战入口不应因为读档而消失。
- 芯片本身若带有内部 comp 或状态，应随芯片一起被恢复，而不是只剩一个槽位字段引用。

## 当前已知边界

- 这份清单验证的是“当前已经接上的第一批主链”。
- 如果某个旧存档是在修复前保存的，里面本来就没有把芯片正式收进容器，则不能保证自动补回。
