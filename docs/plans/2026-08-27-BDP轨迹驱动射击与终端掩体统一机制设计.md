# BDP 轨迹驱动射击与终端掩体统一机制设计

日期：2026-08-27  
状态：已确认设计基线，待编写实施计划  
适用范围：BDP 远程攻击执行、路线弹道、视觉弹道；首个业务验证对象为毒蛇

## 1. 设计目标

解决当前路线弹道的两个根本问题：

1. 原版已经在发射时判定子弹偏射或被掩体拦截，但路线模块仍可能把弹道续接回名义目标，导致视觉飞行和逻辑结果不一致。
2. 原版掩体判定使用射击者位置作为几何起点。对于多段路线弹道，真正应该参与掩体方向计算的是子弹最终一段飞行路径的起点。

本设计不把问题限制为“毒蛇是否无视掩体”，而是建立通用的轨迹驱动射击解析：

```text
子弹的最后一段轨迹决定目标掩体
整条轨迹决定实际飞行障碍
发射时决定首发命中分支
后续碰撞决定最终撞击对象
视觉只表现实际执行的轨迹
```

普通直射子弹只有一段轨迹，因此不需要特殊的“射击者方向”分支。

## 2. 原版机制事实

### 2.1 发射时的命中分支

原版 `Verb_LaunchProjectile.TryCastShot` 的顺序为：

```text
检查射击线
→ 强制未命中
→ ShotReport
→ wild miss（偏射）
→ cover intercept（掩体拦截）
→ intended target（目标分支）
```

`ShotReport.HitReportFor` 在发射时计算射击精度、距离、装备、天气、遮蔽气体、黑暗和掩体等因素。

### 2.2 原版掩体判定

`CoverUtility.CalculateCoverGiverSet` 和 `CalculateOverallBlockChance`：

- 检查目标周围 8 个相邻格；
- 取得相邻格中的掩体物体；
- 按掩体相对目标的方向与传入起点相对目标的方向计算角度；
- 按掩体距离起点的距离进一步修正阻挡概率；
- 由同一组掩体结果产生总体阻挡概率和随机拦截掩体。

原版参数名为 `shooterLoc`，但其实际作用是几何起点。设计上将其统一理解为 `CoverOriginCell`，不引入射击者语义。

### 2.3 原版射击线与硬阻挡

`GenSight.LineOfSight` 检查起点和目标之间的中间格，并使用 `CanBeSeenOverFast` 判断是否可见；目标格本身不作为中间阻挡格。`LineOfSightToEdges` 和 `ShootLeanUtility` 还提供边缘和探身关系。

因此，墙体、山体等物体可能具有两种不同角色：

- 位于路线内部且切断实际飞行路径时，是硬阻挡物；
- 位于目标邻接位置、原版允许从该角度互射时，是终端掩体。

不能按 `ThingDef` 类型静态地把墙体或山体归类为某一种角色。

### 2.4 子弹飞行与最终碰撞

原版 `Projectile` 在飞行到具体格子时，使用 `CanHit` 和 `ThingsToHit` 根据 `HitFlags` 过滤目标，再由 `ImpactSomething` 处理实际撞击。`CoverUtility.ThingCovered` 还会单独阻止完全被完整物体覆盖的目标。

首发命中分支、路线续飞和最终碰撞不是同一件事，不能相互推断。

## 3. 核心模型

在 Core 中增加中性的轨迹与发射解析数据，不让 Core 认识“毒蛇”这个业务名称。

### 3.1 轨迹快照

路线在发射前已经存在时，生成 `ProjectileTrajectorySnapshot`，至少包含：

- 发射位置和发射格；
- 有序的路径段；
- 最后有效路径段的起点；
- 最终目标；
- 路线中用于物理障碍检查的路径信息。

统一定义：

```text
FinalApproachStart = 最后一段飞行路径的起点
```

当没有锚点时：

```text
FinalApproachStart = 子弹实际发射位置
```

不再定义 `ShooterCoverMode` 或“普通武器 / 毒蛇”的掩体起点分支。

### 3.2 终端掩体快照

在发射时依据 `FinalApproachStart` 生成 `TrajectoryCoverSnapshot`，包含：

- 掩体几何起点；
- 原版 `CoverInfo` 列表；
- 总体掩体阻挡概率；
- 可供掩体拦截分支使用的掩体对象。

总体阻挡概率和随机掩体对象必须来自同一份快照，避免概率方向和实际拦截对象方向不一致。

这一步只替换掩体的几何起点，不重写原版掩体角度、距离、基础阻挡率和组合概率公式。

### 3.3 发射结果快照

在真正调用 `Projectile.Launch` 前记录 `ProjectileLaunchDisposition`：

```text
ForcedMiss
WildMiss
CoverIntercept
IntendedTarget
```

同时记录：

- 是否允许命中原定目标；
- 原版实际发射目标或偏射终点；
- 当前路线的续飞模式；
- 偏射路线所需的冻结偏移量。

该结果写入 `ProjectileInitPlan`，并由子弹、到达阶段和视觉启动上下文共同读取。

## 4. 终端掩体与硬阻挡的统一裁定

### 4.1 终端段优先使用原版掩体语义

对最后一段路径：

```text
FinalApproachStart → FinalTarget
```

使用原版 `CoverUtility` 重新计算目标周围掩体。

如果目标位于墙体、山体等完整物体后的最外侧位置，且原版几何关系允许互射，则该物体进入终端掩体结果，而不是被直接判定为绝对阻挡。

如果最终段不存在合法的目标接近关系，则不能仅靠掩体概率放行，应由路线和射击线安全检查判定为不可达或硬阻挡。

### 4.2 中间段继续使用物理障碍语义

整条路线仍然执行现有的路径安全检查和物理阻挡检查：

```text
锚点1 → 墙体/山体 → 锚点2
```

这种墙体或山体是路径硬阻挡物，毒蛇必须绕行，不能因为终端掩体机制而穿透。

终端段的“目标邻接掩体例外”只适用于原版允许互射的目标关系，不扩展到路线中间。

### 4.3 其他掩体的处理

砂袋、路障和其他可作为掩体的物体不再被全局忽略：

- 位于最终进攻方向上：参与掩体判定；
- 只位于旧的射击者到目标方向上：不参与当前终端掩体判定；
- 位于中间路径且构成实际物理障碍：仍由路径碰撞检查处理。

## 5. 首发结果与路线续飞

### 5.1 `IntendedTarget`

沿正常锚点路线继续飞行，并保留命中原定目标的资格。

### 5.2 `WildMiss`

保留原版在发射时产生的偏射结果，不重新抽取第二次随机命中。

毒蛇仍然可以保持蛇形外观，但不能重新接回目标中心。实现方向是：

1. 冻结原版偏射向量或实际偏射终点；
2. 将该偏移应用到名义路线，生成偏移后的路线；
3. 使用已有的路线安全检查和收缩机制验证每一段；
4. 如果偏移路线不安全，逐步缩小偏移；
5. 仍无法形成安全路线时，退回原版偏射的直线飞行。

偏射分支保留原版 `HitFlags` 和目标语义，不授予原定目标的命中资格。

### 5.3 `CoverIntercept`

沿最终进攻段上由同一份掩体快照选出的实际掩体飞行，不再继续接回名义目标。

### 5.4 `ForcedMiss`

保持原版强制未命中行为。除非某个具体轨迹模块显式声明允许视觉路线延续，否则不由路线系统重新接管。

## 6. 视觉一致性

视觉系统不再根据名义目标自行生成路线。

视觉只消费：

- 子弹当前真实位置；
- 路线续飞后的真实采样点；
- 发射结果和实际终点。

因此：

```text
命中分支    → 正常蛇形路线
偏射分支    → 偏移后的蛇形路线或原版直线偏射
掩体拦截   → 飞向实际掩体
强制未命中 → 保留原版轨迹
```

第一阶段不额外制造纯视觉随机偏差；先保证视觉使用真实执行轨迹。若实际游戏观察仍然难以辨认偏射，再在 Development 诊断结果充分后增加不影响碰撞的表现强化。

## 7. 模块边界

### Core.dll

负责：

- 轨迹快照；
- 最终进攻段抽取；
- 终端掩体快照；
- 发射结果状态；
- 路线续飞准入；
- 视觉上下文传递。

Core 不出现毒蛇、砂袋或具体业务武器名称。

### Content.dll

负责：

- 提供毒蛇路线和锚点配置；
- 选择路线弹道的通用轨迹策略；
- 不直接读取原始 `ProjectileHitFlags` 猜测发射结果；
- 不复制原版 `ShotReport` 或 `CoverUtility` 公式。

### Development.dll

仅在需要实际进游戏复现时提供可插拔诊断：

```text
发射分支、最终进攻起点、掩体列表、实际首发目标、续飞决定、最终碰撞结果
```

不记录逐 Tick 弹道日志。

## 8. 不做的事情

- 不全局 Harmony 修改 `CoverUtility`；
- 不把毒蛇实现成完全无视掩体；
- 不为每个锚点重新执行完整 `ShotReport`；
- 不对每个路径段重复掷掩体概率；
- 不用目标最终是否受伤来反推路线应该怎样飞；
- 不用 `ProjectileHitFlags` 单独推断首发分支；
- 不改变普通直射子弹的原版行为；
- 不在 Core 中硬编码具体业务文案。

## 9. 验收标准

### 原版直射基线

- 无锚点时，掩体结果与原版直射一致；
- 天气、光照、距离和射击能力仍按原版计算；
- 目标完全被完整物体遮蔽时，仍不能被错误命中。

### 路线弹道

- 最终段前方的砂袋、路障按最终方向影响命中；
- 只挡住旧射击方向的掩体不再错误影响命中；
- 目标贴墙或贴山体的最外格可复现原版允许互射关系；
- 路线中间的墙体、山体仍然是硬阻挡；
- 没有合法绕行路线时不会穿墙。

### 首发结果与视觉

- `wild_miss` 不再重新吸附到目标；
- `wild_miss` 可沿偏移后的蛇形路线飞行，失败时退回原版直线偏射；
- `cover_intercept` 不再继续接回名义目标；
- 正常命中分支仍可按锚点路线飞行；
- 视觉路径、实际碰撞和首发分支一致。

### 回归范围

- 普通 BDP 直射弹道；
- 毒蛇路线弹道；
- 追踪弹道的续飞状态机审计；
- 组合技发射；
- 存档读写；
- Core / Content / Development 依赖边界。

## 10. 实施顺序

1. 增加轨迹最终段和发射结果的 Core 数据模型。
2. 在发射时生成终端掩体快照，并替换掩体概率和随机掩体来源。
3. 将首发结果传入路线到达阶段，拆开“命中资格”和“路线续飞资格”。
4. 实现 `wild_miss` 的冻结偏移路线和安全回退。
5. 接通视觉上下文，确保拖尾只跟随真实路径。
6. 增加静态烟测、路线烟测和 Development 最小诊断入口。
7. 编译并执行原版基线、路线边界、存档和组合技回归验证。
