# 自施放能力预热视觉根因修正设计

## 已确认的根因

上一版 `BdpVerb_CastSelfAbility` 已跳过原版远程射线计算和瞄准线通知，但仍直接创建原版 `Stance_Warmup`。该姿态的 `focusTarg` 仍是施法者自身，原版武器渲染因此进入瞄准分支；由于目标位置与施法者重合，瞄准角保持默认值 0°，武器表现为朝北。

原版 `Stance_Warmup.StanceDraw()` 的内置预热指示器只有 `GenDraw.DrawAimPie` 扇形，没有可配置的中心圆形模式。`AbilityDef` 参数只能关闭它，不能把它切换为目标需求的圆形进度显示。

## 方案

在 Core（核心层）新增通用 `BdpStance_SelfCastWarmup`，继承 `Stance_Warmup`：

1. 完整复用原版前摇计时、音效、Effecter（效果器）、目标复核、结束时序和保存流程。
2. 使用原版 `Stance_Busy.neverAimWeapon` 语义，阻止自施放姿态把武器送入瞄准绘制分支。
3. 覆盖 `StanceDraw()`，复用原版 `GenDraw.DrawCooldownCircle`（冷却圆绘制）在施法者中心绘制按剩余前摇比例收缩的粗圆形，不调用原版扇形绘制。
4. 圆环只属于“通用自施放姿态”这一表现分支，不引用变色龙名称、Hediff、冷却或其他业务规则。

普通远程能力继续使用 `BdpVerb_CastAbility` 和原版远程预热表现；变色龙只通过已有的通用自施放 Verb 进入该分支。

## 边界与验证

- 不增加 DLC 依赖，不使用远程能力的瞄准线或攻击式身体抖动；只复用原版通用圆形绘制接口，不依赖 DLC 能力特效。
- 只改 Core 自施放姿态和对应边界测试；不改变变色龙效果、Hediff 生命周期、冷却或持续消耗。
- 通过自施放视觉边界、变色龙 Def、攻击路由/关闭、能力冷却、持续消耗相关回归，并完成三程序集 Release 构建。
