# 光魂推进目标确认与伤口来源设计

## 已确认的问题

1. 光魂推进专用 Verb 只重写了 `CanHitTarget`（预览可见性），但继承的地面冲刺 `ValidateTarget`（确认校验）仍要求目标格在射程内且完整穿过地图路径，因此射程外和建筑后的目标只能预览，不能左键确认。
2. 光魂推进的 `DamageInfo`（伤害信息）只提供了释放者作为 `Instigator`（发起者），没有提供伤口界面所需的 `sourceLabel/sourceDef`（来源名称/来源定义）。

## 设计

### 目标确认

光魂推进专用 Verb 自己实现确认校验，并复用 `GroundDashUtility.TryResolvePath`（地面冲刺路径解析）：

- 射程外目标按最大射程裁剪，允许确认，实际推进到裁剪后的终点。
- 建筑后的目标允许确认，实际推进到建筑前最后一个可用格。
- 释放者前方没有任何可移动格时仍拒绝确认。
- 其它地面冲刺能力继续使用基类的严格射程和建筑校验。

### 伤口来源

光魂推进飞行器配置组合技的显示名称，并在每次钝伤调用外压入一个 `SemanticContext`（攻击语义上下文）：

- 显示名称沿用能力语言包名称，并追加释放者名称。
- 使用现有 `SemanticRuntimeScope` 和 `BdpDamageSemanticBridge`，让原版伤口创建补丁写入来源。
- 伤害合并到已有 `Hediff_Injury`（伤口）时，沿用现有合并补丁刷新来源。
- 不改变伤害数值、体型停止力、推挤队形或撞击眩晕。

## 错误处理

- 没有有效路径时仍返回失败，不生成飞行器。
- 能力来源名称缺失时语义桥自然回退原版伤口来源，不硬编码玩家文案。
- 只在当前伤害调用作用域内传递语义，避免污染其它伤害。

## 验证

- 先新增目标确认和伤口来源的失败契约测试，确认当前实现确实捕获两个问题。
- 修改后运行相关冒烟测试、XML 解析、`BDP.Content` Release 构建和 Core 隔离检查。
- 最后进游戏复测射程外、墙后确认，以及伤口标签显示能力名和释放者名。
