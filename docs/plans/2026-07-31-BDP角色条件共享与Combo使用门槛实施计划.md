**Step 1：建立中性模型**

核心形态：

```csharp
public abstract class PawnRequirement
{
    public abstract string Label { get; }
    public abstract PawnRequirementSnapshot Describe();
    public abstract string ValidateDefinition();
    public abstract PawnRequirementSnapshot Evaluate(Pawn pawn);
}
```

`PawnRequirementEvaluator`只接收`IReadOnlyList<PawnRequirement>`；按列表顺序构建快照和失败项。没有条件时返回满足的空结果。

**Step 2：建立统一列表校验**

`PawnRequirementListValidator`返回中性诊断列表并检查：

- 空条件项；
- 每项`ValidateDefinition`；
- 最多一个`TrionIntensityRequirement`；
- 同一`SkillDef`不得重复；
- 允许未来未知派生条件按自己的校验规则存在。

芯片校验器额外要求“恰好一个释放力条件”；Combo 不附加该要求。

**Step 3：保留芯片薄适配器**

`ChipActivationRequirementService`只负责从芯片契约取得`ActivationRequirements`，然后调用统一求值器。Trigger和两处界面仍通过该适配器，不直接读取XML。
