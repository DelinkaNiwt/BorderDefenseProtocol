# 武装构型泛化重构 Implementation Plan（实施计划）

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement the plan task-by-task.

**Goal:** 将芯片制造中的枪壳机制重构为“动作内芯 + 一个显式或隐式有效武装构型 + 一个统一覆盖块”，在不改变现有枪械行为的前提下接通近战、视觉和远程模块覆盖；保留枪械构型可选 1~2 个动作、其它构型默认单动作的现状规则。

**Architecture:** 保留 ChipCombinationResolver（芯片组合解析器）作为唯一组合真值入口。ChipArmamentFormDef（武装构型定义）默认允许一个动作；现有枪械构型数据声明允许两个动作，两个动作先合并为一个多形态动作。解析器先确定显式可见构型或隐式默认构型，再合并动作并由一个统一的 ChipArmamentFormOverrides（武装构型覆盖块）一次性覆盖适用表达条目。射手远程武装芯片使用不可见的 Trion 立方体默认构型，但该构型不进入制造台、不参与动态名称。武装构型属于 BDP.Content.dll（内容程序集），BDP.Core.dll（核心程序集）只继续消费中性的 SourceVariantKey/Label（来源变体键/标签）。本计划不建立远程、近战、视觉或投射物子模块注册表。

**Tech Stack:** C# 7.3、.NET Framework 4.8、RimWorld 1.6 Def / DefModExtension / ThingComp、XML Def、PowerShell 冒烟测试、dotnet msbuild、Core/Content 程序集隔离门禁。

**状态：** 已实施并完成本轮收口验证（2026-08-22）。后续只保留临时攻击手型的游戏内实测与删除，不属于本架构重构的必需收口项。

## 实施纪律

- 直接在当前工程执行，不创建 worktree（工作树），符合项目约束。
- 不修改当前工作区已有的参考图片、obj 缓存或其它无关变更。
- 每个任务先补边界测试，再做最小实现，再运行该任务的测试。
- 不改变现有枪械数值、动作预设数值和制造平衡值。
- 新增玩家可见文案全部写入语言包，不在 C#（C#语言）中硬编码中文。
- 不保留旧存档字段读取、别名或迁移桥；旧格式问题必须直接暴露。
- 每完成一个有独立边界的任务，提交一次小提交，便于回退。

本轮实际收口还增加了 `compatibleActionPresetDefNames`（动作适用白名单）：空列表不限制动作，非空列表要求所选动作全部匹配；制造台、显式构型校验和隐藏默认型查找共用该规则。临时攻击手型 `BDP_ArmamentForm_Temporary` 只接受 `BDP_Preset_Kogetsu`（弧月），只绑定原版破墙斧贴图视觉预设。
