# 远程连续 Job 会话代际清理修复实施计划 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 修复“旧的 `RangedAttackExecution` job 在 `InterruptForced` 清理时，把同一个 formal host 壳上刚绑定好的新攻击会话一并 `Reset()` 掉”的问题，确保远程 formal host 的 cleanup 只清理旧 job 自己那一代会话。

**Architecture:** 这次不改 dual、LOS、毒蛇锚点或 projectile 协议语义，只收口 `JobDriver_BdpRangedAttackExecution` 的会话清理责任。核心做法是把现有“按壳清理”改成“按会话代际清理”：旧 job 在启动后记录自己拥有的 `AttackSessionToken` 快照，退出 cleanup 时仅当当前 verb 壳上的 token 仍与该快照一致时才允许 `Reset()`；若壳已被新会话接管，则跳过清理。这样 formal host 壳仍可复用，但旧 job 不再误杀新 job 的运行态。

**Tech Stack:** C# / RimWorld 1.6 / BDP AttackExecution + VerbHosting / PowerShell smoke tests / `dotnet msbuild`


规则：
- job 第一次真正进入执行时，若 `job.verbToUse` 是 `BdpVerb_Shoot` 且当前存在 `HostSessionToken`，就把该 token 快照记入 job 私有字段。

- 若当前 token 已切换到新的 `attackId/resultId/projection/owner`，或者已经为 `null`，则直接跳过 cleanup reset。

比较维度不偷懒，至少包括：

- `ProjectionVersion`
- `OwnerPawnThingId`
