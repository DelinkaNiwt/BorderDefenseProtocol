# 黑触发器能力适应权重设计

## 目标

让黑触发器定义可以声明 `adaptedAbilities`（适应能力），并把人物在死亡前实际拥有的指定能力作为隐藏形成权重来源；能力不进入玩家形成决策面板。

## 现状与边界

- 现有 `adaptedTraits`（适应特性）已经在死亡前冻结人物事实，并按每项命中 `+3` 计算候选权重。
- Anomaly（异常）不是 BDP 的硬依赖；当前同来源的五个能力为 `PsychicSlaughter`、`ShapeFlesh`、`TransmuteSteel`、`ReleaseDeadlifeDust`、`UnnaturalHealing`。
- BDP 当前 `About.xml` 已硬依赖 Royalty（皇权）和 Biotech（生物科技）；本需求不改变这两个已有依赖。

## 设计

### 1. 可选定义

`BlackTriggerFormationExtension` 增加 `adaptedAbilities`。每条声明保存能力 DefName、可选来源包标识和权重增量。使用字符串 DefName，不使用直接 `AbilityDef` 交叉引用，从而在未安装 Anomaly 时安全加载。

### 2. 运行时加载

验证和匹配阶段按当前 `DefDatabase<AbilityDef>` 解析声明。能力 Def 不存在时跳过该条声明并保留诊断，不使整个 BDP 或该黑触发器定义失效；能力存在时才成为有效适配项。来源包标识仅用于可读诊断和后续内容筛选，不作为硬依赖。

### 3. 来源快照

在死亡前从人物当前 `Pawn_Ability` 列表冻结实际能力 DefName。只保存稳定字符串和必要显示信息，不保存能力运行时对象。形成计算只读取快照，避免死亡后人物引用变化影响结果。

### 4. 权重

继续使用加法模型：候选基础权重为 `1`；每个不同的命中特性增加 `3`；每个不同的命中能力增加 `3`。同一能力声明重复或同一能力多次出现只计一次。能力和特性相互独立，可同时命中。

### 5. 玩家界面与兼容

能力命中记录只留在候选计划和 Development（开发诊断）数据中，决策窗口仍只显示现有传承选项。未安装 Anomaly 时，五项能力声明全部自动失效，特性和其他形成条件照常运行。

## 测试重点

- Anomaly 已加载时五项能力可以解析并正确匹配。
- Anomaly 未加载时无 XML 错误、无形成池整体失效。
- 能力命中分别产生 `1`、`4`、`7` 等预期权重，并与特性命中叠加。
- 重复声明和重复来源能力只计算一次。
- 玩家决策面板不出现能力、命中数或权重。
