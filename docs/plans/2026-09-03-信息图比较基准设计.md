# 信息图比较基准设计

日期：2026-09-03

## 已确认事实

1. `ChipCombinationResolver` 在 `ArmamentFormDefName` 为空时，会调用 `FindImplicitDefaultArmamentForm`；远程武装功能因此会使用数据定义的隐藏默认武装型。
2. `ChipManufacturingPreviewBuilder` 当前把应用武装型前的 `DeclaredConfig` 与应用后的 `ResolvedConfig` 合并为一份统一信息模型。
3. `ChipInformationDetailRenderer` 当前从字段来源链查找 `DeclaredDefinition` 或 `BaseDefinition`，把它们作为图表和字段标记的比较基准。
4. 武装构型的原始覆盖字段不是最终基准值；它们可能是绝对覆盖、倍率、节奏或其它解析操作，不能直接拿来代替完整解析结果。

## 目标

把装配台信息图的默认比较基准改成：

```text
同一芯片功能组合 + 隐藏默认武装型（当前数据定义为 Trion 立方体）
```

该组合必须经过与当前成品相同的统一解析流程。当前选用其它枪型时，图表、字段变化标记、精度曲线以及 RPM（每分钟射击次数）/APM（每分钟攻击次数）都比较“当前最终结果”和“默认武装型最终结果”。当前就是默认武装型时，两者应重合。

## 采用方案

在 Content 层新增轻量的比较模型和基准构建入口：

1. 详情入口为成品芯片同时构建当前信息模型和比较基准信息模型。
2. 基准记录从原组合记录复制，清空显式 `ArmamentFormDefName`，重新调用现有 `ChipCombinationResolver`，从而复用隐藏默认型解析，不复制解析规则。
3. 通过当前模型的稳定 `BlockKey + FieldKey` 把基准模型字段映射到当前字段，不修改 Core 信息模型，不把界面比较语义写进字段来源链。
4. 渲染器优先读取比较模型中的基准值；没有匹配基准或不适用默认武装型时，回退现有 `DeclaredDefinition/BaseDefinition` 基准。
5. 图表派生指标使用基准模型自身的最终字段重新计算，不能用原始来源字段拼接出 RPM/APM。
6. 比较策略保留为 Content 层的模式入口，当前默认模式为隐藏默认武装型；暂不增加玩家界面切换控件，避免为本次语义修正扩大布局范围。

## 不采用方案

- 直接把 `Variant` 来源字段当成基准：会把原始覆盖值误当成“基础值 + Trion 立方体”的最终结果。
- 修改 `ChipInformationField` 或 `ChipInformationProvenance` 的 Core 语义：会让通用信息模型承担具体装配台的业务比较策略。
- 在渲染器内手工计算 Trion 立方体修正：会绕开现有覆盖、倍率、齐射节奏和结构合并规则。

## 失败与回退处理

- 组合无效、缺少功能定义或无法解析隐藏默认型时，当前模型仍可显示，并沿用原始基础值比较。
- 当前与基准模型中某个稳定字段无法匹配时，该字段沿用原始基础值，不把缺失值绘制成零。
- 近战、护盾、能力等没有适用默认远程武装型的内容不改变现有比较逻辑。

## 验证范围

- PowerShell 冒烟测试验证基准记录复制、清空显式武装型、重新解析、稳定字段映射和渲染器接线。
- 使用现有 Trion 立方体 + 远程功能数据检查基准结果确实来自有效解析值，并覆盖齐射 RPM 的基准计算。
- 编译 `BDP.Core` 与 `BDP.Content`，运行现有信息模型、图表几何和装配台交互测试。
- 最终仍需在 RimWorld 内打开装配台，分别检查 Trion 立方体和其它枪型的图表重合/差异表现。
