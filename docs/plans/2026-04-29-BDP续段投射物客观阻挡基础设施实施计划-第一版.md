# BDP续段投射物客观阻挡基础设施 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 为所有 `BdpProjectile` 宿主管理飞行段补上中性的客观阻挡裁定，切开发射语义命中类别与续段物理阻挡，修复段内真实穿墙后继续命中的宿主级问题。

**Architecture:** 本计划不改作者面，不改业务模块接口，不改发射层 `ProjectileHitFlags` 生成口径；只在主模组投射物宿主与 `RangedFlightProtocol` 内部新增一层 `Collision` 小层，并让 `BdpProjectile` 在段末先做客观阻挡裁定，再决定继续飞行或回落原版命中。诊断日志与运行逻辑必须复用同一套段扫描事实。

**Tech Stack:** C# / RimWorld `Projectile` 宿主链 / PowerShell smoke tests / `dotnet msbuild`

记录至少包含：

- `SegmentStart`

- `TraversedCells`

第一版只认：

- `Fillage == Full` 且非开启状态的实体
- 关闭门体

### Task 4: 在宿主 `ImpactSomething()` 中接入客观阻挡裁定

**Files:**
- Modify: `Source/BDP/Core/Projectiles/BdpProjectile.cs`
- Test: `Source/BDP.Tests/ProjectileContinuationObjectiveBlockingSmokeTests.ps1`

**Step 1: 调整 `ImpactSomething()` 的宿主顺序**

顺序改为：

1. 执行 `Arrival`
2. 扫描刚结束的宿主管理飞行段
3. 若命中客观阻挡，则转入阻挡命中收束
4. 否则再执行 `continue flight` 或 `base.ImpactSomething()`

**Step 2: 只在宿主管理段应用该裁定**

该补层只服务于 `BdpProjectile` 宿主已接管的飞行段。

不要去改：

- `BdpVerb_Shoot` 的发射分支
- 原版 `Projectile` 私有自由拦截代码
- 业务模块 `Arrival` / `Hit` / `Impact` 对作者开放的接口

**Step 3: 保持原有业务边界**

客观阻挡裁定不读取任何追踪模块私有业务状态，不依赖具体模块类型，不增加追踪模块专属判断。

**Step 4: 运行续段阻挡 smoke test**

Run:

```powershell

```

### Task 5: 给阻挡命中补齐位置锚定

**Files:**
- Modify: `Source/BDP/Core/Projectiles/BdpProjectile.cs`
- Test: `Source/BDP.Tests/ProjectileContinuationObjectiveBlockingSmokeTests.ps1`

**Step 1: 新增宿主内部的阻挡命中锚点临时态**

补一个仅宿主内部可见的临时记录，用于承载：

- `pendingObjectiveBlockerImpactThing`
- `pendingObjectiveBlockerImpactCell`
- `pendingObjectiveBlockerExactPosition`

该状态只服务当前一次 `Impact` 收束，收束后立即清空。

**Step 2: 在阻挡命中时把 `Impact` 锚到阻挡格**

要求：

- 不能沿用段末格
- 不能只把 `hitThing` 改成阻挡体却保留段末位置
- `LogImpactResolution` 与战斗日志使用的命中格必须与阻挡格一致

**Step 3: 保证正常命中链不受影响**

非边界阻挡命中仍走当前正常路径，不应被该临时态污染。
