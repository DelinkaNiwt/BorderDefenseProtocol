# BDP 芯片信息设施路线 D：原版武器投影诊断原型实施计划

> **For Claude（供执行代理）:** REQUIRED SUB-SKILL（必须使用的子技能）: Use superpowers:executing-plans to implement this plan task-by-task（使用 executing-plans 技能逐项执行本计划）。

**Goal（目标）：** 在 Development（开发程序集）中证明 BDP 正规化表达契约可以通过临时 `ThingDef`（物品定义）驱动 RimWorld 原版武器统计读取链，为路线 E 的正式信息卡接入提供真实证据。

**Status（状态）：** 已完成源码原型与静态边界验证；Release 编译通过；原版表面构造和读取已抽取到路线 E 的 Core 通用设施；游戏内人工调试动作尚未执行，作为正式接入后的验收项保留。

**Architecture（架构）：** Development 诊断入口读取 Core 的 `ChipExpressionContractSurfaceAccess`（表达契约只读读取面），把一个契约条目投影为未注册的临时 `ThingDef`，再分别调用原版 `ThingDef.SpecialDisplayStats`（物品定义特殊统计）和目标 `StatWorker`（属性计算器）。临时对象只存在于本次调用栈，不写入 `DefDatabase`（定义数据库）、地图、容器或存档。

**Tech Stack（技术栈）：** RimWorld 1.6、C# 7.3、Verse、RimWorld、Development、LudeonTK `DebugAction`（开发者调试动作）、PowerShell 静态边界测试。

---

## 一、原版调查结论

1. 原版 `StatsReportUtility.DrawStatsReport(Thing)` 先读取 `thing.def.SpecialDisplayStats(StatRequest.For(thing))`，再按 `StatWorker.ShouldShowFor` 遍历统计定义；因此 BDP Comp 的特殊条目可以自然并入报告，但不能假定一个入口覆盖全部武器统计。
2. `ThingDef.SpecialDisplayStats` 对含主 Verb 的定义生成远程预热、伤害、护甲穿透、连射、停止力、射程和强制偏移等条目；它读取的是 `ThingDef` 私有 Verb 列表和公开 `tools`。
3. `StatWorker_MeleeAverageDPS` 与 `StatWorker_MeleeAverageArmorPenetration` 通过 `VerbUtility.GetAllVerbProperties(thingDef.Verbs, thingDef.tools)` 计算近战平均值，且 `ShouldShowFor` 要求 `ThingDef.IsWeapon`。
4. `StatWorker` 的武器分类显示条件依赖临时定义的 `ThingCategory.Item`、Verb/Tool 和 `IsRangedWeapon`/`IsMeleeWeapon`，不依赖定义是否注册到数据库。
5. 当前本地 DecompilerServer MCP（反编译服务）不可调用；本轮以本机游戏目录中的 `Assembly-CSharp.dll` 通过 `ilspycmd`（反编译命令）读取真实程序集，并以 RimSearcher `3.1.4` 运行时 Def 数据交叉核对。RimSearcher 已提示 `3.1.5` 可用，本轮不升级工具。

## 二、实施任务

### 任务 1：新增 Development 临时原版表面诊断器

新增 `Source/BDP.Development/Information/VanillaWeaponStatProjectionDiagnostic.cs`，并由路线 E 抽取为 Core 通用设施：

- 只读取当前选中 Thing 的正规化表达契约；没有选中物体、契约无效或只有增强模块时输出结构化诊断并安全返回。
- 通过 Core `VanillaWeaponStatSurfaceFactory` 为每个可执行近战/远程条目构造一份临时 `ThingDef`；设置 `ThingCategory.Item`、临时 `defName`、`thingClass`、空 `statBases/comps`。
- 远程表面使用契约中的 `VerbProperties`/`ResolvedVerbSpec`，设置主 Verb，保留射程、预热、连射、准确度、冷却、投射物和覆盖后的值。
- 近战表面使用契约保留的 `DeclaredTools`/近战表面列表，不修改来源 Tool 对象。
- 通过反射只写入原版 `ThingDef` 的私有 `verbs` 字段；反射限定在 Development 临时诊断内，不进入 Core/Content 正式逻辑。
- 通过 Core `VanillaWeaponStatSurfaceReader` 调用临时定义的 `SpecialDisplayStats`，以及原版近战平均 DPS、平均护甲穿透 `StatWorker`，记录标签、数值和说明是否生成。
- 诊断前后检查 `DefDatabase<ThingDef>.GetNamedSilentFail(tempDefName)` 仍为空，确认临时定义未注册。
- 不调用 `ThingMaker.MakeThing`、`GenSpawn.Spawn`、容器加入、存档写入或 Harmony 改写原版统计链。

### 任务 2：提供可插拔调试入口

- 在同一 Development 文件中提供 `LudeonTK.DebugAction`（开发者调试动作），仅在开发者模式和游戏进行中显示。
- 调试入口从当前选中物体读取样本，调用诊断器并把结果写入 `BdpDiagnostics`（统一诊断日志）。
- 入口失败不得阻断 Core/Content 启动；所有原版调用放在可捕获异常的诊断路径内。
- 新增文本只使用已有诊断前缀或语言包键，不在正式玩家界面硬编码文案。

### 任务 3：增加源码边界测试

新增 `Source/BDP.Tests/VanillaWeaponStatProjectionDiagnosticBoundarySmokeTests.ps1`，检查：

- 诊断器位于 `Source/BDP.Development`，且引用 `ChipExpressionContractSurfaceAccess` 与原版 `StatWorker`/`SpecialDisplayStats`。
- 不出现在 Core 或 Content 的正式程序集源码中。
- 包含临时 `ThingDef`、未注册检查、近战平均 DPS/护甲穿透和远程特殊统计调用。
- 不包含 `DefDatabase<ThingDef>.Add`、`GenSpawn.Spawn`、`Scribe`、永久缓存或 Harmony Patch。
- DebugAction 仅允许开发者模式/游戏中使用。

### 任务 4：验证与记录

- 编译 Core、Content、Development Release。
- 执行新诊断边界测试、Development 单向边界、Core 隔离和路线 C 相关测试。
- 能在游戏中选中典型 BDP 芯片执行调试动作时，记录“契约值—临时定义—原版条目”日志；无法实测时明确标记为待人工执行，不把静态通过写成游戏内通过。
- 更新全局规划路线 D 状态；写入下一份 Agent 工作日志，单文件不超过 20 条。

## 三、明确不在本路线实施的事项

- 不接入 `CompManufacturedChip.SpecialDisplayStats`；那是路线 E。
- 不向 `DefDatabase` 注册临时定义，不生成玩家可见临时物品，不写存档。
- 不复制原版伤害、护甲穿透、射程或 DPS 公式；诊断只调用原版 API。
- 不把临时工厂放进 Core；路线 E 再根据证据决定是否抽取中性 `VanillaWeaponStatSurface`。
- 不处理多形态当前状态、外部模组公开接口或装配台大文件拆分；这些按路线 F/G/H 保留。

## 四、完成标准

- Development 可从一个正规化近战条目构造未注册临时定义，并让原版近战平均 DPS/护甲穿透 Worker 返回可观测结果。
- Development 可从一个正规化远程条目调用 `ThingDef.SpecialDisplayStats`，得到原版远程统计条目集合。
- 临时定义前后均不在 `DefDatabase` 中，不进入地图、容器和存档。
- 诊断不修改正式 Core/Content 逻辑，失败只记录诊断，不阻断游戏。
- 日志足以决定路线 E 哪些字段可以自然复用原版，哪些必须保留为 BDP 自定义 `StatDrawEntry`（属性显示条目）。
