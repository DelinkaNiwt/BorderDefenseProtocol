# 远程攻击目标事件与泛用减益模块设计

## 1. 设计结论

铅弹不是“爆炸减益模块”，而是“攻击目标事件减益模块”。爆炸只是当前一种攻击目标生产者，不能进入铅弹的正式业务语义。

本设计遵守以下硬规则：

1. 攻击生产者决定本次攻击产生哪些目标判定，以及同一目标被判定几次。
2. Core 只把每次真实目标判定传递给挂载效果，不按 `Thing`（游戏对象）自行去重。
3. 铅弹只根据目标事件和 `TargetFilter`（目标筛选）决定是否追加 Hediff（健康状态减益）。
4. 伤害是否执行、目标事件是否继续产生、视觉是否播放、护盾是否拦截彼此独立。
5. 如果攻击生产者产生两次同一目标事件，铅弹执行两次；如果生产者在自己的边界上去重，只产生一次事件，铅弹只执行一次。

## 2. 当前代码根因

当前 `BdpProjectile.ExecuteImpact()` 用 `SuppressAllProjectileImpact` 同时挡住伤害和范围效果调用，导致铅弹追加到美特拉后，范围爆炸承载本身也不执行。

当前 `Patch_DamageWorker_ExplosionDamageThing_BdpSemantics` 已经在原版 `ExplosionDamageThing()` 的目标去重边界之后、原版 `TakeDamage()` 之前派发额外效果；这条位置是正确的，但它目前只识别爆炸专用目标范围。

当前 `AreaExplosionModule` 负责产生范围效果计划，并通过 `SuppressBaselineImpact` 避免同一投射物同时产生基线直击伤害与模块爆炸伤害。它不应负责铅弹业务，也不应被铅弹识别。

## 3. Core 中性设施

### 3.1 攻击目标事件

Core 增加通用的 `AttackTargetEvent`（攻击目标事件）语义。事件表示：当前攻击生产者把某个 `Thing` 作为一个攻击对象进行了一次判定。

事件至少携带：

- 目标 `Thing`。
- 目标格子。
- 攻击实例标识。
- 表达结果标识。
- 投射物和来源宿主。

事件是“发生次数”的载体，不是“唯一目标集合”。Core 不使用 `HashSet<Thing>` 或目标列表对事件再次去重。

### 3.2 目标来源与生产者解耦

额外效果正式范围新增通用目标来源，例如 `AttackTargetEvents`（攻击目标事件）。铅弹只订阅这个来源。

直接命中、范围爆炸、多段攻击、链式攻击、穿透攻击等生产者都可以在自己的原版或模块目标判定边界调用同一个 Core 派发设施。Core 不把这些来源写成铅弹专用分支。

原有 `DirectHitThing` 和 `VanillaExplosionAffected*` 可以继续作为已有内容的兼容来源，但铅弹正式配置不依赖爆炸专用枚举。

### 3.3 伤害取消与目标解析分离

Impact（命中结算）计划增加“伤害取消时继续目标解析”的中性策略。

当模块声明取消伤害且保留目标解析时：

1. 攻击生产者仍按自己的逻辑产生目标事件。
2. 额外效果在每个目标事件上执行。
3. 原版伤害入口被跳过。
4. 原版视觉和声音是否播放由区域效果表现策略独立决定。

## 4. 铅弹正式语义

铅弹配置使用通用目标事件来源：

```xml
<TargetScope>AttackTargetEvents</TargetScope>
<TargetFilter>PawnsOnly</TargetFilter>
<DamageSuppression>SuppressAllProjectileImpact</DamageSuppression>
<PreserveTargetResolutionWhenDamageSuppressed>true</PreserveTargetResolutionWhenDamageSuppressed>
```

普通子弹没有额外目标生产者时，直接命中目标作为一个攻击目标事件；美特拉存在范围生产者时，范围生产者产生的每个目标判定作为攻击目标事件。

铅弹不声明美特拉、爆炸、猎犬或枪壳依赖。

## 5. 美特拉组合行为

美特拉仍由自己的范围爆炸模块提供爆炸承载。铅弹只追加通用目标事件效果和伤害取消。

如果美特拉生产一次目标事件：目标获得一次铅块负重。

如果某个攻击生产者对同一目标产生两次独立目标事件：目标获得两次铅块负重。

如果生产者自身用原版 `damagedThings` 规则过滤第二次判定：第二次事件不会产生，铅弹也不会执行第二次。

## 6. 表现与护盾

- 铅弹不决定爆炸贴图、音效或屏幕震动。
- 美特拉或其他攻击生产者自己的 `PresentationPolicy`（表现策略）决定是否播放这些效果。
- 铅弹只声明投射物拦截器与已登记伤害护盾的绕过策略。
- 普通攻击必须先经过原版护盾裁决，再进入 `TakeDamage`（承受伤害）和 `DamageWorker`（伤害工作器）；只有原版确认产生有效受击时，才由原版产生受击反馈。
- 铅弹若完全取消原版伤害链，则只在“明确绕过已登记护盾”之后，用一次窄范围反馈副本补回原版因未进入 `DamageWorker` 而不会自动产生的表现；这不改变普通攻击路径。

## 7. 验证边界

至少验证：

1. 普通投射物：一个直接目标事件对应一次减益，伤害为零。
2. 美特拉：范围生产者仍执行，目标事件逐个派发，伤害为零。
3. 同一目标两个目标事件：减益执行器被调用两次，不被 Core 合并。
4. 生产者在目标判定前去重：Core 不额外制造第二次效果。
5. 铅弹 XML 不出现爆炸模块、具体芯片或枪壳绑定。

## 8. 可选命中反馈颜色

命中闪烁颜色属于远程减益模块可以提交的可选命中反馈策略，但不是该模块的固定行为。

1. `RangedDebuffConfig`（远程减益配置）提供可选 `HitFeedbackColor`（命中反馈颜色）接口；未配置时不改变现有命中反馈。
2. `RangedDebuffModule`（远程减益模块）只把已配置的颜色提交到中性 `ImpactPlan`（命中计划），不在模块内部直接修改原版材质。
3. Core 负责把颜色策略传递给直接命中和攻击生产者产生的目标事件，并在原版 `DamageFlasher`（受击闪烁器）材质生成边界消费它。
4. 只有 `BDP_RangedDebuff_LeadWeight`（铅块负重模块）配置灰黑色；其他减益模块不配置该字段，因此继续保持原版红色或既有反馈。
5. 颜色策略不改变目标筛选、伤害处置、护盾绕过、目标事件次数和爆炸生产者的去重语义。

这样既保留“颜色由铅弹需求决定”的业务归属，也不把灰黑色固化为所有减益模块的默认表现。
