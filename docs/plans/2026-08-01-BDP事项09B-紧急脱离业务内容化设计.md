# BDP 事项 09B：紧急脱离业务内容化设计

## 1. 目标

把当前混在 `BDP.Core.dll` 中的“紧急脱离”具体业务移到 `BDP.Content.dll`，同时保留战斗体本身的通用激活、主动解除、被动崩解、Trion 释放和冷却流程。

本次是归属和依赖重构，不重新设计紧急脱离规则，不改变游戏内表现。

## 2. 当前问题

Core 目前同时知道两件事：

1. 战斗体如何进入崩解、完成退出和清理资源。
2. 某个紧急脱离芯片如何解析、寻找目的地、传送、播放效果和消费芯片。

第二类属于具体业务。它使 Core 直接依赖以下业务语义：

- `EmergencyEscape` 被动表达键。
- 紧急脱离信标和唯一放置规则。
- 紧急脱离目的地、传送表现和来源芯片消费。
- 紧急脱离三态徽标和玩家提示文字。
- `CachedCollapseEmergencyEscape` 这样的具体缓存字段。

如果只移动文件而让 Core 继续直接调用这些类型，物理位置变了，架构依赖并没有真正变干净。

## 3. 目标分层

### 3.1 Core 保留的内容

- `CombatBody` 的激活、主动解除和被动崩解生命周期。
- 崩解表现结束后的通用退出顺序。
- Trion 资源释放、当前值归零、战斗体冷却和后遗症。
- 通用的“崩解开始时准备外部扩展、退出时执行外部扩展、退出后清理外部扩展”入口。
- 战斗体自身的通用状态徽标。

Core 不出现 `EmergencyEscape` 专名，也不保存紧急脱离的业务结果。

### 3.2 Content 承担的内容

- 紧急脱离表达结果解析。
- 紧急脱离解析结果及其来源芯片追踪。
- 紧急脱离信标建筑、地图唯一放置规则和对应 Def。
- 安全位置寻找、传送、特效、玩家提示和来源芯片消费。
- 紧急脱离三态徽标及其贴图、颜色和提示文字。
- 紧急脱离在崩解扩展入口中的注册。

## 4. Core 与 Content 的协同方式

Core 新增中性的 `CombatBodyCollapseExtensionRegistry` 和
`ICombatBodyCollapseExtensionProvider`。

扩展提供三个生命周期动作：

```text
Prepare(pawn)  ：被动崩解刚开始时调用，扩展缓存自己需要的结果。
Execute(pawn)  ：崩解表现结束、通用退出清理开始时调用。
Clear(pawn)    ：激活、主动解除或退出完成时调用，清理残留状态。
```

Core 只调用注册表，不知道注册者是紧急脱离还是未来的其它扩展。没有 Content 时，注册表为空，战斗体仍可正常运行。

紧急脱离 Content 提供器在 `Prepare` 阶段读取已经发布的表达投影，并将解析结果保存到 Content 自己的 Pawn 状态组件中。这样即使崩解期间存档，结果也能随 Content 状态保存，不需要 Core 保存具体业务对象。

## 5. 退出时序

保持现有时序，只替换业务调用位置：

```text
战斗体主动解除
  → 清理外部扩展状态
  → 通用解除、释放 Trion、结束

战斗体被动崩解开始
  → Core 通知外部扩展 Prepare
  → 进入崩解表现

崩解表现结束
  → 移除崩解中提示
  → 原地烟雾
  → Core 通知外部扩展 Execute
  → 取消征召
  → 释放 Trion、归零、进入冷却
  → 添加崩解后遗症
  → Core 通知外部扩展 Clear
```

紧急脱离仍然只在被动崩解中执行；主动解除不会触发。紧急脱离失败也不阻断通用崩解收尾。

## 6. 徽标拆分

- Core 的 `CombatBodyTrionGizmoExtensionProvider` 只提供战斗体未激活、已激活、崩解中、冷却中的通用状态。
- Content 新增紧急脱离徽标提供器，通过现有 Trion 外部徽标注册口加入。
- 未搭载时不显示紧急脱离徽标；已搭载但未就绪显示灰暗；已就绪显示亮色。
- 崩解开始后，徽标使用 `Prepare` 阶段缓存的结果，避免 Trigger 状态变化后徽标反复改变。

## 7. 兼容与边界

- 不保留旧 Core 命名的存档兼容读取。
- 不新增主动紧急脱离按钮。
- 不把紧急脱离变成第三种退出模式。
- 不移动战斗体伤口规则、Trion 伤口泄漏、战斗日志或前台装备配置；这些属于事项 09 的后续分组。
- 保持 `BDP.Content.dll → BDP.Core.dll`，Core 不反向引用 Content。

## 8. 验收标准

1. Core 中不再出现紧急脱离具体业务类型、字段、Def 名称和徽标文字。
2. Core 只保留中性崩解扩展注册口，且没有 Content 时仍能构建和运行。
3. 紧急脱离相关源码和 Def 全部位于 Content 侧。
4. 现有紧急脱离三态徽标、被动崩解触发、信标回退、来源芯片消费和崩解后遗症行为不变。
5. 三程序集构建成功，Core 零本模组程序集依赖门禁通过。
6. 事项 09B 定向边界测试、紧急脱离测试、战斗体退出测试和 Trion 徽标测试通过。
