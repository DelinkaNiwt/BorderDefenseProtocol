## 二、重审时必须遵守的边界

### 2.1 功能语义声明“可以提供什么”，不规定面板“必须显示什么”

`ChipFeatureDef.Properties` 表示某项功能允许公开的属性范围。制造台、装配台、检查面板或第三方消费者可以根据自己的场景决定：

- 显示哪些属性；
- 使用文字、图标、图表还是提示框；
- 是否隐藏零值、默认值或低优先级信息；
- 是否利用多个基础属性计算仅用于比较的派生指标。

面板不得反向根据 `Verb`、`Ability`、`Hediff` 等技术类型重新推断玩家功能。

### 2.2 共用属性只定义一次，由多个功能语义引用

距离、时间、消耗、充能、伤害和范围等属性并不专属于远程攻击。正确结构是：

```text
公共属性目录
├─ 可选目标
├─ 施放需视线
├─ 最大作用距离
├─ 预热时间
├─ 行动冷却时间
├─ 单次使用消耗
└─ ……
        ↑
远程攻击、近战攻击、机动、护盾等功能分别引用其中适用的属性
```

不得为了不同面板名称复制一批含义相同的属性 Def，也不建立“通用功能语义”父类或复杂继承体系。

### 2.3 标准属性名称与面板措辞分开

属性 Def 负责提供唯一、稳定、中性的中文标准名称和说明；具体面板可以为了当前界面采用更自然的措辞。例如：

- 公共标准名称“攻击距离”，远程攻击面板可以显示为“最大射程”；
- 公共标准名称“单次伤害”，远程攻击面板可以显示为“单发伤害”；
- 公共标准名称“攻击次数”，远程攻击面板可以显示为“连发次数”，近战攻击面板可以显示为“连击次数”。

场景化措辞属于消费端职责，不写入功能语义契约。`ChipFeaturePropertySlot` 继续只声明属性引用与顺序，暂不增加 `LabelKey` 或 `DescriptionKey` 覆写。若两个场景无法共用一个中性标准名称，应优先检查它们是否本来就是不同语义，而不是使用别名掩盖差异。

命名必须严格分层：

- 玩家可见名称、需求文档名称使用中文，例如“攻击次数”“攻击间隔”；
- 代码和 XML 技术标识使用稳定英文，例如 `BDP_Property_AttackBurstCount`、`BDP_Property_AttackBurstInterval`；
- 不把技术标识与中文名称拼接成一个玩家属性名。

### 2.4 值必须按真实所有权归属

判断一项数据是否挂在远程攻击上，不以“能否从同一个 XML 或对象中读取”为准，而以执行系统中它真正归谁所有为准：

- 一次远程攻击独立扣除的资源，属于该远程攻击；
- 整枚芯片的激活成本，属于芯片通用信息；
- 多个功能共用的充能池或冷却，不得复制到每项功能上冒充独立状态；
- 某个附加爆炸自己的半径和伤害，属于该额外效果信息组；
- 有真实运行对象时才能提供的当前充能、剩余冷却等信息，属于运行时值层。

### 2.5 缺值、零值和不适用必须区分

- 缺值：来源没有提供或无法确认，不得擅自猜测为零。
- 零值：来源明确给出零，应作为合法值保留；面板可以按规则隐藏或特殊格式化。
- 不适用：例如齐射的连发间隔，语义读取器应直接不提供，不应输出零或原始残留字段。
- 普通实现没有某个可选属性时不显示大量“无”或“未知”。

### 2.6 派生指标不自动成为正式语义属性

只有具有稳定、无歧义业务含义的有效结果才应成为功能属性。依赖展示口径的计算值留在共用计算工具或面板投影中。例如“理论射速”需要决定是否计入预热、能力冷却、角色修正、双持、换目标等条件，因此不作为远程攻击正式属性。

## 三、远程攻击语义的最终结构

```text
远程攻击功能实例
├─ 通用属性引用
│  ├─ 目标与视线
│  ├─ 距离与时间
│  ├─ 消耗与充能定义
│  └─ 基础伤害结果
├─ 远程专用属性
│  ├─ 连发与射击节奏
│  ├─ 原版四项精度
│  ├─ 投射物速度
│  ├─ 停止力
│  └─ 飞行特征
├─ 信息组
│  └─ 额外效果（可重复）
└─ 运行时状态
   ├─ 当前充能
   └─ 剩余冷却等真实状态
```

## 四、远程攻击确认保留的属性

### 4.1 目标与施放条件

#### 可选目标

- 最短说明：攻击允许选择角色、建筑、地点、区域等哪类目标。
- 值形态：可包含多项的稳定键列表，不使用不可翻译的自由文本。
- 展示预期：面板未来大概率使用图标；未知第三方值必须能够回退为本地化文字。
- 提供规则：普通攻击没有值得强调的特殊限制时可以不提供；存在明确目标限制时提供。
- 复用范围：远程、近战、机动、治疗、控制等功能均可引用同一公共属性。

#### 施放需视线

- 最短说明：选择并发动攻击时，使用者是否必须直接看见目标。
- 值形态：布尔值。
- 明确不包含：投射物发射后是否撞墙、能否穿越障碍或怎样规划路线。
- 来源规则：普通 `Verb` 可读取最终目标检查规则；特殊路线由对应来源 Worker 提供最终有效值，不能根据入口是 `Verb` 还是 `Ability` 推断。
- 复用范围：其它需要选取目标的功能也可引用。

### 4.2 距离

#### 最大射程

- 最短说明：使用者与目标之间允许发动攻击的最远距离。
- 单位：格。
- 数据语义：合法攻击距离上限，不表示“精度较好的有效距离”、投射物飞行极限或爆炸范围。
- 来源规则：读取形态、构型、组合和其它有效修改完成后的最终值。
- 属性复用：底层可以复用公共“最大作用距离”属性，远程攻击上下文显示为“最大射程”。

#### 最小射程

- 最短说明：目标距离低于该数值时不能发动攻击。
- 单位：格。
- 提供规则：只在确实存在近距离禁射区且最终值大于零时提供；普通攻击不显示“0 格”。
- 明确不包含：近距离精度衰减。

### 4.3 时间与可用性

#### 预热时间

- 最短说明：从开始发动攻击到发射第一发之前的等待时间。
- 名称决定：使用 RimWorld 玩家熟悉的“预热时间”，不使用“准备时间”。
- 单位：秒。
- 来源规则：对应原版 `VerbProperties.warmupTime` 或其它路线的等价最终事实。
- 明确不包含：连发间隔与攻击结束后的冷却。

#### 行动冷却时间

- 最短说明：动作完成后进入的行动冷却时间。
- 名称决定：对应原版 `cooldown` 的这一项正式称为“行动冷却时间”。
- 适用范围：不仅攻击，非攻击动作也可能拥有相同性质的行动冷却，因此属性 Def 应允许跨语义复用。
- 单位：秒。

#### 能力冷却计时

- 最短说明：能力自身再次可用前的独立冷却计时。
- 名称决定：与“行动冷却时间”分开，正式称为“能力冷却计时”。
- 提供规则：只在该冷却确实归属于当前功能实例时提供；共享冷却不得复制到多个功能实例。
- 静态与运行时：定义中的完整冷却时长和运行时剩余冷却不是同一个值，后续建模不得混写。
- 所有权修正：当这项计时表示玩家主动释放入口再次可用时，由“能力”语义提供；机动、护盾、攻击等结果语义不因底层恰好使用 Ability 而重复引用。

#### 充能上限

- 最短说明：该功能最多能够储存多少次可用次数。
- 提供规则：没有储备次数机制的功能不提供。
- 所有权规则：只在充能池归属于该功能时挂载；共享充能池应进入共享资源状态。

#### 当前充能

- 最短说明：当前还剩多少次可用次数。
- 数据层级：仅限运行时值。
- 制造台与静态成品预览不得伪造或从“充能上限”推算当前值。

#### 充能恢复时间

- 最短说明：恢复一次充能所需的时间。
- 单位：秒。
- 提供规则：只用于逐次恢复储备次数的机制，不与能力冷却计时混用。

### 4.4 消耗

#### 单次使用消耗

- 最短说明：完整发动一次远程攻击实际结算的 Trion 数量。
- 计费边界：四连发若整轮只扣一次费用，则这里记录整轮费用，不按每发重复。
- 值要求：只保存 Trion 数值；BDP 标准功能不会使用其它消耗资源，不重复保存固定资源身份。
- 扩展边界：使用弹药、耐久或其它资源的扩展内容应声明含义明确的扩展属性，不把 BDP Core 预先扩成通用资源系统。
- 所有权规则：芯片激活成本仍属于芯片通用信息；持续维持消耗是另一项概念，不混入本项。

### 4.5 主要伤害结果

#### 单发伤害

- 最短说明：一发投射物或一次主要命中造成的伤害。
- 命名决定：远程攻击上下文显示为“单发伤害”。
- 多发规则：不声明“连发总伤害”，因为多发不保证全部命中。
- 结构规则：爆炸、额外伤害等拥有自己的伤害值时，放在对应额外效果信息组中。

#### 伤害类型

- 最短说明：主要直接命中的伤害种类，例如锐器、钝器、火焰或爆炸。
- 结构规则：每个额外效果可以拥有不同的伤害类型，不能把所有结果挤入远程攻击根部这一项。
- 展示预期：允许文字、图标或二者结合。

#### 护甲穿透

- 最短说明：攻击对护甲的穿透程度。
- 值形态：百分比。
- 原版换算：原版 `0.10` 面向玩家表示为 `10%`，不得显示成 `0.10%`。
- 零值格式：明确的零值保留为合法值，默认显示为 `0`，不写成 `0%`。
- 当前实现问题：现有通用 `AddNumber` 会丢弃零值，后续实施必须修正“明确为零”与“没有信息”的混淆。

#### 停止力

- 最短说明：投射物命中角色时，使其产生短暂踉跄或硬直的能力。
- 名称决定：保留 RimWorld 使用的“停止力”。
- 提供规则：只有真实攻击结果具有停止力时才提供。

### 4.6 发射组织

#### 攻击次数

- 技术标识：`BDP_Property_AttackBurstCount`。
- 最短说明：一次完整攻击行动中执行多少次独立攻击事件。
- 值形态：正整数，最小有效值为 `1`。
- 公共身份：远程攻击与近战攻击共用；不再保留彼此独立的 `BurstCount` 与 `MeleeHitCount` 属性身份。
- 远程面板措辞：可以显示为“连发次数”。
- 单发规则：语义层提供 `1`；面板可以显示为“单发”或隐藏。
- 与投射物数区别：一次攻击事件自身生成多个弹丸时，弹丸数量不自动改变攻击次数。
- 与目标数区别：攻击次数不统计不同目标数量。

#### 射击节奏

- 最短说明：多发攻击采用逐射还是齐射。
- 标准值：`Sequential` 对应“逐射”；`Simultaneous` 对应“齐射”。
- 来源规则：读取 BDP 最终 `RangedExecutionRhythm`，包括武装构型和组合修改后的结果，不只读取原始作者字段。
- 单发规则：攻击次数为 `1` 时节奏没有实际区分，可以不提供。

#### 攻击间隔

- 技术标识：`BDP_Property_AttackBurstInterval`。
- 最短说明：一次完整攻击行动中，相邻两个顺序攻击事件之间的等待时间。
- 公共身份：远程攻击与近战攻击共用；不再保留彼此独立的连发间隔与 `MeleeInterval` 属性身份。
- 远程面板措辞：可以显示为“连发间隔”。
- 单位：语义层统一为秒；面板需要时可在提示中补充原始游戏刻。
- 提供条件：仅当攻击次数大于 `1` 且最终射击节奏为逐射时提供。
- 单发规则：攻击次数为 `1` 时没有相邻攻击事件，本属性为不适用，不能输出 `0`。
- 齐射规则：即使底层 `ticksBetweenBurstShots` 残留非零值，只要最终节奏为齐射，该字段在执行中没有意义，语义读取器必须忽略。

```text
攻击次数 = 1
└─ 不提供射击节奏和连发间隔

攻击次数 > 1，节奏 = 逐射
├─ 提供攻击次数
├─ 提供射击节奏：逐射
└─ 提供连发间隔

攻击次数 > 1，节奏 = 齐射
├─ 提供攻击次数
├─ 提供射击节奏：齐射
└─ 不提供连发间隔
```

### 4.7 原版四项精度

远程攻击采用 RimWorld 原版四项精度，不建立单一“总体精度”，也暂不建立任意距离曲线数据结构：

- 贴身精度：原版 `accuracyTouch`；
- 近距精度：原版 `accuracyShort`；
- 中距精度：原版 `accuracyMedium`；
- 远距精度：原版 `accuracyLong`。

共同规则：

- 值形态为百分比；
- 表示武器或攻击定义在原版四档距离中的精度因子，不等于已经计入射手能力、遮蔽物、天气等全部条件后的最终命中概率；
- 标准来源直接读取最终有效四项精度；
- 第三方不同算法如要复用这一标准语义，应提供可比较的四档值；确实无法表达时再通过 XML 扩展新属性，不提前建设通用曲线语言；
- 数字面板可以直接显示四项值；精度图面板可以把四个锚点交给通用折线图工具绘制；插值与绘图属于消费端，不进入 Core 属性含义。

### 4.8 飞行

#### 投射物速度

- 最短说明：弹体在地图上的飞行速度。
- 单位：格/秒。
- 提供规则：只有存在实际飞行过程时提供；瞬间命中、直接产生结果或不存在投射物的攻击不提供。
- 明确不包含：发射频率或理论射速。

#### 飞行特征

- 最短说明：概括投射物飞行过程中的显著特性。
- 值形态：可扩展的稳定键列表，不使用自由文本堆积底层参数。
- 候选表现：追踪、路线引导、分段变向、曲射、穿越障碍、返回等。
- 粒度决定：不再把“目标追踪方式”“引导方式”、重锁距离、转向响应度等低频实现细节分别做成标准属性。
- 提供规则：普通、没有值得说明的特殊飞行表现时可以不提供。
- 扩展规则：第三方可以提供新的稳定特征键；面板认识的键可使用图标，不认识时必须回退本地化文字。

### 4.9 范围与多目标

#### 效果半径

- 最短说明：以命中位置为中心的作用范围半径。
- 单位：格。
- 明确不包含：最大射程和目标选择区域。
- 归属规则：攻击本身就是范围攻击时可位于远程攻击根部；只有某项附加爆炸具有范围时应放在该额外效果信息组中。

#### 目标数量上限

- 最短说明：一次发动最多作用于多少个不同目标。
- 提供规则：只在攻击确实具有多目标能力且存在明确数量限制时提供。
- 普通单目标攻击不必显示 `1`；作用于范围内全部目标且没有固定上限时不提供。
- 明确不包含：连发次数和投射物数量。
- 归属规则：与效果半径相同，跟随真正拥有目标上限的根攻击或子效果。

## 五、额外效果不是平铺属性

“额外效果”是远程攻击下可重复出现的结构化子项，不是一个 `Text` 或 `List` 属性。它比“施加状态”再抽象一层，允许表达：

- 状态施加；
- 额外伤害；
- 额外爆炸；
- 击退；
- 资源变化；
- 对象生成；
- 未来第三方新增的其它效果语义。

示例：

```text
远程攻击
├─ 单发伤害：13
└─ 额外效果：额外爆炸
   ├─ 伤害：20
   ├─ 伤害类型：爆炸
   └─ 效果半径：2.5 格
```

```text
远程攻击
└─ 额外效果：中毒
   ├─ 强度
   ├─ 持续时间
   └─ 叠加上限
```

后续实现要求：

- 使用功能内部的可重复结构化信息组，不复用 `ChipFeatureDeclaration.Children` 冒充普通参数分组；
- 每项额外效果拥有稳定 Id 和自己的效果类型及属性；只有它本身构成完整玩家功能时才升级为子功能语义；
- 不向玩家暴露 `Hediff`、模块类名或投射物 Def 名；
- 不把多个效果压成需要界面再次解析的长文本；
- 某项效果缺少强度、持续时间等数据时不强制显示“未知”。

## 六、明确删除或不纳入远程攻击的项目

### 6.1 使用方式

- 决定：从远程攻击属性范围删除。
- 原因：作用较小；主动、自动、触发等值无法由 `Verb`、`Ability` 等技术类型可靠推断。
- 当前实现问题：现有 Worker 把 `EntryType` 的 `PrimaryVerb` 等技术值写入 `UsageMode`，不符合玩家语义。
- 未来可能方向：如果面板确实需要主动、自动、反击等说明，可以建立只用于说明和分类的标签；标签不得参与功能识别或执行。
- 全局属性 Def 是否删除：待审视其它功能语义后统一决定，当前只确认远程攻击不引用。

### 6.2 投射物内部定义

- 决定：删除 `ProjectileDef` 公开属性。
- 原因：内部 DefName 对玩家没有意义，并会重新把公开信息绑定到技术实现。
- 替代：速度、飞行特征、伤害、爆炸等玩家真正关心的事实分别提供。
- 特殊弹体确有玩家可见专名时，由功能说明、实例名称或其它明确展示数据承担，不公开底层 DefName。

### 6.3 追踪方式与引导方式

- 决定：删除两个独立标准属性。
- 原因：低频且粒度过细，二者容易随当前模块结构扩张。
- 替代：合并为“飞行特征”列表。

### 6.4 施加状态与状态强度

- 决定：从远程攻击根部删除两个平铺属性。
- 原因：附加结果不一定是状态，一次攻击也可能包含多个不同效果。
- 替代：结构化“额外效果”子项；状态只是其中一种效果。

### 6.5 理论射速

- 决定：不作为正式语义属性。
- 原因：它是由预热、连发、间隔和冷却按特定口径计算的比较指标，并可能受到能力冷却、角色修正、双持和其它停顿影响。
- 后续方向：需要雷达图或比较时，在 Content 或面板适配层提供单一共用计算工具，避免两个工作台各算一套；计算结果不写回 XML，也不冒充执行基础事实。

### 6.6 声响范围

- 决定：当前不加入。
- 证据：BDP 武装构型目前写有 `noiseRadius`，并会将其复制进 `VerbProperties`；本轮检索尚未确认当前攻击执行链存在实际消费该字段的游戏行为。
- 规则：在确认实际效果和玩家价值前，不把“能读到的字段”包装成正式语义属性。

- 远程模块 Worker 目前仍只复用表达条目的公共读取，不能自动产生经本轮确认的“飞行特征”或结构化额外效果。

因此，后续实施必须以本文件的语义决定为准，不能只在现有字段列表上补标签。

## 八、后续实施前仍需明确的技术细节

以下不是需求未定，而是尚未选择最小实现方式：

1. “飞行特征”和“可选目标”稳定键的本地化及未知值回退规则。
2. 额外效果首批需要落地哪些信息组类型；只覆盖 BDP 真实内容，不建立完整效果百科。
3. 定义中的能力完整冷却与运行时剩余冷却如何使用不同属性身份。
4. 当前充能、剩余冷却等运行值如何接入现有 `Runtime` 值层，同时保证制造预览不伪造运行事实。
5. 四项精度、投射物最终伤害、速度和停止力从最终有效投射物与构型覆盖中读取的准确路径。
6. 近战“攻击方式”如何接入新增的结构化信息组，且不复用子功能语义、不把 `Tool` 技术类型暴露给消费端。
7. 近战来源 Worker 如何逐 `MeleeToolSurface` 复用 `VanillaMeleeStatProjection`，避免再次实现原版数值算法。

这些细节必须在实施计划中逐条给出最小方案和验证方式，不能在编码时临时拍脑袋。

## 九、远程攻击验收要点

- 普通单发攻击不会出现无意义的射击节奏、连发间隔、最小射程或飞行特征。
- 逐射多发显示连发次数、逐射和有效连发间隔。
- 齐射多发显示连发次数、齐射，不泄漏无效的底层连发间隔。
- 武装构型修改后的射程、精度、伤害、速度、停止力和节奏读取最终有效值。
- 护甲穿透零值不会变成未知，默认显示为 `0`。
- 原版四项精度可以直接驱动已恢复的通用精度折线图工具。
- 雷达图需要的理论射速由共用计算工具产生，不写入功能语义属性。
- 附加爆炸的半径和伤害位于爆炸子项，不污染远程攻击根部。
- 运行时当前充能和剩余冷却只在真实运行对象存在时提供。
- 第三方新增飞行特征或目标类型时，未知图标能够回退为本地化文字。
- 任何信息读取失败都不得改变攻击、扣费、冷却、投射物或命中行为。

## 十、近战攻击语义的最终结构

近战攻击根部只承担玩家功能分组；所有实际攻击数值归入可重复的“攻击方式”信息组：

```text
近战攻击功能实例
└─ 攻击方式（可重复）
   ├─ 攻击距离
   ├─ 预热时间
   ├─ 行动冷却时间
   ├─ 单次伤害
   ├─ 伤害类型
   ├─ 护甲穿透
   ├─ 攻击次数
   ├─ 攻击间隔（条件提供）
   └─ 额外效果（可重复）
```

结构决定：

- “攻击方式”是玩家语义内部的信息组，不是子功能语义；不向外暴露 `Tool`、`ManeuverDef`、`Verb` 或 `Melee` 等技术类型名；
- 每个原版 `Tool` 或第三方等价实现可以解析为一个独立攻击方式；
- 攻击方式名称优先使用作者显式提供的玩家语言键，BDP 当前内容可以沿用 `ToolLabelKeys`；
- 即使只有一种攻击方式，数据中仍保留一个攻击方式子项，以保证下游读取结构稳定；
- 面板遇到单一攻击方式时可以直接展开内容，不必让玩家看到多余层级；
- 多种攻击方式不取平均值、不取最大值，也不随便选一个冒充整项近战攻击；
- 雷达图选择某种攻击方式、分别绘制或计算综合投影，属于面板职责；功能语义不制造没有唯一口径的综合值；
- 第三方不同技术路线只要能声明近战攻击及攻击方式，就可以提供相同的玩家语义属性，不要求使用 BDP 的 `Tool` 路线。

## 十一、近战攻击确认保留的属性

### 11.1 攻击距离

- 最短说明：攻击方式能够从多远处命中目标。
- 单位：格。
- 提供规则：可执行的近战攻击原则上始终提供实际有效值，不能因默认值不值得突出就省略数据。
- BDP 当前普通近战：实际判定距离为 `1.42` 格；这是允许相邻含斜向格接触的真实执行阈值。
- 展示边界：文本面板可以把默认近战距离显示为“相邻”或直接弱化；雷达图等消费者仍可稳定读取数值。
- 长距离近战：长柄、伸缩或隔格攻击应提供真实执行距离。
- 当前实现问题：现有近战 FeatureDef 没有接收距离，通用来源虽然可能读到 `VerbProperties.range`，但不能继续依靠这一偶然路径。

### 11.2 预热时间

- 最短说明：开始执行攻击后，到第一次攻击事件发生前的准备时间。
- 名称决定：标准名称沿用“预热时间”，与远程攻击共用同一个属性身份。
- 单位：秒。
- 零值规则：`0` 表示立即出手，是有效值，不等于缺失；文本面板可以隐藏零值。
- 来源规则：读取每个攻击方式最终有效 `VerbProperties.warmupTime` 或第三方等价事实。

### 11.3 行动冷却时间

- 最短说明：完成一轮近战攻击后，到能够再次行动攻击之间的等待时间。
- 名称决定：与远程攻击共用“行动冷却时间”，不得混同“能力冷却计时”。
- 正确来源：复用原版 `VerbProperties.AdjustedCooldown(tool, ...)` 取得当前攻击方式的有效冷却，而不是直接读取 `Tool.cooldownTime`，更不能读取无关或通常为零的 `VerbProperties.defaultCooldownTime`。
- 定义预览：没有具体使用者时，按原版定义级调用取得稳定结果；若未来加入真实使用者修正，应进入对应运行时或上下文投影，不覆盖定义事实。
- 零值规则：明确为 `0` 时保留为合法值。
- 当前实现问题：现有 `ChipFeatureSourceWorkerSupport.AddEntryValues` 读取 `props.defaultCooldownTime`，与 BDP 近战真实执行和已有 `VanillaMeleeStatProjection` 不一致，实施时必须改正。

### 11.4 单次伤害

- 最短说明：每一个独立近战攻击事件造成的基础伤害，不表示整轮多击总伤害。
- 公共身份：与远程攻击共用同一个伤害属性；属性 Def 使用中性标准名称“单次伤害”。
- 正确来源：复用原版 `AdjustedMeleeDamageAmount`，不得只抄作者 XML 中的 `Tool.power`。
- 多击规则：攻击次数为 `3` 时仍提供每一击伤害，不额外声明必中的三击总伤害。
- 零值规则：`0` 可以表示只产生其它效果、不造成主要直接伤害的攻击方式。
- 派生指标：总伤害和每秒伤害留给面板或共用计算工具，不作为基础语义属性。

### 11.5 伤害类型

- 最短说明：主要直接命中采用的伤害种类，例如锐器、钝器或火焰。
- 公共身份：与远程攻击共用同一个属性。
- 正确来源：读取当前攻击方式实际生效的 `DamageDef`，包括 Maneuver 或原版能力映射后的最终结果。
- 展示规则：语义值保留稳定伤害身份；面板显示 `DamageDef` 的玩家名称，不显示技术 `defName`。
- 附加结果：额外爆炸、灼烧等拥有自己的伤害类型时，归入对应额外效果信息组，不污染主要攻击方式。

### 11.6 护甲穿透

- 最短说明：当前攻击方式对护甲的穿透程度。
- 公共身份：与远程攻击共用同一个属性。
- 正确来源：复用原版 `AdjustedArmorPenetration` 取得实际有效值。
- 格式规则：正值按百分比显示；明确的零值保留，默认显示为 `0`，不写成 `0%`。
- 附加结果：某项附加伤害自己的穿透归入该额外效果。

### 11.7 攻击次数

- 技术标识：`BDP_Property_AttackBurstCount`。
- 最短说明：一次完整攻击行动中执行多少次独立攻击事件。
- 标准名称：中文统一为“攻击次数”；近战面板可以按自己的展示规则称为“连击次数”。
- 公共身份：与远程攻击共用；删除原有独立的 `BDP_Property_BurstCount` 与 `BDP_Property_MeleeHitCount` 身份。
- 正确来源：当前 BDP 读取最终执行配置中的 `HitCount`/最终 `burstShotCount`；第三方提供等价事实。
- 值规则：最小有效值为 `1`；`0` 是错误配置，不是“没有连击”。
- 准确性：它统计发动的攻击事件，不保证这些攻击最终命中，也不统计目标数量。

### 11.8 攻击间隔

- 技术标识：`BDP_Property_AttackBurstInterval`。
- 最短说明：同一轮内相邻两个顺序攻击事件之间的时间。
- 标准名称：中文统一为“攻击间隔”；近战面板可以按自己的展示规则称为“连击间隔”。
- 公共身份：与远程攻击共用；删除原有独立的 `BDP_Property_MeleeInterval` 身份。
- 单位：秒；BDP 的 `HitIntervalTicks`/最终 `ticksBetweenBurstShots` 需要除以 `60`。
- 提供规则：只有攻击次数大于 `1` 且攻击事件按顺序发生时提供。
- 不适用规则：单次攻击与同时发生的多次攻击均不提供，不能使用 `0` 代替“不适用”。

### 11.9 额外效果

近战攻击复用与远程攻击相同的可重复“额外效果”信息组，不保留 `AppliedHediff` 与 `HediffSeverity` 两个只面向 `Hediff` 的扁平属性。

允许表达但不限于：

- 状态施加；
- 额外伤害；
- 击退；
- 爆炸；
- 资源变化；
- 对象生成；
- 第三方新增的其它玩家语义效果。

归属规则：

- 某个额外效果由哪种攻击方式产生，就挂在对应攻击方式下；
- 每个额外效果只提供自身适用的参数，不要求所有效果都有强度、持续时间或半径；
- 命中部位偏好等过于具体的机制不建立近战标准属性；以后若确有展示需求，可以由相应实现作为一种额外效果扩展声明；
- 当前风刃的 `HitPartPolicy=PreferVital` 没有展示需求，本轮不把它纳入功能语义信息。

## 十二、近战攻击明确删除或不纳入的项目

### 12.1 使用方式

- 决定：从近战攻击删除。
- 原因：手动、自动、反击等不应从 `PrimaryVerb` 或其它技术入口猜测；普通展示价值低。
- 后续若有视觉区分需求，优先作为标签或图标信息处理，不恢复为标准核心属性。

### 12.2 可选目标

- 决定：从标准近战攻击删除。
- 原因：原版合法目标条件过于复杂，普通近战展示价值很低。
- 特殊限制：例如“仅对机械体有效”应由对应特殊效果、限制说明或扩展属性表达，不让所有近战攻击承担宽泛目标分类。

### 12.3 扁平“近战方式”

- 决定：删除 `BDP_Property_MeleeAttackMethod`。
- 原因：当前读取器写入的是 `entry.WeaponMode`，得到的只会是 `Melee` 等技术分类，没有玩家价值。
- 替代结构：使用可重复的“攻击方式”信息组保持各组数值关联。

### 12.4 命中权重

- 决定：删除 `BDP_Property_HitWeight`，且当前没有概率展示需求。
- 原因：原始 `Tool.chanceFactor` 不是最终概率；实际选择还会经过原版 `AdjustedMeleeSelectionWeight`、使用者、目标类型和其它候选攻击方式共同计算。
- 不做替代：不新增“预计使用概率”，也不建设推导工具；游戏执行继续沿用原版权重算法。

### 12.5 独立命中次数与近战间隔

- 决定：删除 `BDP_Property_MeleeHitCount` 与 `BDP_Property_MeleeInterval`。
- 原因：它们分别与远程连发次数、连发间隔表达相同事实。
- 替代：统一使用公共“攻击次数”与“攻击间隔”。

### 12.6 附加状态与状态强度

- 决定：删除 `BDP_Property_AppliedHediff` 与 `BDP_Property_HediffSeverity` 在近战中的平铺引用。
- 替代：复用结构化“额外效果”；状态只是一种效果实现。

### 12.7 命中部位倾向

- 决定：不新增标准属性。
- 原因：粒度过于具体，当前没有展示需求，不值得扩大近战核心契约。
- 扩展边界：未来若需要，由具体实现作为额外效果扩展，而不是写入所有近战攻击都要认识的标准字段。

## 十三、近战攻击当前实现差距与验收要点

### 13.1 当前实现差距

- `BDP_Feature_MeleeAttack` 仍引用已确认删除的使用方式、可选目标、扁平近战方式、命中权重和 Hediff 平铺属性；
- 尚未建立稳定的“攻击方式”信息组；
- 尚未让每个攻击方式读取完整的 `MeleeToolSurface`；
- 攻击距离没有进入近战功能契约；
- 当前通用 Worker 把 `entry.WeaponMode` 错当“近战方式”；
- 当前通用 Worker 从 `VerbProperties.defaultCooldownTime` 读取近战冷却，未复用正确的原版 `AdjustedCooldown(tool, ...)`；
- 当前通用 Worker 直接读取 `meleeDamageBaseAmount` 与 `meleeArmorPenetrationBase`，没有复用 `VanillaMeleeStatProjection` 的原版修正入口；
- 当前通用数值辅助会丢弃零值，无法区分零、缺值和不适用；
- 当前读取器没有产生 `HitWeight`，进一步说明该槽位只是没有真实数据契约的占位项；
- 当前攻击次数和间隔仍使用近战专属属性身份，尚未与远程统一。

### 13.2 后续实施验收要点

- 弧月、蝎子、风刃、光魂大盾与光魂重刃都能解析出稳定攻击方式；
- 单一攻击方式的数据结构与多攻击方式一致，面板允许自行扁平展示；
- 光魂重刃钝击与切割各自保留独立伤害、伤害类型、穿透和冷却，不互相覆盖；
- 普通近战提供实际攻击距离 `1.42`，文本面板可以不突出，雷达图可以读取；
- 弧月行动冷却读取原版有效值 `2.0` 秒，而不是错误的 `defaultCooldownTime=0`；
- 蝎子提供攻击次数 `3` 与攻击间隔 `5/60` 秒；
- 单次近战提供攻击次数 `1`，但不提供攻击间隔；
- 零护甲穿透保留为合法值并默认格式化为 `0`；
- 风刃要害优先策略不因技术上可读取就自动进入展示信息；
- 信息读取失败不得改变 Tool 选择、攻击执行、伤害、冷却或命中部位行为；
- 第三方不使用 BDP Tool 路线时，仍可通过自定义来源 Worker 或显式值声明提供同一近战语义结构。

## 十五、护盾语义逐项重审记录

本节记录护盾语义正在进行的逐项确认。未确认项目只作为待讨论清单，不视为最终设计。

### 15.1 使用方式

- 决定：从护盾语义删除。
- 根因：当前标准来源 Worker 把表达条目的 `EntryType` 直接写成使用方式，因此护盾会得到 `Hediff`。这只是健康状态承载路线，不是玩家能够理解的使用方式。
- 已有实现差异：普通能量护盾、常驻型自动能量护盾与光魂大盾都在符合条件的伤害到来时自动执行抵挡，但它们进入有效状态的方式不同；一个“使用方式”字段无法稳定表达这两层事实。
- 替代表达：本轮不设替代标准属性；“自动”“姿态”“常驻”等短分类可由面板按需作为标签展示。未来若某种护盾确有关键且可展示的特殊启用限制，由该实现追加含义更精确的扩展属性，不让所有护盾承担宽泛字段。
- 设计边界：不得从 `Hediff`、`Ability` 或 `Verb` 等技术结构名称反推出玩家语义；第三方采用不同实现路线时也不需要伪装成 BDP 的承载结构。
- 中文名称与技术标识严格分层：玩家说明和设计讨论使用中文名称；代码与 XML 只在确有必要时单独列出技术标识，不把两者拼成一个名称。

### 15.2 触发条件

- 决定：从护盾语义删除，不改名为“启用条件”。
- 原因：现有护盾没有值得作为标准信息展示的额外启用条件；一个宽泛条件字段还会与抵挡攻击类型、抵挡角度、抵挡概率、抵挡消耗等实际规则重叠。
- 默认事实：护盾随其所属芯片、形态或姿态进入有效状态，不需要再重复声明“芯片启用期间”之类没有区分价值的信息。
- 扩展边界：未来的条件式护盾如果确有重要展示需求，可以追加含义明确的专用扩展属性，不提前为所有护盾保留宽泛槽位。

### 15.3 当前确认的重审优先级

护盾信息先按实际价值分为三组，逐项确认后再决定最终是否保持平铺：

1. 当前必需的核心抵挡信息：抵挡角度、抵挡概率、抵挡攻击类型、伤害吸收比例、抵挡消耗。
2. 可预见但并非所有护盾都适用的耐久信息：护盾容量、护盾恢复速度、恢复延迟。
3. 可重复的结果信息组：额外效果。反射、转化等结果归入额外效果，不作为护盾根部固定属性。

命名决定：原“抵挡类型”最终改称“抵挡攻击类型”，表示近战、远程、爆炸等攻击发生方式；锐器、钝器、火焰等保留“伤害类型”的既有含义。原“附加效果”统一改称“额外效果”；技术标识在实施阶段另行确定，不与中文名称混写。

### 15.4 抵挡角度

- 决定：保留，作为护盾核心抵挡信息。
- 最短说明：护盾能够防护的连续方向范围。
- 单位与数值：使用度数；数值表示完整覆盖总角度，不表示中心线左右各自的半角。
- 全向规则：全方位防护明确提供 `360`，不能因为实现上关闭角度检查就把该信息视为缺失。
- 有效值规则：提供当前实际形态、姿态或组合下的最终有效角度，不固定读取单份基础配置。
- 非连续范围：无法用单一连续扇区准确表达的特殊护盾不强行提供错误角度，可由实现追加更合适的扩展信息。
- 暂不增加：底层已有但当前内容均未使用的方向偏移不进入标准护盾信息；未来确有侧向、背向等展示需求时再独立扩展。
- 当前内容：单枚普通能量护盾 `180` 度，双枚普通能量护盾 `360` 度，常驻型自动能量护盾 `360` 度，光魂灵活姿态 `180` 度，光魂举盾姿态 `120` 度。

### 15.5 抵挡概率

- 决定：保留，作为护盾核心抵挡信息。
- 最短说明：攻击满足角度、类型和资源等其它条件后，护盾成功抵挡该次攻击的概率。
- 格式：按百分比提供；不存在随机失败判定、对合格攻击必定生效的护盾提供 `100%`。
- 明确不表示：抵挡概率不是伤害减免比例，也不把资源不足、角度不符或类型不符造成的失败混入概率。
- 有效值规则：提供当前实际形态、姿态或组合下的最终有效概率。
- 分组边界：不同攻击类别具有不同抵挡概率时不得取平均值；后续结构必须保持概率与其适用类别的对应关系。
- 当前内容：单枚普通能量护盾 `85%`，双枚普通能量护盾 `95%`，常驻型自动能量护盾 `70%`，光魂灵活姿态 `50%`，光魂举盾姿态 `98%`。

### 15.6 抵挡攻击类型

- 决定：保留，作为护盾核心抵挡信息；原“抵挡伤害类型”命名修正为“抵挡攻击类型”。
- 最短说明：护盾能够处理哪些发生方式的攻击，例如近战、远程或爆炸。
- 命名原因：当前 BDP 护盾判断的是攻击发生方式，不是锐器、钝器、火焰、电磁脉冲等伤害本身的性质；后者继续保留“伤害类型”的既有含义。
- 数据规则：使用可重复的稳定类别值，不把多个类别压成长文本；面板负责将类别显示为玩家可读文字或图标。
- 扩展边界：未来确实出现按锐器、火焰等伤害性质筛选的护盾时，再另外增加“抵挡伤害类型”，不提前混入当前属性。
- 反向规则：不能抵挡的普通类别不再重复写成“绕过规则”；抵挡攻击类型已经完整表达其接收范围。
- 当前内容：普通能量护盾、常驻型自动能量护盾与光魂灵活姿态提供远程和爆炸；光魂举盾姿态另外提供近战。

### 15.7 抵挡消耗

- 决定：保留，作为护盾核心抵挡信息；只提供消耗倍率数值，不建立资源—计算方式—数值的复合结构。
- 最短说明：成功抵挡一次攻击时，消耗量相对于本次来袭伤害值的倍率。
- 存储规则：保存原始倍率，例如 `0.5` 与 `0.75`；倍率基准固定为护盾抵挡判定时的来袭伤害值。
- 展示职责：消费端可按场景显示为“伤害值的 50%”或“每抵挡 1 点伤害消耗 0.5 点触力”，语义层不保存格式化句子。
- 零值与缺值：已知无消耗时提供明确的 `0`；缺失只表示该实现未提供或该属性不适用，不能把两者混为一谈。
- 扩展边界：固定消耗、其它资源或非线性公式不是当前标准属性要解决的问题；确有内容时由实现追加含义准确的扩展属性，不把当前简单倍率扩成通用公式系统。
- 当前行为：资源不足时抵挡失败且不消耗；普通能量护盾与光魂大盾倍率为 `0.5`，常驻型自动能量护盾倍率为 `0.75`。

### 15.8 护盾容量

- 决定：保留为可选标准属性，当前 BDP 护盾均不提供。
- 最短说明：护盾自身可以被消耗的独立防护储量上限。
- 所有权边界：只表示护盾自己的容量，不把角色的通用 Trion 上限或其它共享资源上限冒充护盾容量。
- 静态与运行时：本属性提供容量上限；当前剩余容量属于运行时信息，使用独立运行时属性。
- 明确不包含：单次最多能够抵挡的伤害不是护盾容量，未来确有需求时另设属性。
- 零值与缺值：没有独立容量机制时不提供，不能写 `0`；明确的零容量表示存在容量机制但当前上限确实为零。
- 当前内容：BDP 护盾直接消耗角色 Trion，没有独立护盾容量池，因此全部不提供本属性。

### 15.9 护盾恢复速度

- 决定：保留为可选标准属性；原“护盾恢复”改称“护盾恢复速度”，当前 BDP 护盾均不提供。
- 最短说明：护盾自身的独立容量每秒恢复多少。
- 单位：容量/秒，只保存数值，具体显示格式由消费端决定。
- 适用范围：只有存在独立护盾容量且会逐渐恢复的护盾才提供；角色 Trion 或其它共享资源的自然恢复不属于本属性。
- 零值与缺值：已知容量不会恢复时提供 `0`；没有独立容量机制或该属性不适用时不提供。
- 明确不包含：受击后等待多久开始恢复、破盾后多久重新启用不属于恢复速度，不能压进同一个数值。
- 当前内容：BDP 护盾没有独立容量，因此全部不提供本属性。

### 15.10 破盾行为

- 决定：删除宽泛的“破盾行为”属性。
- 原因：容量耗尽后停用、延迟恢复、永久损坏、爆炸、眩晕等结果没有统一且稳定的单值含义；保留枚举会迅速退化为不完整分类或长文本。
- 自然结果：具有容量机制的护盾在容量耗尽后停止防护属于容量机制的自然行为，不重复声明。
- 数值替代：未来确实出现破盾后等待恢复的内容时，新增含义明确的“破盾恢复时间”。
- 结果替代：破盾时爆炸、眩晕、施加状态等后果归入可重复“额外效果”信息组，并由效果本身说明其触发时机。
- 扩展边界：永久损坏等少见规则由具体实现追加专用扩展属性，不为尚不存在的内容建立通用破盾系统。
- 当前内容：BDP 护盾不存在独立容量与破盾流程，不提供相关值。

### 15.11 额外效果

- 决定：保留为可重复信息组，不作为平铺文本或列表属性。
- 最短说明：护盾除核心抵挡之外持续产生或在特定时机产生的其它玩法结果。
- 最小结构：每项额外效果拥有稳定身份、玩家可读名称、生效时机和该效果自身适用的信息；不要求所有效果共享同一组参数。
- 可表达内容：护盾有效期间的属性变化或限制、抵挡成功时的反射或转化、破盾时的爆炸、眩晕或状态施加等。
- 根部减法：删除护盾根部固定的“反射效果”与“转化效果”；它们只是额外效果的具体种类，不值得要求所有护盾认识。
- 排除范围：闪光、火花、护盾贴图回弹等纯视觉表现不属于玩家功能信息。
- 当前内容：光魂举盾姿态提供“移动速度降低 40%”与“无法攻击”两项持续期间额外效果；其它现有 BDP 护盾暂无需要声明的玩法额外效果。
- 复用边界：与远程攻击、近战攻击复用同一种额外效果信息组；具体效果只有在自身构成完整玩家功能时才声明子功能语义，不建立护盾专用效果枚举大全。

### 15.12 持续时间

- 决定：删除护盾专用“护盾持续时间”属性；临时护盾按需复用公共“持续时间”。
- 最短说明：护盾在产生后保持有效的固定时长。
- 提供规则：只有具有明确固定时长的护盾才提供；随芯片、形态、姿态或开关状态持续存在的护盾不提供，不能伪造“无限”时长。
- 静态与运行时：本属性表示定义中的完整固定时长；当前剩余时间属于运行时信息，使用独立运行时属性。
- 公共属性现状：公共“持续时间”由机动、泛用能力与需要固定时长的其它具体语义按需接收；Ability 来源不能只读取 AbilityDef 自身的效果时长，还必须继续解析实际承载时长的 Hediff、组件或业务配置。
- 复用原因：不同功能的“固定保持多久”本质相同；面板可以按护盾上下文显示“护盾持续时间”，语义层不为场景化名称复制属性身份。
- 当前内容：普通能量护盾、常驻型自动能量护盾与光魂大盾均随所属有效状态存在，不提供持续时间。

### 15.13 绕过规则

- 决定：从护盾语义删除。
- 所有权原因：当前 BDP 的护盾绕过策略由来袭攻击携带；“能够绕过护盾”是攻击的能力，不是被绕过护盾需要反向复制的信息。
- 普通接收范围：护盾不能抵挡近战等普通差异已经由“抵挡攻击类型”表达；角度限制由“抵挡角度”表达，不再重复列成绕过规则。
- 当前内容：伤害取消型减益投射物可以绕过已注册伤害护盾，该事实应归入对应远程攻击或额外效果的“护盾穿透”类信息，不归护盾语义。
- 扩展边界：某种护盾独有的特殊弱点若将来确有展示需求，可追加含义明确的弱点属性或额外效果，不恢复宽泛的反向规则列表。

### 15.14 伤害吸收比例

- 决定：新增，作为护盾核心抵挡信息。
- 最短说明：一次抵挡成功后，被护盾消除的伤害占本次来袭伤害的比例。
- 与概率区分：“抵挡概率”决定这次防护是否成功；“伤害吸收比例”决定成功后消除多少伤害，两者不得混用。
- 格式：按百分比提供；完全抵挡提供 `100%`，只减少一半伤害提供 `50%`。
- 明确不包含：单次最多吸收多少点伤害不属于比例；按固定数值吸收且没有稳定比例的实现不强行提供。
- 当前内容：所有现有 BDP 护盾在抵挡成功后把本次伤害降为零，因此全部提供 `100%`。

### 15.15 效果半径

- 决定：护盾按需复用公共“效果半径”，不新增护盾专用“防护范围”或“防护半径”属性。
- 最短说明：区域护盾能够从中心向外保护多远。
- 提供规则：只有确实保护周围区域的护盾才提供；只保护佩戴者的个人护盾不提供 `0`，因为区域半径对其不适用。
- 展示职责：面板可以在护盾上下文显示为“防护半径”，语义层仍使用公共属性身份。
- 视觉隔离：护盾贴图半径、命中特效离人物中心的距离等纯视觉参数不得冒充玩法效果半径。
- 扩展边界：区域内保护哪些阵营或实体等筛选规则等实际出现区域护盾后再设计，不预先建立目标筛选系统。
- 当前内容：现有 BDP 护盾全部只保护佩戴者，因此都不提供效果半径；配置中的 `shieldRadius=0.8` 只服务视觉表现。

### 15.16 恢复延迟

- 决定：护盾按需复用公共“恢复延迟”，不新增护盾专用副本；当前 BDP 护盾不提供。
- 收窄后的公共含义：某个可以自行恢复的容量在受损或消耗后，到开始恢复之间的等待时间。
- 单位：秒。
- 提供规则：只有具有独立护盾容量且受击后会暂停恢复的护盾才提供；立即持续恢复时明确提供 `0`，没有独立容量机制时不提供。
- 明确区分：能力再次可用属于能力冷却计时，攻击后恢复行动属于行动冷却时间，恢复一层离散充能属于充能恢复时间，均不得塞入恢复延迟。
- 破盾边界：普通受击后的恢复等待使用本属性；破盾后重新启用所需时间以后确有内容时使用独立“破盾恢复时间”。
- 当前属性现状：虽然公共属性 Def 已存在，但目前没有任何功能语义引用，也没有来源 Worker 提供；实施时还需删除其现有说明中“或再次触发前”的宽泛表述。

### 15.17 防护规则信息组

- 决定：护盾始终使用可重复“防护规则”信息组承载核心抵挡信息；即使只有一套规则也不退化为根部平铺属性。
- 子项内容：抵挡攻击类型、抵挡角度、抵挡概率、伤害吸收比例、抵挡消耗。
- 拆分条件：多种攻击类型共享全部数值时可以位于同一规则；任一关键数值不同就拆成独立规则，不取平均值，不依赖列表顺序猜测对应关系。
- 根部内容：护盾容量、护盾恢复速度、公共恢复延迟、公共持续时间、公共效果半径和可重复额外效果属于整个护盾，保留在根部。
- 展示职责：单一防护规则可由面板直接展开，不必显示“防护规则”标题；数据结构仍保持与多规则护盾一致。
- 扩展价值：第三方不同护盾路线只需显式声明相同护盾语义和规则结构；不要求使用 BDP 的 Hediff 或能量护盾组件。

## 十六、护盾语义的确认结构

```text
护盾
├─ 护盾容量（可选）
├─ 护盾恢复速度（可选）
├─ 恢复延迟（公共，可选）
├─ 持续时间（公共，可选）
├─ 效果半径（公共，可选）
├─ 防护规则（可重复；至少一项）
│  ├─ 抵挡攻击类型
│  ├─ 抵挡角度
│  ├─ 抵挡概率
│  ├─ 伤害吸收比例
│  └─ 抵挡消耗
└─ 额外效果（可重复）
```

结构边界：

- 根部可选属性没有真实值时不提供，不使用伪造的 `0`、无限或默认文字占位；
- 防护规则中的属性提供当前形态、姿态和组合下实际生效的最终值；
- 当前容量、剩余持续时间和剩余恢复等待属于运行时信息，不覆盖静态定义值；
- 面板可以选择隐藏默认值、换用上下文名称、改成图标或图表，但不能重新猜测属性所有权与对应关系；
- 纯视觉参数不进入功能语义；执行路线名称不进入玩家信息。

## 十八、护盾语义明确删除或不纳入的项目

- 使用方式：技术承载路线不是玩家使用方式；
- 触发条件与启用条件：当前没有稳定展示价值，不保留宽泛槽位；
- 护盾专用持续时间：改为按需复用公共持续时间；
- 破盾行为：含义过宽；明确时间以后使用破盾恢复时间，玩法后果使用额外效果；
- 绕过规则：攻击绕过护盾是攻击自己的能力；
- 反射效果、转化效果：归入可重复额外效果，不占护盾根部固定属性；
- 抵挡伤害类型：当前 BDP 只按攻击发生方式分类；真正按锐器、火焰等伤害性质筛选时再增加；
- 抵挡方向偏移：当前全部为正面或全向防护，没有展示需求；
- 单次抵挡上限：当前没有相应机制；
- 资源不足行为：当前全部是抵挡失败，不为单一现状增加属性；
- 视觉半径、闪光、火花和盾面回弹：属于表现参数，不进入玩家功能语义。

## 十九、护盾当前实现差距与验收要点

### 19.1 已确认的实现差距

- 当前 `BDP_Feature_Shield` 仍是根部平铺属性列表，尚无防护规则信息组；
- 当前 Hediff 来源 Worker 只会把 `EntryType=Hediff` 错误写成使用方式，并读取 Hediff 身份；它不会读取能量护盾组件的角度、概率、攻击类型或消耗倍率；
- Hediff 身份不属于护盾标准属性，因此当前来源即使读到它也不能形成所需护盾信息；
- 当前护盾专用展示器只认识旧平铺属性，不具备防护规则与额外效果结构展示；
- 当前没有提供伤害吸收比例；
- 当前制造组合信息尚不能根据普通能量护盾聚合数量解析单枚与双枚的最终有效值；
- 当前光魂举盾姿态的移动限制与攻击限制仍只存在于 HediffStage 执行定义中，尚未进入额外效果语义。

### 19.2 后续实施边界

- 护盾语义必须继续由芯片或组合显式声明，不能因为发现某个 HediffComp 就自动猜测它是护盾；
- BDP 自有护盾来源优先读取实际执行配置，避免再维护一份容易漂移的展示数值；
- 第三方不同实现路线可以通过显式值或自定义来源 Worker 提供相同防护规则，不要求复用 BDP 组件；
- Core 只承载中性功能、属性、结构化信息组和裁定契约；读取 BDP 能量护盾组件的正式 Worker 位于 Content；
- 信息解析失败不得改变护盾激活、角度判定、概率判定、资源扣除、伤害吸收、聚合升级或光魂姿态行为。

### 19.3 后续验收要点

- 单枚、双枚、常驻自动、光魂灵活姿态和光魂举盾姿态分别得到本章列出的准确最终值；
- 单一防护规则的数据结构与多规则护盾一致，面板允许自行扁平显示；
- 多规则护盾的攻击类型、角度、概率、吸收比例和消耗保持组内对应，不跨规则串值；
- 双枚普通能量护盾展示聚合后的 `360` 度与 `95%`，而不是两份单枚信息；
- `shieldRadius`、命中特效和视觉冲击参数不进入功能信息；
- 光魂举盾姿态显示移动限制与攻击限制，灵活姿态不继承这些效果；
- 角色 Trion 上限和恢复速度不冒充护盾容量与护盾恢复速度；
- 第三方通过 XML 追加新护盾属性或防护规则来源时，不需要修改 BDP Core C#；
- 两个工作台从同一解析结果读取护盾事实，各自决定文本、图标、角度图或其它展示取舍。

## 二十、机动语义逐项重审记录

### 20.1 现有内容范围核对

当前声明为“机动”的内容实际分成三类：

```text
机动
├─ 主动位移
│  ├─ 蚱蜢
│  ├─ 光魂推进
│  └─ 弹射砍击
├─ 持续移动方式
│  └─ 浮空
└─ 自动脱离
   └─ 紧急脱离
```

三类内容的实际信息需求不同：

- 主动位移关心位移距离、准备与冷却、消耗、目标和路径或落点限制；
- 持续移动方式关心移动速度、可选模式、可跨越环境和环境限制；
- 自动脱离关心触发条件、目的地规则和触发后的额外结果；
- `Ability`、`Passive`、`Hediff`、`PawnFlyer` 等仍然只是实现路线，不是机动种类，也不应作为玩家信息。

当前 `BDP_Feature_Movement` 仍是完全扁平的属性列表，无法可靠表达上述差异。当前通用来源 Worker 也只会从被动条目写出 `UsageMode=Passive`，或从 Ability 读取基础冷却、效果半径、持续时间和施放距离；尚不会表达按段累计规则、浮空属性影响、紧急脱离结果或其它业务额外效果。因此当前定义清单不等于已经能够对外提供的真实机动信息。

### 20.2 推进器的语义归属

- 修正决定：推进器本体不再声明“机动”，也不声明“组合支持”；它在没有形成组合时不提供独立功能语义。
- 根因：推进器单独启用时不产生位移、移动速度或路径能力；它只发布稳定被动身份，作为“光魂推进”组合的输入。
- 最终机动归属：真正执行冲刺的“光魂推进”组合继续显式声明“机动”，并提供组合最终生效的信息。
- 展示边界：制造台可以通过 `ComboDef` 的来源关系反向索引告诉玩家推进器能够参与“光魂推进”，但该内容属于组合关系信息，不是推进器的功能语义；不得把尚未形成的组合结果展示为推进器自身机动能力。
- 来源边界：不得因为被动条目名称或芯片说明中出现“推进”文字，就推断推进器本体具有机动功能。

### 20.3 机动方式信息组

- 决定：机动始终使用可重复“机动方式”信息组；即使只有一种方式也不退化为根部平铺。
- 分组单位：一项信息组代表一种可以独立说明的移动机制，不按底层组件数量拆分，也不按同一机制的玩家可选状态拆分。
- 当前映射：蚱蜢弹射、光魂推进、弹射砍击、浮空和紧急脱离各自形成一项机动方式；弹射砍击同时拥有独立的近战攻击方式，两种语义分别提供自己的信息。
- 多方式扩展：未来同一芯片同时提供闪现和持续飞行时，可以声明两项机动方式，避免两者的距离、冷却、触发条件或环境限制串值。
- 展示职责：只有一项时，面板可以直接展开其信息，不必显示“机动方式”标题；数据结构仍与多方式内容一致。
- 模式边界：浮空的关闭、仅移动时浮空和始终浮空属于同一项浮空方式的可选模式，不拆成三项机动方式。

### 20.4 机动形式

- 决定：不纳入标准信息项目。
- 原因：位移、持续移动和自动脱离等概念可以由芯片或组合的简介直接说明；再提供一份分类字段会重复信息，并迫使未来的新路线先适配既有分类。
- 消费边界：面板直接读取当前方式实际提供的距离、速度、限制和额外效果，并自行决定展示取舍；不要求先读取“机动形式”。
- 推断边界：不保留分类字段不等于允许消费端通过 `Ability`、`Passive`、`Hediff` 或字段组合反推功能语义；“机动”身份仍由功能声明显式确定。

### 20.5 有效距离与删除移动距离

- 决定：当前主动位移复用公共“有效距离”；全局删除公共“移动距离”，不再把执行结果建成静态设计属性。
- 最短说明：使用者到目标或作用点的最大有效距离；机动面板可以按场景显示为“最大位移距离”。
- 当前技术事实：蚱蜢、弹射砍击和光魂推进均以原版 `VerbProperties.range` 或运行时 `EffectiveRange` 限制目标点，并实际移动至该目标点，因此当前内容的最大可选距离与单段最大位移距离相同。
- 当前值：蚱蜢每段 `24.9` 格；弹射砍击每段 `24.9` 格；光魂推进 `15.9` 格。
- 不适用内容：浮空不执行一次性位移，不提供；紧急脱离目的地由运行时安全位置决定，不提供伪造的固定值。
- 多段边界：多段位移提供每一段的最大有效距离，不把玩家可连续选择的多段距离相加。
- 结果边界：实际跨越多远还会受落点修正、碰撞、路径中断等运行条件影响，属于执行结果；将来即使出现“可选距离”和“实际位移”不同的内容，也应先按真实设计重新判断其所有权，不自动恢复同名公共属性。
- 展示职责：雷达图等需要稳定数值的消费端直接读取公共有效距离，不读取名称或底层 Ability 字段自行猜测。

### 20.6 作用范围（撤回）

- 最终决定：撤回新增公共“作用范围”的早期结论，不建立该属性。
- 原因：目前只有“全图”“跨地图”两个假想文本结果，现有 BDP 没有使用者，也不能参与数值比较、归一化或雷达图；为此建立枚举、来源与展示契约收益不足。
- 距离边界：有限同地图距离继续使用数值型“有效距离”；不能换算为格数的极少数特殊范围不伪造成巨大数字。
- 当前处理：未来个别全图或跨地图功能先由本地化简介说明；只有出现多个真实内容并产生统一筛选、图标或比较需求时，才重新评估结构化属性。

### 20.7 最小距离

- 决定：机动方式按需复用公共“最小距离”。
- 最短说明：目标距离小于该数值时，不能发动这项机动。
- 提供规则：只有确实存在近距离禁用区时才提供；没有最低距离限制时不提供，不显示没有意义的 `0` 格。
- 含义边界：最小距离约束目标选择，不保证角色最终至少移动这么远；运行时碰撞、落点修正等仍可能改变实际结果。
- 区间表达：与公共有效距离同时提供时，可以表达允许选择的距离区间。
- 当前内容：蚱蜢、弹射砍击和光魂推进均没有明确的最小距离限制；浮空和紧急脱离不适用，因此现有 BDP 机动方式均不提供。

### 20.8 移动速度修正

- 决定：不作为公共属性，也不作为机动方式的固定专属属性。
- 原因：移动速度倍率本质上是对 RimWorld 原版 `MoveSpeed` 的具体属性修正，不是与业务对象解耦的公共概念；把它固定到机动结构还会使机动契约逐渐吸收各种具体角色属性。
- 表达位置：确有展示需要时，归入对应功能的可重复“额外效果”，以具体属性影响表达。
- 当前内容：浮空的 `MoveSpeed=2.0` 可以表达为浮空机动方式的一项额外效果；光魂举盾的 `MoveSpeed=0.6` 继续属于护盾额外效果，两者不共享一个机动固定字段。
- 位移速度边界：PawnFlyer 的 `flightSpeed=45` 是位移过程参数，也不并入移动速度修正；是否需要独立展示只在以后出现真实需求时再审。

### 20.9 准备时间

- 决定：机动方式按需复用公共“准备时间”；它与攻击上下文显示的“预热时间”使用同一公共属性身份。
- 最短说明：开始使用后，到机动实际发动前需要等待的时间。
- 当前值：蚱蜢 `0.2` 秒；弹射砍击 `0.4` 秒；光魂推进 `0.2` 秒。
- 不适用内容：浮空切换没有独立准备阶段，不提供；紧急脱离崩解流程中的表现时长不是玩家发动前准备时间，不提供。
- 展示职责：攻击面板可以显示为“预热时间”，机动面板可以显示为“准备时间”，数据层不建立两个同义属性。

### 20.10 行动冷却时间

- 决定：机动方式按需复用公共“行动冷却时间”。
- 最短说明：机动发动后，角色恢复普通行动前需要等待的时间。
- 原版来源：对应 `VerbProperties.defaultCooldownTime` 产生的原版冷却姿态；不等同于 Ability 再次可用前的计时。
- 当前内容：光魂推进提供 `1` 秒；蚱蜢和弹射砍击没有额外行动冷却，不提供；浮空和紧急脱离不适用。
- 区分规则：行动冷却限制角色后续行动，归具体机动结果；能力冷却计时限制整项能力再次使用，归父级能力。两者可以同时存在于同一功能树，但不得同时平铺进机动方式。

### 20.11 能力冷却计时

- 修正决定：能力冷却计时不再属于机动方式；当主动机动具有独立的再次使用计时时，应声明“能力”父语义，并由父级能力提供该信息。
- 最短说明：整项能力再次可用前需要等待的时间。
- 固定表达：光魂推进固定 `30` 秒。
- 累计表达：蚱蜢为 `5` 秒乘以实际位移段数；弹射砍击为 `10` 秒乘以实际位移段数。
- 数据要求：累计形式至少保留单位时间和“按位移段累计”的稳定依据，不能把 `5` 秒与 `10` 秒错误发布成整次固定冷却。
- 当前实现事实：蚱蜢与弹射砍击在最终段落地后以基础冷却乘总段数覆盖 Ability 冷却；当前通用 Ability 来源 Worker 只读取 Def 基础值，尚未表达累计规则。
- 不适用内容：浮空和紧急脱离没有能力再次使用计时，不提供。
- 运行时边界：这里提供定义规则；当前剩余冷却属于运行时信息，使用独立运行时属性。
- 所有权原因：冷却限制的是玩家再次释放整项能力，而不是“移动结果”本身；即使能力只有一个机动子功能，也不能因此把能力生命周期下沉到机动中。

### 20.12 单次使用消耗

- 修正决定：由释放整项能力产生的单次使用消耗归父级能力；只有确实由某项机动结果单独结算、且不属于能力释放外壳的消耗，才允许归机动方式。
- 最短说明：完成一次结算单位实际扣除的 Trion 数量。
- 结算单位：普通功能默认按整次使用结算，不重复声明；多段位移确实逐段扣费时，额外标明“每段位移”。
- 当前值：蚱蜢每段 `20`；弹射砍击每段 `40`。
- 零值与缺值：光魂推进最终解析出的逐次使用消耗为 `0`，不提供；浮空没有逐次使用消耗，不提供。
- 所有权边界：蚱蜢和弹射砍击的逐段消耗仍属于同一次能力释放的结算规则，因此位于父级能力；芯片容量占用和激活成本属于芯片通用信息，不复制到能力或机动方式；紧急脱离触发后销毁来源芯片属于额外效果，不冒充资源消耗。
- 扩展边界：BDP 标准功能只使用 Trion；扩展模组若使用其它资源，应通过 XML 声明自己的扩展属性，不要求 BDP Core 维护通用资源目录。

### 20.13 可选目标

- 决定：机动方式按需复用公共“可选目标”，不建立机动专属副本。
- 最短说明：玩家发动机动时可以选择什么作为目标。
- 当前内容：蚱蜢、弹射砍击和光魂推进均允许选择地点。
- 不适用内容：浮空没有目标选择，不提供；紧急脱离由系统自动寻找安全位置，不把自动目的地冒充玩家可选目标。
- 展示职责：面板可以隐藏“地点”文字并使用落点图标；语义层继续提供稳定类别值，不把原版 `TargetParams` 技术结构暴露给消费端。

### 20.14 需要视线

- 决定：机动方式按需复用公共“需要视线”。
- 最短说明：选择目标地点时，当前一段起点与目标之间是否必须存在直接视线。
- 当前内容：蚱蜢、弹射砍击和光魂推进当前均要求视线；蚱蜢与弹射砍击的多段路径按每一段起点分别判断。
- 不适用内容：浮空和紧急脱离没有玩家目标选择，不提供。
- 现有定义差异：弹射砍击 XML 注释写有“沿路径跳不需要视线”，但实际字段为 `requireLineOfSight=true`，执行和预览也遵循需要视线；信息层按真实有效值提供 `true`。
- 玩法边界：是否把弹射砍击改为无视视线属于独立玩法需求，本轮不根据过期注释改变现有行为。

### 20.15 路径限制

- 决定：从机动固定属性中删除，不把自由文本升级为结构化路径规则系统。
- 原因：现有主动位移的直线阻挡、光魂推进的截断终点、浮空的混合寻路和紧急脱离的直接传送没有一套稳定同构的值；自由文本只会重复简介，消费端无法可靠解析、比较或可视化。
- 当前表达：路径与环境规则继续由芯片或组合简介说明，并由游戏内目标预览直接反馈。
- 额外效果边界：附带产生的玩法结果可以进入额外效果；普通目标、落点和路径合法性不是额外效果。
- 后续扩展：以后确有高频且需要统一图标或筛选的特征时，再增加含义明确的属性，例如“可穿越墙体”；不提前建立路径规则百科。

### 20.16 持续时间

- 决定：机动方式按需复用公共“持续时间”，当前 BDP 机动内容均不提供。
- 最短说明：机动效果在自动结束前能够维持多久。
- 提供规则：只用于具有固定持续时长的机动状态，例如持续十秒的飞行能力。
- 明确排除：位移从起点到终点所花的时间不是持续时间；芯片保持启用多久不是持续时间；玩家主动关闭或由环境决定结束的状态不提供“无限”或伪造数值。
- 当前内容：蚱蜢、弹射砍击、光魂推进和紧急脱离均为一次性结果；浮空由玩家模式与环境决定，全部不提供。

### 20.17 结束条件

- 决定：从机动语义删除。
- 原因：固定时间结束已由持续时间表达；到达落点自然结束没有展示价值；浮空的玩家模式、征召状态、屋顶环境和安全降落流程无法由单个枚举准确表达。
- 紧急脱离边界：执行一次后自然结束不重复声明；触发后销毁来源芯片属于额外效果。
- 扩展边界：未来确有重要结束规则时，以含义明确的扩展属性或额外效果表达，不保留会膨胀成自由文本或万能枚举的宽泛槽位。

### 20.18 触发条件

- 决定：从机动语义删除；有真实展示需求时再补充含义准确的属性。
- 当前实现：公共属性 Def 虽然存在，并被多个功能语义列入属性清单，但没有任何来源 Worker 提供它，两个工作台也没有专门消费逻辑；游戏执行完全不读取功能信息中的触发条件。
- 紧急脱离：其“战斗体因 Trion 耗尽而被动崩解”条件继续由芯片简介说明，实际触发仍由崩解业务流程负责。
- 删除原因：当前唯一用途只是重复显示紧急脱离简介，没有筛选、图标、图表或其它结构化消费需求，不值得为单个实例建立公共条件体系。
- 全局边界：第二十八节已经确认全局删除公共“触发条件”属性；“组合支持”与“攻击增强”已分别在第二十五节和第二十七节决定删除。

### 20.19 使用方式

- 决定：从机动语义删除。
- 当前错误：通用来源 Worker 直接把表达条目的 `EntryType` 写成使用方式，导致蚱蜢与光魂推进输出 `Ability`、浮空与紧急脱离输出 `Passive`；这些是实现入口类型，不是玩家使用语义。
- 无法区分：浮空由被动表达承载但允许玩家切换模式；紧急脱离同样由被动表达承载但在崩解时自动执行，单个 `Passive` 值无法说明真实交互。
- 当前替代：主动、自动、可切换等必要说明由芯片或组合简介承担。
- 扩展边界：以后确有结构化展示需求时再增加含义准确的交互属性，不从 `Ability`、`Passive`、`Hediff` 或 `Verb` 反推。

### 20.20 额外效果

- 决定：机动方式复用可重复“额外效果”结构，不为具体结果增加机动固定字段。
- 所有权规则：机动本体只描述移动能力；对自身属性、沿途目标或来源芯片产生的其它结果进入额外效果；已经由另一完整功能语义负责的信息不得重复声明。
- 当前内容：
  - 蚱蜢没有额外效果；
  - 浮空的 `MoveSpeed=2.0` 作为属性影响类额外效果；
  - 光魂推进提供沿途敌人受到 `20` 点钝伤、可推动敌人被推向终点，以及发生阻挡碰撞时眩晕 `120` tick（`2` 秒）；
  - 紧急脱离成功触发后销毁产生该功能的来源芯片；
  - 弹射砍击的沿途切割伤害归入其独立近战攻击语义，不在机动额外效果中复制。
- 扩展边界：扩展模组可以追加新的额外效果类型；标准面板不认识具体类型时，至少显示其本地化名称和通用内容，不从实现类名称生成玩家文案。

### 20.21 效果半径

- 决定：机动方式按需复用公共“效果半径”，当前 BDP 机动内容均不提供。
- 最短说明：一次机动能够同时影响目标点周围多大范围。
- 区分规则：有效距离表示目标点可以选择多远；效果半径表示目标点周围多大区域会一起受到机动效果，两者不得合并。
- 提供规则：只有实际移动或影响一个区域内多个对象时才提供；只移动功能所属角色时不提供 `0`。
- 当前内容：蚱蜢、弹射砍击、光魂推进、浮空和紧急脱离都没有区域机动范围。

### 20.22 最大目标数

- 决定：机动方式按需复用公共“最大目标数”，当前 BDP 机动内容均不提供。
- 最短说明：一次机动最多能够移动或影响多少个目标。
- 提供规则：只有存在明确数量上限时才提供；只移动使用者自身时不提供 `1`；区域内没有额外数量上限时不提供“无限”。
- 配合关系：与效果半径同时存在时，表示作用区域内最多实际处理多少个目标。
- 当前内容：现有 BDP 机动功能都只移动使用者自身。

### 20.23 充能

- 修正决定：当充能限制整项主动能力的可用次数时，归父级能力，不归机动方式；当前 BDP 机动内容均不提供。
- 充能上限：该功能最多能够储存多少次可用次数；没有储备次数机制时不提供。
- 充能恢复时间：恢复一次充能所需的时间；不与能力整体再次可用前的能力冷却计时混用。
- 独立性：只有上限但用完不自动恢复时，可以只提供充能上限；共享充能池只由共同父级能力提供，不复制到各项机动方式或其它子功能。
- 运行时边界：当前剩余充能属于角色运行时信息，制造台与静态成品预览不伪造，也不从上限推算。
- 当前内容：蚱蜢、弹射砍击、光魂推进、浮空和紧急脱离都没有充能机制。

## 二十一、机动语义的确认结构

```text
机动
└─ 机动方式（可重复；至少一项）
   ├─ 有效距离（公共，可选）
   ├─ 最小距离（公共，可选）
   ├─ 效果半径（公共，可选）
   ├─ 最大目标数（公共，可选）
   ├─ 可选目标（公共，可选）
   ├─ 需要视线（公共，可选）
   ├─ 准备时间（公共，可选）
   ├─ 行动冷却时间（公共，可选）
   ├─ 持续时间（公共，可选）
   └─ 额外效果（可重复）
```

结构边界：

- 每项机动方式只提供对该方式真实适用的信息；缺值不使用 `0`、无限或默认文字占位；
- 当前只有一种方式时，面板可以直接展开，不要求显示“机动方式”标题；
- 有效距离保持纯数值；极少数全图、跨地图规则暂由简介说明，不伪装成巨大距离数值；
- 独立的能力冷却、充能和能力释放消耗由“能力”父语义提供，不复制到机动方式；
- 多段位移对能力冷却与消耗的累计依据仍由权威业务来源解析，不建立通用公式系统；
- 简介负责说明机动的用途、模式和复杂路径规则；固定属性不重复维护同一段说明；
- 额外效果承载对自身属性、沿途目标或来源芯片产生的其它结果，但不得复制另一个完整功能语义已经拥有的信息；
- 面板决定文本、图标、雷达图和信息优先级，不从 `Ability`、`Passive`、`Hediff`、`Verb` 或 PawnFlyer 等实现结构反推玩家功能。

## 二十二、现有 BDP 机动内容的目标信息结果

### 22.1 蚱蜢

```text
能力：蚱蜢
├─ 能力冷却计时：5 秒 × 实际位移段数
├─ 单次使用消耗：20/段
└─ 机动
   └─ 机动方式：蚱蜢弹射
      ├─ 有效距离：24.9 格/段
      ├─ 可选目标：地点

```

多段路径、目标与落点规则继续由简介和游戏内目标预览说明；不建立“多段”“地面直线”或“路径限制”等固定属性。

### 22.2 弹射砍击

```text
能力：弹射砍击
├─ 准备时间：0.4 秒
├─ 能力冷却计时：10 秒 × 实际位移段数
├─ 单次使用消耗：40/段
├─ 机动
│  └─ 机动方式：弹射砍击
│     ├─ 有效距离：24.9 格/段
│     ├─ 可选目标：地点
│     └─ 需要视线：是（逐段判断）
└─ 近战攻击
   └─ 攻击方式：沿途切割
```

沿途切割伤害归入该组合独立声明的近战攻击语义，不在机动额外效果中复制。XML 中“沿路径跳不需要视线”的注释与实际字段及执行逻辑相反，信息按当前真实值“需要视线”提供；是否改变玩法另行确认。

### 22.3 光魂推进

```text
能力：光魂推进
├─ 能力冷却计时：30 秒
└─ 机动
   └─ 机动方式：光魂推进
      ├─ 有效距离：15.9 格
      ├─ 可选目标：地点
      ├─ 需要视线：是
      ├─ 准备时间：0.2 秒
      ├─ 行动冷却时间：1 秒
      ├─ 额外效果：沿途敌人受到 20 点钝伤
      ├─ 额外效果：可推动敌人被推向终点
      └─ 额外效果：发生阻挡碰撞时，被推动目标眩晕 2 秒
```

光魂推进最终逐次使用消耗为 `0`，不提供单次使用消耗；光魂芯片自身的容量占用与激活成本仍属于芯片通用信息。

### 22.4 浮空

```text
机动
└─ 机动方式：浮空
   └─ 额外效果：移动速度倍率 2.0
```

关闭、仅移动时浮空、始终浮空三种模式仍属于同一项机动方式。露天通行、屋顶限制和安全降落规则由简介说明，不压入路径限制文本。

### 22.5 紧急脱离

```text
机动
└─ 机动方式：紧急脱离
   └─ 额外效果：成功发动后销毁产生该功能的来源芯片
```

战斗体因 Trion 耗尽而被动崩解的发动条件、安全目的地选择及信标优先规则由简介说明；不建立只为这一项内容服务的公共触发条件或目的地规则。

本章数值只记录当前权威定义与执行规则的审计预期，用于验收来源 Worker；不得把这些数值手填进 `Features` 声明。

### 22.6 推进器归属修正

推进器本体单独启用时不产生任何位移、移动速度或路径能力，因此不再声明机动，也不声明其它虚构的独立功能。它参与“光魂推进”的事实由 `ComboDef` 来源关系反向提供；真正执行位移的“光魂推进”组合继续声明机动，并提供 22.3 的最终有效信息。

## 二十三、机动语义明确删除或不纳入的项目

- 机动形式：简介已经能够说明，不增加重复分类字段；
- 使用方式：当前值直接来自 `Ability`、`Passive` 等技术条目类型，不能表达玩家真实交互；
- 触发条件：当前没有来源或消费逻辑，紧急脱离由简介说明；
- 移动距离：属于受落点、碰撞和路径影响的执行结果，不作为静态公共设计属性；
- 路径限制：自由文本不能可靠解析、比较或可视化，复杂规则由简介和目标预览承担；
- 结束条件：固定时间已有持续时间，其余规则差异过大且大多没有展示价值；
- 机动固定移动速度修正：具体原版属性影响进入额外效果；
- 位移速度：当前 PawnFlyer 的飞行速度没有独立展示需求，不提前建立属性；
- 多段路径标记：蚱蜢与弹射砍击由简介和按段距离、冷却、消耗共同说明，不增加重复标签；
- 目的地规则：紧急脱离的安全位置和信标优先策略由简介说明，不为单个实例建立固定结构；
- 芯片容量占用、激活成本与装载限制：属于芯片通用信息，不复制进机动方式。

## 二十四、机动当前实现差距与验收要点

### 24.1 已确认的实现差距

- 当前 `BDP_Feature_Movement` 仍为根部平铺属性列表，尚无可重复机动方式信息组；
- 当前清单仍包含使用方式、触发条件、独立移动距离、路径限制和结束条件等本轮删除项；
- 当前推进器错误声明为机动，尚未移除这项不存在的独立功能声明；
- 通用表达来源 Worker 会把 `EntryType` 写成使用方式，导致 `Ability`、`Passive` 等技术类型泄漏为玩家信息；
- Ability 来源 Worker 只读取基础 Ability 冷却、效果半径、持续时间和施放距离，尚不提供可选目标、需要视线、行动冷却、单次使用消耗及其结算单位；
- Ability 来源 Worker 把 Def 基础冷却当成固定完整冷却，无法表达蚱蜢和弹射砍击按位移段累计的真实规则；
- 组合表达来源 Worker 只读取组合最终表达条目的基础字段，不继续读取最终 Ability 定义与业务执行配置，因而不能形成弹射砍击和光魂推进的完整机动信息；
- 被动来源 Worker 只提供错误的使用方式，不能读取浮空速度影响或紧急脱离触发后销毁来源芯片的额外效果；
- 当前没有机动专用展示器，两个工作台只能落入通用展示，尚不理解“能力 → 机动”的父子结构、机动方式、按段计时与按段消耗；
- 当前公共单次使用消耗仍有重复的 `UseCost`、`TrionCost` 方向，后续实施需按本轮决定收敛为固定 Trion 数值，不建立通用资源身份结构。

### 24.2 后续实施边界

- 机动语义继续由芯片或组合显式声明，不能因为发现 Ability、PawnFlyer、移动 Hediff 或传送代码就自动猜测；
- BDP 自有来源优先读取实际有效 Ability、表达结果、HediffStage 和业务配置，不另维护一份易漂移的展示数值；
- 简介、目标预览和结构化属性各自负责自己的信息，不把复杂路径规则复制为自由文本属性；
- Core 只承载中性功能、公共属性、结构化信息组和合并契约；读取浮空、紧急脱离、光魂推进等 BDP 业务实现的 Worker 位于 Content；
- 第三方可以通过 XML 增加新的机动属性或额外效果，并可注册自定义来源 Worker；标准面板对未知扩展至少提供本地化通用回退；
- 信息解析失败不得改变跳跃、冲刺、浮空寻路、紧急脱离、Trion 扣除、Ability 冷却或近战伤害等现有业务执行。

### 24.3 后续验收要点

- 蚱蜢、弹射砍击、光魂推进、浮空和紧急脱离分别得到 22.1 至 22.5 列出的准确目标信息；
- 推进器本体不显示不存在的独立功能，只在组合关系区域显示可参与“光魂推进”；光魂推进组合继续显示最终机动结果；
- 蚱蜢与弹射砍击在机动子功能显示每段距离，在能力父级显示每段 Trion 消耗和按实际段数累计的能力冷却；不把基础时间误报成整次固定冷却，也不在父子间复制；
- 弹射砍击的切割伤害只出现在近战攻击语义，不在机动额外效果重复；
- 光魂推进的钝伤、推动和条件眩晕保持同一最终组合上下文，不从来源芯片简单拼接；
- 浮空的移动速度倍率进入额外效果，模式与屋顶规则继续由简介说明；
- 紧急脱离只把来源芯片销毁作为额外效果，不额外输出没有消费需求的触发条件和目的地规则；
- 有限距离保持数值可供雷达图读取；极少数全图、跨地图规则只在简介中说明，不伪装成巨大距离数值；
- 单项机动方式允许面板扁平显示，多项机动方式的数据仍保持组内对应；
- 两个工作台读取同一机动解析结果，各自决定文本、图标、雷达图和默认值显隐。

## 二十五、组合支持语义存在性复审

### 25.1 最终决定

- 删除 `BDP_Feature_ComboSupport`（组合支持）功能语义，不再为它逐项设计属性。
- 撤销第二十节中“推进器改为组合支持”的早期暂定方向；推进器本体既不声明机动，也不声明组合支持。
- “能够作为某个组合技的来源”是一项定义关系，不是玩家已经获得的独立功能；不得与远程攻击、护盾、机动等最终功能并列。
- 组合技的距离、目标、时间、消耗和最终效果属于组合结果，不属于仅提供组合输入身份的来源芯片。

### 25.2 当前实现事实

- 当前 `BDP_Feature_ComboSupport` 只存在于功能语义 Def 清单，没有任何正式芯片或组合技实例引用它。
- 推进器当前 XML 仍错误声明为机动；第二十节确认的归属修正尚未实施，因此本次修订不会产生代码或游戏行为变化。
- 六个正式 `ComboDef` 已分别在自己的 `Features` 中声明最终功能语义：飞锥、黄蜂为远程攻击；弹射砍击为机动与近战攻击；光魂推进为机动；旋空弧月为近战攻击；战斧当前错误声明为远程攻击及攻击增强子项，目标结构只保留远程攻击本体。
- 组合表达执行链能够生成和执行组合结果，但统一信息解析器当前只解析芯片有效配置中的 `Features`，尚未把 `ComboDef.Features` 接入面板信息模型。

### 25.3 来源芯片的组合关系

来源芯片只对外提供“可参与哪些组合”的关系信息，不把组合结果伪装为自己的功能：

```text
推进器
├─ 一般信息
│  ├─ 分类：配件
│  └─ 可参与组合
│     └─ 光魂推进
│        ├─ 另一来源：光魂
│        └─ 来源范围：光魂·大盾形态
└─ 独立功能：无
```

- 组合关系以 `ComboDef` 的第一/第二来源键、来源成品准入、形态/姿态范围、来源变体要求和角色使用条件为唯一声明来源。
- 信息系统可以对已加载 `ComboDef` 建立反向索引；这仍然是读取显式定义，不是从技术类、名称或执行代码猜测功能。
- 不在每枚来源芯片上重复维护“支持哪些组合”，避免两处声明漂移。
- 第三方模组新增 `ComboDef` 后，只要声明来源和最终 `Features`，标准关系读取与组合结果展示即可自然接入。

### 25.4 组合结果的功能归属

组合技作为独立结果拥有自己的名称、简介、来源条件和最终功能语义，不挂到任一来源芯片名下：

```text
组合结果：光魂推进
├─ 来源
│  ├─ 光魂：大盾形态
│  └─ 推进器
└─ 最终功能
   └─ 能力：光魂推进
      └─ 机动
         └─ 机动方式：光魂推进
```

组合结果拥有独立的主动释放生命周期时，以“能力”为根功能；同一次释放产生的完整结果作为并列子功能，不在结果之间建立虚假的包含关系：

```text
组合结果：弹射砍击
└─ 能力：弹射砍击
   ├─ 机动
   │  └─ 机动方式：弹射砍击
   └─ 近战攻击
      └─ 攻击方式：沿途切割
```

- 弹射砍击的机动与近战攻击都是最终结果，因此在同一能力下并列，不把近战攻击嵌套为机动的子功能。
- `ComboDef`（组合定义）只是组合结果及来源关系的载体，不自动成为功能语义；组合是否使用“能力”根节点仍按玩家可感知的释放生命周期判断。
- 组合最终值从组合有效表达和实际业务定义读取，不能把两枚来源芯片各自的信息简单拼接。
- 来源形态/姿态只决定组合能否成立；组合结果未来若自己拥有多形态，应建立组合结果自己的上下文，不能借用某一来源芯片的上下文冒充。

### 25.5 两个工作台的消费边界

- 芯片制造台查看单枚候选芯片时，可以显示其独立功能以及由 `ComboDef` 反向得到的“可参与组合”关系；没有形成组合时不得展示组合最终数值。
- 触发器装配台在当前芯片对、来源准入和形态/姿态范围能够匹配某个 `ComboDef` 时，应另外显示一项独立组合结果；来源芯片信息和组合结果信息不得混在同一功能树中。
- 两个面板共用同一份组合关系与组合结果解析数据，但各自决定卡片位置、展开方式、文本、图标和图表。

### 25.6 后续实施差距与验收

- 删除 `BDP_Feature_ComboSupport` Def、语言项及只针对它的无效属性接收清单。
- 移除推进器当前错误的 `thruster_movement` 功能声明；保留其表达被动身份，因为组合执行仍需要它。
- 为信息层增加最小组合关系读取结果，来源直接复用现有 `ComboDef` 索引和准入契约，不另造第二份组合匹配规则。
- 为组合结果建立只读信息入口，解析 `ComboDef.Features` 并继续复用现有 `ResolvedChipFeature`、属性来源 Worker 和展示器。
- 验证推进器单独查看时不显示机动或组合支持；与符合范围的光魂配对时显示独立“光魂推进”组合结果。
- 验证光魂处于重刃形态时不把光魂推进显示为当前可用组合结果；大盾形态下按现有 `FirstSourceScope` 正确成立。
- 信息读取和展示失败不得改变组合匹配、组合表达生成、Ability、Verb、Trion 结算或实际攻击执行。

## 二十六、语义树、上下文与结构化信息组边界

### 26.1 当前运行时模型

当前 `ChipInformationModel` 同时承载身份、一般信息块、顶层功能语义、形态/姿态上下文和诊断：

```text
芯片信息模型
├─ 身份
├─ 一般信息块（允许嵌套子块）
├─ 顶层功能语义
│  └─ 功能实例
│     ├─ 根属性
│     ├─ 功能级子组
│     ├─ 信息组（可重复）
│     │  ├─ 组内属性
│     │  └─ 组级子组
│     └─ 子功能语义
├─ 形态/姿态上下文
│  └─ 各上下文自己的功能语义快照
└─ 诊断
```

- 同一个 `ChipFeatureDef` 可以通过不同稳定 Id 声明多个独立功能实例。
- `ChipFeatureDeclaration.Children` 当前承载子功能语义；根节点深度为 `0`，校验器最多允许到深度 `2`，即根功能、子功能、孙级功能。
- 属性值当前只支持文本、布尔、整数、数值、百分比、时间、枚举和有序简单列表；列表元素没有字段名和组身份，不能可靠承载多套成组参数。
- 一般信息块虽然已有递归子块，但不得借用它承载功能语义内部结构，否则两个面板和扩展模组又要在一般信息与功能信息之间分头读取。

### 26.2 三种嵌套关系必须分开

| 层次 | 职责 | 例子 |
|---|---|---|
| 形态/姿态上下文 | 决定当前有哪些功能以及哪些值生效 | 光魂的大盾、灵活、举盾、重刃 |
| 结构化信息组 | 保持同一功能内部一组参数的对应关系 | 攻击方式、防护规则、机动方式 |
| 子组 | 表达依附于整个功能或某个具体信息组的次级信息 | 额外效果 |
| 子功能语义 | 表示父功能内部确实包含另一项完整玩家功能 | 未来的部署功能所产生实体拥有远程攻击 |

- 同一次结果同时提供两项能够独立理解和消费的功能时，它们应当在共同所有者下并列；弹射砍击的机动与近战攻击就是“能力”父级下的并列子语义。
- 一个功能内部重复出现的参数记录不是子功能；多套防护规则和多种攻击方式必须进入信息组。
- 次要结果如果只需要名称和少量参数，进入“额外效果”子组，并按实际所有者挂在功能或具体信息组下面；只有它具有独立稳定语义、需要自己的专用面板或继续包含完整属性时，才升级为子功能语义。

### 26.3 形态和姿态保持为上下文投影

光魂的目标信息关系为：

```text
光魂
├─ 大盾形态
│  ├─ 灵活姿态
│  │  ├─ 近战攻击：盾击
│  │  └─ 护盾：灵活防御
│  └─ 举盾姿态
│     ├─ 近战攻击：盾击
│     └─ 护盾：举盾防御
└─ 重刃形态
   └─ 近战攻击：重刃
```

- 底层仍使用稳定上下文键和父上下文键；功能来源通过活动表达条目判断在当前上下文是否可达。
- 上下文是查看和有效性维度，不拥有功能属性定义，也不作为功能树中的父功能。
- 面板可以将形态和姿态绘制为树、标签页或选择器，但不能改变解析模型中功能与上下文的所有权。

### 26.4 目标信息组与子组结构（2026-09-28 按用户确认扩展功能级子组）

后续在 Core 增加中性、固定两级的组结构：功能整体和具体信息组都可以拥有一层子组；子组本身不可递归：

```text
功能实例
├─ 根属性
├─ 信息组（可重复）
│  ├─ 组内属性
│  └─ 信息组级子组（可重复；只允许一层）
│     └─ 子组属性
├─ 功能级子组（可重复；归属于整个功能）
│  └─ 子组属性
└─ 子功能语义
   ├─ 根属性
   └─ 自己的信息组
```

- 信息组使用独立于 `ChipFeatureDef` 的轻量 Def 类型，避免把“防护规则”等参数分组伪装为玩家功能。
- 信息组 Def 声明名称、顺序和允许接收的属性槽位；功能语义声明允许使用哪些信息组。
- 功能实例可以声明多个同类信息组，每组有稳定 Id、可选语言键、来源和独立属性结果。
- 用户已明确确认：所有“额外效果”都必须以子组形式嵌套声明，不能作为与信息组并列的根组；额外效果可以归属于整个功能，也可以归属于某个具体信息组。
- 功能级子组和信息组级子组都使用不可递归的独立声明/只读结果类型：`ChipFeatureDef.Subgroups` / `ChipFeatureDeclaration.Subgroups` 表达功能整体拥有的效果，`ChipFeatureGroupDef.Subgroups` / `ChipFeatureGroupDeclaration.Subgroups` 表达具体组拥有的效果。子组不得继续声明子组或完整子功能。
- 所有效果语义均可使用这两种归属方式，不限攻击。归属遵循“最低完整所有者”：属于整个能力、攻击、护盾等功能的效果放功能级子组；只由某一攻击方式、防护规则或机动方式产生的效果放该信息组的子组。不得为了满足结构发明无实际含义的中间父组。
- 远程攻击与近战攻击是不同的玩家语义，必须使用各自的功能实例和合适的语义组；同一芯片可以同时声明两者。共享一个额外效果子组 Def 只复用子组类型，不会把两个功能实例的数据合并。
- 第三方可以通过 XML Patch 向 `ChipFeatureDef.Subgroups` 或具体 `ChipFeatureGroupDef.Subgroups` 追加允许子组，也可以定义新的信息组并加入功能语义的允许清单；全新取值路线仍通过自定义来源 Worker 接入。

本次规则覆盖本记录更早部分所有把“额外效果”画成根功能同级信息组的示意树。前文使用“额外效果信息组”时，描述的是效果类别，不再表示 XML 中与功能根部 `Groups` 并列的层级。功能级效果写入功能声明的 `Subgroups`，组级效果写入对应组声明的 `Subgroups`；两者都保持嵌套子组身份。具体结构由本记录第二十九节与最终开发者指南统一收口。

### 26.5 实施边界

- 不建立通用字典、任意对象图、无限递归或通用公式语言。
- 不把已经确认的攻击方式、防护规则和机动方式继续塞进 `ChipFeatureDeclaration.Children`。
- 保留真正子功能语义的有限树能力和现有最大深度保护；第二十七节已经确认，美特拉与战斧的爆炸属于攻击本体，卵之冠的部位裂解属于额外效果，现有这些 `Children` 均不再保留。
- 结构化信息组属于 Core 中性基础设施；具体 BDP 业务组 Def、来源 Worker 和展示选择分别放在 Content。
- 两个工作台读取相同的上下文、功能、信息组、子功能和组合结果模型；界面只负责决定如何显示，不重新解释技术实现。

## 二十七、攻击增强语义存在性复审

### 27.1 最终决定

- 删除 `BDP_Feature_AttackModifier`（攻击增强）功能语义，不再为它维护目标、触发、伤害、状态或护盾绕过等固定属性清单。
- “攻击增强”只是在描述某项攻击与其它结果之间的关系，不是一项稳定、独立、可直接使用的玩家功能。
- 已经附着到实际攻击的次要结果进入该攻击的“额外效果”信息组；属于攻击基本伤害方式的数据直接回归攻击本体。
- 尚未找到宿主攻击的被动增强来源只显示“可提供的额外效果”关系；形成有效装配后，效果并入实际受影响的攻击，不重新建立一个改名后的攻击增强语义。

### 27.2 判断规则

不能因为实现上存在投射物模块、Hediff、额外命中阶段或组合来源就统一归为额外效果。归属按最终玩家结果判断：

1. 如果某项数据直接定义本次攻击怎样造成主要伤害，它属于攻击本体；
2. 如果攻击本体之外又产生第二项依附结果，它属于额外效果；
3. 如果一项来源必须依附其它攻击才会生效，它在来源预览中属于效果贡献关系，在最终结果中归入宿主攻击的额外效果；
4. 如果来源只参与产生一个独立组合技，它属于组合关系，不是攻击效果。

#### 27.2.1 声明与取值边界

本节必须严格区分“语义允许提供什么”与“某个现有实例现在是什么数值”：

- `ChipFeatureDef` 及其属性槽位只定义该语义能够接收哪些信息，不保存美特拉、战斧、卵之冠或其它具体实例的数值；
- 芯片或组合的 `Features` 只声明功能语义、稳定实例身份和权威来源，不得为了面板展示再手填一份伤害、射程、速度、严重度等数值副本；
- 具体数值只能由来源 Worker 从最终有效的原版 Def、表达结果、组合结果或模块配置中读取；涉及覆盖、抑制和组合裁定时，必须读取裁定后的有效结果，不能只读某个上游原始字段；
- 如果当前来源 Worker 还不能可靠求出裁定后的最终值，就暂不提供该属性并输出诊断，不能由开发者在语义声明中凭推论补一个常量；
- 下文出现的具体数值只是本次复审读取现有权威定义所得的“核验快照”，用于判断归属和验证将来的 Worker，绝不是待复制进 `Features` 的声明模板。

典型区别：

```text
爆炸攻击本体
├─ 单发伤害
├─ 伤害类型：爆炸
└─ 效果半径
```

```text
普通攻击
├─ 单发伤害
└─ 额外效果：命中后另行爆炸
   ├─ 爆炸伤害
   ├─ 爆炸伤害类型
   └─ 爆炸半径
```

### 27.3 美特拉

- 当前错误结构：远程攻击下嵌套一项“攻击增强”范围效果。
- 实际实现核验：`BDP_Projectile_Explosive` 本身使用 `Bomb` 伤害类型、`13` 点基础伤害和 `2.9` 格爆炸半径；爆炸就是投射物的主要伤害方式，不存在先造成另一份直接伤害再追加爆炸的第二结果。
- 目标结构：删除 `meteora_area_effect` 子功能，将伤害、伤害类型、穿透、效果半径、投射物速度和停止力全部留在美特拉远程攻击本体。

以下仅为从现有投射物 Def 读取的核验快照，不写入美特拉的功能语义声明：

```text
远程攻击：美特拉
├─ 单发伤害：13
├─ 伤害类型：爆炸
├─ 护甲穿透：10%
├─ 效果半径：2.9 格
├─ 投射物速度：120
└─ 停止力：2
```

### 27.4 战斧

- 当前错误结构：组合远程攻击下嵌套一项“攻击增强”范围效果。
- 实际实现核验：`BDP_Projectile_Variable_Explosive` 本身使用 `Bomb` 伤害类型、`8` 点基础伤害和 `2.9` 格爆炸半径；爆炸同样是组合攻击本体。
- 目标结构：删除 `tomahawk_area_effect` 子功能；战斧 `ComboDef.Features` 只保留一项远程攻击，组合最终投射物的有效值全部归入该攻击。

以下仅为从现有组合最终投射物 Def 读取的核验快照，不写入战斧的功能语义声明：

```text
组合结果：战斧
└─ 远程攻击
   ├─ 单发伤害：8
   ├─ 伤害类型：爆炸
   ├─ 护甲穿透：5%
   ├─ 效果半径：2.9 格
   ├─ 投射物速度：140
   └─ 停止力：1
```

毒蛇提供的路线引导仍按远程攻击已确认的“飞行特征”表达，不因组合来源而归入额外效果。

### 27.5 卵之冠

- 当前错误结构：远程攻击下嵌套一项“攻击增强”子功能。
- 原始定义事实：`BDP_Projectile_BodyCollapse` 的投射物 Def 写有 `1` 点 Bullet 基础伤害。
- 执行链事实：部位裂解模块向命中计划贡献 `DamageDisposition.SuppressAllProjectileImpact`；命中阶段合并后，`BdpProjectile` 会跳过本次投射物的基础直接伤害、模块额外伤害与范围伤害。因此当前这条执行路线不会实际结算那 `1` 点伤害。
- `0` 的来源说明：它不是 XML 中已有的“最终伤害”字段，而是我根据上述执行链得出的结果表达。这个推导可以用于核验语义读取是否正确，但绝对不能作为常量手填进卵之冠的 `Features` 声明。
- 攻击本体负责射程、准备、行动冷却、精度、飞行速度、追踪和目标等远程行为；命中部位叠加裂解标记属于依附在本次攻击上的额外效果。
- 当前额外效果核验事实：只处理直接命中的 Pawn；按实际命中部位独立叠加；每次严重度增加 `0.2`；不按时间消失；达到最大严重度后移除该部位；尝试绕过原版投射物拦截器和 BDP 已注册伤害护盾。这些同样只能由权威模块配置读取，不能复制进功能声明。
- 后续信息 Worker 只有在能够解析最终有效模块及伤害处置时，才可以把“本次直接伤害结果为零”投影成单发伤害 `0`；若现阶段还没有这条可靠投影，就应暂不提供单发伤害并报告来源能力缺口。无论哪种情况，都不得直接读取并展示已被执行链抑制的基础伤害 `1`。

```text
卵之冠的声明结构
└─ 远程攻击
   └─ 功能级子组：额外效果（部位裂解标记）

来源 Worker 的职责
├─ 远程攻击属性 ← 最终有效 Verb / 投射物 / 命中计划
└─ 部位裂解属性 ← 最终有效模块配置
```

护盾与拦截器绕过是否以图标、短标签或展开参数显示，由消费面板决定；底层信息不得因为暂时不显示而丢失真实效果事实。

### 27.6 旋空

- 当前错误结构：旋空单独声明攻击增强。
- 实际行为：旋空只发布被动身份，作为“旋空弧月”的组合来源；单独启用不会生成攻击，也不会修改另一项现有攻击。
- 目标结构：删除 `senku_attack_modifier`；旋空本体不声明独立功能语义，只通过 `ComboDef` 反向显示“可参与旋空弧月”的组合关系。
- 旋空弧月组合继续声明最终近战攻击，使用消耗、最低要求和攻击结果均归组合结果，不回填为旋空自身的额外效果。

### 27.7 铅弹与铅弹·改

- 当前错误结构：两枚来源芯片各自在根部声明一项攻击增强。
- 实际行为：它们不生成可独立使用的攻击，而是通过 `RangedModuleAugmentations` 向符合条件的有效远程攻击追加铅块负重弹与模块。
- 单独预览时显示“可提供的额外效果”关系，不把尚未匹配宿主的结果伪装成芯片自身的远程攻击或顶层额外效果语义。

```text
铅弹·改
└─ 可提供的额外效果：铅块负重弹
   ├─ 作用对象：有效远程攻击
   ├─ 作用侧：主侧与副侧
   └─ 来源构型限制：左轮手枪
```

```text
铅弹
└─ 可提供的额外效果：铅块负重弹
   ├─ 作用对象：有效远程攻击
   └─ 作用侧：来源芯片的另一侧
```

形成有效装配结果后，贡献并入每项实际受到影响的远程攻击：

```text
最终远程攻击
└─ 额外效果：铅块负重弹
   ├─ 施加状态：由最终有效模块配置读取
   ├─ 每次叠加：由最终有效模块配置读取
   ├─ 投射物速度倍率：由最终有效模块配置读取
   └─ 爆炸投射物对每个目标的叠加倍率：由最终有效模块配置读取
```

- 铅弹模块对宿主攻击的伤害抑制必须反映在宿主远程攻击的最终伤害读取中，不在“额外效果”组里另行声明一项手填的“直接伤害 `0`”。
- 绕过已知投射物拦截器与 BDP 伤害护盾是该额外效果的真实规则，不提升为所有远程攻击的公共根属性。
- 灰黑命中反馈、拖尾颜色和内芯宽度等纯视觉配置不进入功能信息。
- “铅弹·改只作用于左轮手枪”“铅弹只作用于另一侧”等属于效果贡献关系的适用范围；最终已经附着后，面板可以不在每项攻击中重复来源筛选规则。

### 27.8 目标信息结构

删除攻击增强后，相关信息只存在于三个明确位置：

```text
攻击本体
└─ 直接决定主要攻击结果的属性

攻击功能整体或具体攻击方式信息组
└─ 额外效果子组（可重复；按实际所有者选择功能级或组级）

尚未附着的来源芯片
└─ 可提供的额外效果关系
```

- “可提供的额外效果”属于关系信息，不新增 `ChipFeatureDef`，也不和最终已附着效果混为同一层。
- 额外效果子组允许不同效果拥有不同属性集合；不建立要求爆炸、状态、推动、移除部位等所有效果共享同一套字段的万能结构。
- 公共时间、伤害、状态强度、效果半径等属性可以按需被具体效果信息组复用；场景化名称由面板负责。
- 第三方模组可以用 XML 定义新的子组类型，或通过 XML Patch 将它追加到现有功能 Def / 信息组 Def 的 `Subgroups` 允许列表；再由来源 Worker 提供真实值。

### 27.9 后续实施差距与验收

- 删除 `BDP_Feature_AttackModifier` Def、语言项和其旧属性槽位清单。
- 删除美特拉、卵之冠、战斧现有攻击增强子功能声明；按 27.3 至 27.5 将信息回归攻击本体或额外效果信息组。
- 删除旋空、铅弹和铅弹·改的根部攻击增强声明；分别改由组合关系或可提供效果关系表达。
- 组合和装配的最终信息解析必须根据实际有效表达结果把效果贡献附着到正确攻击，不能只把两侧原始声明并排显示。
- 来源预览、最终攻击和运行时执行读取同一份业务声明；信息系统不得再维护一套会与模块配置漂移的独立数值副本。
- `Features` 声明中不得出现为复刻当前面板结果而手填的伤害、速度、半径、严重度或其它实例数值；核验快照只能用于测试 Worker 是否正确读取权威来源。
- 验证美特拉和战斧只显示一项远程攻击，爆炸伤害与半径仍完整可读；不得显示重复的“爆炸额外效果”。
- 验证卵之冠不显示被实际抑制的 `1` 点伤害，并能提供部位裂解的关键额外效果事实；只有最终伤害 Worker 已实现可靠的伤害处置解析时才输出 `0`，否则缺值并诊断。
- 验证旋空单独没有虚构功能，旋空弧月仍显示完整近战攻击。
- 验证铅弹系列单独显示可贡献关系，装配后受影响远程攻击获得铅块负重额外效果，未受影响攻击不得错误继承。
- 信息重构不得改变爆炸伤害、部位标记叠加、部位移除、铅弹注入、护盾绕过、组合匹配或任何攻击执行行为。

## 二十八、隐蔽退役与泛用能力语义重审

### 28.1 存在性决定

- 删除 `BDP_Feature_Stealth`（隐蔽）功能语义。
- 新增 `BDP_Feature_GenericAbility`（泛用能力）功能语义，中文显示名称为“能力”。
- “技能”不作为标准名称，因为 RimWorld 中通常指射击、建造、医疗等角色技能；“能力”更符合玩家对独立能力按钮与特殊功能的认知。
- 技术标识使用 `GenericAbility` 而不是直接使用 `Ability`，用于提醒开发者：该语义不是 RimWorld `AbilityDef` 技术类型的自动映射。
- 泛用能力有两项职责：一是表达当前没有稳定专属信息、不值得建立独立业务语义的玩家能力；二是作为具有独立玩家释放生命周期的父语义，承载冷却、充能、整次释放消耗等信息，并包含零个、一个或多个完整结果子语义。
- 将来某类能力出现稳定专属参数、专属可视化或多个同类实现时，可以提升为独立功能语义，不要求泛用能力永久吞并所有新内容。

变色龙当前只有一个现有隐蔽实例。它由 Ability 负责释放、Hediff 负责状态持续、原版隐身组件负责心理不可见与目标缓存行为、BDP 适配负责攻击后移除状态。这些都是实现路线；玩家层可以用一项泛用能力、公共属性和简介完整表达，没有继续维护隐蔽专属属性目录的必要。

### 28.2 显式声明与技术路线边界

- 泛用能力仍必须由芯片或组合在 `Features` 中显式声明，不能因为发现 Ability、Hediff、Verb、Comp 或其它技术结构就自动分类为能力。
- 同一能力可以同时引用多个权威来源，例如变色龙同时引用 Ability 入口和 Hediff 状态；来源列表共同提供一个玩家功能，不代表两个功能。
- `ChipFeatureDef` 只声明能力可以接收哪些公共属性；芯片的 `Features` 只声明语义、稳定身份和来源，不保存实例伤害、距离、时间、消耗或其它数值副本。
- 具体值由来源 Worker 从最终有效 AbilityDef、VerbProperties、Hediff 组件、表达配置、组合结果或业务配置读取；不能可靠求出最终值时缺值并诊断，禁止手填常量补面板。
- 语义提供属性不等于所有面板必须展示；制造台、触发器装配台和未来消费者分别决定显隐、排序、场景化名称、图标与图表。

### 28.3 子功能嵌套是全局能力

`Children` 是所有功能语义共用的中性结构，不是泛用能力专属机制。泛用能力只是高频父级场景，因为一次玩家可感知的释放可能具有自己的生命周期，并产生一个或多个完整功能结果。

全局判断规则：

1. 根功能表示玩家主要使用或获得的功能，或一个具有独立玩家意义的释放外壳；
2. 子功能必须是可以完整、独立理解的玩家功能，例如远程攻击、近战攻击、机动或护盾；
3. 信息组表示同一功能内部需要保持关联的一组参数，例如攻击方式、防护规则、机动方式和额外效果；
4. 依附主功能、不能独立成立的次要结果进入额外效果，不滥用子功能；
5. 不值得结构化的个体规则由本地化简介承担；
6. 是否保留“能力”父级，不按子功能数量判断；零个、一个或多个子功能都可以合法存在；
7. 只有当技术上的 Ability 入口没有独立玩家生命周期，且所有有意义信息都能由一个具体结果完整解释时，才省略能力层；
8. `AbilityDef`、`Verb`、`Hediff`、`Comp` 等实现类型既不强制产生某项语义，也不能阻止开发者显式声明符合玩家认知的语义。

```text
技术 Ability 只是内部转接，没有独立冷却、充能或使用消耗
└─ 直接声明：远程攻击

只有一个机动结果，但释放本身有独立冷却或消耗
└─ 能力
   └─ 子功能：机动

一次释放共同产生冲刺与斩击
└─ 能力
   ├─ 子功能：机动
   └─ 子功能：近战攻击
```

属性所有权遵循“最低完整所有者”原则：

- 能力再次可用计时、能力充能和整次释放消耗属于能力自己的生命周期，放在父级；
- 某个子功能独有的距离、目标、视线、准备、行动冷却、伤害、防护规则或持续时间，放在该子语义；
- 同一目标、准备或范围确实共同控制多个子功能时，提升到共同父级，只提供一次；
- 父子不得复制同一事实；消费面板可以把父子信息排在同一张卡片中，但不得以界面方便为由污染数据所有权。

这里的“机动”统一指 `BDP_Feature_Movement` 玩家功能语义；“移动”只用于普通中文叙述或 RimWorld 原版移动属性，不是另一项功能语义。

### 28.4 泛用能力确认接收的公共属性

泛用能力不新增任何专属属性，只接收以下十四项已经确认的公共属性：

```text
能力
├─ 目标类型（可选）
├─ 有效距离（可选）
├─ 最小距离（可选）
├─ 效果半径（可选）
├─ 最大目标数（可选）
├─ 需要视线（可选）
├─ 准备时间（可选）
├─ 行动冷却时间（可选）
├─ 能力冷却计时（可选）
├─ 持续时间（可选）
├─ 充能上限（可选）
├─ 充能恢复时间（可选）
├─ 单次使用消耗（可选；单位为 Trion）
├─ 持续消耗（可选；单位为 Trion/秒）
└─ 子功能（可重复；只用于完整玩家功能）
```

能力自身的次要效果也必须作为嵌套子组：整体由能力释放产生的效果进入功能级 `Subgroups`，只由某个具体结果或信息组产生的效果进入该子功能或信息组的 `Subgroups`。不得为此添加没有独立含义的父组。

逐项边界：

- 目标类型：自身、角色、地点、物体或区域等玩家选择对象；没有目标选择的能力不提供。
- 有效距离：有限的数值型最大选择距离；自身能力不提供 `0`。
- 最小距离：只有确有近距离禁用区时提供。
- 效果半径：目标点周围实际受到作用的范围，不与有效距离合并。
- 最大目标数：只有存在明确硬上限时提供；“范围内全部目标”不伪造成固定数字。
- 需要视线：只对存在目标选择的能力提供；无目标选择不等于“不需要视线”。
- 准备时间：能力开始使用到正式生效前的等待；没有准备过程时不提供。
- 行动冷却时间：动作完成后角色恢复行动所需时间，不表示能力再次可用。
- 能力冷却计时：同一能力再次可用前的完整冷却；运行时剩余冷却属于动态值。
- 持续时间：能力整体效果的固定有效时长；瞬时、永久或由开关和环境决定的效果不伪造 `0` 或无限。
- 充能上限：能力自己的离散储备次数；当前剩余充能属于运行时值。
- 充能恢复时间：恢复一次离散充能所需时间，不与能力冷却计时混用。
- 单次使用消耗：每次正式释放能力消耗的 Trion，不混入芯片装备、激活或维持费用。
- 持续消耗：效果维持期间每秒消耗的 Trion，不与一次性费用合并。

上述属性是能力语义允许接收的公共信息，不表示遇到能力就全部放在根部。具体所有权按 28.3 的“最低完整所有者”规则决定；额外效果只承载依附能力的次要结果，不能替代完整子功能。

### 28.5 公共属性目录减法

本轮确认全局删除以下公共属性或早期提案：

| 删除项 | 技术身份或状态 | 删除原因 |
|---|---|---|
| 使用方式 | `BDP_Property_UsageMode` | 当前 Worker 直接输出 EntryType，泄漏 Ability、Hediff、Verb、Passive 等技术类型，不能表达玩家真实交互。 |
| 触发条件 | `BDP_Property_TriggerCondition` | 值域过宽且没有真实来源与消费；具体触发由简介、子语义或额外效果说明。 |
| 触发概率 | `BDP_Property_UsageChance` | 概率必须归属具体触发结果，孤立挂在功能根部没有稳定含义。 |
| 结束条件 | `BDP_Property_EndCondition` | 固定时长已有持续时间，其它结束规则差异过大且仍需简介。 |
| 移动距离 | `BDP_Property_MovementDistance` | 实际位移受落点、碰撞和路径影响，是执行结果，不是静态设计属性。 |
| 作用范围 | 尚未实施的早期提案 | 只有全图、跨地图两个假想文本值，当前没有使用者或结构化消费。 |
| 作用角度 | `BDP_Property_EffectAngle` | 当前完全无人使用；具体角度应归真正拥有角度语义的功能。 |
| 作用间隔 | `BDP_Property_IntervalDuration` | 当前完全无人使用；周期应归攻击、恢复或具体额外效果。 |
| 路径限制 | `BDP_Property_PathConstraints` | 自由文本不能可靠解析、比较或可视化，复杂路径由简介和游戏内预览承担。 |
| Trion 消耗 | `BDP_Property_TrionCost` | 与单次使用消耗、持续消耗重复；BDP 不建立通用资源身份目录。 |
| 生成对象 | `BDP_Property_SpawnThing` | 当前完全无人使用，为假想召唤能力提前设计。 |
| 生成数量 | `BDP_Property_SpawnCount` | 当前完全无人使用，且必须依附具体生成结果。 |
| 旧冷却时间 | `BDP_Property_CooldownDuration` | 同时混入原版行动冷却与 Ability 再次可用计时，拆为两个含义明确的属性。 |

实施时同步删除上述 Def、语言项、功能属性槽位、Worker 自动贡献、测试断言和展示器旧引用。删除信息定义不得改变任何实际攻击、能力、状态、移动、冷却、消耗或组合执行行为。

### 28.6 保留但不进入能力根部的公共属性

以下属性仍有其它已确认所有者，不因泛用能力不接收而全局删除：

- 恢复延迟：由护盾等具有可恢复容量的具体语义使用；
- 施加状态：只能进入具体额外效果或其它明确结果结构，显示玩家名称而不是 Hediff DefName；
- 状态强度：跟随实际状态效果，不平铺到能力根部；
- 叠加上限：跟随实际可叠加效果，不平铺到能力根部。

### 28.7 技术身份收窄

不保留向后兼容，实施时直接使用含义明确的新身份：

- `BDP_Property_MaxUses`（最大次数）改为 `BDP_Property_ChargeCapacity`（充能上限）；
- `BDP_Property_RechargeDuration`（充能时间）改为 `BDP_Property_ChargeRecoveryDuration`（充能恢复时间）；
- `BDP_Property_CooldownDuration`（旧冷却时间）拆为 `BDP_Property_ActionCooldownDuration`（行动冷却时间）与 `BDP_Property_AbilityCooldownDuration`（能力冷却计时）。

单次使用消耗继续使用 `BDP_Property_UseCost`；持续消耗继续使用 `BDP_Property_SustainCost`。两者在 BDP 标准内容中的资源单位固定为 Trion，扩展模组使用其它资源时自行声明扩展属性。

### 28.8 变色龙目标结构

变色龙不再声明隐蔽语义，也不因为底层存在两个表达条目而拆成两个功能：

```text
能力：变色龙
├─ 准备时间
├─ 能力冷却计时
├─ 持续时间
├─ 持续消耗
└─ 本地化简介：说明隐身、攻击后解除等具体表现
```

上图只表示允许输出的信息结构，不包含任何手填实例数值。实际值分别从最终有效 Ability、Hediff 自动消失组件、表达 Trion 配置和其它权威业务配置读取。

变色龙当前没有能够稳定归入现有标准语义的完整结果，因此不需要子功能。其它能力只要产生机动、攻击、护盾等完整结果，即使只有一项，也按 28.3 声明相应子语义；不是必须等到出现多个结果才允许嵌套。

### 28.9 当前实现差距与后续验收

- 当前 `BDP_Feature_Stealth` Def、语言项和变色龙声明尚未删除或迁移。
- 当前尚无 `BDP_Feature_GenericAbility` Def。
- 当前通用表达来源 Worker 会把 EntryType 自动写成使用方式，实施时必须删除该技术泄漏。
- 当前 Ability 来源 Worker 把 AbilityDef 冷却与 Verb 行动冷却合并到旧 `CooldownDuration`，必须按真实所有权拆分。
- 当前 Ability 来源只能读取 AbilityDef 自身的基础效果时长，不能得到由 Hediff 自动消失组件承载的变色龙持续时间。
- 当前 Hediff 来源只提供 Hediff 技术身份，不读取固定持续时间，也不能直接提供玩家功能行为。
- 当前来源尚不能完整提供目标类型、需要视线、充能、单次使用消耗、持续消耗及复合子功能所有权。
- 验证变色龙最终只显示一项“能力”，不显示 Ability/Hediff 技术分类，也不显示重复的两个功能。
- 验证变色龙公共信息全部来自最终有效来源，`Features` 中没有为面板复制的实例数值。
- 验证风刃远程斩击保留“能力”父级并包含“远程攻击”子功能；能力冷却与整次释放消耗不下沉到远程攻击。
- 验证蚱蜢与光魂推进使用“能力 → 机动”，弹射砍击使用“能力 → 机动 + 近战攻击”；浮空与紧急脱离没有独立能力释放生命周期，继续直接声明机动。
- 验证技术 Ability 仅作内部转接且没有独立玩家生命周期时，可以直接声明具体结果语义，不产生空壳能力层。
- 验证删除公共属性后，所有保留 FeatureDef、Worker、展示器与测试不再引用旧身份。
- 验证信息重构不改变变色龙释放、持续、攻击后解除、冷却、Trion 消耗、目标缓存刷新或任何其它游戏行为。

## 二十九、标准功能结构树总览

本节只确定信息结构和所有权，不指定面板必须如何排版，也不把示例值写入 `Features`。结构树中的“信息组”不是功能子节点，不占用 `Children` 深度。

### 29.1 结构判定总树

新增或复审一项内容时，按玩家实际获得的功能逐层判断，不从实现类名开始：

```text
待表达内容
├─ 只是 AbilityDef、Verb、Hediff、Comp 等实现事实？
│  └─ 是：不形成玩家语义
├─ 具有独立的玩家主动释放生命周期？
│  └─ 是：声明“能力”
│     ├─ 没有稳定标准结果语义：能力自身 + 公共信息 + 简介
│     ├─ 一个完整结果：能力 → 一个子功能
│     └─ 多个完整结果：能力 → 多个并列子功能
├─ 没有独立能力外壳，但直接提供完整玩家功能？
│  └─ 是：直接声明远程攻击、近战攻击、护盾、机动或扩展语义
├─ 只是同一功能中的多套关联参数？
│  └─ 是：可重复信息组
├─ 只是依附主功能的次要结果？
│  └─ 是：额外效果子组，挂在最低完整所有者（功能整体或具体信息组）下面
└─ 只是个体规则且没有结构化消费需求？
   └─ 是：本地化简介
```

这里的“独立玩家主动释放生命周期”表示能力层本身拥有区别于具体结果的玩家意义，例如独立命令身份、能力冷却、能力充能、整次释放消耗、持续开关状态或多个结果共享的目标与准备。任何单个技术字段都不是自动判据；不能仅凭存在一个 `AbilityDef` 就判定。已知结果只有一个时，能力父级必须至少增加一项独立意义，否则就是应当扁平化的空壳；暂时没有可归类子语义的变色龙等个体能力，则由能力本身承担完整玩家功能，不受这条“空壳父级”限制。

### 29.2 单一直接功能

适用于普通武器攻击、常驻护盾、被动机动等不存在独立能力释放生命周期的内容：

```text
芯片或当前形态
└─ 远程攻击
   ├─ 根部攻击参数
   └─ 功能级子组：额外效果（适用于整个远程攻击时）
```

同一芯片可以同时具备远程与近战；它们是两个独立功能分支，不共用一个含混的“攻击方式”组：

```text
芯片
├─ 远程攻击
│  └─ 功能级子组：额外效果（若效果由整个远程攻击产生）
└─ 近战攻击
   └─ 攻击方式信息组
      └─ 组级子组：额外效果（若效果只由该攻击方式产生）
```

```text
芯片或当前姿态
└─ 护盾
   ├─ 根部护盾信息
   ├─ 防护规则（可重复信息组；规则专属效果作为该组子组）
   └─ 功能级子组：额外效果（适用于整个护盾时）
```

```text
芯片或被动结果
└─ 机动
   └─ 机动方式（可重复信息组）
```

### 29.3 技术 Ability 不形成玩家能力层

底层虽然使用 `AbilityDef`，但它只是内部调用桥梁，没有独立冷却、充能、消耗或其它值得表达的玩家生命周期：

```text
芯片
└─ 远程攻击
```

不得因为扫描到 `AbilityDef` 自动改成“能力”；显式功能声明仍以玩家实际获得的功能为准。

### 29.4 单结果主动能力

适用于风刃远程斩击、蚱蜢和光魂推进这一类：释放本身具有独立生命周期，即使只有一个完整结果也保留能力层。

```text
能力：风刃远程斩击
├─ 能力冷却计时
├─ 整次释放消耗
└─ 远程攻击
   ├─ 目标、距离、视线与预热
   ├─ 行动冷却时间
   ├─ 伤害、穿透与四档精度
   ├─ 射击节奏与攻击次数
   ├─ 功能级子组：额外效果（整个远程攻击共同产生）
   └─ 投射物相关信息（仍属于攻击本体）
```

```text
能力：蚱蜢
├─ 能力冷却计时
├─ 整次或逐段释放消耗
└─ 机动
   └─ 机动方式：蚱蜢弹射
      ├─ 目标、有效距离与视线
      ├─ 准备时间
      └─ 机动自身的其它适用信息
```

上图只表示属性类别归属。实例值仍由最终有效定义和业务配置解析，不进入 `Features`。

### 29.5 多结果主动能力

多个结果共享一次释放时，它们在能力下并列：

```text
能力：弹射砍击
├─ 共同准备
├─ 能力冷却计时
├─ 整次或逐段释放消耗
├─ 机动
│  └─ 机动方式：弹射位移
│     └─ 目标、有效距离与视线
└─ 近战攻击
   └─ 攻击方式：沿途切割
      └─ 伤害、穿透、攻击次数与攻击间隔
```

机动与近战攻击彼此不是父子；它们只是共同依附同一次能力释放。

### 29.6 暂无标准子语义的个体能力

适用于变色龙等已经具有明确玩家能力身份，但具体效果暂不值得建立新业务语义的内容：

```text
能力：变色龙
├─ 能力公共信息
└─ 本地化简介：说明个体规则
```

若以后变色龙出现值得结构化展示的次要结果，若它属于整项能力则作为能力功能级子组；若属于新增的完整子功能或具体信息组，则归属于那个更具体的所有者。额外效果仍是嵌套子组，不与功能根部信息组并列。

不得为了填满结构把隐蔽、变色、解除条件等低复用概念提前做成新的通用语义。

### 29.7 信息组而非子功能

同一功能内部的多套关联参数进入可重复信息组：

```text
近战攻击
├─ 攻击方式：切割
│  ├─ 本方式参数
│  └─ 额外效果子组
└─ 攻击方式：钝击
   ├─ 本方式参数
   └─ 额外效果子组
```

```text
护盾
├─ 防护规则：远程攻击
│  └─ 角度、概率、吸收比例、消耗倍率
└─ 防护规则：近战攻击
   └─ 角度、概率、吸收比例、消耗倍率
```

攻击方式、防护规则和机动方式均不使用 `Children` 冒充功能树。若额外效果只由某个重复信息组实例产生，它挂在该组的 `Subgroups` 下；若效果由整个功能产生，则挂在功能声明自己的 `Subgroups` 下。两种情况都不是与功能根部 `Groups` 并列的效果组。

### 29.8 额外效果而非子功能

依附主功能、不能独立成立的次要结果进入额外效果子组；父级按效果的实际所有者选择，可以是整个功能，也可以是某个具体信息组：

```text
功能
├─ 功能级 Subgroups
│  └─ 额外效果子组（效果属于整个功能）
│     ├─ 击退
│     ├─ 施加状态
│     └─ 资源变化
└─ 信息组（例如攻击方式、防护规则、机动方式）
   └─ 信息组级 Subgroups
      └─ 额外效果子组（效果只属于该具体信息组）
```

远程、近战、护盾、机动、能力和后续扩展语义都可使用功能级子组；某些效果若只由其中一个重复信息组实例产生，则必须使用该组自己的子组。无需先为每个功能人为添加一个效果父组，也不预设远程与近战共享信息组 Def。

当某项结果已经具备完整、稳定、可独立消费的玩家功能语义时，才从额外效果升级为子功能。

### 29.9 形态与姿态上下文

形态和姿态决定当前哪棵功能树生效，本身不是功能子语义：

```text
芯片：光魂
├─ 大盾形态
│  ├─ 灵活姿态
│  │  └─ 护盾
│  └─ 举盾姿态
│     └─ 护盾
└─ 重刃形态
   └─ 近战攻击
```

不同上下文分别解析最终有效信息，不把多个姿态的值合并成一套虚假综合值。

### 29.10 组合来源与组合结果

来源芯片只提供组合关系；组合结果拥有自己独立的功能树：

```text
来源芯片：推进器
├─ 可参与组合：光魂推进
└─ 独立功能：无

组合结果：光魂推进
└─ 能力
   └─ 机动
```

组合结果的功能信息从组合有效表达与业务定义读取，不把两枚来源芯片的信息简单拼接。

### 29.11 真正的子功能继续嵌套

某项功能产生的对象又稳定提供另一项完整功能时，可以继续使用有限深度的子语义：

```text
能力
└─ 部署
   └─ 远程攻击
```

当前校验器最多允许根功能、子功能和孙级功能三层。超过这一深度时应先重新判断是否把技术对象关系误当成玩家功能关系，禁止建立无限递归对象图。

### 29.12 扩展模组新增实现或新增语义

扩展者采用不同技术路线实现已有功能时，仍声明相同玩家语义，并通过自定义来源 Worker 或显式来源配置提供权威值；整体效果可以加入功能 Def 的 `Subgroups`，专属于某种实现方式/信息组的效果则加入那个组的 `Subgroups`：

```text
第三方护盾实现
└─ 护盾
   └─ 防护规则
```

扩展者新增 BDP 未提供的新玩家功能时，可以新增自己的 `ChipFeatureDef`、属性槽位、信息组和可选子组，并将其声明为根功能或合法子功能：

```text
第三方能力
├─ 能力生命周期信息
└─ 第三方新功能语义
   └─ 第三方结构化信息
```

额外效果作为子组的归属位置也可由 XML 扩展：向 `ChipFeatureDef.Subgroups` 追加表示整个功能允许的子组，或向 `ChipFeatureGroupDef.Subgroups` 追加表示某个具体信息组允许的子组。第三方实现路线无需复用 BDP 的技术来源；只要声明相同玩家语义并提供权威来源，就能进入同一结构化结果。

标准面板对未知扩展至少显示本地化名称和通用信息；专用图表与专用排版由能够识别该扩展语义的消费端负责。
