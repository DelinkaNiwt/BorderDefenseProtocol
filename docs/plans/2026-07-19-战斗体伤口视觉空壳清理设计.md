# 战斗体伤口视觉空壳清理设计

## 目标

删除从未接入运行时的战斗体通用伤口视觉草案，避免它与已经闭环的 Trion 粒子喷溅链并存并造成误解。

## 删除范围

- `Source/BDP/Core/CombatBody/Wounds/Visuals/ICombatBodyWoundVisualProvider.cs`
- `Source/BDP/Core/CombatBody/Wounds/Visuals/CombatBodyWoundVisualContext.cs`
- `Source/BDP/Core/CombatBody/Wounds/Visuals/CombatBodyWoundVisualDecision.cs`
- `Source/BDP/Core/CombatBody/Wounds/Visuals/CombatBodyWoundVisualMode.cs`
- `Source/BDP.Tests/CombatBodyWoundVisualInterfaceSmokeTests.ps1`

前四个类型没有注册器、解析器、运行时调用点或 DevHarness 实现。最后一项静态测试只负责强制这些草案继续存在；删除草案后，该测试也失去测试对象，必须同步删除。

## 保留范围

- 保留 `CombatBodyWoundRuntime`，继续统一接收伤口变化。
- 保留 `CombatBodyWoundTrionBinding`，继续管理伤口 Trion 流失。
- 保留 `CombatBodyWoundSprayRuntime` 与 `CombatBodyWoundSprayEmitter`，继续管理粒子喷溅生命周期。
- 保留原版伤口流血率压制与伤口覆盖贴图压制补丁。
- 不修改 XML、程序集项目文件和 DevHarness。

## 实现方式

项目文件通过通配符收集 C# 源码，因此删除四个源码文件和一项失效测试后，不需要同步维护编译清单。删除后再次搜索四个类型名，任何残留引用都视为失败。

## 验证

1. 全仓搜索确认四个被删除类型没有残留引用。
2. 搜索确认喷溅、Trion 流失和原版伤口贴图压制入口仍存在。
3. 编译主模组，确认删除未破坏程序集。
4. 执行战斗体伤口相关静态烟雾测试。

## 成功标准

主模组不再暴露空置的通用伤口视觉接口；现有战斗体伤口玩法和喷溅运行链保持原样。
