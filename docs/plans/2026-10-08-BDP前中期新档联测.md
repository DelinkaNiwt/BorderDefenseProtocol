# BDP前中期新档联测

用户选择新档，从皇室入口任务完整走一遍。目标是验证已接通的内容在真实游戏中能连续使用，暂不评定数值平衡或补充后期内容。

代码基线：`51c78a42`。工作区Core、Content、Development三个程序集重新编译成功，核心程序集依赖隔离通过；首发定义、任务准入与中文加载、契约、核心生命周期、供物读档、制造装配许可六项检查通过。下文游戏操作均尚待实测，不能用离线检查代替。

## 1. 开始条件与入口

- 重启游戏，确认加载本次工作区版本及其前置：Harmony补丁框架、生物科技、皇权；使用RimWorld 1.6。本轮只在工作区编译，未复制文件到游戏目录。
- 新档使用地面殖民地，允许战斗任务，世界中有仍存在的敌对人类派系。开局不预置皇室成员；这些是现有任务准入条件。
- **正常首发**：当前配置在第8天派发“皇室求援”，收到后从任务面板接受。第8天只是当前可调配置，不作为长期平衡标准。到时若没有出现，先记录游戏天数、叙事者、任务列表和首条报错，区分未派发与已派发但不可接受。
- **重测入口**：开发者操作中打开“BDP：皇室加入任务测试 → 生成皇室求援任务”，再从普通任务面板接受。该入口复用正式任务并保留身份、同类任务、敌对派系与战斗任务准入；不直接招募、生成玩家腺体或替玩家缔约。用它可重测任务内容，但不算定时首发已通过。

## 2. 第一段：入口到首个腺体

这段先观察五个结果即可：

1. **接受与借住**：任务名称、说明和相关信件为中文。皇室人物先以临时借住身份抵达，能安排工作和战斗；此时不能使用皇室契约。
2. **追兵抵达**：间隔以当前任务说明为准；首次在地图出现时已经是真正战斗体，直接装备近界原型触发体。非玩家派系不展示供玩家操作的攻击按钮或Trion资源读数。
3. **两阶段战斗**：战斗体崩解后任务不立即成功，追兵恢复原身并继续进攻；击败任务这一组追兵后任务成功，皇室才正式加入。战斗处理方式由玩家自行选择。
4. **入门物品**：确认皇室库存有Trion驱动核心；检查追兵原型的实际去向，验证玩家能正常取得战利品。战斗可能造成物品损失时记录实际原因，不把看不到物品直接等同于未生成。
5. **主动缔约**：正式加入后，由皇室主动选择另一名合格殖民者使用“缔结皇室契约”；人物走近后完成，目标获得有效腺体，双方各有对应契约记录。后天新获腺体从零积累，不把初始零能量误判为失败。

建议在接受任务后、追兵抵达前存一份档，便于复现人物身份、追兵抵达和任务结束时点。若出现错误，保留首条完整报错及这一份存档，不只记录重复堆栈。

## 3. 后续五段

| 段落 | 正常操作 | 要看到的连接结果 |
|---|---|---|
| 首次使用 | 让新获腺体的成员实际睡眠积累Trion，装备取得的原型，启动战斗体并试用两项武装；退出后再次睡眠恢复 | 无运行核心也能恢复并反复试用；主槽弧月、副槽小行星保持固定预载，原型没有换配面板 |
| 研究与核心 | 将驱动核心放到可分析的位置，由普通合格殖民者沿原版分析；完成基础理论等所需研究，使用该实物建造中继核心；皇室前往绑定，从“献祭补充”准备供物 | 分析保留实物并开放研究；建造消耗核心材料而不撤销分析资格。普通搬运者可协助，“供物”页显示进度，备齐后所选皇室或契约者完成献祭并启动核心 |
| 自主生产 | 按所需研究，在机械加工台制造便携检测器和原型；在BDP制造台制造普通触发体、芯片；芯片入仓后装配到正式触发体 | 成品可以正常制造和使用；制造台、装配台受核心许可控制。储量仍有余时暂时解绑，检查停运，再重新绑定确认可继续；便携检测器与原版工作台保持自身规则 |
| 人员扩充 | 原版异种遗传学完成后，提取含腺体的基因组，存入连接的基因库，制作胚芽并植入另一名成员 | 可以重复制作；植入者获得有效腺体并恢复、装备。随机提取未抽到腺体是原版结果；普通扩充不复制皇室、契约或核心权限 |
| 中期支援 | 建造控制台，指派普通同派系人员值守，用猎犬比较值守与离岗状态；研究联动后制作紧急脱离芯片，装入特殊槽并检查就绪，在被动崩解时观察脱离 | 控制台停运后恢复原有目标条件；脱离后来源芯片被消费，可重新制造补装。信标是同地图可选优先落点，主动解除战斗体不触发脱离 |

这张表是联测顺序，研究、生产和人员筹备可以交错进行。具体研究条件以当前游戏研究树为准；不要求为联测填写整棵树或评定每项强度。

核心供物搬运中途建议再存读一次，观察已搬实物、待搬清单、选定献祭者和绑定储量是否保留。皇室昏迷、外出、基因失效等专项边界保留为后续复测，不挤进第一段。

## 4. 反馈与完成判断

第一轮先反馈第2节的五个结果：任务中文、借住权限、追兵初始状态、正式加入时点、物品及契约是否正确。任何异常说明“停在哪一步、实际看到什么”，有报错时附首条完整堆栈。

所有段落均完成正常操作并核对存读档，才记为前中期整条路线联测通过；当前只完成工作区准备。测试中确认的问题再按具体时序修根因，必要诊断放Development，不预先增加逐刻扫描、全局日志或新的测试业务。
