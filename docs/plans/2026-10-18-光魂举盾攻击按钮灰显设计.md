# 光魂举盾时灰显被禁止的 BDP 攻击按钮

Status: Approved
日期：2026-10-18。目标版本：RimWorld 1.6、1.7。
方案已由用户确认：由 Core 通用按钮生成器读取既有攻击准入结果。

## 现况

BDP 手动攻击按钮由 Core 的 `DefaultManualEntryGizmoResolver.BuildCommand` 生成，并绑定 `AttackExecutionTargetingSource`。该 targeting source 的 `GetVerb` 可以解析实际宿主 Verb。按钮生成器现在检查原版“禁止暴力”状态和 Combo 使用条件，但没有查询 Core 已有的 `AttackAdmissionAccess`。

光魂内容规则 `LightSoulGuardAttackAdmissionRule` 已向 `AttackAdmissionAccess` 注册，并为举盾时被禁止的远程攻击返回既有拒绝原因。其他内容规则也使用同一个准入注册表，例如 Trion 停机攻击限制。攻击执行入口会检查准入结果，因此实际攻击会被拒绝；手动按钮生成时未读取这项结果，按钮仍可能看起来可用。

原版 `VerbTracker.CreateVerbTargetCommand` 只影响原版装备 Verb 命令，而 BDP 使用自己的 `Command_BdpManualEntryTarget`。给原版命令工厂加补丁不会改变这条 BDP 按钮生成路径。

## 目标行为

- 保持“禁止暴力”优先级最高，继续显示原版原因。
- 否则查询实际宿主 Verb 的通用攻击准入；若已有规则拒绝，则禁用对应 BDP 手动攻击按钮并显示该规则提供的原因。
- 准入通过后再检查 Combo 使用条件，保持当前行为。
- 不新增光魂专用按钮逻辑、不增加语言键、不改攻击准入规则，也不改原版按钮。
- Core 只消费中性的准入接口，不知道光魂或 Trion 等业务；Content 继续负责注册各自规则。

## 方案

在 `DefaultManualEntryGizmoResolver.BuildCommand` 的按钮禁用判断中，把 `AttackAdmissionAccess.Evaluate(pawn, targetingSource.GetVerb)` 放在原版“禁止暴力”检查之后、Combo 条件之前。准入拒绝时调用现有 `Command_BdpManualEntryTarget.DisableForUseRequirements`，传入 `AcceptanceReport.Reason`。这只投影已经存在的攻击限制到对应按钮，业务规则仍由原有注册项决定。

因此举盾时，光魂规则会让相应的 BDP 远程攻击按钮灰显；同一 Core 通用入口也会让其他现有准入规则拒绝的 BDP 攻击按钮灰显，这是已确认的中性共同行为。1.6 与 1.7 共用该源码。

## 验证

分别针对 RimWorld 1.6、1.7 构建 Core 与 Content，运行现有 `ViolenceDisabledAttackGateSmokeTests.ps1` 和 `ComboUseRequirementRuntimeSmokeTests.ps1`，并运行 `git diff --check`。构建和源码烟测不能代替游戏内 UI 验收；没有实际启动两个版本时，需明确标记为未实测。
