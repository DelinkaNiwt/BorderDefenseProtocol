# 黑触发器形成、适配与世界唯一基础设施设计

## 文档状态

- 日期：2026-09-16
- 状态：基础设施主体已确认；形成选择与生命印记展示部分已由 2026-09-19 重设计取代
- 适用模组：新 BDP 主模组
- 依赖边界：允许依赖 Royalty（皇权）与 Biotech（生物科技）
- 暂缓内容：风刃、卵之冠的具体倾向与形成路线，特殊敌方持有者及其 AI

> 当前权威说明：本文关于“倾向、最终意志、候选物品直接选择、制造者印记展示”的旧设计不再执行。形成选择、生命经历证据、功能分类、稳定暗选、成品生命印记和开发者诊断，以 `2026-09-19-黑触发器定形方向与生命证据重设计.md` 为准。世界唯一、形成事务、尸体销毁、主动倾注生命、适配绑定等未被替代的章节继续有效。

## 一、目标

在 RimWorld 原版机制能够承载的范围内，引入具有以下特征的黑触发器系统：

1. 玩家殖民者在死亡时，可能以自身生命和意志形成黑触发器。
2. 真正处于个人濒死危机的成年殖民者，可以主动倾注生命并保证形成。
3. 算法根据制造者的一生决定有限候选与形成解释，玩家决定最终凝聚成哪一种黑触发器。
4. 每种黑触发器在单个存档中世界唯一。
5. 黑触发器保存制造者留下的有限生命印记，并据此筛选适配者。
6. 黑触发器首次由适配者装备时绑定，绑定者死亡后才解除。
7. 每种黑触发器仍是一套完整的作者配置，不在游戏中动态拼装能力。

## 二、设计原则

- 原版优先：复用 `ThingDef`、`RecordDef`、`ChoiceLetter`、`GameComponent`、`Alert`、`Gizmo`、`CompBiocodable` 与原版装备检查。
- 最小介入：不制作通用条件表达式、通用死亡遗产框架或常驻逐 Tick 扫描。
- 业务归业务：所有黑触发器正式逻辑位于 Content；Core 不新增黑触发器概念；Development 只提供调试与诊断。
- 单一真值：候选快照只由待决信件保存，最终唯一状态只由游戏组件保存，未定形遗物不复制完整数据。
- 结果可解释：内部可以使用分数，但玩家看到的是生命事实、形成解释与适配原因，而不是裸数值。
- 世界唯一是历史事实：最终生成后，即使物品毁坏或遗失，该种类也不会再次出现。

## 三、范围与共同约束

### 3.1 制造者范围

- 只允许玩家殖民者成为制造者。
- V1 只处理当前生成在地图上的殖民者死亡。
- 商队、世界地图对象和其他离图死亡暂不处理。
- 儿童可以通过自然死亡形成，但不能主动献祭。
- 制造者若被其他模组复活，不获得自动适配权，仍按普通使用者判定。

### 3.2 黑触发器共同规则

- 每种黑触发器以其现有 `ThingDef` 为唯一身份。
- 每件物品可以拥有一至三个无主次、无权重的倾向。
- 世界唯一、不可交易、首次装备绑定、绑定者死亡后解绑属于共同规则，不做成每件物品可随意关闭的开关。
- 黑触发器不能出售或赠礼，可以卸下、搬运、掉落和被抢走。
- 被俘、招募、叛变或改变派系后，绑定继续保留。
- 普通敌方 AI 不会主动装备；未来特殊敌方持有者另行设计。

## 四、程序集职责

### 4.1 Core.dll

本功能不向 Core 增加任何黑触发器专用设施。Content 只读取 Core 已有的三离子容量潜力等正式数据。

明确不加入 Core 的内容：

- 通用遗愿系统；
- 通用死亡遗物框架；
- 通用规则表达式；
- 黑触发器枚举、接口或注册表。

### 4.2 Content.dll

Content 承载全部正式业务：

- 黑触发器 `DefModExtension`；
- 倾向与生命轨迹定义；
- 死亡前快照；
- 自然形成与主动献祭；
- 候选筛选；
- 未定形遗物与选择信件；
- 尸体销毁事务；
- 世界唯一登记；
- 制造者印记；
- 适配与绑定；
- 保存读取和一致性清理；
- 玩家可见语言键。

### 4.3 Development.dll

Development 单向读取 Core 与 Content，提供：

- 制造者诊断；
- 适配诊断；
- 世界唯一状态诊断；
- 全部参与系统的黑触发器配置与当前存档状态目录；
- 上帝模式强制进入献祭流程；
- 单种类世界唯一测试状态重置。

Development 不复制正式算法，卸载后正式功能不受影响。

## 五、倾向、生命轨迹与战术功能

三者必须分开：

- 倾向描述黑触发器意志与价值方向；
- 生命轨迹描述制造者实际活过怎样的一生；
- 战术功能由黑触发器现有固定能力与装备配置决定。

### 5.1 倾向预设

V1 预备以下倾向：

- 守护；
- 讨伐；
- 存续；
- 营造；
- 求索；
- 联结；
- 掌控。

倾向使用轻量自定义 Def，只保存名称、说明、显示顺序和可选图标。倾向本身不自动附带形成条件、适配加成或战斗数值。

“托付”不是普通倾向，而是形成事件中与具体人物绑定的特殊语义。没有实际托付对象时，不显示托付。

风刃与卵之冠如何引用这些倾向暂缓决定。

### 5.2 六种生命轨迹

- 战斗：造成伤害、击倒、击杀、征召与狩猎经历，技能只作辅助证据。
- 救护：治疗、手术、救援、照料与有限的救火证据。
- 营造：建造、制作、修理为主，种植、烹饪、采矿为辅，清扫搬运权重较低。
- 求知：研究时间、研究成果与智识相关长期行为。
- 联结：直接关系、评价、羁绊与明确的人际行为，不用泛化的派系身份代替。
- 承受：承受伤害、倒地、治疗、病床时间与永久伤痕；精神崩溃不直接等同于承受力。

每类轨迹使用原版 `RecordDef` 等真实记录作为主要依据，并通过饱和曲线归一化。重复表达同一事实的记录先分组，再取组内最大值或有限组合，避免重复计分。

长期实际行为是主证据；技能、热情、性格、基因、头衔和临终情境只能按具体路线提供有限辅助，不建立全局映射表。

## 六、生命印记快照

死亡前快照用于保存关系清理前的事实，包括：

- 制造者稳定编号、姓名和基本显示信息；
- 三离子容量潜力；
- 六项生命轨迹的归一化结果与代表事实；
- 相关技能、热情、性格和路线明确要求的特殊事实；
- 直接关系与托付对象候选；
- 临终状态、形成来源和死亡原因摘要；
- 生命印记是否已耗尽。

快照必须在 `Pawn.Kill` 的死亡前阶段捕获，因为原版死亡流程会清理部分关系。死亡后阶段只在确认角色已死且尸体已经落地后提交形成事件。

## 七、自然死亡形成

### 7.1 硬门槛

自然形成前依次检查：

1. 玩家殖民者且当前在地图上；
2. 生命印记尚未耗尽；
3. 三离子容量潜力至少 1800；
4. 生命印记达到总体门槛；
5. 至少存在一个未被占用、未永久生成且路线匹配的候选。

当前三离子、恢复速度和释放强度不参与形成。1800 对应现有分布中的优秀档，约覆盖最高四分之一；优秀只取得资格，卓越及更高档位提高自然形成机会。

### 7.2 生命印记强度

总体印记不把六条轨迹直接求和，而采用：

- 最强轨迹作为主要部分；
- 第二轨迹提供有上限的补充；
- 与其他轨迹的鲜明差异提供辨识度；
- 临终情境只能提供很小且有上限的正向修正；
- 普通关系数量不提供通用加成。

候选数量和候选匹配分不提高形成概率，避免内容越多越容易形成。

### 7.3 稳定判定

自然形成使用由世界标识、Pawn 稳定编号与固定盐生成的稳定结果，不使用死亡 Tick 或全局随机序列。相同存档中，同一殖民者反复读档并更换死亡方式，判定结果保持不变。

具体概率曲线放在 Content 配置中，结构固定，数值通过游戏内测试调整。

### 7.4 明确排除的主动处置

自然形成入口拒绝：

- `DamageDef.execution == true` 的处决、仪式处决和安乐死；
- 致死伤害为 `SurgicalCut` 的致命器官或身体部件摘除；
- 没有尸体的销毁型死亡；
- 已由 BDP 主动献祭流程标记的死亡。

其他真实伤病死亡允许判定，包括战斗、友军误伤、流血、感染、中毒、温度、饥饿、年老和意外手术失败。

系统不尝试推断所有玩家意图，不监控禁食、温控、工作命令或所有友军伤害。

### 7.5 自然失败

任何门槛或稳定判定失败时：

- 保留普通尸体；
- 不写生命印记耗尽；
- 不创建遗物或信件；
- 不弹出多余失败通知。

## 八、主动献祭

### 8.1 原则

不稳定性放在进入献祭的时机，而不是献祭后的结果。只有严格且短暂的个人濒死窗口允许主动献祭；确认献祭后保证建立形成事件，不再抽自然形成概率。

### 8.2 基础准入

- 玩家殖民者且在地图上；
- 原版成年阶段；
- 仍然活着；
- 生命印记未耗尽；
- 三离子容量潜力至少 1800；
- 生命印记达到门槛；
- 至少存在一个可用候选；
- 未处于麻醉、昏迷或精神失常，仍能表达最低限度的意志；
- 没有另一场针对该殖民者的献祭流程。

### 8.3 急性危机

命中以下任一条件：

1. 原版预计失血死亡时间不超过 2500 Tick，约一个游戏小时；
2. 拥有致死严重度的病症达到其致死线的 90%；
3. 无单一致死线的病症当前被原版判定为威胁生命，并且殖民者已经倒地。

普通倒地、疼痛休克、睡眠、麻醉、移动能力丧失、一般慢性病、单纯战斗中或尚未逼近致死阶段的恶劣环境不构成献祭窗口。

突然致死而没有操作窗口的情况由自然死亡形成接管。

### 8.4 玩家入口

- 原版 `Alert` 显示当前存在献祭时机的殖民者；危机解除后自动消失。
- 符合条件的殖民者被选中时显示“倾注生命”命令。
- 点击后暂停并显示不可逆确认。
- 确认瞬间重新验证健康、候选与地图状态。

不为每名殖民者增加逐 Tick 组件；警报使用原版警报检查，命令只在读取 Gizmo 时计算。

### 8.5 献祭提交

确认后：

1. 捕获完整快照并固定候选；
2. 标记本次死亡来源为主动献祭；
3. 让殖民者立即死亡；
4. 阻止自然死亡入口重复判定；
5. 建立未定形遗物与选择信件；
6. 写入生命印记已耗尽；
7. 销毁尸体。

主动献祭只增加一个“主动倾注生命”的临终事实。它不会自动增加守护、联结或其他倾向，不提高黑触发器强度，也不改变适配规则。具体形成路线可以明确选择是否读取该事实。

## 九、候选形成

### 9.1 路线评估

每件仍可用的黑触发器分别检查自己的形成路线。路线产生：

- 是否满足绝对门槛；
- 只用于排序的内部匹配分；
- 支撑该解释的生命事实；
- 最终意志语言键；
- 托付对象及其关系；
- 最终物品需要继承的制造者印记。

同一 `ThingDef` 即使多条路线成立，也只作为一个候选出现，采用匹配最高的路线；同分时按作者优先序，再用稳定编号打破平局。

### 9.2 候选数量

- 一个结果充分成立时允许只出现一个候选；
- 通常提供两个候选；
- 第三个候选必须匹配度足够高，并在主要生命轨迹组合或托付结构上提供明显不同的解释；
- 不为凑数加入弱候选。

第一候选是确定的最佳匹配，后续候选补充其他充分成立的解释。除完全同分的稳定打破平局外，不做随机抽选。

### 9.3 玩家选择的叙事定位

算法已经依据制造者一生排除了不成立的结果。玩家不是替死者编造愿望，而是从数种都成立的回应中，引导一种形态稳定下来。

最终意志不直接读取 Pawn 上不存在的“愿望字段”，而由被选中的黑触发器形成路线确定。

## 十、未定形遗物与选择信件

### 10.1 选择信件

自定义 `ChoiceLetter` 保存待决事件的完整事实：

- 制造者快照；
- 固定候选列表；
- 每个候选的形成路线、解释与代表事实；
- 托付对象；
- 未定形遗物和地图锚点；
- 最终意志与叙事语言键。

信件创建后不因技能、性格、关系、派系或世界唯一状态变化而重新计算候选。

信件：

- 不设超时；
- 不能右键关闭；
- 不提供放弃；
- 提供“稍后决定”；
- 提供定位未定形遗物；
- 提供每个候选的原版信息卡入口；
- 最终选择前使用原版对话节点进行二次确认。

### 10.2 信件文案结构

正文依次显示：

1. 制造者躯体消逝、意志停留的事件叙事；
2. 最鲜明的一至两项生命轨迹；
3. 每个候选的倾向、形成解释、两至四条代表事实、最终意志与托付对象；
4. 只有一种形态能够稳定下来的提示。

玩家不看到内部匹配分。

### 10.3 未定形遗物

未定形遗物是无 Tick 的地图 Thing，只保存事件编号、对应信件编号和少量显示信息。

它：

- 不可选取和交互；
- 不可搬运、入库或交易；
- 不受伤害且没有耐久；
- 不提供工作、按钮或持续运算；
- 只承担地图叙事锚点和最终生成位置。

信件是待决数据的单一真值，遗物不复制候选与快照。

## 十一、形成事务与尸体销毁

### 11.1 建立待决事件

形成成功后的提交顺序必须固定：

1. 计算并冻结快照与候选；
2. 在尸体位置或附近合法格生成未定形遗物；
3. 创建并加入选择信件；
4. 确认遗物和信件都已建立；
5. 写入“生命印记已耗尽”；
6. 销毁制造者尸体。

若遗物或信件建立失败：

- 清理临时对象；
- 不写耗尽标记；
- 不销毁尸体；
- 记录错误。

若主动献祭已经使角色死亡但事件建立因技术问题失败，不尝试复活角色，只保留尸体并不消耗生命印记。

### 11.2 最终凝聚

玩家确认候选后：

1. 重新验证遗物与候选占用；
2. 在内存中创建黑触发器并初始化制造者印记；
3. 在遗物位置或附近合法格放置物品；
4. 放置成功后写入永久唯一登记；
5. 释放未选候选；
6. 移除遗物并关闭信件。

失败时撤销新物品和临时登记，保留待决事件供重试，并显示语言包错误提示。

## 十二、世界唯一

每种黑触发器在单个存档中有三个状态：

```text
可用
  ↓ 进入候选列表
待定占用
  ├─ 被选择 → 永久登记
  ├─ 选择其他候选 → 恢复可用
  └─ 待决事件丢失 → 恢复可用

永久登记
  └─ 永不恢复可用
```

### 12.1 状态来源

- `GameComponent` 只保存已经最终生成过的 `ThingDef` 名称。
- 待定占用从尚未解决的选择信件实时读取，不另存第二份登记表。
- 未定形遗物只保存事件关联，不保存唯一状态。

### 12.2 永久性

最终登记后，即使黑触发器：

- 被摧毁；
- 被抢走；
- 遗失；
- 留在废弃地图；

也不会恢复可用。

未来特殊敌方初始持有黑触发器时，也必须通过同一正式登记入口。

### 12.3 地图废弃

待决遗物所在地图被废弃时：

- 遗物消失；
- 对应信件失效；
- 所有候选解除待定占用；
- 制造者尸体不会恢复；
- 生命印记耗尽保持。

原版开发工具或其他模组绕过正式入口强制生成的重复物品不在保证范围内。系统只记录诊断警告，不全局扫描并删除外部物品。

## 十三、最终制造者印记

最终物品只保存形成路线选择的精简信息：

- 制造者稳定编号与姓名；
- 固定倾向集合；
- 最终意志；
- 托付对象的稳定编号、姓名和形成时关系；
- 一至数条代表性生命事实；
- 绑定者信息。

托付对象死亡或离开后，历史记录仍保留，但不会把精确托付加值转移给其他人。

物品检视信息显示制造者、倾向、最终意志、托付对象、代表性印记与绑定者，不显示完整死亡快照。

## 十四、适配与绑定

### 14.1 二元适配

外部结果只有：

- 适配：允许首次绑定并发挥完整性能；
- 不适配：拒绝装备。

内部可以计算匹配分，但不显示“强烈共鸣／可以共鸣”等没有独立效果的档位，也不根据适配程度改变伤害、消耗、冷却或能力数量。

### 14.2 判定顺序

硬条件先行：

- 已绑定他人；
- 使用者已经绑定另一件黑触发器；
- 三离子容量低于物品要求；
- 使用者类型不允许；
- 物品专用绝对排斥；
- 原版身体、装备槽或其他技术条件失败。

软性适配再读取该物品明确声明的：

- 性格存在或缺失；
- 技能、热情或长期行为；
- 使用者自身生命轨迹；
- 与制造者精简印记相符或冲突；
- 专用特殊条件。

不建立所有性格、基因、背景与倾向之间的全局映射。

托付对象提供较高但有限的适配加值，可以帮助接近门槛的人通过软性适配，但不能覆盖任何硬条件。

### 14.3 首次绑定

- 原版 `EquipmentUtility.CanEquip` 继续处理常规装备条件。
- BDP 在黑触发器准入后追加适配检查。
- 不适配时，右键装备菜单显示语言包中的主要失败原因。
- 适配时，首次绑定前显示不可逆确认和两至四条主要依据。
- 确认后调用自定义 `CompBiocodable` 派生组件完成绑定。

不复用 `CompBladelinkWeapon`，避免人格武器随机特质、心情需求和不符合本设计的解绑行为。

### 14.4 绑定生命周期

- 适配只在首次绑定时计算。
- 后续技能、性格、基因、关系和派系变化不重新判定。
- 绑定者可以卸下和重新装备。
- 其他人不能装备。
- 绑定者死亡后解除绑定，下一名使用者重新适配。
- 一名角色同时只能绑定一件黑触发器。

## 十五、作者配置契约

每件黑触发器在现有 `ThingDef` 上挂同一种 `DefModExtension`，只描述：

- `inclinations`：固定倾向列表；
- `formationSources`：自然死亡、主动献祭或仅剧情生成；
- `formationRoutes`：形成路线；
- `compatibility`：适配规则；
- `choiceSummaryKey`：候选信件摘要语言键。

能力、贴图、装备槽、三离子消耗、市场价值和交易属性继续由现有 ThingDef 与组件负责。

### 15.1 形成路线字段

每条路线包含：

- 唯一内部编号；
- 允许的形成来源；
- 生命轨迹门槛和鲜明度要求；
- 有限的技能、性格或临终辅助条件；
- 托付对象选择规则；
- 最终物品需要继承的印记；
- 最终意志语言键；
- 作者优先度；
- 可选的专用判定类。

标准字段无法表达的少数特例可以使用小型专用判定类，不扩张成任意嵌套表达式语言。

### 15.2 全局配置

以下只配置一次：

- 制造者三离子门槛；
- 自然形成概率曲线；
- 生命印记门槛；
- 候选数量规则；
- 主动献祭危机阈值；
- 世界唯一和尸体销毁事务；
- 绑定共同流程；
- 主动处置死亡过滤。

### 15.3 配置校验

加载时检查：

- 倾向为空或重复；
- 允许玩家形成却没有路线；
- 路线编号重复；
- 引用不存在的生命轨迹、倾向、物品或语言键；
- 门槛和曲线范围无效；
- 缺少绑定组件；
- 仍允许交易；
- 专用判定类类型错误。

无效物品不进入候选池，并记录明确 Def 名和错误原因。

## 十六、保存读取与异常清理

读档后执行一次事件驱动的一致性检查，不做持续扫描：

- 有信件但遗物缺失：取消事件并释放候选；
- 有遗物但信件缺失：销毁孤立遗物；
- 候选 Def 缺失：移除该候选，全部缺失则取消事件并记录日志；
- 永久登记物品已消失：保持登记；
- 检测到外部重复物品：只记录警告。

旧存档兼容不属于本轮目标，不为尚未发布的结构保留兼容层。

## 十七、Development 诊断

沿用现有 `BDP.Development.dll` 中 `DebugAction("Mods", ...)` 的入口形式。

### 17.1 只读动作

- 输出制造者诊断：硬门槛、六项轨迹、危机状态、稳定判定、各路线结果与最终候选。
- 输出适配诊断：硬条件、软性依据、托付加值、最终结果与玩家可见原因。
- 输出世界唯一状态：可用、待定占用、永久登记和重复物品警告。
- 打开黑触发器系统目录：阅览全部参与系统的黑触发器配置，并叠加当前存档状态。

统一日志前缀：

```text
[BDP Development][BlackTriggerFormation]
```

### 17.2 黑触发器系统目录

系统目录使用独立的 Development `Window`，由 `DebugAction("Mods", ...)` 打开。目录不是地图物品扫描结果，而是以所有带 `BlackTriggerFormationExtension` 的 `ThingDef` 为全集；即使某一种黑触发器从未形成、已经遗失或当前没有实例，也必须出现在目录中。带扩展但配置无效的 Def 同样显示，并明确标记配置异常，方便排查。

Content 提供一次性的结构化目录快照，Development 只负责显示，不复制形成、适配、唯一性或实例判定规则。快照在打开窗口和玩家点击“刷新”时重建；窗口绘制过程不逐 Tick、逐帧重新扫描世界。

窗口采用主从布局：

```text
┌ 黑触发器系统目录 ─────────────────────────────┐
│ 搜索……  全部 / 可用 / 待决 / 已定形 / 异常  刷新 │
│ 共 N 种｜可用 N｜待决 N｜已定形 N｜异常 N         │
├────────────────┬────────────────────────────┤
│ 种类清单        │ 所选种类详情                 │
│ 图标、名称      │ 概览 / 形成路线 / 适配 / 存档 │
│ defName、倾向   │                              │
│ 文字状态        │ 分区后的详细信息与跳转动作   │
└────────────────┴────────────────────────────┘
```

左侧清单要求：

- 每行显示物品图标、名称、`defName`、倾向和当前主状态；
- 支持按名称、`defName`、倾向和 `routeId` 搜索；
- 支持“全部、可用、待决、已定形、异常”筛选；
- 颜色只作辅助，状态必须同时用文字表达；
- 默认稳定排序，刷新后尽量保持当前选择。

右侧详情分四页：

1. 概览：倾向、允许形成来源、配置校验结果、世界唯一主状态；
2. 形成路线：每条路线的 `routeId`、作者优先级、生命轨迹要求、特征支持、锚点规则与最终意志；
3. 适配：潜力门槛、绝对拒绝、软性规则、适配阈值、托付加值与专用 worker；
4. 存档：待决信件与预留、最终登记、制造者印记、绑定者、所有可发现实例的位置、实例失踪和重复警告。

目录的主状态采用互斥优先级，保证汇总数字容易理解：配置异常或重复实例归入“异常”，其次为已定形、待决、可用。“已定形但找不到实例”仍属于已定形，同时显示失踪警告。

实例查找覆盖当前游戏能够安全遍历的地图、Pawn 持有物与世界容器，并以实例 ID 去重。地图上的物品、遗物或绑定者提供跳转；商队、世界容器或已经失踪的对象只显示位置说明，不伪造跳转。目录只读，不修改唯一性、绑定或物品状态。

### 17.3 修改状态的动作

- 强制进入献祭流程：跳过个人危机和自然概率，仍检查制造者范围、地图、生命印记、三离子、候选与世界唯一，并调用正式流程。
- 重置所选种类的测试状态：二次确认后只移除该种类永久登记和待定占用，不删除现存物品、不恢复尸体、不清除制造者耗尽记录。

只读诊断要求开发者模式；修改状态的动作额外要求上帝模式。

## 十八、验证矩阵

### 18.1 静态与构建

- Core、Content、Development 依赖方向正确；
- Def 与语言键完整；
- 黑触发器不可交易并拥有正确绑定组件；
- 无效配置不会进入候选；
- Core、Content、Development Release 构建通过。

### 18.2 游戏内必须验证

- 自然形成各硬门槛与稳定读档结果；
- 处决、安乐死和致命器官摘除过滤；
- 主动献祭三类危机与恢复后的入口消失；
- 主动献祭不重复触发自然判定；
- 成功形成时先建遗物和信件，再写耗尽标记并销毁尸体；
- 待决信件保存读取后候选不变；
- 候选占用、选择释放和地图废弃释放；
- 最终登记在物品毁坏或遗失后仍保留；
- 适配失败、首次绑定、卸下、他人拒绝、派系变化和绑定者死亡解绑；
- 未绑定与已绑定物品均不能出售或赠礼；
- 普通敌方不主动装备；
- 孤立信件、遗物和缺失 Def 的清理行为。
- 系统目录包含全部带形成扩展的黑触发器，搜索、状态筛选、详情分页和手动刷新正确；
- 系统目录能够显示可用、待决、已定形、已定形但实例失踪、配置异常与重复实例状态；
- 系统目录的地图跳转只对可定位对象启用，且窗口打开期间不会逐 Tick 重扫世界。

编译通过不能替代这些生命周期实测。

## 二十、最终数据流

```text
玩家殖民者死亡或确认主动献祭
  → 死亡前抓取生命、关系与临终快照
  → 检查制造者门槛与可用候选
  → 自然死亡执行稳定判定／主动献祭保证形成
  → 建立未定形遗物与固定选择信件
  → 写入生命印记已耗尽
  → 销毁尸体
  → 玩家稍后从有限候选中确认一种形态
  → 生成最终黑触发器并永久登记
  → 适配者首次装备并绑定
  → 绑定者死亡后解绑，但世界唯一登记永不撤销
```
