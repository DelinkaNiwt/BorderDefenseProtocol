# 追踪弹模块重构设计（第二版）

> 本文档取代 `2026-04-24-追踪弹模块设计-第一版.md` 作为当前追踪弹方案的正式设计基线。

## 1. 结论先行

当前追踪弹第一版实现证明了以下事情已经打通：

- 主模组统一弹体宿主可以承载曲线路径快照
- 测试模组可以通过远程模块体系注入追踪行为
- 模块私有上下文可以随 projectile 中途存读档连续恢复
- 追踪模块可以保持对 `PathLatch` 完全隔离

但第一版的核心追踪逻辑不适合作为最终方案继续叠补丁。原因不是“不能拐弯”，而是它的行为骨架仍然是：

- 首段规划一次
- 段末续追一次
- 一旦进入终端，就偏向直接收束

这种骨架更容易做出“能追上就贴住，追不上就直接没了”的感觉，不容易稳定做出目标与子弹之间的追躲博弈感，也不利于表现强弱追踪性能差异。

本次重构的正式结论是：

- **保留现有主宿主与曲线路径快照外壳**
- **保留 `ProjectileInit + Arrival` 的主接线方式**
- **重做追踪核心为“短段连续曲线追踪”**
- **不引入对 `PathLatch` 的任何依赖**
- **不引入人为的子弹速度倍率逻辑**
- **命中/擦肩/丢追使用新的多条件判据，而不是单一距离阈值**

## 2. 现状与问题归因

### 2.1 当前实现的真实形态

当前 `HomingModule` 只参与两个阶段：

- `IProjectileInitStageModule`
- `IArrivalStageModule`

当前 `BdpProjectile` 的真实曲线轨迹由 `currentFlightPathSnapshot` 驱动，而这个路径快照只会在两个时点被重新绑定：

- 发射时绑定首段路径
- `ContinueFlight` 时绑定下一段路径

因此，虽然主模组已经存在 `Flight` 阶段接口，但现有 `FlightContribution` 只能改“重定向目标点 / 当前目标 / 倍率”，不能直接提交新的曲线路径快照。也就是说，**当前真正可用的曲线重规划入口仍然是“发射”和“续段”**。

### 2.2 第一版为什么不适合继续打补丁

第一版的主要问题不是“参数不够多”，而是运动学骨架不对：

- 续追段太像“离散纠偏”
- 终端阶段进入过早，容易产生视觉上的收束吸附感
- 没有稳定表达“擦身而过后继续飞离再补追”的机制
- 强弱配置只能体现“更快收束 / 更慢收束”，难以体现“更强补追能力 / 更容易被甩掉”

### 2.3 为什么暂不扩主宿主

目前主宿主并不缺失“继续飞行 / 曲线续段 / 中途存读档恢复”这些能力，真正缺的是追踪模块自己的行为骨架。

如果现在直接为了追踪效果去扩主宿主，让 `Flight` 阶段直接改路径快照，会有两个问题：

- 容易在尚未验证二版追踪骨架前，过早把问题上推到主模组
- 容易让测试模组的行为实验反向侵入主宿主

因此，当前正式决策是：

- **先不改主宿主结构**
- **先用现有续段能力做“短段连续曲线追踪”**
- **只有当二版骨架实测仍不足以表现目标效果时，才考虑给主宿主补一个最小的 `Flight -> PathSnapshot` 扩展点**

这条后备路线会保留为代码中的最简 `TODO:` 注释，但不进入本轮实施范围。

## 3. 本轮需求边界

### 3.1 必须满足

- 子弹轨迹是平滑曲线，不是折线
- 追踪模块不依赖 `PathLatch`，也不需要知道 `PathLatch` 存在
- 追踪强弱由 XML 配置
- 强追踪配置在合理前提下应当拥有很高的最终命中率
- 弱追踪配置在目标急转、走位漂亮时应当能被甩掉
- 视觉上不能抖、乱、吸过去
- 要能出现“擦肩飞过、继续飞、再补追”的博弈感
- 必须考虑 projectile 中途存读档恢复
- 暂缓事项必须以最简 `TODO:` 注释写入代码

### 3.2 明确不做

- 不把旧 `Bullet_BDP` 的宿主结构搬回新模组
- 不增加与 `PathLatch` 的共享状态或调用耦合
- 不通过“人为加速子弹”伪造追踪能力
- 不使用一条单纯的“距离够近就直接判中”逻辑
- 不做正常运行依赖的每 tick 大量碰撞扫描

## 4. 方案比较与最终选型

### 方案 A：继续沿第一版参数微调

做法：

- 保持现有逻辑
- 只调整分段长度、终端阈值、拉回力度

问题：

- 只能修“程度”，修不了“骨架”
- 很难稳定做出擦过后补追
- 很容易继续出现“黏目标”“不自然收束”

结论：不采用。

### 方案 B：短段连续曲线追踪（推荐）

做法：

- 继续以 `ProjectileInit` 注入首段路径
- 以 `Arrival` 作为高频短段重规划调度点
- 每次续段都基于：
  - 当前精确位置
  - 当前真实切线
  - 本段起始时目标位置
  - 本段结束时目标位置
- 重建下一小段三次贝塞尔
- 用“最近接距离 + 段末距离 + 前后关系”决定命中、擦肩、丢追

优点：

- 不改主宿主结构
- 可保持平滑曲线
- 容易表达强弱追踪差异
- 完全兼容现有存读档载体
- 与 `PathLatch` 完全隔离

缺点：

- 段数会增加，需要控制段长与采样数
- 需要更精细的命中/擦肩判据

结论：采用。

### 方案 C：为 `Flight` 阶段补最小主宿主扩展点

做法：

- 主宿主支持 `Flight` 阶段直接覆盖当前曲线路径快照

优点：

- 可进一步提升高弹速下的连续感

缺点：

- 会把实验性需求推回主模组
- 当前没有证据证明二版骨架必须依赖这个能力

结论：本轮不做，仅作为后备方案保留 `TODO:`。

## 5. 第二版总体结构

### 5.1 主宿主层

`BdpProjectile` 与 `RangedFlightProtocol` 不改结构性职责。

继续沿用：

- 发射时绑定首段 `ProjectileFlightPathSnapshot`
- `ImpactSomething()` 先跑 `Arrival`
- `ArrivalRecord.ContinueFlight = true` 时绑定下一段快照
- `launchPlan + AttackContextSnapshot` 持有中途状态并参与存档

### 5.2 模块层

`HomingModule` 继续只实现：

- `IRangedAttackModuleRuntime`
- `IProjectileInitStageModule`
- `IArrivalStageModule`

二版不接 `IFlightStageModule`。原因不是否认 `Flight` 阶段价值，而是当前宿主没有对它开放曲线路径提交面，接了也不能解决当前核心问题。

### 5.3 几何层

`HomingPathPlanner` 保持“纯几何工具”定位：

- 规划首段路径
- 规划续段路径
- 估算本段最近接距离
- 计算续追模式下的段长
- 对控制点做侧向夹制
- 判断是否应退化到安全直线

### 5.4 状态层

`HomingModuleState` 继续作为唯一 projectile 侧模块私有状态容器。

第一版已有字段继续保留：

- `LockedTarget`
- `HasLastObservedTargetPosition`
- `LastObservedTargetPosition`
- `LastSegmentTangent`
- `SegmentIndex`
- `TerminalPhaseArmed`
- `LostSegments`

第二版新增字段：

- `ProjectileFlightPathSnapshot ActiveSegmentSnapshot`
  - 当前这段真正绑定给宿主的路径快照
  - 用于到段末时计算“这段是否擦身而过”
- `bool HasSegmentStartTargetPosition`
- `Vector3 SegmentStartTargetPosition`
  - 记录本段开始时目标真实位置
  - 与到段末时的实时目标位置一起，用于线性近似目标运动
- `float LastClosestApproachDistance`
  - 记录刚完成这一段的最近接距离，便于诊断与存档恢复
- `bool LastSegmentWasPassBy`
  - 记录上一段是否已构成擦肩证据
- `int PassByRecoverySegmentsRemaining`
  - 擦肩后允许继续补追的剩余段数

这些状态都必须进入 `Clone()` 与 `ExposeData()`，保证中途存读档恢复后继续按照同一条追踪叙事运行。

## 6. 第二版追踪流程

## 6.1 发射时

发射时仍只做一次首段规划：

1. 解析锁定目标
2. 读取发射时目标真实位置
3. 用当前发射方向和目标真实位置构建首段贝塞尔
4. 将首段快照写入 `ProjectileInitContribution`
5. 初始化状态：
   - `ActiveSegmentSnapshot = 首段快照`
   - `SegmentStartTargetPosition = 发射瞬间目标位置`
   - `LastObservedTargetPosition = 发射瞬间目标位置`
   - `LastSegmentTangent = 首段起始切线`
   - 清空所有 pass-by / lost / recovery 计数

注意：

- 首段方向仍以**发射瞬间目标位置**为准
- 不在这里过早武断地进入终端收束

## 6.2 每次到段末

当 projectile 自然飞到当前段末时，`Arrival` 阶段执行以下顺序：

1. 解析目标当前真实位置 `liveTargetPosition`
2. 读取当前 projectile 的：
   - `ExactPosition`
   - `ExactRotation`
3. 取出状态中的：
   - `ActiveSegmentSnapshot`
   - `SegmentStartTargetPosition`
   - `LastSegmentTangent`
4. 基于刚完成这一段，评估三类证据：
   - 最近接距离
   - 段末距离
   - 目标相对子弹切线的前后关系
5. 决定：
   - 交回命中
   - 擦肩后继续补追
   - 普通继续追踪
   - 彻底丢追
6. 若继续追踪，则规划下一小段路径并更新状态

## 7. 命中 / 擦肩 / 丢追判据

这是二版的核心。

### 7.1 计算量

每次到段末只做一次轻量评估，不做常驻每 tick 重碰撞。

评估输入：

- `ActiveSegmentSnapshot`
- `SegmentStartTargetPosition`
- `liveTargetPosition`
- `currentPosition`
- `currentTangent`

评估过程：

- 将当前段曲线采样为固定小样本（建议 5～7 个采样点）
- 假设目标在这一段中由 `SegmentStartTargetPosition` 线性移动到 `liveTargetPosition`
- 对每个采样点计算对应时刻的子弹-目标间距
- 取最小值作为 `closestApproachDistance`
- 计算段末真实距离 `endDistance`
- 计算
  `forwardDot = Dot(currentTangent.normalized, (liveTargetPosition - currentPosition).normalized)`

### 7.2 交回命中（handoff to impact）

只有同时满足以下条件时，才停止续段并交回原版命中：

- `endDistance <= ImpactHandoffDistance`
- `forwardDot >= PassByRearDotThreshold`

含义：

- 段末确实已经足够贴近目标
- 目标没有明显甩到弹头后侧

这保证了“命中”发生在视觉上也合理接近命中的时刻，而不是已经飞过了还被硬判中。

### 7.3 擦肩继续飞（pass-by recovery）

满足任一条件时，认为这一段已经形成“擦肩/甩尾”证据：

- `closestApproachDistance <= PassByDistance`
- `forwardDot < PassByRearDotThreshold`

但此时只要恢复预算仍在，就不立刻判丢追，而是进入补追模式：

- `PassByRecoverySegmentsRemaining > 0`

补追模式的下一段会：

- 缩短段长
- 增强拉回力度
- 继续追目标真实位置（可选非常轻的微预测）

### 7.4 丢追（lose track）

只有以下条件持续满足时，才真正放弃追踪：

- 目标已明显在弹头后侧或偏角超限
- `PassByRecoverySegmentsRemaining == 0`
- `LostSegments` 持续超过 `LostDistanceGraceSegments`

这保证了弱追踪弹会被漂亮走位甩掉，但不会因为一次擦肩就立刻傻掉。

## 8. 第二版路径规划原则

### 8.1 仍然主追真实位置

二版默认仍然是“主追真实位置”，不是抢前点追踪。

只保留一个很轻的可选前推：

- `PredictionTicks > 0` 时才启用
- 只是对目标位移做轻量外推
- 主要作用是避免极低段长下的明显迟滞，不把它当成主表现手段

### 8.2 不折线

正常续段始终优先三次贝塞尔。

曲线连续性来自：

- 下一段起点直接接当前段终点
- 下一段入射切线直接继承当前段末/当前真实切线

只有几何退化场景才允许回退到安全直线：

- 起止重合
- 起始切线无法解析
- 角度极端到无法构成稳定控制点

该退化仅作保底，不作为正常追踪表现。

### 8.3 强弱追踪性能如何体现

二版不靠改“子弹速度”，而靠以下几组参数体现追踪性能：

- 重规划频率
  - `MinSegmentTicks`
  - `MaxSegmentTicks`
- 曲线拉回能力
  - `EntryPullRatio`
  - `TerminalPullRatio`
  - `RecoveryPullRatio`
  - `CurveClampRatio`
- 命中窗口与擦肩窗口
  - `ImpactHandoffDistance`
  - `PassByDistance`
  - `PassByRearDotThreshold`
- 被甩掉前的容错预算
  - `PassByRecoverySegments`
  - `LostDistanceGraceSegments`
  - `LostAngleLimit`

因此：

- 强追踪弹 = 段更短、恢复更强、补追预算更高、命中交回窗口更宽
- 弱追踪弹 = 段更长、恢复更弱、补追预算更低、被甩掉更早

## 9. 配置面（第二版）

二版保留第一版已存在字段，并新增以下关键字段：

- `RecoveryPullRatio`
  - 擦肩后补追段的末端拉回力度
- `ImpactHandoffDistance`
  - 允许交回原版命中的段末距离窗口
- `PassByDistance`
  - 认定“这段已经擦身而过”的最近接距离阈值
- `PassByRearDotThreshold`
  - 目标相对子弹切线被认定为“已经跑到后侧”的点积阈值
- `PassByRecoverySegments`
  - 擦肩后允许继续补追的最大段数

运行时需要做最小钳制：

- `MinSegmentTicks >= 1`
- `MaxSegmentTicks >= MinSegmentTicks`
- `ImpactHandoffDistance >= 0.15`
- `PassByDistance >= ImpactHandoffDistance`
- `PassByRearDotThreshold` 钳制到 `[-1, 1]`
- `PassByRecoverySegments >= 0`

## 10. Diagnostics 设计

诊断日志必须继续使用节流输出，不能刷屏。

二版新增或替换为以下事件：

- `homing_handoff_to_impact`
  - 说明本段已进入可交回命中的终端窗口
- `homing_pass_by_recovery`
  - 说明本段已形成擦肩证据，但模块要求继续补追
- `homing_lost_track`
  - 说明目标已被正式判定甩掉

每条日志至少包含：

- `attackId`
- `resultId`
- `projectile`
- `segmentIndex`
- `closestApproachDistance`
- `endDistance`
- `forwardDot`
- `recoverySegmentsRemaining`
- `target`

## 11. 中途存读档恢复

二版必须保持以下恢复事实：

- projectile 当前活动段快照可恢复
- 目标锁定对象可恢复
- 本段起始目标位置可恢复
- 上段最近接距离与擦肩标记可恢复
- 擦肩后剩余补追预算可恢复
- 丢追计数与终端阶段状态可恢复

恢复后行为要求：

- 不重新随机化追踪性能
- 不重置为首段追踪
- 不因为读档让已经形成的擦肩证据消失

## 12. 与旧 BDP 的关系

旧 BDP 值得借鉴的是：

- 有惯性记忆
- 允许擦过后继续飞
- 强弱追踪不是简单命中率差，而是补追能力差

旧 BDP 不值得照搬的是：

- 旧宿主整体结构
- 旧模块对宿主更直接的控制方式

二版因此是“借运动学思想，不借宿主结构”。

## 13. 延后事项

以下内容本轮不做，但必须在代码里写最简 `TODO:`：

- 若短段连续续追在高弹速场景下仍不够顺滑，再评估主宿主最小 `Flight -> PathSnapshot` 扩展点

## 15. 最终裁定

第二版不是对第一版“继续优化”，而是对其追踪核心的正式重构。

它保留了第一版已经验证可用的：

- 宿主接线方式
- 曲线快照外壳
- 模块私有状态持久化
- XML 配置与测试落点

同时替换掉第一版最关键的错误骨架：

- 从“段末纠偏式追踪”
- 改为“短段连续曲线追踪 + 擦肩补追 + 条件性交回命中”

这就是当前最符合 RimWorld 运行现实、模组现有设施、你的审美要求，以及后续可扩展性的正式方案。
