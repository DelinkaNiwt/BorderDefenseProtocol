# 战斗体切换单事务与短时锁 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让同一 Pawn 的一次 A→B 战斗体切换只能被正式入口接受一次，并在 12 tick 短时锁内禁止反向切换，同时确保 Content 最多播放一段扫描动画。

**Architecture:** Core 在既有 `CombatBodyState` 中保存可存档的绝对锁定结束 tick，由正式会话命令在成功激活和成功主动解除后启动，并通过现有 `CanActivate/CanManualDeactivate` 同时约束命令与 Gizmo。Content 在扫描提供器中按 Pawn 保存当前 10 tick 动画窗口，忽略窗口内的重复表现事务，不改变完整人物快照画面或镜像原身逻辑。

**Tech Stack:** C# 7.3、RimWorld 1.6 状态/Gizmo/Def、Harmony 既有表现链、XML 语言包与配置、PowerShell 冒烟测试、dotnet Release 构建。

**Step 3: Write minimal implementation**

在 `ICombatBodyPhaseState` 增加：

```csharp
void BeginManualTransformLock(int lockTicks);
```

`CombatBodyState` 保存 `manualTransformLockEndTick`，`BeginManualTransformLock` 使用 `Mathf.Max(0, lockTicks)` 设置绝对截止 tick；`CanActivate` 与 `CanManualDeactivate` 均要求 `!IsManualTransformLocked()`；`ExposeData` 使用 `Scribe_Values.Look` 保存该字段。

`CombatBodyService` 只增加一个内部转发成员：

```csharp
internal void BeginManualTransformLock(int lockTicks)
{
    phaseState.BeginManualTransformLock(lockTicks);
}
```

`CombatBodySessionService`：

```csharp
public bool TryActivate()
{
    if (!CanActivate()) return false;
    bool activated = activationTransaction.TryActivate(OwnerPawn);
    if (activated) BeginManualTransformLock();
    return activated;
}

public void RequestRelease()
{
    if (!CanManualDeactivate()) return;
    ExecuteExit(CombatBodySessionExitMode.Release);
    BeginManualTransformLock();
}
```

私有 `BeginManualTransformLock` 从 `CombatBodyHostConfigResolver.Resolve().manualTransformLockTicks` 读取配置。Gizmo 在 `Inactive/Active` 分支分别检查 `reader.CanActivate()` 与 `reader.CanManualDeactivate()`，失败时以新语言键禁用。

XML 增加逐条中文注释与值 `12`；语言包增加：

<BDP_Command_CombatBody_TransformLocked>战斗体正在完成变换。</BDP_Command_CombatBody_TransformLocked>
