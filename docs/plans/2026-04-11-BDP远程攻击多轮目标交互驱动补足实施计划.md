# BDP远程攻击多轮目标交互驱动补足实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 把 BDP 远程攻击协议中唯一剩余的根缺口——上游多轮目标交互驱动桥——正式补足，使独立测试模组 v2 能在不改主模组的前提下完整实现战斧类业务。

**Architecture:** 本次只补一个中性能力：让现有 `TargetingInteractionSession`、`TargetingInputFrame`、`TargetingAdvanceDecision` 真正驱动原版 `Targeter` 的下一轮行为。不上升为路径系统，不新增任何战斧专用结构，不改下游飞行与爆炸主骨架。

**Tech Stack:** RimWorld 1.6、C#、Verse / RimWorld API、PowerShell smoke tests、UTF-8 中文文档。

---

## 总原则

- 只补驱动，不补业务。
- 只补共性能力，不补具体业务结构。
- 只以端到端可用为验收，不以协议对象存在为验收。
- 主模组禁止出现路径、锚点、战斧等业务结构本体。
- 当前已完成的私有上下文、冻结链、投射物后半段链、存读档链一律复用，不重做。

## 最终验收标准

必须满足以下 5 条后，才能宣布“主模组终于够了”：

1. 独立测试模组 v2 在不改主模组的前提下，可在一次瞄准中连续输入多轮路径点。
2. 同一个 v2 也可只点一次目标，由模块自动生成路径。
3. 投射物可按路径续飞。
4. 投射物可在中途碰撞或到达指定位置时爆炸。
5. 不挂该业务模块时，远程攻击仍回到原版基线。

## Task 3: 把 `TargetingAdvanceDecision` 真正接入 `Targeter` 主循环

**Files:**
- Modify: `模组工程/BorderDefenseProtocol/Source/BDP/Core/AttackExecution/AttackExecutionTargetingSource.cs`
- Modify: `模组工程/BorderDefenseProtocol/Source/BDP/Core/AttackExecution/TargetingProtocol/Model/TargetingRecord.cs`
- Test: `模组工程/BorderDefenseProtocol/Source/BDP.Tests/RangedTargetingSessionContinuitySmokeTests.ps1`
- Test: `模组工程/BorderDefenseProtocol/Source/BDP.Tests/RangedTargetingDriverBoundarySmokeTests.ps1`

**Step 1: 写失败测试**

断言：

- `OrderForceTarget()` 必须先走“本轮输入驱动”。
- 只有 `Complete` 时才允许进入 `Confirm`。
- `Continue / Back / Reject` 不得直接下单。
- 当前 `moduleSession` 与 `interactionSession` 必须继续沿用，不得重建。

**Step 2: 改写驱动逻辑**

要求：

- 点击目标时，先构造本轮 `TargetingInputFrame`
- 交给驱动器与模块裁决
- 若结果为：
  - `Continue`：原版 `Targeter` 继续保持在当前交互中
  - `Back`：回退一轮后继续保持交互
  - `Reject`：提示原因后继续保持交互
  - `Cancel`：结束交互
  - `Complete`：进入 `Confirm`
- 严禁再把所有点击都直接解释成确认

**Step 3: 运行测试**
