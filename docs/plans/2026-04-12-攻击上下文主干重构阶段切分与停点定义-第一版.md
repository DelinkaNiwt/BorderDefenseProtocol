# 攻击上下文主干重构阶段切分与停点定义-第一版

## 一、用途

这份文档只解决两个问题：

- 重构应该分几段做；
- 每一段做到什么状态就必须停下来验收。

目的只有一个：

- 防止主干重构在中途失控、扩散、回头补丁化。

## 二、总原则

- 一次只改一层，不跨两层一起收口。
- 每一阶段结束都必须有明确停点。
- 没到停点，不进入下一阶段。
- 当前阶段坏现有功能，先修回，不允许带病推进。
- 不允许在后期再回头补主干设计。

## 三、阶段切分

```text
阶段 1：建立主干对象
阶段 2：收请求边界
阶段 3：收目标交互链
阶段 4：收模块私有上下文
阶段 5：收执行前半段协议
阶段 6：收投射物初始化计划
阶段 7：收宿主与投射物后半段
阶段 8：删旧通路并做总回归
```

## 四、各阶段停点定义

## 阶段 1：建立主干对象

范围：

- `AttackContext`
- `AttackContextSnapshot`
- `IAttackContextNode`

本阶段只做：

- 对象建立；
- 最小读写；
- 冻结；
- 存读档。

本阶段不做：

- 接任何现有攻击链；
- 删除任何旧对象；
- 改任何攻击逻辑。

停点标准：

- 新对象能独立编译；
- smoke test 能证明对象模型成立；
- 没有引入复杂总线、复杂 Key、复杂作用域系统。

没满足以上 3 条，不准进入阶段 2。

## 阶段 2：收请求边界

范围：

- `AttackExecutionRequest`
- `AttackExecutionPreparedContext`

本阶段只做：

- 让正式攻击请求边界改成统一上下文。

本阶段不做：

- 不改目标交互链；
- 不改远程协议；
- 不改投射物链。

停点标准：

- 请求对象只认统一上下文；
- 零散确认快照字段退出主干；
- 当前攻击请求仍能正常进入准备阶段。

没满足以上 3 条，不准进入阶段 3。

## 阶段 3：收目标交互链

范围：

- `TargetingRecord`
- `PreviewRecord`
- `ConfirmRecord`
- `AttackExecutionTargetingSource`
- `TargetingInteractionDriver`

本阶段只做：

- 把目标交互相关状态收进统一上下文。

本阶段不做：

- 不改模块私有上下文实现；
- 不改后半段投射物。

停点标准：

- 手动攻击还能正常目标选择、预览、确认、取消；
- 目标交互状态不再独立成第二条主干；
- 确认阶段能正确冻结统一上下文。

没满足以上 3 条，不准进入阶段 4。

## 阶段 4：收模块私有上下文

范围：

- `IRangedModulePrivateContext`
- `RangedAttackModuleSession`
- `RangedAttackModuleSlot`
- 删除 `RangedModuleContextSnapshot`

本阶段只做：

- 把模块私有上下文并入统一主干。

本阶段不做：

- 不改阶段贡献对象；
- 不改投射物后半段读取逻辑。

停点标准：

- 模块还能读写自己的私有上下文；
- 私有上下文可冻结、可存读档；
- 独立模块快照主干已删除。

没满足以上 3 条，不准进入阶段 5。

## 阶段 5：收执行前半段协议

范围：

- `RangedAttackProtocolService`
- `RangedAttackEntry`
- `Aim / Prepare / Fire / ProjectileInit` 阶段上下文

本阶段只做：

- 让前半段协议统一通过 `AttackContext` 读上下文。

本阶段不做：

- 不改阶段贡献对象职责；
- 不改投射物初始化计划结构；
- 不改后半段。

停点标准：

- 前半段各阶段上下文都统一暴露 `AttackContext`；
- 阶段贡献对象仍正常工作；
- 当前远程攻击前半段功能不退化。

没满足以上 3 条，不准进入阶段 6。

## 阶段 6：收投射物初始化计划

范围：

- `ProjectileInitPlan`

本阶段只做：

- 把初始化计划收口成只带统一冻结上下文。

本阶段不做：

- 不改后半段阶段上下文读取实现。

停点标准：

- `ProjectileInitPlan` 只带 `AttackContextSnapshot`；
- 不再持有旧碎片上下文字段；
- 发射宿主仍能正常消费初始化计划。

没满足以上 3 条，不准进入阶段 7。

## 阶段 7：收宿主与投射物后半段

范围：

- `BdpVerb_Shoot`
- `BdpProjectile`
- `Flight / Arrival / Hit / Impact` 阶段上下文

本阶段只做：

- 让后半段只读冻结上下文。

本阶段不做：

- 不新增新的后半段专用上下文系统。

停点标准：

- `BdpVerb_Shoot` 不再回头依赖运行时会话；
- 投射物后半段只读 `AttackContextSnapshot`；
- 存读档恢复后仍能继续跑后半段。

没满足以上 3 条，不准进入阶段 8。

## 阶段 8：删旧通路并做总回归

范围：

- 删除遗留字段；
- 删除死代码；
- 跑全链路回归。

本阶段只做：

- 收尾；
- 删除；
- 验证。

本阶段不做：

- 不再新增对象；
- 不再补设计；
- 不再回头补兼容。

停点标准：

- 代码中只剩一条正式攻击上下文主干；
- 现有攻击相关核心 smoke tests 全部通过；
- 主模组编译通过。

## 五、每阶段必须检查的公共项

每一阶段结束，都必须检查：

- 当前阶段引入的新对象是否仍然简、短、直；
- 是否偷偷引入了第二条上下文主线；
- 是否为了省事保留了兼容双轨；
- 是否破坏了当前已有攻击能力；
- 是否已经达到本阶段停点。

只要有一项答“否”，当前阶段不能结束。

## 六、绝对禁止事项

整个重构过程中，禁止：

- 看到某个业务阻塞就临时给公共对象加专用字段；
- 为了赶进度保留旧碎片字段“先共存”；
- 在后半段继续偷用运行时会话引用；
- 把阶段贡献对象和上下文对象混成一类东西；
- 在没有达到停点时提前进入下一阶段。

## 七、最终判定

这次重构只有两种结果：

### 结果 A：成功

- 一条正式攻击上下文主干成立；
- 旧碎片通路删除；
- 当前已有功能不退化；
- 架构更中性、更短、更直。

### 结果 B：失败

- 仍有两条以上上下文主线；
- 靠兼容字段维持功能；
- 当前已有功能退化；
- 主模组变得更复杂、更懂业务。

只接受结果 A。
