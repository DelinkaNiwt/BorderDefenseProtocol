# BDP 芯片制造台重做设计

日期：2026-08-10  
状态：设计已确认，尚未实施

## 1. 目标与原则

本设计完全重做芯片制造台的面板、制造交互和背后业务逻辑，不以当前制造台实现为产品参考。现有代码只在需要确认客观字段或原版机制时用于调查。

核心原则：

- 制造台制造供边境触发体使用的芯片。
- 原版工作台优先，只替换芯片业务确实需要变化的环节。
- 制造业务全部归属 `BDP.Content.dll`；`BDP.Core.dll` 只提供中性的芯片配置读取契约。
- 面板负责制造决策，不承担动作百科。长描述通过信息卡查看。
- 玩家制造时保存“选择了什么”，具体配置始终按当前预设重新解析。
- 不为每种组合动态生成 `ThingDef` 或 `RecipeDef`。
- 不保留当前自制制造状态机。

## 2. 分类体系

### 2.1 主分类

芯片主分类暂时固定为五种：

- 武装
- 防护
- 能力
- 状态
- 被动

一枚成品芯片只能属于一个主分类。主分类主要用于制造菜单筛选，也可供其他业务读取。

### 2.2 职业体系

“攻击手、射手、枪手、狙击手”从普通标签中移出，组成独立的职业体系：

- 职业字段在全局可为空。
- 一旦填写，只能有一个职业。
- 武装芯片制造当前必须选择职业。
- 动作预设各自声明一个原生职业，用于筛选和兼容判断。
- 成品芯片的最终职业来自玩家制造时选择的职业，不由动作预设反推。

职业对动作的单向兼容关系由数据定义：

```text
攻击手 → [攻击手]
射手   → [射手]
枪手   → [枪手, 射手]
狙击手 → [狙击手]
```

因此枪手菜单允许显示并选择射手动作；射手菜单不显示枪手动作。枪手选择射手动作后，成品仍是枪手芯片。

普通标签继续表达可多选特征，例如实体、能量体、进攻型、专属等，不承担职业互斥语义。

## 3. 动作与枪壳选择

### 3.1 动作数量

- 攻击手、射手、狙击手：恰好选择一个动作预设。
- 枪手：选择一个或两个动作预设。
- 其他主分类当前暂定恰好选择一个动作预设，后续按各自业务继续深化。
- 枪手的两个单形态动作合成为一枚芯片中的一个表达动作，并形成两个形态。

### 3.2 单选行为

- 单形态场景点击其他条目时直接切换选择。
- 再次点击当前条目不取消选择，行为等同单选按钮。

### 3.3 枪手双动作行为

- 选择顺序决定形态一、形态二以及默认形态。
- 条目使用 `①`、`②` 标记顺序。
- 选择两个动作后提供“交换形态顺序”。
- 第三个动作不能自动顶替已有动作，玩家必须先取消一个。
- 取消形态一时，形态二自动前移为形态一和默认形态。
- 动作顺序属于芯片组合的一部分：`小行星 / 毒蛇` 与 `毒蛇 / 小行星` 是不同组合。

### 3.4 预设内置多形态

动作是否自带多形态，以解释后的 `Expression.Modes.Count > 1` 判断，不增加额外标签。

- 内置多形态动作可以单独制造为枪手芯片。
- 内置多形态动作不能再参与枪手双动作组合。
- 选中内置多形态动作后，其他动作全部禁用。
- 已选择一个单形态动作时，内置多形态条目禁用，直到先取消现有动作。
- 内置多形态动作保持自身形态顺序和默认形态，不显示外部交换按钮。

### 3.5 枪壳

- 当前只有枪手显示枪壳选择，因为现有枪壳只兼容枪手。
- 枪壳选择位于动作列表上方，符合“先确定枪械载体，再选动作”的操作顺序。
- 切换枪壳保留动作选择，并立即重新计算预览、修正、材料和工作量。
- 缺少必需枪壳时不能加入队列。
- `GunClassDef` 的兼容声明改为职业列表，不再使用普通标签。

## 4. 双动作兼容与合成规则

### 4.1 结构兼容

两个单形态动作参与枪手组合时必须满足：

- `SlotRegion` 完全一致。
- `SlotOccupancy` 完全一致。
- 两者都不是内置多形态动作。
- 所有扩展和条件都能够按正式规则合并。

不兼容条目保持可见但置灰。条目右侧只显示一个最直接的原因；鼠标悬停显示全部差异。`i` 按钮仍只负责动作自身信息。

### 4.2 芯片级字段

- `CapacityCost`：相加。
- `ActivationCost`：相加。
- `ActivationDelayTicks`：取较大值。
- `DeactivationDelayTicks`：取较大值。
- 普通标签：去重并集。
- 激活互斥组：去重并集。
- 主分类和最终职业：使用玩家选择结果，不做并集。
- 枪壳身份：使用玩家选择的枪壳。

### 4.3 激活条件

- 相同语义的条件取更严格值。
- Trion 释放力最低要求取较大值。
- 相同技能的最低等级取较大值。
- 不同技能、不同条件类型各自保留，并且全部需要满足。
- 未来出现无法合并的条件类型时，组合直接判定为不兼容。

### 4.4 形态独立字段

各动作表达自己的 `UseCost` 和 `MinimumRequired`，不跨形态合并。两个形态分别保留各自数值。

### 4.5 扩展

- 单动作原样保留自身扩展。
- 双动作中的扩展类型必须显式提供组合规则。
- 任一扩展没有组合规则或组合失败，整个双动作组合不成立。
- 不默认拼接，也不让形态一覆盖形态二。

## 5. 成品命名

- 单动作：使用动作预设当前标签。
- 枪手双动作：`动作一 / 动作二`，顺序与形态顺序一致。
- 内置多形态：使用预设自身名称。
- 不允许玩家手动改名。
- 形态标签继续使用各动作自己的当前标签。
- 预设改名后，既有成品名称同步变化。

## 6. 制造面板

### 6.1 入口

- 选择芯片制造台后，通过“芯片制造”大型检视标签打开。
- 不使用殖民者右键菜单打开。
- 不再同时暴露一套重复的原版窄任务标签。
- 制造台停电、损坏时仍可规划订单；实际工作等待设施恢复。

### 6.2 布局

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 芯片制造    [武装] [防护] [能力] [状态] [被动]                             │
│             [攻击手] [射手] [枪手] [狙击手]                                │
├──────────────────────┬──────────────────────────────┬───────────────────────┤
│ 枪壳                 │ 成品芯片规格                 │ 制作提交              │
│ ○ 左轮手枪 [i]       │ 名称、分类、职业             │ 单枚材料              │
│ ○ 突击步枪 [i]       │ 槽位、占用、启停延迟         │ 总材料与库存情况      │
│                      │ Trion 成本、激活条件          │ 数量 [-] 10 [+]       │
│ 动作预设             │                              │ [加入制作队列]        │
│ ● ① 小行星 [i]       │ 枪壳修正 · 左轮手枪 [i]      ├───────────────────────┤
│ ● ② 毒蛇   [i]       │ 射程 →15格  伤害 ×...        │ 制作任务队列          │
│ ○ 猎犬     [i]       │                              │ 1. 小行星/毒蛇 ×10    │
│ ○ ...                 │ 形态一 · 小行星              │ 2. ...                 │
│ [交换形态顺序]       │ 射程  ██████░░  15格         │                       │
│                      │ 伤害  █████░░░  30           │                       │
│                      │                              │                       │
│                      │ 形态二 · 毒蛇                │                       │
│                      │ 射程  ███████░  20格         │                       │
└──────────────────────┴──────────────────────────────┴───────────────────────┘
```

非枪手场景不显示枪壳区域和交换按钮。枪手只有一个动作时，中栏只有一个形态块；不保留空白的形态二占位。

### 6.3 信息呈现

- 动作条目点击负责选择。
- `i` 按钮弹出临时信息卡，显示动作介绍和特殊机制。
- 主面板只显示制造决策需要的属性和参数。
- 枪壳修正在芯片级字段与形态字段之间显示一次。
- 绝对覆盖用 `→`，倍率修正用 `×`。
- 最终字段中受枪壳影响的值使用统一标记。
- 声音、枪口、视觉等非制造重点内容放入枪壳信息卡。

### 6.4 数值条形图

- 数值和条形图放在同一行，精确数值位于右侧。
- 同一字段使用固定标尺，保证切换条目时可直接比较。
- 命中率使用 0–100。
- 射程、伤害、速度使用稳定的固定上限。
- 越低越好的字段暂时只显示数值，不强行使用条形图。

### 6.5 草稿状态

- 当前打开面板期间，每条完整分类路径各保留一份临时草稿。
- 草稿记录枪壳、动作、顺序和数量。
- 切换分类后返回时恢复该路径草稿。
- 关闭面板或取消选择制造台后清空草稿。
- 订单加入队列后保留当前草稿，允许再次提交为另一张独立订单。

## 7. 制作提交与任务队列

- 右栏上部显示单枚材料、总材料、库存情况、数量和加入按钮。
- 材料不足只警告，不禁止加入队列，也不限制数量。
- 加入队列时不扣除或预留材料。
- 配置不完整、组合非法、数量非法或达到队列上限时才禁用按钮。
- 每次提交创建一张独立的有限数量订单，不自动合并。
- 当前阶段不提供“无限制作”“制作至库存”“指定制作者”“材料半径”“输出区”等额外配置。
- 每完成一枚，订单剩余数量减一；归零后保留“已完成”任务，不自动删除。
- 队列任务允许调整顺序、暂停、删除和修改剩余数量。
- 订单的主分类、职业、动作顺序和枪壳不能原地修改。
- “载入配置”只把订单选择复制回编辑区，原订单不变化。
- 成品逐枚制作，`stackLimit = 1`，采用原版 `DropOnFloor`，之后由正常搬运移入芯片储存区。

## 8. 材料与工作量

### 8.1 单枚材料

```text
通用配方基础材料
+ 每个已选动作的 costList
+ 枪壳 additionalCost（最多一次）
= 单枚芯片材料
```

相同 `ThingDef` 合并数量。界面总材料仅为单枚材料乘以制作数量；原版订单每次迭代仍只处理一枚。

基础材料属于唯一的通用芯片配方，用于表达芯片基底。确切材料和数值后续单独正式化。

### 8.2 工作量

```text
通用配方基础工作量
+ 每个已选动作的附加工作量
+ 枪壳附加工作量
= 单枚工作量
```

建议将现有 `additionalWorkTicks` 更名为 `additionalWorkAmount`，避免误导为固定现实时间。界面显示单枚工作量和总工作量，不承诺固定秒数。

### 8.3 动态材料与原版配方

- 全部芯片只使用一个通用 `RecipeDef`。
- 游戏加载时，汇总基础配方、动作预设、枪壳和既有组合记录实际引用过的材料种类，形成该配方的材料槽全集。
- `RecipeWorker.GetIngredientCount` 根据当前订单返回每个材料槽的数量。
- 仅对芯片订单增加一个小型补丁：数量为零的材料槽不交给原版材料搜索。
- 配方关闭混合材料；每个材料槽指向具体材料类型。
- 查找距离、禁用状态、预留、分堆、搬运、消耗和退款继续使用原版逻辑。

动作和枪壳的材料清单只能填写大于零的数量。它们可以引用新的具体材料 `ThingDef`；系统没有封闭的材料类型白名单。当前不支持“任意金属”之类材料类别替代。

## 9. 原版工作台架构

```text
Building_ChipFabricator : Building_WorkTable
    BillStack
        Bill_ChipProduction : Bill_ProductionWithUft
            芯片组合记录
    Thing_UnfinishedChip : Verse.UnfinishedThing
        芯片组合记录
    通用芯片 RecipeDef
```

保留原版：

- `BillStack` 的添加、删除、暂停和排序。
- `WorkGiver_DoBill` 的工作扫描。
- 材料搬运、预留、加工和工作经验。
- `Toils_Recipe` 的半成品、材料消耗、完成和产物落地流程。
- 半成品的材料持有、工作进度和存档结构。

三个必要适配：

1. 芯片订单忽略零数量材料槽。
2. 寻找芯片半成品时比较芯片组合记录，不要求原制作者一致。
3. 完成芯片半成品时允许任意合格殖民者继续。

原版已经会在同一地图寻找可达半成品，因此跨制造台续作不另建系统：

- 同地图、可达、可预留、未禁用。
- 任意兼容芯片制造台。
- 组合记录必须完全一致。
- 不跨地图、商队或世界对象搜索。

删除进行中的订单时，半成品保留在地图上。新建一张组合记录完全一致的订单后，可以在任意兼容制造台续作。玩家主动取消半成品仍使用原版 75% 返还规则；预设非法转化为废弃物时不返还。

## 10. 芯片组合记录与统一解析器

“芯片组合记录”只保存玩家选择：

```text
主分类 DefName
最终职业 DefName
按顺序保存的动作预设 DefName 列表
枪壳 DefName（可空）
上次正常解析出的成品名称（只作缺失时显示备用）
```

数量属于订单，不属于组合。属性、材料和工作量也不属于组合记录。

`BDP.Content.dll` 提供唯一解析入口：

```text
芯片组合记录
    ↓ 查找当前 Def
    ↓ 检查职业、形态、槽位、条件和扩展兼容
    ↓ 合成当前名称、配置、材料、工作量与失败原因
```

制造面板、未开工订单、半成品完成、成品读档和非法物品检测全部调用同一解析器。

同步规则：

- 未开工订单的名称、属性、材料和工作量随预设同步。
- 某枚半成品开工后，本枚已经投入的材料和总工作量固定，不再同步。
- 半成品最终产出的芯片配置仍按完成时的当前预设生成。
- 成品芯片只保存组合记录，名称、属性和运行配置随当前预设同步。
- 同一张多数量订单中，后续新开工的每一枚使用开工时的最新材料和工作量。

## 11. 存档、缺失与非法迁移

### 11.1 三种解析结果

```text
全部来源存在且组合合法
→ 正常同步

全部来源存在但组合明确非法
→ 物品一对一转化为统一废弃物
→ 队列任务直接移除

任一来源 Def 暂时缺失
→ 保留原对象和组合记录
→ 显示上次名称及“配置来源缺失”
→ 不转化、不删除
```

只有第二种结果允许不可逆转化。缺少来源可能只是依赖模组暂时未加载，不能永久破坏存档对象。

### 11.2 统一废弃物

非法成品、半成品和以后出现的其他芯片类物品全部一对一替换为同一种普通废弃物：

- 普通 `ThingDef`，不需要自定义物品类。
- 固定名称、固定描述。
- 可堆叠、搬运、储存、拆解和熔炼。
- 拆解／熔炼获得统一固定产物。
- 不可制作、安装、启用、购买或出售。
- 不保存原物品名称、组合、材料、工作量或制作进度。
- 半成品内部材料直接消失，不退款。
- 具体名称、描述、贴图和熔炼数值后续内容正式化时决定。

### 11.3 转化落点

- 地图物品：原格生成，原格不可放时放到最近可用格。
- 殖民者库存或携带物：中止相关操作，掉落在殖民者脚下。
- 边境触发体槽位：先安全卸除，再掉落在宿主附近。
- 建筑容器：掉落在建筑附近。
- 地图外容器：在原容器中一对一替换。
- 正在加工的非法半成品：中止当前工作，在工作地点生成废弃物。

### 11.4 汇总信件

- 普通数值同步不提示。
- 发生明确非法转化或非法订单移除时，只生成一封中性汇总信件。
- 信件统计任务、半成品、成品和其他物品数量。
- 信件关联当前地图上可定位的废弃物。
- 不逐个弹窗，不刷短消息。

## 12. 程序集职责

`BDP.Core.dll`：

- 中性的芯片配置提供者契约。
- 中性的芯片配置读取入口。
- 不认识制造台、动作预设、枪壳、订单或废弃物转化。

`BDP.Content.dll`：

- 芯片组合记录。
- 职业兼容、组合解析、字段合成和错误原因。
- 动态材料和工作量。
- 工作台、订单、半成品、成品来源组件。
- 制造面板与任务队列界面。
- 原版工作流的三个最小适配。
- 非法物品迁移、统一废弃物和汇总信件。

现有位于 Core 中、直接认识 `ChipPresetDef`、`GunClassDef` 或制造来源的构建逻辑应迁入 Content。Core 通过中性接口读取 Content 提供的当前芯片配置，不反向依赖 Content，也不使用反射。

## 13. 验证方案

### 13.1 定义加载校验

- 主分类、职业、动作和枪壳引用有效。
- 材料数量大于零。
- 枪手双动作满足槽位、形态和扩展规则。
- 内置多形态动作未参与双动作组合。
- 激活条件可以按正式规则合并。

### 13.2 自动测试

- 单动作、双动作、内置多形态的最终配置。
- 相加、取大值、去重、严格值和形态独立字段。
- 动作顺序交换后的名称和默认形态。
- 基础材料、动作材料、枪壳材料的累加。
- 组合记录的保存、读取和预设同步。
- 合法、来源缺失、明确非法三种解析结果。

### 13.3 DevHarness 游戏内实测

- 材料搜索、零数量材料槽、搬运、预留和不足等待。
- 任意殖民者及跨制造台续作。
- 半成品保存、取消、订单删除和重新加载。
- 队列有限数量、暂停、排序、删除和完成保留。
- 成品掉落与正常搬运。
- 地面、库存、槽位、建筑容器和地图外容器中的废弃物转化。
- 汇总信件只生成一次。

游戏内才能复现的问题使用可插拔诊断日志。临时日志和测试设施放在 DevHarness 或独立诊断模块中，验证完成后易于整体删除，不污染正式业务。

## 14. 延后正式化事项

以下内容不阻塞架构和交互实施，但实施前后需要单独正式化：

- 通用芯片基础材料及数量。
- 各动作、枪壳的正式材料和工作量。
- 制作技能门槛、经验倍率和队列上限数值。
- 条形图固定上限的最终数值。
- 防护、能力、状态、被动的专属制造规则。
- 统一废弃物的名称、描述、贴图、储存分类和熔炼产物。
