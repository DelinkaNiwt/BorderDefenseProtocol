# 互斥组修复与芯片激活音效设计

## 目标

修复制造成品芯片在运行时丢失 `ActivationExclusionGroups`（激活互斥组）的问题，并为 BDP 的通用芯片激活前摇补齐开始音效、持续音效、完成后音效和中断清理，使变色龙可以获得完整的前摇/后摇表现。

## 已确认事实

- `CompManufacturedChip`（制造成品组件）通过 `IChipInstanceDefinitionProvider` 提供动态 `ChipDefinitionConfig`（芯片定义配置）。
- `ChipDefinitionService.BuildManufacturedResult`（制造配置投影）复制装载区域、占槽方式和延迟，但漏掉 `ActivationExclusionGroups`。
- `TriggerService`（触发器服务）只在运行时契约的互斥组列表有内容时才能判断跨侧冲突。
- 原版 Ability（能力）前摇支持 `warmupStartSound`（前摇开始音效）、`warmupSound`（前摇持续音效）和 `warmupPreEndSound`（前摇结束前音效）；持续音效通过 `Sustainer`（持续音效实例）维护。
- BDP 当前已有激活延迟状态机和 UI 进度，但没有通用激活音效生命周期。

## 设计

### 互斥组修复

在 `BuildManufacturedResult` 的 `ChipLoadoutContract` 构造中复制动态 `loadout.ActivationExclusionGroups`。同时增加制造成品路径回归测试，确保静态 Def 路径和动态成品路径不会出现字段投影不一致。

### 激活音效设施

在 Core 的通用芯片装载配置中新增可选的激活音效声明，保持 Core 不包含变色龙业务：

- `ActivationWarmupStartSound`：进入 `Activating`（激活中）时播放一次。
- `ActivationWarmupLoopSound`：处于 `Activating` 时通过 `Sustainer` 持续维护。
- `ActivationWarmupEndSound`：芯片正式激活提交后播放一次。

音效只在冲突等待结束、真正进入激活前摇时开始；等待冲突期间不播放。前摇被新请求取消、芯片关闭、战斗体解除、Pawn（小人）离图或音效 Def（定义）失效时，必须停止并清理持续音效实例。激活延迟为 0 时跳过前摇音效阶段，避免瞬时创建又销毁声音。

### 变色龙配置

变色龙不引用皇权 DLC 的 `PsycastCastLoop`。在 BDP 尚未提供专属音频资源前，先使用不依赖 DLC 的原版 Core `SoundDef`（音效定义）：`Power_OnSmall`（开始）、`GasReleasing`（持续）和 `Power_OffSmall`（完成）。以后如果制作 BDP 专属音频，只需替换 XML 中的三个 SoundDef 引用，运行时设施不变。

### 数据流边界

新增字段必须同步经过以下路径：

```text
ChipLoadoutConfig / ChipActivationAudioConfig
  → ChipDefinitionContractResolver
  → ChipConfigurationMergeService
  → ChipDefinitionService.BuildManufacturedResult
  → Trigger 音效生命周期服务
```

### 验证重点

- 两枚同组 `MainSub + Single` 芯片分别位于主、副槽时，后激活者必须使先激活者关闭；激活中的待处理目标也只能保留最后一个。
- 非同组芯片不因音效设施产生额外互斥。
- 前摇循环音效只在 `Activating` 阶段存在，正式激活后停止并播放完成音效。
- 取消、切换、战斗体解除和存档恢复期间不得残留持续音效。
