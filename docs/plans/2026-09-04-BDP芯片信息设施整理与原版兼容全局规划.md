# BDP 芯片信息设施整理与原版兼容 Global Roadmap（全局路线图）

> **For Claude（供执行代理）:** REQUIRED SUB-SKILL（必须使用的子技能）: Use superpowers:executing-plans to implement this plan task-by-task（使用 executing-plans 技能逐项执行本规划拆出的实施计划）。

**Goal（目标）:** 在不推倒现有正确主干的前提下，完成 BDP 芯片信息设施的边界整理、原版物品信息卡接入、多形态兼容与后续技术债收束。

**Architecture（架构）:** 以 `ResolvedConfig`（最终有效配置）为成品事实源，以正规化表达契约为武器能力真值，以 `ChipInformationModel`（芯片信息模型）为玩家解释投影，并新增独立的原版武器统计投影。具体界面只消费，不拥有共享解析业务。

**Tech Stack（技术栈）:** RimWorld 1.6、C# 7.3、Verse、RimWorld 原版 `StatWorker`（属性计算器）与 `SpecialDisplayStats`（特殊信息条目）、PowerShell（命令脚本）、Development（开发诊断程序集）。

- 为每一阶段生成独立、可执行的实施计划提供索引。

## 三、路线 A：共享成品信息模型构建器抽取

### 目标

消除装配台借道制造预览获取信息模型的错位依赖。

### 交付物

- `ManufacturedChipInformationModelBuilder`（成品芯片信息模型构建器）；
- 制造预览改为调用共享构建器；
- 装配台详情改为直接调用共享构建器；
- 基础值、最终值、描述和来源链行为保持不变；
- 更新现有静态契约测试。

### 进入条件

- 基线提交存在；
- 当前相关测试结果已记录；
- 不同时修改文本格式化或图表布局。

### 完成标准

- `ChipAssemblyDetailModelBuilder`（装配台芯片详情模型构建器）不再调用 `ChipManufacturingPreviewBuilder.Build`（制造预览构建）。
- 制造预览类不再私有持有完整信息模型构建逻辑。
- Core 仍不依赖 Content。

## 四、路线 B：信息值格式化与基础查询整理

### 目标

共享类型值格式化，保留各界面的显示密度和特殊策略。

### 必做调查

- 对比制造预览与装配台对布尔、数字、百分比、持续时间、枚举、列表和单位的当前输出。
- 把差异分为“错误不一致”和“合理界面策略”。
- 为当前输出建立特征测试，禁止整理时静默改变玩家文字。

### 交付物

- `ChipInformationTextFormatter`（芯片信息文本格式化器）或等价的最小基础格式化设施；
- 显式的消费者格式化策略，不建立万能格式化配置系统；
- 制造预览、装配台和原版信息卡共用基础类型处理；
- 新增文本文案全部进入简体中文语言包。

### 后续事项

- 评估 `ChipInformationBlock.TryGetBlock`（信息块查询）和渲染器自有查找方法是否存在真实重复；只有出现第二个相同递归查询消费者时才抽取。

## 五、路线 C：表达能力分类与正规化契约只读面

### 目标

形成不依赖芯片分类、职业和名称的统一武器能力判定，并让 Content 能读取已经正规化的正式契约。

### 交付物

- `ChipExpressionCapabilityResolver`（芯片表达能力解析器）；
- `ChipExpressionContractSurfaceAccess`（表达契约读取面）；
- 定义验证、表达解释、信息适配中重复的基础近战/远程判断逐步收敛；
- 制造分类与职业约束继续留在 Content。

### 必测样本

- 防御分类但包含近战武器的 LightSoul（光魂）类样本；
- 只有远程增强、不能独立攻击的被动或附件类样本；
- 缺少投射物的非法远程条目；
- 缺少 `Tool`（近战工具）的非法近战条目；
- `WeaponMode`（武器模式）缺省但可从原版攻击属性判断的兼容样本。

### 未来事项

- 评估两套验证入口可共享的原子规则；不在本路线合并启动期内容验证与运行时契约验证。
- 评估 `ExpressionContractCache`（表达契约缓存）当前未被实际使用的问题；没有性能证据前不启用缓存。

## 六、路线 D：Development 原版武器投影诊断原型

### 目标

在不污染正式程序集的前提下，证明临时原版武器表面能驱动 RimWorld 原版统计逻辑。

### 原型必须验证

- 临时 `ThingDef`（物品定义）无需注册即可被目标 `StatWorker`（属性计算器）读取。
- 远程主要攻击属性能够触发原版射程、预热、伤害、护甲穿透、连射和停止力条目。
- BDP 的精度与冷却值能正确映射到原版武器 `StatBases`（属性基础值）。
- 投射物伤害、速度、停止力与伤害类型覆盖能反映到临时表面。
- 多 `Tool`（近战工具）能被原版近战平均伤害、平均护甲穿透和 DPS（每秒伤害）逻辑读取。
- 临时对象不进入 `DefDatabase`（定义数据库）、地图、容器和存档。

### 交付物

- Development 中可插拔诊断入口；
- 结构化日志；
- 典型芯片的“契约值—信息模型值—原版最终条目”对照记录；
- 明确哪些原版统计可以自然复用，哪些 BDP 特有字段只能作为普通自定义条目。

### 失败处理

原型失败时回到数据形状或原版调用条件追根因，不用 Harmony（运行时补丁框架）修改整张信息卡，也不改写显示文字掩盖错误。

## 七、路线 E：正式原版武器统计投影与信息卡接入

### 目标

让成品芯片在原版物品信息卡中按实际能力自然显示近战、远程和 BDP 普通说明。

### 交付物

- Core 中性的 `VanillaWeaponStatSurface`（原版武器统计表面）；
- Core 中性的表面工厂；
- Content 中的 `ManufacturedChipInfoCardPublisher`（成品芯片信息卡发布器）；
- `CompManufacturedChip.SpecialDisplayStats()` 正式接线；
- 信息卡字段白名单与语言键；
- 无武器能力时不生成武器条目。

### 正式规则

- 普通 BDP 信息读取 `ChipInformationModel`（芯片信息模型）。
- 武器数据读取正规化表达契约。
- 原版属性尽量由原版统计计算器生成。
- BDP 特有机制使用自定义 `StatDrawEntry`（属性显示条目），但不得冒充原版武器统计。
- 不修改共享 `BDP_Chip_Custom` 定义。

### 完成标准

- 远程芯片显示正确原版远程统计。
- 近战芯片显示正确原版近战统计。
- 同时包含两类能力时按已裁定策略显示。
- 非武器芯片不出现伪造武器分区。
- 只有增强模块的芯片不被误判为独立武器。

## 八、路线 F：多形态、当前状态和外部兼容策略

本路线当前不实施，但必须保留在全局规划中。

### 1. 多形态原版信息卡策略

待单独裁定：

- 松散物品显示默认形态主兼容表面；
- 已装载芯片是否显示当前形态；
- 无法取得当前装载状态时如何稳定回退；
- 是否在 BDP 自定义条目中补充其它形态摘要；
- 是否允许同一信息卡发布多套原版武器统计，以及如何避免重复标签混淆。

### 2. 多表达完整读取接口

- 原版和普通信息模组继续读取一套主兼容表面。
- BDP 自有详情继续读取完整 `ChipInformationModel`（芯片信息模型）和上下文。
- 愿意正式适配 BDP 的外部模组读取完整正规化契约或专门只读快照。
- 外部接口不公开内部缓存、窗口对象或可变集合。

### 3. 其它原版信息入口

后续评估是否需要统一覆盖：

- `InspectString`（选中物体检查文字）；
- `Tooltip`（悬浮提示）；
- 账单与制造选择信息；
- 交易、库存或第三方信息模组读取。

没有真实需求或自然扩展口时不提前接入。

## 九、路线 G：装配台详情渲染器内部拆分

本路线属于维护支线，不阻塞原版信息卡主线。

### 建议边界

- 总编排与尺寸测量；
- 概览和描述；
- 远程雷达与精度曲线；
- 近战工具与雷达；
- 护盾、Ability（能力）和 Hediff（健康状态）；
- 比较值读取；
- 文本格式化。

### 约束

- 只沿现有自然边界拆文件，不重新设计玩家布局。
- 图表计算仍属于 Content 展示业务，不移入 Core。
- 职业雷达标尺不包装成通用信息设施。
- 每次只拆一个边界并保持截图和高度测量结果稳定。

## 十、路线 H：远期技术债收束

本路线当前不实施，但纳入长期维护。

### 1. 信息解析内部拆分

- 评估超大表达信息块构建器是否按 Verb（攻击动作）、Projectile（投射物）、Melee Tool（近战工具）、Ability、Hediff 和模块拆成内部协作者。
- 只有文件维护成本持续出现时才拆；不得改变公开模型契约。

### 2. 验证规则收敛

- 区分启动期内容合法性验证与运行时契约验证。
- 抽取完全一致的原子规则和错误代码。
- 保留不同阶段需要的错误上下文与严重程度。

### 3. 缓存与性能

- 先用游戏内测量确认信息卡创建临时表面的实际成本。
- 如确有必要，再设计组合记录指纹、语言、Def 版本和模组加载顺序共同参与的缓存键。
- 缓存只保存只读投影，不保存运行中角色状态。

### 4. RimWorld 版本迁移

- 升级游戏版本时重新核对 `ThingDef.SpecialDisplayStats`（物品定义特殊统计）、`StatWorker`（属性计算器）和近战统计读取路径。
- 不假定 1.6 的内部读取字段永久不变。
- 通过 Development 诊断样本做版本差异对照。

### 5. 测试现代化

- 保留轻量源码边界测试。
- 为纯模型和分类规则补可执行行为测试。
- 为必须依赖游戏数据库的内容保留 Development 诊断和人工实测清单。
- 不把字符串存在性测试当作原版显示正确的充分证据。

## 十二、全局验收门槛

- 任何界面不得调用另一个具体界面来取得共享模型。
- 任何消费者不得从 `ChipInformationModel`（芯片信息模型）反向重建武器。
- 任何武器存在性判断不得依赖芯片名称、职业或分类。
- 任何原版武器统计不得由 BDP 复制公式后伪装成原版结果。
- 任何 Development 诊断不得被 Core 或 Content 依赖。
- 任何新缓存必须有测量证据和明确失效规则。
- 每条路线完成后单独记录日志和提交，失败尝试不得残留在最终工程。
