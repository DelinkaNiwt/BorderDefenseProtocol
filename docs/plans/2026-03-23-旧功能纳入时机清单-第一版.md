# 旧功能纳入时机清单（第一版）

## 目的

这份文档只回答一个问题：

- 旧 BDP 里已经存在或已经露出轮廓的那些功能，应该在什么时候纳入二次重构

它的目标不是做功能总表，
而是防止后面推进时出现两种错误：

- 该晚点做的东西抢跑
- 该早点留口的东西被忘掉

## 一、纳入时机分层

当前统一分成四层：

1. 第一阶段必须打通
2. 第一阶段只留接口
3. 第二阶段优先纳入
4. 后续阶段再考虑

判断标准只有三个：

- 它是不是最小闭环的一部分
- 它是不是会影响当前骨架接口
- 它是不是不早点留口，后面就会大改

## 二、第一阶段必须打通

### 1. Trion 基础资源语义

原因：

- 这是整个系统的底层前提
- 不先稳住，战斗体和表达都会悬空

### 2. 战斗体基础相位

范围：

- `Inactive`
- `Active`
- `Cooldown`
- 激活
- 主动解除

原因：

- 这是玩家实际使用 BDP 的第一层外壳

### 3. Main / Sub 基本槽位装载与激活

原因：

- 没有它就没有最基本的芯片运作

### 4. 单侧近战 / 远程表达

原因：

- 这是最小可验证表达通路

### 5. 默认主近战 / 主远程投影

原因：

- 手动入口和自动入口都要靠它

### 6. 手动入口、自动远程入口、自动近战入口

原因：

- 这是“回到 RimWorld”的最核心检验点

### 7. 主动解除收尾

原因：

- 收尾不完整，整个系统一定会脏

## 三、第一阶段只留接口

### 1. Ability 投影

原因：

- 它属于真实需求
- 但不属于第一条最小闭环
- 不早点留口，后面会改表达宿主边界

### 2. Hediff 投影

原因：

- 和 Ability 同理

### 3. 组合第三表达

原因：

- 这是旧 BDP 的重要方向
- 但它不是第一阶段起步闭环的阻塞项

### 4. FireMode 深化

原因：

- 它会影响很多表现
- 但现在先不让它把范围带炸

### 5. 因子值

原因：

- 它已经有清楚留口
- 但当前不需要让它反客为主

### 6. 独立测试模组接口

原因：

- 当前先在主模组里把接入口想清楚
- 真正做测试模组可以后移

## 四、第二阶段优先纳入

### 1. 组合第三表达真落地

原因：

- 它是表达系统是否真的高于攻击系统的重要检验

### 2. Ability 芯片完整链路

原因：

- 旧 BDP 已经有相关真实需求
- 但第一阶段不靠它验证主闭环

### 3. Hediff 芯片完整链路

原因：

- 和 Ability 同层

### 4. 特殊槽规则

原因：

- 它明显属于装载系统，但不是第一阶段硬阻塞

### 5. 双手锁定细节

原因：

- 它会影响装载切换规则
- 但可以在主闭环稳定后再补

### 6. 被动崩解完整链路

原因：

- 第一阶段先保住主动解除完整
- 被动崩解放到第二阶段更稳

## 五、后续阶段再考虑

### 1. 高级资源恢复细节

### 2. 复杂绘制与枪口表现

### 3. 全量调试展示

### 4. 外围扩展内容

### 5. 大量测试专用内容

### 6. 更完整的 GUI 重设计

原因：

- 它们都重要
- 但都不该压在重构起步阶段

## 六、当前路线结论

当前路线应该固定成：

1. 第一阶段先打通最小闭环
2. 第二阶段优先补表达系统的真正扩展力
3. 之后再补表现、工具、测试和外围内容

只要这个顺序不乱，
就比较不容易重新滑回“早期范围过大、后期维护失控”的老问题。
