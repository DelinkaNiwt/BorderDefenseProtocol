# 战斗体旧档安全解除设计

## 目标

当旧存档中的角色已经处于战斗体激活状态，但宿主换装事务缺失、残缺或与角色当前实物不一致时，解除战斗体必须优先保留角色此刻真实的服装、背包、需求与健康状态。完整的新旧事务继续按原流程恢复；当前 XML 配置不追溯改变已经开始的镜像或预设事务。

## 根因

- 战斗体阶段、宿主变换标记、快照捕获标记和前台服装记录分别存档，读档后没有一致性检查。
- 当前解除链只检查 `TransformationApplied`，没有同时确认 `HasSnapshot` 与 `SnapshotState.IsCaptured`。
- 前台服装恢复会移除角色当前穿着的全部服装，没有使用 `ActiveApparelThingIds` 限定本轮事务拥有的服装。
- 依赖原身快照的火焰、伤势和最终残留清理位于有效快照保护之外；无快照旧档可能误改角色当前健康状态。

## 采用方案

### 1. 宿主桥统一判断有效回滚凭据

完整回滚只在以下三个事实同时成立时执行：

```text
TransformationApplied
且 HasSnapshot
且 SnapshotState.IsCaptured
```

不以快照容器数量判断有效性，因为裸体、空背包或健康角色也可以产生合法空容器快照。

### 2. 前台服装按本轮编号回收

解除时只处理同时满足以下条件的服装：

- 当前确实穿在角色身上；
- 服装编号存在于 `ActiveApparelThingIds`。

镜像事务只销毁这些已记录副本；预设事务只把这些已记录服装放回预设容器。角色在战斗体期间由其他系统追加、或旧档中原本就在身上的未知服装不属于本轮事务，不能移除。

### 3. 无有效快照时安全降级

无有效回滚凭据的激活角色在解除时：

- 保留当前服装、背包、需求、火焰和普通伤势；
- 只移除 `BDP_CombatBodyActive` 战斗体激活标记；
- 快照或前台容器中仍然存在的未知实物不强行穿回，而是先转入不参与正常会话重置的旧档回收容器，再尝试归还角色当前背包；无背包或转移失败时继续随回收容器存档，不销毁；
- 清除宿主的事务布尔标记和前台激活编号，不销毁未知实物；
- 由现有会话链继续完成阶段切换和 Trion 释放；
- 下一次激活重新捕获完整快照，并使用届时 XML 配置的前台模式。

这里不在读档时补做预设换装，也不把当前状态伪造成进入前快照。旧档缺少足够事实，任何重建都会猜测并覆盖玩家当前实物。

### 4. 读档检查与解除前二次检查

读档完成后由宿主桥检查当前事务凭据：

- 完整事务保持原样；
- 标记为已变换但缺少有效快照时，将其收敛为安全解除状态，并输出一次包含角色与关键布尔值的警告；
- 不主动改变角色外观、背包、需求、健康或战斗体阶段。

解除入口仍重新判断有效凭据，形成第二道保护，避免读档后其他系统修改状态。

## 兼容边界

- 已保存的镜像事务继续使用存档中的 `IsMirrorOriginal` 解除，不读取当前 XML 模式反推。
- 已保存的预设事务继续把已记录预设服装收回容器。
- 裸体角色的完整快照仍可正常恢复。
- 本次不修改镜像原身生成、预设生成、扫描画面、Trion 结算和战斗体阶段机。
- 反向异常“阶段未激活但仍留有完整宿主事务”不在本次自动回滚，避免读档期间主动改动角色；保留警告与解除入口保护即可。

## 验证范围

- 缺失快照、快照标记不一致和完整快照三种回滚凭据。
- 前台恢复必须使用保存的服装编号，禁止遍历并移除全部穿着服装。
- 残缺事务容器中的原衣、原背包物品与前台服装必须在清理事务记录前转入独立回收容器；正常会话重置不得清空该容器。
- 安全降级不得调用原身快照恢复、火焰清理、普通伤势清理和最终残留清理。
- 完整镜像与完整预设事务仍按原次序恢复。
- 读档检查不得补换装或主动修改角色实物。
