# 远程增强武装构型白名单设计

## 目标

为 BDP 的开放式远程模块增强增加通用武装构型筛选能力，并让“铅弹·改”暂时只对左轮手枪构型生效。

本次不处理整体技术标识重命名；`BDP_GunClass_*` 的历史命名另行评估。

## 已确认事实

- `ChipArmamentFormDef` 是当前 BDP 的通用武装构型定义。
- `CompManufacturedChip.SourceVariantKey` 当前公开显式或逻辑生效的武装构型 `defName`。
- `FormalExpressionResult.SourceVariantKey` 会把该中性键带入 Core 表达结果。
- `RangedModuleAugmentationConfig` 已提供远程能力匹配和侧别作用范围；增强统一由 `ExpressionAugmentationResolver` 解析。
- 当前构型 DefName 为 `BDP_GunClass_Revolver`、`BDP_GunClass_AssaultRifle`、`BDP_GunClass_SubmachineGun`、`BDP_GunClass_Shotgun` 与隐藏默认型 `BDP_ArmamentForm_TrionCube`。其中 `BDP_GunClass_*` 是历史命名残留，语义上已经属于通用武装构型。

## 设计

### 1. 通用配置字段

在 Core 的 `RangedModuleAugmentationConfig` 增加 `AllowedSourceVariantKeys`（允许的来源变体键列表）。它不命名具体芯片，也不依赖 Content 的 `ChipArmamentFormDef` 类型。

- 列表为空或未声明：不限制来源构型，保持现有行为。
- 列表非空：目标结果的 `SourceVariantKey` 命中任一键才允许增强。
- 构型筛选与 `AppliesToCapability`、`Scope` 同时成立。
- 比较使用稳定字符串键，不解析玩家可见名称。

### 2. 复合结果边界

单侧结果直接比较自身 `SourceVariantKey`。复合结果继续通过已有 `CompositeExpressionReference`（复合结果来源引用）追溯单侧来源结果；名称前缀判断按参与复合结果的实际来源结果筛选。

远程模块仍只在现有单侧结果阶段挂载，双侧远程执行继续按各侧单侧结果继承。组合技模块继承不在本次扩大。

### 3. 铅弹配置

“铅弹·改”保持 `AllSides`（全侧）和既有被动表达，只新增：

```xml
<AllowedSourceVariantKeys>
  <li>BDP_GunClass_Revolver</li>
</AllowedSourceVariantKeys>
```

因此它对主侧或副侧的左轮手枪构型远程射击生效，对其它构型不生效。

新“铅弹”保持 `OppositeSide`（对侧）和当前其它配置，不增加构型白名单，仍对另一侧所有符合能力的远程射击生效。

### 4. 命名处理

本次只确认并记录 `BDP_GunClass_*` 与“武装构型”语义不一致，不改动这些 DefName、语言键或引用关系。后续整体重命名应独立检查 Def、语言包、源码引用、测试和历史文档边界。

## 验证

- 先增加白名单字段、解析分支和铅弹 XML 配置的失败测试，确认当前实现不能误通过。
- 实现后运行作用范围、武装构型白名单、双分支 Def、开放式增强、制造克隆、XML 与语言包回归测试。
- 串行构建 Core 与 Content Release，并运行 Core 隔离与 Development 边界检查。
- 本次仍不宣称已完成游戏内实测；组合技模块继承保持现有边界。
