# 风刃许可声明运行时诊断设计

## 目标

定位风刃 `BDP_Ability_Fujin` 的 `BDP.OperatorConsole.Active` 为什么没有出现在运行时 `FormalExpressionResult.DeclaredPermissionKeys` 中，为后续修复提供明确的断点证据。

## 已确认事实

- Trion 中继核心和操作员控制台的许可提供器均已登记。
- 风刃已经进入动态直视许可解析流程。
- 当前最终结果的 `declaredKeys` 为空，因此接收器选择退出，风刃继续要求直接目标视线。
- 工作区的风刃表达式配置已经声明 `BDP.OperatorConsole.Active`。

## 方案

第一阶段先观察 Trigger 投影生命周期的大方向，不直接判断许可字段的具体拷贝：

```text
投影重建进入 → 投影结果生成 → 战斗投影发布 → 宿主同步返回 → 风刃 Ability 读取结果
```

只有确认这条主链完整后，才使用下面两处表达式边界日志深入定位 `DeclaredPermissionKeys` 的字段丢失。

在两个边界增加限频 Development 诊断，使用现有 Core 中性 `BdpDiagnostics` 接口输出，由 `Development.dll` 接收：

1. **来源声明边界**：在 `DefaultExpressionSourceDeclarationProvider` 将契约条目翻译为来源声明后，记录芯片、条目、AbilityDef、直视要求和声明许可键。
2. **Ability 发布边界**：在 `DefaultExpressionAbilityHostSynchronizer` 将正式结果收集并绑定到 Pawn 的 Ability 前，记录结果 ID、AbilityDef、来源关系和最终声明许可键。

诊断只记录 Ability 来源和对应结果，并携带实际 `AbilityDefName` 供日志筛选；不把具体业务 DefName 写入 Core。不改变任何结果字段、不改变许可查询、不改变存档数据，也不让 Core 引用 Development。

## 诊断判读

```text
来源声明有许可键，Ability 发布无许可键：结果构建或发布链丢失字段
来源声明无许可键：芯片配置读取或契约解释链丢失字段
两个边界均有许可键，但直视访问仍为空：实际使用的结果不是该 Ability 发布结果
```

## 验证

- 先增加一个会因诊断缺失而失败的 Development smoke test。
- 实现诊断后运行该测试，确认通过。
- 构建 `BDP.Core`、`BDP.Content`、`BDP.Development`。
- 重新加载用户存档，触发一次风刃目标选择，检查两条边界日志与已有直视许可日志的结果 ID 是否一致。

## 范围外

- 本次不修正 `DeclaredPermissionKeys` 的业务来源。
- 本次不修改操作员控制台、Trion 中继核心或风刃的正式玩法逻辑。
- 本次不清理与该问题无关的现有 smoke test 基线失败。
