# BDP 芯片形态配置归位 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将芯片形态定义正式收敛为“统一表达目录＋形态引用条目标识”，把默认形态归入表达配置，并在不建立运行中形态状态的前提下支持默认形态解析。

**Architecture:** `ChipExpressionConfig（芯片表达配置）`保存全部条目、默认形态和形态选择表；解释器先完成统一结构校验，再按有效当前形态或默认形态挑选条目。`Loadout（装载配置）`不再携带形态信息，事项 07A 才负责当前形态、存读档、玩家切换和表达刷新。

**Tech Stack:** RimWorld 1.6、C# 7.3、.NET Framework 4.8、Verse、PowerShell 冒烟测试、MSBuild、XML。

### Step 1：建立一份中性结构校验结果

在单个文件中建立最小内部类型：

```csharp
internal sealed class ChipExpressionStructureValidation
{
    internal List<string> Errors = new List<string>();
    internal List<string> Warnings = new List<string>();
    internal bool IsValid => Errors.Count == 0;
}

internal static class ChipExpressionStructureValidator
{
    internal static ChipExpressionStructureValidation Validate(ChipExpressionConfig config)
    {
        // 只检查形态、标识、引用、顺序和父子结构。
    }
}
```

该类只做结构检查，不解析 Verb、Ability、Hediff 或 Trion 业务字段，不建立注册框架。

### Step 2：落实统一结构规则

校验器使用 `StringComparer.OrdinalIgnoreCase`统一比较键值，并按设计检查：

- 单形态禁止默认形态。
- 多形态强制有效默认形态。
- 条目和形态非空、标识非空且唯一。
- 形态至少引用一条表达。
- 引用存在且同形态不重复。
- 多形态条目至少被引用一次。
- Attached 子表达必须声明真实父条目。
- 单形态按 `Entries`顺序检查父先子后。
- 多形态按每个 `ActiveEntryIds`顺序检查父子同时出现且父在前。

错误信息必须指出形态键或条目标识，方便在 RimWorld 日志中直接定位。

### Step 3：让两条校验入口消费同一结果

`DefaultChipDefinitionValidator`：

- 删除旧 `ValidateModeEntries`及形态内嵌条目检查。
- 调用统一结构校验器。
- 把结构错误转换成 `ChipDefinitionValidationMessage`，代码统一使用 `ExpressionStructureInvalid`，归属 `Expression`块。
- 原有单条 Verb、Ability、Hediff、Passive 校验继续只遍历统一 `Entries`。

`DefaultChipExpressionContractInterpreter`：

- 解释前调用同一结构校验器。
- 把错误和警告复制进 `ChipExpressionContractValidationResult`。
- 结构无效时返回无效结果，不执行“尽量拼出部分表达”。

### Step 4：实现最终形态选择

解释器采用下列最小算法：

```text
没有 Modes
  -> 选择全部 Entries，最终 ModeKey 为空

存在 Modes
  -> 当前形态存在且有效：使用当前形态
  -> 当前形态为空：使用 DefaultModeKey
  -> 当前形态未知：回退 DefaultModeKey，并记录警告
  -> 按 ActiveEntryIds 顺序从 Entries 目录取出条目
  -> 每条正式契约记录最终采用的 ModeKey
```

删除：

- `TranslateModeOperations`
- `ApplyCurrentModeOperations`
- `ApplyModeOperations`
- `ReplaceEntry`
- `DisableEntry`
- `FindEntryIndex`
- `TranslateOperationKind`

保留并复用现有 `TranslateEntry`、Verb 正规化、展示、Trion、条件、远程模块和关系字段翻译。

契约中的 `Modes`复制静态 `ModeKey + ActiveEntryIds`，不携带可变配置列表引用。

### Step 5：规范缓存键

进入 `ExpressionContractCache`前先计算有效形态键：

- 单形态使用空键。
- 多形态的空当前键使用默认形态键。
- 未知当前键也使用默认形态键。

这样“空当前形态”和“显式等于默认形态”共用同一缓存项；不同有效形态继续严格隔离。

不修改 `CompTriggerBody.GetChipModeKey()`，它在事项 07 中继续返回空值。
