# 毒蛇自动路径模式移植设计（第一版）

## 1. 文档范围

- 文档类型：业务模块设计文档。
- 目标样本：DevHarness（测试模组）里的毒蛇路线引导模块。
- 当前现况：新 BDP 的 `PathLatchModule（路线引导模块）` 已有手动锚点路径，自动路径模式此前只保留需求口径，没有移植算法与确认分支。
- 实现位置：`BorderDefenseProtocol.DevHarness（伴生测试模组）`。
- 主模组约束：
  - 不新增毒蛇专用概念。
  - 不新增锚点、自动路径、绕障等业务结构。
  - 只继续提供现有中性远程阶段和投射物续段能力。

## 2. 设计目标

- 补回旧毒蛇的自动路径本质需求。
- 保持新 BDP 的路线引导架构：自动路径最后仍冻结成普通锚点路径。
- 手动锚点优先；玩家显式设置锚点时，自动路径不介入。
- 目标可直视且没有手动锚点时，保持普通直射。
- 目标不可直视且没有手动锚点时，尝试生成绕障锚点。
- 自动路径失败时拒绝确认，不伪造命中，不强行穿墙。

## 3. 非目标

- 不把旧 BDP 的 `Verb（动词宿主）` 胶水层原样搬回。
- 不照搬旧 `ShotPipeline（射击流水线）` 里的半成品自动路径模块。
- 不做全局迷宫寻路。
- 不引入 `A*（A星全局寻路）` 作为主逻辑。
- 不保证复杂墙阵、很厚的复合障碍、封闭迷宫都能绕开。
- 不让自动路径修改命中、伤害、沿途碰撞或爆炸语义。

## 4. 核心规则

自动路径模式只补三条行为：

```text
1. 最终目标可直视 + 没有手动锚点
   -> 普通直射

2. 最终目标不可直视 + 没有手动锚点
   -> 自动路径：计算绕障锚点

3. 玩家已经手动设置锚点
   -> 手动路径优先，自动路径不介入
```

这里的关键点是：

- 自动路径不是一种新投射物模式。
- 自动路径不是一次独立飞行协议。
- 自动路径只是在确认前生成一组系统锚点。
- 生成成功后，后续 `ProjectileInit（投射物初始化）`、`Arrival（到达阶段）`、续段飞行都按现有普通锚点路径消费。

## 5. 旧设计保留与舍弃

### 5.1 保留

- 旧 `ObstacleRouter（障碍绕行器）` 的本质算法：
  - 找到射线上的第一个阻挡格。
  - 从阻挡格扩展一团障碍物。
  - 取障碍团外轮廓候选点。
  - 按左右两侧分别选择少量锚点。
  - 逐段验证 `LOS（直线可视）` 是否成立。
- 旧设计的失败边界：
  - 能绕挡在射线上的墙或障碍团。
  - 不承诺解决复杂迷宫。
  - 算不出合法路线就失败。
- 旧设计的输出形态：
  - 左路和右路都可尝试。
  - 成功路线最后变成锚点列表。

### 5.2 舍弃

- 旧 `Verb_BDPRangedBase.TryPrepareAutoRouteForCast()` 里替换施法目标的写法。
- 旧 `Bullet_BDP.InjectShotData()` 里按 projectile id 选择左右路的胶水写法。
- 旧 `AutoRouteAimModule（自动路径瞄准模块）` 与 `LosCheckModule（直线检查模块）` 的冲突式设计。
- 旧预览里硬编码 `maxDepth=3`、`anchorsPerWall=3` 的做法。

## 6. 新架构落点

### 6.1 DevHarness 新增业务对象

- `PathLatchAutoRouteResolver（路线引导自动路径解析器）`
  - 只负责输入起点、终点、地图和配置，输出自动锚点候选。
  - 不读写模块私有状态。
  - 不接触投射物实例。

- `PathLatchAutoRouteResult（路线引导自动路径结果）`
  - 表示是否成功。
  - 保存选中的锚点列表。
  - 保存失败原因，供预览与确认使用。

- `PathLatchPathSource（路径来源）`
  - `Direct（直射）`
  - `Manual（手动）`
  - `Auto（自动）`
  - 只用于 DevHarness 自查、日志和 smoke test（烟雾测试），不进入主模组协议。

### 6.2 现有对象补字段

- `PathLatchConfirmedSnapshot（确认快照）`
  - 增加 `PathSource（路径来源）`。
  - 自动模式成功时，`Anchors（锚点列表）` 写入系统计算出的锚点。

- `PathLatchPathSnapshotContext（投射物路径上下文）`
  - 增加 `PathSource（路径来源）`，方便飞行期诊断。
  - 不改变现有分段消费规则。

- `PathLatchConfig（路线引导配置）`
  - 增加 `EnableAutoRoute（启用自动路径）`。
  - 增加 `AutoRouteMaxDepth（自动路径最大递归深度）`。
  - 增加 `AutoRouteAnchorsPerWall（每个障碍团最多锚点数）`。
  - 增加 `AutoRouteMaxObstacleCells（最大障碍团格数）`。

## 7. Targeting 与 Preview

### 7.1 Targeting（目标选择）

当前 `PathLatchModule` 已在 `ApplyCurrentTargetLegality（当前目标合法性回写）` 里统一裁定鼠标候选点。

自动路径加入后，最终目标候选的合法性改成：

- 有手动锚点：
  - 继续按当前最后一段 `LOS（直线可视）` 判断。
- 无手动锚点且目标可直视：
  - 合法，走直射。
- 无手动锚点且目标不可直视：
  - 尝试自动路径。
  - 自动路径成功则合法。
  - 自动路径失败则非法。

### 7.2 Preview（预览）

预览只显示事实，不提前写状态：

- 有手动锚点：
  - 保持现有白线/红线预览。
- 无手动锚点且目标可直视：
  - 显示普通直线。
- 无手动锚点且目标不可直视：
  - 自动路径成功：显示系统锚点折线。
  - 自动路径失败：显示红线或拒绝原因。

预览可以按当前鼠标目标重复计算，也可以加很小的模块内缓存，但缓存只能属于 `PathLatchModule（路线引导模块）` 自己，不进入主模组。

## 8. Confirm（确认）

确认阶段是自动路径真正冻结的位置。

流程：

```text
确认最终目标
  -> 验最终目标类型与射程
  -> 判断是否已有手动锚点
     -> 有：冻结手动锚点，PathSource = Manual
     -> 无：判断射手到最终目标 LOS
        -> 可视：不写自动锚点，PathSource = Direct
        -> 不可视：运行 AutoRoute
           -> 成功：把自动锚点写入 ConfirmedSnapshot.Anchors，PathSource = Auto
           -> 失败：Reject（拒绝）
```

失败策略固定为拒绝：

- 不回退成普通直射。
- 不把最终目标强塞给发射目标。
- 不让后续飞行层承担“也许能命中”的猜测。

## 9. ProjectileInit 与 Arrival

这两阶段原则上不需要知道路径来源。

- `ProjectileInit（投射物初始化）`
  - 继续通过 `PathLatchSegmentResolver.TryResolveFirstLegTarget()` 找首段目标。
  - 自动路径成功后，首段目标就是第一个系统锚点。
  - `AimTarget（瞄准目标）` 和 `CurrentTarget（正式目标）` 仍保持最终目标，避免锚点污染命中语义。

- `Arrival（到达阶段）`
  - 继续用现有 `CurrentLegIndex（当前段序号）` 推进。
  - 继续生成 `NextFlightPathSnapshot（下一段飞行路径快照）`。
  - 不因路径来源区分手动或自动。

这正是旧设计里最重要的部分：飞行层不关心锚点来自玩家还是系统。

## 10. 算法边界

推荐先用旧 `ObstacleRouter（障碍绕行器）` 的简化移植版：

1. 用 `GenSight.LineOfSight（原版直线可视）` 或等价格线遍历确认直射不通。
2. 找到第一处阻挡格。
3. 用 `BFS（广度优先搜索）` 扩展阻挡格周围不可视/不可通过的障碍团。
4. 找障碍团外侧可通行轮廓点。
5. 按射线左右分组。
6. 每侧选少量候选锚点。
7. 递归尝试到 `AutoRouteMaxDepth（自动路径最大深度）`。
8. 每条候选路线都必须逐段 `LOS（直线可视）` 成立。

补充约束：

- 候选锚点必须在地图内。
- 候选锚点必须可通行。
- 障碍团扩展必须有上限。
- 结果必须稳定，不能同一局面随机变路。
- 算法失败是正常结果，不是异常。

## 11. 验证口径

至少锁定下面几类 smoke test（烟雾测试）：

- 当前主模组源码不出现 `PathLatchAutoRoute`、`ObstacleRouter`、`AutoRoute` 业务实现。
- `PathLatchConfig（路线引导配置）` 暴露自动路径配置，并能 clone（复制）配置。
- 没有手动锚点且目标可直视时，不生成自动锚点。
- 没有手动锚点且目标不可直视时，会调用自动路径解析器。
- 自动路径成功时，确认快照里的 `Anchors（锚点列表）` 来自自动路径，`PathSource = Auto`。
- 玩家手动设置锚点时，不调用自动路径解析器，`PathSource = Manual`。
- 自动路径失败时，确认被拒绝，并出现清楚的中文拒绝原因。
- 自动路径输出的每一段都必须通过 `LOS（直线可视）` 校验。

## 12. 结论

这次移植是自然的，但不应该做旧代码复刻。

合理路线是：

- 把旧自动路径的本质算法迁到 DevHarness。
- 把结果落成现有 `PathLatch（路线引导）` 的普通锚点列表。
- 保持手动优先。
- 保持失败拒绝。
- 保持主模组中性。

这样既满足旧毒蛇自动绕障的玩家需求，也符合新 BDP “业务留在测试模组，主模组只做中性设施”的架构原则。
