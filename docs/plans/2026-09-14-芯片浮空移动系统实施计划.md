# 芯片浮空移动系统 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在 BDP `Content.dll（正式内容程序集）`中加入由“浮空”芯片提供的三态浮空移动，使 Pawn（角色）继续执行原版工作与移动，同时支持露天跨障碍、全屋顶禁飞、可反转起降动画、个体偏好保存和安全降落。

**Architecture:** 芯片通过既有表达系统只发布 `BDP_FloatingFlight` 被动能力；`GameComponent（存档级组件）`保存 Pawn 个体偏好与动画锚点，实际飞行唯一由 `BDP_Hediff_FloatingFlight` 是否存在决定。寻路继续使用原版 `PathFinder（寻路器）`和 `Pawn_PathFollower（路径跟随器）`，仅为两套 BDP 网格、浮空 Pawn 的可达性、合法终点、跨格阻挡与屋顶交接增加窄范围 Harmony（补丁库）接点。

**Tech Stack:** RimWorld 1.6、C#、XML（可扩展标记语言）Def、Harmony、Verse/RimWorld API（接口）、PowerShell 静态冒烟测试、Development.dll 游戏内诊断。

## 统一命名与不变量

后续任务统一使用以下名字，避免不同文件各自发明术语：

```csharp
// 个体长期偏好；关闭也是完整偏好。
public enum FloatingFlightMode
{
    Off = 0,
    MoveOnly = 1,
    Always = 2
}

// 当前一次寻路应选择的网格，不等同于是否实际飞行。
internal enum FloatingFlightPathKind
{
    Vanilla = 0,
    Hybrid = 1,
    Always = 2
}
```

必须始终成立：

1. `FloatingFlightUtility.IsActuallyFlying(pawn)` 只检查 `BDP_Hediff_FloatingFlight`，不得读取偏好或动画高度。
2. 不保存第二份 `isFlying`；动画目标由 Hediff 是否存在推导。
3. `MoveOnly` 只看原版 `pawn.pather.Moving`，不看攻击、工作类型或瞬时位移。
4. 路径中间格可跨越露天障碍，终点必须通过原版地面可站立检查；`Always` 的终点还必须无屋顶。
5. 露天飞行段不加入地面、积雪、建筑和门的路线代价，但保留火焰、允许区域、危险、Pawn 碰撞和原版预留。
6. 任何屋顶都禁飞，不区分人工屋顶、薄岩顶或山岩顶。
7. 移动速度只来自 Hediff 的原版 `MoveSpeed × 2.0` 属性倍率，不再补一套每格移动耗时算法。

**Step 3: 实现状态控制器**

公共行为收敛到以下方法：

```csharp
public static void Reconcile(Pawn pawn, FloatingFlightRecord record);
public static void RequestActualFlight(Pawn pawn, FloatingFlightRecord record, bool shouldFly);
public static float GetPresentationFactor(Pawn pawn, FloatingFlightRecord record, int tick);

public static void NotifyHediffRemoved(Pawn pawn);
public static void ForceGroundedImmediately(Pawn pawn, FloatingFlightRecord record);
```

线性插值公式：

```csharp
float target = FloatingFlightUtility.IsActuallyFlying(pawn) ? 1f : 0f;
float elapsed = Mathf.Max(0, tick - record.TransitionStartTick);
float duration = Mathf.Max(1, settings.transitionTicks);
return Mathf.MoveTowards(record.TransitionStartFactor, target, elapsed / duration);
```

Hediff 增删前先按旧目标计算当前高度，写回 `TransitionStartFactor` 和 `TransitionStartTick`；`Hediff_FloatingFlight.PostAdd/PostRemoved` 负责兜住开发者工具或其他代码直接增删 Hediff 的情况。控制器自身增删时使用一个短生命周期递归保护，避免回调重复改锚点。

`Reconcile` 规则：

- `Off`：合法格立即请求非飞行；非法格启动安全降落。
- `MoveOnly`：移动且当前格无屋顶时请求飞行；否则请求非飞行。
- `Always`：无屋顶请求飞行；屋顶下压制为非飞行。
- 能力丢失与未征召都进入 `Off` 规则，不改偏好。
- Pawn 倒地、死亡、未生成或离图时立即归地；死亡后记录不删。

安全降落先沿 `curPath.Peek(i)` 找第一个原版地面合法格；没有可用前向路径时，用 BDP 飞行网格求最近合法格并把恢复节点装入当前 `PawnPath`，保留原 `destination`、`peMode`、Job 和目标。恢复路径结束后由原跟随器继续原目标；若原目标已失效，只停止路径，不伪造 Job 到达通知。不得新增玩家可见 Job 或独立浮空移动命令。

`RemoveDiscardedRecords` 只清理 `Destroyed/Discarded` 且不可恢复的永久对象；普通死亡尸体与世界 Pawn 保留。
