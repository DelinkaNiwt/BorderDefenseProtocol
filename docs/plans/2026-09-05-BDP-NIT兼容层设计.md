# BDP NIT 兼容层设计

> 状态：已获用户批准，进入实施计划阶段。

## 1. 目标

新增 `BDP.Compatibility.dll`（BDP 外部兼容程序集），为 Nice Inventory Tab（漂亮物品栏页，简称 NIT）提供可选加载的显示适配，让 NIT 在查看 BDP 触发体时读取当前小人此刻实际表达的自动攻击属性；不修改触发体的实际战斗逻辑、原版 `ThingDef`（物品定义）、`tools`（近战工具）或 `verbs`（攻击动作）。

## 2. 已确认事实

1. BDP 当前原版信息面板适配通过 `ThingWithComps.SpecialDisplayStats`（原版信息条目入口）发布动态武器属性。
2. NIT 的装备栏不是读取 `SpecialDisplayStats`，而是从实际 `Thing`（物品实例）、`ThingDef`、`tools`、`verbs` 和原版统计计算自己的显示数据。
3. BDP 触发体的静态定义包含占位近战工具，动态远程表达不会改变触发体静态 `IsMeleeWeapon` / `IsRangedWeapon`（武器分类判断）。
4. 因此 NIT 需要独立的兼容显示适配；不能通过改写 `ThingDef` 来解决。

## 3. 总体架构

```text
BDP.Core.dll
  ├─ 当前自动攻击属性投影（中性、只读）
  └─ BDP.Content.dll
       └─ 原版信息面板适配

BDP.Compatibility.dll
  ├─ 兼容层启动与生命周期
  ├─ 外部模组发现、版本检查、适配器隔离
  ├─ NIT 适配器
  └─ 兼容性诊断
```

依赖方向：

```text
BDP.Compatibility.dll → BDP.Core.dll
BDP.Compatibility.dll -X→ NIT 编译时引用
BDP.Compatibility.dll -X→ BDP.Content.dll
```

NIT 通过运行时反射（运行时类型发现）和 Harmony（运行时补丁）接入，不写入 BDP 编译时依赖。

## 4. 中性属性投影

兼容层不从原版 `StatDrawEntry`（已经格式化好的文字条目）反向解析数字，而是读取共享的中性自动攻击属性快照。

快照至少包含：

- 当前攻击类型：近战或远程。
- 当前自动攻击标识与显示名称。
- 最终伤害。
- 最终护甲穿透。
- 远程射程、瞄准时间、远程冷却和精度字段（存在才提供）。
- 近战攻击次数、连击间隔和按完整连击周期计算的近战每秒伤害。
- BDP 表达投影版本号，用于刷新失效判断。

数据流：

```text
当前小人 + 当前触发体
  → BDP 自动攻击选择结果
  → 只读属性快照
       ├─ 原版信息面板条目
       └─ NIT 显示字段
```

如果当前表达不存在、尚未完成或无法投影，兼容层回退 NIT 原本显示逻辑。

## 5. NIT 适配边界

NIT 当前装备栏的属性缓存和绘制分支是分开的，因此适配层分成两个边界：

1. 数据边界：在 NIT `EquippedItem.UpdateStats()`（装备数据刷新）之后，把 BDP 最终属性映射到 NIT 已有显示数据。
2. 显示类型边界：在 NIT 选择 `DrawWeaponInfo()`（武器信息绘制分支）时，用 BDP 快照的实际攻击类型决定显示远程或近战分支。

只改 NIT 的显示结果，不改 `ThingDef.IsMeleeWeapon` 或 `ThingDef.IsRangedWeapon`。

第一阶段只复用 NIT 已有的显示行；NIT 没有的精度四档、额外远程冷却等字段不在本阶段凭空扩展界面。

## 6. 可选加载和版本策略

启动时逐个处理兼容适配器：

```text
发现 NIT 包和程序集
  → 检查程序集版本
  → 查找必需类型、方法和参数签名
  → 全部通过：安装 NIT 适配补丁
  → 任一关键项失败：只禁用 NIT 适配器
```

兼容层不能因为 NIT 未安装、NIT 更新或 NIT 结构异常而阻塞 BDP 正式程序集加载。

不使用带 NIT 类型参数的静态 Harmony 特性，避免产生硬程序集依赖；采用动态目标解析，并要求补丁安装幂等（重复启动不会重复打补丁）。

## 7. 故障隔离与回退

| 情况 | 处理 |
| --- | --- |
| 未安装 NIT | 不安装补丁，BDP 正常运行 |
| NIT 版本未知 | 默认不安装补丁 |
| 关键类型或方法缺失 | 禁用 NIT 适配器 |
| 普通武器 | 完全走 NIT 原逻辑 |
| 触发体没有有效自动攻击 | 回退 NIT 原逻辑 |
| BDP 投影失败 | 回退 NIT 原逻辑 |
| 单次适配异常 | 保留 NIT 原显示，记录一次诊断 |
| 持续适配异常 | 关闭当前游戏会话的 NIT 适配器 |

兼容层不得抛异常穿透 NIT UI（用户界面）调用栈；不得修改 `DefDatabase`（原版定义数据库）、存档字段或真实战斗对象。

## 8. 刷新和上下文

NIT 传入的 `Thing` 和 `Pawn`（小人）是适配的上下文来源。兼容层不能使用全局“当前小人”状态。

BDP 表达投影版本变化时，NIT 的显示缓存必须重新读取；没有变化时可以复用当前刷新周期的只读快照。第一版优先保证正确性，避免建立跨存档的静态强引用缓存。

## 9. 诊断

正式版本只记录一次性的简短事件：

- 检测到 NIT。
- NIT 版本不支持。
- 关键类型或方法缺失。
- BDP 投影不可用。
- NIT 适配发生异常并回退。
- NIT 适配器已关闭。

详细类型、方法、补丁和投影信息放入 `Development.dll` 可插拔诊断，不污染正式业务。

## 10. 未来其它模组

第一版建立最小通用适配器宿主，不提前搭建大型插件平台：

```text
CompatibilityHost
  ├─ NITAdapter
  └─ 未来的其它适配器
```

只有当未来某个适配器拥有独立依赖、独立发布节奏或明显不同的生命周期时，才考虑拆成单独 DLL（动态链接库）。

## 11. 验证范围

必须覆盖：

1. 没安装 NIT 时 BDP 正常加载。
2. 安装支持版本 NIT 时兼容层成功接入。
3. 普通原版武器显示不受影响。
4. BDP 近战自动攻击显示当前工具的最终多击 DPS 和护甲穿透。
5. BDP 远程自动攻击进入远程显示分支并显示最终属性。
6. 芯片切换或表达版本变化后 NIT 不保留旧属性。
7. 表达无效、NIT 版本未知、方法缺失和运行时异常均回退原逻辑。
8. 原版信息面板与 NIT 使用同一属性来源，实际攻击行为和 `ThingDef` 分类不改变。
