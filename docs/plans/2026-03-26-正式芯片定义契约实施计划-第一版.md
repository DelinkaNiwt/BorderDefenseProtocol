**Goal:** 在主模组内正式建立独立的芯片定义层，完成“正式芯片识别、最低合法校验、统一分块读取、表达块正式接入”这一整条主骨架，让各系统不再各自直接读取芯片 Def 原始写法。

**Architecture:** 本次不是给测试模组补入口，而是在主模组上位层新增 `Core/Chips` 骨架。该骨架只负责正式输入、正式解释、正式校验、正式读取，不持有运行时真值；Trigger、Expressions、Resource 等系统只能通过芯片定义层读取自己被允许读取的声明块。现有表达系统保留为表达块的专业消费者，但其上游输入改由芯片定义层统一供给。

**Tech Stack:** C# 7.3, .NET Framework 4.8, RimWorld `ThingDef` / `ThingWithComps` / `DefModExtension`, XML Def, `dotnet msbuild`

## 执行提示词

### 背景

- 当前主模组已经有“芯片作为物品”的事实，也已经有一部分表达契约。
- 但主模组还没有独立成立“正式芯片定义层”，导致各系统仍可能各自读取 Def 或把表达契约误当整枚芯片契约。
- 本计划的目标不是先让某个功能跑出来，而是先把主模组正式承认的芯片输入边界封干净。

### 约束

- 主模组绝不能知道测试模组存在。
- 不允许反射、Harmony 绕过、`internal` 直连泄漏、`InternalsVisibleTo`、直接摸私有实现。
- 不允许把运行结果塞回芯片定义层。
- 不允许为了少改代码而继续让各系统直接读 Def 原始写法。
- 文档、代码、验证必须同步推进；不能只改代码不回写边界。
- 中文文件处理必须遵守 UTF-8 读取和小块补丁规则。

### 需求

- 主模组能正式回答“这是不是一枚 BDP 芯片”。
- 主模组能正式回答“这枚芯片最低是否合法”。
- 主模组内部各系统能从统一入口读取 `Identity / Loadout / Expression / Resource / Extension` 五块声明。
- 表达系统不再直接把 Def 原始配置当作自己唯一上游入口，而是改读芯片定义层给出的表达块正式引用。
- 现有按钮链路和自动攻击链路不用在本计划里优雅重构成动作表面，但必须完成记账和接线兼容。

### 目标

- 新增 `Core/Chips/Config`
- 新增 `Core/Chips/Contract`
- 新增 `Core/Chips/Validation`
- 新增 `Core/Chips/Access`
- 让表达系统通过芯片定义层接入表达块
- 保持主模组和 DevHarness 可编译
- 回写文档、计划、日志

## 总执行原则

- 芯片定义层只回答静态声明与最低合法性，不回答运行真值。
- 芯片定义层应暴露正式声明结果，不暴露作者原始写法细节给下游系统。
- 各系统统一走 `Access` 层，不直接 new 芯片定义层内部实现。
- 不重做表达系统内部骨架；只改它的正式上游输入来源。
- 先建立最小完整骨架，再做必要迁移，不同时发明第二层新需求。
- 每个阶段都必须可编译。
- 每个阶段都必须回写日志。

## 完成标准

本计划完成时，应同时满足：

- 主模组存在独立的 `Core/Chips` 目录骨架。
- 主模组存在“正式芯片识别”结果对象与读取入口。
- 主模组存在整枚芯片最低合法性校验结果对象。
- 主模组存在五块正式声明对象或正式块句柄。
- Trigger / Expressions / Resource 至少在读取边界上改成“先过芯片定义层”。
- 表达系统已有正式接入芯片定义层的路径。
- 现有“芯片到按钮 / 自动攻击”的桥接链不被打断。
- 主模组与 DevHarness 均可编译。
- 文档、日志与计划已同步回写。
