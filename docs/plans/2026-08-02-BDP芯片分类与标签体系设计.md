# BDP 芯片分类与标签体系设计

## 目标

在不把具体业务规则塞进 Core 的前提下，为正式芯片建立一个稳定的主分类和可扩展的多标签画像，并为弧月、旋空、护盾三枚正式芯片补齐已确认的分类与标签。

## 已确认的正式画像

| 芯片 | 主分类 | 标签 |
|---|---|---|
| 弧月 | 武装 | 攻击手用、实体 |
| 旋空 | 能力 | 进攻型、弧月专属、能量体 |
| 护盾 | 防护 | 能量体 |

“旋空弧月”是弧月与旋空形成的组合技及其能力结果，不是单独的芯片分类对象。

## 结构规则

1. 每枚芯片必须有且只能有一个主分类。
2. 每枚芯片可以有零个或多个标签；标签必须引用已登记的 `ChipTagDef`，不允许自由文本。
3. 同一枚芯片的标签不能重复；标签顺序保持作者声明顺序，供稳定显示和诊断使用。
4. 主分类和标签只描述芯片画像，不直接决定槽位、激活门槛、Trion 费用或表达行为。
5. Core 只提供 `ChipCategoryDef`、`ChipTagDef`、配置翻译、契约快照和通用校验；具体分类和标签 Def 由 Content 提供。
6. 主模组不再引用 `BDP_Dev_UnreviewedChip`；候选库仍为尚未迁移的芯片保留该分类，直到候选模组最终退役。

## 正式 Def 标识

### 主分类

- `BDP_ChipCategory_Weapon`：武装
- `BDP_ChipCategory_Ability`：能力
- `BDP_ChipCategory_Defense`：防护

### 标签

- `BDP_ChipTag_AttackerUse`：攻击手用
- `BDP_ChipTag_Entity`：实体
- `BDP_ChipTag_Offensive`：进攻型
- `BDP_ChipTag_KogetsuExclusive`：弧月专属
- `BDP_ChipTag_EnergyForm`：能量体

## XML 形状

```xml
<Profile>
  <Category>BDP_ChipCategory_Weapon</Category>
  <Tags>
    <li>BDP_ChipTag_AttackerUse</li>
    <li>BDP_ChipTag_Entity</li>
  </Tags>
</Profile>
```

`Tags` 是画像元数据集合，不与表达条目中的 `Tags` 混用；前者描述芯片本体，后者描述具体表达条目。

## 本次迁移的玩家文案

- 弧月芯片：弧月。
- 旋空芯片：旋空。
- 旋空弧月能力、组合技和波体：旋空弧月。
- 护盾芯片：护盾。
- 单枚护盾状态：能量护盾。
- 双枚护盾状态：全防御能量护盾。

## 边界

- 本次不改变四组业务的数值、伤害、费用、门槛和运行时规则。
- 本次不实现分类筛选界面；先把正式画像保存到 Core 契约和运行快照，供后续 UI 或其它 Content 使用。
- Core 不引用 `BDP.Content`，具体业务仍由 Content 加载。
