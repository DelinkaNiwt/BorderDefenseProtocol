# BDP远程追踪模块 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 把当前追踪模块末段改成“近目标渐进放手 + 冻结本轮预计命中点 + 越点未中后有限重锁或飞离”，消除贴脸硬拧带来的不自然转向。

**Architecture:** 不改主模组宿主边界，只在 `BorderDefenseProtocol.DevHarness` 的追踪样例内收敛行为。`Arrival` 先判甩脱，再根据当前轮次的近目标阈值决定继续牵引、进入放手直飞、或触发重锁/飞离；`TrackingPathBuilder` 负责计算每轮软/硬放手距离、追踪衰减和冻结命中点；放手段的 continuation 使用独立 binding target，避免几何终点不是目标本体时再次出现幽灵命中语义。

**Tech Stack:** C# / RimWorld mod XML / PowerShell smoke tests / `dotnet msbuild`

---

## Scope Guardrails

- 只修改这次追踪模块相关文件，不碰主模组其它系统。
- 不引入新的宿主接口，不修改 `Source/BDP/Core` 业务规则。
- 不做中途碰撞拦截处理，不做障碍绕行，不做复杂群体协同。
- 不追求一次调完所有观感参数，先把状态机和末段语义改对。

## Task 4: 改 Arrival 状态机与 continuation 绑定

**Files:**
- Modify: `BorderDefenseProtocol.DevHarness/Source/BDP.DevHarness/RangedModules/Samples/TrackingModule.cs`

**Step 1: 调整 Arrival 判定顺序**

顺序改成：

1. 已结束 / fly-away 收尾
2. `Released` 阶段到点收尾
3. 解析目标与距离
4. 先判甩脱
5. 再判是否进入 release
6. 再决定继续追
7. 最后才保留旧的命中窗兜底

**Step 2: 实现进入 release**

要求：

- 冻结预计命中点
- 阶段切到 `Released`
- continuation 几何终点走冻结点
- `NextTarget` 继续保持语义锁定目标
- `NextBindingTarget` 改绑到 release 终点 cell

**Step 3: 实现 release 到点后的分流**

要求：

- 到达冻结点时，如果子弹还活着，说明本轮“放手观察”失败
- 还有次数：进入重锁
- 没有次数：进入飞离

**Step 4: 补全诊断日志**

要求：

- 能从日志区分 `pursuit / release / relock / flyaway`
- 能看到当前轮次、冻结命中点和分支结果
