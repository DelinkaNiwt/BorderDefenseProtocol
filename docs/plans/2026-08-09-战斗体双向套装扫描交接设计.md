# 战斗体双向套装扫描交接设计

## 目标

让战斗体生成与解除期间的服装真正随扫描线交接：扫描线尚未经过的一侧显示退场套装，已经经过的一侧显示入场套装。继续保持单个扫描 Mote、无粒子、无 RenderTexture（渲染纹理）、无自定义 Shader（着色器）的低开销路线。

## 根因

当前表现提供器只在真实换装前捕获退场服装。宿主事务随后立即完成换装，原版 Pawn 渲染树会完整绘制入场服装；扫描 Mote 只在更高海拔裁切重绘退场服装。因此现在看到的是“完整入场服装作为底层立即出现，退场服装覆盖层逐步消失”，不是两套服装在扫描线两侧互相交接。

## 采用方案

### 1. 增加中性的变换完成通知

Core.dll 的表现生命周期由单一 `Begin` 扩展为：

```text
NotifyBegin：真实换装前，捕获退场套装
    ↓
宿主事务：立即完成玩法状态和真实服装切换
    ↓
NotifyEnd：真实换装后，捕获入场套装并启动视觉交接
```

该通知只表达“宿主变换已完成”，不认识预设、镜像或扫描特效，保持 Core 中性。`MirrorOriginal`（镜像原身）服装生成与恢复逻辑不作修改。

### 2. 捕获两侧服装

Content.dll 的扫描提供器在 `Begin` 暂存退场服装绘制记录，在 `End` 捕获入场服装绘制记录。每条记录继续复用原版解析出的 `Graphic`、朝向、头身网格、腰带偏移和缩放，并额外记录衣物实体编号，用于精确抑制对应的原版入场衣物节点。

暂存只跨越同一次同步宿主事务，按 Pawn 实体编号索引；下一次 `Begin` 会覆盖同一 Pawn 的陈旧暂存，避免残留影响后续变换。

### 3. 只抑制本次可接管的入场衣物节点

Mote 存活的 16 tick 内，通过两个窄范围 Harmony（运行时补丁框架）后置补丁检查原版身体衣物和头部衣物节点。只有同时满足以下条件才阻止原版节点绘制：

- 不是肖像绘制；
- Pawn 正处于本次扫描交接；
- 节点衣物实体编号属于已成功捕获的入场服装；
- 玩家没有关闭 Mote 显示；
- 抑制令牌仍属于当前一轮变换且未超时。

身体、头发、武器、伤口、其他 Pawn 和未被捕获的自定义衣物均不受影响。Mote 销毁时按令牌释放抑制；短超时作为异常销毁的兜底。查找只发生在原版衣物节点的 `CanDrawNow`，活动期很短，不增加粒子和逐帧对象分配。

### 4. 互补裁切绘制

Mote 使用同一条世界扫描线分别计算两组衣物的裁切比例，并复用现有 24 档预建网格：

```text
生成：入场预设保留扫描线上方；退场原身保留扫描线下方
解除：退场预设保留扫描线上方；入场原身保留扫描线下方
```

两边使用同一量化裁切值，边界互补，不留空隙；现有青绿柔光和白色核心光覆盖接缝。这里实现的是随扫描线连续推进的空间替换，不增加高成本的逐像素透明溶解。

## 降级与异常处理

- 镜头外、非站立、人形数据不完整或 Mote 被隐藏：不启用服装抑制，保留原版即时换装，主业务不受影响。
- 具有自定义图形属性或特殊 `drawData` 的衣物：不接管、不抑制，继续由原版或其他模组绘制。
- `Begin` 后没有对应 `End`：下一轮覆盖暂存，不影响玩法状态。
- Mote 提前销毁：销毁回调释放抑制；超时检查防止静态状态残留。

## 验证范围

- 时序测试：进入与解除均为 `NotifyBegin → 真实换装 → NotifyEnd`。
- 内容契约测试：提供器分别捕获退场/入场服装，并把两组记录传给 Mote。
- 裁切测试：两组服装使用相反的 `keepUpper`，共享扫描线和网格缓存。
- 抑制测试：只拦截标准身体/头部入场衣物，不影响肖像、隐藏 Mote 和未捕获衣物。
- 性能契约：`DrawAt` 不创建 Mesh、Material 或 List；不引入粒子、反射、RenderTexture 或自定义 Shader。
- 构建与回归：战斗体变换相关测试、Core 隔离检查、Core/Content Release（正式）构建。
