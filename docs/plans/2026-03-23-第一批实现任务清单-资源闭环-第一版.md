# 第一批实现任务清单：资源闭环（第一版）

## 目的

这份清单只服务第一件事：

- 开始真正写代码时，先把资源闭环落地

它不是总实现计划。

它只覆盖第一阶段路线里的第 1 步，
也就是：

- `CompTrion`
- `ITrionState`
- `ITrionEvents`

## 一、这批任务的完成标准

完成后，至少要成立这些事实：

1. 新项目里已经有清楚的资源接口定义
2. 新项目里已经有第一版 `CompTrion`
3. `Cur / Max / Available / Allocated / Reserved` 这些基础语义能成立
4. 一次性消耗、正式占用、释放能成立
5. 聚合消耗注册与总读值能成立
6. 可用值耗尽事件能成立

## 二、开写前先回查的旧代码

真正开写前，先回查旧文件：

- `BorderDefenseProtocol.Legacy/Source/BDP/Core/Comps/CompTrion.cs`

本轮重点只看这些点：

- 字段有哪些
- 哪些是资源真值
- 哪些是聚合消耗相关
- 哪些是恢复和边界事件相关
- 哪些是旧代码里明显过重、第一版先不带过来的内容

这一步的目的不是照抄旧实现，
而是避免把旧 BDP 真需求读漏。

## 三、建议新增文件

当前新项目 `Source/BDP` 里几乎还是空骨架。

第一批建议先新增这些文件：

- `Source/BDP/Core/Trion/ITrionState.cs`
- `Source/BDP/Core/Trion/ITrionEvents.cs`
- `Source/BDP/Core/Trion/CompProperties_Trion.cs`
- `Source/BDP/Core/Trion/CompTrion.cs`

如果需要放一些纯常量或小工具，
优先收进：

- `Source/BDP/Support/`

不要因为资源系统刚起步，
就顺手把业务规则塞进工具层。

## 四、第一批任务顺序

### 任务 1：先写资源接口

目标：

- 把资源语义先定死在接口层

范围：

- `ITrionState`
- `ITrionEvents`

要求：

- 注释直接写清“它是什么、管什么、不给谁管”
- 字段和方法名优先贴近旧 BDP 已确认语义

停点：

- 接口有没有偷偷长成业务协调层

### 任务 2：写 `CompProperties_Trion`

目标：

- 给 `CompTrion` 提供最小可配置入口

第一版只需要：

- 初始值相关
- 最大值相关
- 基本恢复/结算周期相关

要求：

- 第一版只留资源闭环真正需要的配置
- 不把后面阶段的表现参数提前塞进来

停点：

- 配置是不是已经超出第一阶段资源闭环

### 任务 3：写 `CompTrion` 的第一版核心字段与只读属性

目标：

- 先把资源真值框架立起来

至少包含：

- `cur`
- `max`
- `allocated`
- `reserved`
- `frozen`
- 聚合消耗注册表

至少暴露：

- `Cur`
- `Max`
- `Allocated`
- `Reserved`
- `Available`
- `TotalDrainPerDay`
- `Frozen`

停点：

- 有没有把战斗体或触发体状态塞进来

### 任务 4：写基础操作 API

目标：

- 让资源从“只会读”变成“可被第一阶段使用”

至少包含：

- `CanAfford`
- `TryConsume`
- `ConsumeUntilDepleted`
- `SetReserved`
- `Allocate`
- `Release`
- `RegisterDrain`
- `UnregisterDrain`
- `GetDrainSnapshot`
- `SetFrozen`

要求：

- 先把语义做对
- 不抢着写花哨恢复逻辑

停点：

- 这些 API 有没有开始夹带别的系统事务

### 任务 5：写边界事件

目标：

- 让资源系统能通知第一阶段其他系统

至少包含：

- `AvailableDepleted`
- `TrionDepleted`

要求：

- 第一阶段重点先保证 `AvailableDepleted`
- `TrionDepleted` 可以先一起留好，但不要求先大量使用

停点：

- 事件是不是开始反过来充当真值 owner

### 任务 6：写最小 XML 配置样例

目标：

- 保证 `CompTrion` 在 RimWorld 模组里真能挂起来

建议新增：

- 一个最小测试用 `ThingDef` 或挂载样例说明

要求：

- 只为验证资源闭环服务
- 不提前做测试内容大扩展

停点：

- XML 是否已经开始承担业务设计说明以外的东西

## 五、这批任务先不要做的内容

下面这些先不要顺手做：

- 战斗体激活逻辑
- 触发体装载逻辑
- 表达系统
- 自动入口桥接
- GUI 细节
- 大量调试显示
- 复杂恢复规则

原因很简单：

- 现在只做资源闭环

## 六、这批任务完成后要检查的问题

1. `CompTrion` 还是不是单纯资源 owner
2. 资源接口是不是足够第一阶段后续系统读取
3. 聚合消耗是不是已经被保留下来了
4. 可用值耗尽事件是不是能成为后续崩解入口
5. 是否引入了第一阶段暂时不需要的复杂规则

## 七、完成这批后再进入下一批

资源闭环完成后，
下一批才进入：

- 战斗体基础相位

顺序不要跳。
