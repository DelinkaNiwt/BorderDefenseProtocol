# Hediff 表达宿主边界收口 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 基于当前已经落地的 `Ability` / `Hediff` 最小闭环，把 `Hediff` 通道从“命名约定边界”收成“正式宿主边界”，让后续业务编写依赖的是清晰协议而不是软约束。

**Architecture:** 继续保留 `Trigger -> Expression -> HostSync -> 原版宿主` 主链，不重做 `Hediff` 同步机制，不引入实例级来源平台。本轮只新增一个最小表达宿主基类，用 `HediffDef.hediffClass` 硬化边界，并把校验、同步、样本、文档全部收口到同一套协议。

**Tech Stack:** C#、RimWorld `Hediff` / `HediffDef`、BDP 表达系统、PowerShell smoke tests、DevHarness XML Defs

---

## 范围护栏

本计划只负责：

- 把 `Hediff` 通道的正式边界从“命名前缀建议”改为“`hediffClass` 硬协议”
- 新增最小表达宿主基类
- 收紧校验器与同步器
- 对齐 DevHarness 样本与使用文档
- 用 smoke test 锁住新边界

本计划明确不包含：

- 通用外部 `HediffDef` 复用平台
- 实例级来源追踪
- 额外 `modExtension` 协议
- 形态切换设施
- `Ability` 架构重做

### Task 3：把校验器从软提示改成硬规则

**Files:**
- Modify: `模组工程/BorderDefenseProtocol/Source/BDP/Core/Chips/Validation/DefaultChipDefinitionValidator.cs`

**Step 2：新增 `HediffDef` 解析与宿主类校验**

- 非空且不是 `countToSeverity` 时 warning + 退化

改成：

- 非空且不是 `countToSeverity` 时直接 error

**Step 4：补中文错误文案**

错误文案要说人话，明确告诉业务作者：

- 这个 `HediffDef` 不是 BDP 表达宿主 Def

### Task 4：收口 `Hediff` 同步器口径与防御校验

**Files:**
- Modify: `模组工程/BorderDefenseProtocol/Source/BDP/Core/Expressions/Projection/DefaultExpressionHediffHostSynchronizer.cs`

**Step 1：统一注释口径**

把类注释、字段注释、方法注释统一改成：

- “表达宿主通道”
- “已发布 Hediff 定义”
- “只维护 BDP 表达宿主 Def”

不要再写成：

- 临时规避误伤
- 看起来像专用 Def
- 未来再补来源平台

**Step 2：内部命名做轻量收口**

推荐重命名：

- `ManagedHediffDefsByPawn` -> `PublishedHediffDefsByPawn`
- `GetManagedHediffDefs(...)` -> `GetPublishedHediffDefs(...)`

要求：

- 只做必要命名收口
- 不扩散到不相关文件

**Step 3：新增防御性宿主类校验**

在 `ApplyCurrentHediffs(...)` 里，对每个 `HediffDef` 先做一次防御性判断：

- 如果 `def == null`，跳过
- 如果 `def.hediffClass` 不是 `BdpExpressionHostHediff` 或其子类，跳过并报错日志

注意：

- 这里不是向下兼容
- 也不是 fallback
- 只是防脏配置污染宿主通道

**Step 4：保持当前按 `def` 回收逻辑不变**

`RemoveAllHediffsOfDef(...)` 保持不变。

要求：

- 不补实例级来源标识
- 不加额外映射表
- 不为了未来可能性改重
