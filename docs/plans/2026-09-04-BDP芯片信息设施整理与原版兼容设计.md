# BDP 芯片信息设施整理与原版兼容设计

## 一、状态与裁定

- 状态：已由用户确认，作为后续整理与实现的正式架构基线。
- 基线提交：`833b86f6 记录信息设施架构整理前基线`。
- 适用范围：成品芯片信息模型、制造预览、触发器装配台详情、原版物品信息卡、表达契约只读面及未来信息兼容入口。
- 核心裁定：不建立万能信息系统；共享事实和正规化规则上提，玩家解释投影与原版武器兼容投影并列，具体界面按需消费。

## 二、目标

1. 保留现有正确主干，不推倒重写信息系统。
2. 消除“具体界面持有共享业务、其它界面借道调用”的错位依赖。
3. 统一近战、远程和非武器增强的基础能力判定。
4. 让原版信息卡通过 RimWorld（边缘世界）原版 `SpecialDisplayStats`（特殊信息条目）与 `StatWorker`（原版属性计算器）自然显示武器统计。
5. 保证信息展示不成为战斗真值，原版兼容投影也不反向污染正式表达系统。
6. 为多形态、运行中当前状态、外部信息模组和未来 RimWorld 版本迁移留下清楚边界。

## 三、当前事实

### 1. 已经正确的部分

- `ChipCombinationResolver`（芯片组合解析器）从持久化组合记录产生 `DeclaredConfig`（基础配置）和 `ResolvedConfig`（最终有效配置）。
- `CompManufacturedChip`（成品芯片组件）通过中性接口公开最终配置、基础配置和来源身份。
- `ChipInformationParser`（芯片信息解析器）与 `ChipInformationModel`（芯片信息模型）已经形成不依赖具体界面的解释模型。
- `ChipInformationExtensionRegistry`（芯片信息扩展注册表）允许 Content（内容程序集）向 Core（核心程序集）注册具体 Hediff（健康状态）、Ability（能力）组件和远程模块的信息提供器，依赖方向正确。
- `ChipExpressionContractInterpreter`（芯片表达契约解释器）已经能够正规化 `VerbProperties`（攻击属性）、`Tool`（近战工具）、`ManeuverDef`（近战招式定义）、`ResolvedVerbSpec`（已解析攻击规格）和投射物覆盖。

### 2. 当前错位和重复

- 完整的成品芯片信息模型构建逻辑藏在 `ChipManufacturingPreviewBuilder`（芯片制造预览构建器）的私有方法中。
- 触发器装配台为了取得成品信息模型，调用整个制造预览构建器，再从预览对象取回模型。
- 制造预览和装配台详情各自维护信息值格式化，且枚举、百分比和列表的展示策略并不完全相同。
- 近战与远程条目判定散落在定义验证、表达解释、信息适配、武装构型选择和装配台比较基准中。
- `ChipExpressionContractInterpreter`（芯片表达契约解释器）及其返回对象可满足兼容投影需要，但当前没有面向 Content 的最小只读访问面。
- `ChipInformationDetailRenderer`（芯片详情渲染器）同时承担模型读取、格式化、比较、图表计算、测量与绘制，文件过大，但它的职业雷达与比较业务不适合通用化。

## 四、必须分开的五种对象

| 层次 | 代表对象 | 唯一职责 | 不能承担 |
|---|---|---|---|
| 成品配置真值 | `ResolvedConfig`（最终有效配置） | 说明成品芯片最终包含什么声明 | 界面布局、原版属性计算 |
| 正规化表达契约 | `ChipExpressionResolvedContract`（已解析表达契约） | 说明系统正式承认哪些表达及其正规化武器参数 | 玩家文案、窗口状态 |
| 当前运行真值 | `ExpressionSnapshot`（表达运行快照）与 `FormalExpressionResult`（正式表达结果） | 说明角色此刻真正成立、激活和投影了什么 | 未装载芯片的静态百科 |
| 玩家解释模型 | `ChipInformationModel`（芯片信息模型） | 说明应怎样向玩家解释配置、来源、上下文和最终值 | 战斗判定、反向重建原始武器对象 |
| 原版兼容投影 | `VanillaWeaponStatSurface`（原版武器统计表面，待新增） | 把一条已确认武器契约转换为原版统计系统认识的数据形状 | 成为新的战斗真值、保存进存档、注册成正式 Def（定义） |

判断任何新功能应读取哪个对象时，先回答它提出的问题：

- “成品里写了什么”读取最终有效配置。
- “系统正式承认什么”读取正规化表达契约。
- “角色现在生效什么”读取运行快照。
- “玩家应该看到怎样的说明”读取信息模型。
- “原版只能理解一件普通武器时看到什么”读取原版兼容投影。

## 五、目标数据流

```text
成品组合记录
    ↓
ChipCombinationResolver（芯片组合解析器）
    ↓
ResolvedConfig（最终有效配置，唯一成品事实源）
    ├─→ ManufacturedChipInformationModelBuilder（成品芯片信息模型构建器）
    │       ↓
    │   ChipInformationModel（芯片信息模型）
    │       ├─→ 制造预览
    │       ├─→ 触发器装配台详情
    │       └─→ 原版信息卡中的 BDP 普通说明条目
    │
    └─→ ChipExpressionCapabilityResolver（表达能力解析器）
            ↓
        ChipExpressionResolvedContract（正规化表达契约）
            ↓
        VanillaWeaponStatSurfaceFactory（原版武器统计表面工厂）
            ↓
        RimWorld StatWorker（原版属性计算器）
            ↓
        原版信息卡中的近战或远程统计条目
```

## 六、Core（核心程序集）职责

### 1. 保留现有信息模型边界

以下设施保留现状和职责：

- `ChipInformationSurfaceAccess`（芯片信息读取面）；
- `ChipInformationParser`（芯片信息解析器）；
- `ChipInformationDefinitionInputAdapter`（芯片定义信息输入适配器）；
- `ChipInformationInstanceInputAdapter`（芯片实例信息输入适配器）；
- `ChipInformationInputComposer`（芯片信息输入合成器）；
- `ChipInformationExtensionRegistry`（芯片信息扩展注册表）。

不把 `StatDrawEntry`（原版属性显示条目）、窗口布局或制造组合类型加入 `ChipInformationModel`（芯片信息模型）。

### 2. 新增表达能力解析器

建议新增 `ChipExpressionCapabilityResolver`（芯片表达能力解析器），只处理与业务名称无关的基础语义：

- `IsVerbEntry`（是否攻击动作条目）；
- `ResolveWeaponMode`（解析武器模式）；
- `HasExecutableMeleeSurface`（是否有可执行近战表面）；
- `HasExecutableRangedSurface`（是否有可执行远程表面）；
- `IsAugmentationOnly`（是否只有增强声明而没有独立武器）。

它不读取：

- 芯片分类；
- 职业；
- `DefName`（定义名称）；
- 玩家显示名；
- 制造兼容规则。

制造业务仍可在此基础上追加“只有某分类或职业才能选择某武装构型”的 Content 规则。

### 3. 新增表达契约只读入口

建议新增 `ChipExpressionContractSurfaceAccess`（芯片表达契约读取面），对外只提供：

```csharp
public static ChipExpressionResolvedContract Resolve(
    Thing chip,
    ITriggerLoadoutReader triggerLoadoutReader = null);
```

该入口只包装现有解释器：

- 不复制解释逻辑；
- 不暴露解释器实例；
- 不暴露内部缓存；
- `triggerLoadoutReader`（触发器装载状态读取器）为空时按静态或默认形态解析；
- 有运行状态读取器时按当前形态和姿态解析。

### 4. 新增原版武器统计表面工厂

建议新增：

- `VanillaWeaponStatSurface`（原版武器统计表面）；
- `VanillaWeaponStatSurfaceFactory`（原版武器统计表面工厂）。

输入为已经正规化且合法的 `ChipExpressionEntryContract`（芯片表达条目契约），输出只读、临时的原版数据表面。

远程表面至少需要：

- 主要 `VerbProperties`（攻击属性）；
- 射程、预热、连射数与间隔；
- 精度与冷却对应的 `StatBases`（属性基础值）；
- 最终投射物；
- 投射物伤害、速度、停止力与伤害类型覆盖。

近战表面至少需要：

- 全部正规化 `Tool`（近战工具）；
- 每个工具对应的伤害类型和攻击表面；
- 原版近战 `StatWorker`（属性计算器）所需的 `ThingDef`（物品定义）形状。

硬约束：

- 不修改 `BDP_Chip_Custom`（BDP 共用芯片定义）；
- 不注册临时 `ThingDef`；
- 不把临时对象交给地图、容器或存档；
- 不自己复制原版武器统计公式；
- 仅把 BDP 已解析的最终值映射到原版字段。

## 七、Content（内容程序集）职责

### 1. 抽出成品芯片信息模型构建器

新增 `ManufacturedChipInformationModelBuilder`（成品芯片信息模型构建器），位置建议为：

`Source/BDP.Content/Information/ManufacturedChipInformationModelBuilder.cs`

它接收 `ChipCombinationResolution`（芯片组合解析结果），集中完成：

- 身份构建；
- 功能与武装构型描述收集；
- 基础配置输入；
- 最终配置覆盖输入；
- 来源重分类与输入合成；
- 调用 Core 信息读取面产生最终模型。

制造预览和装配台不得再互相调用以取得模型。

### 2. 整理文本格式化

后续新增 `ChipInformationTextFormatter`（芯片信息文本格式化器）时必须区分：

- 可共享的基础类型格式化；
- 各界面自己的展示策略。

当前制造预览和装配台对枚举、百分比及列表的处理并不完全相同，因此不能在第一阶段直接强行合成一个输出结果。应先做特征测试，再共享基础格式化，保留必要的界面策略入口。

### 3. 新增原版信息卡发布器

建议新增 `ManufacturedChipInfoCardPublisher`（成品芯片信息卡发布器），由 `CompManufacturedChip.SpecialDisplayStats()` 调用。

职责仅包括：

1. 取得完整成品信息模型；
2. 按信息卡自己的字段白名单生成 BDP 普通说明条目；
3. 取得正规化武器契约；
4. 只为确实成立的近战或远程能力创建原版武器统计表面；
5. 调用原版统计入口并返回条目。

它不得：

- 重新解析组合记录；
- 按芯片分类或名称猜武器能力；
- 读取装配台窗口状态；
- 复用装配台雷达图渲染器；
- 自己计算原版近战 DPS（每秒伤害）或护甲穿透公式。

## 八、Development（开发诊断程序集）职责

原版武器投影先在 Development（开发诊断程序集）完成诊断验证，再转为正式 Core 设施。

诊断输出应并列记录：

- 成品组合与最终配置身份；
- 正规化表达条目标识和武器模式；
- `ResolvedVerbSpec`（已解析攻击规格）；
- 临时原版表面关键字段；
- 原版生成的 `StatDrawEntry`（属性显示条目）；
- 信息模型中对应字段；
- 不一致原因。

诊断必须可整体删除，不得让 Core 或 Content 依赖 Development。

## 九、武器能力存在性规则

“包含武器”不按芯片种类判断，而按最终有效配置和正规化契约判断。

### 1. 远程武器成立

至少同时满足：

- 条目是 `PrimaryVerb`（主攻击动作）或 `SecondaryVerb`（副攻击动作）；
- 正规化武器模式为远程；
- 存在合法 `ResolvedVerbSpec`（已解析攻击规格）；
- 存在可供原版读取的有效投射物或对应远程攻击表面；
- 契约验证没有使该条目失效。

只有 `RangedModules`（远程模块）或 `RangedModuleAugmentations`（远程增强声明）不算独立远程武器。

### 2. 近战武器成立

至少同时满足：

- 条目是主攻击或副攻击动作；
- 正规化武器模式为近战；
- 至少存在一个合法 `Tool`（近战工具）或正规化近战工具表面；
- 契约验证没有使该条目失效。

芯片分类、职业和武装构型只影响业务选择，不决定是否显示近战或远程统计。

## 十、多形态与多武器边界

原版信息卡是低粒度读取者，通常只能自然理解一套主要远程武器表面。BDP 自有信息模型则可以表达全部形态和上下文。

长期需要同时支持：

- BDP 详情界面展示完整多形态、多表达明细；
- 原版信息卡提供稳定的主兼容表面；
- 愿意适配 BDP 的外部模组读取完整正式契约。

原版信息卡究竟选择“默认形态主武器”还是“当前装载状态主武器”，属于后续实施前必须单独裁定的策略，不在第一阶段结构整理中暗自决定。

## 十一、缓存与生命周期

第一版不增加缓存：

- 信息卡打开频率低；
- 成品芯片配置可从组合记录重建；
- 过早缓存会引入语言切换、Def 热重载、模组更新和形态状态失效问题。

只有实测证明频繁创建临时表面产生可观开销时，才设计以组合记录指纹、语言和游戏版本为键的只读缓存。

## 十二、错误处理

- 组合无效：不发布动态芯片信息，只保留原版基础物品信息。
- 信息模型构建失败：记录可搜索诊断，不阻断原版信息卡其它条目。
- 武器契约无效：不发布对应武器统计，不伪造默认值。
- 单个扩展提供器失败：保持现有隔离策略，继续处理其它提供器。
- 原版投影失败：Development 阶段输出结构化差异；正式阶段安全跳过该武器块。

## 十三、测试策略

### 1. 结构测试

- Core 不依赖 Content 或 Development。
- Content 不依赖 Development。
- UI（用户界面）构建器之间不再互相借道获取信息模型。
- 信息模型不包含 `ThingDef`、`VerbProperties` 或 `StatDrawEntry` 等原始游戏对象。

### 2. 行为特征测试

- 同一 `ChipCombinationResolution`（芯片组合解析结果）在整理前后产生相同模型树。
- 制造预览与装配台读取同一当前模型。
- 基础配置、构型覆盖和来源链保持不变。

### 3. 游戏内诊断测试

至少覆盖：

- 纯远程武器芯片；
- 纯近战武器芯片；
- 多 `Tool`（近战工具）芯片；
- 防御分类但含近战武器的芯片；
- 只有远程增强、没有独立武器的芯片；
- 带投射物覆盖的武装构型；
- 双功能与多形态芯片；
- 无武器表达的 Ability、Hediff 和 Passive 芯片。

## 十四、明确不做

- 不把信息模型改造成战斗模型。
- 不把装配台详情渲染器改造成所有界面的万能渲染器。
- 不为了本功能修改 RimWorld 原版信息窗口主流程。
- 不用 Harmony（运行时补丁框架）承担信息卡业务。
- 不在第一阶段重写表达系统、验证系统、缓存系统或图表系统。
- 不为尚无第二个真实使用者的细节预建大型插件框架。

## 十五、最终验收

完成全部路线后，应同时满足：

1. 成品配置只有一个正式解析入口。
2. 制造预览、装配台与原版信息卡不互相借道。
3. 近战、远程和增强能力使用同一中性判定。
4. BDP 普通说明来自统一信息模型。
5. 原版武器统计由原版计算器产生。
6. 多形态完整明细与原版单主表面兼容互不压扁。
7. Core、Content、Development 的依赖方向保持不变。
8. 所有临时诊断和失败尝试在正式交付前移除。
