# 拖尾预设注入设计

## 目标

将子弹拖尾特效的归属权从"子弹 ThingDef"迁移到"芯片"侧，使同一个子弹 def 被不同芯片使用时能展示不同拖尾。

## 当前状态

- 拖尾配置 `BeamTrailConfig` 挂在子弹 ThingDef 的 `modExtensions` 上
- `ProjectileVisualAttachmentHost.Initialize(ThingDef)` 从 def.modExtensions 扫描 `IProjectileVisualAttachmentProvider` 并创建附加件
- 一个子弹 def = 一种拖尾，无法按攻击来源区分

## 设计方案

### 1. 新增 BeamTrailPresetDef（拖尾预设定义）

位置：DevHarness 侧

```csharp
// BDP.DevHarness.Projectiles.BeamTrail.BeamTrailPresetDef
public class BeamTrailPresetDef : Def
{
    public string trailTexPath = "Things/Projectile/BDP_BeamTrail";
    public Color trailColor = new Color(0.7f, 0.85f, 1f, 1f);
    public float trailWidth = 0.1105f;
    public int segmentLifetimeTicks = 30;
    public float startOpacity = 1f;
    public float fadeRatio = 0.8f;
    public float fadeExponent = 10f;
    public float altitudeOffset = 0f;
    public float startForwardOffset = 0f;
    public bool debugLogging = false;
}
```

### 2. 芯片侧引用预设

在芯片的扩展块（ChipExtensionBlockConfig）中新增一个可选字段，或新建一个专用 DefModExtension：

```csharp
// DevHarness 侧，挂在芯片 ThingDef 的 modExtensions 上
public class ChipBeamTrailExtension : DefModExtension
{
    public BeamTrailPresetDef beamTrailPreset;
}
```

芯片 XML 示例：

```xml
<modExtensions>
  <li Class="BDP.DevHarness.Projectiles.BeamTrail.ChipBeamTrailExtension">
    <beamTrailPreset>BDP_TrailPreset_ColdBlue</beamTrailPreset>
  </li>
</modExtensions>
```

### 3. 主模组改动：视觉附加件实例级注入

#### 3a. ProjectileVisualAttachmentHost 新增注入方法

```csharp
// 新增方法，允许外部在 Initialize 之后追加实例级附加件
internal void InjectAttachment(IProjectileVisualAttachment attachment)
{
    if (attachment != null)
    {
        attachments.Add(attachment);
    }
}
```

#### 3b. BdpProjectile 暴露注入入口

```csharp
// BdpProjectile 新增 internal 方法
internal void InjectVisualAttachment(IProjectileVisualAttachment attachment)
{
    visualAttachmentHost.InjectAttachment(attachment);
}
```

#### 3c. ProjectileInitContribution 新增视觉附加件贡献字段

```csharp
// ProjectileInitPlanContribution 新增
public List<IProjectileVisualAttachment> VisualAttachments { get; }
    = new List<IProjectileVisualAttachment>();
```

#### 3d. ProjectileInitStageService 消费该字段

在投射物 spawn 后、NotifyLaunch 之前，遍历 contribution 中的 VisualAttachments 并调用 InjectVisualAttachment。

### 4. DevHarness 侧：ProjectileInit 模块实现

```csharp
// DevHarness 侧新增一个 IProjectileInitStageModule 实现
public class BeamTrailInitModule : IProjectileInitStageModule
{
    public void Contribute(
        in ProjectileInitStageContext context,
        ProjectileInitContribution contribution)
    {
        // 从芯片 def 读取 ChipBeamTrailExtension
        // 如果有 beamTrailPreset，创建 BeamTrailAttachment 并加入 contribution
        var chipDef = /* 从 context 获取当前芯片 def */;
        var ext = chipDef?.GetModExtension<ChipBeamTrailExtension>();
        if (ext?.beamTrailPreset == null) return;

        var snapshot = BeamTrailAppearanceSnapshot.CreateFrom(ext.beamTrailPreset);
        var attachment = new BeamTrailAttachment(snapshot);

        for (int i = 0; i < context.EmitCount; i++)
        {
            if (contribution.PlanContributions.Count <= i) continue;
            contribution.PlanContributions[i].VisualAttachments.Add(attachment);
        }
    }
}
```

### 5. 子弹 def 清理

移除子弹 ThingDef 上的 `BeamTrailConfig` modExtension。子弹 def 回归纯弹道参数载体。

## 注意事项

1. BeamTrailConfig 作为 DefModExtension 的旧用法可保留兼容——如果子弹 def 上仍挂了 BeamTrailConfig，视为"默认拖尾"；芯片侧注入的优先级更高，覆盖默认。这样不会破坏现有测试。
2. 主模组改动全部是 internal，不暴露新的 public API。
3. BeamTrailPresetDef 是 DevHarness 侧的业务 Def，主模组不感知它的存在。
4. 如果未来需要"无拖尾"覆盖（芯片明确要求不显示拖尾），可在 ChipBeamTrailExtension 加一个 `suppress = true` 字段。
