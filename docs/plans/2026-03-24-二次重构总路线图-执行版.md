# BDP 二次重构总路线图（执行版）

**目标：** 为 BorderDefenseProtocol 二次重构建立一条可持续执行的总路线，明确当前所在节点、后续固定顺序、每段进入条件、完成标准、禁止越级项与正式交付物，避免后续再次陷入“不断给下一步建议”的漂浮推进方式。

**架构：** 本路线严格服从“旧 BDP 外在本质表现不变、内部原理重构、从 RimWorld 出发并回到 RimWorld、三类真值 owner 不能混、patch 只接线不承载复杂业务”的总原则。路线采用“先钉死高风险规则，再按主链闭环落地，再做表现对齐验证，最后回收外围与扩展层”的顺序推进。

**技术栈：** RimWorld 1.6、C# 7.3、Harmony、XML Def，优先原版 `Verb / Ability / Hediff / Projectile / Gizmo / ThingComp / JobDriver` 宿主。

---

## 一、总路线概览

本项目后续固定按以下路线推进：

1. 路线 A：阶段 1 收口与需求冻结
2. 路线 B：Trigger 与多表达主链落地
3. 路线 C：Trion 与战斗体闭环落地
4. 路线 D：远程攻击链协议落地
5. 路线 E：存读档与恢复闭环落地
6. 路线 F：旧 BDP 核心表现对齐验证
7. 路线 G：外围真实系统回收
8. 路线 H：正式扩展接口、测试层与收尾整理

后续不再用“想到哪个做哪个”的方式切换主题。

任何新工作都必须先声明自己属于：

- 当前路线中的哪一段
- 该段中的哪个子节点
- 它的前置条件是否已满足

如果这三件事答不上来，就不进入实现。

## 三、全局硬规则

## 1. 不允许越级实现

没有完成上一路线段的进入标准前，不进入下一段。

例如：

- 多表达主链没落地，不提前做 FireMode 业务接回
- 战斗体闭环没落地，不提前做伤口扩展深度对齐
- 存读档恢复协议没落地，不提前把大量外围系统接回

## 2. 不允许绕过 owner 边界赶工

不能为了推进进度而：

- 让事件持有真值
- 让 FireMode 持有攻击系统真值
- 让显示层反推业务真值
- 让 patch 成为主要业务宿主

## 3. 不允许以 tick 修补立即成立逻辑

暂停下应立即成立的逻辑，必须在查询口立即成立。

tick 只允许用于：

- 自然恢复
- 冷却
- 在途推进
- 表现计时

## 4. 不允许实现先于文档裁定

进入任一功能实现前，必须先回查：

1. 当前路线节点文档
2. 对应需求专项文档
3. 旧 BDP 对应代码事实

## 5. 不允许为了短期可测把临时能力塞进正式宿主

短阶段可测、可视、可反馈、易诊断仍然必须坚持。

但这只能推动：

- 正式读取口设计
- 正式扩展口设计
- 测试层设计
- 关键诊断点设计

不能推动：

- 往 owner 宿主里继续塞临时 GUI
- 往主模组里继续塞测试专用入口
- 用测试便利破坏正式边界

## 6. 测试与正式必须隔离，删除测试层后主模组零残留

任何测试用、临时用、验证用的东西，
都必须做到：

- 直接删除后，对主模组项目无影响

如果删除测试层后，
主模组仍残留与它强绑定的：

- 类型
- 按钮
- 逻辑分支
- API

就视为测试污染。

## 五、路线 B：Trigger 与多表达主链落地

## 目标

- 让 Trigger 不再只是最小槽位样板，而成为多表达正式来源宿主
- 让多表达系统真正落地，而不再是假多表达
- 让主攻击投影、手动入口投影、兼容表面投影分层成立

## 子节点顺序

### B1. Trigger 装载规则落地

交付物：

- 特殊槽规则
- 局部禁用规则
- 双手锁定与局部封锁规则
- 身体部位联动规则
- 切换态与正式激活态边界落地
- 关键诊断日志点

完成标准：

- Trigger 可以稳定给表达层提供正式来源真值
- 局部激活与局部表现边界不混
- 每个短阶段都具备游戏内可测、可视、可反馈、易诊断机会
- 游戏内测试面若需要，必须优先通过正式扩展口或测试模组提供，不能污染主模组

### B2. 多表达解析主链落地

交付物：

- 单侧表达
- 双武器表达
- 组合第三表达
- 非 `Verb` 表达入口骨架

完成标准：

- 表达结果集合成为正式结果
- 不是只剩默认主近战 / 主远程两个选择器

### B3. 多层投影落地

交付物：

- 手动按钮载体层
- 直接操作入口层
- 默认主攻击投影层
- 场景默认主攻击决策层

完成标准：

- “表达数量、按钮数量、可直接操作入口数量、主兼容表面数量”四者可以正式区分

## 路线 B 完成标准

- Trigger -> 表达结果集合 -> 多层投影 形成稳定主链
- 新 BDP 不再依赖“两个默认按钮”冒充完整表达系统

## 禁止越级项

- 不提前接回 FireMode 具体业务
- 不提前做外围绘制和 GUI 完整回收
- 不提前把战斗体逻辑写进 Trigger

## 六、路线 C：Trion 与战斗体闭环落地

## 目标

- 让资源真值、战斗体阶段真值、收尾事务闭环正式进入游戏主链
- 把最小骨架变成真实业务闭环

## 子节点顺序

### C1. Trion 主链接回

交付物：

- 消耗、预占用、正式锁定、自然恢复、冻结正式接回

### C2. 战斗体进入与退出主链接回

交付物：

- 激活检查
- 激活进入
- 手动解除
- 冷却收束

### C3. 崩解与收尾主链接回

交付物：

- 多来源崩解触发
- 崩解表现期
- 收尾事务链

### C4. 快照与恢复边界接回

交付物：

- 快照创建时机
- 快照恢复责任边界
- 与身体变化恢复的正式连接点

## 路线 C 完成标准

- `CompTrion / CombatBodyState / CleanupCoordinator` 不再是孤立骨架
- 战斗体从激活到退出形成闭环

## 禁止越级项

- 不把 Trigger 当战斗体 owner
- 不把 Trion 当战斗体流程宿主
- 不把崩解写成只靠 tick 兜底的延迟生效逻辑

## 七、路线 D：远程攻击链协议落地

## 目标

- 让远程攻击真正按统一协议阶段落地
- 让调制、模块、能力扩展都通过正式链路接入

## 子节点顺序

### D1. 链内执行阶段宿主落地

交付物：

- 执行请求
- 目标解算
- 发射计划
- 投送宿主初始化
- 在途推进
- 接触解算
- 落地结果

### D2. 阶段结果对象与合并器落地

交付物：

- 阶段结果对象
- 标准字段分类
- 字段级合并规则
- 否决与优先级裁定

### D3. 调制通道正式落地

交付物：

- 表达参数调制口
- 发射计划调制口
- 投送宿主初始化调制口
- 在途 / 落地 / 显示调制口骨架

### D4. 链后读取阶段落地

交付物：

- 信息投影正式读取口
- 视觉投影正式读取口
- 执行链扩展口 / 读取链扩展口分离

## 路线 D 完成标准

- 未知远程能力可按协议挂入
- 不再靠宿主私改和功能特判推进

## 禁止越级项

- 不把 FireMode 写成特权中心
- 不把视觉读取写回执行链
- 不让模块直接写宿主私字段

## 八、路线 E：存读档与恢复闭环落地

## 目标

- 让核心主链在存读档、恢复、暂停、续接下仍保持正式一致

## 子节点顺序

### E1. 三类 owner 存读档闭环

交付物：

- `CompTriggerBody`
- `CompTrion`
- `CombatBodyState`

### E2. 表达与投影重建闭环

交付物：

- 表达结果重算
- 主攻击投影重建
- 兼容表面重建

### E3. 在途宿主续接闭环

交付物：

- Projectile / `PawnFlyer` / 其它正式在途宿主恢复边界

### E4. 快照与恢复链整合

交付物：

- 快照恢复
- 身体变化恢复
- 崩解后恢复链

## 路线 E 完成标准

- 读档后不靠下一 tick 补齐本应已成立逻辑
- 存档恢复不依赖缓存复活

## 禁止越级项

- 不把显示缓存当真值
- 不把桥接对象当恢复基础
- 不让 patch 主导恢复业务

## 九、路线 F：旧 BDP 核心表现对齐验证

## 目标

- 以游戏实测核对“旧 BDP 外在本质表现”是否已被主链正确承接

## 核验主题

- 暂停下立即成立逻辑
- 自动攻击
- 手动入口
- 双武器与组合表达
- 战斗体激活 / 崩解 / 退出
- 远程攻击链表现
- 读档恢复

## 完成标准

- 核心表现与旧 BDP 本质一致
- 差异项被明确记为 bug 或裁定项

## 禁止越级项

- 不在表现未对齐前大量回收外围系统

## 十、路线 G：外围真实系统回收

## 目标

- 回收旧 BDP 中真实影响表现但不属于核心主链首批闭环的系统

## 子节点顺序

### G1. 绘制 / 枪口 / 视觉跟随

### G2. GUI 与信息展示扩展

### G3. FireMode 作为调制参与者接回

### G4. Shield / Glow / 伤口扩展 / 其它外围真实系统

## 完成标准

- 外围系统全部建立在已稳定主链和正式读取口之上

## 禁止越级项

- 不让外围系统反向定义主链协议
- 不让显示系统夺取执行链裁定权

## 十一、路线 H：正式扩展接口、测试层与收尾整理

## 目标

- 固化正式对外读取接口
- 固化测试模组接入方式
- 固化工具与目录整理

## 子节点顺序

### H1. 正式外部读取接口

### H2. 测试模组正式扩展口

### H3. 验证清单、日志与文档收束

### H4. 工具层与目录整理

## 完成标准

- 测试模组删除后主模组无残留影响
- 对外读取接口与内部 owner 边界一致
- 文档与实现进入长期维护状态

## 十二、每一段的统一进入条件

任一路线段开始前，必须同时满足：

1. 上一路线段完成标准已满足
2. 对应需求文档已存在且已回查
3. 旧 BDP 对应代码事实已回查
4. 当前工作不会破坏三类 owner 边界
5. 当前工作已知如何通过正式扩展口或原版宿主落地

## 十三、每一段的统一停点

如果出现以下任一情况，立即停在当前路线段，不继续向下推进：

- 发现 owner 边界又混了
- 发现当前文档不足以指导实现
- 发现必须依赖 patch 承载复杂业务
- 发现逻辑成立被做成依赖 tick
- 发现测试接入会污染主模组

## 十四、执行方式

从这份路线图开始，后续推进统一采用以下表达：

- 当前路线：`A/B/C/D/E/F/G/H`
- 当前节点：例如 `B2`
- 当前任务：该节点下的具体实现项

不再使用：

- “我建议下一步……”
- “也许先做这个……”
- “再看看要不要……”

除非出现新的用户裁决导致路线改道，否则后续默认按本路线执行。

## 十五、当前后的固定推进顺序

本路线图落地后，后续固定顺序就是：

1. 完成路线 A 收口
2. 进入路线 B
3. 路线 B 完成后进入路线 C
4. 路线 C 完成后进入路线 D

## 十六、一句话总括

BDP 二次重构从现在开始不再按零散“下一步建议”推进，而是固定按“需求冻结 -> Trigger与多表达 -> Trion与战斗体 -> 远程攻击链 -> 存读档恢复 -> 核心表现验证 -> 外围系统回收 -> 扩展接口与收尾整理”这八段路线执行；任何新工作都必须先证明自己位于这条路线中的明确节点，否则不进入实现。
