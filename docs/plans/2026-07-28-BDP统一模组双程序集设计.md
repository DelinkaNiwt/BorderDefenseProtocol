# BDP 统一模组双程序集设计

## 一、设计目的

把当前主模组与伴生测试模组重新统一为一个 RimWorld（边缘世界）模组，同时继续用两个 DLL（动态链接库）隔离核心骨架与业务内容。

这次不兼容旧存档、旧 DefName（定义名称）、旧命名空间或旧模组列表，因此允许按正式职责彻底重命名和整理。

## 二、已经确认的决定

1. 最终只保留一个模组包。
2. 最终只保留两个程序集：
   - `BDP.Core.dll`：核心骨架。
   - `BDP.Content.dll`：正式内容。
3. 依赖只能从内容程序集指向核心程序集，禁止核心程序集反向引用内容程序集。
4. 现测试模组中的偏底层系统优先正式化。
5. 上层应用不在第一次合并时批量重做；以后按功能逐项介绍、逐项确认、逐项实施。
6. 游戏内诊断工具保留，但统一归入开发工具区，只在开发者模式或明确诊断开关下运行。
7. 非法 Def（定义）、教学样本和自动验证输入不得作为正式游戏内容加载。
8. 不创建 Git（版本控制）分支或 worktree（工作树），直接在当前工程内工作；每个阶段独立提交，方便回退。
9. `BorderDefenseProtocol.DevHarness（候选测试模组）`只是迁移期间的候选内容库，不是最终发布组成；全部候选内容逐项迁入、删除或确认舍弃后，必须物理退役该模组，最终工程与游戏只保留主模组 `BorderDefenseProtocol`及其中的 `BDP.Core.dll / BDP.Content.dll`。

候选测试模组最终退役时必须同时满足：

- 主模组运行、构建和加载不依赖候选模组的 About（模组说明）、LoadFolders（加载目录）、DLL（动态链接库）、Def（定义）或资源。
- 仍有长期价值的自动测试先迁回主模组测试目录；只验证已丢弃候选业务的测试随业务一并删除。
- 候选内容已经逐项得到“迁入主模组”或“明确舍弃”的结论，不用整批猜测处理。
- Git 历史继续承担回溯作用，不为了“留备份”而保留第二个可加载模组。

## 三、目标结构

```text
BorderDefenseProtocol
│
├─ BDP.Core.dll
│  └─ 中性宿主、状态、协议、裁定、原版接入、扩展接口
│
└─ BDP.Content.dll
   ├─ Shared              内容侧公共底层
   ├─ Interface           正式玩家界面
   ├─ Development         开发诊断与编写辅助
   └─ Features            具体业务应用
```

依赖方向：

```text
BDP.Content.dll ─────→ BDP.Core.dll
BDP.Core.dll    ──X──→ BDP.Content.dll
```

## 四、什么属于核心骨架

只有同时满足下列条件的内容才能进入 `BDP.Core.dll`：

- 不知道任何具体芯片、武器、能力或玩法名称。
- 不引用内容程序集的类型、命名空间、DefName（定义名称）或资源路径。
- 删除内容程序集后仍能独立编译和加载。
- 只提供中性宿主、协议、状态、裁定、扩展口或原版适配。

核心可以知道“存在远程模块”，但不能知道“存在追踪弹”；可以知道“存在视觉附加件”，但不能知道“存在蓝色光束拖尾”。

## 五、什么属于正式内容

以下内容进入 `BDP.Content.dll`：

- 具体芯片、武器、能力、状态和组合。
- 具体伤害、消耗、射程、概率、颜色和冷却参数。
- 具体界面、贴图、音效和视觉表现。
- 对核心扩展接口的正式实现。
- 内容侧可复用但不属于核心运行必需条件的系统，例如光束拖尾。

## 六、本轮优先处理范围

现测试模组中的以下内容优先正式化：

1. 内容程序集工程与启动接线。
2. 程序集单向依赖自动检查。
3. 光束拖尾公共视觉系统。
4. Trigger（触发器）与 Trion（三离子）公共装载界面。
5. 游戏内诊断基础设施。
6. 芯片 Def（定义）公共基线。
7. 非法样本、教学内容和无调用旧代码的隔离或清理。

路线引导、追踪、爆炸、护盾、弧月、旋空弧月以及各类具体芯片属于上层应用，暂不批量重做。它们以后逐项确认正式身份、命名、参数和目录。

## 七、迁移方式

“物理合并”和“业务重做”分开：

1. 先统一模组包和两个程序集，让依赖边界固定下来。
2. 再正式整理偏底层系统。
3. 最后按单个上层应用逐项重新设计。

任何上层应用开始处理前，都必须先用浅层语言向用户说明：

- 它现在是什么。
- 它依赖什么。
- 建议保留、重做还是删除。
- 本次准备改哪些内容。
- 哪些内容明确不动。

得到确认后才能实施。

## 八、开发诊断边界

- 默认关闭，只在开发者模式或诊断开关下启用。
- 只读取正式状态，不持有业务真值。
- 不写入正式存档。
- 不成为正式玩法的必需依赖。
- 正式功能不得反向引用开发工具。
