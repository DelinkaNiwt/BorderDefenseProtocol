# BDP 事项09D：战斗体伤口视觉内容化设计

## 目标

把战斗体伤口的喷溅粒子表现从 Core 拆到 Content，同时保持玩家看到的效果、参数、时序和存读档结果不变。

## 当前问题

Core 的 `CombatBodyWoundRuntime` 当前直接持有 `CombatBodyWoundSprayRuntime`。这使 Core 不仅负责伤口严重度和 Trion 泄漏，还直接知道喷溅发射器和 Fleck Def，属于具体玩家表现业务。

## 采用方案

采用“Core 中性生命周期通知 + Content 视觉提供器”：

```text
Core 伤口运行时
  ├─ 伤口严重度与 Trion 泄漏
  ├─ 活跃伤口生命周期
  └─ CombatBodyWoundPresentationRegistry（伤口表现注册表）
          ↓ 中性通知
Content 喷溅表现提供器
  ├─ 喷溅运行时
  ├─ 单伤口喷溅发射器
  └─ Fleck Def 引用
```

Core 只传递伤口新增、移除、流失过期、Tick、清理和读档重建等生命周期信息；Content 不参与伤口规则判断，也不修改 Trion 账本。

## 关键边界

1. Core 不再出现 `CombatBodyWoundSprayRuntime`、`CombatBodyWoundSprayEmitter` 或 `WoundSprayFleckDefs`。
2. Core 不直接引用 Fleck、喷溅颜色或粒子 Def。
3. Content 只接受 Core 已判定有效的伤口通知，不访问 Core 内部伤口策略类型。
4. 伤口 Trion 泄漏仍由 Core 原有绑定负责；喷溅只是同一生命周期的可插拔表现。
5. Content 提供器异常必须被注册表隔离，不能阻断伤口扣费和伤口状态更新。

## 保持不变

- 喷溅频率、数量、速度、尺寸、颜色和镜头裁剪。
- 受伤瞬间爆发与持续喷射时序。
- 切口倾斜角的存档与读档恢复。
- 伤口严重度、Trion 泄漏、持续扣费和伤口策略 Def。

## 验证方式

- 边界烟测确认 Core/Content 物理归属和单向依赖。
- 伤口 Trion 泄漏、存档恢复和视觉生命周期专项测试继续通过。
- Core、Content、DevHarness Release 构建和全量冒烟测试复核。
