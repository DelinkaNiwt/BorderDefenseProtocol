# BDP 事项 09G：战斗体崩解冷却命名规范化实施计划

> 时间：2026-08-01（Asia/Shanghai）
> 状态：已完成

## 一、目标

修正战斗体冷却字段中残留的“紧急”语义，使名称准确表达它实际服务的对象：战斗体被动崩解后的冷却。

## 二、处理范围

- `emergencyCooldownTicks` 改为 `collapseCooldownTicks`。
- `EmergencyCooldownTicks` 改为 `CollapseCooldownTicks`。
- 同步更新 Core 内部字段、构造参数、宿主接线和退出事务读取。
- 不修改冷却数值、相位时序、玩家提示或存档字段结构。
- `CombatBodyCollapseReasonPresenter` 保留在 Core：当前只翻译通用的 `TrionAvailableDepleted` 原因，不包含紧急脱离业务，也不为一个提示额外引入 Content 注册链。

## 三、验证

1. 新增命名边界冒烟测试，先确认旧名称存在时按预期失败。
2. 验证新名称完整贯通宿主配置、战斗体服务和退出事务，旧名称不再出现在生产源码。
3. 验证 Trion 耗尽原因仍显示“Trion可用值耗尽”。
4. 运行战斗体专项、三程序集 Release 构建、Core 单向依赖门禁和全量冒烟。

## 四、行为结论

这是纯标识规范化。当前默认冷却值仍为 `0`，游戏行为不变；未来配置崩解冷却时，含义也不会再被误读成紧急脱离专用冷却。
