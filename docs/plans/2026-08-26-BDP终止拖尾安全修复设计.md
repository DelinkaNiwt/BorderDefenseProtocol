# BDP 终止拖尾安全修复设计

## 目标

修复投射物终止时最后一段拖尾丢失的问题，同时保证：

1. 普通命中、擦过目标后终止或其它正常销毁路径，拖尾显示到投射物实际终止位置。
2. 撞墙或关闭的门时，拖尾只显示到阻挡格进入前的视觉安全位置，不进入墙体范围。
3. 拖尾终止处理不读取目标中心，不重新构造一条“上一位置到目标中心”的线段。

本设计不修改路线引导模块、命中判定、伤害、投射物速度或物理命中位置。

## 根因与边界

当前 `TickInterval` 已经发布最后一次真实位置样本，但 `BeamTrailAttachment.OnTerminate` 会清除最新的活动头段，因此最后一段没有进入历史拖尾。

同时，客观阻挡逻辑目前可以把物理终点锚到阻挡格中心；拖尾绘制会直接绘制完整矩形线段，不会自动被墙体遮挡。因此物理命中点不能直接作为墙体命中的视觉终点。

## 设计

### 1. 物理终点与视觉终点分离

`BdpProjectile` 保留现有物理命中点，用于 `ExactPosition`、命中和伤害流程。

另外维护一份只服务视觉事件的终点：

- 普通终止：使用实际 `ExactPosition`。
- 客观阻挡终止：使用首次进入阻挡格之前的安全位置。
- 无法求出安全位置：标记视觉终点不安全，拖尾不固化最后活动头段。

视觉安全终点不得覆盖物理命中点。

### 2. 终止时固化已有活动头段

`BeamTrailAttachment.OnTerminate` 只调用地图组件的终止固化操作：

- 将已有活动头段的终点更新为视觉终点；
- 将该头段转入历史线段；
- 交给现有寿命系统淡出。

该操作不创建新线段，不访问目标引用、目标中心或目标语义。

如果视觉终点被标记为不安全，则清除活动头段，优先保证不穿墙。

### 3. 阻挡视觉终点

`SegmentCollisionService` 继续记录逻辑阻挡点，同时新增独立的视觉安全点：

- 根据首次进入阻挡格的路径进度，沿真实路径向前一小段反向回退；
- 候选点必须仍在阻挡格外；
- 线段终点预留极小安全余量，避免发光线帽进入墙体；
- 不能求出阻挡格外的安全点时返回“不安全”，不固化该终止头段。

这个安全点只用于视觉，不改变阻挡物命中位置。

### 4. 真实终点与目标中心隔离

视觉拖尾的最终线段必须满足：

```text
线段起点 = 上一次真实拖尾锚点
线段终点 = 最后一次真实样本终点，或阻挡命中的视觉安全点
```

禁止使用：

- `LocalTargetInfo.CenterVector3`；
- `intendedTarget`；
- `LiveFinalTarget`；
- 重新从上一位置连接到目标中心的终止补线。

## 验证

静态烟测覆盖：

- 终止时固化活动头段，而不是无条件清除；
- 固化操作可以更新终点并进入历史寿命；
- 视觉终点字段与物理阻挡终点字段分离；
- 阻挡视觉终点由路径进度和安全回退得到；
- 拖尾附加件不引用目标中心；
- 终止上下文传递视觉终点安全标记。

构建与专项烟测覆盖：

- 视觉附加宿主边界；
- 终止视觉真值；
- 续段客观阻挡；
- 投射物碰撞边界诊断；
- Core 与 Content Release 构建。

游戏内实测至少覆盖：

1. 空旷地面直射并擦过目标；
2. 直接命中目标；
3. 子弹撞墙；
4. 子弹撞关闭的门；
5. 高速子弹一 Tick（游戏刻）内撞墙；
6. 墙后存在目标时，拖尾不得穿过墙体。
