# 刀光剑影配置适配设计

日期：2026-10-09。依据：用户已要求继续功能、构型、形态、姿态适配的下一步，本阶段定稿设计与实施计划。

## 玩家行为与范围

刀光剑影原有武器配置页加入 BDP 有效近战条目，可搜索、按模组筛选、手动选择刀光、恢复自动、清除设置并保存重启。实际攻击读取对应条目，所有同类芯片实例共享配置。

配置身份依次为功能或构型、该身份实际存在的形态与姿态。构型优先于功能。无形态、姿态时省略名称标注，有姿态的形态仅生成有效姿态条目，不额外生成“无姿态”项。

第一版完成条目、默认类别、刀光纹理覆盖与实际攻击归属；不接管真实攻击距离。BDP 虚拟条目的距离区域明确显示“不适用：沿用 BDP 攻击判定”，禁用距离选择。外部扩距开启时，也不允许它按触发体定义接管 BDP 实际近战。其它武器的行为保持原有规则。

刀光尺寸跟随实际表达视觉、额外范围/能力效果、同刻双击去重调整属于独立后续范围，本计划不混入这些改动。

## 候选枚举与近战资格

1. Def（定义数据）就绪后枚举全部功能模板与构型，不依赖当前角色装载，也不按研究解锁或制造面板显示开关过滤；隐藏风刃功能也应参与。
2. 功能使用声明配置；功能与构型组合通过现有制造合法性检查后，使用现有配置复制、构型覆盖服务。不能只检查功能白名单，须同时检查职业与主分类关系。
3. 枚举真实声明的形态及所属姿态，不做所有形态、姿态的交叉组合。
4. 复用 `ChipExpressionContractInterpreter.ResolveUncached`（解释指定配置与状态）取得经过公共条目、姿态附加条目选择及工具正规化的契约，不另写一套解释器。该方法是内部成员，在兼容层通过经过签名检查的只读反射调用，返回类型 `ChipExpressionResolvedContract`（契约解释结果）已有公开结构。
5. 要求契约有效，且存在主/副 Verb（攻击通道）条目、模式为 Melee（近战）并具有有效工具表面。只有盾、防御效果、远程攻击或能力外观时，不算近战条目。原始配置有工具但当前状态未选择该条目，也不入列。
6. 定义候选表达潜在有效状态。临时缺资源、失能、盾破等运行条件不会删除玩家保存的目录项；真正播放仍由实际合法攻击驱动。

基线名单须包含弧月、蝎子、风刃，以及光魂大盾灵活姿态、光魂大盾举盾姿态、光魂重刃。两个大盾姿态都从形态公共条目继承盾击。

## 稳定身份与名称

保存键格式：`BDP.FB.v1|种类|定义键|状态所属功能键|形态键|姿态键`。各数据段使用 `Uri.EscapeDataString`（安全转义），缺失层级使用空段，避免分隔符与缺省值碰撞。

- 功能条目：种类 `F`，定义键为功能定义名；状态所属功能段为空，因为定义键已经明确来源。
- 构型条目：种类 `C`，定义键为构型定义名。没有功能自身形态、姿态时，状态所属功能段为空，多个功能共享该构型基础配置。
- 构型继承功能的形态、姿态时，状态所属功能段填写功能定义名，防止不同功能的同名状态误合并。
- 制造双功能时自动建立的功能切换形态，只用于反查来源功能；归一化回功能自身声明状态，不凭这层包装另建重复条目。
- 不使用芯片 ThingID（实例标识）、角色、左右手、显示文字、研究状态作为保存键。

名称示例：

- 弧月
- 蝎子
- 光魂【形态：光魂大盾；姿态：灵活姿态】
- 光魂【形态：光魂大盾；姿态：举盾姿态】
- 光魂【形态：光魂重刃】
- 未来构型【功能：光魂；形态：光魂大盾；姿态：举盾姿态】

组合格式使用新增语言键；各名称读取已有语言键，不把内部状态键直接当玩家名称。构型继承功能状态时显示来源功能，防止名称也发生歧义。

## 默认类别与手动设置

自动类别复用刀光剑影 `ClassifyWeaponDef`（装备类型分类）的整套工具评分，不另设 BDP 私有权重，也不按本次随机选中的工具改变整个配置项的默认类别。

分类输入使用所选有效近战契约的全部工具，并带上该条目的基础名称。为调用现有接口，可构造兼容层私有的最小 `ThingDef`（分类输入定义）；不注册到全局定义库、不进入目录、不生成物品、不用于装备或伤害，只作外部分类型参数。每份有效工具配置最多构造一份，并缓存分类结果，避免每帧构造与不断扩张外部缓存。

普通功能状态可以展示固定自动类别。同一无状态构型被多个功能共用、且覆盖后工具仍不同，须分别计算实际有效输入：若全部默认类别一致，显示该类别；否则显示“自动：随实际来源”。保存键仍是一条构型配置，手动选择覆盖全部这些来源。列表与播放使用相同分类规则，不能用池化工具评分冒充统一默认值。

手动刀光设置沿用刀光剑影现有语义：替换刀光纹理，保留自动类别所选基础效果的行为。使用其原有字符串覆盖数据库与设置文件，不另外建一份 BDP 刀光设置。

归属优先级：先选有效构型完整状态条目，否则选功能完整状态条目，再读取该条目手动设置；没有手动设置则使用该条目的自动类别。构型处于“自动”时不回退功能的手动设置。没有形态通用项、姿态通用项等额外继承层。

## 实际攻击路由与时序

在刀光剑影 `DGJY_ContextBuilder.Build`（播放上下文构建）返回后，仅处理 `BdpVerb_MeleeAttackDamage`（BDP 近战攻击）。使用其 `ResultId`（结果标识）读取公开表达结果，按来源槽与芯片实例标识定位真实芯片，再读取功能来源、构型及正式状态。

绑定的主/副来源不靠装备名猜。已确认 BDP 双近战按主侧、副侧依次执行，`MeleeAttackExecutionContext`（近战执行上下文）从当前步骤取得实际来源结果并绑定其宿主；兼容跟随该实际宿主即可，不对聚合结果固定取主侧。

在本次上下文内保存不可变播放选择，使用 `ConditionalWeakTable`（对象随生命周期释放的关联表）关联，避免每次绘制重查状态，也不维护会泄漏的全局实例字典。连击各次实际挥击各自解析当前合法来源；不重复订阅攻击完成事件播放。

若 BDP 攻击合法但来源无法定位，采用当前真实工具的自动类别，不读取触发体或其它条目的手动覆盖；Development（开发程序集）可报告失配。结构不支持或必要接口异常时，停用整个适配器并撤销它自己的补丁，保持原外部行为与 BDP 战斗可运行。

## 接入边界与补丁

全部正式逻辑放在 `Source/BDP.Compatibility/FlashingBlades/`（刀光剑影兼容目录）。保持工程只依赖 Core（核心程序集）；Content（内容程序集）的功能定义、合法性与覆盖服务通过运行时反射读取。不得修改工程引用边界，不新增 Core 业务 API（业务接口），不改触发体、芯片物品定义或真实装备来源。

必要外部接点：

| 接点 | 作用与限定 |
|---|---|
| 配置窗口 `BuildFilteredEntries` 后置处理 | 仅该页面加入虚拟条目，执行相同搜索、模组和已覆盖筛选；不改全局目录与排除列表 |
| 同窗口 `OpenModFilterMenu` | 为该页面显示包含虚拟条目的 BDP 数量，复用其它模组数据；不改全局筛选计数 |
| 同窗口 `DrawWeaponRow` 前置处理 | 仅接管本适配器键的行；显示正确名称、自动类型与禁用距离，复用原刀光菜单 |
| `DGJY_ContextBuilder.Build` 后置处理 | 仅给 BDP 实际攻击关联播放选择 |
| `ClassifyDetailed` 前置处理 | 仅已关联 BDP 上下文返回适配分类；新建结果对象，不能改外部按定义缓存的结果对象 |
| `DGJY_MeleeVfxSpawner.Spawn` 前置处理 | 仅已关联 BDP 上下文替换手动纹理参数；保留外部原有阵营、概率、去重与生成过程 |
| `TryGetExtendedRangeData` 前置处理 | 仅 BDP 实际近战拒绝按触发体定义扩距；其它攻击原样进入 |

安装前一次性检查全部类型、方法签名、字段与枚举，缓存访问器，安装原子化；失败只撤销本适配器。保留 NIT（背包页模组）既有适配器。外部缺失时不初始化目录、不调用外部设置。

触发体原有排除与阵营开关继续按外部现有规则执行；本版不为虚拟条目增加排除页控制，也不接管全局关闭效果、概率和去重。

## 验证与完成条件

可执行行为夹具覆盖真实契约解释、完整状态键、构型优先、公共近战继承、纯远程排除、无状态构型共享、不同来源自动类别、双持来源与重置保存。未来近战构型通过夹具数据验证，不把测试构型放进正式 Def 文件。

编译兼容程序集，检查它仍只依赖 Core、没有外部硬引用；回归现有兼容宿主与 NIT 边界检查。诊断仅在 Development 中启用，记录来源、结果、状态、设置键、默认类别、覆盖类别及一次播放，便于游戏内核对。

游戏内验收：名单和命名、搜索筛选、光魂三个状态分别配置、蝎子三连击次数、双持来源、芯片/状态切换、保存重启、恢复自动、清空配置、开启外部扩距仍保持 BDP 接触判定、卸载外部模组。编译通过不能代替游戏内验收。
