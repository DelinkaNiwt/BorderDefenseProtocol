# 战斗体退出伤口清理与紧急脱离三态徽标设计

## 1. 目标

本次只解决两个已经确认的问题：

1. 战斗体退出时，肉身快照恢复仍发生在 `Active`（激活）相位，恢复的肉身伤口会被伤口监听器误判为战斗体伤口并重新注册 Trion（触力/能量）持续消耗。
2. Trion Gizmo（触力操作面板）缺少独立的紧急脱离三态徽标。

不重做战斗体快照、伤口模型、紧急脱离执行链、Trigger（触发体）槽位系统或 Trion GUI（图形界面）布局。

## 2. 问题一：退出伤口运行时清理

### 2.1 根因

当前退出顺序是：

```text
清理战斗体伤口派生运行时
→ RestoreFromCombatBody（恢复肉身）
→ 恢复肉身 Hediff（健康状态）
→ 伤口监听器在 Active 相位重新注册 CombatBody/Wound 消耗
→ 相位进入 Cooldown/Inactive（冷却/未激活）
```

战斗体临时伤口本身已经被移除；错误残留来自肉身伤口恢复时产生的新注册。

### 2.2 修正

只调整退出事务中的一处顺序：

```text
恢复肉身并完成相位退出
→ 最终清理战斗体伤口派生运行时
```

`ClearActiveRuntime`（清理激活运行时）只注销 `CombatBody/Wound` 持续消耗并停止喷射表现，不删除肉身 Hediff，因此放在相位退出后不会损伤恢复完成的肉身伤口。

主动解除和被动崩解共用同一退出事务，所以这处调整统一覆盖两条退出路径。

## 3. 问题二：紧急脱离三态徽标

### 3.1 玩家可见规则

| 状态 | 图标 |
|---|---|
| 没有搭载紧急脱离芯片 | 不显示 |
| 已搭载，但当前没有正式可用的 `EmergencyEscape`（紧急脱离）表达结果 | 灰暗 |
| 已搭载，且正式 `EmergencyEscape` 表达结果可用 | 高亮 |

崩解已经开始时，以崩解入口缓存的紧急脱离结果为执行真值；缓存可用时继续高亮，避免 Trigger 被统一禁用后图标错误变灰。

### 3.2 真值来源

新增一个 CombatBody 域内的轻量只读状态解析器，合并三个既有正式读取来源：

```text
Trigger 正式装载面
  → 是否存在已装载芯片

Chip 正式定义读取面
  → 芯片是否声明 PassiveKey=EmergencyEscape

Expression 正式发布面 / 崩解入口缓存
  → 当前是否已经就绪
```

解析结果只保留三个内部枚举值：

- `NotInstalled`（未搭载）
- `InstalledNotReady`（已搭载未就绪）
- `Ready`（已就绪）

不新增存档字段、事件订阅或新的状态所有者。

### 3.3 依赖边界

依赖保持单向：

```text
Trigger / Chip / Expression 正式只读面
                  ↓
CombatBody 紧急脱离状态解析器
                  ↓
CombatBody Trion 徽标提供器
                  ↓
Trion 通用徽标扩展契约
```

禁止：

- `Gizmo_TrionStatus`（Trion 状态面板）直接读取 Trigger、Chip 或 Expression。
- 在 Trigger 或 Expression 的通用接口中增加紧急脱离专属字段。
- Trion 核心识别 `EmergencyEscape` 或紧急脱离专用图形键。

紧急脱离图标由 CombatBody 徽标提供器作为 `Texture2D`（二维贴图）传入现有通用徽标契约。Trion 核心只绘制贴图、颜色和提示文本。

### 3.4 芯片能力识别

“已搭载”按已通过正式定义校验的芯片表达声明判断：

- 基础表达条目声明 `Kind=Passive`（类型=被动）且 `PassiveKey=EmergencyEscape`。
- 形态操作中新追加或替换的表达条目声明同一被动键。
- 绑定镜像槽不重复计数。

当前只判断芯片自身声明，不把未来可能由纯组合规则凭空生成的紧急脱离能力反推成“已搭载紧急脱离芯片”。

## 4. 表现

新增一张透明背景的小型紧急脱离状态贴图：

- 轮廓简单，适合缩放到 14×14 像素。
- 不携带颜色状态；灰暗和高亮统一由徽标 `Tint`（着色）控制。
- 无文字、无阴影、无复杂细节。

提示文本固定为：

- 灰暗：`紧急脱离：未就绪`
- 高亮：`紧急脱离：已就绪`

## 5. 验证

### 5.1 静态测试

- 退出事务中的伤口运行时清理必须位于 `EnterCooldown`（进入冷却）之后，并且只执行一次。
- 三态解析器只能读取正式表面。
- CombatBody 徽标提供器不得直接扫描 Trigger、Chip 或 Expression。
- Trion 核心不得出现紧急脱离业务标识。
- 未搭载状态不产生徽标，另外两态分别使用灰暗和高亮颜色。
- 紧急脱离贴图存在并能被内容路径加载。

### 5.2 游戏内验证

1. 肉身无伤，战斗体受伤后主动解除：战斗体伤口和对应 Trion 泄露全部消失。
2. 肉身有旧伤，战斗体受伤后主动解除：肉身旧伤恢复，但没有 `CombatBody/Wound` 持续消耗。
3. 被动崩解退出：退出后没有伤口 Trion 泄露残留。
4. 未搭载紧急脱离芯片：不显示徽标。
5. 已搭载但未激活：显示灰暗徽标。
6. 已搭载且正式结果可用：显示高亮徽标。
7. 崩解入口已缓存可用结果：崩解期间保持高亮，执行并消费芯片后消失。
