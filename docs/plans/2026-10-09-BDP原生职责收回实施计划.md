# BDP 原生职责收回实施计划

日期：2026-10-09。状态：代码修改及自动验证已完成，四个程序集已重新编译；游戏内验收待实测。执行结果见 [交付记录](../reviews/BDP原生职责收回执行结果-20261009.md)。

**Goal（目标）：** 让 BDP 自有攻击原生遵守业务限制，去掉瞄准输入的全局转运和重复爆炸表现决策，同时保持既有游戏规则、原版执行时序及对其他模组的隔离。

**Architecture（架构）：** Core（核心程序集）只提供无状态的攻击准入查询；Content（内容程序集）从既有举盾健康状态提供限制。自有攻击入口直接查询，原版及第三方入口保留必要适配。目标交互在自有界面边界采集输入并显式传递；爆炸表现直接沿用已有原版参数。

**Tech Stack（技术栈）：** RimWorld 1.6（边缘世界）、C# 7.3、.NET Framework 4.8、Harmony（运行时补丁）、PowerShell（命令脚本）、现有真实程序集行为测试和游戏实测。

执行方式：后续按 `superpowers:executing-plans`（执行计划技能）逐任务实施及检查；项目指令优先，只在当前工程、当前分支工作，不创建工作树。本文不授权顺带扩大到其他系统。

### 接口与职责

最小契约示意，不引入上下文对象或另一套攻击请求：

```csharp
/// <summary>报告当前业务是否允许这个人物使用这项攻击；查询不得改变状态。</summary>
public interface IAttackAdmissionRule
{
    /// <summary>允许时返回通过；拒绝时返回已本地化的原因。</summary>

}
```

`AttackAdmissionAccess`（攻击准入入口）只提供注册和查询：启动时注册规则；没有规则默认允许；逐条查询，首个拒绝即返回。遵循现有注册设施的风格，避免重复注册；不新增自动发现、优先级、来源句柄、人物缓存或运行时撤销框架。不得把未知动作转成禁止；无有效攻击对象时让既有入口处理自身有效性。

| 场景 | 要求 |
|---|---|
