# BDP芯片正式骨架重构实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 把当前 `Core/Chips` 中偏抽象、偏企业化的旧骨架清干净，重建一套真正贴合 BDP 世界观与芯片需求的正式芯片骨架。

**Architecture:** 本次重构不再围绕“自证身份的契约对象”展开，而是围绕“BDP 中一枚真实芯片需要声明什么”展开。新骨架固定围绕 `profile / loadout / expression / trion / extensions` 五块组织；其中形态留在表达块内部，Trigger、表达系统、未来 Trion 系统统一经芯片读取口获取自己该读的块。

**Tech Stack:** C# 7.3, .NET Framework 4.8, RimWorld `ThingDef` / `Thing` / `DefModExtension`, XML Def, `dotnet msbuild`

---

## 执行提示词

### 背景

- 当前 `Core/Chips` 已经立了目录和统一读取口，但内部概念明显偏航。
- 当前偏航点包括：
- `IsFormalChip`
- `ContractVersion`
- `ChipKindKey`
- 泛 `Resource`
- 泛 `Namespace / Key / Value`
- 这些东西结构上看似完整，但不属于 BDP 玩家和内容作者自然会理解的芯片概念。

### 约束

- 主模组绝不能知道测试模组存在。
- 不允许继续保留旧坏字段作为兼容层。
- 不允许把运行结果塞回芯片定义层。
- 不允许为了“少改动”保留企业模板式命名。
- 需要激进清理污染，不留半残命名与半残校验逻辑。
- 文档、代码、日志同步推进。

### 目标结构

- `profile`
- `loadout`
- `expression`
- `trion`
- `extensions`

其中：

- `profile` 承载主分类与标签等静态芯片画像
- `loadout` 承载 Trigger 装载语义
- `loadout` 第一版侧别权限固定使用 `HandsOnly / SpecialOnly`
- `loadout` 的双持语义统一使用 `IsDualWieldBinding`
- `expression` 承载条目与形态
- `trion` 承载芯片本体级 Trion 参数
- `extensions` 保留单一总扩展区

### 明确删除对象

- `ChipIdentityConfig`
- `ChipIdentityContract`
- `IsFormalChip`
- `ContractVersion`
- `ChipKindKey`
- 泛 `Resource` 命名
- 泛 `Namespace / Key / Value` 扩展写法

## 总执行原则

- 先改文档定性，再改代码，不倒着来。
- 先删坏概念，再补新概念，不搞双轨兼容。
- 保留“统一读取入口”与“分层”这种对的骨架。
- 删除“自我声明合法”“版本号”“类型键”“泛资源”的错骨架。
- 每完成一个阶段都编译。
- 每完成一个阶段都回写日志。

## 完成标准

本计划完成时，必须同时满足：

- `Core/Chips` 只保留贴合 BDP 的正式块命名。
- 代码中不再存在 `IsFormalChip / ContractVersion / ChipKindKey`。
- 代码中不再以 `Resource` 作为芯片总层正式块名称。
- 代码中不再存在通用 `Namespace / Key / Value` 扩展结构。
- `IChipDefinitionReader` 仍作为统一入口存在。
- Trigger 从芯片读取口读取 `loadout`。
- 表达系统从芯片读取口读取 `expression`。
- 芯片本体级 `trion` 块已成立。
- 相关文档已全部收口为新骨架。
- 主模组与 DevHarness 均可编译。
