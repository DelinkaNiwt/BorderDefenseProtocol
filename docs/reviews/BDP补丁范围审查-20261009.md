# BDP 补丁范围与准入审查（2026-10-09）

当前 BDP **没有做到所有介入都具有完整隔离**。多数行为改写已有 BDP 对象、攻击来源或业务状态门槛；确认了两处会无必要地触及普通人物的遗漏。其余发现分别是作用域边界、退出清理、功能判据、注册以及兼容风险，不能一概说成“全局破坏原版”。

本次只审查，未改功能代码、定义、语言包或程序集。审查基线为当前分支 `79326c6b`；下述结论描述该版本。

## 2. “仅 BDP 准入”到底应检查谁

判断依据是**谁请求了效果、谁实际消费了效果，以及临时状态属于哪次调用**，不是每个补丁第一行都必须写“人物有 BDP 组件”。

| 场景 | 正确门槛 | 为什么不能只检查被调用对象是否 BDP |
| --- | --- | --- |
| BDP 触发体替代攻击、统计、图标 | 对象是 BDP 组件/自定义定义，且正式结果可用 | 普通武器应直接沿用原结果 |
| BDP 穿盾投射物打普通敌人 | **攻击来源**是本次 BDP 请求 | 原版敌人及其原版护盾正是需要作用的目标 |
| 持有 BDP 变色龙隐身的人使用原版武器或能力 | 广泛观察攻击；消费者核对该人物确有 BDP 隐身 | 限定“攻击动词必须 BDP”会漏掉原版武器破隐身 |
| 普通敌人倒地、死亡、复活 | 广泛观察目标；只收束正在攻击这个目标的 BDP 会话 | 目标可以完全没有 BDP 装备或基因 |
| 普通殖民者成为黑触发器形成来源 | 玩家殖民者、业务候选路线、概率/冷却等条件 | 来源人物不必预先持有 BDP 装备 |
| 共享种族/伤口定义挂宿主组件 | 定义接线范围明确；具体玩法消费有阶段/资格/结果门槛 | 种族定义是共享的，不能在启动期按未来每个人物的装备筛选 |

尤其要注意：**核心默认给全部类人挂了战斗体宿主，所以“有战斗体宿主组件”不等于“正在使用 BDP 战斗体”。** 改血流、保护装备等真正业务必须继续核验激活/崩解阶段和当前触发体；本轮已沿这些辅助条件检查。

### F01｜进入屋顶的普通人物被错误加入浮空账本

**判定：确定遗漏：普通对象被额外登记。** 代码确定：持久化记录污染、额外逐 tick 处理；搬动普通人物为满足额外条件的可证风险，尚未游戏实测。

原因：TryEnterNextPathCellPatch 为检查既有降落过渡直接 GetOrCreateRecord，创建在实际 BDP 飞行准入之前；GetOrCreateRecord 只检查非空人物。

实际影响：所有走进屋顶格的普通人物都可能写入存档并被逐 tick 处理；记录除永久销毁外一直保留。若普通登记人物倒地/死亡等并处于普通地面不可通行格，ForceGroundedImmediately 会寻找合法格并直接改位置，可能干扰其他模组的放置/运输机制。

建议：过渡检查先 TryGetRecord；仅实际 BDP 飞行或明确既有 BDP 起降过渡才消费/创建记录。另核对强制落地只对真正 BDP 飞行经历人物执行，并针对当前存档已有普通污染记录制定必要清理。用户本次是审查，暂不修改。

### F02｜普通人物死亡也会被额外重算基因对特性的抑制

**判定：确定遗漏：普通对象被额外写入。** 确定：调用和写入已从当前源码、原版程序集确认；尚未证明某第三方模组的实际冲突

原因：Pawn.Kill Prefix 在 CanCapture 前对所有人物调用 RemoveAllTemporary。该服务只检查 traits 存在，即使 OfType<Trait_BlackTriggerInherited>() 为空，仍调用 RecalculateSuppression。当前原版实现确实逐特性写 suppressedByGene，并非纯读取。BDP 没有临时特性时没有必要新增这次写入。

实际影响：普通原版、其他种族或其他模组人物只要有 story.traits 都可额外进入抑制重算；通常结果相同，但第三方临时抑制或对重算的补丁也会被无依据触发。死亡入口的 BDP 隔离不完整。

建议：在临时特性清理服务中先收集 BDP 临时特性，空集合直接返回；只在实际移除后进行必要重算。保持绑定死亡观察和形成候选观察的各自门槛。

### F03｜攻击语义与穿盾作用域没有独立嵌套伤害身份隔离

**判定：隔离缺口确定；串用影响有触发条件。** 确定缺少身份隔离；具体串用影响需同步独立回调触发，尚未游戏复现。

原因：BdpProjectile 把整个原版 TakeDamage 包在线程策略和语义作用域内，原版 TakeDamage 会调用 DamageWorker.Apply、攻击者 Hediff.Notify_PawnDamagedThing 等同步扩展回调。回调内若另行对任意目标调用普通 TakeDamage，没有推入自己的策略，便继承外层穿盾与来源语义。普通爆炸逐目标补丁会 Push(null) 清穿盾策略，但 SemanticRuntimeScope.Push(null) 是 Noop，仍继承外层语义。爆炸启动绑定还只看当前线程上下文，不认爆炸身份，BDP GenExplosion.DoExplosion 同步通知里新生成的独立爆炸可误挂 BDP 上下文。

实际影响：独立嵌套伤害可能不必要地绕过原版/BDP 盾、显示错误伤口来源；独立同步爆炸可能继承 BDP 抑制伤害/额外效果/视听设置。源 BDP 正常伤害对普通受击者执行穿盾是必要行为，本问题只针对独立嵌套请求。

建议：在真实单次伤害/单个爆炸创建边界传递并核验请求身份，明确同源子结算与独立嵌套请求的规则；独立调用形成空上下文边界，退出时恢复。由 Core 中性结算设施承载，不在每个盾消费者追加各自的绕过补丁。

### F04｜倒地及重新生成的装备保护上下文没有异常出口清理

**判定：异常出口遗漏；影响限定于 BDP 人物。** 确定：异常清理缺失已确认；残留影响是条件性风险，未作游戏内异常复现

原因：MakeDowned 与 Notify_PawnSpawned 的 Prefix 都可能 Enter(Pawn)，但只有 Postfix Exit。原版或其他补丁抛异常时 Harmony 正常 Postfix 不保证执行；保护表按 Pawn 记录深度，之后仍可能 Contains=true。邻近 CheckForStateChange 已有幂等 Restore+Finalizer，另外两条路径遗漏。

实际影响：残留不会让无战斗体的普通人物自动免掉装，因为 TryDropEquipment 还检查阶段和主触发体；但同一个 BDP 人物在 Active/Collapsing 时的后续普通卸装可能被误认为保护调用，改变原版或其他模组动作。

建议：为这两个临时上下文补齐异常出口清理，与正常出口共用幂等状态恢复；保留原异常，不吞异常，不扩展保护对象。

### F05｜远程菜单目标提示的异常/换装备退出不保证清理

**判定：异常或换装出口遗漏；影响限定于 BDP 触发体。** 确定清理只有正常 Postfix；异常或同步换装备时的影响为条件性兼容风险。

原因：Prefix 把提示写入当时主装备的 CompTriggerBody；Postfix 再读取当前主装备后清空。没有 Finalizer 清理异常路径，也没有保存真正写入的组件身份。原方法/其他补丁在提示设置之后抛异常或换装备，原触发体会保留旧提示。

实际影响：只影响 BDP 触发体之后的 PrimaryVerb 选择，可能继续返回上一次菜单目标所选的侧；普通装备原流程不变。该风险不应误称普通玩家必然遭遇的问题。

建议：用短期作用域保存当时组件与旧提示，正常/异常退出均恢复写入的同一组件；无需扩大原版菜单行为。

## 5. 广泛介入中，哪些是有意且必要的

**攻击与目标生命周期观察：** 原版武器需要触发 BDP 破隐身；普通敌人的倒地/死亡等需要通知 BDP 攻击会话。因此目标方法入口广泛有必要，消费者目前有 BDP 人物/会话身份条件。F06 是成功判据错误，与是否允许观察原版武器是两回事。

**黑触发器形成观察：** 普通殖民者可能成为形成来源，所以不能只监听现有 BDP 装备使用者。形成业务已有候选、冷却等门槛。但无 BDP 临时特性也重算特性抑制的 F02，并不因此变得必要。

**皇室血统遗传：** 指令入口确实覆盖原版遗传方法，但只有 `BDP_Gene_RoyalBloodline`（BDP 皇室血统）使用特例，其余基因继续返回原值。指令匹配要求预期的父母两处筛选；不匹配时不强行改写。

**屋顶观察：** 自有浮空网格在暂时没有浮空人物时也应保持正确，所以监听所有屋顶变化有必要。当前仅重算两种 BDP 网格，未改普通网格。但原版已有屋顶变化事件，“必须观察”不等于“必须保留这个 Harmony 补丁”，见 F14。

**皇室首发 XML：** 当前有意向全部原版与第三方叙事者追加一项 BDP 第八天定时事件，只排除已有同事件者。这确实修改了第三方叙事者的部件列表。目的是让玩家所选叙事者都能提供 BDP 皇室入口；没有替换/删除原部件，任务生成再检查扩展、资源、地图、难度和重复任务条件。若未来要允许关闭首发，应做该业务的配置，当前并没有“只给 BDP 叙事者追加”的门槛。

**广泛定义宿主：** 五种人物组件默认覆盖全部原版/第三方类人，包括敌人、商队、奴隶、囚犯。伤口提示组件覆盖原版与第三方伤口/缺失部位及派生类型。这是当前以原版组件承载后来获得的 BDP 资格与状态的明确设计，而不是筛选漏写。

不能把宿主说成完全休眠、没有任何动作：普通类人也会生成永久先天容量潜质/释放力，消费原版随机数，保存 BDP 自有字段；资源与战斗体组件存在初始化、逐刻入口和资源规则核对。没有有效腺体/激活阶段/正式业务结果时，不因此获得护盾、战斗体健康保护或紧急传送。这里确认了覆盖和工作量，未量测性能，不能直接断言造成卡顿。

**开发内容边界：** 10 个开发 Harmony 补丁有开发者模式安装条件，但 3 个开发 XML 示例随加载文件夹始终加载，会追加指定 BDP 预设/语义配置。它们只匹配 BDP 定义，不侵入原版定义；当前也不能说“关闭开发者模式后所有开发内容都不存在”。
