# Targeting 输入事实桥接裁定（第一版）

## 1. 问题

当前 `Targeting（瞄准阶段）` 正式输入面只能表达：

- 当前选中目标
- 当前是否确认
- 当前是否取消

当前正式输入面不能表达：

- 当前点击来自哪个鼠标按钮
- 当前点击附带了哪些修饰键

这会导致业务模块无法在同一 `Targeting（瞄准阶段）` 内区分：

- 普通左键选择
- `Shift（换挡键） + 左键` 辅助选择

## 2. 裁定

主模组补一个**最小、中性、无业务语义**的输入事实桥。

补充范围限定为：

- `TargetingInputButton（目标输入按钮）`
- `TargetingInputModifiers（目标输入修饰键）`
- `TargetingInputRuntimeFacts（目标输入运行时事实）`
- `TargetingInputRuntimeScope（目标输入运行时作用域）`

并在 `Targeter.OrderPawnForceTarget（原版瞄准器下达 Pawn 强制目标）` 前后加一层薄桥：

- 进入时压入当前按钮与修饰键事实
- 离开时立刻弹出

## 3. 不做的事

- 不在主模组加入任何毒蛇、锚点、路径、终点等业务字段
- 不在主模组加入 `IsAnchorClick（是否锚点点击）` 之类业务判断
- 不改 `AttackExecution（攻击执行）` 正式边界
- 不改子弹、飞行、命中链

## 4. 原则

- 主模组只提供输入事实，不解释业务语义
- 业务模块自行解释：
  - 普通左键是什么
  - `Shift（换挡键） + 左键` 是什么
  - 右键取消是什么

## 5. 结果

补完后，业务模块已经可以在同一 `Targeting（瞄准阶段）` 中基于中性输入事实区分：

- 左键最终目标
- `Shift（换挡键） + 左键` 辅助点击
- 其它未来修饰键组合

同时主模组仍然保持中性，不持有任何毒蛇专用概念。
