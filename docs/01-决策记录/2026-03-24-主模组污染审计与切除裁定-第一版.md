# 主模组污染审计与切除裁定（第一版）

## 目的

这份记录用于把本轮回审得到的污染项、保留项、切除原则与补位方向正式钉死。

本记录不是实现过程说明，
而是当前主模组状态的正式裁定结果。

## 一、审计结论

当前新 BDP 在 `B1-a` 推进过程中，
已经出现一次明确的架构污染。

污染的本质不是“代码写得丑”，
而是：

- 为了尽快获得游戏内可视化反馈
- 把测试层能力直接并入主模组正式宿主
- 让 `CompTriggerBody` 再次朝上帝模块方向膨胀

这与二次重构的根本目标直接冲突。

## 二、已识别污染项

### 1. 主模组内置测试 GUI

以下内容被裁定为测试污染：

- `Source/BDP/Core/Trigger/Window_TriggerBodyDiagnostics.cs`

裁定理由：

- 它是临时测试窗口
- 它不属于正式业务结果
- 它不属于正式读取协议
- 它删除后不应影响主模组存在意义

因此它不应留在主模组中。

### 2. `CompTriggerBody` 中的测试按钮入口

以下内容被裁定为测试污染：

- `BuildDebugGizmos(...)`
- `CompGetEquippedGizmosExtra()` 中 `Prefs.DevMode` 下插入 debug gizmo 的分支

裁定理由：

- 这是测试交互入口
- 不是 Trigger 正式职责
- 会把测试便利绑进正式按钮链

因此必须切除。

### 3. `CompTriggerBody` 中的测试专用查询口

以下内容被裁定为测试污染：

- `GetSlotsForDebug(...)`
- `GetHeldChipsForDebug(...)`
- `IsSlotContainerConsistentForDebug(...)`
- `RunIntegrityRepairForDebug(...)`

裁定理由：

- 这些接口以“给临时测试窗口服务”为直接目的
- 它们不是正式对外读取协议
- 它们会诱导 owner 继续承载测试读取责任

因此必须切除。

## 三、已识别的文档污染

以下文档已被错误实现带偏，
必须同步修正：

- `docs/plans/2026-03-24-B1-Trigger装载规则落地-执行清单.md`
- `docs/99-会话交接/2026-03-24-工作推进-卷02.md`

被带偏的典型表述包括：

- 把主模组内置临时 GUI 说成阶段成果
- 把“已有第一个可测试环节”建立在污染实现之上
- 让“可视化测试面”默认落入主模组

这些表述必须被改成：

- 测试机会必须存在
- 但测试层必须通过正式扩展口或外置测试层接入
- 主模组不直接承载临时测试 GUI

## 四、允许保留项

以下内容当前允许保留在主模组：

- 装载成功与失败日志
- 卸载成功与失败日志
- 激活与关闭请求日志
- 读档后一致性修复日志
- 一致性修复失败日志

允许保留的前提是：

- 它们属于关键、非高频、非循环诊断点
- 它们服务正式问题定位
- 它们不要求主模组额外提供测试交互层

换句话说，
允许保留的是“诊断信号”，
不是“测试界面”。

## 五、切除原则

从本次裁定开始，
凡是同时满足以下任一条件的内容，
一律优先判定为污染候选：

1. 只服务测试节奏，不服务正式业务
2. 删除后主模组本应毫无损失
3. 以 owner 最方便下手为理由进入 owner
4. 不属于正式读取口，却长期暴露给外部
5. 以 DevMode 为理由混入正式链路

对这类内容的默认处理不是“先留着”，
而是：

- 记录
- 切除
- 如有必要，再通过正式扩展口在外层补位

## 六、正确补位方向

本轮切污后，
`B1` 的“短阶段可测、可视、可反馈、易诊断”要求仍然有效，
但落地方向必须改为：

### 1. 主模组

只保留：

- 正式业务
- 正式最小读取口
- 关键诊断日志
- 正式扩展口

### 2. 测试层

如需游戏内可视化测试，
必须优先通过以下方式进入：

- 正式扩展口
- 测试模组
- 可直接删除的外置 GUI 层

### 3. 责任边界

`CompTriggerBody` 只负责：

- 装载真值
- 局部激活真值
- 局部禁用真值
- 局部切换协调

不再承载：

- 测试窗口
- 测试按钮
- 测试专用查询口

本轮应立即执行以下动作：

1. 删除 `Window_TriggerBodyDiagnostics.cs`
2. 删除 `CompTriggerBody` 内所有 debug gizmo 与测试专用查询口

4. 保留关键诊断日志

本轮回审的正式结论是：`B1-a` 为了快速形成可视化测试反馈而把测试 GUI、测试按钮和测试专用查询口直接并入主模组，已经构成明确的架构污染；这些内容必须从主模组中一刀切净，只保留服务正式问题定位的关键诊断日志，并把“短阶段可测”重新压回“正式扩展口 + 外置测试层 + 正式读取口”的正确架构轨道。
