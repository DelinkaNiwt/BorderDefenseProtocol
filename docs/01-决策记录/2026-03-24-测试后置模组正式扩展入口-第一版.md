# 测试后置模组正式扩展入口（第一版）

## 目的

明确测试后置模组与主模组的关系边界，避免为了测试而直接改写主模组正式链路。

## 结论

主模组正式提供“触发体额外按钮扩展口”：

- `ITriggerExternalGizmoProvider`
- `TriggerExternalGizmoContext`
- `TriggerExternalGizmoRegistry`

测试后置模组如果需要给触发体追加测试按钮，必须：

- 实现 `ITriggerExternalGizmoProvider`
- 在启动时注册到 `TriggerExternalGizmoRegistry`
- 按钮内部只调用主模组公开方法

禁止测试后置模组通过 Harmony 直接改写：

- `CompTriggerBody.CompGetEquippedGizmosExtra()`
- 主模组正式业务状态
- 主模组内部真值持有对象

## 原因

如果测试按钮本身靠 Harmony 偷挂到主模组方法上，那么测试模组虽然物理上独立了，但接入方式仍然不正式。

这会带来几个问题：

- 主模组没有真正暴露扩展能力
- 测试模组不是“普通扩展内容”，而是在偷偷改主模组
- 以后别人要扩展内容时，也会被引导去走补丁而不是正式协议

这与本次二次重构的目标冲突：

- 主模组提供骨架与标准协议
- 外部内容通过协议自然扩展
- 测试模组本身也应作为这种扩展性的验证者

## 当前边界

主模组负责：

- 提供触发体正式按钮链路
- 提供额外按钮扩展口
- 提供装载、卸载、激活、关闭等正式接口

测试后置模组负责：

- 提供测试 Def
- 提供测试按钮
- 通过正式接口驱动主模组功能

## 直接影响

从这一版起：

- 删除测试后置模组后，主模组不应残留任何测试 Def、测试按钮或测试补丁
- 测试模组的存在不应改变主模组正式按钮链路的实现方式
- 测试模组只是“注册额外按钮提供器”的一个普通扩展案例
