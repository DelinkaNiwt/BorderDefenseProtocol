# 芯片制造系统正式化重设计（第一版）

> 状态：设计阶段完成，待实施 | 2026-08-06

## 一、背景

当前芯片制造系统为原型验证级实现。本次重设计目标是将其从"枪械类远程武装芯片制造器"升级为"芯片制造器"，对芯片一视同仁、统一处理。

## 二、核心设计决策

### 2.1 三套模板模型

芯片制造采用三套独立模板体系，玩家通过"点菜/点套餐"的方式组合：

| 模板层 | Def 类型 | 内容 | 制造时角色 |
|-------|---------|------|----------|
| 物品模板 | `ThingDef`（当前 `BDP_Chip_Custom`） | 贴图、Mass、thingClass、Comp 声明 | 产物外壳，当前 1 个，保留扩展口 |
| 灵魂模板 | 新 Def 类型（替代原型 `ExpressionEntryTemplateDef`） | 完整芯片定义数据 | **必选**，1 个灵魂 = 1 枚芯片 |
| 外壳模板 | `WeaponClassDef`（已有） | 远程武器参数覆盖集 | **可选**，仅当灵魂含 Ranged Verb 条目时可用 |

### 2.2 制造本质

制造面板不是"从零设计芯片的工具"，而是**一个菜单**——所有可选项（灵魂、外壳）都是 XML 预设，玩家只做选择和组合，不做字段级定制。

制造产出始终为 `BDP_Chip_Custom` ThingDef 实例，通过 `CompManufacturedChip` 注入运行时配置。

### 2.3 统一制造路径

废除"预制芯片 ThingDef vs 制造芯片 BDP_Chip_Custom"双轨制。正式芯片（弧月、旋空、护盾等）不再作为独立 ThingDef 存在——它们的配置数据迁移到灵魂模板中，所有芯片统一通过制造产出。

### 2.4 标签驱动的制造模式

`ChipTagDef` 不仅是芯片画像标签，在制造面板中承担**第二级筛选**和**制造模式路由**的职责。不同标签对应不同的操作流程。

枪手、射手、狙击手概念上都属于远程射击，它们的表达动作 Verb 模板共用同一套预设池。

#### 模式 A：射手（无外壳、必须 1 表达）

```
类别筛选 → 射手标签 → 选 1 项表达动作
```

- 无外壳
- 必须选且只能选 1 个芯片预设，可为单形态或多形态
- 最通用、约束最少的模式——作为未知标签的默认回退

#### 模式 B：枪手（有外壳、1~2 表达）

```
类别筛选 → 枪手标签 → 选枪械外壳 → 选 1~2 项单形态表达动作
```

- 外壳（`WeaponClassDef`）必选，从枪手标签兼容的枪械列表中选取
- 芯片预设可选 1~2 个，必须为单形态（自身无 Modes）
- 选 2 个时合并为一个芯片定义，每个预设 = 一个 Mode，外壳字段覆盖所有 Ranged Verb 条目

#### 模式 C：狙击手（有外壳、无表达选择）

```
类别筛选 → 狙击手标签 → 选枪械外壳（与枪手不同的列表）
```

- 外壳（`WeaponClassDef`）必选，从狙击手标签兼容的枪械列表中选取
- 表达动作由枪械外壳通过 `fixedChipPreset` 字段内置引用，玩家不需要选择
- `fixedChipPreset` 指向一个已定义的芯片预设 Def

#### 规则总结

| 标签 | 外壳 | 表达选择数 | 外壳列表 | 备注 |
|------|------|-----------|---------|------|
| 射手 | 无 | 1（必选） | 不适用 | 未知标签默认回退为此模式 |
| 枪手 | 必选 | 1~2（仅单形态） | 列表 A | - |
| 狙击手 | 必选 | 0（外壳内置） | 列表 B | WeaponClassDef.fixedChipPreset |

结果恒为：**1 芯片 = 1 个完整定义**（枪手模式下由 1~2 预设 + 外壳合并而成）。

#### 默认回退

未匹配已知制造模式规则的标签，制造窗口默认走**射手模式**（无外壳、选 1 个预设）。理由：射手约束最少，底层足够通用，不会错误地强制外壳选择。

### 2.5 制造面板交互维度

```
① 类别选项卡（ChipCategoryDef）
   └→ 筛选芯片预设的范围

② 标签筛选（ChipTagDef）
   └→ 决定制造模式路由（射手/枪手/狙击手），进而决定后续步骤

③ 芯片预设选择（所有模式必有）
   └→ 射手：1 个预设（单/多形态均可）
   └→ 枪手：1~2 个单形态预设
   └→ 狙击手：由外壳 fixedChipPreset 自动确定，UI 不展示此步骤

④ 外壳选择（枪手/狙击手模式）
   └→ 从当前标签兼容的 WeaponClassDef 列表选取
   └→ 射手模式不展示

⑤ 制作数量

⑥ 预览区
   └→ 芯片最终名称 / 材料清单 / 关键参数摘要
```

#### 架构定位说明

以上制造模式规则属于**中上层业务规则**——底层数据对象（芯片预设 Def、`WeaponClassDef`、`ChipTagDef`）保持纯粹的数据定义，不直接编码流程逻辑。制造窗口/Controller 层负责根据标签路由到不同的选择流程。

`WeaponClassDef` 新增两个字段支撑制造模式：
- `compatibleTags`：声明此枪械适用于哪些标签（用于区分列表 A / 列表 B）
- `fixedChipPreset`：可选，指向一个芯片预设 DefName。声明后制造 UI 跳过表达选择

### 2.6 命名约定

讨论中"灵魂模板"为比喻用语。正式代码中命名为 **`ChipPresetDef`（芯片预设）**，契合"菜单点菜/点套餐"的制造定位。一个 `ChipPresetDef` 承载一枚芯片的完整静态定义数据（`ChipDefinitionConfig`），是制造时玩家选择的基本单位。

原型阶段的 `ExpressionEntryTemplateDef` 在新设计中被 `ChipPresetDef` 取代。

### 2.7 芯片预设数据结构

`ChipPresetDef`（新 Def 类型，替代原型 `ExpressionEntryTemplateDef`）承载完整 `ChipDefinitionConfig`，除武器身份字段（`weaponClassName`/`weaponClassLabel`）由外壳在制造时写入：

```xml
<ChipPresetDef>
  <defName>BDP_Preset_Kogetsu</defName>
  <label>弧月</label>
  <description>以实体弧月刃形成近战武装...</description>
  <config>
    <Profile>...</Profile>               <!-- Category + Tags -->
    <Loadout>...</Loadout>               <!-- 槽区/槽占/延迟 -->
    <Trion>...</Trion>                   <!-- 容量成本/激活成本 -->
    <ActivationRequirements>...</ActivationRequirements>
    <Expression>                         <!-- 行为定义 -->
      <Entries>...</Entries>
      <Modes>...</Modes>                 <!-- 定义则 = 多形态 -->
    </Expression>
    <Extensions>...</Extensions>
  </config>
</ChipPresetDef>
```

单形态/多形态判断：直接从 `config.Expression.Modes` 是否为空/Count <= 1 判断，无需额外字段。

### 2.8 WeaponClassDef 扩展

```xml
<WeaponClassDef>
  <defName>BDP_WeaponClass_SniperRifle</defName>
  <label>狙击步枪</label>
  <compatibleTags>                      <!-- 新增：适用标签过滤 -->
    <li>BDP_ChipTag_SniperUse</li>
  </compatibleTags>
  <fixedChipPreset>BDP_Preset_SniperBase</fixedChipPreset>  <!-- 新增，可选 -->
  <overrides>...</overrides>
</WeaponClassDef>
```

- `compatibleTags`：空 = 适用所有枪手类标签（回退）。制造面板按标签过滤展示。
- `fixedChipPreset`：可选 DefName。声明后 = 狙击手模式，制造 UI 跳过表达选择。

### 2.9 制造时不可微调

玩家决策范围严格限定为：选哪个预设 + 选哪个外壳 + 做几个。所有数值（Trion、Loadout、Requirements）由预设和外壳的 XML 定义决定，制造面板不提供字段级微调。

### 2.10 两预设组合时的非 Expression 字段合并

仅枪手模式下发生（2 个单形态预设 + 外壳）：

| 字段组 | 合并规则 |
|--------|---------|
| Profile.Category | 必须相同，否则拒绝组合 |
| Profile.Tags | 取并集 |
| Loadout.SlotRegion/Occupancy | 必须一致，否则拒绝组合 |
| Loadout.激活/停用延迟 | 取 max |
| Trion.CapacityCost/ActivationCost | 取 max |
| ActivationRequirements | 取并集去重 |
| Expression | 每个预设 → 一个 Mode（外壳覆盖统一施加） |
| Extensions | 取并集 |

### 2.11 读取链简化

当前所有消费方需做"先 Comp 后 modExtension"双路径判断。新模型下不再有 modExtension 路径——所有芯片配置统一在 Comp 中，读取链退化为单路径。

### 2.12 成本体系

#### 成本声明位置

| 对象 | 字段 | 说明 |
|------|------|------|
| `ChipPresetDef` | `costList: List<ThingDefCountClass>` | 该预设的基础材料成本 |
| `WeaponClassDef` | `additionalCost: List<ThingDefCountClass>` | 外壳附加材料成本（可选） |

`ThingDefCountClass` 为 RimWorld 标准类型（ThingDef + count），与 RecipeDef 材料定义同构。

总材料成本 = Σ(选中预设.costList) + 外壳.additionalCost（如有）。

#### 材料扣除

使用 RimWorld 标准 API 泛化扣除，替代当前原型的白银专用硬编码 `TryDeductSilver`。

### 2.13 制造耗时

采用简单规则：**基础工时 + 预设附加工时 + 外壳附加工时**。

| 来源 | 字段 | 说明 |
|------|------|------|
| `Building_ChipFabricator` | `baseWorkTicks` | 制造台固定基础工时（如 ~3000 ticks） |
| `ChipPresetDef` | `additionalWorkTicks: int` | 该预设附加的额外工时（默认 0） |
| `WeaponClassDef` | `additionalWorkTicks: int` | 外壳附加的额外工时（默认 0） |

总工时 = baseWorkTicks + Σ(选中预设.additionalWorkTicks) + 外壳.additionalWorkTicks（如有）。

制造台采用 Biotech 式 `Start → DoWork → Finish` 状态机，由 WorkGiver/JobDriver 驱动小人完成工作。

### 2.14 倍率系数系统

所有制造消耗（材料、工时）统一经过倍率管道计算，默认系数 = 1.0。

| 倍率 | 字段 | 说明 |
|------|------|------|
| 材料倍率 | `materialCostMultiplier: float` | 默认 1.0 |
| 工时倍率 | `workTicksMultiplier: float` | 默认 1.0 |
| 开发者倍率 | `devMultiplierEnabled: bool` | 置 true 时：材料 = 0，工时 = 0（瞬间制造）。BDP 模组自身的设置选项，与 RimWorld 开发者模式无关 |

```csharp
int finalCost = devMultiplierEnabled ? 0 : Mathf.RoundToInt(rawCost * materialCostMultiplier);
int finalTicks = devMultiplierEnabled ? 0 : Mathf.RoundToInt(rawTicks * workTicksMultiplier);
```

倍率系数放在独立 `ChipManufacturingSettings` 静态类中，保留公开读写口（属性 + 变更回调），供未来 Mod 选项面板接入。

#### 标签级成本修正（预留）

`ChipTagDef` 可声明 `costMultiplier: float` 字段施加标签级成本修正。当前默认不需要（系数 = 1.0），字段预留。此修正与全局倍率**叠乘**。

### 2.15 批量制造

允许。单次面板操作可指定制作数量（默认 1），上限由制造台所在地图可用材料库存实时动态决定。材料检查在点击制造按钮时执行；不足时拒绝并提示缺少的材料类型和数量。

### 2.16 产物预览信息条目

预览区展示条目按逻辑分组，用浅灰分隔线区隔：

| 分组 | 条目 | 说明 |
|------|------|------|
| 身份 | 芯片名称 | 自动生成，Medium 字体 |
| 身份 | 类别 · 标签 | 灰色小字 |
| 运行参数 | 槽位与占用 | Loadout.SlotRegion + SlotOccupancy |
| 运行参数 | 激活/停用延迟 | ticks + 秒数 |
| 运行参数 | Trion 容量占用 / 激活消耗 | Trion.CapacityCost / ActivationCost |
| 激活条件 | 条件列表 | Trion 释放力 ≥ N、技能 ≥ N 等；仅当有 Trion >= 1 以外的条件时展开显示 |
| 形态摘要 | 每个 Mode 的名称 + 简介 | 多 Mode 分列，单 Mode 单行 |
| 枪型特征 | 射程/命中/节奏（仅覆盖的非 null 字段） | **仅武装·枪手/狙击手模式出现**；音效/投射物/视觉不显示 |
| 材料 | 材料清单 | 不足标红 |
| 工时 | 预计秒数 | |
| 数量 | 制作数量调节 | 上限由库存决定，达上限后 + 号灰显不可点击 |

不显示的条目：
- "单形态/双形态"标签——形态列表本身已体现
- "库存可制造 N 个"——数量调节上限已隐含，不额外展示

### 2.17 类别体系扩展与面板自适应

已有类别之外，新增"状态"和"被动"两个类别，当前共 5 个：

```
ChipCategoryDef
├── 武装（Weapon）
│   ├── 攻击手（已有 BDP_ChipTag_AttackerUse）→ 近战，无外壳，选 1 个预设
│   ├── 射手                                → 中距离，无外壳，选 1 个预设
│   ├── 枪手                                → 中距离，有外壳，选 1~2 个单形态预设
│   └── 狙击手                              → 超远程，有外壳，无表达选择（外壳内置）
├── 防护（Defense）
├── 能力（Ability）
├── 状态       ← 新增
└── 被动       ← 新增
```

#### 武装标签距离定位

| 标签 | 距离定位 | 外壳 | 表达选择 |
|------|:------:|:---:|:------:|
| 攻击手 | 近战 | 无 | 1 |
| 射手 | 中距离 | 无 | 1 |
| 枪手 | 中距离 | 有 | 1~2 |
| 狙击手 | 超远程 | 有 | 0（内置） |

面板自适应规则：

| 条件 | 标签行 | 枪型行 | 预设选择 | 预览特有 |
|------|:-----:|:-----:|:-------:|---------|
| 武装类 | 显示（攻击手/射手/枪手/狙击手） | 枪手/狙击手时显示 | 按标签规则 | 枪型特征（射程/命中/节奏） |
| 其他类别 | 隐藏 | 隐藏 | 选 1 个预设 | 无特有（后续按需扩展） |

非武装类别当前简化处理：类别选项卡 + 预设列表 + 预览区。后续按各自需求扩展。

### 2.18 半成品芯片

参照原版 `UnfinishedThing` 机制。制造确认后不直接产出成品，而是创建半成品物品 `BDP_Chip_Unfinished`，存入制造台 `innerContainer`，小人对其工作直至完成。

#### 新 ThingDef：`BDP_Chip_Unfinished`

- thingClass: `Thing_UnfinishedChip : ThingWithComps`
- 存储：`workLeft`（剩余工时）、`totalWorkRequired`、`queuedConfig`、`queuedQuantity`、`chipLabel`、`ingredients`（已耗材料列表，用于取消返还）、`creator`

#### 生命周期

```
确认制造 → 扣除材料 → 创建 Unfinished 存入 innerContainer → 开始工作
  工作中 → DoWork() 减少 workLeft
  workLeft <= 0 → Finish() → 销毁 Unfinished → 生成成品芯片
  取消（Gizmo） → Destroy(DestroyMode.Cancel) → 返还 75% 材料
  制造台离图 → 弹出 Unfinished 到地面（保留进度）
```

#### 复工（后续）

右键地面上的 Unfinished → "在制造台上继续" → 附近有可用制造台时开始继续工作。
