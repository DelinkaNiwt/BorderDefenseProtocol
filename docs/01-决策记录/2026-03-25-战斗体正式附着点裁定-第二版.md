# 战斗体正式附着点裁定（第二版）

## 当前有效裁定

战斗体主链当前正式附着到：

- `Pawn ThingComp`

具体说：

- 以 `CompCombatBodyHost` 作为 Pawn 身上的正式主链宿主位
- 以 `CombatBodyState` 继续持有战斗体相位真值
- 以 `CombatBodyCoordinator + EnterPipeline + ExitPipeline` 继续承担主链事务编排

## 同时明确排除

下列对象都不是战斗体主链宿主：

- `Hediff / HediffComp`
- `CompTriggerBody`
- `CompTrion`
- 额外平行生命周期容器

## Hediff 的正式位置

`Hediff` 在战斗体领域中的正式位置是：

- 战斗体处于激活、崩解等阶段时的身体状态表现层

不是：

- 主链常驻宿主
- 相位真值 owner
- 总流程协调者

## 采用 Pawn ThingComp 的原因

### 1. 需要一个常驻、自然、可序列化的 Pawn 主链挂接点

战斗体主链要长期存在于 Pawn 身上，
并承接：

- 相位状态
- 进入请求
- 离开请求
- 事件广播

当前最自然且侵入性最低的正式宿主位是 Pawn `ThingComp`。

### 2. 它不会把 Hediff 误用成常驻骨架

如果让 `Hediff` 承担主链宿主，
就会自然滑向：

- 常驻身体状态承载主链
- 表现层和主链骨架混合

这与当前明确裁定冲突。

### 3. 它不会打破三核心真值边界

`CompCombatBodyHost` 只是宿主位与对外面承接位，
不是第四个真值核心。

当前三类真值 owner 仍然只有：

- `CompTrion`
- `CombatBodyState`
- `CompTriggerBody`

## 结构边界

### 1. `CompCombatBodyHost`

它负责：

- 挂在 Pawn 身上
- 承接战斗体主链运行时对象
- 对外暴露 `Reader / Commands / Events`

它不负责：

- 自己另持相位真值
- 自己另持资源真值
- 自己另持 Trigger 装载真值

### 2. `CombatBodyHostAccess`

它负责：

- 从 Pawn 上取正式外部面

它不负责：

- 构造平行状态
- 兜底创造临时宿主
- 绕开正式主链直接改状态

### 3. `Hediff`

后续若接入：

- `Active`
- `Collapsing`
- 其他身体状态表现

都只能作为阶段表现层，
由战斗体主链驱动生成与清理。

## 一句话裁定

战斗体当前正式附着点是 Pawn `ThingComp`；`Hediff` 只允许作为战斗体激活或崩解时的表现层存在，不再承担战斗体主链宿主职责。
