# 远程目标语义与合法性边界口径（第一版）

## 目的

这份口径文档只做一件事：

- 把主模组里已经存在的远程目标字段、冻结节点和合法性判断边界重新说清楚。

这次不新增大系统，不引入 `TargetRole（目标角色）` 大枚举，也不把毒蛇的路径业务硬塞进主模组。

## 1. 目标字段词汇表

- `Target（导航目标）`
  - 指确认阶段最终写回的导航目标。
  - 它服务导航、朝向、首段物理发射与宿主兼容链读取。
- `SemanticTarget（语义目标）`
  - 指确认阶段最终写回的语义目标。
  - 它服务命中语义、后半段 `intended target（意图目标）` 和 `dual（双侧）` 等多目标场景。
  - 未显式给出时，默认回退到 `Target（导航目标）`。
- `NavigationTarget（冻结后的导航目标）`
  - 指写进 `ConfirmedTargetSnapshot（已确认目标冻结快照）` 的导航目标。
  - 它是确认结果冻结后的导航口径，不再允许后续阶段随意重猜。
- `LaunchTarget（发射目标）`
  - 指投射物真正朝向的目标。
  - 它偏物理发射与首段飞行。
- `AimTarget（瞄准目标）`
  - 指投射物解算瞄准、散布与命中概率时使用的目标。
  - 它可以和 `LaunchTarget（发射目标）` 相同，也可以不同。
- `CurrentTarget（当前目标）`
  - 指宿主兼容链需要消费的当前目标快照。
  - 它是兼容字段，不应该反过来重新定义发射目标和瞄准目标。
- `NextDestination（下一段目的地）`
  - 指飞行阶段下一段几何推进落点。
  - 它表达“往哪里飞”，不直接表达“这次算打谁”。
- `NextTarget（下一段目标）`
  - 指飞行阶段下一段给后续逻辑消费的目标位。
  - 它和 `NextDestination（下一段目的地）` 可以一致，但职责仍然分离。

## 2. 各阶段字段流转

- `TargetingInputFrame（瞄准输入帧）`
  - 保存玩家当前输入结果与被选中的目标。
- `ConfirmRecord（确认阶段记录）`
  - 把确认阶段最终结果整理成：
    - `Target（导航目标）`
    - `SemanticTarget（语义目标）`
- `ConfirmedTargetSnapshot（已确认目标冻结快照）`
  - 冻结成：
    - `NavigationTarget（冻结后的导航目标）`
    - `SemanticTarget（冻结后的语义目标）`
- `ProjectileInitPlan（投射物初始化计划）`
  - 再拆到：
    - `LaunchTarget（发射目标）`
    - `AimTarget（瞄准目标）`
    - `CurrentTarget（当前目标）`
- `ArrivalContribution（到达阶段贡献）`
  - 只允许给出：
    - `NextDestination（下一段目的地）`
    - `NextTarget（下一段目标）`

这条流转的核心原则是：

- 导航值和语义值可以缺省回退，
- 但不能在主模组里重新混成一个“万用目标”。

## 3. 候选合法性 / 段合法性 / 最终确认合法性

- 当前候选点合法性
  - 指 `Targeter（原版目标器）` 当前这一帧鼠标候选点是否合法。
  - 作用是：
    - 光标提示
    - 禁止图标
    - 即时拒绝文字
  - 它不是正式确认结果。
- 段合法性
  - 指“某个起点 -> 某个候选目标”这一段现在能不能成立。
  - 主模组通过 `TargetingSegmentLegalityRequest（段合法性请求）` 与 `ITargetingSegmentLegalityService（段合法性服务）` 提供中性查询口。
  - 它不是整次攻击是否合法，只是单段事实判断。
- 最终确认合法性
  - 指这次攻击能不能正式下单并进入执行链。
  - 这是 `Confirm（确认阶段）` 与业务模块共同负责的正式结论。

一句话区分：

- 当前候选点合法性 = 当前光标能不能这样指。
- 段合法性 = 这一段几何 / 原版规则现在能不能成立。
- 最终确认合法性 = 这次攻击能不能正式落地。

## 4. 主模组负责什么

- 定义中性字段口径：
  - `Target（导航目标）`
  - `SemanticTarget（语义目标）`
  - `NavigationTarget（冻结后的导航目标）`
  - `LaunchTarget（发射目标）`
  - `AimTarget（瞄准目标）`
  - `CurrentTarget（当前目标）`
- 定义冻结与流转节点：
  - `ConfirmRecord（确认阶段记录）`
  - `ConfirmedTargetSnapshot（已确认目标冻结快照）`
  - `ProjectileInitPlan（投射物初始化计划）`
- 提供中性合法性查询口：
  - 当前候选点即时反馈口
  - 单段合法性查询口
- 提供默认回退规则：
  - 没有显式语义目标时，回退到导航目标。

## 5. 业务模块负责什么

- 决定什么时候要写入独立的 `SemanticTarget（语义目标）`。
- 决定什么时候 `LaunchTarget（发射目标）` 与 `AimTarget（瞄准目标）` 应该分离。
- 决定多段飞行时的：
  - `NextDestination（下一段目的地）`
  - `NextTarget（下一段目标）`
- 决定最终确认是否允许下单，以及拒绝原因是什么。
- 决定视觉层、逻辑层、校验层的具体业务规则。

换句话说：

- 主模组给“口”和“骨架”。
- 业务模块给“赋值”和“细化规则”。

## 6. 明确不做什么

- 不在主模组里新增 `Viper（毒蛇）`、`PathLatch（路线引导）`、锚点、路径等业务术语。
- 不把主模组扩成统一路径系统。
- 不新增 `TargetRole（目标角色）` 这类大一统总枚举。
- 不让 `DefaultTargetingSegmentLegalityService（默认段合法性服务）` 接管最终确认责任。
- 不让宿主层把“当前候选点是否合法”误当成“最终是否允许攻击”。

## 本轮裁定

- 值得上提的只有：
  - 统一目标口径
  - 统一冻结口径
  - 统一语义目标默认解析口径
  - 统一单段合法性边界口径
- 不值得上提的仍然留在业务模块：
  - 路径业务
  - 锚点业务
  - 具体多段飞行策略
  - 业务专属最终确认规则
