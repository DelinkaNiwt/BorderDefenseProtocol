# 命名原则：Main / Sub（第一版）

## 目的

这份记录只解决一个问题：

- 二次重构里，触发体内部与按侧相关的命名到底怎么定

这个问题本身不算最大需求，
但它会影响：

- 核心对象名
- 字段名
- 接口名
- 文档表述

如果现在不定，
后期越改越痛。

## 一、最终决定

触发体内部稳定命名统一采用：

- `Main`
- `Sub`

并固定约定：

- `Main = 右`
- `Sub = 左`

## 二、为什么不用 `Left / Right`

因为旧 BDP 已经暴露出两个冲突：

### 1. 身体部位直觉是对的

触发体槽位和：

- 左手是否缺失
- 右手是否缺失
- 左右手部位损坏

确实有直接联系。

所以旧版很多地方写 `LeftHand/RightHand`，
本来是为了和身体事实保持直觉一致。

### 2. 玩家观察体验又会反过来违和

RimWorld 中小人静默待机时常常面朝玩家，
这时玩家感知的左右，
和角色身体自己的左右往往是反的。

于是：

- 用 `Left/Right` 做内部稳定命名
- 在 UI 和理解层就容易长期别扭

## 三、为什么不用 `A / B`

因为太抽。

它确实中性，
但没有任何直觉锚点。

而 `Main/Sub` 至少还有：

- 主侧
- 副侧

这种可用的稳定语义。

## 四、命名使用规则

### 1. 触发体内部稳定命名

一律优先使用：

- `Main`
- `Sub`

适用范围：

- 槽位
- 表达来源
- 切换状态机
- 主副攻击投影内部字段
- 接口参数
- 文档中的系统结构描述

### 2. 身体部位事实命名

只有在和 RimWorld 身体部位直接对接时，
才继续使用：

- `Left`
- `Right`

适用范围：

- 缺手检查
- 身体部位损坏
- 原版 body part 桥接
- 与原版左/右部位逻辑一一对应的代码

### 3. UI 文案

UI 默认不强制写“左/右”。

优先考虑：

- 主 / 副
- 主槽 / 副槽

如果某些界面确实需要说明身体侧，
再补充：

- 主槽（右）
- 副槽（左）

## 五、这条原则的真正目的

不是为了好看。

而是为了把下面三件事拆开：

- 触发体内部槽位语义
- 角色身体左右事实
- 玩家观察视角

以后这三者各自都能清楚，
不会再互相打架。
