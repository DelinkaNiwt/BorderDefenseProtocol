# Trigger 事件驱动表达缓存（第一版）

## 目的

把 Trigger 的最小事件口真正接到表达运行时上，避免事件只停留在“有接口、没人用”的状态。

## 结论

主模组新增：

- `Source/BDP/Core/Runtime/TriggerResolvedExpressionCache.cs`

并让：

- `CompTriggerBody`
- `BdpProjectionRuntime`

通过这层形成最小正式链路：

1. Trigger 槽位装载变化
2. Trigger 激活已提交
3. Trigger 关闭已提交
4. 表达缓存失效
5. 下一次按钮 / 自动远程 / 自动近战查询时重建表达快照

## 当前边界

这层只负责：

- 监听 Trigger 已经成立的状态变化
- 让旧表达缓存失效
- 让所有入口读取同一份最新表达快照

这层不负责：

- 持有 Trigger 真值
- 直接生成按钮或攻击
- 替代 CombatBody / Trion 的 owner 职责
- 做成一个泛化的大总线

## 为什么现在先做到这里

当前第一阶段真正已经接到游戏入口的是：

- Trigger
- Expressions
- Runtime
- Projections

所以本轮优先把这条已在使用的主链补成“事件可达”的最小闭环。

`CombatBody` 虽然已经有阶段事件口，但当前还没有正式装配到主模组实际入口里，因此不能把它算作同等完成度。

## 一句话结论

当前“事件通信已落实”的真实范围是：

- Trigger 变化可以正式驱动表达快照刷新

而不是：

- 整个 BDP 已经完成通用事件总线
