# ADR-0001 二次重构起步原则

## 状态

已接受

## 决策

二次重构从旧 BDP 出发，不从一次重构的新项目出发。

起步阶段先做以下事情：

- 建立新的模组项目骨架
- 固定最小文档记录机制
- 固定中文文件与终端工作规则
- 研究旧 BDP 的领域边界
- 研究 RimWorld 原版引擎通道

在完成这些前，不开始正式业务重构。

## 原因

- 一次重构的主要问题不是“代码不够多”，而是方向偏了
- 当时更像是在做一个悬浮于 RimWorld 之上的系统，而不是做 RimWorld 模组
- 旧 BDP 虽然耦合重，但外部表现已经接近目标
- 因此二次重构必须保留旧版行为基准，只重做内部结构

## 当前明确拒绝的做法

- 不沿用一次重构的总体架构
- 不先搭复杂平台再追回业务
- 不把事件总线当作系统中心
- 不把表面业务名词直接当成架构边界

## 后果

- 起步速度会更慢一点
- 但能避免再次在错误方向上投入大量实现成本
- 后续每一步都必须留下可追溯记录
