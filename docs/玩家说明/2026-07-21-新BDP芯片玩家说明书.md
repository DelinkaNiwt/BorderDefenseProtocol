# 新 BDP（边境防御协议）芯片玩家说明书

> 盘点日期：2026-07-21
>
> 适用范围：新主模组 `BorderDefenseProtocol`（边境防御协议）与伴生测试模组 `BorderDefenseProtocol.DevHarness`（边境防御协议·开发测试模组）。
>
> 不包含旧版模组。本文按当前工作区里的实际定义与运行代码整理。

## 一、先看结论

- 主模组目前有 **0 枚具体芯片**。它只提供装载、切换、表达、资源、组合、攻击执行等通用底座。
- 测试模组目前有 **16 个芯片定义**：其中 **15 枚是正常测试芯片**，另有 **1 枚故意写坏的非法样本**。
- 这些芯片用于证明框架能做什么，数值没有按正式游戏内容平衡，不应视为最终成品。
- “组合技”不是额外的芯片物品，而是指定两枚芯片同时生效后产生的新能力。

一句话理解当前结构：

```text
芯片物品
  ↓ 装入触发器的主手、副手或特殊槽
芯片表达
  ├─ 攻击：近战 / 远程
  ├─ 技能：主动按钮
  ├─ 状态：持续增益或减益
  └─ 被动：交给认识该被动的系统使用
        ↓
可再叠加组合技、远程模块、视觉和 Trion（触能）消耗
```

| 芯片 | 玩家向简介 | 关键特点 |

| 芯片 | 玩家向简介 | 关键特点 |
|---|---|---|
| 测试紧急脱离芯片 | 战斗体被动崩解时，把小人传送到安全位置。 | 只装特殊槽；优先传送到通电的紧急脱离信标附近；成功后会消耗掉提供该被动的芯片。 |
| 测试混合芯片 | 同一枚芯片里同时放入一个远程攻击和一个附着被动。 | 远程部分是射程 22 格的单发射击；被动部分目前没有业务系统读取，只用于证明“攻击 + 被动”能共存。 |

紧急脱离找落点的顺序：

```text
通电的紧急脱离信标附近
  ↓ 找不到
最近的殖民者建筑附近
  ↓ 找不到
小人原地附近
  ↓ 找不到
地图中心一带的安全格
```

### 2.5 旋空弧月样例芯片，共 2 枚

| 芯片 | 玩家向简介 | 关键特点 |
|---|---|---|
| 测试弧月芯片 | 本身是一枚普通近战芯片，也是旋空弧月组合的主材料。 | 单把刀刃，基础伤害 20；为组合提供弧月侧身份。 |
| 测试旋空芯片 | 单独装上时没有玩家可主动使用的招式，主要作为组合材料。 | 为旋空弧月提供副侧身份、50 点使用消耗与 50 点最低资源要求。 |

弧月与旋空同时成立后，会产生“测试旋空弧月”组合技能：

- 射程 10～40 格，预热约 1.2 秒，冷却 300 个 tick（游戏刻，约 5 秒）。
- 发出会向前推进的月牙剑气；近距离宽而扁，远距离窄而深。
- 对每个目标只伤害一次；伤害 50，护甲穿透 0.5。
- 当前配置允许误伤友军，也会伤害建筑；建筑受到 4 倍伤害。
- 天然山体会阻挡月牙剑气，人造建筑不会被当成路径阻挡。
- 消耗与最低要求都跟随旋空侧，即 50 点 Trion（触能）。

## 四、设计一枚新芯片前，需要先确定什么

不必先懂代码。只要先回答下面 9 组玩家问题，就足够把需求交给开发者。

### 4.1 身份

- 芯片叫什么？
- 一句话卖点是什么？
- 它是近战、远程、技能、状态、被动，还是混合型？
- 图标、地面贴图、质量、价值和获得方式是什么？

### 4.2 装在哪里

- 装主副手区，还是特殊槽？
- 是否一枚芯片同时占住双手？
- 与哪些芯片互斥？
- 切入和切出需要多久？

### 4.3 花多少 Trion（触能）

- 装入后占用多少容量？
- 激活时一次性消耗多少？
- 激活期间每秒消耗多少？
- 每次攻击或施放消耗多少？
- 使用前至少要保留多少？

### 4.4 实际做什么

- 近战：伤害、伤害类型、护甲穿透、几段、段间隔、使用哪把刀刃或工具。
- 远程：射程、预热、冷却、弹丸、发数、逐射还是齐射、发射点是否散布。
- 技能：选谁、选哪里、射程、冷却、效果、是否敌对。
- 状态：改变哪些属性、有几层、如何叠加、何时移除。
- 被动：触发时机、触发条件、效果、是否消耗芯片、由哪个系统接收。

### 4.5 能选什么目标

- 能否打地面、小人、建筑、自己和友军？
- 是否必须直线看见目标？
- 墙、山体、护盾和屋顶如何处理？
- 电脑控制的小人能否自动使用，还是只允许玩家手动使用？

### 4.6 命中与结束规则

- 命中后是单体伤害、爆炸、施加状态，还是继续飞行？
- 会不会穿透、反弹、分裂、追踪或绕路？
- 目标死亡、消失、进门或离开地图时怎么办？
- 是否允许友伤和建筑伤害？

### 4.7 看起来和听起来怎样

- 手持贴图、朝向、大小、偏移和绘制前后关系。
- 枪口位置、弹道、拖尾、爆炸、光效和音效。
- 普通状态与攻击状态是否使用不同贴图。
- 与另一枚芯片组合时是否更换复合外观。

### 4.8 与其他芯片怎样互动

- 能否与别的芯片同时生效？
- 两枚指定芯片是否产生组合技？
- 组合后保留原能力，还是替换、隐藏某个能力？
- 组合技的消耗跟随主芯片、副芯片、两者相加，还是写固定值？

### 4.9 怎样算完成

- 玩家在游戏里应看到什么按钮、提示和数值？
- 至少准备一个正常场景、一个资源不足场景和一个目标失效场景。
- 需要验证存档读取、自动攻击、双持、切换与组合时，再分别写清预期。

可以直接复制下面这张最小需求卡：

```text
名称：
一句话效果：
类型：近战 / 远程 / 技能 / 状态 / 被动 / 混合
槽位：主副手 / 特殊 / 双持绑定
资源：容量占用__；激活__；每秒__；每次使用__；最低要求__
目标：
核心数值：
命中或触发后的效果：
友伤、建筑、墙体规则：
外观与声音：
组合与互斥：
完成时必须通过的三个游戏场景：
```

## 五、当前框架已经足以实现哪些芯片

### 5.1 基本只写 XML（可扩展标记语言）就能完成

这里的意思是“沿用已经存在的宿主和效果”，不需要改主模组架构。

- 普通单发、连发、齐射、发射点散布的远程武器。
- 普通单段或多段近战，以及多把近战工具参与选择。
- 不同射程、预热、冷却、弹丸、伤害、护甲穿透和音效的武器。
- 双持绑定、主副手装载、特殊槽装载、切换时间和互斥关系。
- 使用原版现有效果组件的主动技能，例如烟雾、跳跃、范围效果等。
- 使用状态定义实现的移速、护甲、恢复、感知等持续增益或减益。
- 同一枚芯片同时提供攻击、技能、状态和被动中的多个条目。
- 两枚指定芯片解锁新的攻击、技能、状态或被动组合。
- 单侧与双持时使用不同武器外观，配置枪口、叠加层和绘制顺序。

### 5.2 不改主模组，但需要在测试模组增加业务代码

主模组已经给出接入位置，新的具体玩法应继续放在测试模组或未来业务模组里。

- 新的远程瞄准方式：多点选路、扇形、链式选敌、地面区域选择。
- 新的弹道：制导、曲线、绕障、穿透、反弹、分裂、返回、加速或减速。
- 新的命中效果：爆炸、范围状态、地形变化、召唤物、持续区域。
- 新的技能效果：月牙剑气、传送、护盾、召唤、范围治疗等。
- 新的被动效果：受伤触发、击杀触发、资源不足触发、崩解触发等。
- 新的视觉效果：特殊拖尾、动态贴图、自定义波体和复杂叠加层。

远程模块已经把一次攻击拆成清楚的阶段：

```text
按钮 → 选目标 → 预览 → 确认 → 瞄准 → 准备 → 发射
     → 弹丸初始化 → 飞行 → 到达 → 判定命中 → 落点效果
```

因此，大多数“改变远程攻击某一段行为”的创意，都可以作为独立模块挂上去，不必重写整套攻击系统。

### 5.3 当前已有、可直接复用或仿写的业务样例

- 路线引导：手动路径点、撤销、自动绕障、分段飞行。
- 追踪：有限转向、目标预测、追丢、重新锁定、飞离。
- 爆炸：瞄准预览、落点范围结算、压制普通单体命中。
- 教学骨架：完整展示远程攻击各阶段的标准接法。
- 烟雾技能：表达结果同步到原版技能宿主并正式扣费。
- 高速状态：表达结果同步到状态宿主、按来源数叠层并持续扣费。
- 紧急脱离：被动表达被战斗体崩解流程读取并消费来源芯片。
- 旋空弧月：组合技生成自定义月牙剑气实体并完成范围扫掠。

## 六、当前还不能只靠配置完成的内容

| 想做的事 | 当前状态 | 现在应怎样处理 |
|---|---|---|
| 芯片在多个形态间切换 | 配置结构和解释器已有，但触发器当前总是读不到实际形态。 | 暂时不要把“形态切换”当作可交付功能；需要先补正式形态运行系统。 |
| 按血量、天气、资源量等条件决定条目是否成立 | 条件入口已有，但现有条件解释器仍是占位；写入条件会被视为未知且不成立。 | 先为目标条件增加正式解释器，再写芯片条件。 |
| 仅填写一个新被动名字就自动出现效果 | 被动发布和查询已经可用，但只有认识该名字的业务系统才会执行效果。 | 新被动必须同时编写接收方；当前现成业务只有“紧急脱离”。 |
| 用“功率要求”阻止低功率触发器激活 | 数值目前只被保存和显示，没有准入检查。 | 不能依赖该字段做平衡门槛。 |
| 给普通近战按次扣除 Trion（触能） | 近战条目可以携带消耗数据，但当前近战执行链没有正式扣费闸门。 | 若玩法依赖近战按次扣费，需要先补近战扣费闭环。 |
| 任意新世界系统自动读懂芯片扩展文本 | 扩展块只是信息容器，本身不会产生行为。 | 必须有明确的读取方与执行代码。 |

持续消耗现在归实际成立的表达效果所有，使用 `SustainCostBySourceCount（按有效来源数计费）`。例如同一状态由一张芯片提供时可以每秒消耗 2 点，由两张芯片共同提供时可以改为整组每秒 5 点；效果失效便停止收费。芯片本体旧字段 `ActiveDrainPerSecond（激活期间每秒消耗）`以及更早的 `DrainPerDay / DrainPerSecond / SustainCost` 都不是当前正式字段。

## 七、判断一个创意是否适合当前框架

可以用这条简单规则：

```text
只是在“已有攻击 / 技能 / 状态”上换数值或组合
  → 通常只写定义即可

要改变远程攻击某个阶段
  → 写一个可插拔远程模块，通常不用改主模组

要增加新的技能效果或被动业务
  → 在测试模组写效果组件或被动接收方

要依赖形态切换、自定义条件、功率门槛或近战按次扣费
  → 当前存在框架缺口，应先补对应基础闭环
```

## 八、当前盘点中发现的差异

- “测试旋空弧月”的技能说明仍写着“月牙剑气业务效果后续再补”，但当前运行代码已经实现月牙剑气生成、推进、伤害和绘制。本文按实际运行代码介绍；后续应单独更新这条游戏内说明文字。
- “测试毒蛇齐射路径芯片”的说明写着带发射点散布，但当前执行块只声明了齐射，没有写散布范围。本文按实际配置介绍；若要恢复说明中的效果，应另行补配置并做游戏内验证。
- 3 个相关冒烟脚本仍只识别旧的 `ResourceBase`（原版资源基类），而当前芯片已经统一继承 `BDP_ChipBase`（BDP 芯片基类），因此会误报找不到路径、追踪和爆炸芯片；实际模块挂载与共享弹丸引用仍然存在。
