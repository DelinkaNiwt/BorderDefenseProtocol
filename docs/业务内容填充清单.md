## 5. 建筑与生产链

### 5.1 芯片制造链（核心链）
```
研究 BDP_Research_BasicTriggerEngineering
  → BDP_ChipFabricator（Building_ChipFabricator : Building_WorkTable, IBillGiver；comps: Power/Flickable）
  → 玩家在 Window_ChipManufacturing 里选「职业 + 功能模板(ChipManufacturingPresetDef) + 构型(ChipArmamentFormDef)」
       组合解析 ChipCombinationResolver / ChipCombinationCompatibilityService
       成本计算 ChipManufacturingCostCalculator（RecipeDef 基底 15 钢 + 2 工业零件，
                 再按 preset.costList 与 preset.additionalWorkAmount 动态累加）
  → 产出账单 Bill_ChipProduction : Bill_ProductionWithUft, IChipCombinationRecordHolder
       （携带 ChipCombinationRecord : IExposable，记录本次组合）
  → 工作 WorkGiverDef BDP_DoBills_ChipFabricator → 原版 JobDriver_DoBill
       中间物 BDP_Chip_Unfinished（Thing_UnfinishedChip）
       补丁保证中间物与零材料账单可用：WorkGiver_DoBill.ClosestUnfinishedThingForBill、
                                      WorkGiver_DoBill.TryFindBestIngredientsInSet_NoMixHelper
  → RecipeWorker_ChipProduction : RecipeWorker → ChipProductCreationService
  → 产物 BDP_Chip_Custom（Thing_ManufacturedChip : ThingWithComps + CompManufacturedChip）
```
一条通用配方 `BDP_Recipe_ProduceChip` 承载全部芯片（`workAmount=6000`、`workSkill=Crafting`、`workSpeedStat=GeneralLaborSpeed`、`allowMixingIngredients=false`），
具体材料与工作量由账单动态计算 —— 不是一功能一配方。

6. **网格缓存** `CombatBody\Transform\CombatBodyScanMeshCache.cs`（96 行）：预建 `Mesh[2,2,25]` 共 100 个裁切网格，启动期 `WarmUp()`。Core 有 `Core\Trigger\Visual\VisualMeshKind.cs` 但无网格缓存设施；裁切档数(24) 与「保留上段/水平翻转」是战斗体专属语义，通用化价值未确认。

### 8.4 反向观察：边界守得住的地方
- **Core 完全不含业务**：`Source\BDP\Core\` 下 25 个子域（AttackExecution 145 文件、Expressions 125、Trigger 94、Information 83、Projectiles 64、CombatBody 51…）没有 Shield / Chameleon / Grasshopper / BlackTrigger 等业务命名的目录。
- **13 个远程模块零注册代码**，纯 XML `runtimeClass` 挂载，说明阶段模块这条扩展点设计到位。
- **`ContentBootstrap` 只有 139 行**承载 453 个文件的接线，注释明确「不承载具体业务判断，避免启动代码膨胀」—— 接线成本控制得住。

## 结论：一个独立框架需要支持的内容扩展种类

从 BDP 实际填充反推，框架至少要支持这 12 类扩展点：

1. **阶段协议模块** — 攻击/瞄准/确认/发射/飞行/到达/命中/影响各阶段可插拔模块（BDP 用了 8 个阶段接口，13 个模块实现，单模块最多实现 7 个阶段）；需配套 `defaultConfig` 反射挂载、私有状态容器（`IRangedModulePrivateContext`）、维度仲裁（`ModuleStageArbitrator` / `ModuleDimensionClaim`）。
2. **提供器注册表** — 准入规则、许可解析、容量贡献、恢复门控、资源规则、切换延迟策略、固定装载工厂、效果执行器、阈值动作…（BDP 有 30+ 个注册点）。
3. **自定义 Def 类型** — 框架定义基类，业务既可 Core 定义 + Content 填充（如 `ChipFeaturePropertyDef` 41 条），也可 Content 自定义新类型（如 `ChipManufacturingPresetDef` 24 条）。
4. **DefModExtension** — 挂到原版/框架 Def 上的旁挂配置（BDP 5 个）。
5. **Comp / CompProperties** — 建筑、物品、Hediff 三条线（BDP 13 对 ThingComp + 3 对 HediffComp）。
6. **条件 / 需求抽象** — 一处定义、按钮/AI/目标确认/执行多处共读（`PawnRequirement`）。
7. **表达式与视觉预设** — 武器形态、双持变体、持握渲染（26 条 `ExpressionVisualPresetDef`）。
8. **信息展示 schema** — 功能(5)/分组(3)/属性(41) 三级 + 来源 Worker(9) + 渲染器(5)，让新功能的信息卡自动成型。
9. **Gizmo / 面板扩展** — 外部 Gizmo 提供器、Gizmo 内嵌面板提供器（BDP 4+2 个）。
10. **生产链扩展** — 自定义 `Bill` / `RecipeWorker` / 动态成本 / 中间物 / 容器 Comp / WorkGiver + JobDriver 全套。
11. **世界与叙事扩展** — 自定义出场模式（`PawnsArrivalModeWorker`）、落点竞标钩子、可存档事件控制物、QuestNode/QuestPart/LordJob、GameComponent 级世界状态 + 快照模型 + 决策窗口 + Letter/Alert。
12. **战斗日志与表现** — `IBattleLogEntryFactory` + RulePack 语法、Fleck/Mote/Effecter/SubEffecter、地图级视觉组件、路径预览的 Immediate/Deferred 双模式。

此外框架还需提供（BDP 现在缺或放错位置的）：泛型提供器注册表、稳定随机、人物视觉快照捕获、Def 校验器调用约定、存档迁移脚手架。
