# 批量充能能力框架接入说明

日期：2026-10-15。适用：RimWorld（边缘世界）1.6、1.7，共享源码、独立构建。

后续进展：开发目录已接入“护城盾”真实验证芯片，参数与进入方式见[护城盾验证步骤](Testing/2026-10-15-护城盾验证步骤.md)。下文保留框架自身的职责和异常边界。

本轮提供可配置的能力框架，没有添加具体芯片、墙体、配方或平衡数值。次数和恢复由原版 Ability（能力）持有；框架补齐来源开关、直线选格、整批预算与批量效果之间的连接。

## 1. 玩家层面的规则

```text
启用来源 → 能力按钮 → 原版直线拖拽 → 预览目标数与总费用
                                      ↓ 松开确认
                              原版施放作业保存目标列表
                                      ↓ 实际施放
                  再查来源、位置、次数、触力能 → 一次支付
                                      ↓
                            扣 N 次 → 效果处理 N 格

角色原版能力对象：剩余次数 + 下一次恢复计时 + 原版存档
       ↑ 始终保留；关闭来源只隐藏／禁用入口
       └ 每轮补回一次，未满则开始下一轮
```

- 一个去重后的目标格对应一次充能与一份使用成本。有剩余次数时，恢复中的能力仍可使用。
- 再次使用不重开已有恢复进度。关闭、换装、重新启用都不创建新的次数池；同角色同能力定义共用一池。首次获得能力按原版填满初始次数。
- 拖拽期间不收费、不生成。超额、范围外、不可见或任何不合法格使整批拒绝，不偷偷缩短或挖掉中间一格。
- 同一能力只保留一份在途作业。当前没有多批排队、资源预占或人工智能自动选格。
- 前摇中资源或位置改变，实际施放前重新验证；取消或校验拒绝不扣费。
- 恰好支付最后一份可用触力能时，本次已通过验证的效果仍完成，随后承受既有战斗体崩解。目标与地图在支付前冻结，防止崩解同步结束作业时吞掉效果。
- 恢复服从原版游戏时间和角色能力更新，不是现实时间的离线计时器。离图、世界角色及读档恢复表现仍需按下文实测。

## 2. 接口与职责

| 位置 | 接口或类型 | 职责 |
|---|---|---|
| Core（核心） | `BdpBatchAbility`（批量能力） | 读原版作业目标、整批验证、排作业、一次激活扣 N 次 |
| Core | `BdpVerb_CastBatchAbility`（批量施放动作） | 最后复查后提交总费用，进入既有能力动作链 |
| Core | `Command_BdpBatchAbility`（批量能力按钮） | 进入绑定当前角色的划选工具 |
| Core | `Designator_BdpBatchAbility`（批量划选工具） | 复用原版直线与长度标注，预览／确认读取完整原始候选 |
| Core | `CompAbilityEffect_BdpExpressionLifecycle`（表达来源生命周期） | 来源无效时隐藏并禁止使用，保留原版能力对象 |
| Core | `BdpAbilityTrionCostCommitter`（触力能成本提交器） | 从既有表达成本组件汇总 N 份费用并支付一次 |
| Content（正式内容） | `CompAbilityEffect_BatchBuildingSpawn`（批量建筑生成效果） | 按配置在每个目标格生成一个一格建筑 |

`BdpBatchAbility` 的公开入口：

| 入口 | 调用方式／含义 |
|---|---|
| `TryValidateBatch(cells, out targets, out reason)`（验证整批） | 只读检查；返回去重候选与拒绝原因，不收费 |
| `QueueBatch(cells)`（提交批次） | 再验证后写入原版作业；程序调用也走这条入口 |
| `CurrentBatchTargets`（当前批次目标） | 效果读取的只读列表；平时来自当前作业，支付过程中来自临时冻结上下文 |
| `CurrentBatchMap`（当前批次地图） | 与上述目标一起使用，不能在支付后重新依赖当前作业 |

费用查询／提交共用表达结果中的 `Trion.UseCost`（触力能使用成本），批量时解释为每格单价。`MinimumRequired`（最低要求）只作为一次资格门槛，不按格重复收费：

```text
总费用 = 所有成本组件的每格费用之和 × 目标数
所需可用量 = max（总费用，所有最低门槛中的最大值）
正式支付 = 总费用
```

`TryGetTotalCost`（查询总价）和 `CanAfford`（检查预算）不修改资源；`TryCommit(ability, count)`（按数量提交）只调用一次正式资源支付。原有无数量参数入口保持既有行为，未切换为批量能力的芯片不会改为按格扣费。

## 3. 后续能力如何接入

能力定义需选用下列类型；这是字段清单，没有加入任何可加载的示例芯片。

| 字段／组件 | 接入要求 |
|---|---|
| `abilityClass`（能力类型） | `BDP.Core.Abilities.BdpBatchAbility` |
| `gizmoClass`（按钮类型） | `BDP.Core.Abilities.Command_BdpBatchAbility` |
| `verbProperties.verbClass`（动作类型） | `BDP.Core.Abilities.BdpVerb_CastBatchAbility` |
| `charges`（次数上限） | 具体能力自行配置正整数 |
| `cooldownPerCharge`（逐次恢复） | 有限次数能力必须为 `true`（开启） |
| `cooldownTicksRange`（恢复游戏刻范围） | 最小值必须大于零；固定恢复时间则两端相同，60 游戏刻为一游戏秒 |
| `burstShotCount`（每轮动作发数） | 必须为 1；一批只激活一次 |
| `jobDef`（作业定义） | 留空使用原版 `CastAbilityOnThing`（对地图目标施放能力），或显式指定该定义 |
| `CompProperties_AbilityEffect_BdpExpressionLifecycle`（来源生命周期参数） | `retainWhenInactive=true`（关闭仍保留）；未挂此组件的既有能力不改变回收规则 |
| `CompProperties_AbilityEffect_BdpTrionCost`（触力能成本参数） | 继续从正式表达结果读取单价／门槛，不把成本再写一份到能力定义 |
| `targetParams`（目标参数）与射程 | 配置为地图格目标；每格均检查原版射程、可见性及效果规则 |

当前批量入口拒绝世界目标、非打断式自施放、等待作业结束再冷却、共享组冷却、其它作业类型，以及会把一个目标扩展为多个目标的原版范围效果。它们会改变次数或时序，不能仅换一个能力类型就假定可用。也不要附加现有“来源级释放冷却账本”组件：本框架使用原版能力自己的逐次恢复，不再保存第二套计时。

所有效果组件由原版激活一次。需要逐格执行的效果应主动读取 `CurrentBatchTargets` 和 `CurrentBatchMap`；普通单点效果组件只会收到代表格，不会自动执行 N 次。具体效果的其它资源成本同样不会自动变成 N 倍。

若配置原版确认对话，划选确认会先显示对话，接受后才排作业；`QueueBatch` 是程序提交入口，调用方自行安排需要的确认交互。

## 4. 建筑效果扩展点

在能力组件中选用 `BDP.Content.Abilities.CompProperties_AbilityEffect_BatchBuildingSpawn`（批量建筑生成参数），提供 `buildingDef`（生成建筑定义）；需要材料类型的建筑还要提供兼容的 `stuffDef`（材料定义），不需要材料的建筑必须留空。当前不会消耗普通施工材料。

接受一格建筑，整批落点直接使用原版 `GenConstruct.CanPlaceBlueprintAt`（建造蓝图合法判定），不额外要求空格或可站立。草、岩屑、地面物品等是否允许由原版决定；能力本身仍保留射程、视线、可见性、次数与资源约束。

即时生成采用原版建筑框架完工相同的 `WipeMode.FullRefund`（旧物清理及返还模式）：由原版处理植物、污渍、物品移位和可替换物，不另写一套清场算法，也不启用开发者无视建造限制的模式。

正常施工已把蓝图转成框架，但即时生成没有这一步，因此生成前只取消原版 `CanReplace`（替换判定）允许被本次建筑替代的建筑蓝图，避免实体墙与旧施工请求重叠；其它蓝图不一概清除。

建筑自身寿命、耐久、受伤、回收等继续由建筑定义及其组件负责。专用墙体若要采用其它落点规则，可继承生成效果并重写 `Valid`（落点验证）；配置类型检查可通过 `ConfigurationValid`（配置有效性）扩展。正常施放前仍须让完整候选列表经过同一套规则。

异常边界：若创建或生成代码抛出异常，组件删除本批已创建对象，再将异常交给原版日志；**已经支付的触力能、次数和恢复计时不会自动退回**。本轮没有通用地图事务、资源退款或所有效果回滚协议。“整批拒绝不收费”仅指支付前的正常校验失败，不包含配置错误或第三方组件抛错。

## 5. 存档与原版机制

次数、上限、恢复结束时间由原版能力保存；确认后的目标列表使用原版 `Job.targetQueueA`（作业目标队列）保存，作业同时保存能力和动作引用。新增的支付上下文只存在于一次同步调用中，不增加存档字段。

能力提供 `BdpBatchAbility(Pawn)`（读档传入角色）和 `BdpBatchAbility(Pawn, AbilityDef)`（工厂传入角色及定义）两条原版构造入口；不能只提供无参构造，否则角色能力列表的深存档无法恢复此类型。

表达同步器只对显式保留的能力跳过移除。来源重新成立时复用角色已有对象，来源未成立时生命周期组件守住隐藏、可施放、目标验证和人工智能入口。直接调用单点激活或世界激活不能绕过批量动作的支付前验证。

没有具体芯片接入，因此游戏内验收仍待后续执行，两个版本各自完成：

1. 首次满次数；生成 N 格后扣 N 次、N 份费用，旧充能进度不重置。
2. 关闭芯片后等待多个恢复周期；重新启用、换装或同定义换来源均不刷满。
3. 超额、无资源、直线中一格有障碍、取消、角色倒地或前摇中关闭来源均不收费。
4. 前摇中另一格变为原版不允许建造时整批拒绝；原版允许的物品／人物出现不再一概拒绝。同能力重复排队被拒绝。
5. 费用恰好耗尽可用触力能时仍生成整批并扣正确次数，随后崩解，无丢目标或重复施放。
6. 充能中读档、已确认作业读档、切地图、离图后返回；核对恢复、目标地图和角色引用。
7. 对话取消不收费；重新打开划选工具不显示上次拖拽的目标数；没有非法格被悄悄过滤。
8. 错误建筑配置能拒绝；主动制造生成异常时确认日志与本批对象清理，按上述边界不宣称退款。

下一步主线是用 Development（开发辅助）接入一份可移除的测试配置，完成上述双版本实测；正式芯片与墙体机制另行设计后再接入。
