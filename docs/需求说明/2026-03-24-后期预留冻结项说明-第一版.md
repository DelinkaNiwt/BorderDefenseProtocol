# 后期预留冻结项说明（第一版）

## 目的

这份说明不是为了现在就定义后期所有功能怎么实现。

这份说明要冻结的是：

- 后期无论接入什么功能，都必须共用的协议骨架
- 后期无论实现什么系统，都不能突破的边界约束

因此本文只冻结：

- 扩展口类别
- 正式结果对象类别
- 合并与裁定规则
- 存读档分类法
- 外部读取层级
- 原版通道优先与 patch 严格准入约束

本文不冻结：

- 后期具体功能清单
- 具体 UI 形态
- 具体数值
- 具体视觉细节
- 具体类拆分方式

## 一、总原则

### 1. 现在冻结的是协议骨架，不是后期细节

后期可以继续扩展：

- 新表达
- 新远程能力
- 新显示层
- 新兼容层
- 新外围系统

但这些扩展都只能长在当前先冻结好的骨架上。

### 2. 不允许以后再临时发明一类新入口

如果某个后期功能接不进去，
正确动作应是：

- 检查它是否误判了自己属于哪一类正式口
- 检查现有正式骨架是否真的缺一层通用能力

而不是：

- 为这个功能单独再发明一条私入口

### 3. 不允许以后用后期功能反向塑形前面主链

后期外围系统、兼容系统、显示系统、参数系统，
都不能反向决定：

- 表达怎么成立
- 执行链怎么裁定
- owner 真值怎么划分

## 二、扩展口冻结

未来任何功能接入时，必须先判定自己属于以下四类正式口之一。

## 1. 执行链扩展口

适用对象：

- 会影响攻击执行结果的参与者

正式定位：

- 挂在执行链内部阶段
- 读取正式输入
- 提交执行意图
- 由宿主统一合并

不能做：

- 直接写宿主最终结果
- 跳过阶段合并器
- 冒充读取层扩展

## 2. 读取链扩展口

适用对象：

- 信息、兼容、视觉等读取方

正式定位：

- 只消费正式结果
- 生成对外读取面

不能做：

- 回写执行链
- 重开执行裁定
- 倒流进表达成立与主攻击选择

## 3. 调制通道

适用对象：

- 各类参数调整方

正式定位：

- 挂在执行链各阶段的正式调制口
- 对公开参数面提交调制意图

不能做：

- 成为独立攻击链
- 反向决定表达是否成立
- 绕过宿主合并器

## 4. 恢复通道

适用对象：

- 存读档、重建、续接相关流程

正式定位：

- 声明对象属于哪类恢复分类
- 声明谁负责恢复真值、重算结果、清空缓存、续接过程

不能做：

- 成为自由拼装的“恢复钩子市场”
- 让外部功能私自定义恢复协议

## 5. 事件不升格为正式并列扩展口

事件只允许作为：

- 上述正式口的附属通知机制

事件不允许作为：

- 第五类独立扩展口

原因是：

- 事件只通知
- 事件不持有真值
- 事件不应承载正式业务接入责任

## 三、正式结果对象冻结

现在冻结的是“结果对象种类”，不是每类对象的完整字段清单。

长期正式结果对象固定为以下八类：

1. 表达结果
2. 执行请求
3. 发射计划
4. 投送宿主初始化结果
5. 在途结果
6. 接触结果
7. 落地结果
8. 读取结果

其中读取结果长期正式分为：

- 信息读取结果
- 视觉读取结果

## 1. 表达投影不升格为第九类并列结果对象

以下内容长期承认为：

- 表达结果的正式投影读取面

而不是：

- 与执行请求、发射计划、落地结果同级的独立第九类结果对象

包括：

- 主攻击投影
- 手动入口投影
- 默认兼容表面

## 2. 冻结的是字段分类，不是字段细表

每类结果对象现在只冻结：

- 它属于什么种类
- 它允许承载什么字段分类

现在不冻结：

- 完整字段枚举
- 具体字段命名实现细节

## 四、合并与裁定规则冻结

## 1. 合并必须字段级

长期不允许使用：

- 功能级整块覆盖

只能使用：

- 字段级合并

## 2. 标准合并语义固定为最小集合

长期正式语义保留：

- `Accumulate`
- `Override`
- `Clamp`
- `Deny`
- `Tag`

其中 `Tag` 不能被删掉，
因为未来会存在：

- 不直接改数值
- 只附带解释或后续阶段提示

的参与者。

## 3. 优先级来源必须正式化

优先级只允许来自：

- 表达宿主
- Def 配置
- 显式协议字段

不允许来自：

- 注册顺序
- 文件加载顺序
- 某个功能碰巧先执行

## 4. 否决规则必须单向安全收敛

正式 `Deny` 一旦成立，
低优先级参与者不能再偷偷把它放开。

## 5. 读取链不参与执行链裁定

信息读取、视觉读取、兼容读取，
都不能回到执行链里重新提交裁定意图。

## 五、存读档分类冻结

未来任何新对象接入前，都必须先归入以下四类之一：

1. 必须持久化
2. 必须重算
3. 必须清空
4. 允许续接

## 1. 必须持久化

适用于：

- owner 真值
- 正式容器关系
- 不可直接从当前世界反推、但恢复闭环必需的正式恢复数据

## 2. 必须重算

适用于：

- 表达结果
- 投影结果
- 链后读取结果
- 调制合并结果

这里明确冻结：

- 调制合并结果只能重算
- 不能作为持久化真值

恢复时保存的是：

- 调制参与者自身正式状态

不是：

- 上次已经合并完成的攻击参数快照

## 3. 必须清空

适用于：

- 临时缓存
- 临时按钮与命令对象
- 临时事件订阅关系
- 只服务于当前一次动作的现场上下文

## 4. 允许续接

适用于：

- 正式在途宿主
- 冷却、崩解、在途等时间过程
- 局部表现过程

## 5. 不允许跨类混用

同一对象不能：

- 一部分当真值持久化
- 一部分又当缓存复活

也不能：

- 今天归“必须重算”
- 明天又偷偷拿它做恢复基础

## 六、外部读取层级冻结

长期正式只保留两种外部读取级别：

1. 默认兼容表面
2. 完整正式读取接口

不保留：

- 半公开中间接口

## 1. 默认兼容表面

适用对象：

- 只认“当前主武器/主攻击表面”的原版与普通外部系统

正式要求：

- 稳定
- 单一
- 可回退

但它不代表：

- 完整真实状态

## 2. 完整正式读取接口

适用对象：

- 愿意按 BDP 协议深度接入的外部系统

正式要求：

- 读取完整正式结果
- 不反向绑架内部协议

## 3. 内部分层继续保留两面

虽然外部只保留两级读取，
但系统内部长期仍要承认：

- 信息读取面
- 视觉读取面

两者都属于：

- 读取链正式结果

## 4. 不允许因外部需求再开半正式私接口

如果某个外部系统想读更多，
它只有两种正式选择：

- 接受默认兼容表面
- 接入完整正式读取接口

不能因为某个外部系统想多拿一点信息，
就为它加一个半公开私接口。

## 七、原版通道优先与 patch 严格准入冻结

## 1. 原版优先应写成“原版自然通道家族优先”

后续实现时，不应只盯几个代表类名。

应先检查 RimWorld 原版自然通道家族是否能承接。

至少包括：

- 攻击与执行家族：
  `Verb / VerbTracker / Stance / JobDriver / Toil`
- 能力与状态家族：
  `Ability / Hediff / HediffComp / Gene / Need`
- 投送与落地家族：
  `Projectile / Explosion / Damage / BattleLog / ThingComp`
- 交互与展示家族：
  `Gizmo / Command / InspectString / FloatMenu`
- 容器与持有家族：
  `ThingOwner / ApparelTracker / EquipmentTracker / Inventory`

核心不是背类名表，
而是先证明：

- 有没有原版自然宿主族能承接

只有证明没有，
才允许进入 patch 评估。

## 2. patch 必须满足最严格前置条件

只有同时满足以下条件，才允许评估 patch：

- 已确认不存在可接受的原版自然通道
- patch 目标点稳定且必要
- patch 只负责导流或接线
- patch 不持有真值
- patch 不承载复杂裁定
- patch 不把显示层、兼容层、测试层偷偷接进执行链
- patch 侵入面最小化
- patch 兼容性风险已被显式记录
- patch 移除后主业务仍有清晰正式宿主

若存在多个 patch 候选点，
必须选择：

- 侵入性最低
- 兼容风险最低

的一处。

## 3. 出现以下任一情况，应直接否决 patch

- patch 需要持久持有业务状态
- patch 需要跨多个系统拼接复杂流程
- patch 需要依赖执行顺序巧合
- patch 会把未来扩展逼到同一个侵入口竞争
- patch 会让恢复逻辑、调制逻辑、读取逻辑混层

## 八、测试隔离与稳定标识冻结

## 1. 测试隔离冻结

测试内容必须：

- 通过正式扩展口进入
- 删除测试模组后主模组零残留

不允许：

- 测试逻辑混进主模组核心按钮链
- 测试逻辑混进主业务链
- 测试逻辑混进正式 Def

## 2. 稳定标识冻结

后续正式结果对象、正式接口、扩展声明、恢复分类，
都必须拥有：

- 稳定命名
- 稳定键位
- 稳定分类名

这条必须现在就冻结，
因为后面会涉及：

- Def 扩展
- 存档字段扩展
- 外部接入

不能等后期实现已经铺开后，
再回头补“稳定标识”。

## 3. 命名与边界一致性继续冻结

长期继续保留：

- `Main/Sub` 作为内部稳定命名
- `Left/Right` 只在直接贴身体部位时使用

同时继续要求：

- owner、结果、投影、读取、调制、恢复这些词不混用

## 九、对后续路线的直接要求

从路线 B 开始，
任何新工作进入实现前都必须先证明：

1. 它属于哪类正式扩展口
2. 它依附哪类正式结果对象
3. 它使用哪类正式合并语义
4. 它属于哪类存读档分类
5. 它对外暴露哪一级读取面
6. 它是否已经穷尽原版自然通道家族
7. 如果评估 patch，是否满足严格准入条件

只要以上任一条答不上来，
就说明它还不具备进入实现的条件。

## 十、一句话总括

后期预留真正需要现在冻结的，不是“未来所有功能的细节设计”，而是“未来所有功能都只能共用的协议骨架与边界约束”：四类正式扩展口、八类正式结果对象、字段级合并与正式裁定、四分法恢复分类、两级外部读取层、原版自然通道家族优先与 patch 严格准入、测试隔离与稳定标识；从现在开始，任何后期功能都只能在这套冻结骨架内扩展。
