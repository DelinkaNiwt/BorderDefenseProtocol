# 视觉渲染与信息兼容读取模型说明（第一版）

## 目的

这份说明不再讨论“旧 BDP 具体画了什么”“现在信息面板具体列了什么”，而是专门定义：

- 不同读取者各自允许读取哪一层正式结果
- 哪些读取者只能拿场景默认主攻击决策
- 哪些读取者可以拿完整多表达结构
- 视觉层与信息层分别读取什么，而不是各自反推业务
- patch / 定点桥接在读取模型里处于什么地位

也就是说，这份文档的本体不是：

- 视觉功能清单
- 兼容对象清单

而是：

- 读取模型
- 读取权限
- 读取粒度
- 回退规则
- 正式接口层次

## 一、先下总结论

### 1. 视觉层和信息层都不是 owner，只是读取者

这两层都不应持有：

- 真实多表达真值
- 主攻击投影真值

它们只能：

- 读取正式结果
- 投影给各自宿主

### 2. 真正需要统一的是“读取模型”，不是“显示内容长相”

系统后续是否稳定，不取决于：

- 现在 UI 多漂亮
- 现在图画得多复杂

更取决于：

- 视觉层到底读哪份正式结果
- 原版信息卡到底读哪份正式结果
- 外部模组默认只能读哪份结果
- 愿意接入 BDP 的扩展怎样读完整结果

### 3. 场景默认主攻击决策只是低粒度回退口

它的重要性很高，但它仍然只是：

- 单表面读取者的正式回退口

它不是：

- 内部真实状态
- 视觉默认读取口
- 多表达明细口

### 4. 视觉层默认应忠于“真实执行与真实状态”，不是忠于“兼容回退口”

视觉层的首要职责是：

- 在游戏里正确反映真实多表达状态与执行状态

而不是：

- 迎合外部系统只能读一个表面的限制

### 5. patch 不是读取模型本体，只是无自然扩展口时的桥接器

patch 可以把正式读取结果送到某些对象能看懂的位置，
但 patch 不应：

- 自己推导业务
- 自己定义读取规则

## 二、适用范围与行为真标准

### 1. 行为真标准

这份文档的行为真标准有两层：

第一层：

- 当前需求文档已经明确的多层投影边界

第二层：

- 旧 BDP 已证明“复杂视觉表现是真需求”，以及旧 BDP 中 inspect / tooltip / stat / weapon draw / patch 等读取点存在的代码事实

但旧 BDP 在这里的作用是：

- 证明读取点和视觉点确实存在

不是：

- 规定读取模型必须照着旧 patch 形状长

### 2. 适用范围

本文适用于：

- 视觉读取层
- 场景默认主攻击决策层
- 多表达信息明细层
- 外部正式读取接口层
- 定点桥接层

本文不单独定义：

- 真实多表达如何成立
- 战斗体闭环
- 远程链内部协议

## 三、名词释义与辨析

### 1. 真实状态

“真实状态”指的是：

- 当前正式成立的多表达结构及其关系

它是所有读取模型的上游，但不是所有读取者都能直接读完整真实状态。

### 2. 视觉读取结果

“视觉读取结果”指的是：

- 视觉层用于决定“当前该画什么、跟谁、何时切”的正式读取面

### 3. 场景默认主攻击决策

“场景默认主攻击决策”指的是：

- 当外部读取者只能理解一个主要武器 / 攻击表面时，系统提供给它的正式回退结果

### 4. 多表达信息明细

“多表达信息明细”指的是：

- BDP 自己对完整多表达结构的说明面

### 5. 外部正式读取接口

“外部正式读取接口”指的是：

- 愿意显式接入 BDP 的扩展内容，用来读取完整或更高粒度结果的正式入口

### 6. 定点桥接

“定点桥接”指的是：

- 某些对象没有自然扩展口时，把正式读取结果桥接到它们能理解的位置

它不是：

- 自己重新推一套内部状态

## 四、读取模型总原则

## 1. 读取者不能越权读取比自己职责更高粒度的结果

不是所有读取者都应直接读取：

- 全量真实多表达结构

必须分层给不同读取者不同粒度的结果。

## 2. 读取模型必须先定义“正式结果层”，再定义“读取者”

不能反过来按读取者需要去拼系统。

正确顺序应是：

1. 先有真实状态层
2. 再有不同粒度的正式投影结果
3. 最后各读取者按允许粒度读取

## 3. 任何读取者都不应自己从零散内部状态反推业务

视觉层不能自己猜：

- 当前武器是谁

信息层也不能自己猜：

- 当前主表面是谁

它们都必须读取正式结果。

## 4. 低粒度读取者必须有稳定回退口

对于无法理解完整多表达的对象，系统必须给它：

- 稳定
- 可预测
- 长期不乱变

的低粒度读取口。

## 五、正式结果层次

这份读取模型建议长期固定以下正式结果层次：

1. 真实多表达状态层
2. 当前执行表达层
3. 视觉读取结果层
4. 场景默认主攻击决策层
5. 多表达信息明细层
6. 外部正式读取接口层
7. 定点桥接结果层

这些层次不是读取者本身，而是：

- 读取者允许读取的正式结果层

## 六、各层的读取模型

## 1. 真实多表达状态层

### 作用

- 作为所有下游读取模型的最高粒度上游

### 允许包含什么

- 当前全部正式成立表达
- 它们的关系
- 当前主 / 副 / 执行语义

### 哪些读取者不应直接读取它

- 原版单表面信息对象
- 普通未接入 BDP 的第三方对象

## 2. 当前执行表达层

### 作用

- 回答“当前正在执行谁”

### 它与主兼容表面的区别

当前执行表达可能是：

- 某个单侧表达
- 某个双武器表达
- 某个组合第三表达

它不等于：

- 当前场景默认主攻击决策

### 谁应读取它

- 视觉执行跟随
- 枪口 / 发射点跟随
- 某些战斗日志或即时显示

## 3. 视觉读取结果层

### 作用

- 回答视觉层“当前该画什么、跟谁、何时切”

### 这层至少应允许表达什么

- 当前常驻可见对象集合
- 当前执行跟随对象
- 当前双武器 / 组合视觉关系
- 枪口或发射基准跟随对象

### 视觉层为什么不能直接读真实状态层

因为视觉层最终需要的是：

- 已经整理好的视觉读取结果

而不是自己把真实状态再翻译一遍。

## 4. 场景默认主攻击决策层

### 作用

- 服务低粒度、单表面读取者

### 这层至少应保证什么

- 稳定
- 默认唯一
- 可预测
- 不要求读取者理解完整多表达

### 这层绝不能被误当成什么

- 内部系统真相
- 视觉层默认对象
- 多表达信息明细

## 5. 多表达信息明细层

### 作用

- 让 BDP 自己承担完整说明责任

### 这层至少应允许表达什么

- 当前全部表达
- 各表达层级关系
- 当前场景默认主攻击决策是谁
- 当前执行表达是谁

### 谁应读取它

- `Inspect`
- `Tooltip`
- BDP 自己的状态说明面板

## 6. 外部正式读取接口层

### 作用

- 给愿意显式接入 BDP 的扩展提供更高粒度读取能力

### 它至少应允许读取什么

- 真实多表达集合
- 场景默认主攻击决策
- 当前手动入口集合
- 当前执行语义

### 为什么要单独立这一层

因为：

- 默认兼容口要照顾低粒度对象
- 正式接口层要服务高价值接入对象

这两者不能混成一个读取口。

## 7. 定点桥接结果层

### 作用

- 给没有自然扩展口但必须兼容的对象提供最后桥接结果

### 它应当如何产生

- 从上面已有正式结果层读取
- 再写入目标对象能理解的位置

### 它不应做什么

- 自己定义主兼容表面
- 自己推一套视觉逻辑

## 七、读取者分类规则

为避免各层乱读，读取者应至少分成以下几类：

## 1. 视觉读取者

例如：

- 武器绘制
- 执行表现
- 枪口跟随

它们默认应读取：

- 视觉读取结果层
- 必要时读取当前执行表达层

## 2. 低粒度信息读取者

例如：

- 原版单表面信息对象
- 只认一个主要武器表面的第三方对象

它们默认应读取：

- 场景默认主攻击决策层

## 3. BDP 自有说明读取者

例如：

- Inspect
- Tooltip
- 状态说明窗口

它们默认应读取：

- 多表达信息明细层

## 4. 高粒度外部扩展读取者

例如：

- 愿意明确适配 BDP 的模组

它们默认应读取：

- 外部正式读取接口层

## 5. 无扩展口但必须兼容的读取者

它们不能直接读正式接口时，才允许通过：

- 定点桥接结果层

## 八、回退规则

## 1. 回退必须分层发生

回退只能沿着正式层次往下走：

- 真实状态层
- 视觉 / 信息正式投影层
- 场景默认主攻击决策层
- 定点桥接层

不能跳过正式投影层，直接回到：

- 偷读内部缓存

## 2. 低粒度读取者回退到场景默认主攻击决策

这是最重要的标准回退路径。

## 3. patch 回退是最后退路

只有当目标对象：

- 没有自然扩展口
- 又确实值得兼容

时，才进入 patch / 定点桥接。

## 九、读取一致性规则

## 1. 视觉一致性

视觉层必须保证：

- 当前执行结果与跟随对象一致
- 形态切换后读取同步更新
- 双武器 / 组合结果不会和执行状态打架

## 2. 信息一致性

信息层必须保证：

- 场景默认主攻击决策稳定
- 多表达明细不丢层级
- 外部正式接口和 BDP 自己说明面不会互相矛盾

## 3. 回退一致性

低粒度对象看不全可以，但不能：

- 看见错误结果
- 看见和正式主兼容表面冲突的结果

## 十、patch / 定点桥接边界

## 1. patch 只负责接线

patch 的正式职责只能是：

- 把已经算好的正式读取结果写进目标对象可读位置

## 2. patch 不负责推导业务

patch 不应自己回答：

- 当前真实多表达是什么
- 当前主兼容表面该是谁
- 当前视觉默认该跟谁

## 3. 是否值得桥接必须有价值判断

不是所有对象都值得补桥接。

只有：

- 高价值
- 常见
- 没有自然扩展口

的对象才值得做少量定点桥接。

## 十一、第一阶段必须落地与只留口

## 1. 第一阶段必须正式落地

当前阶段至少必须落地：

- 场景默认主攻击决策最小读取口
- 手动按钮层与自动读取层分层
- 视觉读取接口预留
- 多表达信息明细接口预留

## 2. 当前阶段只留口但必须明确

当前阶段可以不完整实现，但必须明确预留：

- 完整视觉读取结果对象
- 完整多表达信息明细模型
- 外部正式读取接口
- 定点桥接策略标准

## 十二、对后续实现的直接要求

### 1. 不能让视觉层自己猜业务

视觉层只能读取：

- 正式视觉读取结果

### 2. 不能让外部信息层自己拼业务

信息层只能读取：

- 场景默认主攻击决策
- 或正式接口层

### 3. 不能把场景默认主攻击决策误当系统真相

它只是：

- 低粒度读取者的正式回退口

### 4. 不能让 patch 变成主兼容策略

patch 只能是：

- 最后桥接器

不能反过来定义读取模型本体。

## 十三、一句话总括

视觉渲染与信息兼容读取模型真正要定义的，不是“现在旧 BDP 画了什么、显示了什么”，而是“在真实多表达状态之上，分层产出视觉读取结果、场景默认主攻击决策、多表达信息明细和外部正式接口，让不同读取者只读取自己允许读取的正式粒度，并把 patch 严格收缩到最后桥接层”的正式读取标准。
