# 远程攻击链正式输入输出说明（第一版）

## 目的

这份说明不再试图枚举旧 BDP 已有远程功能，更不以旧功能名清单来塑造协议。

它要回答的是更根本的问题：

- 在**不知道未来具体会出现哪些远程功能**的前提下，怎样定义一套统一协议
- 让任何远程功能都只能通过正式扩展口接入，而不是各自偷偷改链
- 让不同功能可以共存、叠加、裁定冲突，而不互相认识、不互相硬编码
- 让整条链始终回到 RimWorld 正式宿主，而不是自成一套脱离 RimWorld 的规则世界

因此这份文档的重心不是：

- 已知模块案例
- 已知弹种案例
- 已知功能表现顺序

而是：

- 链路标准
- 阶段协议
- 输入输出契约
- 合并规则
- 扩展挂点
- owner 边界

## 一、先下总结论

### 1. 远程攻击链的本体是一套“阶段协议”，不是一串已知功能

远程链真正需要被正式化的，不是：

- 现在有哪些玩法
- 现在有哪些模块名字
- 现在有哪些弹种

真正要被正式化的是：

- 每一段协议接受什么输入
- 每一段协议允许产出什么输出
- 每一段协议允许怎样改写结果
- 结果如何合并
- 冲突如何裁定
- 下一段只能读什么正式结果

### 2. 模块不是“功能实现单元”，而是“协议参与者”

模块在这条链里的正式地位，不应理解成：

- 一个模块 = 一个完整玩法

更准确地说：

- 一个模块 = 在某个协议阶段对某类结果提出变更意图的参与者

### 3. 扩展性来自“未知能力也只能走同一协议”

这份协议要做到的不是：

- 先把已知远程能力都列出来

而是：

- 即使未来出现今天完全没想到的新能力，它仍然只能通过现有阶段协议表达自己

这样系统才会天然支持未知扩展，而不是靠后补特判。

### 4. 真正统一的是“标准字段与合并语义”，不是“统一功能形状”

统一协议不等于：

- 所有远程功能最后都长得一样

真正统一的是：

- 它们都通过同一套标准字段表达意图
- 它们都通过同一套合并语义进入宿主结果
- 它们都遵守同一套冲突裁定规则

## 二、适用范围与行为真标准

### 1. 行为真标准

这份文档的行为真标准有两层：

第一层：

- 旧 BDP 已经证明远程链必须分段，且局部已经存在意图合并模式

第二层：

- 当前二次重构要求的是“统一标准与协议”，不是“复刻旧业务形状”

因此旧 BDP 在这里的作用是：

- 证明“按协议分段”是必要的

而不是：

- 规定协议里必须直接出现哪些具体玩法名

### 2. 适用范围

本文适用于：

- 远程表达进入正式远程链之后
- 命中与落地正式结束之前
- 以及链后信息 / 视觉投影读取正式结果时

它不直接定义：

- 多表达如何成立
- 战斗体闭环
- FireMode 参数细节
- GUI 表现细节

## 三、名词释义与辨析

### 1. 协议阶段

“协议阶段”指的是：

- 远程链中一个有独立输入、独立输出、独立可改写边界的正式阶段

它不是：

- 某段代码文件
- 某个类名

### 2. 阶段结果

“阶段结果”指的是：

- 某一协议阶段正式产出的、可供下一阶段读取的唯一结果对象

它不是：

- 某模块的临时私有状态

### 3. 意图

“意图”指的是：

- 单个协议参与者对阶段结果提出的局部改写主张

它不是：

- 阶段最终结果本身

### 4. 宿主结果

“宿主结果”指的是：

- 宿主把多个参与者意图合并后，得到的该阶段正式结果

### 5. 协议参与者

“协议参与者”指的是：

- 在某一阶段读取当前上下文，并提交意图的扩展单元

它可以是：

- 模块
- 能力适配器
- 表达宿主桥

但它在协议中的地位统一视为：

- 参与者

## 四、协议总原则

## 1. 每段只有一个正式输入面

每一阶段都必须只从这些来源读取：

- 上一阶段正式结果
- 当前共享只读上下文
- 当前阶段允许读取的正式宿主信息

不允许跨段偷读：

- 更早阶段的私有临时状态
- 某模块内部缓存
- 某个 UI 临时对象

## 2. 每段只有一个正式输出面

每一阶段最终只能产出：

- 一个正式阶段结果

无论内部参与者多少，下一阶段只读这一份结果。

## 3. 参与者只能提交意图，不能直接篡改最终宿主状态

参与者可以：

- 读取允许读取的上下文
- 提交意图

参与者不能：

- 直接替宿主写最终结果
- 直接跳过合并器去改下一阶段输入

## 4. 合并器是阶段内唯一结果裁定者

一个阶段如果允许多个参与者并存，就必须有：

- 宿主级合并器

由它统一决定：

- 哪些字段累加
- 哪些字段替换
- 哪些字段取最小 / 最大 / 首个 / 最后一个 / 优先级最高
- 冲突时哪个意图失效

## 5. 链后投影不回写链内结果

信息投影和视觉投影只能：

- 读取链内正式结果

不能：

- 反过来回写链内阶段结果

## 五、正式阶段标准

这份文档不把重点放在“已有玩法名”，但仍然承认远程链至少存在以下正式阶段：

1. 远程执行请求进入
2. 目标解算
3. 发射计划解算
4. 投送宿主建立
5. 在途推进
6. 接触解算
7. 落地结果解算
8. 信息投影
9. 视觉投影

这些阶段的存在，不是为了贴旧功能，而是因为：

- 任何远程行为无论具体长什么样，都必须回答这几类问题

## 六、各阶段正式输入输出契约

## 1. 远程执行请求进入阶段

### 正式输入

- 已正式成立的远程表达结果
- 执行者
- 当前目标输入
- 语义上下文

### 正式输出

- 一份远程执行请求

### 这个请求至少要包含什么

- 来源表达标识
- 执行者标识
- 原始目标
- 原始参数面
- 语义上下文

### 这一阶段的意义

- 把表达层结果转成远程链统一入口协议

## 2. 目标解算阶段

### 正式输入

- 远程执行请求
- 当前世界态中允许读取的目标 / 路径 / LOS 信息

### 正式输出

- 一份目标解算结果

### 结果至少要允许表达什么

- 最终目标
- 中间导向目标
- 是否允许执行
- 空间约束解释
- 目标修正信息

### 参与者能提出哪类意图

- 修改目标
- 增加中间导向点
- 否决当前目标
- 附加目标解算解释

## 3. 发射计划解算阶段

### 正式输入

- 远程执行请求
- 目标解算结果

### 正式输出

- 一份发射计划

### 发射计划至少要允许表达什么

- 本次要不要发射
- 发射次数 / 批次 / 节奏
- 基础参数调制结果
- 使用消耗结算结果
- 投送宿主初始化所需参数

### 参与者能提出哪类意图

- 调整发射次数
- 调整节奏
- 调整参数
- 附加消耗
- 否决本次发射

## 4. 投送宿主建立阶段

### 正式输入

- 发射计划
- 目标解算结果
- 远程执行请求

### 正式输出

- 一份投送宿主初始化结果

### 它至少要允许表达什么

- 本次使用哪类 RimWorld 宿主
- 宿主初始化时携带哪些链内正式数据
- 在途阶段初始状态是什么

### 这一阶段的本质

- 把协议结果正式注入 RimWorld 可理解宿主

## 5. 在途推进阶段

### 正式输入

- 投送宿主初始化结果
- 当前在途状态

### 正式输出

- 下一步在途状态结果

### 在途状态至少要允许表达什么

- 当前位置 / 方向 / 生命周期
- 中间导向修正
- 在途阶段附加语义
- 是否继续推进
- 是否转入接触解算

### 参与者能提出哪类意图

- 改变推进方向
- 改变推进速度
- 改变生命周期
- 提前结束在途
- 请求进入下一阶段

## 6. 接触解算阶段

### 正式输入

- 当前在途状态结果
- 接触上下文

### 正式输出

- 一份接触解算结果

### 它至少要允许表达什么

- 是否接触成功
- 接触对象是谁
- 接触点是什么
- 接触后是否继续在途
- 应把哪类信息带入落地阶段

### 参与者能提出哪类意图

- 修改接触对象
- 修改接触解释
- 请求穿透 / 延续
- 请求中止

## 7. 落地结果解算阶段

### 正式输入

- 接触解算结果
- 原始语义上下文
- 投送宿主初始化结果中携带的链内数据

### 正式输出

- 一份落地结果

### 落地结果至少要允许表达什么

- 伤害
- 爆炸
- 状态施加
- 生成物
- 其它 RimWorld 可理解后果

### 这一阶段必须遵守的要求

- 最终结果必须回到 RimWorld 可理解对象

## 8. 信息投影阶段

### 正式输入

- 远程执行请求
- 落地结果
- 语义上下文

### 正式输出

- 对外信息投影结果

### 它至少要允许表达什么

- 伤害来源语义
- 场景默认主攻击决策解释
- 外部正式读取接口可消费的数据

## 9. 视觉投影阶段

### 正式输入

- 目标解算结果
- 发射计划
- 在途状态结果
- 落地结果

### 正式输出

- 视觉读取结果

### 它至少要允许表达什么

- 发射跟随基准
- 在途表现跟随信息
- 落地表现解释

## 七、标准字段分类规则

为保证未知能力也能接入，阶段结果中的字段应按语义分类，而不是按已知玩法名分类。

至少长期分为：

- `Gate` 字段：
  是否允许继续
- `Target` 字段：
  目标、导向、空间位置
- `Timing` 字段：
  节奏、时序、批次
- `Resource` 字段：
  消耗、锁定、释放请求
- `Carrier` 字段：
  投送宿主初始化信息
- `Transit` 字段：
  在途推进信息
- `Contact` 字段：
  接触与命中解释
- `Outcome` 字段：
  落地后果
- `Semantic` 字段：
  来源与解释语义
- `Visual` 字段：
  视觉读取信息

这样做的意义是：

- 新能力只要能表达成这些语义字段之一，就能自然接入
- 不需要为每种新玩法再发明一套私协议

## 八、合并规则标准

## 1. 合并规则必须按字段类型定义

不能写成：

- “模块 A 优先于模块 B”

这种过粗的规则。

应当写成：

- 哪些字段允许累加
- 哪些字段允许替换
- 哪些字段允许裁剪
- 哪些字段只能否决不能放宽

## 2. 至少承认四类标准合并语义

### 1. `Accumulate`

用于：

- 可叠加值
- 标签集合
- 附加说明集合

### 2. `Override`

用于：

- 最终目标替换
- 最终宿主替换

但必须定义优先级来源。

### 3. `Clamp`

用于：

- 参数收紧
- 生命周期收紧
- 射程 / 速度 / 次数等边界裁剪

### 4. `Deny`

用于：

- 否决执行
- 否决某目标
- 否决某落地行为

## 3. 否决语义必须是单向安全收敛

一旦某参与者对某阶段提出正式否决，
后续不能由另一个低优先参与者轻易把它重新放开。

否则整条链会变得不可预测。

## 九、冲突裁定规则

## 1. 冲突裁定必须由阶段宿主完成

参与者不能彼此协商。

冲突裁定只能由：

- 当前阶段宿主 / 合并器

统一完成。

## 2. 冲突裁定优先级必须来自正式来源

优先级可以来自：

- 表达宿主
- Def 配置
- 明确的协议优先级字段

不能来自：

- 模块注册顺序碰巧排前
- 文件加载顺序碰巧更早

## 十、扩展挂点规则

## 1. 扩展必须声明自己挂在哪个阶段

任何远程扩展都必须先回答：

- 我参与哪一个正式阶段

而不是先回答：

- 我是什么玩法名

## 2. 扩展必须声明自己读哪些字段、写哪些字段

这一步非常关键。

否则系统永远无法知道：

- 两个未知扩展会不会冲突

## 3. 扩展不应要求知道其它扩展存在

一个优秀的扩展挂点标准应尽量做到：

- 扩展只知道协议
- 不知道其他扩展名字
- 不需要和其他扩展直接互调

## 十一、链内与链外边界

## 1. 链内正式结果不能被按钮层替代

按钮层只是远程表达的一个入口投影。

它不是远程链协议输入。

## 2. 链内正式结果不能被视觉层替代

视觉层只能读取：

- 链内正式结果

不能回写：

- 目标结果
- 发射计划
- 命中结果

## 3. 链内正式结果不能被信息兼容层替代

信息层也只能读取正式结果做解释，
不能自己再推一套链内近似结果。

## 十二、链内执行阶段与链后读取阶段分层说明

前文仍把“信息投影”“视觉投影”列在正式阶段表中，
这里需要进一步澄清：

- 它们属于正式读取阶段
- 但不属于链内执行裁定阶段

之所以仍保留“阶段”这个叫法，
不是为了把它们重新混回执行链，
而是为了强调：

- 它们也必须走正式输入输出协议
- 它们也必须只读取正式结果
- 它们也不能各自私下重算一条伪攻击链

### 1. 链内执行阶段

链内执行阶段只包括：

1. 远程执行请求进入
2. 目标解算
3. 发射计划解算
4. 投送宿主建立
5. 在途推进
6. 接触解算
7. 落地结果解算

这一段才是：

- 真正决定攻击怎样执行
- 真正裁定参数怎样合并
- 真正决定 RimWorld 宿主怎样行动

因此只有这几段允许：

- 改写链内正式结果
- 提交执行意图
- 参与正式冲突裁定

### 2. 链后读取阶段

链后读取阶段包括：

1. 信息投影
2. 视觉投影

这两段的正式定位是：

- 从链内执行结果读取可消费结果
- 给信息层、兼容层、视觉层提供正式读取面

它们不是：

- 再做一次目标解算
- 再做一次发射计划改写
- 再做一次命中与落地裁定

### 3. 为什么仍要给链后读取阶段单独协议

因为如果不把它们单独写成正式读取阶段，
后面最容易出现两种退化：

- 信息层自己重算一套“看起来像是攻击结果”的说明值
- 视觉层自己重算一套“看起来像是飞行状态”的表现值

一旦发生这种退化，
系统就会出现：

- 行为结果一套
- 信息解释一套
- 视觉跟随一套

三者彼此不一致的问题。

### 4. 链后读取阶段的严格边界

信息投影与视觉投影可以：

- 读取链内正式结果
- 生成对外消费结果
- 生成兼容接口结果
- 生成视觉跟随结果

信息投影与视觉投影不能：

- 回写链内执行结果
- 重新决定命中与否
- 重新决定发射次数
- 重新决定宿主初始化参数
- 重新夺取调制或合并权限

### 5. 对后续实现的直接要求

后续实现时必须长期区分：

- 执行链协议扩展口
- 读取链协议扩展口

如果某个扩展想要：

- 改目标
- 改发射计划
- 改在途推进
- 改落地结果

它就必须挂在：

- 链内执行阶段

如果某个扩展只是想要：

- 解释结果
- 兼容外部读取
- 组织视觉表现

它就只能挂在：

- 链后读取阶段

不能以“只是为了显示”之名，
偷拿执行链裁定权限。

## 十三、第一阶段必须落地与只留口

## 1. 第一阶段必须正式落地

当前阶段至少必须落地：

- 远程表达进入统一入口
- 最小远程宿主投影
- 语义进入投送宿主
- 语义进入伤害 / 爆炸下游

## 2. 当前阶段只留口但必须明确

当前阶段可以不完整实现，但必须明确预留：

- 各阶段正式结果对象
- 标准字段分类
- 标准合并语义
- 冲突裁定规则
- 扩展挂点声明面

## 十四、对后续实现的直接要求

### 1. 不能按已知功能名设计协议

后续如果有人提出：

- 引导
- 追踪
- 穿透
- 范围
- 状态施加

首先要问的不是：

- 给它建哪个玩法模块类

而是：

- 它参与哪个阶段
- 它读哪些标准字段
- 它写哪些标准字段
- 它的意图怎样合并

### 2. 不能让未知能力通过私有旁路接入

所有未来能力都必须通过：

- 正式阶段
- 正式字段
- 正式合并器

接入。

只要允许旁路，协议最终一定失效。

### 3. 不能把协议写成与具体宿主深度耦合的功能清单

宿主可以是：

- `Verb`
- `Projectile`
- `Explosion`
- `Damage`

但协议本体不应绑死在：

- 某个具体子类行为形状

## 十五、一句话总括

远程攻击链正式输入输出说明真正要定义的，不是“旧 BDP 远程功能该怎样复刻”，而是“一套即使不知道未来具体功能长什么样，也能让任何远程能力以统一阶段、统一字段、统一意图、统一合并、统一冲突裁定规则接入，并最终稳定回到 RimWorld 宿主”的正式协议标准。
