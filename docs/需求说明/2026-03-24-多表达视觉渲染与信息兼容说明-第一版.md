# 多表达视觉渲染与信息兼容说明（第一版）

## 目的

这份说明专门把“多表达系统如何在游戏里被看见”和“多表达系统如何被外部读取”这两件事拆开讲清楚。

它回答的是：

- 旧 BDP 的复杂视觉表现到底属于什么性质的需求
- 信息面板与信息类模组兼容为什么是这次重构要新增强化的需求
- 多表达真实状态、视觉渲染、信息暴露、兼容回退、定点补丁边界各自属于哪一层
- 哪些做法是正确方向，哪些做法会把系统重新压扁

## 一、先下总结论

### 1. 复杂视觉表现是旧 BDP 已有的既有需求

这里不是“未来要不要支持复杂视觉”。

真正的问题是：

- 旧 BDP 在多表达前提下，已经真实做了复杂视觉表现
- 所以重构必须把它视为既有需求来理解和保留
- 不能把它误降级成“可选优化”或“以后再说的美术问题”

### 2. 信息对外兼容是这次重构要新增强化的需求

这里也不是“顺手补一点信息显示”。

真正的问题是：

- 旧 BDP 的内部真实状态是多表达并存
- 但对外信息暴露与兼容边界并不成熟
- 所以重构必须新增一套更正式、更稳定、更高兼容的信息投影能力

### 3. 视觉渲染和信息兼容不是同一层

它们都基于同一份真实多表达状态，但职责不同：

- 视觉渲染回答：游戏里到底画什么，跟谁，何时切
- 信息兼容回答：原版和其它模组到底应读到什么，默认看见什么

### 4. 默认单表面只是最后退路，不是系统真相

当某些外部对象天然只能理解一个主武器表面时：

- 允许回退到场景默认主攻击决策

但必须明确：

- 这只是兼容退路
- 不是内部真实状态
- 也不是视觉层的默认原则


## 二、正面的正确认识

### 1. 真实多表达状态是本体

所有后续讨论的起点都应该是：

- 当前真实成立了哪些表达
- 这些表达之间如何共存、合成、失效、切换

视觉和兼容都只能是它的投影层。

### 2. 视觉层是“游戏内投影”

视觉层回答的是：

- 当前应该画出哪些武器或部件
- 左右手当前各显示什么
- 当前执行攻击时，枪口、挥击、轨迹特效该跟谁
- 双武器和组合技当前怎样被看见

因此视觉层首先忠于：

- 游戏里的真实状态

而不是首先忠于：

- 外部信息系统只能识别一个武器表面的限制


### 3. 信息兼容层是“对外投影”

信息兼容层回答的是：

- 原版信息卡该看到什么
- 信息类模组该自然读到什么
- 外部系统一次只能读一个主要攻击表面时该读谁
- 哪些外部扩展可以通过正式接口读到更完整的多表达结构

因此信息兼容层首先忠于：

- 对外暴露边界

而不是首先忠于：

- 视觉层当前画了几把武器


### 4. 视觉层和信息层可以读取同一真实状态，但不必给出同一个结果

同一时间里完全可能出现：

- 视觉层同时画出双手两把武器
- 玩家手动层同时能点多个入口
- 自动攻击默认只读取一个主表达
- 原版信息卡默认只显示一个主兼容表面

这不是矛盾，而是多层投影的正常结果。

### 5. 旧 BDP 的视觉复杂度不能被原版单武器惯性吃掉

原版大多数时候默认只有一个主要武器。

但 BDP 不是原版单武器系统，所以不能简单推出：

- “原版只会画一把，所以 BDP 也只该画一把”

正确理解应该是：

- 原版单武器惯性主要限制的是默认宿主与默认兼容口
- 并不自动否定 BDP 自己的复杂视觉表现需求

### 6. 信息兼容新增需求也不能反过来压扁多表达系统

你现在要求的是：

- 内部多表达真实状态继续存在
- 在这个前提下，补出更成熟的对外信息暴露能力

所以信息兼容增强的正确方向不是：

- 把内部重新装成单武器系统

而是：

- 在真实多表达之上，加一层更清楚的对外投影

## 三、反面的错误认识

### 1. 错误：把视觉复杂度当成“以后再优化的表现问题”

这会直接低估旧 BDP 的真实需求。

后果通常是：

- 重构后逻辑对了，游戏里看起来却不对
- 双武器、组合技、切换状态在视觉上被压扁

### 2. 错误：把信息兼容等同于“主攻击模式显示一下就够了”

主兼容表面确实重要，但它只解决：

- 默认主表面回退

它解决不了：

- 多表达明细如何被 BDP 自己展示
- 外部扩展如何读到完整表达结构
- 视觉层和信息层读取口为何不同

### 3. 错误：让视觉层自己猜当前武器是谁

如果视觉层自己从零散状态反推，就会非常容易出现：

- 逻辑状态已变化，但绘制没变
- 组合已失效，但图标或武器残留
- 当前执行侧已切换，但枪口仍按旧侧偏移

### 4. 错误：让外部信息层自己从内部零散状态硬猜当前表面

如果外部信息层自己到处拼：

- 左侧缓存
- 右侧缓存
- 组合缓存
- 当前动作状态

最后往往会得到不稳定、滞后、互相打架的结果。

### 5. 错误：为了兼容，让系统回到“只有一把武器”

这是最危险的退化。

一旦这么做，就会重新损伤：

- 双武器真实并存
- 组合技独立表达
- 形态切换后的连锁重算
- 视觉与逻辑的一致性

## 四、这组问题里必须拆开的层级

### 1. 真实多表达状态层

回答：

- 当前真实成立了哪些表达
- 谁是单侧、谁是双武器、谁是组合技、谁已失效

### 2. 视觉渲染层

回答：

- 当前应画出哪些武器、部件、特效
- 左右手当前各显示什么
- 当前执行表现跟随谁

### 3. 场景默认主攻击决策层

回答：

- 当外部对象只能理解一个主要表面时，应默认暴露谁

### 4. 多表达信息明细层

回答：

- BDP 自己的 inspect、tooltip、说明面板，如何展示完整多表达状态

### 5. 外部正式读取接口层

回答：

- 愿意接入 BDP 的扩展内容，应如何读取完整表达集合、主兼容表面、当前手动入口、当前执行语义

### 6. 定点桥接 / 补丁层

回答：

- 哪些原版或第三方对象没有自然扩展口，只能在明确边界上做少量桥接

## 五、必须注意的复杂度

### 1. 视觉层的复杂度，不只是“多画几把武器”

真正复杂的是：

- 当前显示哪些常驻武器
- 当前哪些只是执行瞬间表现
- 枪口与发射点如何和当前执行表达一致
- 形态切换后绘制何时更新
- 双武器、组合技、切换中状态如何不互相打架

### 2. 信息兼容层的复杂度，不只是“显示几个数字”

真正复杂的是：

- 原版默认只理解一个主表面
- BDP 内部又是真多表达并存
- 因此必须长期同时维护：
  - 主兼容表面
  - 多表达明细
  - 对外正式接口

### 3. 这两层都受形态切换连锁影响

形态切换一旦改变了：

- 单侧表达
- 主副攻击
- 双武器合成
- 组合成立性

那么视觉和信息两层都必须同步重算。

### 4. 这两层还受自动攻击 / 主攻击投影影响，但不应被其吞掉

自动攻击默认读取主攻击投影，
但视觉与信息层不能因此退化成：

- “只看主攻击就够了”

因为：

- 玩家手动可操作内容可能比主攻击更多
- 视觉同时显示内容可能比主攻击更多
- BDP 自己的多表达明细也必须比主攻击更多

## 六、兼容要求的正确理解

### 1. 高兼容性适配的正确目标

不是：

- 让所有外部对象都天然理解完整多表达

而是：

- 先给大多数对象一个稳定、正式、可预测的默认读取口
- 再给愿意接入 BDP 的对象一个更完整的正式接口

### 2. 场景默认主攻击决策的真实地位

它的重要性在于：

- 原版和很多信息类模组天然只会读一个主要武器表面

所以它必须存在。

但它的地位仍然只是：

- 兼容默认口

不是：

- 系统真实状态

### 3. BDP 自己应承担完整多表达说明责任

也就是说：

- 原版和第三方对象未必能看全
- 但 BDP 自己的 inspect、tooltip、状态说明必须能把完整多表达结构讲清楚

### 4. 外部扩展应尽量走正式接口，不鼓励靠 patch 猜业务

这既是兼容要求，也是架构要求。

否则外部扩展会被逼着：

- 偷读内部缓存
- 模仿 BDP 自己的推导逻辑
- 在版本变化后频繁失效

## 七、定点补丁的边界理解

### 1. 哪些地方可以考虑做少量定点桥接

只限于这类对象：

- 原版明确只有单入口，但我们必须接进去的读取点
- 原版或高价值第三方对象没有正式扩展口，却有明确兼容价值的地方
- 结果写入点、显示写入点、读取写入点这种清楚边界

### 2. patch 的任务是什么

- 接线
- 桥接
- 把正式投影结果送到外部对象可理解的位置

### 3. patch 不该做什么

- 不承载复杂业务规则
- 不重新推导一套内部真实状态
- 不代替正式表达结果层
- 不代替正式信息投影层

### 4. 为什么不能把 patch 当默认优先方案

因为一旦这样做，就会滑回旧问题：

- 看起来兼容很多
- 实际上各处都在偷偷算业务
- 最后谁也说不清唯一真规则在哪里

## 八、对后续重构的直接要求

### 1. 视觉方面

必须始终记住：

- 旧 BDP 复杂视觉表现是既有需求
- 重构要先保真，再谈是否优化

若当前阶段缺正式视觉系统宿主支持，则允许采用最低回退方案：

- 武器贴图用“触发体”贴图
- 视觉绘制按原版逻辑

但后续仍要继续回到正式视觉投影层。

### 2. 信息方面

必须始终记住：

- 信息兼容是这次重构新增强化需求
- 目标是在真实多表达之上补正式投影，不是把系统压回单表面

若当前阶段缺正式信息系统宿主支持，则允许采用最低回退方案：

- 提供原版会拾取的等概念属性参数
- 远程场景读取“远程默认主攻击”
- 近战场景读取“近战默认主攻击”

后续正式信息层落地后，应继续承担：

- 把这些属性参数伪装成真实武器
- 让游戏引擎自然拾取

### 3. 文档方面

以后凡是写到：

- 当前武器显示
- 当前外部表面
- 当前信息兼容
- 当前绘制对象

都必须先说明自己指的是：

- 真实状态
- 视觉投影
- 场景默认主攻击决策
- 多表达明细
- 还是定点桥接结果

### 4. 测试方面

后续不能只测：

- 有没有攻击
- 能不能命中

还必须分别测：

- 视觉是否忠于真实多表达状态
- 形态切换后视觉是否同步更新
- 主兼容表面是否稳定正确
- 多表达明细是否完整
- 外部默认读取是否合理
- 少量定点桥接是否只接线、不偷算业务

## 九、一句话总括

这组需求的本质是：

旧 BDP 已经证明“多表达系统可以有真实复杂视觉表现”；而二次重构必须在保住这件事的同时，再新增一层更成熟的“对外信息暴露与兼容”能力，但这层新增能力绝不能反过来压扁真实多表达系统。
