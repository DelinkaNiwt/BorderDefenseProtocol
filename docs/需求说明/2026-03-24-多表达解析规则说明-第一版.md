# 多表达解析规则说明（第一版）

## 目的

这份说明专门用于把 BDP 中“表达来源如何解析成多表达结果，以及这些结果如何分层投影”压成一份正式规则文档。

它不是：

- 芯片定义手册
- Trigger 装载规则手册
- 远程链模块细节说明
- 视觉实现细节说明

它回答的是：

- 当前输入到表达解析层的正式信息是什么
- 单侧表达如何成立
- 双侧关系如何重算
- 攻击型与非攻击型表达如何共同成立
- 双武器与组合技如何被理解
- 表达结果如何分别投影到按钮、默认主攻击、自动攻击、外部兼容表面与非攻击结果读取层
- 哪些变化会触发整套结果重算

## 一、先下总结论

### 1. 表达解析层处理的是“来源 -> 结果”，不是“芯片 -> 按钮”

芯片进入表达系统后，首先提供的是表达来源。

表达解析层的职责不是直接回答：

- 现在有几个按钮
- 当前默认武器是谁
- 外部面板显示谁

表达解析层首先回答的是：

- 当前正式成立了哪些表达结果

按钮、默认主攻击、兼容表面、视觉跟随，都属于表达结果之后的投影层。

### 2. 单侧表达先成立，双侧关系后成立

解析顺序必须先承认：

- Main 当前成立了什么
- Sub 当前成立了什么

然后才继续回答：

- 两侧是否构成攻击型高层结果
- 两侧是否构成非攻击型高层结果
- 当前默认主攻击投影应取谁
- 当前非攻击型来源是否发生叠加、覆盖或联动

如果跳过单侧表达，直接从双侧状态凑结果，系统会极易退化成：

- 只剩一个默认攻击
- 双武器与组合技全靠特判
- `Hediff / Passive / Ability` 全被当成外围杂项

### 3. 双武器与组合技是高层新表达，不是按钮附加功能

当左右两侧表达同时存在时，系统可以额外成立：

- 双武器表达
- 组合技表达

它们不是：

- 两侧按钮简单并排
- 左右两条攻击同时执行的小技巧

它们的本质是：

- 由多个已成立来源进一步解析出的更高层表达结果

但这里必须补一条：

- 高层新表达不只可能发生在攻击型来源上

对于非攻击型来源，也可能存在：

- 叠加后形成的新状态结果
- 联动后形成的新能力结果
- 组合后形成的新被动结果

只是旧 BDP 当前最明确、最完整的事实主要落在攻击型表达上。

### 4. 主攻击投影不是全部表达的总代名词

表达结果层可能同时成立多个结果。

但系统在某些场景必须选一个默认结果时，需要单独给出：

- 默认主攻击投影

它主要服务于：

- 自动远程默认读取
- 自动近战默认读取
- 对外兼容表面默认读取

它不等于：

- 玩家当前全部可操作表达

而且它只回答：

- 攻击型默认读取口

它不直接代表：

- `Ability` 默认读取口
- `Hediff` 结果集合
- `Passive` 结果集合

### 5. 一个按钮可以承载多个直接操作入口

旧 BDP 已明确存在：

- 左键主攻击
- 右键副攻击

因此：

- 按钮载体数量

不等于：

- 直接操作入口数量

### 6. 形态切换是正式重算触发点

芯片形态变化会直接改变：

- 单侧来源
- 单侧表达
- 双侧关系
- 主副攻击可用性
- 双武器结果
- 组合技结果
- 默认主攻击投影
- 按钮与描述
- `Ability` 可用性
- `Hediff` 叠层或模式结果
- `Passive` 成立状态与外部读取结果

因此，形态切换必须视为整套表达解析的正式重算触发点。

### 7. 特殊侧武器类表达拥有主副侧武器类拦截权

特殊侧和 Main / Sub 不同。

因为特殊侧芯片默认是：

- 整组同时激活

所以如果不额外裁定武器类表达规则，
就会很容易把系统拉成：

- 特殊侧多武器同时成立
- 特殊侧武器和主副侧武器一起并存
- 最后又靠按钮层或主攻击层硬压结果

当前第一版正式裁定为：

- 如果特殊侧当前存在武器类表达，则它拦截 Main / Sub 的武器类表达
- 此时主副侧武器类表达不再作为并列表达成立
- 特殊侧武器类表达被视为当前唯一武器类单侧表达
- 特殊槽当前只允许正式表达出一个武器类结果，禁止多个武器类同时成立

这里要补清楚：

- 这条拦截规则只针对武器类表达
- 不自动吞掉非武器类 `Ability / Hediff / Passive`

也就是说，特殊侧的地位不是：

- 一出现就把整个表达系统全部盖掉

而是：

- 在武器类表达上拥有更高优先级与唯一化裁定

## 二、表达解析层的正式输入

表达解析层当前只应读取已经正式成立的上游事实。

### 1. 芯片装载事实

包括：

- 当前槽位装了什么芯片
- 芯片当前形态
- 芯片所属侧

这里应额外允许表达解析层读取：

- 当前是否存在特殊侧武器类表达

因为这会直接影响：

- Main / Sub 武器类表达是否还能成立
- 当前武器类表达是否进入唯一化裁定

### 2. 局部激活事实

包括：

- 当前哪些槽位已正式激活
- 哪些槽位只是切换中目标，不算正式成立

### 3. 局部禁用事实

包括：

- 某槽位当前是否因局部规则失效

禁用来源不能继续参与表达成立。

### 4. 来源声明事实

包括：

- 该芯片当前形态下声明了哪些来源
- 每条来源属于哪种顶层大类
- 每条来源的角色、条件、标签、局部 Trion 参数

这里的顶层大类至少包括：

- `Verb`
- `Ability`
- `Hediff`
- `Passive`

### 5. 战斗体相关前置事实

若某来源要求战斗体激活才能成立，则表达解析层可以读取：

- 战斗体是否已正式处于允许状态

但表达解析层不持有战斗体真值。

## 三、单侧表达如何成立

### 1. 单侧表达的来源来自该侧当前正式激活槽位

单侧表达只能从：

- 当前侧已正式激活的槽位

中读取来源。

以下内容不应被算入单侧正式表达：

- 未装载芯片
- 未正式激活的槽位
- 已禁用槽位
- 仍在 `WarmingUp` 中尚未提交真值的目标槽位

### 2. 单侧表达是一个结果集合，不是单个固定对象

单侧表达至少可能同时包含：

- 攻击型 `Verb` 来源
- `Ability` 来源
- `Hediff` 来源
- `Passive` 来源

因此，单侧表达本身就不应被理解成：

- 一把单独武器
- 一个单独按钮

更准确地说，单侧表达是：

- 某一侧当前正式成立的全部表达结果集合

### 3. 单侧攻击表达至少要区分主攻击与副攻击

对于攻击型表达，单侧内部至少要能回答：

- 当前是否有主攻击
- 当前是否有副攻击

旧 BDP 的事实已经证明：

- 单侧攻击不等于只有一个直接操作入口

### 4. 单侧非攻击表达也必须正式成立，而不是附属挂件

对于单侧 `Ability / Hediff / Passive`，表达解析层至少要能回答：

- 当前是否存在 `Ability` 结果
- 当前是否存在 `Hediff` 结果
- 当前是否存在 `Passive` 结果
- 这些结果当前是独立存在、还是附着于某个攻击表达一起被说明

这一步很关键，因为如果不把非攻击表达作为正式结果，系统会退化成：

- 攻击算正式表达
- 其它都算副作用

这不符合芯片标准结构中四个顶层大类并列的事实。

### 5. 单侧表达先于双侧关系

表达解析层必须先把每一侧自己的结果集合建立出来，再去重算双侧关系。

原因是：

- 双武器和组合技都依赖已成立的单侧结果
- 手动按钮、默认主攻击、兼容表面都不能跳过单侧层直接硬凑

### 6. 特殊侧武器类表达先于 Main / Sub 武器类并列成立

在武器类表达上，特殊侧不是普通第三侧并列参与者。

更准确地说：

- 它先决定“主副侧武器类表达还能不能继续成立”

因此在武器类这条子链上，顺序应理解为：

1. 先看特殊侧是否正式成立武器类表达
2. 若成立，则主副侧武器类表达被拦截
3. 当前武器类结果只保留特殊侧这一份单侧表达
4. 若不成立，才继续走 Main / Sub 的普通单侧成立与双侧关系重算

这样做的目的不是偷懒，
而是承认特殊侧“整组同时激活”这一输入事实带来的正式优先级差异

## 四、双侧关系如何重算

### 1. 两侧同时存在时，不自动吞掉单侧表达

当 Main 与 Sub 都有已成立表达时：

- 双侧关系重算可以额外产生更高层结果

但默认不应直接抹掉两侧独立表达。

否则系统会错误退化成：

- 只剩一个双手主攻击
- 只剩“攻击是真结果，其它表达是假附加”

### 2. 双武器表达的本质是高层合成结果

当两侧都存在攻击型表达时，系统可以进一步判断：

- 是否成立双武器表达

双武器表达是：

- 基于两个单侧攻击结果合成出的新攻击表达

它不等于：

- 左右各打一遍的并排表示

### 3. 组合技表达也是高层新结果

当两侧满足特定匹配条件时，系统可以进一步判断：

- 是否成立组合技表达

组合技表达与双武器表达一样，属于：

- 在单侧结果之上进一步成立的新结果

它不是：

- 某个按钮描述附带文字
- 某种只影响 UI 的组合状态

### 4. 双武器与组合技允许并存于结果层

表达结果层应优先回答真实成立了什么，而不是先急着压缩成最少按钮数。

因此：

- 左侧独立结果
- 右侧独立结果
- 双武器结果
- 组合技结果

在规则允许的情况下可以同时存在于结果集合中。

### 5. 非攻击型双侧关系也必须允许形成高层结果

对于 `Ability / Hediff / Passive`，双侧关系重算不能只回答“有没有攻击型合成”。

它还应允许回答：

- 左右两侧同类状态是否叠加
- 左右两侧不同类来源是否联动
- 某些组合是否形成新的非攻击型高层结果

旧 BDP 当前最明确的例子包括：

- 护盾类 `Hediff` 的叠加结果
- 未来可能存在的 `Ability + Ability`、`Passive + Passive`、`Ability + Hediff` 组合结果

因此，双侧关系层的正式语义应是：

- 它重算的是“多输入表达的高层结果”

而不是：

- 只重算武器合成

### 6. 默认主攻击投影必须在高层重算后单独选出

默认主攻击不应在单侧阶段就提前写死。

更合理的顺序是：

1. 单侧结果成立
2. 双侧关系重算
3. 在完整结果集合中选出默认主攻击投影

这里补一条特殊侧武器类裁定后的顺序解释：

- 如果特殊侧武器类表达已经成立并拦截主副侧武器类表达
- 那么默认主攻击投影应直接从这份唯一武器类结果继续下游投影
- 而不是再回头假装 Main / Sub 武器类还在候选集中

## 五、表达结果到投影层的分层

## 1. 手动按钮载体层

这一层回答：

- 当前哪些表达结果被投影成玩家可见按钮

它不回答：

- 当前总共成立了多少表达结果

这里必须补一条：

- 不是所有表达结果都必须生成手动按钮

例如：

- `Passive` 可能没有直接按钮
- 某些 `Hediff` 结果也可能只有状态成立、不提供主动入口

### 2. 直接操作入口层

这一层回答：

- 每个按钮内部实际可直接操作几个入口

旧 BDP 已明确证明：

- 一个按钮至少可以承载主攻击与副攻击两个入口

对于非攻击型表达，这一层还要能回答：

- 某个 `Ability` 是否通过单独按钮提供直接入口
- 某些非攻击型结果是否根本不进入直接操作层

### 3. 默认主攻击投影层

这一层回答：

- 当前系统必须选出一个默认主攻击时，应使用谁

它服务于：

- 自动攻击
- 默认兼容表面
- 单一主攻击读取场景

### 4. 自动攻击读取层

这一层回答：

- 自动远程默认读谁
- 自动近战默认读谁

它本质上只处理攻击型默认读取，不代表全部表达系统。

### 5. 外部兼容表面层

这一层回答：

- 原版或外部系统如果只能识别一个主武器表面时，应看到谁

如果当前表达结果不属于主武器表面类型，则这一层不应强行把它们压成武器结果。

### 6. 视觉绘制与执行跟随层

这一层回答：

- 当前绘制跟谁
- 枪口或执行侧跟谁

这层读取真实结果，但不负责重新解析表达。

这里要额外承认一种正式但克制的视觉例外：

- 某些双手锁定武器虽然在结果层仍然只是单侧表达
- 但在视觉层允许被伪装成双侧表达

这条规则的边界必须钉死：

- 伪装只发生在视觉读取层
- 不反向改变结果层身份
- 不把单侧表达改写成双侧结果
- 不影响默认主攻击、手动入口或高层关系重算

### 7. 非攻击结果读取层

这一层回答：

- 当前已成立的 `Ability / Hediff / Passive` 结果应如何被正式读取
- 哪些结果只供 BDP 内部读取
- 哪些结果需要暴露给外部兼容或说明面板

这一层存在的原因是：

- 非攻击表达不能被硬塞进“主攻击投影层”才能拥有正式地位

## 六、重算触发点

以下变化都必须视为正式重算触发点：

- 芯片装载变化
- 芯片卸载变化
- 槽位正式激活提交
- 槽位正式关闭提交
- 槽位禁用状态变化
- 芯片形态切换
- 双侧已成立表达发生变化

### 1. 重算必须依赖正式状态变化，不依赖 tick 自然流动

立即应成立的解析结果，不允许做成“等时间动起来再刷新”。

tick 只允许用于：

- 资源自然过程
- 冷却
- 表现计时

不允许作为“表达是否成立”的前提。

## 七、典型状态组合的正式理解

### 1. 只有一侧成立攻击表达

此时：

- 成立一个单侧攻击结果
- 可以投影出一个按钮
- 该按钮内部可能仍有主副攻击两个入口
- 默认主攻击通常取该结果

### 2. 两侧都成立独立攻击表达

此时：

- 至少成立左右两侧各自的攻击结果
- 不应先天被压成一个结果

### 3. 一侧攻击 + 一侧非攻击表达

此时：

- 攻击表达仍是攻击结果
- 非攻击表达也必须作为正式结果成立
- 默认主攻击投影只回答攻击型默认读取
- 非攻击结果通过自己的读取层继续存在

### 4. 两侧可组成双武器表达

此时：

- 左右独立结果仍然是输入基础
- 系统可额外成立双武器表达结果
- 默认主攻击投影可能改为双武器表达

### 5. 两侧可组成组合技表达

此时：

- 左右独立结果仍是输入基础
- 系统可额外成立组合技表达结果
- 若规则要求，默认主攻击投影可被组合技接管

### 6. 两侧可形成非攻击型高层结果

此时：

- 左右独立非攻击结果仍是输入基础
- 系统可额外成立叠加、联动或组合后的高层结果
- 该高层结果不必一定映射成攻击按钮

### 7. 单按钮双入口

此时：

- 一个按钮载体
- 两个直接操作入口
