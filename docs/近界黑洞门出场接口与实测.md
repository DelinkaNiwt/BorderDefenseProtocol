# 近界黑洞门出场接口与实测

本功能在 Content（正式内容层），只组织人物怎样入场；人物生成、战斗体和战斗队伍继续使用现有逻辑。Development（开发层）只提供测试菜单。Core（基础设施层）没有新增业务。

## 配置组合

参数位于 `1.6/Content/Defs/PawnsArrivalModeDef/GateArrival.xml`，每波启动时复制并保存，不受后续定义修改影响。60游戏刻相当于标准速度下一秒。

| 需要的形式 | 配置 |
| --- | --- |
| 全部门同时开启 | `gateOpenIntervalTicks = 0`（开门间隔为零） |
| 门依次开启 | `gateOpenIntervalTicks > 0`（逐门开门间隔） |
| 各门就绪后分别出兵 | `waitForAllGates = false`（不等待全部门） |
| 等全部门就绪，同刻开始出兵 | `waitForAllGates = true`（等待全部门） |
| 每门分批出兵 | `releaseAllAtOnce = false`（分批），另设 `batchSize`（每批人数）与 `releaseIntervalTicks`（批次间隔） |
| 每门一次放完 | `releaseAllAtOnce = true`（本门全量） |
| 整波同刻放完 | 全量出兵并等待全部门就绪 |
| 各门独立关闭 | `closeTogether = false`（各门人员放完即可关闭） |
| 整波放完统一关闭 | `closeTogether = true`（等待整波） |

另外可设首门等待、开门动画、开门后等待、最短保持、关门动画和尺寸。出兵受阻时原版容器保留人物，按批次间隔重试；不把人物放到门范围外，也不把失败当出场成功。

## 给后续袭击和诱导建筑的接口

命名空间为 `BDP.Content.Factions.GateArrival`（门抵达业务）。主要入口：

- `Thing_GateArrival.Start`（启动一波）：接受人物及点位，默认均匀分配；另一重载接受 `GateArrivalGroup`（显式门分组），可自定每门人数、兵种及队伍来源。调用者负责生成人物，并在启动后通过原版给完整人物列表建队。
- `GateArrivalHooks.ActiveWaves(map)`（查询地图当前门波）：得到各波及只读门状态。使用波对象和门序号定位目标，不需要全局门注册表。
- `wave.TryRedirect(index, destination)`（请求改址）：只接受当前地图内未遮蔽、可站立的格子和未开启的门，返回是否接受。不会移动已经出场的人物。原始位置和当前目的地分别保留。
- `GateArrivalHooks.ResolvingDestination`（开门前解析通知）：诱导建筑在回调中检查地图、范围和供电条件，再调用 `request.Propose(cell, priority, sourceId)`（提交位置、优先级和来源标识）。优先级高者优先；同级按稳定来源标识排序，完全相同时按坐标排序；无效候选依次跳过。建筑可用自身 `ThingID`（原版对象标识）作为来源。
- `wave.Cancel()`（取消出场）：已出场人物继续战斗，未出场人物移出队伍并归还世界。取消不发原版“全部敌人被击败”信号；任务调用方通过取消通知处理自己的失败或撤销规则。

可订阅开门、改址、人物落地、出场完成、开始关门及取消通知。音效、额外闪光、消耗诱导资源等挂在对应通知上；本功能不强制这些业务。订阅静态通知的外部系统需在自己的退出流程解除订阅，回调异常会记录日志且不打断出兵。

默认抵达方式只接管近界普通进攻的自动选择，皇室追兵显式使用同一方式；特殊策略、明确指定的其它抵达模式和其它派系保持原入口。默认点位暂借原版地图入口附近的可用格；后续新袭击直接提供自己的门分组即可。

## 保存和原版关系

一波由一个地图对象持有，未出场人物在原版人物容器中深存，每扇门只保存人物引用和进度。任务人物转入容器前从世界人物列表移除；取消时避免重复归还。完整人物列表在原版队伍内，因此首批全灭不会仅因地图上暂时没有敌人而消灭整波队伍。

门画面复用原版折跃出口的内部面和外圈两层。仅把特效年龄推进到稳定段并维持，关闭时推进至消退段；暂停停止游戏刻，但仍每帧绘制。原版着色器内部纹理能否按预期持续流动，以及遮挡层次，必须进游戏观察，当前未验证着色器本体公式。

地图卸载前只取消本地图的 BDP 门，再完整执行原版卸载。不能在较晚的地图部件通知中清理，因为原版已经收集递归对象快照，并可能将未落地人物标记为丢弃。

## 本轮验证及下一步

已通过正式和开发程序集构建、门时序与诱导裁决测试、原版语言加载测试、现有皇室入口与追兵队伍回归、开发层单向依赖检查及新增配置格式检查。

游戏内打开原版开发菜单的 BDP 分类，进入“黑洞门出场测试”。所有测试门等待十秒后开启；纯视觉门再保持十秒。四种人员测试均为三门九人，会产生真实敌人。

1. 先用纯视觉门，检查形状、边缘、保持和收缩；在保持阶段暂停，观察纹理是否继续流动。
2. 比较四种组合；依次开门与各门全量出兵并不等于整波同刻出兵，整波同步另用等待全部门参数。
3. 在十秒等待窗口内用重定向工具点新位置，再尝试改动已开启的门，确认拒绝且人物没有被移动。
4. 分批出兵中保存并读档，对照“输出当前地图门状态”；再检查首批全灭、受阻后恢复、两波重叠及不同速度。
5. 在有未出场人物时取消或移除地图，检查日志、世界人物保存和皇室任务结果，确认取消未被当作战斗胜利。

以上五组游戏内验证仍待执行；离线检查不能替代这些结果。
