# 近界战斗 AI（行动决策）诊断新档测试说明

2026-10-13 版本已加入正式的自动攻击边界修复：远程查询只返回默认攻击，实际起手才准备会话；自动近战向原版提供短剑，不替换原版任务。诊断集中于 Development.dll（开发程序集），随程序集自动启用；无需打开开发者模式、选中人物或点击诊断按钮。统一搜索标记：`BDP_AI_TRACE`。

本日后续版本还补齐自动双近战同一次计划的有限跨段，仍由原版管理任务和目标。具体实现及离线验证见[有限续段补齐记录](02-研究记录/2026-10-13-自动近战有限续段补齐.md)。

## 开始前

完全退出并重新启动 RimWorld（边缘世界），然后开新档。只在同一个游戏进程里返回主菜单建新档不会重新加载程序集。

启动日志应出现 `hooks_ready`（观察入口注册完毕），数值 `installed=24, expected=24`；主菜单尚无游戏对象时，日志计时为 `tick=-1`。进地图应出现 `map_ready`（地图诊断加载完成）以及 `map_pulse`（地图心跳）。这两类不依赖敌人到场；有错误会出现同一标记下的中文错误说明和具体失败方法。

## 一轮建议观察顺序

1. 生成近界宙域普通袭击，确认有 `pawn_registered`（人物登记），记下至少一名敌人名字；名字不是诊断开启条件，只方便之后对照画面。
2. 先让其向殖民者 A 使用弹丸射击，再让 A 离开视线；保留另一名被动站立的殖民者 B 和一座有效炮塔，观察任务变化。
3. 观察被动殖民者身旁能否正常出短剑，以及随后恢复视线时能否重新射击。若再次出现贴脸不打，保持原状至少十秒，再让该殖民者近身反击，继续约十秒，保留两种状态的入口计数和周期快照。
4. 若条件允许，在同一新档中移除炮塔后重复一遍；不必为诊断额外更改模组设置。
5. 测试结束后先保留本轮 `Player.log`（游戏日志），再重新启动游戏，避免后续运行覆盖。反馈大致发生顺序与样本名字即可，不需要手工筛日志。

## 日志如何区分方向

本次补齐另需观察：准备一名合法启用双近战的非玩家 BDP 单位，确认主手打完、冷却结束后能接副手，原任务没有被换成 BDP 持续任务。随后分别在主手冷却中换任务、换目标、让目标离开近战范围，再在两段之间保存并读取，检查旧计划不会继续攻击旧目标或从首手无限循环。短期限原任务若已经结束，剩余副手取消符合本轮边界；原版后续可以重新发起一次新攻击。现有 `cast_request / cast_result`（实际起手尝试／结果）、`melee_shot`（近战单击）、任务记录和人物宿主快照可用于对照；自动跨段本身不会经过旧持续任务的 `melee_tick`（近战任务推进）。

| 关键记录 | 能确认的问题层次 |
|---|---|
| `decision_enter / decision_result`（原版派工开始／结果） | 原版进入作战、破坏、走向敌人、开路还是反击；空任务也输出 |
| `shoot_position`（射击位置结果） | 是否因为找不到射击站位而回退 |
| `bdp_query_transform`（BDP 查询前后） | BDP 是否清掉原版原本已有的攻击候选 |
| `ranged_query`（远程候选查询）中 `bridgeHandled=True`（提供默认攻击） | 确认 BDP 提供了远程能力；新版已移除旧会话清空候选分支和对应字段 |
| `job_start_attempt / job_started / job_cleanup`（任务启动请求／实际状态／清理） | 谁创建了近战／走路任务及为何退出；新版自动近战不应再创建 BDP 持续近战任务 |
| `override_enter / nearby_enemies`（重决策／附近敌人判断） | 到期后是否重新决策，还是被附近敌人条件挡住 |
| `wait_auto / melee_request`（等待自动检查／近战请求） | 人物是否仍在战斗等待里检查攻击；原版究竟有没有请求近战 |
| `melee_tick / session_validation`（近战推进／会话校验） | 已有近战任务是否卡在忙碌、追击、接触距离或失效会话 |
| `cast_request / cast_result`（实际起手尝试／结果） | 接单后是否真正成功启动攻击；外层准备和原版起手分层记录 |
| `melee_shot / ranged_shot`（实际近战单击／远程发射） | 有没有真正进入攻击动作，区分闪避、没命中和完全未出手 |
| `ranged_reset`（远程重置） | 旧远程会话何时真正释放 |
| `pawn_pulse`（人物周期摘要） | 每五秒输出任务、来源、姿态、寻路、目标、邻格威胁、宿主状态和累计计数，未调用的关键入口明确为零 |

重复探测会计数；相同记录最多每三秒重复一次，内容变化立即输出。人物每秒采样、每五秒固定摘要，地图每十秒心跳。高频正常出手保留短上下文，异常、任务变化及周期摘要保留完整快照，避免大袭击淹没日志。事件与周期快照相互补充，因此站着没有动作也会有证据。

所有快照只读取已有状态，不调用攻击选择、可用性裁定或实际起手来“测试”人物。只跟踪非玩家 BDP 装备持有者，已登记样本卸装后继续观察。数据不写入存档；移除诊断源码目录和对应开发语言包、重编译并同步 Development.dll 即可撤销本轮诊断。

## 验证边界

注意：早期诊断使用参数数组观察 BDP 后置补丁，已查实会隐式恢复旧攻击候选，改变实际派工结果。该版本的“BDP 查询前后”记录也可能读取旧值，不能作为无干扰的测试基线。源码现已改为按参数位置只读，并补充真实 Harmony（补丁框架）引用参数检查；具体安装状态及旧档证据见[本轮核查记录](02-研究记录/2026-10-12-诊断补丁改变攻击查询结果的核查.md)。

正式修复及原版／BDP 分工见[修复记录](02-研究记录/2026-10-13-自动远近战边界正式修复.md)。诊断应当保留，直到这一轮地图实测确认结果；代码检查不能证明所有游戏内场景已经修好。

已核实真实程序集中的补丁方法、回调参数、内部读取口及语言键，四个程序集全量编译。另实际调用诊断计时读取口，验证主菜单无游戏对象、游戏对象无计时器、正常计时三种状态。离线检查没有启动游戏，不冒充游戏内复现或补丁运行成功；新进程中的入口注册日志和周期反馈负责确认现场加载状况。
