# 毒蛇通用骨架重审评估

## 总判断

- 毒蛇暴露出来的“多目标语义、分段合法性、预览绘制、续段飞行”需求，主模组已经抽出了大半通用骨架。
- 当前最有价值的工作不是继续大抽象，而是把现有骨架的职责口径集中写清楚。
- 毒蛇自己的锚点链、路径状态、段推进器、Shift 追加锚点、右键取消等内容，仍应留在测试模组业务层。

```text
Targeting（目标选择）
  -> 当前候选点合法性

Confirm（确认）
  -> Target（导航确认目标）
  -> SemanticTarget（语义目标）

Snapshot（冻结快照）
  -> NavigationTarget（导航目标）
  -> SemanticTarget（语义目标）

ProjectileInit（投射初始化）
  -> LaunchTarget（发射/首段目标）
  -> AimTarget（瞄准目标）
  -> CurrentTarget（当前语义目标）

Arrival（到达续段）
  -> NextDestination（下一段目的地）
  -> NextTarget（下一段目标）
```

## 已经合理抽成主模组骨架的内容

### 1. 多目标语义

- `ConfirmRecord` 已经区分 `Target` 与 `SemanticTarget`。
- `ConfirmedTargetSnapshot` 已经区分 `NavigationTarget` 与 `SemanticTarget`。
- `ProjectileInitPlan` 已经区分 `LaunchTarget / AimTarget / CurrentTarget`。
- `FlightRecord / HitStageContext / ImpactStageContext` 已经在飞行、命中、影响阶段继续携带语义目标。
- 毒蛇只是把这些字段赋成“首段锚点”和“最终目标”，没有把毒蛇字段反塞回主模组。

### 2. 分段合法性

- `TargetingSegmentLegalityRequest` 只描述“从哪一格到哪个候选目标”的中性事实。
- `DefaultTargetingSegmentLegalityService` 只复用原版目标参数和命中线判断，不知道毒蛇、锚点、路径。
- 毒蛇在业务层决定“当前要检查哪一段”，然后调用主模组的中性合法性服务。

### 3. 预览绘制

- `PreviewRecord.DrawItems` 与 `PreviewDrawItemKind` 已经提供线、圈、格子组、文字标签。
- 毒蛇只把折线和标签填进去，主模组不需要理解“毒蛇路径”。

### 4. 续段飞行

- `ArrivalContribution` 已经提供是否继续飞、下一段目的地、下一段目标。
- `BdpProjectile` 统一消费续段结果并移动投射物。
- 毒蛇只发布下一段真值，不接管真实碰撞、命中、伤害。

## 值得考虑的轻量上提

### 1. 目标语义口径文档

- 价值：高。
- 成本：低。
- 形式：补一份主模组架构说明，不一定改代码。
- 目的：明确每一层的目标字段分别负责什么，避免以后又把首段导航点和最终语义目标混用。

### 2. 语义目标解析小工具

- 价值：中。
- 成本：低。
- 现状：`AttackExecutionService.Stages` 与 `RangedAttackProtocolService` 都有“优先读冻结快照的 `SemanticTarget`，没有再退回请求目标”的类似逻辑。
- 可选做法：以后如果继续碰到目标语义分歧 bug，可以抽一个中性 `TargetSemanticResolver`。
- 注意：这只是收拢默认读取规则，不应新增“毒蛇目标角色枚举”。

### 3. 候选合法性与确认合法性边界说明

- 价值：中。
- 成本：低。
- 当前代码已经有 `HasCurrentTargetLegalityOverride` 这条桥。
- 仍应说明：
  - 候选点合法性负责光标提示和禁止图标。
  - 最终确认合法性负责是否允许落地攻击。
  - 分段合法性只回答一段是否成立，不替业务决定整条路线。

## 不建议上提的内容

- `PathLatchState`：保存毒蛇锚点、最终目标、当前段索引，是毒蛇私有状态。
- `PathLatchSegmentResolver`：按“锚点 + 最终目标”构建段列表，是毒蛇路径模型。
- Shift 追加锚点、右键取消、最大锚点数、最终目标类型限制：都是毒蛇交互业务。
- 把所有目标塞进一个 `TargetRole` 字典或大枚举：当前显式字段更清楚，强抽会让简单模块也背复杂度。
- 抽通用“路径系统”：目前只有毒蛇明确需要这套锚点路径模型，缺少第二个真实复用者。

## 灰区解释

- “多段飞行”本身是主模组骨架，因为任何模块都可能要求投射物改下一段。
- “具体路线怎么算”是业务，因为不同模块可能是锚点、追踪、反弹、散射、回旋，算法完全不同。
- “目标语义分层”是主模组骨架，因为双持、齐射、引导、续段都会受影响。
- “毒蛇如何给这些目标赋值”是业务，因为它只代表毒蛇自己的首段与终点关系。

## 结论

- 不需要把毒蛇机制整体抽进主模组。
- 不建议新增大框架。
- 下一步若要整理，优先做“目标语义口径说明”和“可选的语义目标解析小工具”，保持短、简、直。
