# 远程间接攻击许可最终方案

## 结论

本次需求不是给风刃、猎犬、黄蜂等芯片分别打补丁，而是把“远程表达可以在许可条件下使用非直视目标”提升为 BDP 远程表达的通用能力。

```text
正式远程表达
    ├─ 目标选择/Verb 命中检查
    │      └─ 间接攻击许可：前置授权 → 屋顶后置条件
    └─ ProjectileInit
           └─ 使用同一授权结果合并投射物交互策略
```

## 许可来源

| 来源 | 许可事实 | 屋顶下目标 | 投射物策略 |
| --- | --- | --- | --- |
| 操作员控制台 | 既有地图控制台许可，且表达显式声明控制台许可键 | 允许，保持现有语义 | 不新增绕过策略 |
| 浮空 Hediff | Pawn 自身 `BDP.FloatingFlight.SelfActive` | 不允许；屋顶下仍按原版直射规则 | `AllowNonTargetPassThrough=true` |

`Hediff_FloatingFlight` 仍是浮空状态的唯一事实来源。Core 只认识许可接口和投射物策略，不认识浮空业务。

## 验收边界

1. 非屋顶目标：拥有浮空许可的远程表达可以选取，不要求射手到目标的直射 LOS。
2. 屋顶下目标：浮空许可不放宽非直视目标限制；目标若原本可直射，仍可按原版规则攻击。
3. 墙、山、深水等 BDP 目标阻挡物：浮空许可下的 BDP 投射物沿已有 `BdpProjectile` 路径继续飞行。
4. 原版投射物拦截器、注册护盾等其它原版交互不因本次需求被全局关闭。
5. 风刃的距离重定向、视觉、伤害等专属模块不迁移到 Core，只复用通用许可协议。
6. AI 不需要额外分支：许可接入不检查玩家、征召或 UI 状态，AI 只要拥有相同 Pawn 许可即可使用同一运行时路径。

## 拦截链共享

额外许可不再只绕过 BDP 自有阻挡扫描。Core 的 `ProjectileInterceptionDecision` 同时负责：

- 把明确目标发射的许可结果适配为原版 `ProjectileHitFlags`；
- 判断 BDP 自有几何扫描发现的非目标世界物体是否应放行。

没有额外许可时，原版 flags 和 BDP 扫描均保持原有结果。本阶段不修改原版 `Projectile` 的 Harmony 拦截方法；`flyOverhead` 仍是原版越顶投射物的独立快速路径。

## 兼容策略

- 保留旧的直射许可解析器注册表，已有控制台或第三方接入不因结构化许可上线而失效。
- 新结构化许可解析器单个异常按未授权隔离，不阻断攻击主链。
- Core 不引用 Content，浮空接收器在 Content 启动时注册。
- 所有远程表达默认支持，不增加每个芯片重复配置的禁用字段。
