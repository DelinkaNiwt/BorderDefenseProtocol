# 新 BDP 二审整改完成报告（第一版）

## 结论

本轮架构二审整改的代码侧主线已完成，
但整个计划还没有在“最终验收”意义上彻底闭环。

当前真实状态应表述为：

- 代码结构收口已完成
- 临时 smoke 已删除
- 最终仍缺游戏内实测与结果记录

本轮真正完成的重点不是“补了更多功能”，
而是把几个最危险的结构退化方向先压住：

- 表达系统不再对外暴露宿主同步口
- Trigger 不再在 Tick 和 UI 读取路径里顺手驱动外围同步
- VerbHosting 不再保留独立时钟
- 自动近战 / 自动远程 patch 进一步退回入口桥地位
- 多个单实现接口已收缩删除

## 已完成事项

### 1. 表达系统收缩

- 删除 `IExpressionHostSync`
- 删除 `ResolveHostSync()`
- 表达层只保留正式结果读取
- Ability / Hediff 宿主同步改为内部消费侧能力

### 2. Trigger 去协调器化第一轮

- `CompTriggerBody.CompTick()` 不再驱动宿主时钟
- `CompGetEquippedGizmosExtra()` 不再在读取路径里顺手同步宿主
- 状态变更后的外围刷新改成显式 `RefreshProjectedOutputs()`

### 3. VerbHosting 去运行时化第一轮

- 删除 `IVerbHostClock`
- 删除 `DefaultVerbHostClock`
- `VerbHostSurfaceAccess` 不再暴露时钟
- 宿主层保留为投影宿主读取 / 重建适配面

### 4. AttackExecution 与 patch 边界收紧

- 自动远程代理 Verb 创建转入 `AttackExecutionSurfaceAccess`
- 自动近战正式请求组装转入 `AttackExecutionSurfaceAccess`
- patch 侧进一步退回原版入口桥接

### 5. 伪抽象层收缩

已删除的单实现接口包括：

- `IAttackExecutionEntry`
- `IExpressionConditionEvaluator`
- `IExpressionHostSynchronizer`
- `IExpressionVerbHostResolver`

这些调用点已直接改为依赖具体实现，
减少了主链跳转层数和空壳抽象。

### 6. UI 副作用与热路径诊断收口

- 常规 `ExpressionInfoProjection` 读取不再默认附带芯片定义 / 契约诊断
- 诊断信息改为显式请求时才构建，不再默认压入普通 UI 说明读取
- `TriggerExternalGizmoRegistry` 在没有外部提供器时不再进入主路径
- 删除剩余单实现接口 `IVerbHostRefreshService`

## 验证结果

本轮代码侧整改期间，已通过以下验证：

- 主模组 `BDP.csproj` 编译通过
- `BDP.DevHarness.csproj` 编译通过
- 临时 smoke 停点脚本通过
- 删除临时 smoke 后，主模组仍可独立编译通过

注意：

- 临时 smoke 只服务于本轮整改
- 现已按约定删除
- 它不再属于后续长期开发流程

## 当前状态判断

当前代码状态已经比整改前更接近以下目标：

- 三核心 owner 与外围投影/桥接关系更清楚
- 表达层不再继续长成对外总协调口
- Trigger 的 UI 读取副作用已明显下降
- VerbHosting 的 runtime 身份被压缩
- patch 对核心执行链的侵入进一步下降
- 诊断与空扩展口不再默认压进普通 UI 热路径

但这不等于：

- 所有业务问题已经补齐
- 所有结构风险都彻底消失
- 可以跳过游戏内实测

## 仍需人工完成的最终验收

按本轮约束，
最终验收仍应以游戏内实测为准。

建议至少覆盖：

- 普通芯片装载 / 卸载 / 启停
- 双手绑定芯片装载 / 启停 / 挤占
- 自动近战
- 自动远程
- 手动攻击按钮
- 部位禁用 / 恢复
- 伤害语义显示

如果这些在游戏中通过，
则本轮架构整改可以视为真正完成。

在这一步完成前，
本报告只能视为“代码侧整改完成报告”，
不能视为“整轮计划最终验收报告”。

## 后续开发入口规则

整改完成后，后续继续开发必须遵守：

- 不得恢复表达层宿主同步公开口
- 不得把 Tick 或 UI 读取重新变成隐式修正点
- 不得把 VerbHosting 重新做回独立运行时层
- 不得把 patch 重新长成业务决策层
- 需要扩展时，优先落在正式 owner、正式结果或最薄桥接层
