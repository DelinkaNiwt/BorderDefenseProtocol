# Trigger读档激活真值恢复完成报告（第一版）

## 目标

本轮只解决一个结构性问题：

- Trigger 在 `PostLoadInit` 内恢复完 slot/container 后，首次表达与宿主重建不能再被通用读路径里的运行时重算打断

## 最终架构

### 1. 单一真值方向不变

- `TriggerSlotState` 仍然是唯一正式业务真值
- `chipContainer` 仍然只是从属持有容器

本轮没有回退到 `container -> slot` 的补洞路线。

### 2. 新增显式 PostLoad 恢复阶段

`CompTriggerBody` 现在显式区分：

- PostLoad 恢复阶段
- 常规运行时读取阶段

恢复阶段的职责只有：

1. 恢复 slot truth
2. 重建从属 container
3. 立即按恢复后的正式真值刷新 expression / host

### 3. 读路径在恢复阶段不得重写真值

`PrepareReadState()` 现在会先判断当前是否处于 PostLoad 恢复阶段。

如果是，则直接返回，不再继续：

- `SyncDisabledStateFromOwnerPawn(false)`
- `ResolveDueSwitchTransitions()`

这意味着：

- 恢复链首次重建表达时，消费的是刚恢复好的正式真值
- 不是“恢复一半后又被运行时重算改掉”的中间态

## 为什么之前会出错

之前的链路是：

1. `PostLoadInit` 恢复 slot truth / container
2. `RefreshProjectedOutputs()` 构建 expression snapshot
3. expression 通过 `ITriggerLoadoutReader` 读取 active slots
4. 读取 active slots 时触发 `PrepareReadState()`
5. `PrepareReadState()` 又触发禁用同步和切换结算

结果是：

- 读档恢复链尚未稳定
- 首次投影就被重新按运行时路径改写
- expression snapshot 可能直接变空
- host 随之缺失
- 自动远程继续取不到主远程宿主
- 最终以 `Verse.Stance_Warmup had a bugged verb after loading` 暴露

## 本轮落地内容

### 代码

- 在 `CompTriggerBody` 增加显式恢复阶段成员与进出方法
- `PostExposeData()` 的 `PostLoadInit` 路径改为恢复阶段包裹，并使用 `try/finally` 确保退出
- `PrepareReadState()` 在恢复阶段直接短路

### 测试

补强 `TriggerSingleTruthSmokeTests.ps1`，新增静态断言：

- 必须存在显式恢复阶段成员
- `PostLoadInit` 恢复链必须包裹在恢复阶段内
- `PrepareReadState()` 恢复阶段必须短路在运行时重算之前

如果手工验证通过，则可以认为这次报错对应的架构缺口已经被正式收口。
