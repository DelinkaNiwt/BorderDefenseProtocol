# BDP远程攻击模块系统架构图汇总-第一版

## 1. 总体架构总图

```text
玩家点攻击入口
    │
    ▼
[表达系统 / 入口投影]
    │
    ├─ Chip / Combo 产出正式远程表达结果
    └─ RangedModules 挂载顺序 = 模块唯一顺序来源
    │
    ▼
[上游目标交互协议]
    │
    ├─ ManualEntry   攻击入口
    ├─ Targeting     目标交互推进
    ├─ Preview       预览绘制
    └─ Confirm       确认冻结
    │
    │   冻结产物：
    │   - 最终目标
    │   - ConfirmedInputSnapshot
    │   - ConfirmedInteractionSnapshot
    │   - 模块私有上下文快照
    │   - 模块顺序快照
    ▼
[执行前半段协议]
    │
    ├─ Aim
    ├─ Prepare
    ├─ Fire
    └─ ProjectileInit
    │
    │   再冻结成每发 projectile 的正式计划：
    │   - ProjectileInitPlan
    │   - ModuleContextSnapshot
    │   - ConfirmedInteraction
    │   - 语义 / 日志快照
    ▼
[BdpProjectile 原版 Bullet 宿主桥]
    │
    ├─ 只吃冻结计划
    ├─ 不回头读上游会话
    └─ 自己负责存读档恢复
    │
    ▼
[执行后半段协议]
    │
    ├─ Flight
    ├─ Arrival
    ├─ Hit
    └─ Impact
    │
    ▼
落回原版能力
    ├─ 原版伤害
    ├─ 原版爆炸
    ├─ 原版日志/特效
    └─ 其它原版结算
```

## 2. 三层结构图

```text
第1层：作者业务模块
    你写的模块本体
    - 只写业务逻辑和配置
    - 只通过正式阶段接口参与
    - 不直接改主骨架

第2层：主模组模块协议层
    主模组提供
    - 阶段上下文
    - 标准贡献
    - 停止请求
    - 附加挂件
    - 私有上下文
    - 冻结/恢复
    - 诊断/裁决

第3层：攻击链桥接层
    主模组插进原版链路
    - Targeter
    - Verb
    - Bullet
    - 命中/爆炸/伤害
    原则：尽量让原版自己推动
```

## 3. 十二阶段职责图

```text
0. 表达结果准备
   Chip / Combo 先产出正式远程表达结果
   并给出 RangedModules 挂载表

1. ManualEntry
   生成玩家能点的攻击入口
   可改入口展示，不直接执行攻击

2. Targeting
   接收玩家当前输入
   驱动目标交互推进
   可继续、完成、取消、停止

3. Preview
   在玩家操作时持续给可视反馈
   只负责“画什么”
   不负责解释业务含义

4. Confirm
   最终确认
   把上游结果冻结成正式快照
   从这里开始，不再依赖上游临时态

5. Aim
   执行前半段的瞄准裁定
   产出正式目标、命中倍率、失准半径等

6. Prepare
   发射前准备
   资源、门禁、预热、锁定等都在这里收口

7. Fire
   把一次攻击展开成一发或多发 emit

8. ProjectileInit
   把每一发 emit 冻结成 projectile 正式计划

9. Flight
   投射物每 tick 飞行推进

10. Arrival
    到达阶段点后裁定
    是继续飞、还是进入命中

11. Hit
    把当前命中事实整理成正式命中记录

12. Impact
    把命中记录翻译成中性效果计划
    再落回原版伤害/爆炸/特效
```

## 4. 作者接口接触面图

```text
你会接触的，只有正式作者面：

上游：
- IManualEntryStageModule
- ITargetingStageModule
- IPreviewStageModule
- IConfirmStageModule

执行前半段：
- IAimStageModule
- IPrepareStageModule
- IFireStageModule
- IProjectileInitStageModule

执行后半段：
- IFlightStageModule
- IArrivalStageModule
- IHitStageModule
- IImpactStageModule

通用配套：
- GetPrivateContext<T>()
- GetOrCreatePrivateContext<T>()
- TryGetPrivateContext<T>()
- StopRequest
- Addon Hook
- 各阶段 Contribution
```

```text
你不会直接碰的东西：

- Targeter 具体驱动
- Verb 内部调度
- BdpProjectile 内部推进
- 阶段服务实现
- 模块仲裁器
- 模块运行时宿主
- 存读档恢复细节
```

## 5. 数据闭环图

```text
Targeting
  读取玩家输入
  ▼
写入模块私有上下文
  ▼
Confirm
  冻结进入执行链
  ▼
ProjectileInit
  把需要的数据带进 projectile plan
  ▼
Flight / Arrival / Hit / Impact
  继续读取同一模块自己的私有上下文
  ▼
提交正式贡献
  ▼
原版结算
```

## 6. 三类关键数据边界图

```text
TargetingInteractionSession
    = 给玩家操作阶段用
    = 负责“当前交互进行到哪”
    = 不负责模块自己的业务数据

模块私有上下文
    = 给模块自己跨阶段带数据用
    = 一模块一份
    = 主模组只负责传递、冻结、恢复

ProjectileInitPlan
    = 给投射物后半段用
    = 只保存后半段继续运行所需冻结数据
    = 不保存上游临时会话
```

## 7. 冻结边界图

```text
冻结点一：Confirm
    冻结：
    - 最终目标
    - ConfirmedInputSnapshot
    - ConfirmedInteractionSnapshot
    - 模块顺序快照
    - 需要进入执行段的私有上下文

冻结点二：ProjectileInit
    冻结：
    - ProjectileInitPlan
    - ModuleContextSnapshot
    - ConfirmedInteraction
    - 语义快照
    - 日志显示快照
    - 后半段所需正式执行事实

原则：
    下游只消费冻结结果
    不回头读取上游临时态
```

## 8. 主模组与测试模组边界图

```text
主模组
    只负责：
    - 中性协议
    - 阶段分发
    - 裁决规则
    - 冻结与恢复
    - 原版桥接
    - 统一诊断

测试模组 / DevHarness
    只负责：
    - 教学样例
    - 业务验证样例
    - 作者演示配置

边界要求：
    删除测试模组后
    主模组仍必须能独立正常工作
```

## 9. 系统“为什么算干净”图

```text
主模组只认识：
    - 阶段
    - 快照
    - 上下文
    - 贡献
    - 停止
    - 附加挂件
    - 诊断

主模组不认识：
    - 战斧
    - 路径
    - 锚点
    - 爆炸模块
    - 任何具体业务名词

因此：
    业务可以外挂实现
    主骨架仍保持中性
```

## 10. 作者最常见的五种模块写法图

```text
模式 A：只改上游显示
    ManualEntry / Preview

模式 B：上游收集数据，下游使用
    Targeting / Confirm 写上下文
    Prepare / Fire / ProjectileInit / Flight / Impact 读取上下文

模式 C：只改发射参数
    Aim / Prepare / Fire / ProjectileInit

模式 D：只改投射物后半段
    Flight / Arrival / Hit / Impact

模式 E：只加附加表现
    Addon Hook
```

## 11. 最简理解图

```text
主模组 = 中性的阶段式攻击骨架
业务模块 = 往骨架各阶段挂的逻辑片段
原版 RimWorld = 真正推动攻击发生的底层引擎
```

---

## 12. 使用建议

```text
写业务模块时，不要先想“我要改整个攻击系统”

只要按这个顺序想：
1. 我要影响哪个阶段？
2. 我要改这个阶段的哪个正式结果？
3. 我要不要带自己的私有上下文？
4. 我要不要请求停止？
5. 我要不要追加附加逻辑？
```

这就是当前 BDP 远程攻击模块系统的标准理解方式。
