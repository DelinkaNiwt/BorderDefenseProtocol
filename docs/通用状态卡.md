# 通用状态卡

`BDP.Core.UI.StatusCards.Gizmo_StatusCard`（通用只读状态卡）提供与骑士盾参考卡相同的紧凑形态：宽 140、高 75，上方标题，下方单条数值。卡片没有点击动作。

## 接入

从自己的原版 `GetGizmos`（界面项枚举）或已有扩展入口返回卡片即可。卡片不要求芯片、触发体或护盾；无需新登记中心。调用方负责何时显示、查询游戏真值，以及把标题、正文和提示从语言包取出。

```csharp
// 在自己的界面项枚举中返回；读取函数在每次绘制时调用。
yield return new Gizmo_StatusCard(() =>
{
    float current = ReadCurrentValue();
    float maximum = ReadMaximumValue();
    return new StatusCardSnapshot(
        "MyResource_Title".Translate(),
        "MyResource_Value".Translate(current.ToString("F0"), maximum.ToString("F0")),
        maximum > 0f ? current / maximum : 0f,
        Color.gray,
        "MyResource_Tip".Translate());
});
```

示例中的语言键应由实际业务语言包声明；`ReadCurrentValue`（读取当前量）与 `ReadMaximumValue`（读取上限）替换成业务自己的读取口，每次绘制取得最新值。倒计时业务可提供 `1 - remaining / duration`（已完成比例）和本地化后的剩余秒数，普通进度可提供 `completed / total`（完成量比例）；时长和总量必须为正值。颜色和正文都由调用方决定。

`StatusCardSnapshot`（显示快照）不可写，只含标题、正文、填充比例、填充颜色和可选悬停提示。比例限定在零至一；无效数字按零处理。读函数返回空时不画内容；是否从操作栏中移除仍由调用方的枚举入口决定。显示层不推进计时、不改真值、不存档。

## 护盾接入规则

护盾提供器复用触发体已有的界面项追加入口，读取正式开启槽位的当前形态和姿态，从对应护盾定义中获得盾组键及标题语言键；不写死芯片名称或盾组列表。

- 单选玩家人物、护盾芯片开启：每组一张卡，双普通盾显示共享上限。
- 护盾完好：显示整数当前耐久与当前有效上限。
- 护盾破损：显示恢复进度和剩余游戏秒数，保留一位小数。
- 芯片关闭：隐藏卡片，后台计时继续；重新开启读取实际剩余冷却或已恢复耐久。
- 光魂姿态切换沿用同一组卡片；多选不显示个人卡片。
- 整个触发体卸下后不从该入口显示卡片；状态恢复仍由已有持久记录负责。

## 游戏内实测清单

重启游戏以加载新程序集后，单选装备触发体的玩家人物：

1. 分别打开普通盾、双普通盾、自动盾、光魂，检查各组标题、耐久上限和数量；双普通盾应只有一张共享卡。
2. 使用既有护盾开发菜单制造可被抵挡的攻击，观察只有成功吸收伤害才扣耐久。
3. 强制破盾，观察数值条从恢复开始向右填充，并显示约 10 秒的倒计时。
4. 暂停与加速游戏，观察倒计时跟随游戏时间。
5. 破盾期间关闭芯片：卡片消失。等待数秒后重开：剩余时间减少；等到到期再开：满耐久。
6. 切换光魂姿态，确认卡片数量和共享耐久不重置；多选人物确认个人卡片隐藏。

离线编译和配置检查不验证实际游戏中的绘制效果与选中刷新。
